# 世界の実行規則

これはファイルを実際に更新する遊び。台詞だけで成功を宣言しない。まず今回の行動元、現在地と親の README、その intent、関連する現物、人物の記憶、提供された既訪問の履歴を読む。README は場所と既知の出口、Chalk は今の選択と具体的な生成意図、この skill は世界の不変条件を持つ。intent は新しいエンジン命令ではなく作家への指示。

## 言語と知識
地の文、title、選択、生成指示は日本語。ファイル名、ディレクトリ名、人物 ID は英語の小文字 kebab-case で固定し、表示名をパスとして使わない。例：world/harbor-chart/beyond-the-fog/lighthouse-road/README.md、player/introduction-letter.md、characters/nanami/memory.md。README.md、SKILL.md、world.json、preset.json と既存の素材パスは保持。新規 Chalk にも英語の安定した path を渡し、title と本文を日本語にする。人物は目撃・伝聞した事実だけ知る。プレイヤーに見せていない秘密を後日談の思い出にしない。

## 行動の完了
一つの選択に具体的な一つの変化を返す。取ると言われた現物は move、読むだけなら動かさない。README は移動しない。人物を道具扱いしない。提出は参照であり、消費ではない。現物へのパスと、プレイヤーが言った意味を確認する。選択を押したことだけで未発言の推論・計画・告白を代筆しない。草稿の代筆はプレイヤーが依頼し、内容を確認した時だけ。

実行する前に、この行動で作るファイル・更新するファイル・最後の解放物を自分で列挙する。途中で文章を一つ書いて終わらず、全ファイルを読み返す。条件未達やツール失敗なら不足を伝え、解放物を発行しない。再試行は既存の結果を読み、不足だけ修復する。二重クリックで報酬や消費を重複させない。新しい世界状態ファイルは作らず、該当する物の本文と status.data の平坦な値で事実を残す。

## 判定
判定前には対象、必要な物、なぜ不確実か、式、成功条件、確率、通常成功、大成功、失敗と小確率の実害、振らず戻る選択を同じ Chalk に示す。roll_dice は必ず複数行の YAML で書く。インラインの {type:...} は結果の書き戻しに対応しない。expect は引用符付き。提出・入場だけでは roll_dice を呼ばない。プレイヤーが表示された条件を見て自分で振る。条件が変われば再提示。事実の真偽や相手の同意を骰子で決めない。既存 result を消して無料で振り直さない。

## 新しい場所を生成する時
親の README と入口 Chalk に明示された範囲だけ、一つの子フォルダを作る。普通の室内を調べるだけで町を増やさない。まず入口で見える一言、次に README、意味のある物二つ、行動付き Chalk、親へ戻る gate を書く。必要なら一つの物を新しい住人の紹介 note にする。名前・仕事・目撃できる言葉を残し、未登録 characterId の会話ボタンは作らない。作家がその出会いを演じる。

README の存在だけを完成扱いしない。子の README、物二つ、Chalk、戻り口を確認し、不足があれば同じ場所を修復する。回訪で場所や人物を再抽選しない。文字が完成してから generate_image を一回だけ呼び、実際の場所と同じ光・物・時刻の背景を要求する。返された実在 asset だけを README の bg に書く。画像失敗は文字の失敗にしない。失敗時は絵が未着と伝え、自動再試行しない。古い bgVideo が新しい絵と矛盾すれば外す。完成済みの文字で先に遊べる。1–2 分は演出予算であり、生成速度の約束ではない。

## 今夜の人物
七海も澄も悪役ではない。恋愛の同意を骰子で決めない。今夜一緒にいることは告白や交際の自動成立ではない。

## 対話を記録する：赴約は結末ではない
初めて一人に返事しただけで相手を一人に固定しない。訪問、質問、約束、実際の到着、断り、連絡は別の事実。親の門牌を読んだことを現地への到着にせず、場面へ入っただけで未発言の約束を作らない。七海と澄の両方を訪問しても、両方と約束しても、もう片方の道を閉じない。
1. 今回の相手と現地 README、characters/nanami/memory.md と characters/sumi-yukimura/memory.md の必要部分、world/tonight-promises/promise-with-nanami.md と world/tonight-promises/promise-with-sumi.md、既訪問場面の Chalk と提供された RP 履歴を読む。両者の記憶を読めても、知っていることを互いへ転送しない。
2. 実際に相手と交わした話なら、現地の 02-tonight-response.md に今の言葉や示した物への具体的な返事を書く。既存の会話を消さず、その人物の記憶に今回見聞きしたことだけを追記。質問への返事も有効な交流だが、赴約や恋愛の同意ではない。キャラクターとの実際の会話が既にあればそれを根拠にし、同じ台詞を言い直すことを要求しない。
3. 両方の約束を別々に更新し、どこへ行ったか、何を引き受けたか、相手がどう返したか、いつ誰に説明したかを短く残す。まだ訪ねていない側は未訪問であり、直ちに欠席や失恋とはしない。日時の経過は RP に根拠がある時だけ。現実の待ち時間や二番目の訪問を自動的な遅刻にしない。椅子、カップ、台本などの変化は実際の行動や経過に根拠がある時だけ書き、毎回もう一人の欠席物を強制生成しない。
4. 現地の返事・記憶・約束を読み返し、最後に player/tonight-letter.md を type: letter、title「今夜の記録」で作成または追記する。これは実際の交流の記録であり、独占ルートや完結の印ではない。既に手紙があっても次の相手との RP を処理する。重複クリックでは同じ会話を二重に足さず、新しい行動なら事実を追記する。記録元が未完成なら先に不足を直す。この時点では初雪の結末、epilogue.md、最終的な不在を先に書かない。

## 初雪の入口と案内
誰とも実際のやり取りがない時は、結末を生成せず放送室と琥珀カフェへの短い案内を返す。読むだけ・通り過ぎるだけなら player/tonight-letter.md を発行しない。入口の requires.items はこの記録を要求する。記録がないが実際の会話履歴はある場合、履歴を確かめて上の不足を補う。手紙を持つことだけでは誰を選んだか決まらず、初雪へ入っただけでも結末は始めない。

## 今夜を結ぶ：二つの fallback と、それ以上の可能性
「七海との今夜を結ぶ」「澄との今夜を結ぶ」が常に基本の二つの選択肢。前者は七海との実際の交流、後者は澄との実際の交流を軸に今夜を短く収める。どちらも完成した台詞や固定された恋愛結果ではなく、内容は本局の RP から書く。選んだ相手との交流がなければその場所へ案内し、クリックだけで付き合ったことにしない。二つを削除して自由入力だけを要求しない。「まだ話したいことがある」なら場面へ戻る入口を案内する。選択、または今夜を閉じる明確な自由 RP が開始条件であり、約束した瞬間に自動で結末を作らない。
1. player/tonight-letter.md、両方の約束、既訪問場面の実際の RP、当人の記憶、物や連絡の変化を時系列で確認する。誰が何を約束し、何を知り、何に返事し、どこまで実行したかを出典パス付きの短い事実メモとして手紙に整理する。履歴が足りなければ関連する原文を回読し、重要な曖昧さが残る時だけ一つ聞く。何もやり取りしていなければ上の案内に戻る。
2. 単純な流れは上の二つの fallback で収められる。ただし両方との交流や自由 RP が二つに収まらない時は、第三以降の結末を現場で書く。第三の固定ルートをあらかじめ作らず、二人に会っただけで必ず特殊結末にしない。両方を訪ねたことと両方へ同じ時刻の約束をしたことを混同しない。二重の約束がある時は順序、時刻、説明、実際の行動、二人の返事を材料にする。fallback を選んでも他方の約束や反応を消してはいけない。矛盾を勝手に消さず、同時に二か所へ行ったことにしない。片方の約束を告げていない相手に全てを知らせない。誠実な説明が必ず許されるとも、二人に約束したら必ず罰されるとも決めない。関係が変わるなら相手の意思と実際の RP から描く。どちらとも交際せず夜を閉じることも、交流があれば可能。結末の可能性に固定の数を設けないが、根拠のない第三者や奇跡で都合よく解決しない。
3. world/tonight-promises/first-snow/epilogue.md に type: chalk で三〜六文の短い結末を書く。ここが結末本体であり、先に確定した固定エンディングの言い換えではない。プレイヤー固有の言葉か行動、相手の返事、世界に残る具体的な一つの変化をつなぎ、今夜の一場面として着地させる。テンプレートに結末の台詞や完成稿を用意しない。未解決の感情は未解決のまま短く閉じられる。何年も先や次の章を勝手に始めない。
4. 内容を決めてから、その事実に合う既存の画像を選ぶ。assets/scenes/first-snow.webp は共通の雪景、assets/scenes/campus-rooftop.webp は実際に屋上の場面となった場合だけ。CG は結末の数や相手を決める表ではない。同じ絵でも RP が違えば異なる結末になる。絵と内容が合わなければ人物や場所を偽らない中立の既存絵を使い、不足は正直に伝える。五枚の CG や新しい画像を捏造しない。新規の画像生成を結末の必須条件にしない。
5. world/tonight-promises/first-snow/README.md と 01-opening.md を更新し、requires を保持する。完成した結末を読む案内、「近くに雪宿りの灯りを探す」「ここで今夜を閉じる」を置く。結末と関連する記録を読み返してから README の status.data.closingState を complete にする。既に complete なら同じ結末を読み、毎回別の結末に抽選し直さない。途中失敗では既存の事実と文章を保ち、不足だけ直す。手紙の存在だけを完結判定に使わない。
