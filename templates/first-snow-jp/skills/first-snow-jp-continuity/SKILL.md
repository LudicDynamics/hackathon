# 初雪ラジオ · 今夜をつなぐ

## 変えない事実

プレイヤーは学生ディレクター。七海は十年来の友人で、初雪の日の屋上の約束を覚えている。雪村澄はデビューしたばかりの歌手で、ツアー前の四十分を仕事抜きで過ごしたい。どちらの気持ちも本物で、どちらも悪役ではない。

言葉の規則は世界直下の language.md にある。本文、台詞、選択肢、場面名と記憶は日本語。プロトコルのキーとパスは翻訳しない。

## 最初の一歩

1. world/README.md と world/01-opening.md を読み、放送終了前の九十秒から始める。プレイヤーが初めから事情を全部知っている扱いにしない。
2. 用紙を読む行動なら request-sheet.md の消し跡を具体的に示す。持つと明言したら move でその実物を player/ に移し、短い Chalk で手に入った手触りを描く。読んだだけで所持したことにはしない。
3. world/tonight が一級の「今夜の約束」。その下に放送室、カフェ、屋上、初雪の場面がある。行き先は既存の Gate で示し、同名の階層を重複生成しない。入れなかったときは移動完了を語らない。

## 一回の応答

1. 対象場面の README、関係する物、人物の記憶と直近の出来事を読む。前の返事の推測だけで次を書かない。
2. プレイヤーが実際に行った一つの行動に、一つの具体的な変化を返す。紙の書き込み、物の受け渡し、待つ場所の変化などをファイルに残す。
3. 長い説明で止めず、短い Chalk と次に取れる行動を一、二個置く。選択肢以外の自由な発言も受け止める。変化がないなら無理に新しい物を作らない。
4. 人物は自分が見聞きした行動だけを覚える。別の場所の秘密は、プレイヤーが伝えるまで共有しない。好感度の数字や別の状態ファイルは作らない。

## 初雪の区切り

プレイヤーが現地で「今夜は一緒にいる」と伝える行動だけが、今回の短い区切りを始める。部屋を覗く、物を読む、質問するだけでは成立しない。radio-studio/README.md と amber-cafe/README.md の最初の選択肢がその入口で、同じ意味の自由な言葉も受け止める。選択肢は親の画面からも見えるため、直近の layer_entered と現在の視点を必ず確かめる。まだ現地でなければ「その場所で伝えよう」と Gate を案内するだけにする。

これは相手の恋心を獲得する判定ではない。一緒に過ごすという具体的な行動への返事であり、告白・恋人・永遠の約束を勝手に成立させない。運や好感度の数値で相手の同意を決めない。

### 赴約が成立した一回の応答

1. 現地の README、関係する人物の memory.md、world/tonight/nanami-promise.md と sumi-promise.md、プレイヤーが明示した物の現物を読む。player/tonight-letter.md が既にあれば、それは実際に起きた前の区切り。二回クリックを新しい赴約として演じ直さず、同じ結果へ案内する。変心が明示されたら前の事実を消さず、何を相手に伝えるか一つ尋ねる。
2. 今の場面に短い Chalk を一つ書く。相手の返事はプレイヤーが今伝えた具体的な言葉か、実際に示した物を一つ引用する。「来てくれた」だけの共通台詞では足りない。人物の memory.md に見聞きした一文を追記する。別の場所の相手に、この会話の内容を知らせない。
3. 不在側の場所に absence.md を一枚書く。七海を選んだならカフェで二つ目の椅子が戻され、冷めたカップが残る。澄を選んだなら放送室で二人分だった台本が一冊閉じられる。これは短い時間経過の結果として描く。通知していないのに相手が理由を知っている、泣いている、裏切られたと思っているとは決めない。プレイヤーが先に連絡したなら、それに合う静かな痕跡に変える。
4. 対応する約束の note を更新する。選ばれた側には今夜一緒にいる事実、不在側には行かなかった事実と連絡の有無を書く。これは別の状態システムではなく、その約束という实体の現在。必要なら link で約束と新しい痕跡を結ぶ。実際に渡すと頼まれた物だけ move し、話題にしただけの物は動かさない。
5. world/tonight/first-snow/README.md の本文を二〜四文で実際の雪の場面に書き換える。七海なら屋上へ続く道、澄なら駅へ向かう道で、隣の反応と離れた場所の具体的な痕跡を対照にする。bg、requires、その他の既存設定は保つ。one-umbrella.md の本文も誰と何を共有したか分かる短い事実にする。新しい画像は要求しない。
6. 上の変更を読み返してから、最後に player/tonight-letter.md を type: letter、title: 今夜の手紙 で作る。これは鍵アイテムの偽装ではなく、プレイヤーが実際に伝えた言葉と相手から返された言葉を保存する一枚。未発言の告白を足さない。この手紙が現れると既存の requires.items により初雪の Gate を通れる。先に手紙を作ると未完成の結果へ入れてしまうので、必ず最後にする。
7. 現地の Chalk に「今夜の手紙を持って、初雪の場面へ」という次の一歩を示す。既存 Gate を使い、移動していないのに移動済みと言わない。ここで応答を終える。

失敗したファイルがあれば手紙を発行しない。どの描写まで形になったかを短く伝え、再試行は現物を読んで不足だけ補う。区切りのあと、新章を自動で始めない。

## 生成の範囲

普通の物を調べるときは短い文書か物の変化で十分。引き出しを見ただけで新しい町を作らない。今夜の主題は同じ場所と人の関係の変化であり、大量の場所を増やすことではない。

## 任意の一〜二分：雪宿りの灯り

初雪の後に「近くに雪宿りできる小さな場所を探す」と頼まれたときだけ始める。「ここで閉じる」には短く応じて終え、新しい Gate を作らない。手紙がまだなければ先に今夜の返事へ戻す。これは次の章ではなく、世界が続けられることを一度だけ見せる余白。

1. player/tonight-letter.md と現在の初雪 README を読む。誰と歩いているか、何を伝えたか、どの道の続きかを確定する。小さな夜店、駅前の待合い、閉店間際の花屋など一つだけを選び、手紙から一つの具体的な要素を引き継ぐ。場所は固定抽選でも別世界でもない。
2. 初雪の場面に threshold.md を type: chalk で書く。「雪の向こうに小さな灯りが見える」のような一歩を示す。world/tonight/first-snow/snow-shelter/README.md を作ると、その場所の Gate が実際に現れる。本文は入場第一眼と二つの choice を含める。画像がまだなければ bg を捏造しない。文字だけでも中に入れる。
3. その新しい場所に resident.md と found-object.md を書く。resident.md は type: note、portable: false の人物紹介。新しい日本語の名前、今している仕事、プレイヤーが見聞きできる一言、出会ったばかりで秘密を知らないという境界を短く持つ。これは Writer が Chalk で演じる出会いであり、未登録の characterId や動かない独立会話ボタンを置かない。found-object.md はこの場所ならではの一つの物。予め所持したことにしない。
4. 新しい場所に arrival.md を type: chalk で書き、人物に話しかける／物を調べるという二つの行動を置く。次の要求では同じ resident.md を読み、同じ人物として答え、知ったことをその文書へ残す。これで環境、人物、物、Chalk が先に遊べる。
5. 文字が揃ってから generate_image を一度だけ呼ぶ。prompt はいま書いた場所の具体物・照明・冬の時間と同じ。暖かいアニメ調の夜景、文字や UI のない背景一枚を要求する。新人物は背景中の小さな姿でよく、立ち絵の追加生成をこの一歩の条件にしない。成功時に返された実在の asset を新 README の bg に edit する。古い bgVideo があれば新しい絵と食い違わないよう外す。
6. 画像失敗は文字場面の失敗にしない。「景色の絵はまだ届いていない」と明示し、同じターンで自動再試行しない。ユーザーがもう一度絵を頼んだときだけ試す。再訪時は README と resident.md を読み直し、名前、場所、背景を振り直さない。

一〜二分は演出の設計予算であり、タイマーでも速度の約束でもない。読み取る内容が先、画像が後。待ち時間を埋めるための余分な台詞や無関係な人物は増やさない。
