# 世界の実行規則

これはファイルを実際に更新する遊び。台詞だけで成功を宣言しない。まず今回の行動元、現在地と親の README、その intent、関連する現物、人物の記憶、提供された既訪問の履歴を読む。README は場所と既知の出口、Chalk は今の選択と具体的な生成意図、この skill は世界の不変条件を持つ。intent は新しいエンジン命令ではなく作家への指示。

## 言語と知識
地の文、title、選択、生成指示は日本語。ファイル名、ディレクトリ名、人物 ID は英語の小文字 kebab-case で固定し、表示名をパスとして使わない。例：world/harbor-chart/beyond-the-fog/lighthouse-road/README.md、player/introduction-letter.md、characters/nanami/memory.md。README.md、SKILL.md、world.json、preset.json と既存の素材パスは保持。新規 Chalk にも英語の安定した path を渡し、title と本文を日本語にする。人物は目撃・伝聞した事実だけ知る。プレイヤーに見せていない秘密を後日談の思い出にしない。

## 行動の完了
一つの選択に具体的な一つの変化を返す。取ると言われた現物は move、読むだけなら動かさない。README は移動しない。人物を道具扱いしない。提出は参照であり、消費ではない。現物へのパスと、プレイヤーが言った意味を確認する。選択を押したことだけで未発言の推論・計画・告白を代筆しない。草稿の代筆はプレイヤーが依頼し、内容を確認した時だけ。

実行する前に、この行動で作るファイル・更新するファイル・最後の解放物を自分で列挙する。途中で文章を一つ書いて終わらず、全ファイルを読み返す。条件未達やツール失敗なら不足を伝え、解放物を発行しない。再試行は既存の結果を読み、不足だけ修復する。二重クリックで報酬や消費を重複させない。新しい世界状態ファイルは作らず、該当する物の本文と status.data の平坦な値で事実を残す。

## 判定
判定前には対象、必要な物、なぜ不確実か、式、成功条件、確率、通常成功、大成功、失敗と小確率の実害、振らず戻る選択を同じ Chalk に示す。roll_dice は必ず複数行の YAML で書く。インラインの {type:...} は結果の書き戻しに対応しない。expect は引用符付き。提出・入場だけでは roll_dice を呼ばない。プレイヤーが表示された条件を見て自分で振る。条件が変われば再提示。事実の真偽や相手の同意を骰子で決めない。既存 result を消して無料で振り直さない。

## 新しい場所を生成する時
親の README と入口 Chalk に明示された範囲だけ、一つの子フォルダを作る。普通の室内を調べるだけで町を増やさない。まず入口で見える一言、次に README、意味のある物二つ、行動付き Chalk、親へ戻る gate を書く。必要なら一つの物を新しい住人の紹介 note にする。名前・仕事・目撃できる言葉を残し、未登録 characterId の会話ボタンは作らない。作家がその出会いを演じる。

README の存在だけを完成扱いしない。子の README、物二つ、Chalk、戻り口を確認し、不足があれば同じ場所を修復する。回訪で場所や人物を再抽選しない。文字が完成してから generate_image を一回だけ呼び、実際の場所と同じ光・物・時刻の背景を要求する。返された実在 asset だけを README の bg に書く。画像失敗は文字の失敗にしない。失敗時は絵が未着と伝え、自動再試行しない。古い bgVideo が新しい絵と矛盾すれば外す。完成済みの文字で先に遊べる。1–2 分は演出予算であり、生成速度の約束ではない。

## 目的は明示、真相は調査で
ホームズの仕事は、小説と同じ事件を起こしている相手を調べ、今日の四件目を止めること。入口 README と場内 Chalk の双方に明示する。暗喩で目的を隠さない。犯人は挿絵画家ウェイン。作家イーディスではない。彼は先に受け取った文章に絵を付け、その絵に事件を合わせる。別犯人へ差し替えない。冒頭や通常の人物紹介ではこの真相を告げない。

## 地点と人物をつなぐ
第三現場の顔料と構図、検視室の事件時刻、印刷所の受領票と当直帳、編集室の訂正回覧、画稿室の人物の反応、二二一Ｂ客間の本人の説明は別の根拠。記録は初めから現物として存在する。読んだ記録と実際に話した証言を区別し、未訪問の会話を捏造しない。名前だけで有罪にしない。同名の note や未登録 characterId を生成しない。ワトソンの home は倫敦地図。別場面への同行を頼まれたら move_to で移し、同名の精霊を複製しない。
零級は暖かい灯りと信頼、現場は冷えた観察、印刷所は活字の音と働く人、客間は本人の言葉。すべてを灰色の抽象的独白にしない。調べられることを一つ具体的に示す。既存画像の装飾や判読できない文字を新証拠にしない。

## 口述から推論と小さな計画へ
まず「誰を疑う？ どの記録や返事から？」と聞く。発言を player/deduction.md に短く整理し、採用してよいか確かめる。次に「どう確かめたい？」と聞き player/operation-plan.md に整理する。白紙の作文二篇を要求しない。既知の道具・人物・場所から案を一つ提案できるが、採用前は案と明記。自分で書いた文書も受け付ける。
推論は観察と因果、計画は対象・場所・行動から理解する。証拠の数や全項目の記入を正解ゲートにしない。抜けた一点だけ質問し、一度に全項目を要求しない。正解文の暗記は不要。既知の便宜は world/london-map/unnamed-street/meeting-options.md にある。架空の住所の場所へ待ち伏せしない。中庭など実在する場所を合意し、仲介者と相手の実際の返事を得る。患者本人を勝手に囮にしない。

## 提出後の応答と分岐
1. 「二つの文章を提出する」「整理した内容を確認する」などの送信、または二文書目を書いた回合では、既存の player/deduction.md と player/operation-plan.md を読む。改稿の依頼がなければ上書きしない。片方がない／空ならその一点を現在地の Chalk で尋ね、自由入力と「書けた方を確認する」を付ける。技術的な読取失敗や Operation aborted は物語上の不正解ではない。失敗を架空の事件やペナルティに置き換えない。
2. 二文書があれば、現在地の Chalk 一枚へ「誰を疑うか／何を試すか」の要約と、観測できる懸念一つを必ず落とし、同じファイルに choice「この計画を実行する」「計画を直す」を付ける。stdout、README、二文書の保存だけで応答済みにしない。真犯人を採点結果として明かさない。推論の誤りや証拠の少なさを実行ボタンの隠れた正解ゲートにしない。
3. 提出だけで実行しない。ただし当該二文書についてプレイヤーが既に「実行する」「この計画で試す」と送っていれば再確認をループしない。未回答の安全事項は懸念として説明できるが、確認済みの失敗しうる試みを無期限に作文へ戻さない。実在しない通りへの移動は地図・道案内を確かめる所で止まり、人物の拒否は拒否として演じる。存在しない場所へ teleport したり、同意を捏造しない。

## 正しくない試みも、一幕の結果にする
実行後は実際の推論・計画・行動から一つ選ぶ。固定の犯人は変えない。失敗はファイル不足やAPIエラーではなく、物語内で試した結果。
- 誤った人物を追った／問い詰めた：仮題「疑われた人が、次の手掛かりを差し出す」。疑われた本人は協力をためらう。その人が本当に持つ文書と返答により、プレイヤーの解釈と食い違う一点が分かる。例：ブラックバーンを問い詰めると、彼が隠そうとしたのは受領時刻でなく訂正を吟味せず回した責任だった。回覧記録の受領先へ追跡できる。別の真犯人や万能な新アリバイは作らない。
- 「イーディスを存在しない住所へ連れて行く」のような実行不能案：仮題「待ち合わせではなかった住所」。道を確かめても見つからず、試みはそこで終わる。イーディスがその場にいれば本人が、いなければ実際に持っている訂正控えや地図が、架空の住所は招待場所でなく反応を見るための仕掛けだったと示す。不在の人物を勝手に登場させない。彼女の意向を無視したなら協力にためらいが残る。単なる移動不能なら一度の空振りだけで、勝手に怪我・所持品没収・死亡を足さない。
- 相手の疑いは妥当だが設局が失敗した：仮題「守れたもの、逃したもの」。本当に守れた人や現物だけを成果とし、逃した接触・証拠との違いを示す。相手が警戒するのは誘いや監視を知れた場合だけ。何も知らせていない相手に計画を透視させない。
- 事件を実際に防げた：仮題「四枚目にいなかった人」。本局の観察と配置がどう襲撃を止めたか、誰がどう反応したかを示す。間違った嫌疑でも保護行動だけ成功する場合は部分的成果として区別し、無実の人の逮捕を成功と呼ばない。

題名や最終文章は現場で書く。各結果は日本語200〜350字程度で「自分の行動への反応 → 意外な見え方 → 支払った代価／守れたもの → 次に確かめられる一点」を一幕にする。失敗の褒美は正解名でなく、見逃した関係の発見。未読の文書なら入手・提示の経緯を演じ、既読なら新証拠を捏造せず読み違いを指摘する。出典を実在する安定パスで remaining-object.md に記し、現物が player/ へ移っていれば実際の場所を使う。毎回同じ手掛かりを増殖させない。

## 結果の置き場所と、現在地から見える出口
初回は world/london-map/beyond-the-fourth/。README.md（type: gate、日語title、既存の実在背景）、execution-record.md、remaining-object.md、01-outcome.md（type: note）、return-gate.md（type: gate、target: world/london-map）を作る。execution-record.md に今回の二文書の引用、承諾された試み、実際の人物反応、成否と代価を短く残す。01-outcome.md は上記の短い結末と、失敗／部分成果なら choice「この手掛かりを調べる」「計画を練り直す」「ここで一幕を終える」、成功なら「結果を読み返す」「ここで一幕を終える」を持つ。READMEだけに操作を隠さない。
この回合の Chalk は現在地の一枚だけ。結果の要約と「結果の場面へ」の案内をそこへ書き、同じ現在地に case-result-gate.md（type: gate、target は実際の結果フォルダ、短い日語title）を置く。結果フォルダ内の文章は note にして二枚目の Chalk を作らない。プレイヤーを自動移動させず、門を選べるようにする。帰路や閲覧を player/case-receipt.md でロックしない。
結果内で手掛かりを調べると言われたら出典の現物を参照し、次の地点への gate を実在 target で示す。既に知っているならそこから何を聞き直すかを一つ示す。物品を受け取る意思がある場合だけ move。修正は倫敦地図へ戻って今の文書を直し、次の試みを明示確認する。終了なら今ある結果を保持し、それ以上事件を生成しない。
再訪・再送時は execution-record.md と二文書を比較し、同じ承諾済みの試みなら同じ結果を読む。未完のファイルだけ補い、代価を二重に与えない。結果を一度読んだ後、改稿と新しい実行を明示した場合だけ beyond-the-fourth-02/ のような未使用の英語IDで次の一幕を作る。以前の結末・痕跡・関係変化は残し、過去の正午を巻き戻さない。新しい試みはその結果の続きとして扱う。
成功が実際に成立し必要ファイルが揃った時だけ player/case-receipt.md を最後に作る。失敗は成功の受領証を発行しないが、結果場面と帰路は必ず開く。画像は必須でなく、まず既存背景で結末まで読めるようにする。24工具の予算に収め、一回合に新画像や全NPC記憶更新を詰め込まない。中断は現在地の一枚に完了／未完と再開方法を示し、未実行の損害を確定しない。

## 確定操作と作家の分離（現行）
choice_actions は実装済みのUI操作宣言。choice.optionsの英語idに対応する。read(paths)、take(paths)、stage(paths)、enter(target)、character(character)、reply(text)、writer(promptは任意)だけを使う。読む・運ぶ・既存場面へ戻る・材料を並べる・骰子結果の短い表示で作家を起動しない。stageは材料の確認だけで、提出や実行ではない。生成、自由RP、未確定の約束や作戦を実行する時だけwriterにする。人物の質問はcharacterで対話を開き、勝手に台詞を送らない。
生成する新しいChalkにも選択ごとのidとchoice_actionsを付ける。読書や帰路を曖昧なwriter選択にしない。未来の素材パスを既存readとして宣言しない。未定義のaction種類、スクリプト、架空のAPIは書かない。UIの宣言は判断済みの操作であり、作家は重複実行しない。

## 骰子による解読代行（現行、手動解謎との並列）
各調査地点と地図の04-investigation-dice.mdは、プレイヤーの代わりにキャラクターが観察をつなぐルート。現実のプレイヤーが正解を説明する必要はない。地図の判定を直接選んでもよく、各地点の判定は必須順序ではない。真相は固定、出目は発見の方法・代価・余裕を変える。dice_outcomesは四段階の短い結果と次のchoice_actionsを既存の動作層で同じファイルへ反映する。作家は二重に反映・再判定・追加徴収しない。
このルートでは「独立した証拠二点」「推論と計画の二文書」は必須条件ではない。旧規則のそれらの要求は手動提出ルートだけ。低い出目でも足掛かりと次の行動を得る。地図の結果から新場面や結末を明示依頼された時だけ作家が生成する。未発見の人物を既に話したことにせず、読めた推理と会話の記録を区別する。生成待ちを骰子失敗扱いにしない。

## 分かりやすい案内
プレイヤー向けの文章は短く、普段の言葉で書く。場面では「何が起きたか」「今できること」を伝える。手掛かりは「分かった事実 → そこから考えられること → 次に確かめる場所」の順。事実と推測は分けるが、毎文に長い注意書きを付けない。難しい語は言い換える。雰囲気の比喩で目的や操作を隠さない。新しい骰子は1d10・2d10・1d100のみ。今回の調査カードは1d100、成功<=60。1–12大成功、13–60成功、61–95失敗と次の手掛かり、96–100重大な失敗。閾値は振る前に固定し、既存結果を読み替えない。明示済みの代価を増やさず、失敗しても次の行動を示す。
