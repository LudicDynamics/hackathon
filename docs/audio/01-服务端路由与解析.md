## 1. 一句话定位

**服务端是"值 → URL"的唯一解析点**：新增 `GET /api/audio` 把仓库根 `assets/audio/**` 变成平台级可寻址资源，新增 `resolveAudioRef` / `readLayerAudio` 把层 README 的 `ambient` / `bgm` 与 `world.json` 的 `audio.theme` 解析成 URL（或 `null`），并通过 `/api/layer`、`/api/manifest` 下发；前端只收 URL，永不做解析（`00 §4.1`、`00 §9.2`）。

### 2.2 `resolveAudioRef`（NEW，模块级函数，不导出）

```ts
/**
 * 单个音频值 → URL。三态：
 *   - `assets/…` 世界相对路径 → `/api/asset?path=<enc>`（直取世界文件；404 → null）
 *   - 裸名 → 覆盖链：先世界级 `<worldRoot>/assets/audio/<cand>`（覆盖）→ `/api/asset`；
 *            再平台级 `<AUDIO_ROOT>/<cand>`（兜底）→ `/api/audio`
 *   - 无匹配 / 违规 / 目标不存在 → null
 */
function resolveAudioRef(
  v: string,
  kind: 'ambient' | 'bgm',
  store: LocalWorldStore,
  audioRoot: string
): string | null
```

**为什么带 `kind` 而不是拆两个函数**：两种字段共用同一套「`assets/` 判定 + 编码 + 世界根防穿越」逻辑，只有裸名候选表不同。拆两个函数会把那段公共逻辑复制两份、两份可能漂移（`00 §4.1` 要求单一真相源）。用一个 `kind` 参数 + 一张候选表，逻辑单点。

```ts
/** 裸名候选表（顺序即优先级，00 §2.3）。探测是**层级优先（level-major）**：
 *  先穷举全部候选的**世界级** `<worldRoot>/assets/audio/<cand>`（世界私有，覆盖平台同名），
 *  全落空后再穷举全部候选的**平台级** `<AUDIO_ROOT>/<cand>`（平台兜底）。
 *  ⚠️ 切勿写成「候选优先（candidate-major）」的两两交错探测——那会让世界池项
 *  （`ambient/pool/X`）输给平台常驻床（`ambient/X`），静默反转"世界覆盖平台"。 */
const AUDIO_POOL: Record<'ambient' | 'bgm', readonly string[]> = {
  ambient: ['ambient/{n}.mp3', 'ambient/pool/{n}.mp3'],
  bgm: ['bgm/{n}.mp3', 'themes/{n}.mp3'],
};
```

## 3. 行为契约逐步（每步写"漏了会怎样"）

### 3.1 `GET /api/audio?path=<rel>`

1. 取 `rel = String(req.query.path || '').replace(/^\/+/, '')`。
   - **漏了**：绝对路径 `/etc/passwd` 会被当成相对段交给 `path.resolve`，虽然最终被 `startsWith` 拦住，但错误归因混乱。
2. `if (!rel) return 400 {error:'path required'}`。
   - **漏了**：空 path 会 resolve 到 `AUDIO_ROOT` 自身，`sendFile` 对目录行为不可控。
3. 拒绝显式 `..` 段：`if (rel.split('/').includes('..')) return 403`。
   - **漏了**：`a/../../x` 依赖 `startsWith` 兜底，语义不显式（`00 §2.4` 要求拒绝 `..`）。
4. `const abs = path.resolve(AUDIO_ROOT, rel); if (!abs.startsWith(AUDIO_ROOT + path.sep)) return 403`。
   - **漏了**：`path.resolve` 归一化后的逃逸（如 `rel = '../audio2/x'`）会命中兄弟目录。
5. **符号链接二次校验**：`const real = realpathSync(abs); if (!real.startsWith(realpathSync(AUDIO_ROOT) + path.sep)) return 403`。
   - **漏了**：`assets/audio/link-to-/etc` 这类软链逃逸（前缀检查只看字符串路径，不解析软链）。
6. `res.sendFile(abs, { headers: { 'Cache-Control': 'public, max-age=31536000, immutable' } }, err => ...)`。
   - **漏了**：素材每次进层重拉；`00 §10` 说素材是产出的不可变文件，长缓存安全。
7. `sendFile` 回调 `err` → `res.status(404).json({ error })`。
   - **漏了**：express 默认 404 HTML，前端 `fetch` 仍能靠 `res.ok===false` 判定，但响应体不可解析。

**Content-Type**：由 `res.sendFile` 按扩展名自动置 `audio/mpeg`（`.mp3`），无需手写。**Range**：[推断] `00 §13-4` 判定浏览器 `decodeAudioData` 全量解码，无需 HTTP Range；`sendFile` 自带 Range 支持，不额外接线。

> 实测（父 agent）：`/api/audio` 未接线时 Express 返回**原生 404**（非 SPA fallback），故新增该路由零冲突；vite dev 的 `'/api'` 前缀代理已覆盖 `/api/audio`，dev 零改动。

### 3.2 `resolveAudioRef(v, kind, store, audioRoot)`

1. `const val = v.trim(); if (val === '') return null`。
   - **漏了**：空字符串会落到裸名分支去试探 `ambient/.mp3`。
2. **世界相对分支**：`if (val.startsWith('assets/'))`：
   a. 世界根防穿越：`const abs = path.resolve(store.worldRoot, val); if (abs !== store.worldRoot && !abs.startsWith(store.worldRoot + path.sep)) { console.warn(...); return null }`。
      - **漏了**：`assets/../../x` 逃出世界根后仍生成 `/api/asset` URL（虽被 `/api/asset` 二次拦，但服务端自解析点也应自守）。
   b. **存在性预判**：`if (!existsSync(abs)) return null`（决策见 §4）。
      - **漏了**：声明了但磁盘上没有的世界级素材会被前端 fetch 到 404 —— 而 `00 §7` 规定"世界级路径 404 = 视同 null（静音）"，与"fetch 失败 = 合成兜底"是**两种不同降级**（见 §4）。
   c. `return '/api/asset?path=' + encodeURIComponent(val)`。
3. **契约违规分支**：`if (val.includes('/'))`（能到这里说明不是 `assets/` 开头却含 `/`）→ `console.warn('audio ref must be a bare pool key or start with assets/: ' + val); return null`。
4. **裸名分支（覆盖链）**：**外层遍历层级 `['world','platform']`，内层遍历 `AUDIO_POOL[kind]` 候选**——即世界级**全部候选**先于平台级**任何候选**（`00 §2.3` 的 5 级链）：
   - 世界级命中 → 世界相对路径 `assets/audio/<cand>` → `/api/asset?path=<enc>`（**覆盖**平台同名）。
   - 平台级命中 → `/api/audio?path=<enc(cand)>`（**增强/兜底**，31 条对所有世界生效）。
   - **漏了**：只探平台（旧稿）→ 世界自带同名素材永远无法覆盖平台；**把候选放外层、层级放内层**（交错序 `world/ambient → platform/ambient → world/ambient/pool → platform/pool`）→ 当世界有 `assets/audio/ambient/pool/X.mp3`、平台有 `ambient/X.mp3` 时，会错误返回**平台** URL，"世界覆盖平台"被静默反转；候选序错亦命中错误素材（`calm` 应先 `bgm/calm` 再 `themes/calm`）。
5. 全部落空 → `return null`（**不报错**，`00 §2.3`）。
   - **漏了**：把"平台池也没有"当错误抛，会让进层 500。

### 3.3 `readLayerAudio(fm, store, audioRoot)`

1. `for (const kind of ['ambient','bgm'] as const)`：
   a. `const raw = fm?.[kind];` 仅当 `typeof raw === 'string' && raw.trim() !== ''` 才 `resolveAudioRef(raw, kind, store, audioRoot)`；否则该键 = `null`。
      - **漏了**：YAML 里 `ambient: [a, b]`（非字符串）会进 `resolveAudioRef`，`.trim()` 抛错。
   b. 结果写入 `{ ambient, bgm }`。
2. 返回。**本函数只翻译"本层 README 声明的值"，不做继承**——继承（`00 §3.3` 的"层 > 世界 map 层 > null"）由**调用方** `/api/layer` 实现（§5.1），因为它是"跨 README 的比较"，不是"单份 fm 的翻译"。
   - **漏了**：若本函数自作主张做继承（读世界 README），会让 `readLayerAudio(mapFm,…)` 递归再继承一层，语义错乱；且把"读哪份 README"的知识塞进翻译器。

### 3.4 `readLayerBg(raw)` 改写

1. `const parsed = parseFrontmatter(raw); const fm = parsed.frontmatter;`
2. `src`：**保持既有逻辑**——`fm.bg` 是顶层字符串，去掉尾随 `# 注释` 与包裹引号（`world.ts:95-99` 原样保留）。
3. `tone`：`typeof fm?.bgStyle?.tone === 'string' ? fm.bgStyle.tone : 'warm'`。
4. `grain`：`typeof fm?.bgStyle?.grain === 'string' ? fm.bgStyle.grain : 'parchment'`。
   - **漏了 tone/grain**：裸正则 `/^\s*tone:/m` 会抓到**正文**里行首带空白的 `tone:`（实测 bug，§8.1），返回错误材质色。

## 4. 关键决策：服务端预判世界级存在性（**明确段落**）

**决策：服务端预判存在性。** 世界级与平台级是**同一条覆盖/增强 fallback 链**（用户原话："世界级和平台级应该是覆盖/增强的关系……平台确实会提供一些基础音频"），不是互斥的两条路：

```text
裸名 ambient: fireplace
  1. <worldRoot>/assets/audio/ambient/fireplace.mp3       世界级私有（覆盖平台同名）
  2. <worldRoot>/assets/audio/ambient/pool/fireplace.mp3
  3. <AUDIO_ROOT>/ambient/fireplace.mp3                   平台级兜底
  4. <AUDIO_ROOT>/ambient/pool/fireplace.mp3
  5. 全落空 → null
```

- **覆盖**：世界自带同名文件 → 赢过平台（世界可替换平台的 `calm`/`rain`）。
- **增强**：世界没有 → 落平台池（31 条对所有世界生效）。
- **`assets/` 前缀值仍直取世界文件**（不参与 3/4 步；世界级 404 → null，不试平台同名——这是"显式指定世界路径"的语义，与裸名的可选覆盖不同）。
- URL 归属：命中世界级 → `/api/asset?path=assets/audio/…`；命中平台级 → `/api/audio?path=…`。

`resolveAudioRef` 对**每个候选**逐层 `existsSync`；命中哪层决定返回哪个 URL。**"只返回磁盘上确实存在的 URL"** 仍是硬约束：`assets/` 前缀值 404 → `null`（世界级 404 视同静音）；裸名全落空 → `null`。

理由（三条，缺一不可）：

1. **只有服务端能区分"声明静音"与"素材加载失败"。** `00 §7` 冻结了二者的不同降级：
   - 「解析为 null」= 声明静音（合成器也停）；
   - 「素材加载失败」= 合成兜底（合成器顶上）。
   若把不存在的 `assets/` 前缀世界路径下发前端，前端 `fetch` 失败会走**兜底**（合成器顶上），而契约要求"世界级路径 404 视同 null（静音）"。语义错位。故服务端把"声明了但没有文件"折叠成 `null`。
2. **`00 §2.3` 已把 `existsSync` 定为服务端的判定原语**；世界分支与平台分支共用同一原语，实现对称、心智负担最低。
3. **代价可忽略**：裸名最多 4 次 `existsSync`（2 候选 × 2 级），`stat` 级开销，远低于同请求里已有的 SQLite 查询与多次 `readFile`。
4. **覆盖链的先后由探测顺序保证**：外层**层级**（`world` → `platform`）、内层**候选**（§3.2 步 4）——世界级全部候选先于平台级任何候选，"世界覆盖平台"是顺序的结构性结果，无需额外分支；`assets/` 前缀值走独立分支（直取世界、404→null）。

**反例存档（为什么不是"交给前端 fetch 失败"）**：前端有 URL 才会 fetch；没有 URL（`null`）时前端根本不该发请求。把存在性判断放前端，等于让前端区分 HTTP 404（静音）与网络错误（兜底）——这正是 `00 §7` 两条降级，需要前端读 status code 才能分开，成本更高且把解析逻辑泄回前端（违 `00 §9.2`）。

## 5. 落账 / WS 前端联动

**无落账**：解析纯读，不写 `canvas.db` / `history.db`，不发 `world_event`。音频状态由前端 effect 驱动（`00 §6.3`，落点见 `docs/audio/03`）。

### 5.1 `/api/layer`（`world.ts:182`）

- 现状 `world.ts:255` 令 `bg` 默认值 `{src:null,tone:'warm',grain:'parchment'}`；`:257-259` 读 README 一次 → `readLayerBg(raw)`。
- 改写：README `raw` 读取后，**同一次** `parseFrontmatter(raw)` 结果供 `readLayerAudio`；`readLayerBg(raw)` 签名不变（内部自解析）。
- **继承链实现（`00 §3.3` 的唯一定义处）**：`ambient`/`bgm` 各自独立继承，**三态**（`00 §3.3` 冻结）：

  |本层 YAML|结果|
  |---|---|
  |**键不存在**（未声明）|回退 map 层同字段（map 也缺 → `null`）|
  |**键存在但解析为 `null`**（`ambient: null`、或声明的裸名/世界路径不存在）|`null`（**不回退**）——`00 §7`「解析为 null = **声明**静音」|
  |**键存在且解析出 URL**|该 URL|

  **继承放服务端**——前端不知道 `world/README.md`，也不该解析（`00 §4.1`/`§9.2`）。`/api/layer` 已是解析点，直接在解析处落：

```ts
// 现 world.ts:255-262 的 try 内，raw = 当前层 README 原文
const parsed = parseFrontmatter(raw);
const ownFm = parsed.frontmatter;                                     // 可能为 null
const own = readLayerAudio(ownFm, store, AUDIO_ROOT);                 // 本层解析（URL | null）
// 键"存在性"与本层解析结果无关：YAML 里出现 ambient:/bgm: 即视为已声明
const declared = (k: 'ambient' | 'bgm') => ownFm != null && k in ownFm;
let audio = own;
if (layer !== 'map') {                    // map 层没有可继承的"上层"
  // catch 只包 map README 的读取 —— 本层解析(own)已在上面完成，绝不被 map 失败吞掉
  try {
    const mapFm = parseFrontmatter(await store.readFile('world/README.md')).frontmatter;
    const inh = readLayerAudio(mapFm, store, AUDIO_ROOT);
    audio = {
      // 未声明 → 回退 map；已声明（哪怕解析为 null）→ 用本层值（null = 声明静音，不回退）
      ambient: declared('ambient') ? own.ambient : (inh.ambient ?? null),
      bgm:     declared('bgm')     ? own.bgm     : (inh.bgm     ?? null),
    };
  } catch { /* map README 缺失 → 不继承，保持 own */ }
}
res.json({ layer, bg, audio, items: enriched, links, presence, worldFrozen });
```

  - `parsed`/`store`/`AUDIO_ROOT`/`readLayerAudio` 在此作用域内均已就绪；评审已实测该骨架编译 EXIT=0。
  - **为什么不能写 `own.ambient ?? inherited.ambient`**：`??` 把「键不存在」与「键存在但解析为 null」压扁成同一种——而后者是**显式静音声明**（`05` 用 `ambient: null` 表达"明确静音优于错配"），不该被 map 层覆盖。三态必须靠 `k in ownFm` 区分。
  - **漏了**：`layer !== 'map'` 分支漏判 → map 层会读自己为"上层"（多一次 IO，值不变）；漏掉整个继承 → `05` 的 stub 层（无 `ambient` 字段）永远拿不到 map 层音频，正是评审抓到的闭环断裂。

- `bg` 形状**逐字不变**（`00 §4.2`）：仍是 `{ src, tone, grain }`。
- 实测基线（父 agent，真实 :3001）：现 `/api/layer` 顶层键为 `['layer','bg','items','links','presence','worldFrozen']`（无 `audio`）→ 本次是**纯增量**，向后兼容。
- 契约**未要求** `/api/layer` 响应带 `errors`；本批**不**下发 `errors`，违规仅服务端 `console.warn`（见 §6、§11-1）。

### 5.2 `/api/manifest`（`world.ts:170`）

- `store.getManifest()` 返回 `validateWorldManifest({...parsed, layers})`（`local-store.ts:286-293`）。
- **跨包改动（父 agent 实测确认，必须）**：`WorldManifestSchema` 用 `.passthrough()`（`packages/shared/src/schemas/world.ts:44`）→ 运行时**保留** `audio` 键，但**推断类型不含** `audio`（`:25-44`），TS 会报错。**必须**在 `packages/shared/src/schemas/world.ts:25-44` 的 `WorldManifestSchema` 内加：

```ts
audio: z.object({ theme: z.string().optional() }).optional(),   // NEW（跨包）
```

  改后 `WorldManifest` 类型自带 `audio?: { theme?: string }`，**无需 cast**，且 `pnpm build` 重建 shared。
  - **漏了**：TS 编译失败；或退化成 cast，类型系统失去约束（本批最初方案，已被父 agent 实测否定）。
- **决策（已写入 `00 §4.3`）：`/api/manifest` 把 `audio.theme` 解析成 URL**（与 `/api/layer` 对称），形状 `audio: { theme: string | null }`。理由：裸键会迫使前端拼 `/api/audio?path=...`，即前端做解析，违 `00 §4.1`/`§9.2`。已与 `FrontendState` 对齐（见 §10 冲突 1）。
- 实现：

```ts
const themeKey = manifest.audio?.theme;                     // 类型已声明（见上）
const theme = typeof themeKey === 'string' && themeKey.trim() !== ''
  ? resolveAudioRef(themeKey, 'bgm', store, AUDIO_ROOT)     // themes 在 bgm 候选表（00 §2.3）
  : null;
res.json({ ...manifest, audio: { theme } });
```

## 附：`resolveAudioRef` / `readLayerAudio` 完整实现骨架（可编译，仅真实符号）

```ts
// 依赖（真实存在）：
//   import { existsSync, realpathSync } from 'node:fs';         // NEW
//   import path from 'node:path';                               // world.ts:5 已有
//   import type { LocalWorldStore } from '@airp/shared';        // world.ts:8 已有

const AUDIO_POOL: Record<'ambient' | 'bgm', readonly string[]> = {
  ambient: ['ambient/{n}.mp3', 'ambient/pool/{n}.mp3'],
  bgm: ['bgm/{n}.mp3', 'themes/{n}.mp3'],
};

function resolveAudioRef(
  v: string,
  kind: 'ambient' | 'bgm',
  store: LocalWorldStore,
  audioRoot: string
): string | null {
  const val = v.trim();
  if (val === '') return null;

  // 世界相对：assets/ 开头（00 §1 解析律）
  if (val.startsWith('assets/')) {
    const abs = path.resolve(store.worldRoot, val);
    if (abs !== store.worldRoot && !abs.startsWith(store.worldRoot + path.sep)) {
      console.warn('[audio] ref escapes world root:', val);
      return null;
    }
    if (!existsSync(abs)) return null;              // 世界级 404 → 视同 null（§4 决策）
    return `/api/asset?path=${encodeURIComponent(val)}`;
  }

  // 含 / 但非 assets/ 开头 = 契约违规（00 §3.1）
  if (val.includes('/')) {
    console.warn('[audio] ref must be a bare pool key or start with assets/:', val);
    return null;
  }

  // 裸名：覆盖链 —— 先穷举【世界级全部候选】，再穷举【平台级全部候选】；
  // 命中层级决定 URL 归属（00 §2.3 的 5 级链顺序）
  for (const level of ['world', 'platform'] as const) {
    for (const tpl of AUDIO_POOL[kind]) {
      const cand = tpl.replace('{n}', val);
      if (level === 'world') {
        // 世界级私有：<worldRoot>/assets/audio/<cand> —— 覆盖平台同名
        const worldAbs = path.resolve(store.worldRoot, 'assets/audio', cand);
        if (existsSync(worldAbs)) {
          return `/api/asset?path=${encodeURIComponent(`assets/audio/${cand}`)}`;
        }
      } else {
        // 平台级兜底：<AUDIO_ROOT>/<cand> —— 31 条对所有世界生效
        if (existsSync(path.join(audioRoot, cand))) {
          return `/api/audio?path=${encodeURIComponent(cand)}`;
        }
      }
    }
  }
  return null;
}

function readLayerAudio(
  fm: Record<string, any> | null,
  store: LocalWorldStore,
  audioRoot: string
): { ambient: string | null; bgm: string | null } {
  const out: { ambient: string | null; bgm: string | null } = { ambient: null, bgm: null };
  for (const kind of ['ambient', 'bgm'] as const) {
    const raw = fm?.[kind];
    if (typeof raw === 'string' && raw.trim() !== '') {
      out[kind] = resolveAudioRef(raw, kind, store, audioRoot);
    }
  }
  return out;
}
```

**URL 编码（与 `00 §4.2` 逐字一致）**：对**整体相对路径**做 `encodeURIComponent`，故所有 `/` → `%2F`：

- `ambient/fireplace.mp3` → `/api/audio?path=ambient%2Ffireplace.mp3`
- `bgm/calm.mp3` → `/api/audio?path=bgm%2Fcalm.mp3`
- `themes/whitechapel.mp3` → `/api/audio?path=themes%2Fwhitechapel.mp3`
- `assets/scenes/x.png` → `/api/asset?path=assets%2Fscenes%2Fx.png`

理由：整体编码同时覆盖路径段中的 `..`、`&`、`#`、空格，且完全匹配契约示例；不使用"仅编码段"的写法，避免与契约逐字比对时产生歧义。express 侧 `req.query.path` 会把 `%2F` 解回 `/`，与既有 `/api/asset` 行为一致。

### 附 2：`GET /api/audio` 实现骨架

```ts
router.get('/audio', (req, res) => {
  const rel = String(req.query.path || '').replace(/^\/+/, '');
  if (!rel) return res.status(400).json({ error: 'path required' });
  if (rel.split('/').includes('..')) {
    return res.status(403).json({ error: 'path must not contain ..' });
  }
  try {
    const abs = path.resolve(AUDIO_ROOT, rel);
    if (!abs.startsWith(AUDIO_ROOT + path.sep)) {
      return res.status(403).json({ error: 'path escapes audio root' });
    }
    const real = realpathSync(abs);
    if (!real.startsWith(realpathSync(AUDIO_ROOT) + path.sep)) {
      return res.status(403).json({ error: 'path escapes audio root (symlink)' });
    }
    res.sendFile(
      abs,
      { headers: { 'Cache-Control': 'public, max-age=31536000, immutable' } },
      (err) => {
        if (err && !res.headersSent) {
          res.status(404).json({ error: err.message });
        }
      }
    );
  } catch (err) {
    res.status(404).json({ error: err instanceof Error ? err.message : String(err) });
  }
});
```

> `realpathSync` 对不存在路径会 throw → 被外层 catch 转 404，正确。`sendFile` 的默认 `dotfiles` 策略与 `/api/asset`（`world.ts:559`）一致。

### 附 3：`readLayerBg` 改写骨架

```ts
function readLayerBg(raw: string): { src: string | null; tone: string; grain: string } {
  let src: string | null = null;
  let tone = 'warm';
  let grain = 'parchment';
  try {
    const parsed = parseFrontmatter(raw);
    const fm = parsed.frontmatter;
    const bgValue = fm?.bg;
    if (typeof bgValue === 'string' && bgValue.trim() !== '') {
      const cleaned = bgValue.replace(/\s+#.*$/, '').trim().replace(/^["']|["']$/g, '').trim();
      src = cleaned === '' ? null : cleaned;
    }
    // bgStyle is a NESTED block (templates/holmes-world/world/README.md:6-8);
    // a bare regex also matched prose lines (see §8.1) — read the structure.
    if (typeof fm?.bgStyle?.tone === 'string') tone = fm.bgStyle.tone;
    if (typeof fm?.bgStyle?.grain === 'string') grain = fm.bgStyle.grain;
  } catch {
    src = null;
  }
  return { src, tone, grain };
}
```
