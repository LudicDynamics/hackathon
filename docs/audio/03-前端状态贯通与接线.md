# docs/audio/03 前端状态贯通与接线

> 子文档 03 / 模块 owner：**FrontendState**。母文档与冻结契约：`docs/audio/00-共同上下文.md`（下称 §NN）。
> 本文只负责**前端状态层把服务端已解析的音频 URL 贯通到引擎**这条链：`useWorld.LayerState.audio` → `App.tsx` effect → `useAudio` surface → 引擎。
> 被引用的引擎符号（`setTheme` / `setBGM` / `preloadAudio` / `playStinger`）**唯一定义处是子文档 `02`（AudioEngine）**，本文不重复定义，只写调用侧契约。解析归属与 `/api/audio`、`/api/layer`、`/api/manifest` 的响应形状**唯一定义处是子文档 `01`（RouteResolver）**。
> 本文遵守契约 **§5.4（`unlock()` 不再种默认、无 App 默认值回退、`LayerState.audio` 必需）**，并把三态语义（URL / `null` / "首帧前短窗"）落进 §3/§6/§9。

---

## 1. 一句话定位

**前端不做任何解析，只做"搬运"**：把 `/api/layer` 给的 `audio.ambient` / `audio.bgm`、`/api/manifest` 给的**已解析** `audio.theme` 原样喂给引擎三条主轨，并用 `preloadAudio` 预热。`tone`（材质色）从此与音频彻底脱钩；**前端不设任何默认声场**——环境音该声明、不该推断（§5.4）。

层的 `ambient`/`bgm` **唯一来源是 `/api/layer`**（契约 §4.1）；`/api/manifest` 的 `layers` 是目录派生的，**不携带音频字段**（主 agent 实测，2026-09-12）——前端 MUST NOT 期望从 manifest 拿层音频。

## 2. 签名 / 参数 / 类型

### 2.1 `LayerState`（`apps/web/src/state/useWorld.ts:32-39`，**新形状逐字**）

```ts
export interface LayerState {
  layer: string;
  bg: { src: string | null; tone: string; grain: string };   // 形状不变（§4.2）
  audio: { ambient: string | null; bgm: string | null };     // ← 新增，必需（§5.4 冻结）
  items: LayerItem[];
  links: LayerLink[];
  presence: PresenceEntry[];
  worldFrozen: boolean;
}
```

**内层形状逐字**：`{ ambient: string | null; bgm: string | null }`。
**外层 `audio` 为必需字段**（§5.4 冻结）——服务端恒定下发该对象（§4.2），三态由**字段值**表达：`"url"`（播放）/ `null`（声明静音）/ 首帧前 `worldState` 整体为 `null` 的短窗。**MUST NOT** 写成可选 `audio?` 再叠加"整体缺失"分支（那会把三态压扁成两态——本文早期稿的错，已被 §5.4 裁决修正）。

- `audio.ambient` / `audio.bgm` 是**服务端解析好的 URL**（`/api/audio?path=…` 或 `/api/asset?path=…`，§2.1），**不是裸名**。前端 MUST NOT 二次解释其内容（§9.2）。
- `audio.ambient === null` = 服务端判定该轨**声明静音**（§7），前端 MUST 原样 `null` 下推，**不得**用 `||`/默认值替换（§5.4 #3 明确禁止）。

### 2.2 `WorldManifest`（前端本地接口，`apps/web/src/App.tsx:17-24`，**新增一行**）

```ts
interface WorldManifest {
  id: string;
  name: string;
  genre: string;
  material: string;
  layers: Record<string, any>;
  characters: any[];
  audio?: { theme: string | null };   // ← 新增：世界主题曲 URL（服务端已解析，§4.3）
}
```

> 该接口是**前端手抄**的，与服务端 `WorldManifestSchema`（`packages/shared/src/schemas/world.ts:25-44`）不同源。服务端 schema 是 `.passthrough()`（`world.ts:44`），运行时**保留** `audio` 但**推断类型不含**——主 agent 已实测（2026-09-12）：必须在 `schemas/world.ts:25-44` 的 `WorldManifestSchema` 加 `audio: z.object({ theme: z.string().optional() }).optional()`，否则 TS 报错且 `manifest.audio` 在强类型路径上不可见。**这是跨包改动（`packages/shared`），落点归子文档 `01`（已在 `01 §5.2/§7` 落地）/ `05`；改后需 `pnpm build`**（`docs/tools/00 §6.1` 红线）。前端接口这一行是**镜像**，不能替代服务端 schema 声明。

## 3. 行为契约逐步（每步写"漏了会怎样"）

### 3.1 服务端 → `LayerState`（`useWorld.ts` 的 `fetchLayer`）

`fetchLayer` 现在从 `data` 构造 `next`（`useWorld.ts:86-93`）。**新增一行**：

```ts
const next: LayerState = {
  layer: data.layer,
  bg: data.bg ?? { src: null, tone: 'warm', grain: 'parchment' },
  audio: data.audio ?? { ambient: null, bgm: null },   // ← 新增：必需字段；缺省视同静音
  items: Array.isArray(data.items) ? data.items : [],
  links: Array.isArray(data.links) ? data.links : [],
  presence: Array.isArray(data.presence) ? data.presence : [],
  worldFrozen: data.worldFrozen === true,
};
```

- **`audio` 为必需字段**（§5.4），应恒有值。`data.audio ?? { ambient: null, bgm: null }` 是**防御性默认**：服务端按契约一定下发（§4.2），此兜底只为不让旧服务端把字段变 `undefined` 而破坏类型。**兜底值是静音，不是"播放某物"**——与 §7 一致（不得悄悄播任何东西，§5.4 #3）。
- **漏了会怎样**：不构造该键 → `worldState.audio` 为 `undefined`，`worldState.audio.ambient` 直接抛 `TypeError`（`audio` 是必需字段，TS 也不允许）。故必须构造。
- **绝不能兜成非静音值**（如 `{ ambient: 'rain', bgm: 'calm' }`）：那会把"服务端未声明"替换成"悄悄播 rain"，违反 §7 与 §5.4 #3。

### 3.2 `App.tsx` 进层 effect（**改写**，`App.tsx:51-54`）

```ts
// 现状（bug）：拿材质色调猜环境音
// Ambient bed follows the layer's material tone (T2.1): warm → fireplace, else rain.
// useEffect(() => {
//   setAmbient(worldState?.bg?.tone || 'rain');
// }, [currentLayer]);
```

**改为（直传三态，无默认值回退，契约 §5.4 / §7）**：

```ts
// Audio beds follow server-resolved URLs from /api/layer (00 §4.2). `tone` is a
// material CSS hook only — it is NOT an audio selector anymore.
//
// `worldState.audio` is REQUIRED (00 §5.4): "url" → play, null → declared silence.
// No fallback default (00 §5.4 #3): silence is a declaration, never replaced.
useEffect(() => {
  if (!worldState) return;                 // ← 首帧短窗：不碰任何主轨，见下
  const audio = worldState.audio;
  setAmbient(audio.ambient ?? null);
  setBGM(audio.bgm ?? null);
  const urls = [audio.ambient, audio.bgm, themeUrl].filter(
    (u): u is string => typeof u === 'string' && u.length > 0
  );
  if (urls.length > 0) void preloadAudio(urls);
}, [worldState?.audio?.ambient, worldState?.audio?.bgm, themeUrl]);
```

逐步：

1. **`if (!worldState) return;`** — 首帧 `worldState` 为 `null`（`useWorld.ts:66`），这是唯一的"字段缺失"短窗，且此时音频上下文本就 suspended（§5.4 #3）。
   - **漏了会怎样**：首帧 `worldState.audio` 访问抛 `TypeError`（`worldState` 为 `null`），effect 崩溃、后续副作用中断。
2. **`setAmbient(audio.ambient ?? null)`** — 收 URL 或 `null`（引擎 §5）。`?? null` 只把 `undefined` 收敛为静音；`null` 原样透传。
   - **漏了会怎样**：环境音床停在上一层的，切层无声场变化。
3. **`setBGM(audio.bgm ?? null)`** — 收 URL 或 `null`（引擎 §5 **已裁决** `setBGM(ref: string|null)`，对外收 URL，合成兜底由 doc 02 内部按 URL 推断 `BGMood`）。
   - **漏了会怎样**：BGM 主轨永不随层切换。
4. **`preloadAudio(nonNullUrls)`** — 只预热非空项。AudioEngine 已确认（hub 回复，2026-09-12）：`preloadAudio` **内部防御性跳过 falsy**，且**永不 reject**（失败记 `failCached` + `console.warn`，await 的是全部 settled）→ `void preloadAudio([...])` 是正确写法，**无需 try/catch**。本文仍按签名 `string[]` 过滤 null，类型更干净。
   - **漏了会怎样**：首次进某层时 fetch+decode 落在播放瞬间，短促静默 + 交叉淡入延迟。非正确性必需，属体验。

#### 3.2.1 effect deps 决策（本题明确要求）

**决策：deps 从 `[currentLayer]` 改为 `[worldState?.audio?.ambient, worldState?.audio?.bgm, themeUrl]`。**

理由（带证据）：
- `worldState` 每次 `fetchLayer` 都换新对象（`useWorld.ts:94-95`）。若 deps 保留 `[currentLayer]`，**同一层内** `audio` 变化不会触发 effect——而这是真实场景：WS 收 `file_changed` 时 `fetchLayer(layerRef.current)`（`useWorld.ts:179-183`），层号不变。作家/上帝改了该层 README 的 `bgm:`，服务端重解析出新 URL，前端却因 deps 不含 URL 而不更新。
- 用 `[worldState]` 整体做 dep **过于宽**：`moveCard`（`useWorld.ts:124-131`）与 `card_position`（`:196-205`）都会换 `items` 数组，拖卡牌会高频重跑音频 effect。引擎虽对同 URL 幂等，但 `preloadAudio` 被无谓触发属浪费。
- **dep 精确到两个 URL 字符串（值相等即不重跑）即足够**，且覆盖 `url ↔ null` 的转换。
- `themeUrl` 进 deps：manifest 异步落地（`App.tsx:86-96`），`themeUrl` 从 `null` 变 URL 时需重跑一次以预热主题曲。

### 3.3 `App.tsx` 世界主题曲 effect（**新增**）

```ts
const themeUrl = manifest?.audio?.theme ?? null;

// World theme: set on world load, persists across layers (00 §5.3).
useEffect(() => {
  setTheme(themeUrl);
}, [themeUrl]);
```

- 生命周期：进世界起、跨层持续（§5.3 轨表）。**不放进进层 effect 逐层重设**——层切换不该重启动主题曲，否则每次切层都听 1.5s 交叉淡入抖动。
- `manifest.audio.theme` 是**服务端已解析的 URL**（§4.3，doc 01 §5.2 已落地），前端**零解析**，直接 `setTheme`。
- **漏了会怎样**：主题曲永不播放（`setTheme` 零调用者），世界级声场缺失，退化成只有层 BGM。
- 首帧 `themeUrl` 为 `null` → `setTheme(null)`。**假设**引擎 `setTheme(null)` 不置"已请求"标志。**待 doc 02 确认**，见 §11#1。
- **降级**：theme 素材加载失败 = **静音**（§7 补行；无合成可回退，不拿 drone 冒充世界主题曲）。前端无感，不重试、不改 URL。

### 3.4 `useAudio` surface 扩展决策

| 符号 | 进 hook？ | 理由 |
|---|---|---|
| `muted` / `toggleMuted` | **已在** | `MuteButton.tsx:10` 真实订阅（render 依赖），必须保留。 |
| `ambient` 值 | **保留（放宽类型）** | 现有 surface，零 render 消费者（`grep useAudio` = 仅 `App.tsx:44` 取 `setAmbient`、`MuteButton.tsx:10` 取 `muted/toggleMuted`）。冻结既有不改，类型由 `string` 放宽为 `string \| null`。 |
| `bgm` / `theme` **值** | **不加** | 无任何 render 消费者。加了只引入无意义重渲染与死 surface。 |
| `setAmbient` | **保留（放宽签名）** | `App.tsx:44` 已在用；放宽为 `(ref: string \| null)` 承接 URL / `null`。 |
| `setBGM` | **加** | App 进层 effect 需要，走 hook 与 `setAmbient` 体例一致（单一 React 桥）。 |
| `setTheme` | **加** | 同上，世界主题曲 effect 需要。 |
| `playStinger` | **不加** | 一次性动作、无状态、调用方是 `CharacterModal.tsx`（子文档 `04`）。塞进 hook 只为"看起来完整"，属过度设计。 |

实现（`useAudio.ts`，新增两个 wrapper）：

```ts

```

- 这两个 wrapper **不写模块状态、不 `notify()`**：没有订阅者读它们，`notify()` 只会白触发所有 `useAudio()` 订阅者重渲染。
- `setAmbient` 保留既有 `notify()`（`useAudio.ts:48-52`），只改参数类型与模块变量类型（§8）。

## 5. 落账与 WS 联动

**音频状态不落账**：`events` 表（`docs/tools/00 §5.1`）没有、也不应有音频事件——音频是**派生的呈现状态**，不是世界事实。故本文**不新增 `appendEvent` 调用**。

**但经 WS 间接驱动**：`useWorld` 的 WS handler 在 `file_changed` / `item_moved` / `god_action` 时 `fetchLayer(layerRef.current)`（`useWorld.ts:178-183`）。因此**同一层内 README 的 `ambient:`/`bgm:` 被改写**会 → 服务端重读 frontmatter → 新 URL → `worldState.audio` 变化 → §3.2 effect（deps 含 URL）重跑 → 声场切换。这正是 §3.2.1 选 URL deps 而非 `[currentLayer]` 的原因。

`world_frozen` / `world_thawed`（`useWorld.ts:184-189`）与音频无关，不动。

## 6. 错误边界

| 情形 | 前端行为 | 断言处 |
|---|---|---|
| `/api/layer` 非 2xx | `fetchLayer` 直接 `return`（`useWorld.ts:80-83`），`worldState` 保持旧值 → effect 不重跑，声场维持现状（不炸、不清空） | 网络面板无新 `/api/audio` 请求 |
| 响应缺 `audio` 键 | 防御兜底 `{ ambient: null, bgm: null }` → 两层静音（**不是**播 rain，§5.4 #3） | `audioDebugState().ambient === null` 且无雨床 |
| `audio.ambient === null` | 原样下推 → 引擎静音该轨（**声明**，不回落合成，§7） | `audioDebugState().ambient === null` 且无合成雨床 |
| `audio.ambient` 是 URL 但 404/decode 失败 | 前端无感；引擎记 `failCached` 并**回落合成**（§7） | `audioDebugState().loaded` 不含该 URL；console.warn 带 URL |
| `audio.theme` 是 URL 但 fetch/decode 失败 | 前端无感；引擎**静音**（§7 补行：theme 无合成可回退，不拿 drone 冒充） | `audioDebugState().theme === '<该 URL>'`（ref 已记）**且 `loaded` 不含它**，`<audio>` 无 drone 声 |
| `/api/manifest` 失败 | `fetchManifest` catch 后 `console.warn`（`App.tsx:93-95`），`manifest` 保持 `null` → `themeUrl === null` → 世界无主题曲，层 BGM 照常 | `audioDebugState().theme === null` |
| 音频上下文未解锁 | effect 照常调用 setter，引擎挂起，`unlock()` 后补播（`audio.ts:592-609` 的 resume 保留；**种默认已按 §5.4 删除**） | 首次点击后声音出现 |

**关键区分**（§7）：**`null`（声明静音）= 前端 MUST 透传，不替换**；**URL 加载失败 = 引擎兜底合成**（**例外：theme 失败即静音**，§7 补行）。前端**不承担任何默认声场**（§5.4 #3）。

**`theme` 的三种状态不可混**（评审 Semantics 抓出的混淆，此处钉死）：
| 状态 | `audioDebugState().theme` | 说明 |
|---|---|---|
| 无主题曲（manifest 无 `audio.theme`） | `null` | **从未声明**——服务端下发了 `theme: null` |
| 有主题曲、加载成功 | `'<该 URL>'` 且 `loaded` 含它 | 正常播放 |
| 有主题曲、加载失败 | `'<该 URL>'` 且 `loaded` **不含**它 | **ref 已记**（与"从未声明"可区分），但**无合成 drone**（§7） |

**MUST NOT** 把"加载失败"的断言写成"`theme === null` 或不在 loaded"——那会把"从未声明"与"声明了但加载失败"混为一谈；二者是**不同的可断言状态**。

## 7. 代码落点（精确到文件与函数名）

- **`apps/web/src/state/useWorld.ts`**

## 9. 验收测试（可执行断言）

> **前提事实**：`apps/web/package.json` scripts 仅 `dev`/`build`/`preview`，**无测试运行器**（无 vitest/jest 依赖）。故本模块验收**以浏览器网络断言 + curl 为准**；完整降级矩阵归子文档 `06`（Verifier）。

**S-1（服务端前置，RouteResolver 负责，此处只作依赖）**
- `curl -s '/api/layer?layer=world/baker-street' | jq -c .audio` → `{"ambient":"/api/audio?path=…","bgm":"/api/audio?path=…"}` 或 `{"ambient":null,"bgm":null}`；**键必须存在**。
- `curl -s /api/manifest | jq -c .audio` → `{"theme":"/api/audio?path=themes%2F…"}` 或 `{"theme":null}`（§4.3 / doc 01 §5.2）。

**S-2（进层切换声场）**
- dev 站进 `map`，再点 gate 进子层。
- Network 过滤 `api/audio`：切层时出现新的 `/api/audio?path=…` 请求、状态 200、`Content-Type: audio/mpeg`；旧轨不产生 404。
- 断言：两个不同 README 声明的层，请求的 `path` 不同。

**S-3（同层 README 热改，验证 deps 决策）**
- **不换层**，改该层 `README.md` 的 `bgm:`（`calm` → `tense`），等 server `fs.watch` + WS `file_changed`。
- 断言：无需手刷，Network 出现新 `bgm/tense.mp3` 请求。**若 deps 仍是 `[currentLayer]`，此断言必失败**——这是 §3.2.1 的回归测试。

**S-4（首帧守卫，验证 `!worldState`）**
- 冷启动、不做任何点击。
- 在 `setAmbient` 首行临时 `console.count('setAmbient')`：加载完成后计数 ≥1，且**首帧（worldState===null）不计**（该帧被守卫挡掉，不抛 `TypeError`）。移除插桩后复验行为。

**S-5（三态 / 无默认值回退）**
- **(a) 服务端未声明**：某层 README 无 `ambient`/`bgm` → `/api/layer` 的 `audio` = `{ambient:null,bgm:null}` → 断言 `audioDebugState().ambient === null` 且**无合成雨床**（静音是声明，§7；**不得**听到 rain）。
- **(b) 缺字段**（旧服务端容错）：人为让响应无 `audio` 键 → 前端兜底 `{null,null}` → 仍**静音**，**不是** rain。
- **(c) URL**：正常层 → `audioDebugState().loaded` 含该 URL，采样播放。
- **核心回归**：任何情况下 App 都 MUST NOT 凭空播 rain/calm——这是 §5.4 #3 的断言。若听到 rain，即前端的"默认回退"复活了。

**S-6（主题曲）**
- 世界有 `audio.theme` 时加载后 Network 出现 `themes/<key>.mp3`；**跨层切换不重复请求**（deps 只含 `themeUrl`）。
- 无 `audio.theme` 时无该请求，层 BGM 照常。
- **theme 失败即静音**（§7 补行）：把 theme URL 指向不存在路径 → 断言 `audioDebugState().theme === '<该 URL>'`（ref 仍记着，与"从未声明"可区分）且 `loaded` 不含它，**无 drone 冒充**（theme 无合成可回退）。若写成 `theme === null` 即混淆了"从未声明"与"加载失败"（见 §6 三态表）。

**S-7（`tone` 脱钩）**
- 进 `bgStyle.tone: cold` 的层，断言 Network **不出现**由 `tone`（`cold`/`warm`）拼出的音频请求；`SceneBackdrop` 的 `data-tone` 仍为 `cold`（纯视觉）。

**S-8（layer 音频不来自 manifest）**
- 断言 `curl /api/manifest | jq '.layers["world/baker-street"]'` **不含** `ambient`/`bgm` 键；层音频只出现在 `/api/layer` 的 `audio`。**若前端从 manifest 取层音频，此断言暴露错误设计**。

> `audioDebugState` 当前**未挂到 `window`**；断言方式为 dev 临时 import 或挂 `window.__airpAudio`（**本文不规定实现，归 doc 06 测试方案**）。

## 10. 发现的冲突 / 需修订上位文档

### 冲突 1（load-bearing，**已裁决**）：`manifest.audio.theme` 裸键 vs "解析只在服务端"

- §4.1 冻结"解析发生在服务端，前端只收 URL"、§9.2 禁前端解析；但旧 §4.3 写"manifest **原样透传即可**" → 会下发裸键 `"whitechapel"`，迫使前端拼 `/api/audio?path=...`。

### 冲突 2（**已裁决**）：`setBGM` 签名曾与 URL 调用矛盾

- 旧 §5：`setBGM(mood: BGMood | null)`（枚举），但 §6.3 示范传 URL → 类型对不上。

**裁决：`setBGM(ref: string | null)`**，与 `setAmbient` 对称；`BGMood` 枚举**仅作合成兜底内部**用（doc 02 内部按 URL 推断 mood）。契约 §5 已改（`00:207-208`）。本文 §2.3/§3.2 已按新签名。**已消解。**

### 冲突 3：`useAudio` 模块级默认 `ambient = 'rain'` 与新语义冲突

`useAudio.ts:18` `let ambient: string = 'rain';` —— 初值是**合成音床名**，而新语义下 `ambient` 只能是 URL 或 `null`，`'rain'` 是**非法值**。且 §5.4 已判"无默认"，hook 模块级不该有默认。改为 `string | null`、初值 `null`。**归本文（03）**，实现时一并改。

### 冲突 4（跨引，非本文修订）：doc-19:124 / 前端改造计划:224 的"作家 mood 标签"

`docs/gameplay/doc-19-多模态与游戏性交互升级.md:124` 与 `docs/ui/前端改造计划.md:224` 仍写 BGM 由"作家单轮返回的情绪标签（`mood: tense/calm/crisis`）"驱动。已被 §12 冲突 1 证伪（无生产者）。本文 BGM 驱动源是**层 README `bgm` 字段**（服务端解析 → §3.2）。修订文本归 Verifier（06）。

### 冲突 5（次要）：`/api/manifest` 的 `audio` 与前端手抄接口

`App.tsx:17-24` 的 `WorldManifest` 是手抄接口，加 `audio` 后有**长期漂移风险**（服务端 schema `.passthrough()`，`world.ts:44`，永不因缺字段报错）。本文只加一行；合并为 `@airp/shared` 类型属既有技术债，**不在 A1 范围**。注意：schema 的类型声明（§2.2）是**构建正确性**必需，本批必做（doc 01 已认领）。

### 冲突 6（**已裁决**）：`LayerState.audio` 必需 vs 可选

本文早期稿曾把 `audio` 写成可选（`audio?`）以承接"整体缺失"分支。**裁决：必需字段**（§5.4 冻结段）：服务端恒定下发 `audio` 对象，三态由字段值（`"url"` / `null`）+ 首帧 `worldState===null` 短窗表达。**本文已改回必需**（§2.1/§3.1/§3.2），并删除"App 回退 rain"分支（§5.4 #3）。**已消解。**
