## 1. 一句话定位

**`lib/audio.ts` 从"纯运行时合成器"升级为"采样优先、合成兜底"的三主轨音频引擎：主轨（`ambient`/`bgm`/`theme`）优先播放服务端给的 URL 素材，素材缺失或解码失败时回落既有合成引擎，声明 `null` 时则真静音；Foley/stinger 是一次性采样，Foley 失败回退合成。**

三件事同时发生：

1. **新增一条采样链**（`fetch → decode → AudioBufferSourceNode`），与既有合成链并列，不替换；
2. **三主轨语义分轨**：`theme`（世界级轻主轨）/ `bgm`（层情绪）/ `ambient`（层环境床）各自独立 crossfade，复用既有 `AMBIENT_FADE = 1.5`（`audio.ts:30`）；
3. **既有 surface 语义扩展**（`setAmbient` / `setBGM` / `playFoley` 变"采样优先"）：`setAmbient` 只加宽类型，`setBGM` 对外签名改为 `string | null`（`BGMood` 退居内部，见 §3.5.1），`playFoley` 不变。

> 为什么"合成引擎必须保留"不是保守，而是硬约束：`00 §9` 反模式 4 明禁删除合成代码，它是 `assets/audio/` 缺席时的**离线演出保底**——本仓 `templates/holmes-world` 无 `assets/` 目录（`00 §10`），世界级素材当前必然落空，demo 仍要出声。**引擎的正确形态是双链共存，不是替换。**

### 2.4 `audioDebugState()` 语义（写死，供 `06` 测试）

- `ambient` / `bgm` / `theme` = **最近一次 setter 收到的 ref 原样**（URL 字符串、裸名、或 `null`）。**与是否加载成功无关**——`loaded` 才反映加载结果。

## 3. 行为契约逐步

### 3.1 采样链（每步写"漏了会怎样"）

```text
loadSample(url):
  1. failCached.has(url) ? → return null            （避免反复 404）
  2. decodeCache.has(url) ? → return 缓存 Promise    （同一 URL 只解一次）
  3. fetch(url)                                       ← 漏了：拿到 Response 不检查 r.ok，404 页面被当音频喂给 decode
  4. !res.ok → throw                                  ← 漏了：404 的 HTML 文本进入 decodeAudioData，报 DOMException 而非清晰告警
  5. res.arrayBuffer()                                ← 漏了：直接 decode Response 对象（不是 buffer），类型不符
  6. ctx.decodeAudioData(arrayBuffer)                 ← 漏了：decode 在 ctx 之外，被自动播放策略挂起
  7. 成功 → decodeCache.set(url, Promise<AudioBuffer>) → return buffer
  8. 任一步失败 → failCached.add(url) + console.warn(带 url) → return null
```

**漏了第 7 步的后果**：每次进同一层都重新 fetch+decode 同一首 60s BGM，解码卡顿且浪费带宽。**漏了第 8 步**：失败 URL 每次触发都重试一次 404，控制台刷屏（`00 §7` 要求"URL 记 failCached"）。

### 3.2 播放一个 clip（一次性节点的正确用法）

`AudioBufferSourceNode` **不可重用**——`start()` 只能调一次，停掉后要播放必须**新建 source**。这是与振荡器（`OscillatorNode`）一致的一次性语义，**现有 `noiseSource()`（`audio.ts:104-108`）已是此模式先例**：每次调用新建 `ctx.createBufferSource()` + `src.buffer = makeNoise(...)`（缓存 buffer）。

```text
playClip(dest, buffer, loop, level):  → { src, gain }
  1. src = ctx.createBufferSource()                  ← 漏了"新建"：复用已 stop 的节点抛 InvalidStateError
  2. src.buffer = buffer
  3. src.loop = loop
  4. gain = ctx.createGain(); gain.gain.value = 0    ← 从 0 起，避免突入爆音
  5. src.connect(gain); gain.connect(dest)           ← dest = master（本引擎所有声音都落 master 总线）
  6. src.start()                                      ← 一次性：此处之后不可再 start
  7. gain.gain.linearRampToValueAtTime(level, now + AMBIENT_FADE)
  8. !loop → src.onended = () => { src.disconnect(); gain.disconnect(); }   ← 漏了：短音节点泄漏
  9. return { src, gain }                             ← 主轨调用方自行登记；一次性音丢弃返回
```

**`playClip` 是轨无关的**（评审 D1）：签名只认 `dest: AudioNode` + `buffer` + `loop` + `level`，**不依赖 `TrackId` 或 `tracks` 表**——三条主轨与 foley/stinger 共用同一个播放器。主轨调用方（`playTrackLoop`）拿到返回的节点后自己登记进 `tracks[id].clip` 并做 crossfade；foley/stinger 只借它播一次、**不登记、不参与任何 track 状态**。若 `playClip` 收 `TrackId`，foley/stinger 在类型上根本调不到它（它们不在 `TrackId`，也无 `tracks` 条目）——这正是"骨架不能按文档逐字落地"的缺陷。

**漏了第 4 步**：新 clip 以满增益瞬间切入，与仍在淡出的旧 clip 叠加 → 爆音。**漏了第 8 步**：一次性短音（foley/stinger）播完不 disconnect，长期累积节点。

### 3.3 轨切换（crossfade，独立于其它轨）

```text
playTrackLoop(id, url|null):                          ← 三条主轨专用包装（唯一 use playClip + 登记 clip 的地方）
  1. 旧 clip 存在且 url 不同 → 旧 gain ramp 到 0，AMBIENT_FADE 后 src.stop()+disconnect
  2. url === null → 该轨停止（不回退合成）              ← §7：解析为 null = 声明静音
  3. url 是 URL → loadSample(url)
       - 成功 → playClip(master, buf, loop=true, level) → 登记 tracks[id].clip
       - 失败 → **显式合成兜底**（见 §3.5.1，评审 D2）：
           ambient → setSynthAmbient(toneFromHint(synthHintFromUrl(url)))
           bgm     → setSynthBgm(moodFromHint(synthHintFromUrl(url)))
           theme   → 不兜底（静音）
  4. url 是裸名 → 兼容层，见 §3.5（ambient/bgm 走合成，theme 不播）
```

**第 3 步的"失败"分支不是可选**（评审 D2）：契约 §7 要求"素材加载失败 → 保底演出"，骨架必须真调合成 setter，否则 URL 404 时会静音而非兜底。这与第 2 步的"声明 null → 停"是**两条不同路径**，`playTrackLoop` 里必须都写。

**漏了第 1 步的"旧 clip 淡出"**：两句 BGM 硬切，接缝处相位对撞产生 click。**三条轨各自独立**：切 `ambient` 不得触碰 `bgm`/`theme` 的 gain——**漏了独立性的后果**是三层声场塌成一层（`00 §14.3` "够味"判据）。

### 3.4 逐轨的"声明 null vs 加载失败"分流（`00 §7` 关键区分）

| 场景 | `ambient` | `bgm` | `theme` |
|---|---|---|---|
| `ref === null` | 采样停 **且** 合成 `activeTone=null`（真静音） | 采样停 **且** 合成 `activeMood=null` | 采样停（theme 无合成） |
| 裸名 | 采样停，合成按 hint 开（§3.5） | 采样停，合成按 hint 开 | 不播 + warn（引擎无法解析裸名，§3.5.1 / §10 冲突 1已裁决） |
| URL 加载成功 | 播放采样，合成 `activeTone=null` | 播放采样，合成 `activeMood=null` | 播放采样 |
| **URL 加载失败** | 采样停，**回落合成**（URL→hint 反推，兜底 `rain`） | 采样停，**回落合成**（URL→mood 反推，兜底 `calm`，见 §3.5.1） | 采样停，**静音**（无合成可回退） |

**"解析为 null" ≠ "素材加载失败"**（`00 §7`）：前者是声明静音，合成器也必须停；后者是保底演出，合成器顶上。**把两者混为一谈的后果**：层声明"这里没有环境音"时仍听到 rain 合成噪声——直接违反契约。

`theme` 无合成回退是**有意的**：世界主题曲缺席时宁可不响，也不要一段不知从哪来的 drone 冒充主题曲。

### 3.5 裸名 = 合成 hint（引擎不做路径解析）

`00 §1` 解析律把"裸名 → URL"的活派给**服务端**（`01`）；`00 §2.3`（新增覆盖链）让裸名先探世界 `assets/audio/`、再落平台池——**两条都在服务端，引擎零感知**。引擎收到的 URL 一律以 `/` 或 `http` 开头，按**前缀**分流（裸名分支仅剩兼容用途，见下）：

```ts
const isUrl = (ref: string): boolean => ref.startsWith('/') || ref.startsWith('http');
```

**裸名保留的唯一用途**是向后兼容：`useAudio.ts:18` 现在种 `'rain'`，`App.tsx:53` 现在传 `bg.tone`，`unlock()`（`audio.ts:602`）现在种 `'rain'`/`'calm'`。这些裸名在 `04`/`03` 接线落地前**仍走既有合成路径**，靠既有 hint 映射（`audio.ts:322-324` 的 `fire`/`drip` 子串判定 → `toneFromHint`）。**接线完成后**主轨全部收 URL，裸名分支退化为兼容层。

**引擎 MUST NOT** 把 README 声明的裸名值（如 `'rain'`）拼成 `'/api/audio?path=ambient%2Frain.mp3'`——这是路径解析，`00 §9` 反模式 2 明禁（两端口径漂移风险）。**例外（已裁决）**：`playFoley`/`playStinger` 自建平台固定 URL（键=文件名，非声明值），见 §3.7/§3.8 与 §10 冲突 2。

### 3.5.1 采样失败时 URL → 合成兜底的推断规则（主 agent 裁决要求写明）

**纯采样成功时不需要推断**——直接播 URL。推断只在 **URL 加载失败 → 合成兜底** 时发生，且仅两条主轨需要。**完整调用链**（评审 D3：`synthHintFromUrl` 必须被点名，不留孤悬）：

```text
ambient 失败路径：setSynthAmbient( toneFromHint( synthHintFromUrl(url) ) )
                    └── setAmbient 内既有合成切换（抽出为 setSynthAmbient）
                        └── toneFromHint 把 stem 映射到 ToneKey（fire→fireplace / drip→drip / 其余→rain）
                            └── synthHintFromUrl 从 URL 末段取文件名 stem（…ambient%2Ffireplace.mp3 → fireplace）

bgm 失败路径：    setSynthBgm( moodFromHint( synthHintFromUrl(url) ) )
                    └── moodFromHint: stem 含 tense→'tense'、含 crisis→'crisis'、其余→'calm'

theme 失败路径：  不调任何合成 setter → 静音
```

- **`ambient`**：`synthHintFromUrl` 从 URL 末段取 stem（`/api/audio?path=ambient%2Ffireplace.mp3` → `fireplace`）→ `toneFromHint` 选床；**stem 空或无匹配 → `rain`**（既有默认床，`audio.ts:322-324`）。
- **`bgm`**：同 `synthHintFromUrl` 取 stem → `moodFromHint`；**兜底恒为 `calm`**（`BGM_TARGETS` 里电平最低的一档，`audio.ts:42-46`）。
- **`theme`**：不调用 `synthHintFromUrl`、不兜底 → 静音（§3.4）。

**两个 helper 的归属**：`synthHintFromUrl`（URL→stem）与 `moodFromHint`（stem→mood）是 `audio.ts` 内部函数，**均被 `playTrackLoop` 显式调用**（§3.3 第 3 步、§7.1 骨架），非孤悬符号。

**`BGMood` 的定位**：对外 surface 已改为 `setBGM(ref: string | null)`（§2.1），`BGMood` 联合类型**退居内部**——只作为 `bgmEngines` 的键与 `BGM_TARGETS` 的记录类型（`audio.ts:42,340`），以及 `moodFromHint` 的返回类型。**`setBGM` 不再出现在对外签名的类型里。**

**为什么兜底 `calm` 而非 `tense`**：加载失败是不可知事件，`calm` 是最不冒犯的保底；把失败误映射成 `crisis`（鼓点）会让一次网络抖动听起来像剧情高潮。

**漏了这条推断规则的后果**：URL 失败后所有轨一律掉进默认床，层的情绪意图（"这里是酒馆紧张对峙"）在降级瞬间丢失——虽然不比静音糟，但也不该。若评审认为推断超纲（[推断]，§11.3），可整体降级为"固定默认床"。

### 3.6 `setTheme(ref)`（新增）

- `ref === null` → 停 theme 采样。**漏了**：换世界后旧主题曲不停，两世界主题曲叠奏。
- URL → 独立轻主轨播放，loop，level 最低（`theme` 在 `00 §5.3` 表里是"bg 层"）。
- 生命周期：**进世界起、跨层持续**。它**不参与** `ambient`/`bgm` 的层继承链（`00 §3.3`），由 `03` 在进世界时调一次。
- 与 `bgm` 可同时存在：`theme` 铺底，`bgm` 叠其上——**引擎不做互斥**，两轨独立 gain。**漏了独立性**：进层 BGM 会把主题曲顶掉，世界失去听觉身份。

### 3.7 `playFoley(name, intensity)`（采样优先）

```text
1. name（含新值 'page-turn'）→ 查表 URL = /api/audio?path=foley%2F<name>.mp3
2. loadSample(url) 成功 → playClip(master, buf, loop=false, level=FOLEY_SAMPLE_LEVEL × intensity)，**不登记 track**
3. 失败 → 回退既有 switch（audio.ts:475-569）的合成音
```

- `intensity` 只影响合成的 `paper-slide`（`audio.ts:481`）；采样路径**统一用它缩放 clip level**（`0`–`1`），保持语义连续。**漏了**：拖拽强度信息在采样路径丢失。
- **既有合成 switch 全量保留**（§5 清单），只在采样成功后绕过。

### 3.8 `playStinger(emo)`（新增）

```text
1. ctx 未 running（未解锁 / suspended）→ 直接 drop，不排队、不补播   ← 见 §6.4
2. URL = /api/audio?path=stinger%2F<emo>.mp3
3. loadSample(url)：当前 stinger/ 目录不存在（契约 §2.2 已定义该目录，待产出）→ 必然 404 → failCached → return null
4. null → 静默 no-op（console.warn 一次，靠 failCached 去重）
5. 成功 → playClip(master, buf, loop=false, level=STINGER_SAMPLE_LEVEL)，**不登记 track**、独立于三条主轨
```

- **绝不触碰主轨增益**（`00 §5.3`、§9 反模式 1）：stinger 是纯叠加，`ambient`/`bgm`/`theme` 的 gain 一个不动。**漏了**：每次角色换情绪，BGM 被拉低一下——正是契约禁止的 galgame 反例。
- 时长 <1.5s 由**素材本身**保证（`00 §5.3`），引擎不裁剪；若将来素材超长，由 `05` 重裁素材而非引擎截断。
- **情绪枚举直映射**（`00 §2.2` 勘误）：URL 键就是 `Emotion` 六值本身，不经裸名解析（`stinger/` 不是平台池的可试探目录）。

### 3.9 `preloadAudio(urls)`（新增，永不 reject）

```text
1. 遍历 urls，跳过 falsy（'' / null / undefined）——防御性，签名仍是 string[]
2. 每个 url 调 loadSample(url)（命中缓存则即时 resolve）
3. await Promise.allSettled(...)  ← 用 allSettled：单个失败不能让整批 reject
4. 永远 resolve（失败只记 failCached + warn）
```

**调用方无需 try/catch**（已在 IRC 与 `03` 对齐）：`void preloadAudio([...])` 是安全写法。**漏了第 3 步的 allSettled**：一个 404 让整批预热 reject，调用方的 fire-and-forget promise 变 unhandled rejection。

### 3.10 `unlock()`（`00 §5.4` 裁决落地）

**删除**（`audio.ts:602-603`）：
```ts
if (!ambientRequested) setAmbient('rain');
if (!bgmRequested) setBGM('calm');
```
**删除**标志（`audio.ts:54-55`）：`ambientRequested` / `bgmRequested`。

**保留**：`ctx.resume()`（`:595-601`）+ master 增益恢复（`:606-608`）+ `rampAmbient()`/`rampBgm()` 重排（`:604-605`），**并新增 `rampClips()`**——采样 clip 的 gain ramp 若在 suspended 时排定会冻结在时间轴上（与 `rampAmbient` 同款问题，`audio.ts:301-313` 注释已述）。

**理由**（`00 §5.4`）：引擎是哑执行器，"默认环境音"是产品决策，归 `03` 的 App 侧；引擎偷种默认会产生第二个真相源，且与"App 解析为 null = 静音"直接打架。**两端必须同批**：只改 `unlock` 不改 App → 进层前完全无声（死默认）。

`unlock()` 新语义一句话：**只做"把手松开"（resume + 恢复增益 + 重排已声明的 ramp），不替任何人做选择。**

`initAudio()` **不变**：仍懒建 `ctx` + `master`（`audio.ts:61-77`），`master.gain.value = 0` 直到首次 `unlock()`。

## 6. 错误边界

### 6.1 加载失败（`fetch` 4xx/5xx、网络断、`decodeAudioData` 抛）

→ `failCached.add(url)` + `console.warn`；主轨回落合成（§3.4），foley 回落合成 switch，stinger 静默。**不得抛到调用方**（`preloadAudio` 除外——它按设计就吞）。

### 6.2 竞态（快速连续换层）

`setTrackSample` 每次 `token++`；async decode 落地时比对 token，过期则丢弃（不播放、不 swap）。**漏了**：A 层素材慢、B 层素材快，A 落地时覆盖 B → 播放错误层的 BGM。

### 6.3 无 `AudioContext`（node / 禁用 Web Audio）

`initAudio()` 返回 `null`（`audio.ts:67` 无 `window.AudioContext` 时）或 catch 置空（`:72-74`）。此时：

- setter **仍写 `tracks[id].ref`**（§2.4，`06` 依赖此断言）；
- 不播放、不 fetch、不 warn；
- `preloadAudio` **立即 resolve**（无解码器，无可失败）；
- `audioDebugState().loaded === []`。

### 6.4 上下文未解锁 / suspended

- 主轨 setter：照常记录 ref 并尝试排程；`unlock()` 后 `rampClips()` 重排（§3.10）。
- **`playStinger`：drop，不排队**（与 `04` 已达成一致）。理由：<1.5s 瞬时情绪音，unlock 后补播必然错拍，补播的"情绪"也与当下台词无关。
- `playFoley`：**同样 drop**（一次性交互音，补播无意义；现有 `playFoley`（`audio.ts:468-570`）本就无排队逻辑，保持现状）。

### 6.5 `master` 为 null

所有播放函数开头 `if (!initAudio() || !master) return;`（沿用 `audio.ts:469` 模式）。

### 7.1 采样播放器完整可编译骨架（TS）

只用**真实符号**：`ctx` / `master` 为 `audio.ts:48-49` 既有模块级变量；`AMBIENT_FADE` 为 `:30` 既有常量；`initAudio` 为 `:61` 既有导出。

```ts
/* ============================================================
 * Sample layer — real files behind the same surface as the synth
 * engines. Each track: one AudioBufferSourceNode (loop?) → its own
 * GainNode (crossfade ramp) → master. Sources are one-shot nodes
 * (same pattern as noiseSource(), audio.ts:104): every play builds
 * a fresh source from the cached AudioBuffer.
 * ============================================================ */

type TrackId = 'ambient' | 'bgm' | 'theme';

interface Clip {
  url: string;
  src: AudioBufferSourceNode;
  gain: GainNode;
  loop: boolean;
}

interface SampleTrack {
  ref: string | null; // declared ref verbatim (debug truth)
  clip: Clip | null; // what is sounding now
  token: number; // async-race guard
}

const tracks: Record<TrackId, SampleTrack> = {
  ambient: { ref: null, clip: null, token: 0 },
  bgm: { ref: null, clip: null, token: 0 },
  theme: { ref: null, clip: null, token: 0 },
};

const decodeCache = new Map<string, Promise<AudioBuffer>>();
const failCached = new Set<string>();

const SAMPLE_LEVELS: Record<TrackId, number> = { ambient: 0.5, bgm: 0.35, theme: 0.22 };
const FOLEY_SAMPLE_LEVEL = 0.7;
const STINGER_SAMPLE_LEVEL = 0.8;

const isUrl = (ref: string): boolean => ref.startsWith('/') || ref.startsWith('http');

/* --- URL → synth-hint helpers (used only on the sample-failure path, §3.5.1).
 * toneFromHint is EXTRACTED from the inline mapping at setAmbient:321-324
 * (Feasibility: remove the inline copy, don't duplicate it).
 * ToneKey already exists at audio.ts:27 — do NOT redeclare it. --- */

/** Decode the file-name stem from a platform URL.
 *  `/api/audio?path=ambient%2Ffireplace.mp3` → 'fireplace'. */
function synthHintFromUrl(url: string): string {
  const file = url.split('/').pop() ?? '';
  const q = file.includes('?') ? (file.split('?')[1] ?? '') : file;
  const raw = q.includes('path=') ? decodeURIComponent(q.split('path=')[1] ?? '') : file;
  return (raw.split('/').pop() ?? '').replace(/\.[a-z0-9]+$/i, '');
}

/** Bare-hint → ambient bed (map toneFromHint).
 *  NOTE: this is the extracted body of setAmbient:321-324 — the inline
 *  substring mapping there MUST be deleted when this lands. */
function toneFromHint(hint: string): ToneKey {
  const t = hint.trim().toLowerCase();
  if (t.includes('fire') || t.includes('hearth') || t === 'warm') return 'fireplace';
  if (t.includes('drip') || t.includes('cellar') || t.includes('cave')) return 'drip';
  return 'rain';
}

/** Bare-hint/stem → BGM mood; `calm` is the safe floor (§3.5.1). */
function moodFromHint(hint: string): BGMood {
  const t = hint.trim().toLowerCase();
  if (t.includes('crisis')) return 'crisis';
  if (t.includes('tense')) return 'tense';
  return 'calm';
}

/* Synth halves of §3.4: these drive the EXISTING engines (audio.ts:204-326
 * ambient, :340-460 bgm). `null` silences the bed. They are thin setters over
 * the module state activeTone / activeMood + the existing rampAmbient/rampBgm. */
function setSynthAmbient(tone: ToneKey | null): void {
  ensureAmbientEngines();
  activeTone = tone;
  rampAmbient();
}

function setSynthBgm(mood: BGMood | null): void {
  ensureBgmEngines();
  activeMood = mood;
  rampBgm();
}

/** Fetch → arrayBuffer → decode, cached per URL. Failure is recorded in
 *  failCached (never retried) and resolves to null — callers fall back to
 *  the synth engines. Never throws. */
function loadSample(url: string): Promise<AudioBuffer | null> {
  if (failCached.has(url)) return Promise.resolve(null);
  const cached = decodeCache.get(url);
  if (cached) return cached;

  const c = ctx;
  if (!c) return Promise.resolve(null);      // ← P0 修复：无 ctx 时【先返回】，
                                             //   绝不构造/缓存 promise（否则 decodeCache 残留
                                             //   resolved-to-null，audioDebugState().loaded 非空，
                                             //   与 06 §9 E5「无 ctx 时 loaded 恒 []」矛盾）
  const p: Promise<AudioBuffer | null> = (async (): Promise<AudioBuffer | null> => {
    try {
      const res = await fetch(url);
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const ab = await res.arrayBuffer();
      return await c.decodeAudioData(ab);
    } catch (err) {
      failCached.add(url);
      decodeCache.delete(url); // failCached owns the negative result
      console.warn('Audio: sample load failed', url, err);
      return null;
    }
  })();
  decodeCache.set(url, p as Promise<AudioBuffer>);
  return p;
}

/** Start a fresh one-shot source for `buffer`, fading its own gain up.
 *  TRACK-AGNOSTIC (D1): takes a destination node, not a TrackId, so the
 *  three sample loops AND the foley/stinger one-shots share one player.
 *  Callers own the returned nodes: main tracks register them in
 *  tracks[id].clip; one-shots just let onended clean themselves up. */
function playClip(
  dest: AudioNode,
  buffer: AudioBuffer,
  loop: boolean,
  level: number
): { src: AudioBufferSourceNode; gain: GainNode } | null {
  const c = ctx;
  if (!c) return null;

  const src = c.createBufferSource(); // one-shot node: never reuse
  src.buffer = buffer;
  src.loop = loop;
  const gain = c.createGain();
  gain.gain.value = 0; // fade in from silence (no click)
  src.connect(gain);
  gain.connect(dest);

  const t = c.currentTime;
  src.start(t); // start() is once-only per source
  gain.gain.linearRampToValueAtTime(level, t + AMBIENT_FADE);

  if (!loop) {
    src.onended = (): void => {
      src.disconnect();
      gain.disconnect();
    };
  }
  return { src, gain };
}

/** Fade out, then stop + disconnect a specific main-track clip. */
function stopClip(track: TrackId, clip: Clip, fade: number): void {
  const c = ctx;
  if (!c) return;
  const t = c.currentTime;
  clip.gain.gain.cancelScheduledValues(t);
  clip.gain.gain.setValueAtTime(clip.gain.gain.value, t);
  clip.gain.gain.linearRampToValueAtTime(0, t + fade);
  window.setTimeout(() => {
    try {
      clip.src.stop();
    } catch {
      /* already stopped */
    }
    clip.src.disconnect();
    clip.gain.disconnect();
  }, fade * 1000 + 40);
  if (tracks[track].clip === clip) tracks[track].clip = null;
}

/** Play a main-track sample loop and register it in the track table. */
function playTrackLoop(track: TrackId, url: string, buffer: AudioBuffer, token: number): void {
  if (!master) return;
  const nodes = playClip(master, buffer, true, SAMPLE_LEVELS[track]);
  if (!nodes) return;
  // A newer set() landed while we were decoding → discard this clip.
  if (token !== tracks[track].token) {
    nodes.gain.gain.cancelScheduledValues(ctx!.currentTime);
    nodes.gain.gain.setValueAtTime(nodes.gain.gain.value, ctx!.currentTime);
    nodes.gain.gain.linearRampToValueAtTime(0, ctx!.currentTime + 0.05);
    try {
      nodes.src.stop(ctx!.currentTime + 0.06);
    } catch {
      /* already stopped */
    }
    return;
  }
  const prev = tracks[track].clip;
  tracks[track].clip = { url, src: nodes.src, gain: nodes.gain, loop: true };
  if (prev) stopClip(track, prev, AMBIENT_FADE);
}

/** Declare a track's sample ref, then apply it. Records the ref even when
 *  there is no AudioContext (debug/test contract, §2.4). */
function setTrackSample(track: TrackId, ref: string | null): void {
  const tr = tracks[track];
  tr.ref = ref;
  tr.token += 1;
  const c = initAudio();
  if (!c || !master) return;
  if (!ref) {
    // Declared silence: stop the clip AND the synth bed — do not fall back (§7).
    if (tr.clip) stopClip(track, tr.clip, AMBIENT_FADE);
    if (track === 'ambient') setSynthAmbient(null);
    else if (track === 'bgm') setSynthBgm(null);
    return;
  }
  if (!isUrl(ref)) {
    // Bare name = compat hint → synth only.
    if (tr.clip) stopClip(track, tr.clip, AMBIENT_FADE);
    if (track === 'ambient') setSynthAmbient(toneFromHint(ref));
    else if (track === 'bgm') setSynthBgm(moodFromHint(ref));
    return;
  }
  const token = tr.token;
  void loadSample(ref).then((buf) => {
    if (token !== tr.token) return;
    if (buf) {
      if (track === 'ambient') setSynthAmbient(null); // sample wins, silence the synth
      else if (track === 'bgm') setSynthBgm(null);
      playTrackLoop(track, ref, buf, token);
    } else {
      // Load FAILED → synth fallback (D2). theme has no synth → stays silent.
      const stem = synthHintFromUrl(ref);
      if (track === 'ambient') setSynthAmbient(toneFromHint(stem));
      else if (track === 'bgm') setSynthBgm(moodFromHint(stem));
    }
  });
}

/** Re-assert every clip ramp from now (mirrors rampAmbient, audio.ts:303). */
function rampClips(): void {
  const c = ctx;
  if (!c) return;
  const t = c.currentTime;
  const ids: TrackId[] = ['ambient', 'bgm', 'theme'];
  for (const id of ids) {
    const clip = tracks[id].clip;
    if (!clip) continue;
    clip.gain.gain.cancelScheduledValues(t);
    clip.gain.gain.setValueAtTime(clip.gain.gain.value, t);
    clip.gain.gain.linearRampToValueAtTime(SAMPLE_LEVELS[id], t + AMBIENT_FADE);
  }
}
```

> 注意：`loaded` 从 `decodeCache` 的**成功项**派生。失败项在 `loadSample` 里 `decodeCache.delete` 了（纳入 failCached），所以"在 decodeCache 且不在 failCached" = 成功。无 ctx 时无人 `decodeCache.set`，故 `[]`（§2.4）。

## 10. 发现的冲突 / 需修订上位文档

> 本节登记的 4 条冲突**均已被主 agent 裁决**，契约 `00` 已同步更新。以下保留"发现→裁决"留痕，便于 `06` 的契约修订追溯。
> 另：勘误广播已修正 `00` 的 5 处（Foley 调用点、`BGMood` 拼写、stinger 目录、`gate-open`/`page-turn` 不接线、`:106` 行号），本文已按新口径写。

### 冲突 1（load-bearing）→ **已裁决：服务端解析**

原 `00 §4.3` 写 manifest "原样透传" `world.json.audio.theme`（裸键 `"whitechapel"`），与 `00 §9` 反模式 2（前端不解析）及 `§1` 图（要 URL）自相矛盾。**裁决**：`/api/manifest` 由服务端用 `resolveAudioRef` 解析为 URL 再吐（`01 §5.2` 已落地；`00 §4.3` 已改）。本文 `setTheme` 只收 URL（§3.6）即按此写；裸名 theme 的"warn 不播"分支保留（不修则世界主题曲永远无声）。

### 冲突 2 → **已裁决：引擎自建 foley/stinger URL 合法**

`playStinger` 要拿 `stinger/<emo>.mp3`、`playFoley` 要拿 `foley/<name>.mp3`，但**无任何服务端字段**提供它们。**裁决**：`00 §9` 反模式 2 已精化——禁的是"解析 **README 声明的裸名值**"，**引擎自建平台固定约定 URL（键=文件名，非声明值）明确允许**。本文 §3.7/§3.8 写法正确，**不需要** `01` 加 `foleyBase`/`stingerBase` 字段。

### 冲突 3 → **已裁决：theme 失败 = 静音**

`00 §7` 表首行"失败回落合成"对 `ambient`/`bgm` 适用，但 `theme` 无合成引擎。**裁决**：`00 §7` 已补行「`theme` 失败 → 静音（无合成可回退）」。本文 §3.4 表 `theme` 行正确——不拿 drone 冒充世界主题曲。

### 冲突 4 → **已裁决：本批不删**

`unlockOnFirstInteraction()`（`audio.ts:614-622`）全仓零调用（`grep` 实测）。**裁决**：`00 §9` 新增反模式 8 明确"只登记，不删"（死代码但超出 A1 范围）。本文不动它。

> **4 条全部消解**，无遗留需修订项。`06` 请将这 4 条裁决连同勘误并入"契约修订留痕"。
