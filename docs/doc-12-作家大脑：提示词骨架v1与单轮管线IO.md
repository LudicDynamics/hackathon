### #6 展开：为什么"下一步"要单独占一条

前五条解决的都是"让 agent 知道世界什么样"。但试玩里 agent 卡壳的典型形态不是**不知道**，而是**知道了却不动**——注入块把场景、背包、最近事件全报了一遍，末尾什么也没说，于是作家又写一段风景描写，角色又寒暄一句。

所以注入的最后一段必须是**祈使的**，且只能由**事实推出来**，不能是空泛的"请继续推进剧情"：

- 有未回应的玩家动作（事件段里最新那条是 `choice_selected` / `use_item_on` / `roll_resolved`）→ "玩家选了 B / 掷出 14，**这一结果还没有被叙事回应**"；
- 有刚生成、玩家还没看过的东西 → "第一幕已落，玩家尚未进入该层"；
- 什么都没发生（状态块全部"同上一轮"、事件段为空）→ 明说"世界无变化，**不要为了填空而写**"——这一句同样重要，它是 doc-05 §5.1「事件不打断作家」的提示词侧配套。

**边界**：这一段只陈述"什么悬着"，不替 agent 做决定（不写"你应该让老板娘开口"）。判据同 doc-22 §3.3——注状态不注剧情。

## 边界

- 这是**提示词文本工程**，不是引擎功能——所有条目进 preset slot，不是新版引擎代码；**怎么写**（文风、结构、坑怎么记）另有规范见 **doc-23**，本文只管**写什么**；
- 不翻旧账：wc 的一部分（提示词骨架）赛前 A 类已由明月写，本文是把它补全成"可读的完整骨架"。

## journal 为什么不做（2026-09-12 撤销）

原设计里 `journal/` 是"故事的摘要记载"，配一个滚动摘要宏注入作家上下文（本文原 #2、doc-08 候选方向、doc-18 §3.4 #1）。现在整条撤销，三个理由：

1. **journal 本质就是作家的记忆系统**，而角色记忆系统已经暂缓（doc-13）。只给作家单建一套记忆层不对称；且"把已经写在世界文件里的东西再抄一份进专用记忆目录"正是 doc-05 §8.5 反复拒绝的第二真相源的近亲。
2. **剧情板书如今一律老老实实落在场景目录里**。chalk 从不主动消失、fold 是无损重组（doc-08 定案 1/2），"故事写在哪"已经有答案了——journal 只是同一批内容的第二份副本，还得靠作家的自觉去同步。
3. **摘要宏原本要解决的"作家忘了前情"已经换了解法**：doc-22 的状态块（当前值）+ doc-21 的事件段（变化）每轮进上下文，会话本身的压缩归 pi-rp（preset `hiddenOverrides.compaction`）。三者都天生有界，不需要再叠一层 journal 摘要。

**因此不做**：journal 摘要宏 / `journal/存档/` 归档 / 世界模板预置 `journal/` 骨架 / 进程重启后的"journal 恢复"（doc-07 C3b、doc-16 #4 相应作废）。

**没有禁止的**：作家想写一篇总览性的长文（阶段回顾、人物关系梳理），直接 `chalk` / `write` 落在相应的层里就是了——那是普通世界内容，不需要一个专门的目录协议来批准它。

> 同 doc-13 的口径：这是**暂缓**，可基于试玩失败重新立项（"作家确实记不住跨层的长线伏笔"）。而 state / 状态文件那一类是**绝对不做**，两者不要混。
