# 画布重叠治理与整理 Agent：设计评审汇总

> 日期：2026-09-14。本文汇总 06–12 设计稿和三位只读评审的结果，不实现代码。评审结论为**暂不通过实现门**：方向已清楚，但跨篇契约仍有真实 blocker。实现前必须完成本文的收敛并重新评审。

## 1. 已确认的产品解法

### 1.1 生成源与画布写入分两层治理

- 生成源先修 Writer 同一 `agent_start` 内反复注入同一 `llmRole:'user'` 状态块导致的 Chalk 自激；`extensions/context.ts:125-193` 是证据，跨进程实测旧 guard 在 max=2 时 50 次均放行。guard 只能限流，不能当根因修复。
- 坐标源修复 `seatNear` 读—算—写竞态、旧 arrange 子集忽略未选障碍、玩家多卡逐条 last-writer、footprint 时序和幻影接管。所有持久写入仍只经过 ActionService/LocalWorldStore，`canvas.db` 是画布坐标真相。
- 生成中 Chalk 不能绘到邻卡。07 必须最终选定动态占位、safe clipping 或 delayed readable 之一；正式 row 接管是另一条验收线。

### 1.2 整理 Agent 的最小闭环

```text
玩家点击 → 独立 functional canvas-arranger session
  → view_canvas(auto) 读取真实 rows/overlaps/unplaced/links/presence/viewpoint
  → 必要时 screenshot_canvas 读取同一 Canvas DOM 的真实 PNG
  → arrange_canvas 通过服务端 planner + 版本/事务安全闸
  → view_canvas(auto) 复读最新 rows 并全层 AABB 校验
  → canvas_patched + agent_activity 到达前端
  → 本地状态完成/partial/failed/conflict/cancelled
```

关键边界：不占 Writer queue、不写 Markdown/frontmatter、不改玩法、不直接 SQL、不新增第二 WebSocket。模型坐标、截图视觉印象、action 回包和 staging 都不能单独证明完成。

## 3. 评审后的推荐默认裁决

为避免实现继续分叉，主代理建议采用下列低复杂度默认：

1. **工具**：`view_canvas(auto)`、`screenshot_canvas`、`arrange_canvas`；保留既有 `view_canvas` 名称，只新增后两者。
2. **视觉完成闸**：不把第二个视觉模型塞进本批 runtime；由 screenshot route 返回 PNG + DOM rendered geometry，服务端最新 rows AABB 是硬完成闸。12 可以保留 Nodesign vision-checker 作为未来可插拔增强，但不能成为当前必需字段。
3. **失败**：pre-commit screenshot failure = failed/no-write；post-commit visual/DOM failure = partial/conflict + 保留事实；所有 UI 文案显式区分。
4. **外部身份**：HTTP 只暴露 opaque worldId；内部 server 将它解析到 active world root。`canvasVersion`、`canvasRevision`、`snapshotId` 各自只承担单一语义。
5. **结构保留**：服务端只承诺机器可复核的 links/card identity 与最小相对关系；不能让模型凭 receipt 自报“保留分组”。
6. **生成中 Chalk**：优先 delayed readable——先展示 shell/ink tip，正式落地或安全 footprint 确认后再展示正文；这样不会把 overflow 交给 CSS 假装解决，也不改 cards 真相。

这些是建议默认，不等于已冻结代码契约；B/C/D/F/E 必须把同一裁决回写到各自文档后，再由评审复核一次。

## 4. 推荐实施顺序（仍未开始）

1. 先实现并证明 E-GEN-01：修复同一 Writer run 的 one-shot continuation，防止座位算法掩盖额外 Chalk。
2. 冻结 Actor/Scope、worldId、error/outcome、tool/HTTP/schema 集合；建立可机械双向检查。
3. 建立 `canvasVersion` 与唯一 atomic canvas writer，迁移 near、seat/reseat、footprint、drag batch、旧 position/arrange 的写入口；所有旧入口不能绕过安全闸。
4. 落实 delayed readable phantom 与正式 footprint 接管，执行真实 DOM red→green。
5. 实现 read-only `CanvasSnapshotV1`、server-side Playwright gate/capability 和 `screenshot_canvas`；禁止写 viewpoint/footprint/WS。
6. 实现独立 functional runtime、preset、白名单和取消/世界切换 fence；只加载三项模型工具，不能复用 Writer session/queue。
7. 实现左侧按钮/本地 conflict 状态/i18n；运行 HTTP/WS/浏览器/无障碍验收。
8. 回写 00/06/07–12、tools/agent-awareness/wiring 及文档索引，重新通过评审门后才进入实现。
