# docs/layout/04 — 生成批次与初始化接缝

## 一句话定位

把「文件何时可见」与「卡片何时取得坐标」拆开：一次 `seatUnplaced(layerId, files)` 只为该次读取中仍无 canvas 行的文件形成一个自动批次，生成器只负责产出文件/事件，服务端在可重试的 `/layer` 读取中以稳定排序调用共享 `flowColumns`，随后由幻影和真实层状态完成接管。

## 1. 现状证据与本篇边界

| 事实 | 证据 | 对本篇的影响 |
|---|---|---|
| Chalk 是写叙事正文的动作；新建后写 `entity_created`，追加后写 `entity_edited` | `packages/shared/src/actions/chalk.ts:388-527` | 新建 Chalk 才是候选新卡；`append_to` 不是新卡，不能因此重排或新建座位 |

本篇只设计生成、取数、批次、排序和初始化接缝；不改 `docs/layout/00-共同上下文.md`，不拥有 `flowColumns` 的几何实现，不重新设计 footprint metadata、幻影注册表或 Chalk 拖拽权限。

## 2. 冻结术语：一次调用就是一个批次

定义（引用 `docs/layout/00-共同上下文.md:73-86`）：

> **自动批次 = 一次 `seatUnplaced(layerId, files)` 调用在临界区内确认没有 canvas 行的 `files` 集合。**

因此：

1. 目标 `/layer` 在同一快照内把当前页面完整 `items` 传入 `seatUnplaced`；store 再次以 path 检查行，并只把仍无 row 的 `files` 作为本批最终集合。当前代码仍先传 `unseated`，这是本批待实现的 occupied 修复点，不是目标口径。
2. 同一 writer turn 写下的多文件，若在一次 `/layer` 快照建立前都可见，就在一次调用中同批进入 `flowColumns`。
3. 文件监听先看到 Chalk、后看到组件，或两次 `/layer` 之间只完成一部分写入，则形成两个批次；第二批只使用剩余无行文件，第一批座位不动。
4. 已有 row 的文件即使正文被 `edit` 修改，也不是自动新批次；只有 footprint 变化按 `docs/footprint/00` 的规则进入 `reseatLayer`，且只影响触发变化的行。

**漏了第 1 步会怎样：** 把已经有 row 的文件再次当新卡，跨次追加会重排旧卡；或只把 `unseated` 传入 store，使 occupied 漏掉同页已有卡与跨层 README 门牌，导致右扫验收继续失败。

## 3. 同一 writer turn 的排序提示

### 3.1 排序目标

同批排序不能把「目录枚举顺序」或 SQLite 返回顺序当成叙事顺序。`flowColumns` 的冻结不变量是先 `order`、再 `id`（`docs/layout/00-共同上下文.md:144-153`）。因此“阶段优先”必须先在调用方编成 `SeatFile.order`，不能让一个任意的调用方提示越过 Chalk 护栏：

```text
先按来源阶段 rank：chalk(0) < component(1) < other(2)
阶段内按调用方提示 / 已知创建事件 seq
最后按 ASCII path
→ 将上述结果重新编号为连续的 SeatFile.order
→ flowColumns 只看 order，再以 id 作最终稳定 tie-break
```

`SeatFile.order` 只能表达**阶段内的批内顺序提示**，不能编码 batch id、turn id、时间戳或 footprint；新增形状如下（NEW）：

```ts
export interface SeatFile {
  path: string;
  w?: number;
  h?: number;
  kind?: string;
  formVersion?: string;
  /** NEW：调用方提供的阶段内顺序提示；不是批次身份，也不写 metadata。 */
  order?: number;
}
```

实现时 `GET /layer` 或 `seatUnplaced` 必须先做上面的 stage-major 排序，再把排名写入传给 `flowColumns` 的 `AutoLayoutBox.order`；**不得直接把未经阶段约束的外部数字转发给 flowColumns**。这样即使组件文件名小于 Chalk，组件也不会抢到 Chalk 的第一格。若没有提示，仍按阶段内 event `seq`、再 ASCII path；原生 write 的缺失提示不能伪造。

`flowColumns` 最终仍只接收 `AutoLayoutBox.order?: number`，不读取文件、事件或 DOM（`docs/layout/00-共同上下文.md:133-153`）。几何函数不猜来源，批次边界和 stage-major 排序归调用方。

### 3.2 提示来源与 Chalk 优先

1. **Chalk action 新建**：`writeChalk` 在写文件成功后追加 `entity_created`（`chalk.ts:488-527`）。服务端可用该事件 `seq` 作为同阶段次序；同一 writer turn 内 `submitWriter` 会串行解决 beat（`apps/server/src/engine/lifecycle.ts:125-147`），但不能把 turn 本身当批次。
2. **Chalk append/edit**：`append_to` 只走 `entity_edited`（`chalk.ts:408-429,510-519`），绝不提供新卡排序提示，也不进入 `seatUnplaced`。
3. **通过 action 创建组件**：`createEntity` 写文件后追加 `entity_created`（`packages/shared/src/actions/create.ts:103-126`），用事件 `seq` 作同阶段次序。
4. **原生 write 新建组件**：它没有 world event，不能伪造 `seq`。`GET /layer` 将其归入“已注册 component kind”阶段，使用稳定 ASCII path；如果未来要保留调用方精确顺序，应由写入接缝在内存/独立 layout-order sidecar 中产生 `order`，而不是修改 footprint metadata。
5. **同一 turn 的安全默认**：`kind === 'chalk'` 的默认阶段先于 `componentDefOf(kind) !== null` 的注册组件 kind，注册组件又先于其它实体；因此组件不会因为 `componentName < 01-chalk` 而占据 Chalk 的第一格。阶段内再用 action `seq`，缺失时用 ASCII path。这个默认是视觉叙事护栏，不声称可以恢复原生 write 的真实调用时刻。
6. **初始化器的多文件**：`layer_initialized.files` 仅是产物清单（`packages/shared/src/actions/layer.ts:91-103`；schema 见 `packages/shared/src/schemas/events.ts:96-101`），不是坐标或 batch metadata。若实现能保留 initializer 的计划顺序，可把列表索引作为 `SeatFile.order`；否则使用同一 `kind` 阶段内 ASCII path，仍保证每次结果相同。

**漏了阶段 rank 会怎样：** 同一个 turn 生成 `00-lock.md` 组件和 `01-fog.md` Chalk 时，纯字典序会先放 lock，读者先看到陈设而非叙事入口；修复前非空性测试见 §10。

### 3.3 不能用哪些东西排序

- 不能使用 `cards.metadata`：footprint metadata 冻结为 `formVersion / measuredAt / seatW / seatH` 四键，见 `docs/layout/00-共同上下文.md:84-86` 与 `docs/footprint/00`。
- 不能使用 SQLite `SELECT` 返回顺序；既有 `getLayerCards` 只按查询结果建 Map，未承诺顺序（`local-store.ts:577-589`）。
- 不能使用 fs.watch 回调抵达顺序：watcher 会防抖且 `filename` 可能为空（`event-bridge.ts:446-462`）。
- 不能把 event `seq` 直接当自动批次 id；它只说明事件提交顺序，且原生 write/edit 没有事件。
- 不能让初始化器输出 x/y；初始化器是文件生产者，座位仍归存储层 + `flowColumns`（`docs/layout/00-共同上下文.md:199-207`）。

## 4. 现实竞态：怎样让一次 `seatUnplaced` 调用成立

### 4.1 竞态时序

典型场景：Chalk 写完，组件仍在写；文件 watcher 第一次回调触发 `/layer`；同时第二个 watcher 回调、`world_event` 或用户刷新又触发 `/layer`。

```text
T0  writeChalk 写 Chalk 文件，随后追加 entity_created；组件 write 尚未完成
T1  fs.watch → file_changed；GET /layer-A 看到 Chalk，无 row
T2  component write 完成；GET /layer-B 看到 Chalk + component，无 row
T3  GET-A / GET-B 的 seatUnplaced 若都先读再插，会各自用旧 occupied 算坐标
T4  world_event / 下一次 file_changed 再次 fetch；真实 rows 胜过幻影
```

在同一 Node 进程内，当前 `seatUnplaced` 的读完后循环没有 `await`，所以两个 route callback 不会在该同步区间交错；但 `GET /layer` 在 `pageOfLayer`、`readFile`、`getLayerCards` 前有多个 await，跨进程/多连接或未来把座位计算改成异步后，读→插入仍可能交错。这是必须测试而不是凭事件顺序假定的边界。

### 4.2 原子性与幂等判据

实现必须满足下面的可机械核验判据：

- **同一路径唯一行：** 任意数量并发 `/layer` 后，每个新文件最多一个 `cards.id = path` row。
- **同一批不重叠：** 一次调用返回的 placements 互不重叠；并发调用合并后的所有新 rows 也不得因各自旧 occupied 快照而重叠。
- **旧卡不动：** 并发首读不能更新已有 row 的 x/y/z；只有 footprint 变化按 `reseatLayer` 规则移动变化卡。
- **重放稳定：** 第二次对同一文件集合调用 `seatUnplaced` 返回空数组（或仅返回已存在 row 的等价无动作结果），不改变 x/y/z。
- **部分批次可合并：** A 只看到 Chalk、B 只看到组件时，B 的 occupied 必须包含 A 已提交的 row；B 不能重算 A。

推荐实现接缝：在 `LocalWorldStore.seatUnplaced` 内以已有 SQLite 写事务原语（`writeFootprints`/`applyPlaceCard` 已使用 `BEGIN IMMEDIATE`，`local-store.ts:881-925,1002-1014`）包住「重新读 rows → 计算 `flowColumns` → 插入全部 rows → COMMIT」；冲突/忙时让调用方按有限次数重读，不能用 stale placements 继续写。`ON CONFLICT(id) DO NOTHING` 仍保留作最后一道行幂等保护，但**不能**单独证明几何安全：两个调用若各自为不同 path 计算同一 anchor，唯一键不冲突，仍会重叠。

这条复用的是 `docs/layout/00-共同上下文.md §3.1` 明确允许的既有 SQLite 原子写事务，不新增锁表、文件锁或跨进程业务状态源；实例内 `withSeatLock` 只是减少同一 Node 进程的重复计算。事务必须覆盖重新读取 occupied/maxZ、计算与插入，不能只包 INSERT。

**漏了事务/等价串行化会怎样：** 两个快照都看到空 occupied，各给不同 path 同一候选点；最终虽有两行、也各自成功，却出现视觉重叠。这不是 `reqSeqRef` 能修复的服务端事实。

### 4.3 失败、忙、重试

- `flowColumns.exhausted === true` 不是成功失败二元值；调用方必须保留最后候选并产生开发者可见诊断，不能回退中心重叠点（`docs/layout/00-共同上下文.md:149-153`）。
- SQLite busy/事务冲突：回滚本次未提交座位，短暂退避后重新读取；重试必须重新计算 occupied，不得重放旧 placement。
- 单个文件缺失/读失败：从本次 `files` 丢弃并等待下次 `file_changed`/`world_event`；不能用猜测的 w/h 或伪造 row。
- 文件已存在但 row 已由另一调用提交：视为幂等命中，重新读 row 并从本批排除；不得 UPDATE 它来“纠正”位置。
- 初始化失败不由座位层吞掉：`layer_init_failed` 由 I1 action 记录，场景 W2 是否落盘由 init 契约决定；有实际文件的后续 `/layer` 仍按普通文件批次处理。

## 5. I1 scene/nook init：初始化器不拥有坐标

### 5.1 场景初始化

`airp-init` 的冻结执行序是解析/判空 → 拼 brief → spawn → 检查产物 → `recordLayerInitialized` 或 `recordLayerInitFailed`（`docs/init/00-共同上下文.md:67-84`）。它只能写目标目录文件并记录结果：

1. `scene-init` 成功，目录至少出现 `README.md`，记录 `layer_initialized { layer, by, files }`。
2. 失败或完成但无产物，走 W2 写 `README.md` + `opening.md`，再记录 `layer_initialized` 或失败事件，取决于 init 内核分流；W2 文件同样不带 x/y。
3. `/layer` 读到这些文件后，README 作为 `scene` 独立返回，不作为本层 `items` 再座一次（`world.ts:655-674`）；`opening.md` 等普通卡才进入 seatUnplaced。

**漏了“README 不入 items”的边界会怎样：** 初始化入口会在父层门与自身场景重复生成同一路径的两个座位，且一张文件拥有两个 x/y 真相。

### 5.2 小天地初始化

nook-init 同样只产出文件并记录 `layer_initialized`/`layer_init_failed`；失败按冻结契约 `fallback: 'none'` 不写 W2 nook 模板（`docs/init/00-共同上下文.md:255-260`）。本篇不把 nook 文件加入 `/api/layer`，也不改变 `GET /api/nook`；若 nook 页面未来需要排座，必须继续复用同一 seat/flow 接缝，不能让 initializer 自己发坐标。

### 5.3 判空、幂等、重试

- 顺序重复：`isLayerEmpty`/`isNookEmpty` 在命令开始判空，已有内容则短路（`docs/init/00-共同上下文.md:67-72,120-150`）。
- 并发重复：`airp-init` 进程内以 `kind:target` in-flight 集合挡双击（`docs/init/00-共同上下文.md:88-92`）。这只保证同一 initializer 不跑两次；它不取代 `seatUnplaced` 的数据库原子性。
- 场景失败重试：W2 使 README 存在，下一次进入按判空短路；部分产物是否保留由 `hasInitProduct`/W2 分流，不由 canvas 座位补救。
- nook 失败重试：无模板时可再次触发；已经成功写出的文件在下一次 layer/nook 读取中按“无 row 才入新批次”处理。
- `layer_initialized.files` 是审计与产物清单，不是坐标清单；不要添加 x/y、w/h、batch id 或 metadata JSON。

## 6. 首次进入、GET /layer 与两条 WS 信号

### 6.1 首次取数不是完成通知

`enterLayer` 在看到目标目录没有 README 时返回 `first: true`，随后 web `enterLayer` 在允许自动写时发 `{ type:'airp_init', ... }`，并立即 `fetchLayer(next)`（`apps/web/src/state/useWorld.ts:179-198`）。因此可能出现：

- `first=true` → 初始化尚未开始/仍在生成 → 首个 `/layer` 返回空或仅有旧门；
- 初始化器写入一部分文件 → watcher 防抖触发再次取层；
- 事件尾读到 `layer_initialized` 或 `entity_created` → `world_event` 触发再次取层。

`GET /layer` 的响应本身只返回 `{ layer, scene, bg, audio, items, links, presence, worldFrozen }`（`apps/server/src/routes/world.ts:706-726`），没有“批次完成”字段；这正是文件/row 当前状态的快照，不应扩成第二个世界真相源。

### 6.2 `file_changed` 与 `world_event` 的职责

- `file_changed`：文件系统变化的整层重取触发器；不是事件审计，也不是“初始化完成”。同批多文件可能被防抖合并，也可能分成多个 fetch。
- `world_event`：事件表已提交后的世界语义通知；`entity_created`/`entity_edited`/`layer_initialized` 等由尾读广播。前端 `useWorld` 对事件去重后按现有规则重取，真实 `/layer` 坐标优先（`docs/wiring/00-共同上下文.md:87-96`；`docs/layout/00-共同上下文.md:189-195`）。
- 两者都可能先后到达、重复触发；`reqSeqRef` 使较早响应不能覆盖较新的请求（`apps/web/src/state/useWorld.ts:147-173`）。这只防客户端快照倒退，不负责服务端座位排版。
- 若文件由原生 write/edit 写入且无 world event，`file_changed` 是唯一已知触发；因此不能要求每次自动批次都有 `world_event`。

## 7. 幻影、真实座位与 footprint 纠偏闭环

```mermaid
sequenceDiagram
  participant W as Writer / I1
  participant FS as world files
  participant WS as EventBridge
  participant P as Phantom registry
  participant API as GET /layer
  participant DB as canvas.db
  participant F as browser footprint

  W->>FS: chalk / native write-edit / initializer writes files
  W->>WS: action world_event (仅 action 路径；native write/edit 无 event)
  WS-->>P: chalk_writing/image_generation_progress → flowColumns 临时 seat
  FS-->>WS: fs.watch → file_changed (150ms debounce)
  API->>FS: read current files and README
  API->>DB: seatUnplaced(layerId, no-row files)
  DB->>DB: transaction: reread + flowColumns(boxes, occupied) + INSERT
  DB-->>API: real CardRecord x/y/w/h/z
  API-->>P: items with real seats; reconcileLanded 撤 ghost
  WS-->>API: world_event/entity_created or layer_initialized → refetch
  F->>API: POST /card/footprint(real w/h)
  API->>DB: writeFootprints (只改 w/h + 四键 metadata，不改 x/y)
  API->>DB: next GET /layer → reseatLayer(变化卡, measured w/h)
  DB-->>API: shared flowColumns; stable siblings remain obstacles
  API-->>P: real corrected coordinates win; no new WS frame
```

| 阶段 | 输入 | 座位拥有者 | 失败/漏接后果 |
|---|---|---|---|
| 生成中 | `chalk_writing` 或 image progress、临时尺寸 | 前端幻影调用共享 `flowColumns` | 自造 spiral 会与服务端视觉分叉；幻影不能拖 |
| 文件落地 | `chalk_landed`/`image_landed` 或 file visible | 仍是幻影旧座位，等待真实层 | land 时重新排会跳位；应是座位过户 |
| 首次真实取层 | `GET /layer` 的 no-row files + 当前 rows | `LocalWorldStore.seatUnplaced` + DB | 未包住竞态会同点重叠；重复取层必须幂等 |
| 浏览器稳定测量 | DOM footprint | `writeFootprints` 只改真实 w/h/metadata | 把 x/y 写回会误伤玩家位置；漏 `reseatLayer` 会真实盒子重叠 |
| 纠偏取层 | 变化卡 + 稳定兄弟障碍 | `reseatLayer` 调共享 `flowColumns` | 重排全部卡会把玩家已摆位置吞掉 |

幻影注册与过户复用 `docs/perform/00-共同上下文.md:145-159` 的 `phantom.ts`；真实 `items` 到达后由 `reconcileLanded` 撤影，服务器坐标优先。自动 seat 直接写 `cards`，**不发 `canvas_patched`**：`canvas_patched` 属于显式 canvas action 的增量补丁，而本篇的世界文件落地由 `file_changed`/`world_event` 触发真实重取；不新增 WS 帧（`docs/layout/00-共同上下文.md:189-195`）。

## 8. 跨次追加：只给新卡找位置

情形：第一次 fetch 只看见 `01-fog.md`，第二次 writer turn 追加 `02-door.md` 与一个组件。

1. `/layer` 以当前 `items` 建 `rowByPath`；`01-fog.md` 有 row，因此绝不进入第二批的 `missing`。
2. 第二批的 `occupied` 必须包含 `01-fog.md` 的当前真实矩形、所有其它已有卡以及本批已放的文件；`flowColumns` 只为 `02-door.md` 和新组件找列流位置。
3. `flowColumns` 的“旧障碍继续向右扫描”保证新增内容避开玩家卡与旧自动卡；不能为了回到 origin 而移动旧卡。
4. 已有卡被玩家 `arrange({place})`/拖拽后，其 x/y 是稳定障碍；新批次不吸附、不整理旧卡。
5. 若旧卡的真实 footprint 后来变化，只有该变化卡进入 `reseatLayer`；稳定兄弟仍保留原位置并作为 occupied。纠偏不是新批次，也不应借机重新排序所有文件。

**漏了 §8.1 会怎样：** 每次文件监听都把全层文件传给自动排版，旧卡会不断跳回列首，玩家拖好的空间和叙事阅读位置均失效。

## 9. 输入、输出与副作用

### 输入

- `layerId: string`。
- `files: readonly SeatFile[]`，其中 `path`、真实服务端 w/h、kind/formVersion 和可选 `order`；w/h 来自服务端存储/声明规则，不读 DOM。
- `occupied` 由当前层既有 rows（以及幻影侧同层幻影）形成；自动真实座位不把客户端猜测当真相。

### 输出

- `seatUnplaced` 返回本次新建/确认的 `CardRecord[]`；每行含真实 `x/y/w/h/z` 与四键 metadata。
- `/layer` 返回当前快照的 enriched items；没有 batch id，也不承诺该快照是初始化最终态。
- `world_event`、`file_changed` 仍使用既有帧名；自动座位本身无事件/无新帧。

### 副作用

- 只在 `canvas.db.cards` INSERT 新行；`metadata` 只写 footprint 四键允许的座位基线，不写顺序/来源/batch。
- 文件正文由 Chalk、原生工具或 init 写入；seat 层不改正文，不让初始化器写坐标。
- `flowColumns` 纯计算，不读 DOM、不写 DB、不发事件（`docs/layout/00-共同上下文.md:133-153`）。

## 10. 验收用例（含修复前会失败的非空性）

跳过全量 build/test/lint；主 agent 统一运行项目门禁。本篇验收应至少覆盖：

1. **同 turn Chalk + registered component 的非空性反例（修复前失败）：** fixture 同层有 `00-lock.md (kind=lock，且 lock 是真实注册 component kind)` 与 `01-fog.md (kind=chalk)`，两者无 rows、相同 declared footprint。运行当前旧 `path.localeCompare` 排序，断言第一 placement 的 id 是 `01-fog.md`（旧实现会得到 `00-lock.md`，断言失败）；接入阶段 rank 后断言 Chalk 先放，且两矩形不重叠。
2. **并发非空性反例（修复前失败）：** 用两个受控 `seatUnplaced` 调用在“读完 rows、插入前”暂停，分别提交不同 path。旧实现两调用都看到空 occupied，最终两行坐标相同/重叠；断言修复后所有 pair `!boxesOverlap`，且两调用合计两行。若实现决定不采用事务，必须把本用例列为阻断而非放宽断言。
3. **同 path 幂等：** 并发/重复调用同一 path，`cards` 只有一行，第二次不改变 x/y/z/metadata。
4. **部分可见分批：** 首次只写 Chalk 并取层，第二次再写 component 并取层；第二次结果只含 component 新座位，Chalk x/y 与 z 不变。
5. **初始化接缝：** `enterLayer` 返回 `first=true` 后立即 GET 可见空/部分状态；scene-init 成功事件到达后，后续 `file_changed`/`world_event` 取层出现文件；README 不在自身 `items` 里重复座位。nook 失败 `fallback:none` 不凭空出现 nook 模板。
6. **过户与 footprint：** 幻影先用同一 `flowColumns` 临时座位，真实文件出现后 `reconcileLanded` 移除幻影；DOM 测量只改 `w/h` 和四键 metadata，下一次 GET 只纠偏变化卡，玩家拖过的稳定兄弟不动。
7. **canvas_patched 负断言：** 自动文件落地/自动 seat 不产生 `canvas_patched`；显式 arrange/canvas action 的既有帧语义不被改写。
