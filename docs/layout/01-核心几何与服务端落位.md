# docs/layout/01 — 核心几何与服务端落位

## 1. 一句话定位

把服务端所有“自动给新卡找座位”的几何收敛为一个无副作用的 `flowColumns`：同一批卡按确定顺序自上而下流入列，使用 `cards.width/height` 的真实占位绕开旧卡，并让 footprint/kind 漂移只重排真正变化的卡。

本篇只设计共享几何与 `LocalWorldStore` 落位接缝；不改 `docs/layout/00-共同上下文.md`，不设计 Canvas/幻影实现，不扩展 WS 帧。

## 2. 现状证据与目标边界

- 当前 `LocalWorldStore.seatUnplaced` 在 `packages/shared/src/store/local-store.ts:592-676` 中按 `path.localeCompare` 排序，并以 `SEAT_ANCHOR`、`SEAT_STEP` 和 `spiralCells()` 搜索候选（常量见 `local-store.ts:20-27`）。这只表达“找到一个空格”，不表达从上到下的叙事流。
- 当前 `seatUnplaced` 的占用集在 `local-store.ts:610-616` 建立；同批新座位随后必须加入占用集并推进 z。批内修复已经存在于 `local-store.ts:666-675`：`occupied.push(...)` 和 `nextZ++`。替换 spiral 时 MUST 保留这两个不变量，不能回退到同批同点、同 z。
- `GET /layer` 先获取文件并构造 `rowByPath`（`apps/server/src/routes/world.ts:577-615`），再对无行文件调用 `seatUnplaced`（`:616-624`），之后调用 `reseatLayer`（`:626-634`）。这使 `/layer` 成为自动批次进入服务端画布的接缝。
- `reseatLayer` 当前在 `local-store.ts:679-857` 已区分 declared/kind drift 与 measured footprint drift；但实际落位仍是 `spiralCells()`（`:806-819`），需要把几何替换为同一 `flowColumns`。
- `cards.width/height` 的唯一真相、I1/I2、metadata 四键和“实测值不可被 declared 冲回”见 `docs/footprint/00-共同上下文.md §3.1-§3.2、§5.1-§5.2`。本篇不把 `CARD_FORMS.h` 当已排座卡的真实高度。
- `arrangeCards` 的显式布局会调用 `boxesOf` 和 `placeCards`（`packages/shared/src/actions/canvas.ts:561-576`）；`placeCard` 的尺寸拒绝与 x/y/z 语义在 `canvas.ts:429-479`。它不是自动 flow 的入口。

目标是“可读的列流 + 不挪稳定卡”，不是每次刷新整理全层，也不是把所有卡强制变成网格。

## 3. 几何接口（冻结形状的实现落点）

### 3.1 唯一纯函数

新增文件：`packages/shared/src/layout/flow-columns.ts`（**NEW**，由 `packages/shared/src/index.ts` 显式导出）。完整接口沿用 `docs/layout/00-共同上下文.md §4.1`，不在本篇改形状：

```ts
export interface AutoLayoutBox {
  id: string;
  w: number;
  h: number;
  order?: number;
}

export interface AutoLayoutRect {
  id?: string;
  x: number;
  y: number;
  w: number;
  h: number;
}

export interface FlowLayoutConfig {
  origin: { x: number; y: number };
  columnHeight: number;
  gapX: number;
  gapY: number;
  obstacleGap: number;
  maxColumns: number;
}

export interface FlowLayoutResult {
  placements: Array<{ id: string; x: number; y: number; w: number; h: number }>;
  exhausted: boolean;
  columnsUsed: number;
}

export function flowColumns(
  boxes: readonly AutoLayoutBox[],
  occupied: readonly AutoLayoutRect[],
  config?: Partial<FlowLayoutConfig>,
): FlowLayoutResult;
```

默认值必须是 `docs/layout/00-共同上下文.md §4.3` 的设计值：

```ts
{
  origin: { x: 360, y: 96 },
  columnHeight: 1080,
  gapX: 56,
  gapY: 32,
  obstacleGap: SEAT_PAD, // 当前为 22；实现时从共享布局模块引用同一常量
  maxColumns: 64,
}
```

`origin` 表示候选矩形左上角，而不是卡中心。默认 origin 不再使用旧的 `SEAT_ANCHOR = { x: 960, y: 540 }`（`local-store.ts:20-21`）；`SEAT_ANCHOR` 只可在 `seatNear` 的适配器中转成局部 origin，不能成为第二套 flow 默认值。

### 3.2 不变量与伪代码级行为

实现必须满足以下顺序；每一步漏掉的后果一并写明，施工时应把这些步骤直接转成单元测试。

1. **校验并冻结输入。** 复制/读取输入不得修改调用方数组；校验每个 `id` 非空且唯一、`w/h` 为有限正数，障碍矩形同样为有限正数，配置的 gap 不得为负、`columnHeight > 0`、`maxColumns` 为正整数、origin 有限。
   - 漏掉校验会把 `NaN`/重复 id 写进 `cards` 或让扫描永不终止；纯函数应抛出 `TypeError`/`RangeError`，不能静默改成 280×180。
2. **稳定排序。** 首先按调用方给出的有限 `order` 升序，再按 `id` 的稳定 ASCII 比较；没有 `order` 的输入按 `id`。不要依赖 SQLite 返回顺序、Promise 完成顺序或模型输出顺序。
   - 漏掉 tie-breaker 会让相同输入在不同 DB/运行时产生不同叙事顺序。
3. **建立占用视图。** 逻辑上把 `occupied` 与本次已经落位的 placements 合并；碰撞判定用实际矩形（左上角 x/y、真实 w/h），对障碍边界按 `obstacleGap` 膨胀。`gapY`/`gapX` 是同批卡之间的流间距，不可替代 obstacleGap。
   - 漏掉本批已落位矩形会复现 N1：多张无行卡相同 `(x,y)`；漏掉 obstacleGap 会让像素边缘贴合，前端视觉上仍像重叠。
4. **当前列自上而下尝试。** 第一列的 x 为 `origin.x`，游标 y 从 `origin.y` 起。候选矩形与任一占用矩形冲突时，沿 y 向下跳到冲突矩形的 bottom 加 obstacleGap，再继续检查；无冲突才放置。放下后本批占用集立即加入该矩形，下一张从 `placed.bottom + gapY` 开始。
   - 漏掉“跳过冲突后继续扫描”会把障碍当成 exhausted，或把新卡放在障碍上。
5. **列高溢出后右移。** 若当前卡放下会超过 `origin.y + columnHeight`，且它不是超高单卡，则结束当前列，开下一列；下一列 x 为当前列已放卡最大 right 加 `gapX`。新列的游标重新从 `origin.y` 开始。
   - 漏掉列边界会使一列无限向下，Chalk/长正文会压住视线下方内容；用固定卡高比较而不是候选的真实 h 会错误地容纳超高卡。
6. **右侧障碍继续扫描。** 新列候选如果与既有障碍在 x 方向相交并且 y 候选也会冲突，先把 x 推到相关障碍的 right 加 `obstacleGap`，再重新从该列的 origin.y 扫描。多个右侧障碍重复此步骤，直到候选列没有冲突；旧矩形永不移动。
   - 漏掉该步骤会把新列起点塞进旧卡，恰好是“第一列看似规整、第二列撞到玩家卡”的回归。
7. **超高卡特殊语义。** 若 `h > columnHeight`，该卡允许独占一列并跨越 columnHeight；若当前列已有卡，先开新列。它仍必须绕开障碍，且应在找到合法候选后返回 `exhausted: false`：超高是合法内容，不是算法失败。
   - 把超高卡当普通溢出会不断开列或把它标成 exhausted，前端/开发诊断会误报失败；把它截成 `CARD_FORMS` 名义高则违反 footprint I1。
8. **maxColumns 与 exhausted。** 最多尝试 `maxColumns` 列。达到上限且没有合法位置时，保留最后一个确定候选（而不是回到中心锚点或丢弃该 box），返回该 box 的 placement，并将结果 `exhausted: true`；每个输入 box 仍必须有一个 placement。调用方必须产生开发者可见的 `console.warn`/结构化诊断，不能伪装成成功。只要所有卡都合法落位，`exhausted` 为 false；超高卡本身不触发它。
   - 漏掉“最后候选”会让卡消失；回退中心会制造确定性的硬重叠；只打印日志而不在结果中传递 exhausted 会让调用方无法验收拥挤世界。
9. **返回值。** placements 按落位顺序返回，`columnsUsed` 为实际尝试/使用的列数（空 boxes 返回空 placements、0 列、false）；纯函数不读 DOM/相机、不写 DB、不落事件、不发 WS。
   - 漏掉稳定返回顺序会使座位过户和 API 响应抖动；在函数内写 DB 会让服务端和幻影不能共享同一几何。

碰撞判定应以闭区间外的矩形相交语义实现：加入 gap 后，只要 `a.x < b.x + b.w && a.x + a.w > b.x && a.y < b.y + b.h && a.y + a.h > b.y` 即冲突；仅边界相切不算冲突，但 gap 膨胀后通常仍会保留呼吸距离。

### 3.3 同批 Chalk/component 的确定顺序

`flowColumns` 不认识 frontmatter，也不读取 `CARD_FORMS`/registry；因此“chalk 应先于 component”必须在调用方变成 `order`，不能把 kind 规则偷偷塞进纯几何。

规范批次（`GET /layer` 的 `items`）使用以下确定排序键并分配连续的 `order = 0,1,...`：

1. 调用方显式 `order`（若输入产品/初始化链路已给出）优先；
2. 无显式 order 时，`kind === 'chalk'` 优先于注册 component kind；其余 kind 按既定 kind rank（gate/note 等）分组；
3. 同一 kind rank 内，basename 的 `NN-` 数字前缀升序（无前缀排在有前缀之后或由实现固定为一个明确值，不能依赖 locale）；
4. 最后用完整 POSIX path 的 ASCII 字节序作 tie-breaker。

该方案不增加 footprint metadata：`order` 只存在本次调用内的 `SeatFile`/`AutoLayoutBox`，不得写入 `cards.metadata`。应在 `apps/server/src/routes/world.ts` 的 `/layer` handler（当前构造 `items` 与 `unseated` 的 `:586-624`）实现一个调用方排序 helper（**NEW，完整签名建议如下**）：

```ts
type SeatOrderInput = Pick<SeatFile, 'path' | 'kind' | 'order'>; // NEW
function stableSeatOrderOf( // NEW
  files: readonly SeatOrderInput[],
): Array<{ path: string; order: number }>;
```

混合输入的规则也要固定：显式 `order` 为有限数字时优先；无 order 的项目在显式项目之后，按 kind rank/编号前缀/path 派生连续序号。规范 `/layer` 应始终一次性给全批分配 order，避免混合态依赖实现细节。

`SeatFile` 仅新增 `order?: number` 这一排序提示字段（**NEW**，不得扩展为 batch id 或任意 metadata）；`AutoLayoutBox.order` 使用同一个连续编号。`seatUnplaced` 收到已编号 files 后只负责保留 order 并交给 `flowColumns`。

兼容旧调用者：`actions/delete.ts:205-210` 的 `seatFileOf` 当前只返回 `{path,w,h}`，`actions/move.ts:172-183` 以单文件调用 `seatUnplaced`/`seatNear`；不要求它为单卡制造 batch order。没有 order 的 `flowColumns` 仍严格按 ASCII id，单卡语义不受影响。若未来旧调用者批量传入 kind 但无 order，`seatUnplaced` 可使用同一 kind-rank/数字前缀 helper 临时排序；若连 kind 也没有，则必须明确回退 path，而不是从 metadata 猜 batch。

这里存在一个需要评审确认的张力：`docs/layout/00-共同上下文.md §3.1/§4.2` 将“缺省 order 时 ASCII path”冻结为通用 fallback，同时产品目标要求同批 Chalk 不被 path 字典序的 component 插队。本篇不改 00：通过 canonical `/layer` 必填 derived order 来满足产品顺序；纯 `flowColumns` 与无 kind 的旧调用者仍保留冻结的 path fallback。若评审要求所有入口都强制 Chalk 优先，需回写 00 后再改 `SeatFile`/调用者，不能在实现中静默漂移。

## 4. 行为步骤与服务端落位

### 4.1 `seatUnplaced`：一次调用的一次自动批次

一个批次严格沿用 `docs/layout/00-共同上下文.md §3.1`：`/layer` MUST 把该层页面的完整 `items` 传入 `seatUnplaced`，store 在 SQLite 临界区内过滤出无 row files；不能由路由先缩成 `unseated`，否则 occupied 会漏掉同页既有卡与跨层 README 门牌。批次成员仍然只是本次临界区确认无 row 的 files。

施工步骤：

1. 在 store 层先进入排座临界区：复用已有 SQLite `BEGIN IMMEDIATE`，并可用实例内按 world/layer 的 `withSeatLock`；事务开启后再读取传入 page items 的 rows、跨层门牌 rows 与 layer 当前最大 z，形成去重后的 occupied。
   - 漏掉全层/展示页已有 rows 会把新卡放进玩家已经摆好的卡；在事务外缓存 occupied/maxZ 会让并发请求各自基于旧快照计算，无法由 `reqSeqRef` 修复。
2. 过滤 `row` 不存在的 files；保留 canonical 调用方 order，旧无 order 输入按 `order ?? id` 的冻结 fallback。若 missing 为空，提交/退出且不更新任何行。
   - 漏掉 row 过滤会重排已有卡，违反“已有坐标永不因新批次移动”。
3. 每个 missing file 的尺寸使用 `storedSizeOf` 传来的行值/声明初值；首次无行只能使用 declared 初值，不得读取 `CARD_FORMS.h` 另算第二套尺寸。实现必须拒绝无效 w/h，而不是隐式使用 schema DEFAULT 280×180。
   - 漏掉该界线会违反 footprint I1；SQL DEFAULT 不是任何 kind 的真实占位，第二次 arrange 会对错误尺寸布局（footprint §5.5）。
4. 调用 `flowColumns(boxes, occupied, config)` 一次计算整个 missing batch，按 placements 写入 `cards`。每插入一个矩形，逻辑占用集立即追加；每插入一个新 row，z 从 layer 当前最大值递增。这里 MUST 保留当前已修复的 `occupied.push(...)`/`nextZ++`（`local-store.ts:666-675`），只是把 spiral 候选替换为 flow placement。
   - 漏掉批内追加会退回 N1 的同点/同 z bug；一次对每张卡单独调用 flow 且不传前一张也会产生相同回归。
5. 每条新行写 `id/layer/x/y/width/height/z_index/metadata`，metadata 只能有 `formVersion / measuredAt / seatW / seatH` 四键；初次 seat 至少写 `seatW/seatH`，`formVersion` 由同次 `/layer` 的 `reseatLayer` 按 declared 回填。footprint POST 不可改 x/y/z，也不落 history 事件。
   - 漏掉 seat baseline 会使下一次 measured drift 无法比较；把 order/batch id 放 metadata 会违反 footprint 封闭 schema。
6. 返回实际写入的 `CardRecord[]`，并在 flow exhausted 时留下开发者可见诊断（path、columnsUsed、maxColumns、最后候选），但仍返回确定 row；不要回退旧 anchor 或静默吞掉卡。
   - 漏掉诊断会把拥挤世界伪装成正常；回退 anchor 会重新引入严重重叠。

### 4.2 `reseatLayer`：只移动漂移卡

`reseatLayer` 的 drift 判定 MUST 逐条遵守 `docs/footprint/00-共同上下文.md §5.1` 的短路顺序：

1. row 缺失：首次排座，使用 declared；
2. row w/h 非正：脏行修复，使用 declared；
3. `rowVersion !== declaredVersion`：kind/form 尺寸变更，先于 measured 判定，使用 declared 并清空 `measuredAt`；
4. `measuredAt` 存在且 `row.w/h !== seatW/seatH`：实测占位变化，使用 row 的真实 w/h；
5. legacy 无版本/无测量：行值等于 declared 时只补 formVersion，不动 x/y；行值不等时按一次 declared 重排；
6. measured row 无 formVersion 且尺寸未移动：保护竞态，no-op。

施工步骤：

1. 先读所有目标 rows，构成 `moving`（仅命中上述 1/2/3/4 的卡）与稳定 siblings。kind drift 取 declared，measured drift 取 row w/h；不能把 declared 重新覆盖到 measured row。
   - 漏掉 kind drift 在 measured drift 前判定，会按旧宽折出的 stale measured 高排座并用新 formVersion 隐藏问题（footprint §5.1 BLOCKER-C）；漏掉 measured 分支则 F1 长高 Chalk 永远不让座。
2. occupied 只含稳定 siblings 的当前坐标与当前 row w/h；moving 卡先从障碍中移除，避免与自己的旧矩形冲突。跨层展示页的 README 行也应纳入去重后的 occupied。
   - 漏掉稳定 sibling 会撞玩家卡；把 moving 仍留在 occupied 会让自身旧位置阻挡新位置，导致无意义 exhausted。
3. 以 moving 的稳定 order 调 `flowColumns` 一次，放入同一新流；stable siblings 永不改 x/y/z。单卡 measured drift 也走该函数，不另造“推开一点”的几何。
   - 漏掉同一函数会重新形成服务端多套几何；把整层 files 传入会移动未变化兄弟，违反 00 §3.1/§3.2 的“只动变化卡”。
4. 先完成纯计算，再在一个 SQLite 写事务中 UPDATE/INSERT moving rows；UPDATE 卡保留原 z，INSERT 才分配递增 z；同时写新的 `seatW/seatH`，measured row 保留 `measuredAt`，kind drift 清空 measuredAt。
   - 计算中途写 DB 会在 flow 校验失败时留下半套布局；重排稳定卡 z 会导致每次 /layer 读都改变堆叠顺序。
5. 对 legacy “只标记”分支只 UPDATE metadata，不碰 x/y/w/h；若无 drift，完全 no-op。返回变更行供 `/layer` 更新 `rowByPath`。
   - 把 metadata 缺失直接当重排会首次打开旧世界时打乱玩家位置；把 no-op 当写入会制造无意义 DB churn。

`reseatLayer` 不因新批次到来而移动既有卡。只有 footprint §5.1 的合法 drift 才能改变变化卡 x/y，这正是 I2 的“回写不降级”与“真实变大时让开”同时成立的边界。

### 4.3 并发：不能只依赖前端 reqSeqRef

`GET /layer` 存在 read → compute → INSERT 竞态：请求 A/B 都可能在 `rowByPath` 中看见无 row，用相同 occupied 计算相同座位，然后各自 INSERT；`ON CONFLICT(id) DO NOTHING` 只会让后写者不写，但如果它照旧返回自己算出的 placement，响应和内存结果会过时，且 z 计算也可能重复。前端 `reqSeqRef` 只能丢弃旧响应，不能保护数据库。

实现必须在 store 层采用以下真实序列化方案：

- **主方案：SQLite 写事务 + 实例内按 world/layer 的异步锁。** 在 `LocalWorldStore` 增加 **NEW** 私有 helper（完整签名）：

  ```ts
  private async withSeatLock<T>(
    layerId: string,
    operation: () => Promise<T>,
  ): Promise<T>;
  ```

  `withSeatLock` 的 key 至少包含当前 world 实例与 layer；锁包住 `seatUnplaced`/`reseatLayer` 的读、flow 计算、写、提交，避免同一进程的请求交错。事务内部用 `BEGIN IMMEDIATE`，该 SQLite 机制也会序列化不同进程对同一 canvas DB 的写者；提交失败必须 rollback。
- `seatUnplaced` 的事务顺序固定为：BEGIN → 重新读 rows/最大 z → 过滤 missing → flowColumns → INSERT（保留 `ON CONFLICT DO NOTHING` 作为防御）→ COMMIT。禁止在事务外缓存 occupied 或 maxZ 再写。
- 若 SQLite 返回可重试的 busy/locked，做有限次数、带退避的事务重试；超过上限返回可识别错误（包含 layer 与操作），不能回退 spiral/anchor，也不能吞错。`withSeatLock` 是同步数据库调用的串行保护，不增加事件或 WS。
- **冲突防御/回读：** 若部署形态存在无法共享进程锁的外部 writer，`ON CONFLICT` 后必须检查实际 row 是否由本次写入；发现冲突就 rollback/重新读取该层 rows、重新计算剩余 missing，再返回 DB 中最终行。不能只依赖“INSERT ignored”继续返回 stale placement。读回必须按 id 重新构造 `CardRecord`，以数据库为准。
- 这不是新增跨进程业务锁表，也不是前端授权；canvas.db 的 `BEGIN IMMEDIATE` 是该 store 已有的写事务模式（例如 `placeCards` 在 `local-store.ts:1002-1014`、`writeFootprints` 在 `:881-925`）。若实现选择文件锁/数据库锁表替代，必须保持同样的“锁住读取到提交”的范围，并记录 `SQLITE_BUSY` 的 fail-loud 语义。

这样 A/B 的结果最多是 A 先落一组，B 等待后看到 rows 并 no-op/只处理新 missing；不会出现两份都声称成功、但数据库只接受一份的座位分配。

## 5. 文件、输入输出与数据库副作用

### 5.1 输入

- `flowColumns`：readonly boxes、readonly occupied、可选 Partial config；boxes 的 w/h 是本次排座实际占位，occupied 的 w/h 是已落座卡的 row 值。服务端不读 DOM。
- `seatUnplaced(layerId, files)`：layer id 与 `SeatFile[]`；调用方应提供 declared kind/size 与本次排序提示 order。批次成员由 store 过滤无 row 决定。
- `reseatLayer(layerId, files)`：files 提供 declared kind/size（`GET /layer` 当前在 `world.ts:629-632` 传入），store 从 row metadata 读 measured/seat baseline。

### 5.2 输出

- `flowColumns` 输出 placements/exhausted/columnsUsed，不产生外部副作用。
- `seatUnplaced` 输出新插入的 `CardRecord[]`；`reseatLayer` 输出重排或 metadata 回填的 rows；两者都以 DB 读回值为最终事实。
- exhausted 只表示在保护阀内未找到无冲突候选，不表示卡被丢弃；实现必须使它进入开发者可见诊断。现有 `seatNear`/move 的 `{ exhausted }` 形状继续保持。

### 5.3 允许的 DB 写入

| 路径 | 可写列 | 不可写 / 不产生 |
|---|---|---|
| 新卡 `seatUnplaced` | `cards.id, layer, x, y, width, height, z_index, metadata`（metadata 四键） | 不写文件、history.db、world event；不移动已有 rows |
| drift `reseatLayer` | 变化卡的 x/y 与真实 w/h；对应 seatW/seatH/formVersion/measuredAt；新 row 才写 z | 稳定兄弟不改 x/y/z；不把 measured 值换回 declared |
| legacy backfill | 仅 `cards.metadata` 的 formVersion/seat baseline | 不重排、不改尺寸/坐标 |
| footprint POST | 本篇不实现；按 footprint §3.3 只改 width/height/measuredAt，绝不改 x/y/z、事件 | 不得把 order/batch id 放 metadata |

`arrange` 的显式 x/y/z 仍经 `arrangeCards → placeCard/placeCards` 写入；自动 flow 不接管它，也不新增 history event。画布坐标层沿用 `canvas.db only` 约束（footprint §3.6）。

## 6. 与 arrange/place/seatNear 的既有语义

1. **`arrange({layout})` 不走 flow。** `arrangeCards` 的 grid/circle/row 仍由 `LAYOUT_COMPUTERS` 计算并由 `placeCards` 落位（`actions/canvas.ts:492-576`）；它是用户明确要求的整体布局，不能被“新批次自动流”覆盖。若路径尚无 row，仍先用 declared 建行（现有 `seatDeclaredRows` 接缝见 `canvas.ts:561-564` 的设计注释），避免 schema DEFAULT；布局本身只改 x/y，不改 z/尺寸。
   - 漏掉该边界会让一次用户 arrange 后刷新又被 flow 改回叙事列，破坏显式动作的可预测性。
2. **`arrange({place})` / `placeCard` 只移动目标卡。** `arrangeCards` 在 `canvas.ts:444-489` 校验单卡并调用 `placeCard`；`placeCard` 不接受 w/h，尺寸不对称仍遵守 footprint §5.3。flow 不应在玩家拖拽/显式 place 后偷偷重排目标或邻居。
   - 漏掉该边界会把“玩家已摆位置永不因新批次移动”变成假话，并让尺寸来源重新分叉。
3. **`seatNear` 保留“只落一张、相邻指定 anchor、返回 exhausted”的外部语义。** 它当前在 `local-store.ts:1177-1259` 以 anchor 中心和 occupied 构造单卡候选，且不重排已有卡。迁移后用一个 flow adapter（**NEW，完整签名建议如下**）调用同一 `flowColumns`：

   ```ts
   private async seatNearWithFlow(
     layerId: string,
     file: SeatFile,
     anchorPath: string,
   ): Promise<CardRecord & { exhausted: boolean }>;
   ```

   adapter 读取 anchor 的 row x/y/w/h，把一个 box 的 origin 设在 anchor 右侧（anchor right + `gapX`，y 为 anchor y），occupied 包含 anchor 与该层其它 rows，`flowColumns` 只放这一张；不得调用原 spiral，也不得移动 anchor/兄弟。返回 `result.exhausted`，并用现有 `seatNear` UPSERT/metadata 规则写入 row。
   - 漏掉 anchor 会把 near 退化为普通首列；一次传入整个层会重排旧卡；丢掉 exhausted 会让 move 的动作详情错误地声称找到干净位置。

`seatPresence` 是 point presence，不是 card rectangle；本篇不把它硬塞进 flow。其既有 card/presence 障碍读取继续由 presence 领域契约负责。

## 7. 跨端闭环与 WS 接缝

- 服务端 `/layer` 是唯一自动落座落盘点：读取文件 → 取得 rows → `seatUnplaced`（flow）→ `reseatLayer`（flow，仅 drift）→ enriched 返回 row x/y/w/h。`world.ts:636-650` 的返回必须继续以 stored row 尺寸为准，不可回读 form 高覆盖 measured 高。
- `02-幻影与演出接线` 必须把同一 `flowColumns` 输入/默认值用于 ghost：occupied = 当前层真实卡 + 同层幻影，ghost 尺寸按其 own `ghostSizeFor`/Chalk declared 保守估计，不写 cards；`chalk_landed`/`image_landed` 是座位过户，不能再次 flow。真实 `/layer` 返回坐标优先，且幻影撤销由 `reconcileLanded` 完成。
- 本篇不新增 WS 帧名。已有 `useWorld` 消费点在本批次继续接收既有帧；服务端落位结果通过 layer 重取/既有事件链被消费，不让 Canvas framing effect 或 pointermove 成为第二排版器。
- `04-生成批次与初始化接缝` 必须在一次生成/初始化完成后把同批文件稳定传到 `/layer`，或保证 `/layer` 的 items 映射能产生相同 `order`；初始化器不写 x/y，不在正文/metadata 写 batch id。文件监听抖动时，每次只 flow 仍无 row 的文件，旧 row 不动。
- footprint 回写闭环：前端稳定测量 → `POST /api/card/footprint` 只写 row w/h + measuredAt → 下一次 `/layer` 的 `reseatLayer` 命中 measuredMoved → flow 只重排变化卡 → 返回新 row 尺寸/坐标。I1/I2 详见 `docs/footprint/00-共同上下文.md §3.2`。

## 8. 错误边界与不静默降级

- 几何输入非法、重复 id、非法 config：纯函数抛出并不写 DB；上层将其视为开发/调用方错误，不能把坏尺寸替换为 form/default。
- `flowColumns.exhausted`：仍返回最后候选以保留卡的可见性，同时在 store 日志中包含 path、columnsUsed、maxColumns 和碰撞原因摘要；不得回退 `SEAT_ANCHOR`，不得只返回空数组。
- SQLite busy/locked：事务 rollback，按有限次数退避重试；最终失败返回带 `layerId`/operation 的可识别错误。禁止 catch 后返回“已排好”的假 CardRecord。
- DB insert 冲突：`ON CONFLICT` 不是成功证据；必须回读并验证 id/x/y/w/h/z，冲突即重算或返回最终数据库行。
- malformed metadata：沿用 `parseCardMetadata` 的保守解析，按 footprint §5.1 的 legacy 分支；metadata 缺失本身不能直接触发整层重排。
- measured row 的 `w/h <= 0` 或 declared 缺失：记录开发者可见警告；按 §5.1 仅在有 declared 时做 declared 修复，无法确定 declared 时跳过该卡并报告，不猜 280×180。

## 10. 验收测试（机械断言与反例）

测试文件建议：`packages/shared/test/canvas.test.mjs` 增加 flowColumns 纯函数测试，或新增同目录的布局测试并由 05 统一编排；本篇只定义可机械核验的行为，不执行全量验证。

### 10.1 旧 spiral 的几何反例（必须保留）

以真实 footprint §2.3 的 `evening`（460×578）、`late-night`（460×481）、`raindrops`（至少按 row 的真实 w/h）构成同一批。旧 spiral 的 `SEAT_STEP=96`（`local-store.ts:23`）远小于 460 的卡宽：从中心候选到横向相邻候选的 x 间距只有 96，任意同 y 候选的水平重叠至少 `460-96=364px`；即使当前 N1 修复让第二张继续试，spiral 也没有“先填满一列、超过列高才右移”的不变量，结果会在中心周围环绕，不能保证叙事顺序和列高。旧实现因此不满足视觉目标；N1 修复只保证批内看到自己的座位，不等于 flow。

### 10.2 “没有 flowColumns 就会失败”的非空性断言

fixture 必须使用非空三卡输入，而不是 `[]`：

```ts
function overlappingPairs( // NEW test helper
  rects: ReadonlyArray<{ x: number; y: number; w: number; h: number }>,
  obstacleGap: number,
): number;

const boxes = [
  { id: '02-late-night.md', w: 460, h: 481, order: 1 },
  { id: '01-evening.md', w: 460, h: 578, order: 0 },
  { id: '03-status.md', w: 300, h: 220, order: 2 },
];
const result = flowColumns(boxes, [], { columnHeight: 1200 }); // 让前两张验证同列方向
assert.equal(result.placements.length, 3); // 非空性：三张都必须有确定 seat
assert.equal(new Set(result.placements.map((p) => p.id)).size, 3);
assert.equal(overlappingPairs(result.placements, 22), 0);
assert.ok(result.placements[0].y < result.placements[1].y); // 同列叙事方向
```

修复前用旧 spiral/旧批内实现时，该 fixture 的 `placements.length === 3` 可能成立，但真实 row 尺寸下 `overlappingPairs(...) > 0` 或顺序不满足列流；因此单纯检查“返回了数组”是假绿，必须同时断言非空、零重叠和顺序。没有 `flowColumns` 的实现不能满足这一组断言。

### 10.3 障碍、列高、超高与 exhausted

1. occupied 放一个 `x=360,y=96,w=460,h=200`，输入两卡；首候选必须向下避开障碍，不能覆盖 occupied；右侧再放一个跨候选 x 的旧矩形，必须继续右移而不是挪旧卡。
2. `columnHeight=500`，三张 `h=200` 卡；前两张按 y 流，第三张落在下一列，`columnsUsed >= 2`，稳定 siblings 不动。
3. 一张 `h=1500`、`columnHeight=1080` 的 Chalk 必须有 placement 且 `exhausted === false`。
4. `maxColumns=1` 且 occupied 覆盖所有候选：placements 长度仍等于 boxes 长度，`exhausted === true`，日志/诊断非空，不能回到 `{960,540}` 中心。

### 10.4 服务端批次与占用/z

使用一次 `/layer` 使 4 张无 row 同时进入 `seatUnplaced`：断言四个 `(x,y)` 在 obstacleGap=22 下两两不重叠、z 互异且按落位递增；特别检查代码仍执行 `occupied.push` 与 `nextZ++`。重复 GET `/layer` 必须不移动四行、不新增行。

### 10.5 footprint drift 与玩家位置保护

- 先用 declared 给 A/B/C 建行，手动移动稳定 B；只将 A 的 row h 从 `seatH` 变为真实测量 h，下一次 `reseatLayer` 只改变 A 的 x/y（必要时其余 moving 同批），B 的 x/y/z 完全相同。
- 对 kind declared version 变化且已有 measuredAt 的 A，断言先走 kind drift：用 declared 排、清空 measuredAt；不能用旧 measured row 排，也不能把新 formVersion 写成让下一次永不触发的假稳态。
- legacy metadata 缺失且 row 尺寸等于 declared 时，断言只补 metadata，玩家坐标不变。
- measuredAt 非空且 row w/h 等于 seatW/seatH 时，第二次 pass 断言 no-op。

### 10.6 并发

并发触发两个 `/layer` 请求，使用同一无 row fixture：最终 DB 每个 id 只有一行，任意两个 row 的落位来自一次稳定 flow 且不重叠；两个响应回读后都与最终 DB 一致。测试应能在移除 `BEGIN IMMEDIATE`/store lock 时复现“双请求都计算同一点或返回 stale placement”，证明前端 reqSeqRef 不是充分保护。

1. `docs/layout/00-共同上下文.md §3.1/§4.2` 的通用 fallback 是“无 order 按 ASCII path”，而同批 Chalk/component 的视觉目标不允许 canonical `/layer` 只用 path；本篇采用“canonical caller 先派生 order，纯函数/旧无 kind caller 仍 path fallback”的兼容解，不私改 00。若评审要所有入口都 Chalk 优先，需回写 00 后再落地。

3. 当前 `seatUnplaced`/`reseatLayer` 的方法主体以多个 `execCanvas` 分散写入（`local-store.ts:651-665`、`:820-854`），而并发正确性要求读/算/写同一事务；此篇建议 `BEGIN IMMEDIATE` + world/layer lock，需与 store 的现有事务错误处理统一。不能用 `ON CONFLICT DO NOTHING` 或前端 `reqSeqRef` 冒充互斥。
4. `docs/footprint/00 §5.1` 已冻结 drift 判定但未规定 flow 的 exhausted 如何反馈；本篇建议记录 store 开发者诊断、保持现有 `CardRecord[]` 返回形状，不新增 WS/metadata 字段。若 05 要求 API 公开 exhausted，需另开响应契约，不在本篇偷加字段。
5. `seatNear` 现有“anchor-relative spiral”与“唯一新排版几何 flowColumns”存在语义张力。本篇以单卡 flow adapter 保留 near/exhausted/不移动兄弟三项外部语义；若产品要求严格保留 spiral 位置分布，则须回写 00 的“不能再有服务端 spiral”条款，不能两套几何并存而不记录冲突。
