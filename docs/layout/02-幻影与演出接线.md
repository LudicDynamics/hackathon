## 一句话定位

**幻影只是在真实卡到达前占一个由 `flowColumns` 算出的临时座位；`chalk_landed`/`image_landed` 只做座位过户，随后由 `useWorld` 的真实重取接管，绝不让第二套 spiral 或第二个 WS 成为布局真相。**

## 2. 共享几何与尺寸口径

### 2.1 唯一几何入口

唯一排版几何是冻结契约中的 `flowColumns`（`docs/layout/00 §4`）：

```ts
export interface AutoLayoutBox {
  id: string;
  w: number;
  h: number;
  order?: number;
}

export interface AutoLayoutRect {
  id?: string;
  x: number;
  y: number;
  w: number;
  h: number;
}

export interface FlowLayoutConfig {
  origin: { x: number; y: number };
  columnHeight: number;
  gapX: number;
  gapY: number;
  obstacleGap: number;
  maxColumns: number;
}

export interface FlowLayoutResult {
  placements: Array<{ id: string; x: number; y: number; w: number; h: number }>;
  exhausted: boolean;
  columnsUsed: number;
}

export function flowColumns(
  boxes: readonly AutoLayoutBox[],
  occupied: readonly AutoLayoutRect[],
  config?: Partial<FlowLayoutConfig>,
): FlowLayoutResult;
```

`flowColumns` 的实现落点由 `01` 篇裁定，建议为 `packages/shared/src/layout/flow-columns.ts`（NEW，导出上述完整签名），并由服务端与 web 侧可消费的 shared 构建入口导出；本篇不另造 geometry helper。

必须保留的机械不变量：

1. `order` 后按 `id` 稳定排序；不能依赖 SQLite 返回顺序。
2. 一列由上至下放，超过 `columnHeight` 后向右；右侧旧障碍存在时继续向右扫描。
3. `occupied` 与批内已放 boxes 都用真实 `w/h` 加 `obstacleGap` 检查；旧卡不移动。
4. `h > columnHeight` 允许单卡占一列；达到 `maxColumns` 才是 `exhausted=true`，不得回退到中心重叠点。
5. 函数不读 DOM、不读相机、不写 DB、不发事件（`docs/layout/00 §4.2`）。

### 2.2 三种尺寸不能混用

| 对象 | 输入尺寸 | 能否写 `cards.width/height` | 用途 |
|---|---|---:|---|
| 服务端已有真实卡 | `row.w/row.h`，由 `storedSizeOf(item,row)` 取值 | 已在行中；实测回传覆盖 | `flowColumns` 的真实障碍与 `reseatLayer` 的 measured-move 分支 |
| 服务端无行新卡 | `declaredSizeOf(item)` 的 `form.w/h` | 首次 `seatUnplaced` 写入 | 自动批次的初始落位；不能假称是最终绘制高 |
| Chalk 幻影 | 至少 `{ w: form.w, h: form.h }` 的 declared 保守盒 | **否** | 在 `chalk_writing` 到 `chalk_landed` 间占位，不能把临时估计回写 DB |
| image 幻影 | `ghostSizeFor(width?,height?)`（NEW，完整签名见下） | **否** | 以请求长宽比和上下限构造视觉/排版临时盒 |
| 已字体稳定的前端卡 | `.object` 外壳 `offsetHeight`，按 `docs/footprint/00 §3.5` | 通过 `POST /api/card/footprint` 回写真实行 | 下一次服务端读取时参与真实排座；本地碰撞可先用 `measure.ts` 事实 |

```ts
export function ghostSizeFor(
  width?: number,
  height?: number,
): { w: number; h: number }; // NEW，建议落点 apps/web/src/lib/ghost.ts
```

`ghostSizeFor` 的具体上下限沿用 `docs/perform/03 §8.1` 的视觉设计（`GHOST_W`、`GHOST_H_MIN`、`GHOST_H_MAX`）；它不是服务端真实像素，也不是 `cards.width/height`。Chalk 的 declared 盒可能远小于绘制盒（真实 chalk 曾 `declared h=190`、绘制高 `481–578`，`docs/footprint/00 §2.3`），因此 Chalk 幻影只能被标记为“临时保守估计”，落地后仍须等待 footprint 收敛。

## 3. 端到端行为步骤（每步含漏了会怎样）

### 3.1 服务端真实卡落位

1. `GET /api/layer` 的 `GET /layer` 分支读取 `pageOfLayer` 得到文件，并用 `rowByPath` 判断行是否存在（`world.ts:582-614`）。**漏了会怎样：**无法区分新卡和玩家已有卡，后续可能把玩家座位当成自动排版输入。
2. 对 `/layer` 页面完整候选 items 调用 `seatUnplaced(layer, items)`；store 在事务内过滤没有 row 的 files，将同一调用中确认的 missing files 作为一个自动批次。服务端改造后，函数构造 `AutoLayoutBox[]`，以 `row.w/h ?? declared.w/h` 为尺寸，并将 `flowColumns(boxes, occupied, config)` 的 placements 写入 rows。**漏了会怎样：**先在路由过滤成 `unseated` 会使 store 看不到同页既有卡，批次顺序或尺寸也会重新从 SQLite 顺序推导，导致新卡撞到真实卡或每次重取改变叙事顺序。
3. `seatUnplaced` 的 `occupied` 包括传入页面 items 对应的所有既有行（含跨层 README 门牌），并在批内逐项加入已放 placement；新批次不得把已经有坐标的 rows 当成可移动 boxes。**漏了会怎样：**同批卡重叠，或新生成内容挪动玩家已经摆好的卡。
4. 随后以 declared 形状调用 `reseatLayer`（`world.ts:626-634`）；其 kind-version 分支使用 declared，实测 footprint 变化分支使用 row 值。**漏了会怎样：**把实测高用 declared 冲回去，或把 kind 改尺寸误判成稳定，重新制造 chalk 竖向重叠。
5. `enriched` 必须仍由 `storedSizeOf(it,row)` 输出行的 w/h（`world.ts:636-651`）。**漏了会怎样：**服务端虽然按真实尺寸落位，前端却收到名义尺寸，随后 phantom/DOM 计算与真实卡再次分叉。

### 3.2 `chalk_writing` 与湿墨

1. `writer_delta` 的 `toolCallId` 先到时，`apps/web/src/lib/phantom.ts::appendInk`（由 `01` 实现）必须对未知 id 建 pending 缓冲；这是 `docs/perform/00 §5` 的 P0 时序纪律。**漏了会怎样：**delta 在没有 phantom entry 时被静默丢弃，随后 Chalk 落地只有空正文。
2. `chalk_writing` 在 `useWorld` 的同一 `switch` 注册 `{kind:'chalk', source:'writer', layer: layerRef.current, seat}`；`seat` 来自 `phantomSeatFor({w: CARD_FORMS.chalk.w, h: CARD_FORMS.chalk.h}, layerRef.current)`，不能在 `useWorld` 里写第二个坐标算法。**漏了会怎样：**湿墨没有独立浮层，因落地前没有 path 而无法渲染；或者第二个 seater 与服务端冲突。
3. `register` 将 pending 文本灌入 entry，之后 `writer_delta` 只追加；`chalk_writing` 不重置已有 text/seat。**漏了会怎样：**帧乱序时正文重复、丢失或幻影跳位。
4. `chalk_landed` 调 `landPhantom(toolCallId, { path })`，**不传 seat**，并保留其座位直到真实重取。**漏了会怎样：**“内容已到但卡跳到另一格”，违反 `docs/perform/00 §5` 的座位过户。
5. `PhantomLayer` 在唯一挂载点按 `kind` 分派 image 与 Chalk；当前工作树已恢复 `ChalkMark` 分支（`PhantomLayer.tsx:71-84`），后续实现必须保留该分支并为它增加回归验收，而不是只在 registry 留一条 entry。**漏了会怎样：**未来重构若再次删掉分支，服务端和 phantom 都算对了 seat，但玩家仍看不到 Chalk 演出。
6. `file_changed`/相关 `world_event` 仍进入既有 `fetchLayer` 路径；成功重取以返回 rows 为准，再按真实 path 集合调用 `reconcileLanded`。**漏了会怎样：**真实卡和浮层双画，重进同层时出现 encore 幻影。

### 3.3 `image_generation_progress` 与 `image_landed`

1. `useWorld` 新增同一 `onMessage` 的 `case 'image_generation_progress'`：校验 `toolCallId`，用 `ghostSizeFor(msg.width,msg.height)`，将 `msg.source` 归一为 `'writer' | 'character'`，然后调用 `phantomSeatFor(size, layerRef.current)` 与 `registerPhantom`。**漏了会怎样：**生图没有可见等待态；把 source 固定为 writer 还会把角色车道显示在错误叙事流。
2. `register` 必须按 `toolCallId` 幂等合并 `label`/`elapsedMs`，忽略心跳中的 seat 重算；每 10 秒心跳不能创建第二张卡。**漏了会怎样：**同一次生图不断叠加幻影并逐渐耗尽列位。
3. `image_landed` 调 `landPhantom(toolCallId, {asset,mimeType,width,height,reused})`，不传 seat；`GhostCard` 在同一座位从骨架换真图。**漏了会怎样：**落地图跳位，或只显示骨架。
4. 资产由既有 `/api/asset?path=${encodeURIComponent(asset)}` 取用；生图资产目录被 watcher 忽略，不能等待 `file_changed` 作为唯一完成信号（`docs/perform/00 §6b-3`）。**漏了会怎样：**图已经生成但画布无任何完成反馈。
5. 后续 `file_changed`/`world_event` 若带来真实 `bg.src` 或真实卡，`fetchLayer` 成功后撤掉对应 phantom；若没有真实变更，`LANDED_DWELL_MS`/`REUSED_DWELL_MS` 兜底撤离。**漏了会怎样：**image phantom 永久占位，层切换回来继续覆盖真实投影。

### 3.4 层切换、并发与真实接管

1. `enterLayer(next)` 继续先更新 `layerRef`/React layer、重置 footprint scheduler，再 `fetchLayer(next)`（`useWorld.ts:179-205`）；`fetchLayer` 保留 `reqSeqRef` 的 stale response guard（`:147-153`）。**漏了会怎样：**旧层慢响应覆盖新层，幻影座位镜像也会被旧数据污染。
2. fetch 成功时先写 `stateRef.current`，再 `publishSeatItems(next.layer,next.items)`，最后以 `new Set(next.items.map(it => it.path))` 调真实 path collection 的 `reconcileLanded`（现状调用为 `useWorld.ts:167`）。**漏了会怎样：**新真实 rows 尚未成为占用障碍就开始计算下一幻影，或把错误的层/过户集合传入。
3. `PhantomLayer` 仅渲染 `entry.layer === currentLayer` 的幻影；registry 不因切层清空，切回时仍能看到仍在运行的演出。其 DOM 不带 `.object` 且 `pointer-events:none`，遵守 `docs/perform/00 §5` 及反模式第 5 条。**漏了会怎样：**别层幻影漂到当前页，或用户拖动临时壳造成第二个坐标写入口。
4. 并发 phantom 的 `occupied` 必须是“当前层真实 items + 当前层全部 phantom（Chalk 与 image）”，并在每次首次注册时调用同一 `flowColumns`。**漏了会怎样：**现状 `phantom-seat.ts:56-58` 只过滤 image，两个 Chalk 会同座；这是一条修复前会失败的非空重叠用例。
5. 服务器和前端输入集合必须诚实区分：服务器是一次 `seatUnplaced` 视角中的 rowless files 及已有 DB rows；前端是当前 `items` 镜像加同层 phantom。两端调用同一纯函数但不承诺输出完全同构。真实 fetch 后服务器 rows 赢，phantom 只保留到过户/撤离。**漏了会怎样：**实现者会错误地把“算法同构”宣传成“座位必同构”，进而在客户端强行覆盖服务端真实坐标。

## 4. `phantomSeatFor` 设计与输入输出副作用

现有文件 `apps/web/src/lib/phantom-seat.ts`（现状 `:1-62`）保留为 web 侧唯一幻影座位适配器，但替换其 spiral 调用：

```ts
export function publishSeatItems(
  layer: string,
  items: readonly { x: number; y: number; w: number; h: number; z: number }[],
): void; // apps/web/src/lib/phantom-seat.ts，现有适配接口

export function phantomSeatFor(
  size: { w: number; h: number },
  layer: string,
): { seat: PhantomSeat; occupied: AutoLayoutRect[] }; // NEW/统一，apps/web/src/lib/phantom-seat.ts
```

`phantomSeatFor` 的实现步骤：

1. `publishSeatItems` 只在 `fetchLayer` 成功后发布当前层 rows；层不匹配时把 items 当空集，避免旧层数据压住新层真实内容。
2. 从 `getPhantomsSnapshot()` 取快照，过滤 `p.layer === layer` 或未声明 layer 的条目；**不得按 kind 过滤**，`phase === 'evicted'` 不再计入。
3. 把 rows 与 phantom seats 统一转为 `AutoLayoutRect` 的 top-left 坐标；不要把 `makeBox` 的 center 坐标传给 flowColumns。
4. 构造一个带稳定 id 的单元素 `AutoLayoutBox`，调用 `flowColumns([candidate], occupied, config)`；从唯一 placement 生成 `{x,y,w,h,z}`。z 仅由当前真实 items 的最大 z 推导，心跳/重复 register 不重算 entry seat。
5. `flowColumns` 返回 `exhausted=true` 时仍使用最后候选，但记录开发者可见诊断；不得回退 anchor，不得通过 `console.warn` 代替玩家可见的失败 UI。布局耗尽不是演出失败，phantom 仍须可淡出。

输入：phantom 尺寸、层名、上一次成功 fetch 的当前层 rows、同层未撤离 phantom 快照。输出：临时 `PhantomSeat` 与本次碰撞占用快照。副作用只有更新 `publishSeatItems` 的内存镜像；`phantomSeatFor` 自身不得写 DB、React state、事件或 WS。`register` 的模块态订阅由 `phantom.ts` 负责，不能在该 helper 另开 registry。

## 5. `useWorld` fetch/reconcile 与 WS 接线

### 5.1 fetch/reconcile

代码落点是 `apps/web/src/state/useWorld.ts` 的 `fetchLayer`（现状 `:147-173`）：

- 保留 `seq === reqSeqRef.current` 的 stale response guard。
- `stateRef.current = next` 与 `setState(next)` 后，调用 `publishSeatItems(next.layer,next.items)`。
- `reconcileLanded` 的实际代码当前接受 path collection：`apps/web/src/lib/phantom.ts:185` 的 `reconcileLanded(paths: Iterable<string>)`；调用处当前传数组（`useWorld.ts:167`）。落地设计应在入口将 `new Set(next.items.map((it) => it.path))` 传入，函数内部按 collection 语义判断，避免重复 path；同时在冲突回写中把 perform 文档的 `ReadonlySet`/数组三套说法收敛为这一条。
- 真实坐标、真实 `w/h` 和真实 `z` 永远来自 HTTP 层返回；reconcile 不能把 phantom seat 写进 item，也不能二次调用 `flowColumns`。

footprint POST 仍遵守 `docs/footprint/00 §3.3–§3.6`：字体稳定后批量回传 `offsetHeight`，只改行的 w/h 与四键 metadata，不落事件。下一轮 `/layer` 由 `reseatLayer` 判断 measured footprint 变化并以 row 值 flow；因此“phantom declared/ghost 尺寸 → 真实测量尺寸”的收敛不是浏览器本地偷改座位，而是服务端下一次真实读取接管。

### 5.2 WS 时序与共同消费点

所有 case 都只加在 `useWorld.ts` 的 `onMessage`/`switch (msg.type)`（现状 `:342-522`），不得建立第二连接（唯一 `new WebSocket` 在 `:527-535`）。帧到达后的机械顺序为：

```text
writer_delta(toolCallId)
  → pending appendInk（entry 可能尚不存在）
chalk_writing(toolCallId)
  → flowColumns 首次分配 Chalk declared 幻影 seat
writer_delta(...)
  → 追加同一 entry
chalk_landed(toolCallId,path?)
  → land：不变 seat，只附 path
file_changed/world_event
  → fetchLayer → publish rows → reconcile real paths → 真实卡赢
```

```text
image_generation_progress(toolCallId,width?,height?,stage?)
  → ghostSizeFor → flowColumns 首次分配 image ghost seat
image_generation_progress(...same id...)
  → 幂等更新 stage/elapsed，不重排
image_landed(toolCallId,asset,...)
  → land：不变 seat，换真图
file_changed/world_event 或底图匹配/停留兜底
  → reconcile/evict
```

成功 `tool_end` 不提前 evict；失败 `tool_end { isError:true, toolCallId }` 才对所有 source 调现有单参 `evict(toolCallId)`。失败分支必须放在当前 `case 'tool_end'` 的 writer 计数之外；现状 `useWorld.ts:389-399` 只在 `source === 'writer'` 内撤离，无法覆盖 character image phantom。

## 6. 错误边界与可见性

| 边界 | 设计行为 | 漏了会怎样 |
|---|---|---|
| 畸形帧缺 `toolCallId` | 当前 case `break`，不创建无法关联的 entry | `undefined` key 把多次演出合并，后续无法过户 |
| `writer_delta` 早于 `chalk_writing` | `appendInk` pending，register 时灌入 | 湿墨静默丢失；这是 `docs/perform/00 §5` 明列的 P0 失败 |
| `tool_end.isError === true` | 对该 id 调现有单参 `evict(toolCallId)`，淡出期间显示玩家可读失败文案；不能只 `console.warn` | 骨架/半成品永久留在画布，违反 `docs/perform/00 §9` 反模式第 3 条 |
| `image_landed` 缺失/非法 asset | 不 land；保持临时 entry，最终由 dwell/超时撤离并显示失败 | `undefined` 被拼进 `/api/asset`，出现静默破图标 |
| `/api/asset` 404 / `<img onError>` | 调现有单参 `evict(toolCallId)`，由组件渲染失败相位/封条并淡出 | 用户看到破图而不是失败信息 |
| `flowColumns.exhausted` | 使用最后候选并记录开发者诊断，不回中心点；保持 phantom 可撤离 | 以中心 fallback 造成确定性重叠 |
| fetchLayer HTTP 失败 | 保留当前 state 与旧 phantom，展示既有 notice/错误；不把旧 items 当新层镜像 | 层切换后 phantom 被错误绑定到不存在的数据 |
| 同层多个并发 phantom | 首次注册分别把之前所有同层 phantom 加入 occupied；同 id 心跳只更新 | Chalk/image 互相覆盖，无法证明并发安全 |
| 用户切层 | 只过滤渲染，不销毁仍运行的 registry entry | 回到原层看不到仍在进行的生图，或当前层显示别层 phantom |

“失败可见”是 DOM/玩家文案，不是日志：`docs/perform/00 §9` 明确禁止用 `console.warn` 冒充失败反馈；`tool_end` 又不携带错误原因（`event-bridge.ts:168-181`），所以只能提供稳定的泛化文案。

## 7. 性能与不新增 WS 帧

- `flowColumns` 只在**首次 phantom register** 和服务端落位/footprint 需要真实重排时运行；`image_generation_progress` 心跳走幂等字段合并，不重新计算座位；React render、相机 framing effect、drag pointermove 均不调用它。
- `phantom.ts` 继续模块态 + `useSyncExternalStore`；phantom 进度不塞进 `LayerState`，避免每个心跳重渲整棵 `items.map`（`useWorld.ts:153-164` 是真实层状态更新点）。
- `publishSeatItems` 保存最近一次成功 fetch 的 rows 镜像，不在每次 render 复制全层；快照过滤和矩形转换只发生于新 phantom 注册。
- 服务端流式批次使用稳定排序和一次 `flowColumns` 结果；`maxColumns` 是保护阀，不是用户可见列数上限。
- 不增加 WS 帧名、不另开 WS、不增加 `cards.metadata` 键。复用既有 `chalk_writing`、`chalk_landed`、`image_generation_progress`、`image_landed`、`tool_end`、`file_changed`/`world_event`；`docs/perform/00 §1` 和 §9 反模式第 1、2 条优先。
- footprint 仍只写 `width/height` 与四键 metadata，且不落 history event（`docs/footprint/00 §3.3、§3.6`）。phantom seat、stage、失败相位都是临时投影，不写 `canvas.db`。

## 8. 验收：可机械时序断言

以下是设计后的测试/浏览器验收契约，不表示测试已写入；全量验证由主 agent 统一执行。

### 8.1 共享几何

1. 给 `flowColumns` 三个同批 boxes `a(320×200, order:1)`、`b(320×200, order:2)`、`c(320×200, order:3)`，`columnHeight=500`：同列的 `a.y < b.y`，超列后的 `c.x > b.x`；任意 placement 与 occupied 障碍的扩张矩形不相交。
2. 给右侧旧障碍，断言结果继续向右而不是移动障碍；已有 placements 的 x/y 输入在加入新 box 后保持不变。
3. 给 `h > columnHeight` 单卡，断言只占一列且 `exhausted === false`；给受限 `maxColumns` 的密集障碍，断言 `exhausted === true` 且返回位置不是 anchor fallback。

### 8.2 修复前会失败的非空 phantom 重叠用例

固定同层 rows 为空，先按当前代码调用 `phantomSeatFor({w:460,h:190}, 'world/x')` 并注册 `chalk-a`，再调用同样尺寸并注册 `chalk-b`。由于施工前 `apps/web/src/lib/phantom-seat.ts:56-58` 只把 `kind === 'image'` 加入 occupied，两个 Chalk 的 seat 相同，矩形交集面积 `overlapArea(chalk-a.seat, chalk-b.seat) > 0`（非空，预期为真）；修复后必须断言交集面积 `=== 0`。同一 fixture 同时断言真实 row 障碍也无交集。该用例不能只断言“返回了一个 seat”，否则旧代码也会假绿。

### 8.3 WS/过户时序

1. 注入 `writer_delta(toolCallId='c1', delta='ink')` 后再注入 `chalk_writing(c1)`：entry 最终 `text === 'ink'`，且只存在一个 c1 entry；当前 `phantom.ts` 已有 pending 缓冲，这条是回归锁——移除该缓冲的实现必须失败。
2. 注入 `chalk_writing(c1)`、多个 `writer_delta(c1)`、`chalk_landed(c1,path='world/x.md')`：land 前后 `seat.x/y/w/h` 相同；`land` payload 不含 seat。
3. 注入两条相同 `image_generation_progress(toolCallId='i1')`：registry entry 数量为 1，seat 不变，仅 `label/elapsedMs` 更新。
4. 注入 `image_landed(i1,asset)`：entry 在原 seat 进入 landed；随后模拟 `fetchLayer` 返回包含真实 path/底图，断言 path collection reconcile/底图匹配撤掉 phantom；不发生第二次排座。
5. 注入 `tool_end {source:'character',toolCallId:'i2',isError:true}`：即使 source 不是 writer，也出现可见 evicting 状态；不得只靠 writer busy counter 分支撤离。
6. 模拟 `enterLayer('world/y')` 的慢旧响应晚于新响应：`reqSeqRef` 丢弃旧响应；当前层 rows 与 phantom layer 仍为 y，旧层 phantom 只隐藏不污染 y 的 occupied。
7. 浏览器实测两个并发 Chalk 和一个 image ghost：三者都在当前层可见、无 `.object` 拖拽命中；随后真实 `/layer` 返回时 phantom 淡出、真实卡位置与 HTTP 的 x/y 完全相等。

### 8.4 性能/反模式门禁

- `node tools/check-ws-contract.mjs --json` 只验证既有帧消费字面量，不能替代可见行为实测；`docs/perform/00 §10` 已警告该门禁会因加 `case` 而假绿。
- 检索确认 `useWorld.ts` 是唯一 `new WebSocket`；确认无新 WS 帧名、无 `seatSpiral`/`spiralCells` 的**幻影排座调用**、无 `attention === 'authoring'` 参与幻影权限。`seatPresence` 的独立几何不属于本批，不纳入全仓零命中断言。
- DOM/浏览器断言：phantom 外壳没有 `.object`，`pointer-events:none`；失败封条在淡出期间可见；`image_landed` 的 `<img>` URL 使用既有 encode 规则；`PhantomLayer` 对 Chalk 有真实渲染分支而非只保留 image。

### 8.5 初始化 stub 空层与 Chalk 可见性

1. 初始化 stub 的空层 fixture 必须走 `phantomSeatFor(size, layer)` → `flowColumns([box], [], config)`；断言首个 seat 等于冻结 config 的 `origin`（默认 `{x:360,y:96}`），且不等于旧 `SEAT_ANCHOR` `{x:960,y:540}`。这样能机械阻止 `docs/init/03` 的 anchor 特判重新出现。
2. 注入 `chalk_writing(c1)` 后挂载唯一 `PhantomLayer`，断言渲染树存在 Chalk 分支的非空节点（例如 `data-path` 为 `phantom:c1` 的可见湿墨节点），而不是只有 image 分支；断言该节点没有 `.object`，不可进入卡片拖拽。
3. 初始化 `layer_initialized`/`layer_init_failed` 后，断言初始化专用 stub ghost 与演出 registry 不各留一份；真实层重取完成后 phantom 数量归零或仅保留其它仍在运行的 toolCallId。

**漏了会怎样：**空层仍从旧 anchor 显示而生成批次从 origin 落位，或 Chalk registry 有 seat 却无 DOM，视觉验收会错误地把“未重叠”当成“已接线”。


## 9. 与 `docs/perform/00` 冻结反模式的逐条引用

1. **反模式 1：不在前端再造帧名常量。** 本文只消费既有 `case` 字面量，不新增帧（`docs/perform/00 §9`）。

## 10. 发现的冲突 / 与 01、05 的接缝

### 10.1 与 `docs/perform/03-生图幻影与过户.md` 的冲突（需回写）

该篇把 `phantomSeatFor` 描述为 `seatSpiral`，并给出旧版 spiral 伪实现；这与冻结 `docs/layout/00 §4` 的唯一 `flowColumns` 冲突。当前工作树的 `PhantomLayer.tsx:71-84` 已有 Chalk 分支，但 `phantom-seat.ts` 仍是第二套几何且 occupied 只收 image。应在 `perform/03` 回写：

- `phantomSeatFor` 改为调用 shared `flowColumns`，不再引用 `SEAT_ANCHOR/seatSpiral`；
- occupied 过滤由“只 image”改为同层全部未撤离 phantom（Chalk + image）；
- 保留当前 `PhantomLayer` 的 Chalk 实际分支，并在回归验收中防止再次删掉；
- 明确前后端输入集合不同、输出不保证同构，真实重取优先；
- `reconcileLanded` 按代码当前的 path collection 语义（`Iterable<string>`）统一文档；当前 `useWorld.ts:167` 传数组，设计建议传 `Set` 作为 collection，但不改变“按真实 path 集合撤离”的含义；

### 10.2 与 `docs/layout/01-核心几何与服务端落位.md` 的冲突点

- `reseatLayer`：按 `docs/footprint/00 §5.1` 的 declared-version / measured-moved 判定，只有合法漂移卡进入 boxes；稳定兄弟是 occupied；玩家已有 x/y 不可被普通批次移动。

### 10.3 与 `docs/layout/05-验收与回写清单.md` 的冲突点

`05` 的验收若只检查服务端真实 rows 不相交，会漏掉本篇的核心 phantom bug；应加入：

### 10.4 与 `docs/init/03-触发链路与前端.md §3.5` 的接缝

`init/03` 目前把 stub 层自己的生成占位描述为 `ghostItemFor`，并建议空层直接使用旧 `SEAT_ANCHOR`/`seatSpiral`（`docs/init/03-触发链路与前端.md:235-286`，具体路线表 `:470-477`）。这与本批冻结的 `docs/layout/00 §4.3` 起点 `{x:360,y:96}` 及“唯一 `flowColumns`”冲突，不能让初始化 stub 幻影成为第三套座位算法。

- `ghostItemFor`（若 init 批次仍保留该 NEW 接缝）必须只构造初始化状态/文案，不自行算 x/y；座位委托 `phantomSeatFor(size, layer)`，而 `phantomSeatFor` 委托 shared `flowColumns`。
- 空层不是旧 anchor 特例：`occupied=[]` 时 `flowColumns([box], [], config)` 的首个合法 placement 就是冻结 config 的 `origin`（默认 `{x:360,y:96}`），不是 `SEAT_ANCHOR={x:960,y:540}`。如产品坚持初始化占据旧 anchor，必须先在 01/00 评审中改变 config，不能在 `ghostItemFor` 内静默特判。
- 初始化 phantom 与 Chalk/image phantom 共用同一 `PhantomLayer` 注册/过滤/过户原则；初始化专用的 `ghost` prop 若暂时保留，必须保证它不与 `phantom.ts` 产生两份同层占用或两个渲染器。
- Chalk 分支必须保留实际可见渲染：当前 `PhantomLayer.tsx:71-84` 已有 `p.kind === 'chalk'` 到 `ChalkMark` 的分支；后续 layout/init 改动不能删掉它。该分支不带 `.object` 拖拽命中。

**漏了会怎样：**stub 层仍可能在旧 anchor 显示而真实批次从新 origin 落位，生成后出现跳位；或者 flowColumns/phantomSeatFor 都正确但 Chalk 仍不渲染，验收只能看到 image 幻影而误报“布局已修复”。
