## 2. 验收对象、真相层与成功定义

06 §1、§4 已冻结两条结果：服务端最终 `canvas.db` 卡片状态按真实 `x/y/w/h/z` 不重叠，且左侧「整理」触发独立 `functional` Agent（稳定 `agentId = canvas-arranger`），读取结构化状态，必要时读取真实浏览器画面，经专用画布动作写回并复读验证。成功不等于 Agent 被 spawn，也不等于某次 action 返回 200；必须同时满足：

1. **几何成功**：目标层最新版本的所有受检 AABB（真实行值 `w/h`）无重叠；若浏览器可用，再以真实绘制盒（至少 `offsetWidth/offsetHeight`）复核 Chalk 高度；任何 `exhausted`、旧快照、未取得截图、版本冲突均不可冒充成功。
2. **行为成功**：一次玩家请求只有一个整理操作身份，经过 D 本地请求态 `accepted → processing → arranging → verifying → landed/completed`（不是 `agent_activity.phase`）或明确的 `failed/cancelled/conflict` 终态；坐标写入走 `LocalWorldStore`/ActionService，服务端安全闸通过，未写世界正文、history 事件或第二 WS。
3. **独立性成功**：整理 Agent 的 `source=functional`、`agentId=canvas-arranger`、独立 `turnId`、独立 scope/session 与 Writer 的身份、队列、结果、TTS 完全分离；按钮不能复用 Writer turn，也不能把总结当 Writer 台词。

真相优先级为 06 §2 的顺序。`canvas.db` 行值是服务端几何真相；真实 DOM 是浏览器呈现真相；`view_canvas(auto)` 是结构化感知证据而非截图（`packages/shared/src/actions/look-at.ts:399-490`）；Activity/HTTP/UI 是过程证据，不得替代最终行值。

#### 4.3.2 版本与快照集合（A/B/C/D 双向核验）

`canvasVersion:number` 是同层 canvas.db 单调位置版本；`canvasRevision:string` 是当前 canvas.db 值 digest；`snapshotId:string` 绑定 layer rows 与 source/content digests；`expectedRevision:number` 仅是 history 高水位。E 必须从 A/B/C/D 的 route schema、snapshot 返回、WS `canvas_patched` details 和 `useWorld` guard 双向提取 `{ layer, canvasVersion, canvasRevision, snapshotId, expectedCanvasVersion }`，三者不得互换。

验收须同时断言：HTTP 202 ack `ok:true` 只进入本地 `accepted/processing`，不能进入 completed；Activity 仍只用 `started|completed|failed`；`landed` 只在同层 patch/refresh 到达后，`completed` 只在服务端最新全层 rows proof（以及 screenshotPolicy evidence 的诚实表达）后；post-commit evidence failure 是 `partial`，currentness 不明是 `conflict`。D 的 `useWorld` 仍是唯一 WS ingest，不得在控制组件另开 socket。
#### 4.3.3 C snapshot / screenshot 形状与证明边界

C 篇冻结 `CanvasSnapshotV1` 身份 `{ version:'canvas-snapshot-v1', snapshotId, canvasRevision, canvasVersion, capturedAt }`，rows 必须携带 `layer/path/kind/x/y/w/h/z/footprintSource`，并完整返回 `overlaps/unplaced/links/presence/viewpoint`。截图请求携带 `{ worldId, layer, snapshotId, captureCapability, viewport, region? }`；成功返回同一 identity、PNG、renderedGeometry 与仅视觉性的 `geometryEvidence`；快照变化返回 HTTP/内部 `conflict`，不能压成 failed/cancelled。E 必须校验 requested/observed identity、同 Canvas DOM、origin/auth/ready/gate；截图是视觉 evidence，不替代最新 rows 全层 AABB proof。

### 5.5 真实 Playwright/Chromium 层

当前仓库没有 AIRP Playwright 截图实现，且 `view_canvas image` 明确 unsupported（06 §3）。因此本层只有 09 冻结并实现截图 owner/auth/origin/ready/gate 后才能执行；在此之前任何“看过图”结论均为阻断。

浏览器步骤（`NEW: tools/probe-arrange-browser.mjs` 或评审冻结的等价命令）：

1. 启动固定测试 world，打开与用户相同 origin 的 Chromium 页，等待明确 ready 信号；记录 page URL、layer、viewport、owner/session，不记录 token。
2. 先通过结构化 `view_canvas(auto)` 取 `CanvasSnapshotV1`（`snapshotId/canvasRevision/canvasVersion/rows/overlaps/unplaced/links/presence/viewpoint`），再调用冻结后的只读 `screenshot_canvas`，核对请求 `{worldId,layer,snapshotId,captureCapability,viewport,region?}` 与 screenshot 的 requested/observed identity、layer 相等；服务端不得自己渲染替代页面。
3. 在浏览器执行只读 DOM probe：对每张卡读取 `data-path`、`getBoundingClientRect()`、`offsetWidth`、`offsetHeight`、computed visibility；Chalk 另记录文本增长前后高度。截图/DOM 均不得写世界。
4. 点击整理按钮，观察阶段顺序与按钮 disabled/取消入口；等待 canvas refresh 后再取结构化 rows 和 DOM boxes。
5. 断言 painted AABB（含 CSS transform 后 rect）与服务端 rows 的重叠均为 0；对 Chalk 高度，若真实 DOM 高于 row，应将结果判为未验证/失败并进入 footprint 回写，而不是把截图当成功。
6. 依次模拟 browser missing、origin mismatch、not ready、permission denied、gate timeout、page closed；每项都必须显示失败原因，不能降级成 auto 摘要或 completed。

浏览器层能证明：同画布真实渲染路径、真实高度、按钮阶段与截图失败可见。不能证明：跨进程 SQLite 锁的所有时序、重启后的幂等、preset 集合完整性（需静态/集成层）。
