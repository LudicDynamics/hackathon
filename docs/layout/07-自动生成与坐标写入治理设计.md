## 1. 一句话定位

**所有会写 `cards.x/y` 的入口必须在同层最新真实占位、单调画布版本和 SQLite 原子边界内完成；自动排版复用 `flowColumns`，玩家位置和临时幻影不再以逐卡并发、模型坐标或视觉投影冒充最终事实。**

最小源头修法：

1. `seatNear` 把 read→compute→z→write 收进现有 `withSeatLock` + `BEGIN IMMEDIATE`；
2. explicit layout 将未选卡作为障碍，正常优先 `grid/circle/row`，冲突时只用共享 `flowColumns` 安全回退，服务端再做全层 AABB 校验，耗尽整批失败；
3. Canvas settle 把多张 DOM 结果合为一次批量坐标写，以画布版本拒绝旧快照；
4. footprint 回写与座位重排按层串行，前端丢弃低版本 `/layer`/WS；
5. phantom 继续一次性 `flowColumns` seat 与真实卡过户，长 Chalk 只属于 provisional 视觉，不写 `cards`。

## 4. NEW canvas version 与原子坐标契约

### 4.1 存储语义

**NEW `canvas_meta`**（同一 canvas.db 的并发护栏，不是第二坐标真相）：

```sql
CREATE TABLE IF NOT EXISTS canvas_meta (
  layer TEXT PRIMARY KEY,
  position_version INTEGER NOT NULL DEFAULT 0
);
```

- `position_version` 是每层单调坐标提交版本；真实坐标仍仅在 `cards.x/y/z_index`。
- 自动新批、reseat、near、explicit、drag 每次实际坐标提交在同事务中递增一次；footprint 仅改 w/h/metadata，不直接递增，随后 reseat 真移动才递增。[推断]
- 删除卡不能使版本倒退，版本行保留；跨进程依 SQLite WAL + `BEGIN IMMEDIATE`，不能依赖 Promise/HTTP/`reqSeqRef`。
- 该版本不是 history seq；`canvasRevision` 是 snapshot 的内容 digest，`snapshotId` 绑定 rows 与 source/content digests；三者不能互换。
### 4.2 NEW store 形状

```ts

  canvasRevision: string;

```

`arrangeCanvasLayer` 是唯一 store 内核；ActionService 适配器名为 `arrangeCanvas(ctx,input)`，工具名为 `arrange_canvas`（见 06 §4.5）。`applyCanvasLayout` 等底层 primitives 仍只能被该内核调用，不能成为另一个 Agent-facing action。

- `canvasVersion` 只代表该层 canvas.db 坐标写版本；`canvasRevision` 只代表 snapshot 内容 digest；`snapshotId` 绑定 layer rows 和 source digests。
- 内核在事务内检查 expected version/snapshot fence、读取全层真实 rows、执行服务端 planner 与 AABB guard；冲突整批不写。
- `z` 不由 layout 改写；drag 默认不传 z；seed 由规范 seating writer 写有效 declared w/h/metadata，不写 schema `280/180`。
- 版本冲突统一为 HTTP/tool machine outcome `conflict`（HTTP 409，details 带 expected/current `canvasVersion`、`canvasRevision`、`snapshotId`）；不得混用 `stale`/`already_exists`。

### 4.5 ActionService 接缝

ActionService 的唯一整理入口是 `arrangeCanvas(ctx,input)`，工具唯一名称是 `arrange_canvas`；store 内核唯一名称是本篇 §4.2 的 `arrangeCanvasLayer(store,input)`。08 负责 ActionContext 身份、输入校验、结果包装和工具壳，A 只提供全层 planner/真实尺寸/AABB 与低层 transaction primitives。不得再出现第二套 Agent-facing action。

### 4.6 输入、输出、副作用与操作身份

- 输入身份不是模型 turn：每次坐标提交都由 `layer + source + expectedCanvasVersion` 组成；`source` 只能是 `auto-new-batch`、`footprint-reseat`、`near`、`player-drag`、`player-arrange` 之一。整理 Agent 的 functional `turnId` 由 B 贯穿，但不能替代 `canvasVersion`。
- 输出必须包含服务端回读的 `layer`、完整 changed cards、`canvasVersion`、`canvasRevision`、`snapshotId`，以及 explicit arrange 的 `safeFallback`（若发生）；失败包含 `conflict`/`overlaps`/`exhausted` 的机器字段。
- 副作用仅限 `canvas.db` 的 cards 当前值与版本元数据，以及既有 `canvas_patched`/`card_position` 帧；不写 markdown、`history.db`、WriterResult/TTS 或 phantom registry。footprint 的 w/h 写入保持不落事件。
- 读/算阶段不得改变旧 rows；事务失败 before/after 必须相同。取消只截断未提交工作；已提交坐标事实保留。

## 5. `seatNear` 整段事务/锁

1. 校验 layer/path/anchor 后，以 `withSeatLock(layerId, ...)` 包整个 operation，第一条 DB 语句 `BEGIN IMMEDIATE`。漏掉会让两个调用在同一快照算座位。
2. 在事务内读 anchor；缺 row 时调用 **NEW** `ensureAnchorRowInSeatTransaction(layerId: string, anchorPath: string): CardRecord`，直接复用 declared 建行；不得锁内调用公开 `seatUnplaced`/`anchorOf`，避免重入死等。漏掉会使未 flush anchor 为 undefined 或锁嵌套。
3. 在事务内用 `layoutOccupied(layerId,[anchor])` 取得完整同层 stored `w/h`，不只读 anchor、不读 form。漏掉会覆盖旧卡/高 Chalk。
4. 保持现有 anchor 中心、`spiralCells`、`SEAT_STEP`、`SEAT_PAD`、跳过 `(0,0)` 的 near 语义；near 不换 flow。漏掉会丢相邻意图。
5. 同事务读 max z/version，找到 free candidate 才写；exhausted 必须结构化可见。现有 `seatNear:1504-1543` 把最后候选写出并标 `exhausted`；A 不把它说成 clean。是否改成未提交 `no_free_seat` 需连同 `moveEntity:181-205` 的文件先移动问题一并拍板。
6. COMMIT 后回读 row/version；异常 ROLLBACK，不吞错。取消只在 commit 前有效；提交后坐标保留并显示部分/已完成。
7. 同 path 重试若已有 row，返回现有 row，不再次移动；不同 path 跨进程依 SQLite 锁重读 occupied/maxZ。稳定旧卡/玩家位只作为障碍，near 不自动重排。

## 6. explicit arrange 对未选障碍

### 6.1 输入/规划

- 无 `paths`：目标是完整 `pageOfLayer`。
- 有 `paths`：校验同层；selected boxes 用 stored row，缺 row 只形成 declared seed，不先提交。
- planner snapshot 必须含全层 rows（真实 x/y/w/h/z）、seed declared 尺寸、expected version；path 按 ASCII 稳定排序。
- 只传 selected、先 `seatDeclaredRows`、不查同层/版本，分别会造成旧卡重叠、失败留孤行、旧 snapshot 覆盖新卡。

### 6.2 几何步骤

1. 用既有 `computeGrid`/`computeCircle`/`computeRow`（`canvas.ts:332-373`）生成 requested positions。
2. 用 `packages/shared/src/render/spatial.ts:29-35` 的 `boxesOverlap` 检查 selected 内、未选 rows、seed；间距由 `flowColumns` 的 `SEAT_PAD`/`obstacleGap` 统一，不加第三套常量。
3. 无冲突则保留 requested mode，未选卡不动。
4. 有冲突则 selected boxes + 未选真实 rows 交给 `flowColumns`，标 `safeFallback:'flowColumns'`；未选永不移动，selected 可被 explicit 授权移动。
5. `flowColumns.exhausted` 抛 `no_free_seat`（或评审核定的唯一等价错误），整批不插 seed、不改 x/y、不增 version；不能最后候选后称 completed。
6. `applyCanvasLayout` 同事务插 seed、写所有 positions、增一次 version、回读 rows、发既有 `canvas_patched`。服务端结果而非模型坐标决定安全。

### 6.3 旧卡/玩家语义

- 未选卡始终 obstacle，保留玩家位置；selected 旧卡只有 explicit arrange 才可移动；自动生成/footprint 不调用该 planner。
- B 的 arrange Agent 默认应传全层，或明确接受 safe fallback；F 的 prompt 不能把相对坐标当安全证明。
- layout 不改 z；失败必须英文结构化错误，如 `Cannot commit layout: selected card overlaps an unselected obstacle.`，不能只有 warning。

## 10. 失败矩阵

| 场景 | 必须结果 | 禁止 |
|---|---|---|
| near anchor 缺失/跨层 | ActionError，未提交/回滚，可见 | NaN/中心默认点 |
| near 并发不同 path | 锁/事务串行，后者重读 occupied/maxZ，不同坐标/z | 同座、后写静默覆盖 |
| near exhausted | `exhausted`/`no_free_seat` 明示非 clean；文件移动半步待 §14 拍板 | warning 后宣称成功 |
| subset 未选障碍 | 服务端 AABB/flow fallback；exhausted 整批不写 | 只移动选中卡撞旧卡 |
| version 过期/无法证明最新 | 409，before/after 不变；D local `conflict` | failed/cancelled/completed 猜测 |
| drag 任一 AABB 相交 | batch 整批 400，不写，重取/提示 | 前几张先写 |
| footprint 未稳定/重复 | pending、单飞、最新 snapshot | 写 hover 或旧 response 覆盖 |
| 同一 Writer run 重入 | 首次 request 一次 imperative；continuation 只 facts；重复 action 结构化收束/结束 run | 依 max-call warning 或 seat 算法掩盖重复生成 |
| DB/网络失败 | 失败可见，重试；不伪装完成 | console.warn 即成功 |
| phantom 乱序/失败 | pending/register/land/evict 幂等，真实 row 接管 | phantom 写 cards/重复 seat |
| cancel commit 前/后 | 前者停止未提交；后者保留事实并显示部分完成 | 假装全回滚 |
