# 世界与存档

世界书架采用两级菜单：世界 → 各次游戏存档。模板只是新游戏的起点，继续游戏必须打开对应的 `worlds/<id>`，不会再复制模板。

当前六个 `templates/*-playtest/` 体验版完整入 Git，随包携带剧情、世界 skill、角色与资产；无需队友拉取后再编译内容。无后缀目录保留作旧素材版 / 原型，当前入口清单见根 README。`tools/experiences/` 是内容编译源，维护时须与发布模板同步。带额外版本后缀的实验模板、`worlds/` 玩家存档、密钥和运行缓存仍不入库；发布模板不是用户游玩状态，更新它不会修改已有存档。

现有目录后缀是随机 UUID 的前 8 位，不是 Git commit hash；界面标为「存档 ID」。每份存档显示完整 ID、更新时间（manifest 与历史/画布数据库及 WAL 的最近修改时间）、当前游玩标记。不是历史快照列表，不提供 commit 回滚。

## 协议与归属

`GET /api/worlds` 保留 `templates`、`worlds` 数组，增加 `groups: [{id,name,templatePath,saves:[{id,path,updatedAt,active}]}]`。只枚举含有效 `world.json` 的非隐藏真实目录。先用 manifest.id 匹配模板，兼容旧脚手架时再用最长模板目录名前缀匹配；不按可翻译的显示名称合并。找不到模板的存档仍有独立入口。这里只建立书架投影，不移动旧存档、不改世界正文或新建剧情状态文件。

`DELETE /api/worlds/save` 请求 `{worldPath:"worlds/<id>"}`，响应 `{ok:true,recoveryPath}`。操作限定 worlds 的直接子目录，拒绝模板、隐藏项、穿越、符号链接、当前活动存档。删除与加载共用互斥标记，并发时返回 409。删除不是实体工具 `delete`，不产生虚假的剧情事件。

## 删除与恢复

界面逐份确认，显示存档 ID；当前游戏禁删，需先切到另一份存档。确认后整个目录原子改名至 `worlds/.trash/<原id>-<uuid>`，保留资产、数据库与会话文件，不做递归清除。回收目录不出现在书架。恢复暂由开发者停止相关游戏进程后将该目录移回 `worlds/<原id>`，先确认目标不存在；本轮没有批量删除、永久清空或恢复 UI。

实现：server `world-shelf.ts`（派生分组与安全回收）、`routes/world.ts`（接线与互斥）；web `components/WorldShelf.tsx`（两级菜单、确认与三语文案）。测试 `tools/world-shelf.test.mjs` 覆盖分组、孤立存档、当前存档保护、非法路径、符号链接、回收后内容完整和列表排除。
