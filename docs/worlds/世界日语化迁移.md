## 3. 主观流程与目录

玩家先在零级放送室听到七海叫自己，读到纸上消不干净的约定；进入一级“今夜の約束”，再选择放送室、咖啡店或屋顶。场景里的物件让玩家有具体话题可问，而不是只点角色名字选恋爱结局。

初雪原模板结构（稳定英文 ID；体验版的层级以其内容包为准）：

```text
world/                         零级：放送終了まで九十秒
  README.md                    场景第一眼
  01-opening.md                首次可行动 Chalk
  request-sheet.md             可携带的节目用纸
  tonight/                     一级：今夜の約束
    radio-studio/              二级：七海与台本
    amber-cafe/                 二级：澄与四十分钟
    campus-rooftop/             二级：初雪旧约
    first-snow/                 二级：短结算的场景骨架
```

当前前端以 `map` 对应 `world/`，因此零级直接放根目录；不是绕过导入进入一级。每个目录仍用自己的 README 描述场景，没有在 manifest 里重复声明 layers。

体验版命名示例：`world/tonight-promises/radio-studio/README.md`、`world/tonight-promises/first-snow/snow-shelter/README.md`、`player/tonight-letter.md`。日本語写在 title、正文和世界指令里，跳转与关联始终使用稳定路径。

`README.md`、`world.json`、`SKILL.md` 保留；人物资料也用英文 ID（如 `personality.md`、`memory.md`）。`first-snow-jp` 继续标识日语内容包，不要求目录名本身写成日语。

## 4. 生成语言与显示接线

当前 Writer 通过世界 skill 加载 `skills/first-snow-jp-continuity/SKILL.md` 并读取 `language.md`。角色 preset 使用平台 `system-char`，其后读语言文件与人物文档。这是现状记录：全提示词语言化还要覆盖共享指令和动态 brief 的人类可读内容，按语言维护可复用版本，不按每个世界复制一套平台规则；工具字段与协议不翻译。本轮不更改引擎或运行提示词。

两个角色 preset 里的语言槽相同：

```json
{
  "kind": "slot",
  "id": "world-language",
  "slot": "file",
  "options": {
    "path": "language.md",
    "baseDir": "cwd",
    "onMissing": "skip"
  }
}
```

`world.json.locale = "ja"` 让 UI 在世界载入时切日语；`characters[].name` 是可选显示名，不改变 `characters[].id` 或文件路径。未声明的旧模板保持原回退行为。
