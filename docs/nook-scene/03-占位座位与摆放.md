## ① 一句话定位

**给小天地子场景一条真正能用的“摆进去 / 拖得动 / 排得开”通路**：把两处写侧门禁从「只认角色根」换成「认完整 `nookSceneId`」，并让 `arrangeCards` 的两条分支把「场景」认成 `dirOf(path)`（而非角色根）——否则子场景的卡**回写必 400**（footprint）、**摆放静默写错页或必 404**（arrange place 写角色根、layout 撞白名单/复核），玩家在子场景里拖卡会把行写进父场景、点「整理」会报未知层。

### 2.6 两处门禁「修复前」的行为**不同**（契约 §2.5 修正后，2026-09-15 实测）

**这不是同一个 bug 的两个副本** —— 两处对子场景的失败形态**不同**，MUST 分开断言（`Main` 2026-09-15 spike 复核 + `N2Verify(06)`/本文实测）：

| 通路 | 现状代码 | 对 `layer=characters/elias/office` | 失败形态 |
|---|---|---|---|
| `POST /api/card/footprint` | `routes/world.ts:1194` `isValidCharacterId(layer.slice('characters/'.length))` | `slice` 得 `'elias/office'` → 正则拒 `/` → **400** | **响亮的 400**（会被立刻发现） |
| `arrangeCards`（place/layout） | `actions/canvas.ts:566` `nookIdOf(characterIdOfPath(layer) ?? '')` | `characterIdOfPath('characters/elias/office')` = `'elias'`（**只答归属哪个角色**，剥掉后续段）→ `nookIdOf('elias')` = `'characters/elias'` | **静默指向根场景**（不报错；`characters/elias/a/b`、尾斜杠 `…/office/` 同样得 `'characters/elias'` —— **`characterIdOfPath` 不看尾斜杠**） |

**为什么 arrangeCards 这条「比 400 毒得多」**：400 会立刻暴露；而「静默写错页」会让 `cards.layer` 与操作意图不一致（§4.4 破），还可能**重排根场景**——用户以为在排子场景，实际排了父场景，且**没有任何报错**。

**对验收的直接约束（`06` MUST 遵守，本文 §⑩ 已据此写）**：
- footprint 的「修复前」判据可用 **400**（那条是真的）。
- **`arrangeCards` 的「修复前失败」判据 MUST 用「写错页」描述**（断言修复前 `details.layer === 'characters/elias'` ≠ `'characters/elias/office'`），**MUST NOT 写成 404/400** —— 写成 400/404 的断言在修复前**也会通过**（假绿：它根本没报错）。layout 分支除外：它**会**在 ④ 报 `not_found`（§③ 步骤 4），那是「成员集取错页 + 复核失败」的二次效应。
- **尾斜杠 `characters/elias/office/`（E6c）**：两处修复后都 MUST 为 **400**（形状非法，§4.1）。修复前 footprint 已 400（`slice` 得 `elias/office/`，正则拒 `/`）；arrangeCards 则是 `not_found`（④）——**形状闸 MUST 是 `isNookSceneId`，不能靠 `characterIdOfPath` 兜底**（它对尾斜杠照样返回 `'elias'`）。

## ③ 行为契约逐步（每步写「漏了会怎样」）

### 步骤 0 —— 先确立一条全局不变量（本文所有论证的地基）

> **「每个目录都是场景」**：`deriveNookLayers(nookId, dirs, readFm)`（NEW）对 `dirs` 里**每一个**目录建 key（与 `deriveLayers` 同型循环，`layers.ts:56-96`），而 `listDirs(nookId)`（§2.4）是**连续目录行走**（`local-store.ts:349-369`，每遇到目录就 `out.push`）——故：**对任意真实存在的文件路径 `p`（落在 `characters/<id>/` 子树内），其直接父目录 `dirOf(p)` 必是树中的一个场景**。
> ⇒ 两个表达式恒等：`nookSceneOfPath(p, nookLayers) === dirOf(p)`。后者**免建树、免读 README**。
> 该恒等式由 `N2Shared(01)` 2026-09-15 用证据确认；本文在写侧消费它。

**边界（01 确认，实测）**：`dirOf` 对**无斜杠**输入返回 `''`（`layers.ts:48`）；`isNookSceneId('')` = false ⇒ 裸目录/半截路径返回 `null`，不会误判。

**漏了会怎样**：若不知道这等价性，place 分支会误以为「必须建树才能知道场景」，于是每次热路径拖拽都 `listDirs(nookId)` + 逐目录 `readFile`（把一次拖拽放大成 N 次 `stat`+`read`，撞 `AGENTS §5` 性能红线）。本文 C2 正是靠它把 place 做成**零额外 IO**。

### 步骤 1 —— `cards.layer` 的取值口径（契约 §4.4 已冻结）

**`cards.layer` MUST 填该卡所在场景的完整 `nookSceneId`**：

- 根场景卡 = `characters/<id>`（**与 N1 逐字相同 ⇒ 零迁移**）；
- 子场景卡 = `characters/elias/office`、`characters/elias/a/b` 等。

**为什么不能沿用 `characters/<id>`（两条理由；第 2 条是 2026-09-15 新增的强理由）**：

1. **语义**：`cards.layer` 的语义是「这张卡属于哪个页面」。子场景是独立页面（§3 决定 2/3），其卡属于该子场景。若子场景的卡沿用角色根，它们与父场景的卡在**语义上**混成一页 ⇒ `arrangeCards` 无法区分「要重排哪一页」（§4.4 原文）。
2. **座位正确性的前提**（§5.4.1，实测）：`layoutOccupied(layerId, ...)`（`local-store.ts:508-518`）逐字 `const ids = new Set(this.cardsInLayer(layerId))`，而 `cardsInLayer` = `SELECT id FROM cards WHERE layer = ?`（`:1972-1976`）。⇒ **占用集 = `cards.layer = <layerId>` 的全部行 ∪ 本页行**；`nextZ` 同样按 `cards.layer` 取 MAX（`:1022-1025`）。若父子共用一个 `cards.layer`：父场景的**门牌**与子场景**内部的卡**会被强行互相避开，而二者**根本不在同一屏**——排出的座位会为一个看不见的邻居让路。

**为什么零迁移**：根场景卡的 `cards.layer = characters/<id>` 与 N1 逐字相同（§3 决定 6）。既有 `cards` 行**无需 UPDATE**：`layer` 列只在**新排座**时写入，而子场景的行本来就不存在（子场景此前一行都看不见）。

**写入自洽性（实测，N1 §3.7 要点 3）**：`placeCard` → `applyPlaceCard`（`local-store.ts:1717-1745`）把 `layer` 实参**直接写进 UPSERT 的 `layer` 列**（`:1722-1723` 的 `cols=['id','layer']`、`vals=[path,layer]`），**不做任何反查**。故本文所有分支只要把「场景 id」作为实参传下去，写出的 `cards.layer` 即自洽；`placeCards`（`:1680-1705`）同理。

**漏了会怎样**：子场景卡若写成角色根 → 占用集被父子两页污染 → 门牌与子场景卡互斥让位 → 屏幕上出现无来由的空档；且 layout 的「重排本页」会波及不可见页的行。

### 步骤 2 —— `POST /api/card/footprint`：门禁从「角色根」换成「场景」

**现状（逐字，`routes/world.ts:1193-1212`）**：

```ts
if (layer.startsWith('characters/')) {
  const characterId = layer.slice('characters/'.length);
  // Shape gate first (NEVER path-normalise: §3.2), then existence.
  if (!isValidCharacterId(characterId)) {          // ← 对 'elias/office' 必 false

  if ((await store.statKind(`characters/${characterId}`)) !== 'dir') {

  }
} else if ((await store.resolveLayer(dirOfLayer(layer))) !== layer) {
  return res.status(404).json({ ok: false, code: 'not_found', error: 'layer must be an existing layer id' });

```

**实测确认（2026-09-15，非推断）**：`layer = 'characters/elias/office'` → `slice('characters/'.length)` 得 `'elias/office'` → `isValidCharacterId('elias/office')`：正则 `^[a-z0-9][a-z0-9-]*$`（`characters.ts:21`）拒绝 `/` → **400**（与 N1 §2.5 逐字一致）。

**改为**：

```ts
if (layer.startsWith('characters/')) {
  // Shape gate first（逐段正则，NEVER path-normalise: §4.1），then existence.
  if (!isNookSceneId(layer)) {                     // ← 接受 characters/<id>[/<seg>]*（§5.1）
    return res.status(400).json({ ok: false, code: 'invalid_argument', error: `nook scene "${layer}" is not a valid nook scene id` });
  }
  if ((await store.statKind(layer)) !== 'dir') {   // ← 检查「该场景目录」本身，不再是角色根
    return res.status(404).json({ ok: false, code: 'not_found', error: `nook scene "${layer}" has no directory` });
  }
} else if ((await store.resolveLayer(dirOfLayer(layer))) !== layer) {
  return res.status(404).json({ ok: false, code: 'not_found', error: 'layer must be an existing layer id' });
}
```

- **保留 `startsWith('characters/')` 前缀分流**（N1 §④ 理由仍成立）：畸形的 `characters/**` 值（`characters/elias/../x`、`characters/elias/Bad!`）**收进 id 校验** → 统一 400，而**不是**漏到层门禁得到误导性的 404「layer must be an existing layer id」。
- **逐段正则，不做路径 normalize**（§4.1）：`characters/elias/../office` 第二段是 `..` → `isNookSceneId` false → 400。
- **存在性 = 该场景目录的 `statKind` 为 `'dir'`**（§5.5 bullet 2）：`statKind`（`local-store.ts:309-316`）对不存在返回 `'missing'`、对文件返回 `'file'`，两者都算**不存在**。
- **不改的部分**：`boxes` 数组与逐盒校验（现状 `:1213-1233`：非数组 400、空数组直接 200、逐盒全字段校验整批 400）；`store.writeFootprints(layer, boxes)`（`:1235`）——它只用 `layer` 做 warn 文案，**行匹配是 `id = path` ONLY**（`:1272` `SELECT width, height, metadata FROM cards WHERE id = ?`，无 `layer` 条件），故 `layer` 取值**不影响命中**（`04` 篇 §9.2 已实证，本文引用不重复）。
- **漏了存在性**：对不存在的场景收下 footprint → `writeFootprints` 找不到行 → **跳过 + `console.warn` + `unchanged++`、HTTP 200**（`:1275-1281`）——把「场景名打错」伪装成「值已对」，正是 footprint §3.3 BLOCKER-1 明令 fail-loud 的那类。
- **漏了整条分支**（回到 `resolveLayer` 单门禁）：`characters/**` 走 `resolveLayer` 恒 `null`（`local-store.ts:951-956`，逐字注释「player/**, characters/<id>/**, world.json are not layers」）→ 恒 404 → 前端 `createFootprintScheduler` 的 `post`（`useWorld.ts:603-609`）把非 2xx 抛异常 → **实测尺寸永远写不回 → `cards.height` 永远是声明值 → 长卡片按声明高排座 → 长卡片重叠**（`AGENTS §7.5` 老 bug 原样复现）。

> **两端同批点名**：生产端 = `routes/world.ts` 的 `POST /api/card/footprint`；消费端 = 前端 `useWorld.ts:603` 的 `fetch('/api/card/footprint')`（`layer` 由 `layerRef.current` 提供）。`04` 篇负责保证子场景下 `layerRef.current === nookSceneId`；本文只承诺「端点对完整 nookSceneId 返回 200」。若两端不同批改，会以「POST 404、尺寸永远不更新」的**死回写**形态落地。

### 步骤 3 —— `arrangeCards` place 分支：场景 = `dirOf(place.path)`

**现状（逐字，`canvas.ts:518-534`）**：


**改为**（一次收口，其余段落逐字不动）：

```ts
let layer = layout.layer;
let paths = layout.paths;

// ── 第 0 步：建 nook 树（只建一次，供 ③/④ 复用）。硬前置：listDirs 必须在
// WorldStore 接口上（契约 §8 P7），否则本函数编译期不通（见 §⑪ 阻断项）。
const nookRoot =
  layer !== undefined && characterIdOfPath(layer) !== null ? characterIdOfPath(layer)!
  : paths !== undefined && paths.length > 0    ? characterIdOfPath(paths[0]) ?? null
  : null;
let nookLayers: Record<string, LayerConfig> = {};
if (nookRoot !== null) {
  const nookId = nookIdOf(nookRoot)!;
  nookLayers = deriveNookLayers(nookId, await store.listDirs(nookId), readFm);
}

// ── ①a 形状闸：`characters/**` 的 layer 若**不是**合法 nookSceneId ⇒ 400，MUST NOT 漏到白名单。
// 漏了 → 尾斜杠 `characters/elias/office/` 会落到 ①b 白名单 → `not_found`（形状错伪装成名字不存在），
// 且与 footprint 侧（同一输入 400）**口径不一致**。与 footprint 的前缀分流同款（§③ 步骤 2）。
if (layer !== undefined && layer.startsWith('characters/') && !isNookSceneId(layer)) {
  fail('invalid_argument', `Nook scene "${layer}" is not a valid nook scene id.`);
}
// ── ①b 白名单：显式 layer 是「层」才检查 manifest.layers；nookSceneId 是并列合法值。
// A nook scene id is a SIBLING of layers, not a member of the derived tree
// (`characters/**` is not a layer, local-store.ts:951-956). Sibling, not "join":
// `deriveLayers` (layers.ts:61-62) stays untouched (§3 决定 5).
const layerIsNook = layer !== undefined && isNookSceneId(layer);   // 形状已过闸 ⇒ 非层即 nook
if (layer !== undefined && !layerIsNook) {
  const layers = (await store.getManifest()).layers;
  if (layer !== 'map' && !(layer in layers)) {
    fail('not_found', `Unknown layer "${layer}".`);
  }
}
// 存在性：与 footprint 同型（§5.5 bullet 2）——scene 不是目录 ⇒ 404，不是「空场景」。
if (layerIsNook && (await store.statKind(layer)) !== 'dir') {
  fail('not_found', `Nook scene "${layer}" has no directory.`);
}

// ── ② 页面成员（省略 paths 时）。nook 走 §5.2 的唯一口径，与 GET /api/nook 同源；
//    与 pageOfLayer().cards 对齐（都不含门牌），门牌由 §4.3 单独合成。
if (paths === undefined) {
  if (layer === undefined) {
    fail('invalid_argument', 'arrange: a layout without "paths" needs a "layer".');
  }
  paths = layerIsNook
    ? nookSceneCards(layer, await store.listFiles(layer))
    : (await store.pageOfLayer(layer)).cards;
}

paths = [...paths].sort((a, b) => a.localeCompare(b));
for (const p of paths) assertCardPath(p, 'paths[]');

// ── ③ 从 paths[0] 反推 layer（仅当未显式给出）。nook 优先，且**去 MAP_LAYER 兜底**（§5.3）。
if (layer === undefined) {
  if (paths.length === 0) {
    fail('invalid_argument', 'arrange: cannot infer a layer from an empty "paths".');
  }
  const scene = nookSceneOfPath(paths[0], nookLayers);
  const inferred = scene ?? (await store.resolveLayer(paths[0]));
  if (inferred === null) {
    fail('not_found', `"${paths[0]}" is not on a canvas layer; arrange can only lay out cards shown on a layer page.`);
  }
  layer = inferred;
}

// ── ④ 逐 path 归属复核。**无条件**对每个 p 判断它自己属于哪个模型——这样 ③ 无论
//    走哪条入口，守卫都正确（不依赖「③ 改过 layer 后要同步改判据」这种耦合）。
for (const p of paths) {
  try { await store.readFile(p); } catch { fail('not_found', `Card not found: "${p}". Use look_at / view_canvas to list the current layer's cards.`); }
  const scene = characterIdOfPath(p) === null ? null : nookSceneOfPath(p, nookLayers);
  const owner = scene ?? (await store.resolveLayer(p));    // 两条都不命中 ⇒ null ≠ layer ⇒ 拦下
  if (owner !== layer) {
    fail('not_found', `"${p}" is not on layer "${layer}".`);
  }
}
```

> ⚠️ 上面 `④` 从 ③ 里**拆出 `layerIsNook` 的依赖**：不写 `layerIsNook ? ... : ...`，而是对每个 `p` 独立判 `characterIdOfPath(p)`。原因是 `layer` 可能由 ③ 新赋成 nook 场景，而 `layerIsNook` 是 ① 之前算的——若在 ④ 复用它就会漏判（**这是我初稿的一处自相矛盾，已改**）。`characterIdOfPath(p) === null` 只是省一次树查询；`nookSceneOfPath` 自身也已先经 `characterIdOfPath` 过滤（§5.3）。

**`readFm` 的实现**：给每个目录读 `${dir}/README.md`，缺则 `null`——与 `scanLayers`（`local-store.ts:455-466`）的 `fmByDir` 构建同款。`nookSceneOfPath` / `nookSceneCards` / `layerOfPath` **不消费 `readFm` 的内容**（只用树形与 key），故 `readFm` 可返回 `() => null`；但为与 `deriveNookLayers` 的契约形状一致、且将来 stub 判定可能需要，本文建议照 `scanLayers` 真读。

**`listDirs` 缺失时**（若 §8 P7 的接口补签名未落地）：`arrangeCards` **编译期就不通** ⇒ 见 §⑪ 阻断项与替代方案（③/④ 全改 `dirOf(p)` + `isNookSceneId`，免建树）。**不许写一个编译不过的设计。**

**推导与守卫的说明（补齐上面的选择理由）**：

- **`nookLayers` 在第 0 步就建好**（不依赖 `layer` 最终是否 nook）：`nookRoot` 从 `layer`（若是 nook）或 `paths[0]`（若是 nook 路径）取得。这消掉了「③ 把 `layer` 赋成场景后，④ 的判据要不要同步换」的耦合——④ 里每个 `p` 独立判。
- **`paths === undefined` 时**用 `nookSceneCards(layer, listFiles(layer))`：它内部**按路径位次**取「直接子级」（`cardsOfLayer` = `dirOf(f) === layer` 精确目录匹配，`layers.ts:106-114`；子场景 nook 分支委托 `nookCardPaths` = `directChildrenOf`，`emptiness.ts:19-29`），**不依赖目录集**。
- **④ 为什么用 `nookSceneOfPath` 而不是 `dirOf`**：契约 §5.5 明文要求此守卫用 `nookSceneOfPath`；且它能正确拒绝**另一角色**的 nook 路径（`characters/ryo/x.md` → `null` ≠ `'characters/elias/office'`），与 `canvas.ts:611-614` 注释「a path from ANOTHER nook still fails here」的既有裁决一致。（`dirOf(p)` 是等价表达式，place 分支 §③ 步骤 3 用它以免建树。）
- ⚠️ **MUST NOT 把守卫「改松」成「同角色前缀即放过」**：那会让 `characters/elias/balcony/*.md` 混进 `office` 的重排（`seatDeclaredRows`/`placeCards` 会把别页的卡按本页层写），**静默写坏数据**（N1 §6.3.1 的同一警告）。
- ⚠️ **MUST NOT 用裸 `layerOfPath`**：其 `'map'` 兜底（`layers.ts:131`）会让 `layer='map'` + `characters/elias/office/*` 的组合**恰好通过**守卫（§5.3.1 实测危害）。这正是契约把 `nookSceneOfPath` 定为 `string | null` 的原因。

**`paths[0]` 推导规则**（`layer` 省略时）：
- `paths` 是**路径集**，本文**不要求**「全同场景才推出」——`inferred` 取 `nookSceneOfPath(paths[0])`；随后 ④ 对**每一个** path 复核 `owner === layer`，**混源路径集必然在 ④ 失败**（不是静默接受）。这与既有行为（`:594` 取 `paths[0]`、`:615-618` 逐 path 复核）**逐字同型**。

**`manifest.layers` 白名单为什么对 nook 是「并列绕过」而不是「加入」**：`manifest.layers` 由 `scanLayers` → `deriveLayers` 从 `world/**` 派生（`layers.ts:61-62` 的 `.filter(d => d === WORLD_DIR || d.startsWith('world/'))`）。把 `characters/**` 塞进去 = A 方案，早已否决（N1 §3.1）。**故 `deriveLayers` 逐字不动**，nook 分支在白名单**之外**并列成立（§3 决定 5）。

**漏了逐卡点会怎样**：
- 漏 **①a（形状闸）** → 一个**畸形**的 `characters/**` layer（尾斜杠 `characters/elias/office/`）会落进 ①b 白名单 → `not_found "Unknown layer …"`：**「形状错」被伪装成「名字不存在」**，且与 footprint 侧（同输入 400）**口径不一致**。**这是本片新增的一条**（源自 `06` 的 E6c 实测，§⑪ 冲突 3c）。
- 漏 ①b（`layerIsNook` 并列）→ 子场景 `layer` 落入 `manifest.layers` 白名单检查。**实测（Main 2026-09-15 spike）**：`characterIdOfPath('characters/elias/office')` 返回 `'elias'` ⇒ N1 版的 `nook` 非 null ⇒ 今天白名单**被跳过**；但本文**不依赖**这个「恰好通过」（它依赖 `characterIdOfPath` 只取第一段的实现细节）——①a 先做形状闸，①b 再显式 `layerIsNook` 判别，两层都不依赖该细节。

### 步骤 5 —— 座位命名空间（契约 §4.5，含 §5.4.1 修正）

`seatUnplaced` / `reseatLayer` 的 `layerId` 实参 = **该场景的 nookSceneId**。

- **不冲突的机制**：两函数匹配既有行都走 `getLayerCards(paths)` → `SELECT id, layer, x, y, width, height, z_index, metadata FROM cards WHERE id IN (...)`（`local-store.ts:966-972`）——**纯 `id = path`，与 `layer` 列无关**。不同场景的路径集天然不相交（`characters/elias/office/desk.md` ⊄ `characters/elias` 的直接子级）。
- **占用集按 `cards.layer` 隔离**（§5.4.1，实测）：`layoutOccupied(layerId, existing)`（`:508-518`）= `cardsInLayer(layerId)`（`SELECT id FROM cards WHERE layer = ?`，`:1972-1976`）∪ 本页行。⇒ 只要子场景的卡 `cards.layer` 填**完整** nookSceneId，占用集就只含**本场景**的卡。
- **`occupied` 只含本场景的卡是正确**：父场景的门牌占一个位，子场景内部的卡在**子场景画布上**排座——两者不在同一屏（§4.5 原文）。让它们互相避让会为看不见的邻居留空档；而**不**避让才是正确（各自的画布各自排）。

**漏了会怎样**（逐条）：
- 漏「`layerId = 完整场景 id`」（仍传角色根）→ 占用集变「所有子场景 + 门牌」的并集 → 子场景首进时 `seatUnplaced` 会为父场景的门牌/他场景的卡让位（屏幕上出现无来由的空档），且 `nextZ` 按父场景的 MAX 起算 → z 序跨页漂移。
- 漏「`getLayerCards` 的 `id = path` 语义」→ 会误以为要按 `layer` 列匹配；若真按 `layer` 匹配，`seatUnplacedLocked` 的 `existingIds`（`:1003-1005`）会漏掉已存在的行 → `ON CONFLICT(id) DO NOTHING`（`:1032`）救命，但**位置不会被读回**，排座会重复算已占座位。**这是既有实现已规避的坑，N2 不碰它**（footprint §9.2 已实证，本文引用）。

### 步骤 6 —— 落账与 WS（契约 §4.7）

| 通路 | 事件 | 帧 | 依据 |
