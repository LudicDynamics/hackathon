### 2.2 层体系的既有排除（N2 **不改**）

- `deriveLayers` 只收 `world/**`（`layers.ts:61-62`）——**N2 不动它**。
- `resolveLayer()` 对 `characters/**`、`player/**` 返回 `null`，逐字注释「player/**, characters/<id>/**, world.json are not layers」：`local-store.ts:951-956`。**N2 不改它的返回值语义**；子场景是它之外的**并列**判断。

### 2.3 `listDirs()` 必须泛化（**本批新增改动，2026-09-15 实测修正**）

`listDirs()`（`local-store.ts:349-369`）的 `walk` 从 `resolvePath(WORLD_DIR)` 起步，**只返回 `world/` 子树**；唯一调用点是 `scanLayers`（`:455`，无参调用）。

⚠️ **初稿曾冻结「nook 目录集 MUST 从 `listFiles(nookId)` 推导」。该条已被 spike 证伪并撤回**，见 §2.3.1。

**冻结修法**：把 `listDirs()` 泛化为 `listDirs(prefix = WORLD_DIR): Promise<string[]>`（**默认参数 ⇒ 唯一既有调用点 `scanLayers`（`:455`，无参）行为逐字节不变**，零破坏）。nook 用 `listDirs(nookId)` 拿目录集。

**为什么 MUST 用目录行走、MUST NOT 用 `listFiles` 推导**：

| 事实 | 后果 |
|---|---|
| `listFiles` 是**文件**行走，只 push 文件（`:334-336`） | **完全空的子目录永远不出现** ⇒ 它的门牌无法生成 |
| `listDirs` 是**目录**行走，`out.push(full)` 在递归前（`:363-364`） | 空目录照常出现 ⇒ 门牌存在，与 `world/` 一致 |

**这不是细节，是产品语义**：`world/` 今天**会**为一个完全空的子目录出 stub 门牌（实测 §2.3.1），含义是「门存在、场景未写——走进去就把它写出来」（`layers.ts:12-13`、`doc-11 §3`）。nook 若用 `listFiles` 推导，就会出现「world 里空房间有门，nook 里空房间凭空消失」的**双口径**，且**推翻**「嵌套 = 目录」这条架构公理（`layers.ts:19-22`：目录树决定嵌套，与目录里有没有文件无关）。

## 4. 冻结形状

### 4.1 `nookSceneId`（场景 id，本批新增概念）

**`nookSceneId` = `characters/<id>/` 子树中某个**目录**的世界根相对路径**（无前导 `/`，无尾随 `/`）。

```text
characters/elias                    ← 角色根场景（=== N1 的 nookId，逐字不变）
characters/elias/office             ← 子场景
characters/elias/parallel-timeline  ← 子场景
characters/elias/a/b/c              ← 任意深度
```

- 第一段 MUST 通过 `isValidCharacterId`（`rules/characters.ts:24`，`^[a-z0-9][a-z0-9-]*$`）。
- 后续每段 MUST 通过**同一正则**（`isValidNookSegment`，§5.1）。**任一段含 `.` 开头或非 kebab-case ⇒ 非法**（这同时挡住 `.pi`、`..`、大写、空格）。
- **MUST NOT** 用路径 normalize 做校验闸；闸在**逐段正则**（与 N1 §3.2 同一条纪律）。
- **前导 `/` 的处置（裁决，2026-09-15 采纳 `02`）**：`isValidNookScenePath` **拒绝**前导 `/`（逐段正则下空段 ⇒ false），路由侧**MUST NOT** 归一（不 `replace(/^\/+/, '')`）。理由：归一化会把 `/office`、`//office`、`office` 三种**不同字符串**静默折叠为同一语义 —— 与「不做 path normalize」同一条纪律。（`01` 的 U5 曾倾向宽容化；**以本条为准**。）
- **尾斜杠同样非法**：`characters/<id>/office/` MUST 被拒（无尾随 `/`），且 MUST **不**靠 `characterIdOfPath` 兜底（它对尾斜杠照样返回 `<id>`，见 §2.5）。
- 校验函数唯一实现：**§5.1**。禁止各处自行拆分字符串判断。

### 4.2 端点形状（`GET /api/nook`）

```jsonc
// GET /api/nook?character=<id>&scene=<相对该角色根的路径，可省略>
// scene 省略或为空  ⇒ 角色根场景（=== N1 行为）
// scene = "office"  ⇒ characters/<id>/office
// scene = "a/b"     ⇒ characters/<id>/a/b
```

返回体**仍与 `/api/layer` 的 `LayerState` 逐字段同形**（`layer, scene, bg, audio, items, links, presence, worldFrozen`），其中：

| 字段 | 冻结取值 |
|---|---|
| `layer` | **该场景的完整 nookSceneId**（如 `characters/elias/office`）。根场景即 `characters/<id>` |
| `scene` | 该场景目录的 `README.md`（`kind: 'scene'`）；**缺 README 则 `null`**（不合成，交前端渲染「只有卡、没有门面」） |
| `items` | 该场景的**卡（§5.2）** + 直接子目录的**门牌项（§4.3）** |
| `bg` / `audio` | 从**该场景 README** 的 frontmatter 读（OWN-only，`characters/` 不继承 `map` 的三态；沿用 N1 §3.1）。缺 README ⇒ 默认值 |

### 4.3 门牌项（door）—— 冻结形状

**门牌来源 = 该场景的「直接子目录」**，与 `world/` 的 `childLayers` 同型。**直接子目录的定义 = 该场景路径下的下一层目录**（从 **`listDirs(nookId)`** 的目录集推导，§2.3/§5.3）。**含完全空的子目录**（实测对照组：`world/` 对空目录照常出门牌）。

每个门牌是一个 `LayerItem`，形状与 `/api/layer` 的门牌**同型**：

| 情形 | `path` | `filename` | `frontmatter` | `body` |
|---|---|---|---|---|
| 子目录**有** `README.md` | `<子场景>/README.md` | `'README.md'` | 该 README 的真实 frontmatter | 真实正文 |
| 子目录**无** `README.md` | `<子场景>/README.md` | `'README.md'` | `{ type: 'readme', name: <目录名>, door: true, stub: <§见下> }` | `''` |

**`stub` 的冻结口径（诚实性要求）**：`stub = true` **当且仅当**该子目录**既无 README 又无直接卡**。若目录有卡但无 README（今日实测：`characters/elias/meta/`），`stub = false` —— 否则前端会照 `isStub` 打「UNWRITTEN / まだ白紙」文案，而该目录**明明有内容**，那是**说谎**。（初稿此处的例子是 `writing/`，该目录已于 `0424fe8` 改名为 `meta/`；语义不变。）

> ⚠️ **`stub` MUST NOT 被读作「真正空目录」（评审 B-B2，2026-09-15 更正）**：本批**刻意不新增 `hasDeeper`**（§3 决定 / `02:226` / `06:119`），故一个**只含孙目录**的目录（如 `characters/elias/a/` 下只有 `b/c.md`）满足「无 README 且无直接卡」⇒ `stub = true`，**但它并非空**（走进去会看到门 `b`）。因此 `stub` 的**精确语义**是「**本目录层没有可读内容**」，**不是**「房间是空的」。下游 MUST NOT 据此判定「可以安全重新初始化」——那正是这个字段被做诚实之后**残留的误读风险**。
>
> **`stub` 的文案承诺 MUST 与之相符（评审 B-B3）**：前端对 `stub=true` 渲染 `CardRenderer.tsx:160` 的 `UNWRITTEN · walk in, and it will be written →`（日文 `まだ白紙 · 一歩先から物語が生まれる →`）。但本批**冻结了「nook 子场景 stub 初始化不在范围内」**（§6 边界；`05:110-116` 实测这是**结构性**的：`init` 的 `dir` 恒为 `characters/<id>`，永不指向子场景）。⇒ 这句文案**承诺了一个本批结构上无法兑现的事件**：玩家走进去只会看到空画布且无可提交控件（`04:633-636` 自己承认「玩家看不到出路」）。**范围边界不构成「不可兑现承诺」的许可证 —— flag 被做诚实了，但玩家真正读到的那句话没有。**
> **冻结**：`stub=true` 的门牌文案 **MUST NOT 承诺「走进去就会被写」**。落地期二选一：① 改为**陈述现状 + 给出去路**（如「本房间还没有内容 · 从外面可开门查看」）；② 若本批要保留初始化承诺，则 MUST 把「子场景 stub 初始化」纳入范围（本批已明确不纳）。**推荐 ①**（本批不动初始化，故文案必须降级为诚实陈述）。该文案落在 `CardRenderer.tsx:159-160`，属**前端改动**，归 `04` 认领并在其文档登记。

**门牌 MUST NOT 递归**：只出直接子目录，子目录内部的卡与更深门牌**不得**出现在父场景（§3 决定 4）。

### 4.4 `cards.layer` 的取值（冻结）

**`cards.layer` MUST 填该卡所在场景的完整 `nookSceneId`。**

- 根场景卡的 `cards.layer` = `characters/<id>`（**与 N1 逐字相同 ⇒ 零迁移**）。
- 子场景卡的 `cards.layer` = `characters/<id>/office` 等。
- 行匹配**仍是 `cards.id = path` ONLY**（footprint 契约不变）；`cards.layer` 与匹配键解耦（N1 §3.3 的同一逻辑）。
- `placeCard`/`placeCards` **直接把实参写进 `cards.layer`、不反查**（N1 §3.7 要点 3 已实测），故写入自洽。

**为什么这样对**：`cards.layer` 的语义是「这张卡属于哪个页面」。子场景是独立页面，其卡属于该子场景。若沿用 `characters/<id>`，子场景的卡会与父场景的卡在**语义上**混成一页（虽然 `id=path` 让存储不冲突），且 `arrangeCards` 无法区分要重排哪一页。

### 4.5 座位命名空间（冻结）

- `seatUnplaced(sceneId, files)` / `reseatLayer(sceneId, files)` 的 `layerId` 实参 = **该场景的 nookSceneId**。
- **不冲突的机制**：两函数匹配既有行都走 `getLayerCards(paths)` → `WHERE id IN (...)`（`local-store.ts:966-972`），**纯 `id = path`，与 `layer` 列无关**。不同场景的路径集天然不相交。
- 占用集（`occupied`）的邻居只来自**本场景的卡**——这是**正确**的：父场景的门牌占一个位，子场景内部的卡在子场景画布上排座，两者不在同一屏，**不需要**互相避让。

### 4.6 前端寻址（冻结）

### 4.7 新子目录的显示时机（本批不做实时）

**冻结**：本批**不做**「新建子目录立刻出现在 nook 里」的实时推送。

### 10.2 复现出的规律（值得记住的）

**RB1 是「假绿」的镜像形态——不是「永远绿」，而是「永远红」**：断言写成了**结构脆弱的正则**（跨注释跨元素），于是它在**任何**实现下都失败。传统「假绿」是测不出 bug；这种是**测不出正确**，同样让验收失去意义，且更吵（会掩盖真正的失败）。
⇒ **验收断言 MUST 锚定结构边界**（行首 / JSX 元素），不得用会跨注释的贪婪区间。

**RB3 是「两个各自正确的决定叠出一个不可达分支」**：形状闸先于存在性检查（`02` 正确）、文件路径含 `.` 故非法（`§4.1` 正确）⇒ 「指向文件 ⇒ 404」这条断言**在数学上不可能为真**。两处设计都对，**交互错了**。这正是评审门存在的理由。
