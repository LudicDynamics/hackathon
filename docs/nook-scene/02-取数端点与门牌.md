## ③ 行为契约逐步（每步写「漏了会怎样」）

> 顺序即实现顺序。**形状闸在前、存在门禁在后**：反过来会让 `?scene=../..` 这类畸形输入先撞 `statKind`（`resolvePath` 会抛 `ActionError` → 落到 catch → 500），把 400 变成 500。

### 步骤 1：取活跃世界（**不改**，但注意那条 400 分支对 `/nook` **不可达**）

```ts
const store = getActiveStore();
if (!store) return res.status(400).json({ error: 'No active world' });   // routes/world.ts:675-676（既有，保留）
```

- 这行**留着**，但它对 `/nook` **不可达**：`createWorldRouter` 的前置中间件把 `/nook` 列在 `needsWorld`（`routes/world.ts:488`），未加载世界时在 `:489-491` 就返回了。**[实测]** 真起服务、`getActiveStore()` 恒返 `null`：

  ```jsonc
  // GET /api/nook?character=elias  —— 未加载世界时
  {"code":"no_active_world","error":"Choose a world or start a new save."}   // HTTP 409（不是 400！）
  ```

- **漏了会怎样**：`store` 为 null 时 `store.listFiles` 直接 TypeError → 500，前端拿到 500 而非明确的「未加载世界」。**实测该分支对 `/nook` 不可达（前置中间件给 409）—— 见 §⑪ 冲突 1（主 agent 已采纳本片实测并改契约）。**

### 步骤 2：校验 `character`（**不改**）

```ts
const id = typeof req.query.character === 'string' ? req.query.character : '';
if (!isValidCharacterId(id)) {
  return res.status(400).json({ ok: false, code: 'invalid_argument', error: 'character must be a lower-kebab-case id' });
}
const nookId = nookIdOf(id)!;   // 已过同一正则 ⇒ 非 null（nookIdOf 内部就是 isValidCharacterId，rules/characters.ts:35-37）
```

- **`!` 断言安全**：`nookIdOf` 用的就是 `isValidCharacterId` 的同一个正则，步骤 2 已闸住。
- 缺参 / `''` / `character=Bad` / `character=../etc` / `character=a/b` → 400。**[实测]** `?character=Bad` → `400 {"ok":false,"code":"invalid_argument","error":"character must be a lower-kebab-case id"}`；`?character=nobody`（形状合法、目录不存在）→ 步骤 4 的 404。
- 重复 `?character=a&character=b`：express 给 `string[]` → `typeof !== 'string'` → 走上式的 `''` → 400。**有意**（不是「取第一个」）——见 §⑫ U4。
- **漏了会怎样**：`?character=../../../etc` 直达步骤 4 的 `statKind`；虽然 `resolvePath`（`local-store.ts:260-262`）会拦，但那是**抛异常** → 500，且「靠下层偶然拦截」不是安全边界。

### 步骤 3：解析并校验 `scene`（**本片新增，核心**）

```ts
const rawScene = req.query.scene;
let scene = '';
if (rawScene === undefined) {
  scene = '';                                    // 省略 ⇒ 角色根
} else if (typeof rawScene === 'string') {
  scene = rawScene;                              // '' ⇒ 角色根；否则逐段校验
} else {
  return res.status(400).json({ ok: false, code: 'invalid_argument', error: 'scene must be a single string' });
}
if (!isValidNookScenePath(scene)) {              // NEW（01）；'' / null / undefined ⇒ true
  return res.status(400).json({
    ok: false, code: 'invalid_argument',
    error: 'scene must be a slash-joined path of lower-kebab-case segments',
  });
}
// 唯一校验函数已放行 ⇒ 这里是纯机械拼接，MUST NOT 再写一份「按 / 拆分判断」。
const sceneId = scene === '' ? nookId : `${nookId}/${scene}`;
// 二次断言（廉价、防御性）：拼出来必须是合法 nookSceneId。契约 §4.1 冻结「无前导 /、无尾随 /」。
if (!isNookSceneId(sceneId)) {                   // NEW（01）
  return res.status(400).json({ ok: false, code: 'invalid_argument', error: 'scene must be a valid nook scene path' });
}
```

- **MUST NOT 用路径 normalize 做闸**（nook-scene 00 §4.1 逐字）。`path.normalize('a/../b')` 悄悄变成 `b` —— 那是**第二种被接受的形状**，与「逐段正则」这条纪律直接冲突。
- **MUST NOT 在解析处 `replace(/^\/+/, '')` 或剥尾斜杠**（`01` 的 U5 建议前者）。**本片裁决：前导/尾随 `/` ⇒ 400。** 理由：契约 §4.1 冻结「无前导 `/`、无尾随 `/`」；主动剥离会让 `?scene=/office` 与 `?scene=office` 都成功，于是「什么形状合法」有了两份答案，而**唯一实现**的目的一旦破掉，`03` 的 `arrangeCards` 门禁就会与这里分叉（它拿的是 `cards.layer` 列，不会剥离）。分歧登记在 §⑪ 冲突 3，交主 agent 裁决。
- **`isValidNookScenePath` 必须拒绝**（逐段正则 `^[a-z0-9][a-z0-9-]*$`，与 `CHARACTER_ID_RE` 同条）：

  | 输入 | 结果 | 为什么 |
  |---|---|---|
  | `office` / `a/b/c` | ✅ 放行 | 全 kebab-case；深度不限（nook-scene 00 §3 决定 1） |
  | `office/` | ❌ 400 | 尾段 `''` 不匹配正则 |
  | `/office` / `office//a` | ❌ 400 | 首 / 中空段 |
  | `.pi` / `..` | ❌ 400 | 首字符不是 `[a-z0-9]` |
  | `Office` / `a_b` / `a.b` / `办公室` | ❌ 400 | 非 kebab-case |

- **漏了会怎样**（逐条）：
  - 漏 `typeof !== 'string'` 分支：`?scene[a]=b` 时 express 给对象 → `isValidNookScenePath` 收到非字符串 → **若 `01` 的实现 `.split('/')` 会 TypeError → 500**；即使容错，也是「靠下层偶然」。
  - 漏 `isValidNookScenePath`：`scene` 带着 `..` / 前导 `/` 直入 `statKind` → 要么 500（`resolvePath` 抛），要么**逃出角色目录读到世界别处**（`scene=../other`），后者是**越权读取**，比 500 严重得多。
  - 漏 `isNookSceneId` 二次断言：只是少一道廉价保险，**不构成漏洞**（前两步已足够）。留着是因为它把「契约冻结的形状」写成可机械核验的一行（`06` 可断言）。

### 步骤 4：场景存在性（**200 与 404 的分水岭**）

```ts
// statKind 是唯一能分开 'missing' / 'file' / 'dir' 的原语（local-store.ts:309-316，不抛）。
// listFiles 对不存在的路径静默返 []（:339-341 的空 catch），用它做存在性判据会让 404 永不发出。
if ((await store.statKind(sceneId)) !== 'dir') {
  return res.status(404).json({
    ok: false, code: 'not_found',
    error: scene === '' ? `No such character: "${id}"` : `No such scene: "${sceneId}"`,
  });
}
```

- 判据是 **`!== 'dir'`** 而非 `=== 'missing'`：`scene` 指向一个**文件**（畸形世界）时也 404。**但注意：仅当该文件名不含 `.` 时才能走到这里**（见下方「file 分支的可达性」）。
- **`characters/<id>` 与 `characters/<id>/office` 走同一行判断** —— 这是 N1 步骤 3 的**泛化**：`scene === ''` 时 `sceneId === nookId`，那个「角色存在」分支自然被覆盖，不再需要单列。
- **「场景不存在」与「场景是空的」由此可区分**（§4.2 硬要求）。**三态的触发条件**：

  | 事实 | 触发条件 | `statKind` | HTTP |
  |---|---|---|---|
  | 目录存在、有 README、无卡 | `scene=office` | `'dir'` | **200** `items:[]` + `scene != null` |
  | 目录存在、无 README、有卡 | `scene=writing` | `'dir'` | **200** `items.length===3` + `scene === null` |
  | 目录不存在 | `scene=nope` | `'missing'` | **404** `not_found` |
  | **无扩展名的文件**存在 | `scene=office`（把 `office` **建成文件**） | `'file'` | **404** `not_found` |
  | **含 `.` 的路径**（如 `unspoken.md`） | — | **走不到步骤 4** | **400**（步骤 3 形状闸先拦） |

  **⚠️ file 分支的可达性（评审 blocker N2-A4，主 agent 2026-09-15 实测）**：步骤 3 的 `isValidNookScenePath` 逐段正则 `^[a-z0-9][a-z0-9-]*$` **拒绝任何含 `.` 的段** ⇒ `?scene=unspoken.md`、`?scene=office/desk.md` **恒返 400**，**永不进入步骤 4**，因此 `statKind === 'file'` 分支**用带扩展名的文件名永远测不到**。**[实测]** `isValidNookScenePath('office/desk.md') === false`、`isValidNookScenePath('unspoken.md') === false`。

  **本片裁决（采纳主 agent 的方案 ②）**：**不改设计**（形状闸先于存在性是**正确**的 —— 它同时挡住 `..` 越权，见步骤 3），改为把「file 分支」的验收 fixture 定为**无扩展名的文件**：夹具把 `characters/ryo/office` 建成一个**文件**（而非目录），则 `?character=ryo&scene=office` 的 `scene=office` 是合法 kebab-case 段 ⇒ 通过步骤 3 ⇒ 步骤 4 的 `statKind('characters/ryo/office') === 'file'` ⇒ **404**。夹具建法归 `06`；本片只负责声明**该分支可被触发、触发条件是「无扩展名文件」**。

  **理由**：§4.2 冻结「不存在 / 是文件 / 是空的」三者必须可区分 —— **不测这个区分等于没测**。`unspoken.md` 这条断言（旧 A6）测的是形状闸（400），**不是** file 分支，故必须换 fixture 才能覆盖三态。

- **漏了会怎样**：缺这一步 ⇒「不存在的场景」被当「空场景」→ 200 + 空 `items`；前端 `NookView` 的空态判据 `state.items.length === 0 && state.scene === null`（`NookView.tsx:473`）于是把**不存在的房间**渲染成「未写过的房间」，还会给出初始化入口（`StubPrompt kind="nook"`）—— 用户会在一个**根本不存在**的路径上触发 `nook-init`。

### 步骤 5：派生 nook 树（**门牌的来源**）

```ts
// dirs MUST 来自 listDirs —— §2.3：listFiles 是文件行走，完全空的子目录会消失。
const dirs = await store.listDirs(nookId);                     // P1 泛化后（01）；泛化前它只认 world/，行为错
const fmByDir = new Map<string, Record<string, any> | null>();
for (const d of dirs) {
  try { fmByDir.set(d, parseFrontmatter(await store.readFile(`${d}/README.md`)).frontmatter); }
  catch { fmByDir.set(d, null); }                              // 无 README ⇒ stub 场景
}
// readFm 是【同步】回调（与 deriveLayers 同型），所以必须先预读 —— 与 scanLayers(:456-463) 同一模式。
const tree = deriveNookLayers(nookId, dirs, (d) => fmByDir.get(d) ?? null);   // NEW（01）
const doorIds = nookSceneDoors(sceneId, tree);                 // NEW（01）；= childLayers(sceneId, tree)，稳定序
```

- **`readFm` 同步**是**实现陷阱**：`deriveNookLayers` 逐目录调它，回调里 `await` 会得到 Promise 对象而不是 frontmatter，于是**每个目录都被判成 stub**（`layers.ts:88-93` 的 `fm ? … : {stub:true}` 分支），门牌全部丢 `name` → 前端显示目录名。预读 Map 是唯一正解（`scanLayers` 已这么做，照抄）。
- **`deriveNookLayers` MUST 复用** `layers.ts` 的 `dirOf` / `cardsOfLayer` / `childLayers` / `layerOfPath`，不复制实现（nook-scene 00 §5.3）。
- **`listDirs(nookId)` 是关键**（P1 + P7）。**[实测]（主 agent spike B/C 对照）**：完全空的子目录在 `listFiles` 里**不出现**，在 `listDirs` 里出现；`world/` 侧今天**会**给空目录出门牌（`world/totally-empty`）⇒ nook 若用 `listFiles` 推，就出现「world 空房间有门、nook 空房间凭空消失」的双口径，且 §4.3 的 `stub=true` 分支**永不可达**。
- **作用域**：`listDirs(nookId)` 只扫该角色目录（不是整个世界），与 `listFiles(nookId)` 同量级。
- **漏了会怎样**：用 `listFiles` 推目录集 → 空目录不出现（门牌丢失 + `stub=true` 死码）；不预读 frontmatter → 门牌全变 stub 视觉（`CardRenderer.tsx:159-160` 打「UNWRITTEN · walk in, and it will be written →」），**对一间已经写好的房间说谎**。

### 步骤 6：组装 `items` = 卡 + 门牌（**本片核心**）

```ts
// 一次 listFiles(nookId)：角色作用域（不是世界作用域），同一份结果同时服务「卡集」与「门牌 stub 判定」。
const allFiles = await store.listFiles(nookId);

// 6a. 卡：§5.2 的唯一页面成员函数（根场景委托 nookCardPaths，子场景委托 cardsOfLayer）
const cardPaths = nookSceneCards(sceneId, allFiles);            // NEW（01）；不含门牌、不含自身 README
const cardItems = await readLayerItems(store, cardPaths);       // 复用 routes/world.ts:420-428（逐字同形）

// 6b. 门牌：§4.3 冻结形状。直接子目录，一律 path = `${doorId}/README.md`
const doorItems = await Promise.all(doorIds.map(async (doorId): Promise<LayerItem> => {
  const readme = `${doorId}/README.md`;
  try {
    const { frontmatter, body } = parseFrontmatter(await store.readFile(readme));
    return { path: readme, filename: 'README.md', frontmatter, body };    // 有 README：真实 frontmatter + 真实正文
  } catch {
    // 无 README：合成门牌。stub 口径见下 —— 与 /api/layer 有意不同。
    const hasCards = nookSceneCards(doorId, allFiles).length > 0;         // 该目录【直接】有卡吗
    // MUST NOT 检查「更深子目录」——主 agent 2026-09-15 裁决（见 §⑫ U2）：
    // stub 的判据是「该目录自身有没有内容」，不是「它下面有没有更深目录」。
    return {
      path: readme,
      filename: 'README.md',
      frontmatter: { type: 'readme', name: doorId.split('/').pop(), door: true, stub: !hasCards },
      body: '',                                                           // 冻结：MUST NOT 照抄层的那句英文
    };
  }
}));

const items = [...cardItems, ...doorItems];                     // 卡在前、门牌在后（与 /api/layer 的 allItems 同序）
```

**`stub` 口径（冻结 §4.3，**主 agent 2026-09-15 裁决按字面**）**：

```
stub = true  ⟺  该子目录【无 README】且【无任何直接卡】
```

- 两个条件缺一不可。契约原文「既无 README 又无任何卡（**真正空目录**）」——**主 agent 2026-09-15 裁决按字面实现**：`stub` 的语义是「**这间屋子本身**还没被住过」，判据是该目录**自身**有没有内容，**不是**它下面有没有更深目录（见 §⑫ U2 的反例）。
- `hasCards` 由 `nookSceneCards(doorId, allFiles)` 回答（同一份 `allFiles`，不再走一次文件系统）。

### 步骤 7：座位（**复用 N1 §3.3，只换 `layerId` 实参**）

```ts

  sceneId,
  items.map((it) => ({ path: it.path, ...declaredSizeOf(it) }))

```

- **唯一的分叉就是这两处 `layerId` 实参**：根场景时 `sceneId === nookId`（与今天逐字节相同，零迁移）；子场景时是 `characters/<id>/office`。
- **为什么必须是 `sceneId` 而不是 `nookId`（冻结 §4.4/§4.5 + 主 agent 第 3 条更正）**：`seatUnplaced` 的占用集走 `layoutOccupied(layerId, existing)` → `const ids = new Set(this.cardsInLayer(layerId))`（`local-store.ts:508-518`），而 `cardsInLayer` = `SELECT id FROM cards WHERE layer = ?`（`:1972-1976`）；`nextZ` 同样按 `cards.layer` 取 `MAX(z_index)`（`:1022-1025`）。**传 `nookId` 会让父子场景共用一个占用集**：父场景的门牌（当前世界 5 张）与子场景内部的卡会被强行互相避让 —— 而它们**根本不在同一屏**。传 `sceneId` 则天然隔离（不同场景的路径集不相交，见 §④）。
  - **漏了会怎样**：`cards.layer` 撒谎（子场景的卡被标成根场景），父子座位互相挤压，`03` 的 `arrangeCards` 无法区分要重排哪一页。
- **门牌也要有座位**：门牌是画布上的卡（kind = `gate`，由 `filename === 'README.md'` 判定，`forms.ts:117`，`w:288 h:240`），所以**必须**进 `items` → 进 `seatUnplaced`。这就是 §4.3 把门牌放进 `items`（而非像 `scene` 那样单独返回）的**机制性理由**：**`/api/layer` 的 `scene` 与门牌是两类东西** —— `scene` 是「**本页自己**的 README」（不进 `items`，防止一个 path 两个位置，`routes/world.ts:935-938`），门牌是「**别的**页面的 README」（进 `items`、要座位）。nook 沿用同一分层。
  - **门牌如何进 `occupied`**：它走同一条 `seatUnplaced(sceneId, …)`，于是它的行 `cards.layer = 父场景 id`、占用集 = 父场景的行 ∪ 本页行（`layoutOccupied` 的 `ids` 并集）→ 与父场景的卡互相避让（正确，同屏），与子场景内部的卡互不干涉（正确，不同屏）。
- **顺序不可颠倒**：先 `seatUnplaced`（建行）再 `reseatLayer`（判漂移/补 `formVersion`），与 `/api/layer:895-906` 同序。`reseatLayer` 是 F1「实测占位变大 → 座位让开」的**唯一**发生地；`seatUnplaced` 只给无行的卡排座。
- **幂等**：第二次请求时所有 path 都有行 → `seatUnplaced` 返 `[]`；`reseatLayer` 只在 declared/measured 漂移时才动。

## 关键设计决定与最不确定处（一段话）

**关键设计决定**：`scene` 走**逐段正则**闸（`isValidNookScenePath`）而**绝不 normalize / 归一化斜杠**（前导、尾随 `/` 一律 400；主 agent 已采纳并把契约 §4.1/§4.2 同步），把 `sceneId` 拼装与存在性判断（`statKind !== 'dir'` → 404）串成「形状在前、存在在后」的单线性；`items` 由「`nookSceneCards` 的卡」+「`nookSceneDoors` 的直接子目录门牌」两段构成，**门牌一律 `path = <doorId>/README.md`、`body: ''`、`stub = 无 README 且无直接卡`**（按字面，主 agent 已裁决不批 `hasDeeper`）。这条 `stub` 与层口径（`stub = 无 README`）的差异是**本批的核心修复**：它让 `meta/`（无 README、有 1 张卡）的门牌**不报 UNWRITTEN**（层口径会报，正是本批要修的谎）。座位只改 `layerId` 实参（`nookId` → `sceneId`），靠 `cards.layer` 隔离父子占用集，门牌因此天然落进父场景的 `occupied`。

**最不确定**：① `items` 的顺序未冻结（卡序来自 `fs.readdir`、门牌序来自 `childLayers.sort()`，见 U3）—— 它只影响同批排座的 z 分配，不影响正确性，但 `06` 值得连发两次探针看是否稳定；② **夹具数量不可信**（见 U9，已裁）—— 本片的数量断言（5 门牌 / 4 卡 / 1 卡）绑在一个被第三方改过的 `templates/exp/` 上，`06` MUST 改用现场构造的冻结世界。其余曾与主 agent 对撞的项（无世界 409、前导 `/` 拒绝、`stub` 按字面）**均已裁决消解**，本文已按裁决改。
