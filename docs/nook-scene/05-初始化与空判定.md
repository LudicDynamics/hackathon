## ① 一句话定位

**把「小天地是空的吗」这个判据从「只数根目录的散文件」改成「既看散文件、也看有没有房间」——因为 A 档下「内容全在子目录」是常态，而旧判据会把这种房间判成空房，然后往里再铺一层家具。**

一句话实现：`isNookEmpty` / `hasInitProduct` 各加一个**目录集入参**，并在 `rules/emptiness.ts` 新增唯一原语 `directChildDirsOf`，使「有子目录」可由 `listDirs` 的输出自洽判定（`files` 是**文件**行走，看不到空目录——契约 §5.4 ⚠️ 实测）。

**两个函数是同一个 bug 的两半，MUST 同批改**：`isNookEmpty` 控制「要不要 spawn」，`hasInitProduct` 控制「spawn 之后算不算成功」。只看 `files` 的判据在两个位置都会把「内容在子目录」误判为「没有内容」。

### 2.2 语义（逐字冻结）

```ts
/**
 * 直接子目录名（不含路径前缀、不含 dir 自身）。与 `local-store.ts:360` 的点开头
 * 规则一致：段以 '.' 开头即跳过。
 */
export function directChildDirsOf(dirs: readonly string[], dir: string): string[] {
  const prefix = dir === '' ? '' : `${dir}/`;
  const out = new Set<string>();
  for (const d of dirs) {
    if (!d.startsWith(prefix)) continue;
    const rest = d.slice(prefix.length);
    if (rest === '' || rest.includes('/') || rest.startsWith('.')) continue;
    out.add(rest);
  }
  return [...out].sort();
}

/** nook 为空 ⟺ 无任何非 .json 直接子级，且无任何直接子目录。 */
export function isNookEmpty(files, dir, dirs): boolean {
  return directChildrenOf(files, dir).every((n) => n.endsWith('.json'))
      && directChildDirsOf(dirs, dir).length === 0;
}

/** 产物 = 写了卡（非 .json 直接子级）或建了子场景（直接子目录）。 */
export function hasInitProduct(files, dir, kind, dirs): boolean {
  const children = directChildrenOf(files, dir);
  if (kind === 'scene') return children.includes('README.md');   // dirs 不参与
  return children.some((n) => !n.endsWith('.json'))
      || directChildDirsOf(dirs, dir).length > 0;
}
```

**关键取舍 1：为什么目录集是「入参」而不是「从 `files` 推导」。**
契约 §5.4 ⚠️ 已实测：`isNookEmpty` 的 `files` 来自 `listFiles`，那是**文件**行走（`local-store.ts:334-336` 只 push 文件），**完全空的子目录永不出现**。若从 `files` 的路径前缀反推目录，会与契约 §5.3 的 `deriveNookLayers(nookId, dirs, readFm)`（收 `listDirs` 产物）形成**第二份目录口径**——同一份空目录，门牌看得见（§4.3 的 `stub=true` 分支）而空判定看不见，两处对不上。故 `dirs` MUST 与 §5.3 同源：`store.listDirs(dir)`。N2Shared(01) 已确认此点一致（双方都不从 `files` 推目录）。

**关键取舍 2：为什么新原语叫 `directChildDirsOf`、落 `rules/emptiness.ts`、且**不**构成「第三个目录推导」。**
它**不推导目录**——它是对**已有目录列表**做一次直接子级过滤，与 `directChildrenOf(files, dir)`（`emptiness.ts:19-29`，全项目「直接子级文件」的唯一实现）严格对称。目录**推导**仍然只有 `listDirs`（`local-store.ts:349`，泛化后 world/nook 共用）与 `deriveNookLayers`（`01`）。落 `rules/` 而非 `store/`：`rules/emptiness.ts` 声明「Zero dependencies on purpose」（`:4`），而放进 `nook-layers.ts` 会让 `emptiness.ts` 反向 import `store/`。**同源而非同文件**：一份 `listDirs` 产物，`01` 用它走祖先扫描装配树，本片用它数直接子级——两种读法，不是两份目录集。

**关键取舍 3：新参数是必填，不是可选。**
把 `dirs` 设成可选、默认 `[]`，会让 nook 分支在漏传时**静默退回旧的危险语义**（内容全在子目录 ⇒ 判空/判未产出 ⇒ 再铺一层）。这正是 P4 的原始 bug，绝不能再留一条可达路径。代价是 `kind: 'scene'` 的调用点也要写实参——传什么都被忽略，但**必须写**。收益：类型系统强制每个 nook 调用点显式交代目录集来源。**这是「用签名消灭一类 bug」而非「用默认值藏一个 bug」。**

## ③ 行为契约逐步（每步写「漏了会怎样」）

### 步骤 1：`init-command.ts` 解析出 `dir`

```ts
// init-command.ts:198-199
const isScene = args.kind === 'scene';
const dir = isScene ? dirOfLayer(args.target) : nookIdOf(args.target);
```

**实测（决定性）**：对 `kind: 'nook'`，`dir` **恒为 `characters/<id>`**（`nookIdOf` 在 `packages/shared/src/rules/characters.ts:35-37`，输入是**裸 id**，只产 `characters/${id}` 一种形状）。`args.target` 是裸 id——`parseInitArgs`（`:71-87`）只校验 `typeof o.target === 'string' && o.target !== ''`，不校验 id 形状；形状闸在下游 `nookIdOf` 返 `null` 时把命令短路（`:200-203`）。

⇒ **空判定只作用于「角色根」，MUST NOT 也无法作用于子场景。** 本片**不需要**为子场景加任何分支：`dir` 里根本装不下 `characters/elias/office`，故那些 `dir.slice(0, ...)` 之类的深路径算术**不存在**。契约 §6「子场景的 nook-init 不在本批」因此是**结构性保证**的，不是靠自觉。

- **漏了会怎样**：若有人把 `dir` 改成 `characters/<id>/<scene>`，`isNookEmpty(files, dir, dirs)` 会以子场景为根判空，而 §6 明确不为子场景实现 init——判据与执行能力脱节，命令会去 spawn 一个无人消费的 initializer。

### 步骤 2：读 `files`（既有）

```ts
// init-command.ts:240-248
let files: string[];
try { files = await store.listFiles(); } catch { … return; }
```

`store` 的类型是 **`LocalWorldStore`**（`extensions/toolkit/deps.ts:27` 的 `worldStore(ctx): LocalWorldStore`）。这是本片方案成立的前提（主 agent 2026-09-15 实测确认）：契约 §8 P7 说的「`listDirs` 不在 `WorldStore` 接口里、动作层编译期拿不到」**不适用于本片调用点**——`init-command.ts` 手里就是 `LocalWorldStore`，`listDirs` 直接可用。

### 步骤 3：读 `dirs`（本片新增）

```ts
// init-command.ts:249 之前
const dirs = await store.listDirs(dir);   // NEW 调用；LocalWorldStore.listDirs（local-store.ts:349）
```

- `listDirs` 返回**含根自身**的目录集（`local-store.ts:369` 逐字 `[root, ...out]`），且目录在递归前 push（`:363-364`）⇒ 空目录照常出现。`directChildDirsOf` 的第一条 `rest === ''` 正是为剔除 `dir` 自身而写（N2Shared 已确认其树也因此把根留为 `parent = null`，两者对「根」的处理一致）。
- **漏了会怎样**：
  - 漏传 `dirs`（若签名可选）→ 编译过、行为退回 P4（本片拒绝这种设计，见 §2.2 取舍 3）。
  - 用 `listFiles(dir)` 代替 → 空子目录消失，判据与 §4.3 门牌脱钩（契约 §2.3.1 对照实测 B/C）。
  - 用 `listDirs()`（无参）→ 拿到的是 `world/**`，对 `characters/**` 恒无匹配，`directChildDirsOf` 恒返 `[]` ⇒ 静默退化成旧语义。**这是最阴的一种漏**，因为无参调用今天合法（`:455` 就这么用）。故本片 MUST 依赖 `01` 的泛化签名，实现前复核 `listDirs` 形参存在。

### 步骤 4：空判定短路（既有位置，语义收紧）

```ts
// init-command.ts:249-254
const empty = isScene ? isLayerEmpty(files, dir) : isNookEmpty(files, dir, dirs);
if (!empty) { sendRootTerminal(false); emit(report(args, 'already initialized (no action)')); return; }
```

- 这是**顺序幂等**的唯一来源（`:240` 注释逐字 "the sequential idempotency source"）。收紧后，「根只有 `preset.json`、房间在子目录」这一类不再被误判为空 ⇒ 不再进入 spawn。
- **漏了会怎样**：不修 ⇒ 每次进入一个「内容全在子目录」的小天地都重跑一轮 `nook-init`。`extensions/instructions.ts:333` 逐字要求初始化器「已有真实内容就停」，但**它看不到这个判断**——判据在触发点就错了，初始化器根本没机会执行那条纪律。

### 步骤 5：spawn 后产物判定（既有位置，语义收紧）——**同一 bug 的另一半**

```ts
// init-command.ts:328-329
const after = await store.listFiles();
if (result.status === 'completed' && hasInitProduct(after, dir, args.kind, dirs)) { … }
```

**`hasInitProduct` 的 nook 分支今天走 `children.some(name => !name.endsWith('.json'))`（`emptiness.ts:68-72`），只看直接子级文件名** ⇒ 内容全在子目录时返回 `false`（主 agent `/tmp/spike-initproduct.mjs` 实测：`content only in subdir → isNookEmpty=true, hasInitProduct=false`，两处同错）。

**漏了会怎样（nook 分支的完整失败路径，带 `file:line`）**：
`hasInitProduct` 返 `false` ⇒ 跳过 `:329` 的成功分支 ⇒ 落到 `:337`：

```ts
// init-command.ts:337-351
const reason = result.status === 'completed' ? 'no product written' : result.status;
…
} else {
  // A nook that stays empty is a normal state — do not invent content.
  await svc.recordLayerInitFailed({ layer, reason, fallback: 'none' });   // :348
  finish(true, errorKind);
  emit(report(args, `failed (${reason}); nook left empty`));              // :350
}
```

⚠️ **证据修正**：nook 分支的 `fallback` 逐字是 `'none'`（`:348`），**不是** W2 模板兜底（W2 只走 `isScene` 分支 `:340-345`）。所以 nook 的后果是：
1. 一次**完整的子代理 spawn 白跑**（45s 上限、`TIMEOUT_MS.nook`，`:46`）——而 initializer 很可能已按 `instructions.ts:333` 正确地「看到内容就停、什么都没写」；
2. 落一条**撒谎的 `layer_init_failed`**（`reason: 'no product written'`），把一个**本来就已布置好的房间**记成初始化失败；
3. `layer_initialized` 永远不会为该房间落下 ⇒ 该房间每次进入都再触发一轮（与步骤 4 同源）。

⇒ 第四参数 `dirs` 对 `hasInitProduct` **不是可选项，是同一修复的另一半**；两个函数**同批改**。（主 agent 措辞「走 W2 兜底再写一遍」对 nook 不成立——已按 `:348` 实测更正，见 §⑪ 冲突 8。）

### 步骤 6：`.pi` 与其它点开头目录

`listFiles` 的 walk 逐字跳过 `entry.name.startsWith('.')`（`local-store.ts:331`），`listDirs` 同样（`:360`）⇒ `.pi/` 在两个入参里都不出现。但纯函数**仍要自洽**（契约 §5.4 第三条）：`directChildDirsOf` 的 `rest.startsWith('.')` 必须挡住手工传入的 `characters/elias/.pi`。

- **漏了会怎样**：不做该过滤 ⇒ 手工构造的 `dirs` 里的 `.pi` 会把一个空房间判成非空，且与 §4.3 门牌集（`01` 的 `deriveNookLayers` 输出，同样基于 `listDirs` ⇒ 不含 `.pi`）不一致——「有看不见的房间因此不初始化」，无法解释。

## ⑤ 落账

**本片不新增、不删除任何事件类型。** 逐条：

1. `isNookEmpty` / `hasInitProduct` 是**纯判定函数**（`emptiness.ts:4` 逐字 "Zero dependencies on purpose"），自己不落账。
2. 它们**间接**改变落账分布：
   - 旧行为下「已布置的房间被误判为空」会走完 spawn 并落 `layer_initialized`（`:331` → `recordLayerInitialized`）或 `layer_init_failed`（`:348`）；
   - 新行为下同一个小天地在 `:249` 短路，**不落任何事件**。
3. 那些旧记录是**撒谎**的：`layer_initialized` 谎称「初始化器写了这个房间」，而实际上它只是往已布置的房间又走了一趟；`layer_init_failed` 谎称「没写出产物」，而实际上房间本来就有内容。
4. 契约 §4.7 与 `doc-21` 的 `type` 是封闭枚举，本片 MUST NOT 新增（遵守）。
5. **不改** `recordLayerInitialized` / `recordLayerInitFailed` 的调用点（`:280` / `:331` / `:343` / `:348`）——本片只在更早的判据处减少进入，不动落账代码本身。

**没有落账回写需求**（`docs/init/doc-11` §6 的事件表不变）。

## ⑥ WS / 前端（跨端同批点名）

**判据与呈现必须同源**（契约 §5.4 第二条，硬要求）。本片定义**服务端语义**，`04` 消费它做空态：

| 端 | 落点 | 要求 |
|---|---|---|
| **生产端（本片）** | `packages/shared/src/rules/emptiness.ts` 的 `isNookEmpty(files, dir, dirs)` | 「有直接子目录 ⇒ 非空」。这是唯一服务端判据 |
| **生产端（`02`）** | `GET /api/nook` 的 `items` | 直接子目录门牌**必须**进 `items`（契约 §4.3）。**一个「根无卡、只有子场景」的场景，`items.length` MUST ≥ 1** |
| **消费端（`04`）** | `apps/web/src/components/nook/NookView.tsx:473` | 空态判据现状 `const isEmpty = state !== null && state.items.length === 0 && state.scene === null;`。**MUST 保持此式不变**——它已与收紧后的 `isNookEmpty` 等价：门牌在 `items` 里 ⇒ `isEmpty === false` |

- **不需要新增帧、不需要 WS 变化**：`characters/**` 的变化照常经 `world_event` 广播（`event-bridge.ts` 尾部不按路径前缀过滤），前端按 `wiring/00 §4` 消费。

   - ⇒ **不改 `isLayerEmpty`**，并显式记录：**「层与 nook 的空语义不同」是有意的**（不是遗漏）。

## ⑫ 仍未知待拍板

1. **空子目录算不算「内容」？（本片最关键的产品未知项）**
   本片**按契约字面 + 主 agent U1 裁决**：`isNookEmpty` 认「任何非点开头直接子目录」，**包括完全空的**——依据是 §4.3 冻结「空子目录也出门牌（`stub=true`）」，门牌即内容，两处必须同源（真值表 F）。**已知后果（非遗漏）**：`chat-history/`（§⑪ 冲突 4）会让一个角色根**永久非空**、永不触发 `nook-init`。两种口径的代价：
   - 认空目录（本片）：与门牌一致；代价是任何运行期杂目录都会阻止初始化。
   - 不认空目录：需在 `directChildDirsOf` 之上再叠「目录里有文件」判据 ⇒ 又需要一份 `files` 集，与「目录集判定」的初衷相悖；且与 §4.3 门牌脱钩——**玩家看得见门牌，服务端却说这房间是空的**。
   **本片选前者**。建议的根治是让运行期目录离开角色目录（`.chat-history/` 点开头，或移进 `.airpworld/`）——那是内容/运行时约定的改变，超出 N2。

2. **`chat-history/` 的最终处置**：本片只能保证「它会阻止 init」这一后果被写清，**无法在判据层区分「真场景」与「运行期杂目录」**——那需要白名单，而已被排除在本批之外。

3. **`:329` 的 `dirs` 快照过期问题**：`dirs` 取自步骤 3，而 `hasInitProduct` 的 `files` 是 spawn 后的 `after`。若 initializer **只新建了子场景目录、没写文件**，`dirs` 看不到它 ⇒ `hasInitProduct` 判 `false` ⇒ 走失败分支（`:337-350`）。本片倾向**不重取**（保守失败 + 避免热路径多一次行走），**需拍板**：是否在 `:329` 前再 `await store.listDirs(dir)`。

4. **`hasInitProduct` 的 `kind: 'scene'` 分支要不要也收 `dirs`？** 本片裁决**忽略**（层的产物判据是 `README.md`）。若主 agent 认为层的「产物」也应认子层目录，需同时改 `isLayerEmpty`——回到 §⑪ 冲突 6。

5. **`listDirs` 与 `directChildDirsOf` 的分层（已裁 2026-09-15，闭合）。** `01` 已裁 P8：`listDirs` 的 walk 补 `entry.name === 'node_modules'` 跳过，与 `listFiles:331` 对齐（理由逐字：「同一原语的两个行走 MUST 同规则」）。终局是**分层而非双保险**：
   - **`listDirs(nookId)`（行走阶段）**：负责「哪些目录会进入列表」——排除点开头（`local-store.ts:360`）与 `node_modules`（P8）。
   - **`directChildDirsOf(dirs, dir)`（过滤阶段）**：只对**已进入列表的路径**做直接子级过滤——它**不是**行走器，不重复排除。
   ⇒ **本片无需改**：`directChildDirsOf` 的输入恒定来自 `listDirs`，P8 生效后 `node_modules` 根本不会出现在输入里。
   ⚠️ **依赖方向（真正要写清的约束，比机械补一个 `node_modules` 判断更有价值）**：若将来有人把**非 `listDirs` 来源**的目录列表喂给 `directChildDirsOf`（手工构造、别的 store 实现、缓存快照），`node_modules` 就会漏进来。所以这不是「重复过滤」问题，而是**调用方契约**问题——`directChildDirsOf` 的 `dirs` MUST 是某次 `listDirs` 的输出。**在 `directChildDirsOf` 里再补一个 `node_modules` 判断会造成「双保险」假象，掩盖真正的输入约束**（点开头的过滤之所以留在函数内，是因为 `directChildrenOf` 已对称覆盖、且契约 §5.4 第三条要求纯函数自洽；`node_modules` 不走这条路）。

6. **`.pi` 之外是否还有需要排除的运行期目录**：本片只依赖 `listDirs` 的点开头规则（`:360`），未做额外枚举。若产品决定新增黑名单，MUST 只落一处（`listDirs`）并让门牌集随之生效，判据层不另加。

## 关键设计决定与最不确定处

**关键设计决定**：把「目录集」作为 `isNookEmpty` / `hasInitProduct` 的**必填入参**（而非从 `files` 反推），并在 `rules/emptiness.ts` 新增与 `directChildrenOf` 严格对称的 `directChildDirsOf`——因为 `files` 是文件行走、看不到空目录，若从它反推就会与契约 §5.3 的 `deriveNookLayers(nookId, dirs, …)` 形成致命的双口径（空目录有门牌却判空）。两个函数是**同一个 bug 的两半**（一个管该不该 spawn、一个管算不算成功），必须同批改。用必填参数而非默认值，让「漏传目录集」在编译期暴露，而不是静默退回 P4 的危险语义。同时改写 `emptiness.ts` 两处已失效的 doc comment 与两条既有单测——**只改代码不改理由，下一个人会照旧理由做决定**。

**最不确定**：**（空）子目录该不该算「内容」**——本片按契约 §4.3 门牌语义裁决为「算」，但这使 `chat-history/` 这类运行期目录永久阻止初始化；若改判「不算」，就需要第二份文件集、并与门牌语义脱钩。这是产品口径而非实现细节，已登记为待拍板 1/2。
