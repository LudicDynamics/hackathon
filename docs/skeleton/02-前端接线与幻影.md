## 1. 一句话定位

**在 `useWorld` 的 WS `switch` 里加 `case 'card_writing'`，把服务端判好的 `kind` 从帧搬进第三类幻影（`kind:'component'`），并用一个纯函数 `skeletonShapeFor(kind)` 把它折算成"与落定卡同形"的骨架形状；骨架的挂载/撤离/排座全部复用既有 `phantom.ts` + `phantomSeatFor` + `land`/`reconcileLanded`，本批不新增任何排座或过户机制。**

```ts
export type SkeletonChrome =
  | 'paper' | 'note' | 'slab' | 'board' | 'panel' | 'scroll' | 'cover' | 'bare';

/** 一条灰色占位线：w = 骨架内宽百分比（1–100），h = px。 */
export interface SkeletonLine { w: number; h: number; }

/**
 * 该 chrome 的材质语汇开关（渲染组件按此：**根 class 表达**）。
 *
 * **裁决 H（`00 §7` 冲突 5，2026-09-13）**：`ruled`/`inset`/`grid`/`wash` 是
 * **纯 CSS 属性开关**（作用在根/已有节点上的 class），**MUST NOT 为它们建 DOM
 * 元素**——`03` 逐个建 span 会造 4 个空节点。仅 `clip`/`block`/`band`/`seal`/
 * `edges` 这 5 个可对应真实子元素（`03 §5.0`）。
 * 实现者读 decor 时须区分"改 class"vs"建元素"，`02` 只声明布尔，不规定渲染。
 */
export interface SkeletonDecor {
  ruled: boolean;   // CSS only（note 横格）
  clip: boolean;    // 可建元素（note 回形针）
  block: boolean;   // 可建元素（slab 中央方框）
  inset: boolean;   // CSS only（slab 内阴影）
  grid: boolean;    // CSS only（board 格纹）
  wash: boolean;    // CSS only（panel 浅墨洗）
  band: boolean;    // 可建元素（cover 顶部色带）
  seal: boolean;    // 可建元素（cover 序号印章）
  edges: boolean;   // 可建元素（scroll 双横边）
}

export interface SkeletonShape {
  chrome: SkeletonChrome;
  /** false = 不出骨架（bare 档：chalk / sprite / portrait）。 */
  visible: boolean;
  lines: SkeletonLine[];
  decor: SkeletonDecor;
}

/** 入参 = `PhantomEntry.cardKind`（服务端已判的 cardKind，如 'letter'/'lock'）。 */
export function skeletonShapeFor(kind: string | undefined): SkeletonShape;

/**
 * NEW. 白名单守卫（§3.1⑤ 的机械形态，供 `useWorld` 与单测共用）。
 * 仅当"能推出合法层 ∧ chrome ≠ bare ∧ kind ≠ gate"时返回 `true`（== 可注册）。
 * `form` 传 `CARD_FORMS[kind]`（未命中即 `undefined`）。纯函数，无 React/DOM。
 */
export function cardWritingGuard(
  form: { chrome: SkeletonChrome } | undefined,
  kind: string | undefined,
  layer: string | undefined
): boolean;
```

## 3. 行为契约（逐步，每步写"漏了会怎样"）

### 3.1 帧消费：`case 'card_writing'`

```
收到帧 msg →
  ① 守卫：msg.source === 'writer' 且 typeof msg.toolCallId === 'string'，否则 break
  ② kind  = typeof msg.kind === 'string' ? msg.kind : undefined
  ③ form  = kind !== undefined ? CARD_FORMS[kind] : undefined
  ④ layer = typeof msg.layer === 'string' ? msg.layer : undefined      // 不回退！缺失即 undefined
  ⑤ if (!cardWritingGuard(form, kind, layer)) break;   // 白名单（裁决 F+L+M+O）
     // == if (!form || form.chrome === 'bare' || kind === 'gate' || !layer) break;
  ⑥ seat  = phantomSeatFor({ w: form.w, h: form.h }, layer).seat
  ⑦ registerPhantom(msg.toolCallId, { kind:'component', source:'writer', seat, layer,
                                      cardKind: kind,
                                      cardTitle: typeof msg.title === 'string' ? msg.title : undefined })
```

**服务端零过滤（`SK-Server` 已定，`01` 篇）**：`write` 不专写组件卡——scene-init 用 `write` 写 `type: chalk` 的开场段（`extensions/instructions.ts:230`）、探针也这么干（`tools/probe-provider.ts:19-21`），故 `kind` 可能是 `'chalk'`/`'gate'`。服务端对**任何** `write` 一律发帧（不做白名单：白名单会把 `CARD_FORMS.chrome` 渲染策略耦合进纯映射函数）。→ **前端必须纵深防御**（白名单，`cardWritingGuard`）：`chrome ≠ bare`（`chalk`/`sprite`/`portrait` 排除，`forms.ts:66,68,99`）**且 `kind ≠ gate`**（`chrome:'cover'`，但 README 永不进 `items`，见 §3.1b）**且 `layer` 能推出非空**（§3.1c）**才 `registerPhantom`**。

- **①** 与既有 `chalk_writing`（`useWorld.ts:450`）逐字同纪律。
  **漏了会怎样**：character 车道若误发同名字段，会在作家层画一张不属于它的骨架；`toolCallId` 非字符串则 `register` 的键变成 `undefined`，后续 `land`/`reconcileLanded` 全对不上，骨架永挂。
- **②③** `form` 直接查 `CARD_FORMS[kind]`（`packages/shared/src/schemas/forms.ts:64-100`）。**不做前端回退**（裁决 F）。
  **漏了会怎样**：`CARD_FORMS[kind]` 为 `undefined` 时若继续算 `.w` 会崩；且未命中即不该画骨架（见 ⑤）。
  **kind 的来源保证（`00 §5.3` 勘误）**：`args.content` 无 frontmatter 时，服务端 `resolveComponentKind` 最终 `return 'note'`（`components/registry.ts:78`；前端 fallback 分支同值 `forms.ts:123`）——故正常帧的 `kind` **不会是 `undefined`/未知**；`!form` 只应出现在畸形帧。
- **④⑤【裁决 O / F-10，白名单口径】** 注册前提 = **「该 path 会进入某个 `items`」**。守卫写成**白名单**（"能推出合法层 ∧ `chrome ≠ bare` ∧ `kind ≠ gate` 才注册"）。`layer` 必须是非空字符串（`!layer` 同时挡 `undefined` 与 `''`）。
  **漏了会怎样（F-10 一般化泄漏）**：`reconcileLanded` 只按 `entry.path ∈ items.paths` 删（`phantom.ts:185-195`），evicted-drop 只处理失败路径。故任何**既非失败、又永不进 `items`** 的写入，其骨架**永挂**：`player/` 背包 `.md`（不在任何 `world/**` 层）、stub 层文件（`resolveLayer` 无 README 的层被排除）、非层目录 `.md`（`resolveLayer` 返回 null）。这些的 `layer` 推为 `''`/缺失 → 若**回退 `layerRef.current`** 会**错排进当前层**并永挂，还经 `phantomSeatFor` 的 `occupied`（`phantom-seat.ts:49-57`）挤走后续真卡 → 违反 `perform/03:589`「`getPhantomsSnapshot()` 最终为空」。**MUST NOT 回退**（覆盖 F-2 第 2 条原写法，`00` 附 F-10 裁决 O 已勘误）。
  **两个前提互相独立**：`kind`（形状/gate）与 `layer`（归宿）任缺即不注册。服务端 `layerOfDir(dirOf(args.path))` 对非层路径返回 `''`（`layers.ts:37-48`）→ 帧省略 `layer` → 前端 `!layer` 命中（详 §3.1c）。
- **⑥** 座位**只**从 `phantomSeatFor` 取（`phantom-seat.ts:42`），传入 `{w,h}` 来自 `CARD_FORMS[kind]`（与真卡同形，`00 §3.3`）。
  **漏了会怎样**：自造排座 → 违反 `layout/00 §5` 唯一 seater 纪律，与 chalk/image 抢位。
- **⑦** `cardKind` 存原始 `kind`（可能 `undefined`），转形状的职责归 `card-skeleton.ts`（§3.2）。
  **漏了会怎样**：`PhantomEntry` 无 `cardKind` → `CardSkeleton` 只能画 `paper`，锁/门/卷轴全成便签形。
- **不做**：不调 `beginTurn('chalk')` / `playCharge`（`00` 未给 `card_writing` 分配声音或状态机落点；`perform/00 §8b` 的声音表里无此帧）。也不把 `card_writing` 加进 `App.tsx:153` 与 `WriterResult.tsx:14` 的"writer 忙"列表——同一次 `write` 必然已发 `tool_start`（`event-bridge.ts:145`），那两处已覆盖。
  **漏了（即误加）会怎样**：`playCharge(0)` 与随后 `chalk_landed` 的 `endCharge()`（`:471`）配错对，或 writer 状态机被非 chalk 帧污染。

### 3.1a 为什么 `bare`（及 `!form`）必须挡在 `register` 之前（**裁决 F，`00 §3.6`**）

- `registerPhantom` 一旦建条目，`phantomSeatFor` 的 `occupied` 就把"同层全部未撤离幻影"计入障碍（`phantom-seat.ts:49-57`）。一个 `bare` 幻影**什么都画不出**（`CardSkeleton` 见 `visible===false` 返回 `null`，§3.2），**却占住一个座位**——在 `chalk_landed` 前把真卡挤走，恰好制造本批要消灭的"错位"。`!form`（畸形帧）同理：无尺寸来源，注册即崩或占座。
- **漏了会怎样**：`write` 一张 `type: chalk` 的开场段 → 注册一个不可见幻影 → chalk 车道的 `chalk_writing` 随后**自己也注册一个**（`useWorld.ts:452`；与 `write` 是不同工具、不同 `toolCallId`），两个占位叠加，前一个直到 `reconcileLanded` 才清；期间真卡落位被推后。
- **判据的机械形态**：`form.chrome === 'bare'` 用的是与 `skeletonShapeFor` 同一张表（`CARD_FORMS`），不引入第二份 kind 名单。


### 3.1b 为什么 `kind === 'gate'` 也要挡（**裁决 M，F-8**）

- `resolveComponentKind` 对 `filename === 'README.md'` 返回 `'gate'`（`packages/shared/src/components/registry.ts:73`；`forms.ts:119` 同）；`gate` 的 `chrome:'cover'`（`forms.ts:67`）→ **不属于 `bare`**，故裁决 F 的守卫**挡不住它**。
- 但 **README 永不进 `items`**：`/api/layer` 的 `cards` 是 `cardsOfLayer(...)`（已排除 README），层门 README 单独作为 `doors` 返回（`packages/shared/src/actions/look-at.ts:282-284,424-425`；`render/layer-page.ts:144-147` 逐字注释 "minus its README" / "Direct child layers, as their README paths"）。而 `reconcileLanded(paths)` 的输入**只是 `items.paths`**（`phantom.ts:185-195`）。→ gate 幻影**永不被 `reconcileLanded` 删除**，且它非 `image`，evicted-drop 也不管它 → **骨架永挂**。
- **漏了会怎样**：作家（或 init）写一个 `world/README.md` 场景门 → `card_writing{kind:'gate'}` → 注册一个 `cover` 骨架 → 占住座位且永不撤离。
- **守卫位置**：与裁决 F/O **同一行**（§3.1⑤），不新增第二处判据。

### 3.1c 为什么 `layer` 推不出时也不注册（**裁决 O，F-10，白名单口径**）

- 注册前提是**白名单**：「该 path 会进入某个 `items`」⇒ `layer` 能推出合法层 ∧ `chrome ≠ bare` ∧ `kind ≠ gate`，**三者同时满足才注册**。
- `layer` 缺失（帧省略）或为 `''` ⇒ 该 `write` 的 path 不在任何层（`player/` 背包、stub 层、非层目录），**永不进 `items`** ⇒ `reconcileLanded` 永不删 ⇒ evicted-drop 也不管（非失败）⇒ **永挂 + 挤座**。故 `!layer` 必须 `break`。
- 守卫写法（白名单，一行）：`if (!form || form.chrome === 'bare' || kind === 'gate' || !layer) break;`
- **MUST NOT 回退 `layerRef.current`**（`00` 附 F-10 裁决 O 覆盖 F-2 第 2 条）：回退会把"无归宿"的写入**错排进当前层**，既永挂又经 `occupied` 挤走真卡。
- **判据的机械形态**：`!layer` 同时挡 `undefined`（字段缺失）与 `''`（服务端推出空串），无第二种"层来源"。

### 3.2 `skeletonShapeFor(kind)` 的形状推导（"行数从 form 推出"）

**它怎么知道 chrome？** `CARD_FORMS[kind]?.chrome`。web 端**可**读 `CARD_FORMS`：`useWorld.ts:11` 已 `import { CARD_FORMS } from '@airp/shared/forms'`，且 `@airp/shared` 的 `./forms` 导出存在（`packages/shared/package.json` `exports["./forms"]` → `dist/schemas/forms.js`），`apps/web/node_modules/@airp/shared` 已链接。**不 import `components/registry`**（那会让 web 拿到 null resolver 之外的第二个真相源，`00 §2.1`）。

**`skeletonShapeFor` 内部 → 回退 `paper`**（**纯函数自身的防御**，与本篇 §3.1⑤ 的 `break` 不冲突）：`const form = (kind !== undefined ? CARD_FORMS[kind] : undefined) ?? CARD_FORMS.default;` → `chrome = form.chrome`（`default` 行 `chrome:'paper'`，`forms.ts:70`）。

> **两条"未知"要分清**：§3.1⑤ 的 `case` 在 `!form` 时**不注册**（裁决 F）；而 `skeletonShapeFor` 作为纯函数**仍对任意字符串给非空形状**（回退 `paper`），以便单测与 `03` 独立调用。正常帧不会走到 `!form`（`00 §5.3` 勘误：无 frontmatter → `resolveComponentKind` 返回 `'note'`）。

**行数由 `form.h` 推出**（不是逐 chrome 写死）；**decor 由 `DECOR_BY_CHROME` 表给出**（不是逐 kind 手绘）：

```

LINE_PITCH = 34   // 行距 px
WIDTHS     = [92, 78, 86, 60, 74, 66]   // 确定性"长短不一"图样，按行序取模
LINES_BAND: Record<SkeletonChrome, [min, max]> = {
  paper: [3,4], note: [3,3], panel: [2,5], cover: [2,4],
  slab: [0,0], board: [0,0], scroll: [0,0], bare: [0,0],
}

  paper:  { ruled:false, clip:false, block:false, inset:false, grid:false, wash:false, band:false, seal:false, edges:false },
  note:   { ruled:true,  clip:true,  block:false, inset:false, grid:false, wash:false, band:false, seal:false, edges:false },
  slab:   { ruled:false, clip:false, block:true,  inset:true,  grid:false, wash:false, band:false, seal:false, edges:false },
  board:  { ruled:false, clip:false, block:false, inset:false, grid:true,  wash:false, band:false, seal:false, edges:false },
  panel:  { ruled:false, clip:false, block:false, inset:false, grid:false, wash:true,  band:false, seal:false, edges:false },
  scroll: { ruled:false, clip:false, block:false, inset:false, grid:false, wash:false, band:false, seal:false, edges:true  },
  cover:  { ruled:false, clip:false, block:false, inset:false, grid:false, wash:false, band:true,  seal:true,  edges:false },
  bare:   { ruled:false, clip:false, block:false, inset:false, grid:false, wash:false, band:false, seal:false, edges:false },
}

count = clamp( floor((form.h - LINE_TOP) / LINE_PITCH), min, max )
widths = chrome === 'panel' ? 全 80（等宽条）: WIDTHS.slice(0, count)
decor = DECOR_BY_CHROME[chrome]   // 返回的全新副本（§3.2 末：不外泄冻结引用）
```

（`DECOR_BY_CHROME` 即 §3.2「逐档返回表」的 `decor` 列逐字，二者必须一致——表是该常量的投影。）

- **`note` 的 3 行、`paper` 的 3–4 行**都来自 `00 §2.3` 的文字规格，用 band 上限兑现：`paper` 大卡（如 `book` h=264）算到 6 也被 clamp 回 4，仍读作"信纸"。
  **漏了 band（纯 floor）会怎样**：`book` 出 6 条线 → 观感变"文档"而非"信纸"，偏离 `00 §2.3`。
- **`slab`/`board`/`scroll` 的 0 行**是刻意的：它们的"形状"由 `decor`（方框/格纹/双横边）承载，不是文字线。`00 §2.3` 明写"绝不呈现正文字符"。

**逐档返回表**（对 `CARD_FORMS` 真实行手算，可核）：

| chrome | `visible` | `lines` | `decor` | 覆盖 kind（示例 → count） |
|---|---|---|---|---|
| `paper` | `true` | 3–4 条参差灰线 | 全 false | `default`(168→3) `letter`(176→3) `book`(264→4) `ledger`(176→3) `photo`(240→4) `cipher`(168→3) `diary`(240→4) `thread`(200→4) |
| `note` | `true` | 3 条（`WIDTHS` 前三：92/78/86） | `ruled`,`clip` | `note`(168→3) |
| `slab` | `true` | `[]` | `block`,`inset` | `lock` `container` `trap` `mechanism` `anchor` |
| `board` | `true` | `[]` | `grid` | `instrument` `board` |
| `panel` | `true` | 3 条等宽（80×3） | `wash` | `clock`(160→3) `tape`(148→3) |
| `scroll` | `true` | `[]` | `edges` | `map` |
| `cover` | `true` | 4 条参差 | `band`,`seal` | `gate`(240→4) |
| `bare` | **`false`** | `[]` | 全 false | `chalk` `sprite` `portrait`（**不出骨架**） |

- **`visible:false` 是渲染的硬开关**：`03` 的 `CardSkeleton` 见到 `visible === false` MUST `return null`（`00 §3.5` 只对 chalk/sprite/portrait 说了"不出骨架"，此处给出机械判据）。

- **裁决 H 的接线侧含义**：`skeletonShapeFor` **只返回 9 个布尔，不返回元素描述**（无 `children`/`tag` 字段）。`03` 决定"哪些布尔落成 class、哪些落成子元素"。`02` **MUST NOT** 在 `SkeletonShape` 里加 DOM 结构（那会把渲染细节耦合进纯函数，违反 `00 §6.1` 前端不推渲染）。

- **每次返回全新对象**（含 `lines` 新数组、`decor` 新对象），不外泄模块级冻结引用。
  **漏了会怎样**：`CardSkeleton` 若 mutate 了返回的 `lines`，下一次调用读到被污染的共享数组（同一 bug 形态见 `ghost.test.mjs` G4）。

### 3.3 乱序：帧 vs 注册 vs 过户（既有 `pendingInk` 够不够？）

**够——本车道不需要新增任何缓冲。** 论据：

1. **`card_writing` 与 `chalk_landed` 走同一条 WS 连接、服务端顺序 `push`**：`tool_execution_start`（`event-bridge.ts:143-149`）先于 `tool_execution_end`（`:168-192`），两者都经 `EventBridge.broadcast` 同序下发。故**同一 `toolCallId` 下，`register` 必先于 `land`**。
2. **本车道无 delta**：component 不走 `writer_delta`（`00 §2.4` 不做真流式），故 `appendInk` 的 `pendingInk` 缓冲（`phantom.ts:73-74,129-138`）**用不上**，不需要为其新增。
3. **`land` 先到的兜底**：`land` 对未知 id 静默返回（`phantom.ts:154-155`）。这不是本车道的正常路径（见 1），且**新增"pending land"会违反 F-1"不得为不存在的问题造机制"**。
4. **`evict` 先到的兜底**：`evict` 对未知 id 入 `pendingEvict`（`phantom.ts:166-169`），既有行为，component 无需特判。
5. **多卡交错（F-1）**：`tool_execution_start` 严格串行，但各卡 `tool_execution_end` 顺序可能交错。**过户按各自 `toolCallId` 独立**（`land(id)` / `reconcileLanded(paths)` 均按 id/path，`phantom.ts:153,185`），**MUST NOT** 假设"先 start 的先 land"，也 **MUST NOT** 新增"同批预占"。

**漏了（即误加预占/pending-land）会怎样**：为已证明不存在的重叠问题造复杂度，并可能让两个骨架互相挡位（预占集合与 `occupied` 双算）。

|---|---|---|---|
| 正常落地 | `chalk_landed{path}` | `case 'chalk_landed'`（`useWorld.ts:468-474`）→ `landPhantom(id,{path})` → `file_changed`→`fetchLayer`→`reconcileLanded(paths)`（`phantom.ts:185-195`） | 幻影按 path 删除，真卡同座位（**复用，不改**，`00 §3.4`） |

**`03` 已确认的实现（`SK-Render` 回信，落 `PhantomLayer.tsx`，非本文改）**：`useEffect`（`:47-69`）改为——`p.phase === 'evicted'` 时按 kind 取预算（image=`EVICT_FADE_MS`700 / component=`SKELETON_EVICT_MS`320 / chalk=undefined 自撤）后 `drop`；`landed-dwell` 仍 `if (p.kind !== 'image') continue;`（component 无 min-dwell，`00 §2.5`）。**正常路径不依赖计时器**（`reconcileLanded` 按 path 删）。

> **可见窗口实测（`00` 附 F-4，2026-09-13）**：`00 §2.5` 初稿"write 窗口几十毫秒"**是错的**。真 server + 真 LocalWorldStore（world=templates/wuwu）实测：write 落盘 0.42ms → `fs.watch` ~16ms → 服务端 `WATCH_DEBOUNCE_MS` 150ms（`event-bridge.ts:13`）→ `/api/layer` 往返 64ms；因 `land` 后节点**停住不删**，真正删除要等 `file_changed`→`fetchLayer`→`reconcileLanded`，**合计 ≈230ms+**（200–400ms 稳定可见窗口）。→ 这**不影响** 02 的接线设计（仍不设 min-dwell，`00 §6.3` 禁人为延时），但确认了骨架的观感价值。`§2.5` 原文"几十毫秒"应删（登记为需修契约，`00` F-4）。

> **`00 §2.5` 勘误（`03` 冲突 1，2026-09-13）**：初稿"落地帧到达时**立即撤离**"是歧义。准确语义 = **`land` 只把相位改成 `landed`、停住内容，不删节点**；节点真正的删除由 `reconcileLanded`（`fetchLayer` 触发）完成。本文 §3.4 的"正常落地"行即此语义——**别在 `land` 时就 `null` 掉骨架**，否则"真卡尚未进 `items`"的窗口会留座位空洞。

> **裁决 L（F-7，2026-09-13，致命）**：服务端 `case 'tool_execution_end'` 里 `tool_end{isError}` 与 `chalk_landed` 是**同一次事件内按序 push**（`event-bridge.ts:248-255`），`chalk_landed` 的 push **不判 `isError`**。前端按帧序处理：`tool_end{isError}` → `evictPhantom` → `phase='evicted'`（`useWorld.ts:414-421`）；随后 `chalk_landed` → `landPhantom` → `land()` 若**无相位守卫**（现状 `phantom.ts:153-161` 直接 `entry.phase = 'landed'`）→ **覆盖 evicted** → evicted-drop（裁决 G）永不触发，且失败 write 不产文件故 `reconcileLanded` 不命中 → **骨架永挂**。→ **`land()` 开头 MUST 加 `if (entry.phase === 'evicted') return;`**。对既有 chalk/image **无影响**（正常路径 `land` 恒先于 `evict`；只修"失败后又来 landed"这条泄漏）。

`useWorld` 侧**不**删 `land`/`reconcileLanded` 任何行；component 天然走它们（两者都按 id/path，不判 kind）。

### §11-兼容性论证（针对冲突 3/4/8，`perform/00 §8.1` 冻结集）

`perform/00 §8.1`（`:228-253`）+ `phantom.ts:11-12` 注明该文件"Frozen shape. Owner 01"。本批改动是**加性、源兼容**的，逐条：

1. **加 kind 字面量**：`PhantomKind` 是 `kind` 字段的类型。既有生产者只传 `'chalk'`/`'image'`（`useWorld.ts:453,490`），类型加宽后**仍合法**；既有消费者是 `switch`/比较（`PhantomLayer.tsx:51` `!== 'image'`、`:83` 三元），加宽不改变它们对既有值的判定。仓库内 `grep PhantomKind` 仅命中 `phantom.ts:17,30,53` 的定义与使用，无 exhaustive `switch` 会因新字面量编译失败。
2. **加可选字段**：`cardKind?`/`cardTitle?` 为 `undefined` 缺省。`PhantomEntry` 的所有既有读者（`PhantomLayer`/`GhostCard`/`ChalkMark`/`phantom-seat`）不读它们即无感；`PhantomInit` 的所有既有生产者（`useWorld` 的 `chalk_writing`/`image_generation_progress`/`image_landed`）不传即合法。**无既有字段被重命名、删除或改语义。**
3. **`phase` 值域不变**：`'pending' | 'writing' | 'landed' | 'evicted'`（`phantom.ts:48`）一字不改。component 映射：注册 `'pending'` →（无 `'writing'`）→ `land` 后 `'landed'` → `evict` 后 `'evicted'`。故 `phase === 'writing'` **仍且仅**意味着 chalk（`00 §3.2` 冻结）。
4. **`register` 幂等合并语义不变**：新增两行沿用既有写法（`!== undefined` 才赋值，不重置 `createdAt`、不改 `phase`、不重排座位，`phantom.ts:86-89` 的 doc 逐字仍成立）。
5. **结论**：这是对冻结集**只加不改**的扩展（additive extension），不构成"改形状"。风险仅剩 §11 冲突 5 的**行为**缺口（evicted 泄漏），需 `03` 配合，**不在字段层**。
6. **`land()` 相位守卫（裁决 L）的兼容性**：`if (entry.phase === 'evicted') return;` 只在"已 evict 后又被 land"时短路。既有 chalk/image 的正常时序是 `tool_execution_start`→writing→`tool_execution_end`→landed（成功）或 `tool_end{isError}`→evict（失败，且**仍会**随后收到 `chalk_landed`！）——对失败 chalk/image 而言，此守卫把"错误地翻回 landed"改为"保持 evicted"，**修复而非改变**既有语义（`phantom.ts:86-89` 幂等 doc 本就承诺不重置 phase）。仍属加性。
