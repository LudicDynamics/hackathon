## 1. 一句话定位

**作家用 pi-rp 原生 `write` 落一张组件卡时，服务端在读得到 `args.path` 与 `args.content` 的那一刻（`tool_execution_start`），用纯函数现算 `layer` / `kind` / `title`，向前端补发一条 `card_writing` 演出帧——它只携带"哪个座位、什么形状、什么标题"，不携带任何正文。**

本条与既有 `chalk_writing`（`tool_execution_start` case 内、`if (event.toolName === 'chalk')` 那个分支）同形族、同通道、同"不落账"纪律；落地过户由**既有** `chalk_landed`（`tool_execution_end` case 内、`toolName === 'chalk' || 'write'` 那个分支）承担，本条**不新增落地帧**（`00 §2.2` 裁决 B）。

### 2.2 新帧 `card_writing` 载荷（逐字 = `00 §3.1`）

### 2.3 `source` 的类型与 F-5 跨批协调（**实现前必读**）

- **现状**（`agent-awareness` 在途前）：`export type EventSource = 'writer' | 'character';`（`apps/server/src/engine/event-bridge.ts` 顶层类型）。
- **在途**（F-5）：该批新增 `ActivitySource = 'writer' | 'character' | 'functional'`（`apps/server/src/engine/agent-activity.ts:3`），并把 `EventSource` 可能改成 `ActivitySource` 的**别名**。
- **对本篇的影响**：
  1. `card_writing.source` 的**类型标注**要跟随实际值域（若成别名则用别名；不自行硬编码三值联合）。
  2. **守卫逻辑不变**：仍是 `source === 'writer'`（§3.1）。`'functional'`（初始化命令自身，`extensions/toolkit/init-command.ts`）不会走到本分支，因为初始化子代理的 `write` 事件根本不冒泡（**F-6**，见 §13）。
  3. **值域扩张不改变本批行为**：`'functional'` 落定与否只影响类型，不影响 `write` 触发条件。
- **漏了会怎样**：若实现时硬编码 `source: 'writer' | 'character'` 而该批已把类型换成 `ActivitySource`，TS 编译红；若误把 `'functional'` 也算进触发，则在 `agent-awareness` 落地后可能重复/错位发帧。

## 3. 行为契约逐步（每步写「漏了会怎样」）

### 3.1 触发条件（**精确到 `write`**，F-3 的硬要求）

符号插入点 = `case 'tool_execution_start'` 内，紧随既有 `if (event.toolName === 'chalk') { … }` 分支之后、该 case 的 `break;` 之前；与 `agent-awareness` 批插入的 `pushActivities(...)` **并列**（互不重排，便于 `git add -p` 分离——F-5 第 2 条）。

```ts
case 'tool_execution_start': {
  toolArgs.set(event.toolCallId, event.args);           // 既有，不动
  push({ type: 'tool_start', ... });                    // 既有，不动
  // agent-awareness 批插入：pushActivities(projector.acceptToolStart(...))  ← 在途，勿动
  if (event.toolName === 'chalk') {                     // 既有分支，不动
    push({ type: 'chalk_writing', source, toolCallId: event.toolCallId });
  }
  if (event.toolName === 'write' && source === 'writer') {   // ★ NEW（见 §8）
    push(cardWritingFrame(source, event.toolCallId, event.args));   // 见 §3.2–3.6
  }
  break;                                                // 既有，不动
}
```

- 判据 = `event.toolName === 'write' && source === 'writer'`。
- **MUST NOT** 写成 `chalk || write` 式的宽松集合（`00` 附 F-3 第 3 条）。
- `source === 'writer'` 的依据：本批的车道名与消费侧都按 `source === 'writer'` 过滤（`useWorld.ts:450` chalk 分支逐字 `if (msg.source !== 'writer' …) break`）。组件卡的**父作家进程自身**的 `write` 报 `source:'writer'`；初始化**子代理**的 `write` 不冒泡（F-6，§13）；`'functional'` 是初始化命令自身的活动中继，不构成本分支事件（§2.3）。
- **漏了会怎样**：
  - 写成宽松集合 → 未来某条车道给 `chalk` 也发 `card_writing`，前端注册一个 `kind:'chalk'` 的骨架，与既有 `chalk_writing` 的湿墨幻影**同 `toolCallId` 撞车**（`phantom.ts` 的 `register` 幂等合并会改写既有 entry 的 `kind`）。
  - 漏 `source` 门 → character/functional 侧写文件也会在前端凭空插骨架。

### 3.2 `layer` 判定（本批曾最可能的埋雷点，F-2 已裁决）

```ts
const a = event.args as { path?: unknown; content?: unknown } | undefined;
const relPath = typeof a?.path === 'string' ? a.path : '';
const dir = dirOf(relPath);              // layers.ts:46-48：'world/baker-street/evening.md' → 'world/baker-street'
const layer = layerOfDir(dir);           // layers.ts:37-39：'world' → 'map'，其余恒等
// dir === '' （路径无 '/'）→ layer === ''  → 省略该字段，不产非法值
```

- **为什么不是 `layerOfPath(path, layers)`**（`layers.ts:130`）：
  1. 它**需要** layers 记录，而 `mapEngineEvent` 拿不到（纯函数）。
  2. 即便硬塞 layers 进来，它对 nook 路径是**错的**：layers 的 key 是 `map` 与 `world/*`，`layerOfPath('characters/bob/x.md', layers)` 无最长前缀命中 → 回退 `MAP_LAYER='map'`（`layers.ts:131`），把 nook 里的卡谎报成主图。
- **实测（本设计期在仓库内跑过）**：`world/baker-street/evening.md → 'world/baker-street'` ✓；`world/README.md → 'map'` ✓；`characters/bob/README.md → 'characters/bob'`（恒等，正合 nook 的 `currentLayer`）；`evening.md → ''`（无目录）。
- **漏了会怎样**：`layer` 缺失或错误 → 前端 `ghostVisibleOn(entry.layer, currentLayer)`（`apps/web/src/lib/ghost.ts:50`）把骨架过滤掉（玩家看不到），或把它画到错误层（`phantomSeatFor` 在错层占座）。这正是 `00 §3.1` 说"`layer` **必须**随帧下发"的原因。

### 3.3 `kind` 判定（裁决 A：服务端判）

```ts
const filename = path.basename(relPath);                        // path 已在模块顶部 import node:path
const content = typeof a?.content === 'string' ? a.content : '';
const fm = parseFrontmatter(content).frontmatter;               // frontmatter.ts:180
const kind = cardKindOf(fm, filename);                          // forms.ts:112-124
```

- 服务端**能**判的机械依据（`00 §2.1`，已核验）：`@airp/shared` barrel 全量 re-export `./components/index.js`（`packages/shared/src/index.ts:37`），`components/registry.ts:38` 在模块加载时 `registerComponentKindResolver(...)` 推入 resolver，故服务端 `cardKindOf` 走的是 registry 分支（`forms.ts:116`），`type: component, component: lock` 会得到 `'lock'` 而非塌成 `note`。
- **前置条件（必须写进实现注释）**：`event-bridge.ts` 现在只做**类型导入**（`import type { LocalWorldStore } from '@airp/shared'`，会被编译抹除）。要实现本节，必须加**值导入**（`parseFrontmatter` / `cardKindOf` / `layerOfDir` / `dirOf` / `entityName` 均经 barrel 可达），这个值导入同时**保证 registry 被加载、resolver 已推入**。生产路径本已加载 barrel（`apps/server/src/index.ts:9`），故这是幂等的。
- **漏了会怎样**：若只改前端（前端 `componentKindResolver === null`，`apps/web` 从不 import `components/registry`，`00 §2.1` 已核验）→ `type:component` 全塌成 `note`，锁/门/板/卷轴全画成便签形状，落地换真卡时形状跳变——正是本批要消灭的观感。

### 3.5 退化路径（**不抛异常、不产半截帧**）

| 情形 | 行为 | 判据 |
|---|---|---|
| `args.content` 不是字符串 / 空串 | `parseFrontmatter('')` 不匹配 `FM_BLOCK`（`frontmatter.ts:175,183-185`）→ `frontmatter:null` → `kind` 取最终回退 | 帧仍发出，`kind==='note'` |
| 有正文但**无 frontmatter 块** | 同上，`frontmatter:null` | 同上 |
| frontmatter 是半个 YAML / `doc.errors` 非空 | `parseFrontmatter` 内部 `try/catch` + `doc.errors` 收集，不抛（`frontmatter.ts:195-209`） | 帧仍发出 |
| `args.path` 不是字符串 / 缺 `path` | `relPath=''` → `layer` 省略；`path.basename('')===''` → `kind` 走回退；`title` 为空串 | 帧仍发出，**不含 `layer`** |
| `args.path` 无 `/`（如 `x.md`） | `dirOf` 返回 `''` → `layerOfDir('')===''` | **省略 `layer`**，不产空串（F-2 第 2 条） |

- **"不产半截帧"**的定义：绝不 `push` 一条缺 `type`/`kind`/`toolCallId` 的帧，也绝不在解析途中 `push` 再补——`push` 只在 §3.6 的**单次**构造里调用。
- **绝不 throw**：`mapEngineEvent` 是 `emitEngine` 循环里的**同步**调用（`EventBridge.emitEngine` 方法内对 `mapEngineEvent(...)` 的返回数组逐个 `broadcast`），抛出会中断整条 `onEvent` 链（后续 `writer_idle` 等帧全丢）。与既有 `show` 分支的"缺 `details.frame` 只 `console.warn` 不抛"同纪律。
- **最终回退 kind = `'note'`，不是 `'default'`**：`cardKindOf → resolveComponentKind` 的最后一行是 `return 'note'`（`registry.ts:78`），且 note 谓词显式含 `fm.type === undefined && fm.component === undefined`（`components/core.ts:86-89`）；无 registry 时 `forms.ts:123` 的回退同样是 `'note'`。`CARD_FORMS.default`（`forms.ts:70`）**经 `cardKindOf` 不可达**（其注释自称 "Defensive fallback only"）。`00 §5.3` 初稿曾写 `default`，**已勘误为 `note`**（详见 §11 冲突 1，已解决）。

### 3.6 组装与发射（单点）

符号位置：§3.1 所示的 NEW `if` 块内（即 `tool_execution_start` case、chalk 分支之后、`break;` 之前）。

## 5. 落账：**本帧不落事件**（依据）

`card_writing` 是**演出帧**，一条事件都不落。三层理由（与 `docs/perform/01-作家演出通道.md §5`、`docs/perform/02-骰子仪式.md §5`、`docs/perform/05-演出库.md §5` 同构）：

1. **通道定义**：`doc-21-事件表协议.md:33` 逐字把 `writer_delta / tool_start / chalk_writing / writer_idle` 列为「**传输帧**（演出用，瞬时）——只走 WS，不落库」；`:38` 的判据「它回答的是『世界现在什么样』，它不是事件；事件回答的是『世界怎么变成现在这样的』」。`card_writing` 是"一张卡**正在**被写"的动画中间态，不回答"世界变成了什么"。
2. **事实已由动作自己落**：`write` 是**原生工具**，世界变化由扩展的 `tool_result` hook 落账（`doc-21-事件表协议.md:49` 入口 B：「只盯 `write`/`edit` 两个名字」），经 `history.db` → 尾部读表 → `broadcast({type:'world_event'})`。此处再落一条，同一事实两份账。
3. **落账会污染 `seq`**：`event.seq` 是前端唯一排序游标与去重键。骨架是**纯投影**（`00 §6` 反模式 4），写进事件表会让每条 `write` 多触发一次 `case 'world_event'` → `fetchLayer` 整层重取（`apps/web/src/state/useWorld.ts` 的 `world_event` 分支）——为一张尚未落盘的卡重取一次层。

**机械判据（可核验）**：`grep -c appendEvent apps/server/src/engine/event-bridge.ts` = **1**，且该唯一命中是一处**注释词**（"`appendEvent` returns only after COMMIT"），非调用。`EventBridge` 只调 `getEventsSince`/`getMaxSeq`。本分支**不改变这个数字**。（设计期实测：已跑。注意：`agent-awareness` 在途批会改变该文件行数，故此处**不锁行号**，只锁"调用计数"。）

- **漏了会怎样**：若顺手落一条 `card_writing` 事件，`00 §6` 反模式 4 被破，且 `04` 篇的"演出帧不落账"验收判据失效。

## 7. 错误边界

| 情形 | 行为 | 依据 |
|---|---|---|
| `args` 为 `undefined` / 非对象 | 所有取值走 `typeof !== 'string'` 分支 → `relPath=''`、`content=''` | §3.5；不抛 |
| `args.content` 非字符串（数组/对象） | 视为 `''` → `frontmatter:null` | 同上 |
| frontmatter YAML 报错 | `parseFrontmatter` 内部吞错（收集进 `errors`） | `frontmatter.ts:195-209` |
| `args.content` 半截（YAML 未闭合） | `FM_BLOCK` 不匹配 → `frontmatter:null` → `kind='note'` | `frontmatter.ts:175` |
| `args.path` 无 `/` | 省略 `layer` | F-2 第 2 条 |
| `kind` 推成 `'chalk'` / `'gate'` / `'sprite'` | 服务端**照发**（见 §9 差异 4）；"不出骨架"是渲染侧政策 | `00 §2.3`（`chrome:'bare'` 档） |
| 解析中任何 throw | **不允许**（§3.5） | `emitEngine` 循环的健壮性 |

- **服务端不做 kind 过滤**的权衡：把 `CARD_FORMS.chrome` 的白名单塞进纯映射函数，会让 `event-bridge` 依赖渲染策略，且为将来每个 `chrome` 档改动扩散到服务端。前端做纵深防御更内聚（`00 §6` 反模式 1 只禁"前端自行推 kind"，不禁止"前端按已给的 kind 决定画不画"）。**这与 `SKWiring` 的边界已在 IRC 对齐、并升为 `00` 附裁决 F：前端对 `chrome==='bare'` 的 kind MUST NOT `registerPhantom`**（否则会占座，见 §11 冲突 3）。
- **漏了会怎样**：若服务端对 `chalk` kind 也发帧而前端未过滤 → 占座幻影挤走真卡座位。

## 13. 已知缺口（有意，非缺陷）

本节按 `00` 附 F-3 / F-6 / F-9 的 MUST 要求**显式声明**，避免读代码的人误以为"组件生成演出已全覆盖"。

### I. `edit` 改写组件卡**无任何演出**（F-3）
- 事实：作家指令原文（`extensions/instructions.ts:84`）明写组件卡"create or **rewrite** it with **write or edit**"；但落地帧只认 `chalk || write`（`event-bridge.ts` 的 `tool_execution_end` 分支），且本篇的 `card_writing` 触发条件**精确到 `write`**（§3.1）——故 `edit` **既无 writing 帧、也无 landed 帧**。
- 为何是有意的：`write`=新建（卡还不在 `items` 里，骨架是"预告"）；`edit`=改写（卡已在画布上，骨架会盖在真卡上，语义变成"这张卡正在被改"——**另一个演出**）。
- 本批立场：只覆盖 `write`；`edit` 的改写演出**登记为后续**（`00 §8` 未知 5）。**实现 MUST NOT 把触发条件放宽到 `edit`。**

### II. 初始化（scene-init / nook-init）期间落地的组件卡**不出骨架**（F-6）
- 事实：初始化子代理（`ctx.spawnAgent`）的 `tool_execution_*` 事件**不冒泡到父会话事件流**（`vendor/pi-rp/packages/coding-agent/src/core/subagent/spawn.ts:143-152` 只捕获其自身 `state_update`）。故服务端**收不到**它们的 `write` 的 `tool_execution_start`，`card_writing` 不发帧。
- 为何接受：初始化是"整幕一次点亮"，玩家没有"等一张卡"的预期；这不是缺陷。
- 本批立场：**不覆盖**。**实现 MUST NOT** 为它新增事件桥接（那属另一批的范围）。

### III. character / functional 车道的 `write` **不出骨架**（本批范围边界）
- 本批的 `source` 守卫是 `source === 'writer'`（§3.1）；`character`（角色写内容）与 `functional`（初始化命令自身）**不发帧**。
- 若评审要扩，见 §12 未知 3。

### IV. `write` 一张 `type: chalk`（或 `gate`/`sprite`）**仍会发一条 `card_writing`**
- 这不是"缺口"而是**有意**（裁决 F）：服务端零过滤，帧照发；前端按 `chrome==='bare'` 不注册幻影、`CardSkeleton` 返回 null。**不得视为 bug。**
- **限定**：仅指**父作家进程自身**的 `write`。初始化子代理的 `write` 根本不发帧（F-6，§13-II），故续 §13-II 的豁免。

### V. `write` **覆盖**既有卡时，骨架会排在**另一个座位**（F-9，裁决 N）
- 事实：`write` 的 guidelines 逐字「Use write only for new files or **complete rewrites**.」（`vendor/pi-rp/packages/coding-agent/src/core/tools/write.ts:22`）——即 `write` 也可**整卡重写**一张已在画布上的卡。此时前端对同一个 `path` 既有一张真卡、又新注册一个骨架；`phantomSeatFor` 把这张真卡当作**障碍**（`apps/web/src/lib/phantom-seat.ts:47-58`），于是骨架被排到**另一个座位** → 窗口内出现**虚假双卡**。
- 为何本期**不改**：`card_writing` 帧**故意不带 `path`**（`00 §3.1`）——前端在注册期**判不出**"这次 `write` 是新建还是覆盖"（`tool_execution_start` 只有 `args.path`，而该字段按契约不随帧下发）；要判需另加字段或前端读层，均越出本批范围。
- 本批立场：**登记为已知偏差**（同 F-3/F-6 的"不许静默"纪律），不修。窗口结束由 `chalk_landed` → `land` 收束；真实卡由既有 `file_changed` → `fetchLayer` → `reconcileLanded` 接管。**实现 MUST NOT** 为它私增 `path` 字段或排座特判。
