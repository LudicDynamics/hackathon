## 3. 行为契约逐步（每步「漏了会怎样」）

> 本节把「不改门禁」这个结论拆成可核验的逐步推理；每步都给**只读**核验方式。

1. **确认 `event-bridge.ts` 已在门禁的 EMITTERS 名单里**（`tools/check-ws-contract.mjs:41`）。
   *漏了*：若发射点落在一个**不在名单**的新文件里，帧会**逃过**门禁的 EMITTED 扫描——这才是真正需要改门禁的唯一情形。本批发射点在既有 `event-bridge.ts`，**不发生**。

2. **确认 `useWorld.ts` 已在 CONSUMERS 名单里**（`tools/check-ws-contract.mjs:49`）。
   *漏了*：消费点在新文件（如新建 `card-skeleton.ts` 里写 `case`）会逃过 CONSUMED 扫描。**本批消费点 = `useWorld.ts` 的 `case 'card_writing'`**（`02` 篇落点，兄弟已回执：置于 `case 'chalk_writing'`（`:449`）之后、`case 'writer_delta'`（`:462`）之前），仍在名单内。

3. **确认 `contractFrom` 只扫 §6.2 的第一张表**（`tools/check-ws-contract.mjs:144-177`：从 `### 6.2` 起、遇 `##`/`###` 或空行结束）。
   *漏了*：若把 `card_writing` 写成**子表**（"要删的帧"/"保留改名的帧"）里的行，契约扫描**看不见它** → 同时触发 UNDECLARED。故 §2 明确要求落**第一张表**。

4. **确认帧名正则吃 `card_writing`**（`tools/check-ws-contract.mjs:169`：`/^[a-z][a-z_0-9]*$/`）。
   `card_writing` 全小写 + 下划线，匹配。*漏了*：若命名带大写（如 `cardWriting`），契约扫描**静默漏收** → 门禁把已发射的帧判成 UNDECLARED。

5. **确认不需要 `INTENTIONALLY_UNCONSUMED`**（`tools/check-ws-contract.mjs:61-69`）。
   该名单是"发射了但**前端永不消费**"的登记。本批前端**消费** `card_writing`（`case 'card_writing'` 注册幻影）→ 不属该名单。*漏了（误加）*：会把一条**真消费**的帧登记成"故意不消费"，门禁从此对这一帧**失去 DARK 检测力**（正是该名单存在的意义被反用）。

6. **确认不需要 `KNOWN_DARK`**（`tools/check-ws-contract.mjs:76-89`）。
   同上，前端会消费 → 不 dark。*漏了（误加）*：把待办登记成"已知暗帧"，`02` 未落地时门禁会**假绿**。

**结论**：`tools/check-ws-contract.mjs` **零改动**。

### 3.4 门禁本体的**只读推演**（`[实测]`，本机 2026-09-13）

## 7. 错误边界

1. **契约表加了行、服务端忘了发** → `missing`（契约承诺无人兑现）。*防线*：`01` 篇服务端测试。
2. **服务端发了、契约没加** → `undeclared`。*防线*：§2 的表行。
3. **前端监听但服务端没发** → `ghost`（死监听）。*防线*：`02` 篇 + 门禁。
4. **误把帧登记进 `INTENTIONALLY_UNCONSUMED`/`KNOWN_DARK`**（§3 step 5/6）→ 门禁**假绿**（对真消费/待办帧失去检测力）。*防线*：本文 §3 明确"两名单都不加"。
5. **帧名写成子表行或非 snake_case**（§3 step 3/4）→ 契约扫描静默漏收。*防线*：§2 逐字行文 + 正则核验。
6. **`chrome:'bare'` 的 kind 被无条件注册**（裁决 F，00 §3.6）→ `phantomSeatFor` 把它计入 `occupied` → 挤走真卡座位。*防线*：前端在 `registerPhantom` **之前** `const form = CARD_FORMS[kind]; if (!form || form.chrome === 'bare') break;`。**服务端零过滤**（`mapEngineEvent` 是纯映射，不做渲染策略）。
7. **component 幻影无 drop 路径**（裁决 G，00 §3.7）→ `evict` 后永不 `drop`，注册表不排空（违反 ``docs/perform/03-生图幻影与过户.md` §10.3「验收判据」第 1 行（`getPhantomsSnapshot()` 最终为空）` 的「`getPhantomsSnapshot()` 最终为空」）。*防线*：`PhantomLayer` 的 evict-drop 分支扩到 component，用独立常量 **`SKELETON_EVICT_MS = 320`**。
8. **致命竞态（附 F-7 / 裁决 L）**：失败的 `write` 的 `tool_end{isError}` → `evict` 后，同序的 `chalk_landed` 会调 `land()` 把 `phase` 从 `'evicted'` **覆盖**回 `'landed'`（`phantom.ts:153-161` 无相位守卫）→ evicted-drop 永不触发、`reconcileLanded` 也不命中（失败无文件）→ **骨架永挂**。*防线*：`phantom.ts::land()` 加 `if (entry.phase === 'evicted') return;`（一行，不动其他语义）；`apps/web/test/` 加 `register → evict → land` 后 `phase` 仍为 `'evicted'` 的**非空性**用例。
9. **README 永挂（附 F-8 / 裁决 M）**：`README.md` kind=`gate`（`registry.ts:77`），但**永不进 `items`**（`layers.ts:106-114` 排除本层 README；`reconcileLanded` 按 `items.paths` 删）→ cover 骨架永留画布。*防线*：前端守卫**扩到 `kind === 'gate'`**：`if (form.chrome === 'bare' || kind === 'gate') break;`（与裁决 F 同一守卫位）。scene-init 第 1 步正是先写 `README.md`。
10. **一般化泄漏（附 F-10 / 裁决 O）**：任何"登记了但路径永不进 `items`"的幻影都会永挂（`player/` 背包 `.md`、stub 层文件、非层目录 `.md`）。*防线*：注册前提 = **白名单口径「能推出合法层 ∧ chrome≠bare ∧ kind≠gate」才注册**；`layer` 推不出或为 `''` 时**直接不注册**（**勘误**：`02` 初稿"缺 `layer` 回退 `layerRef.current`"**取消**——回退会错排进当前层并永挂）。
11. **`write` 覆盖既有卡的座位偏差（附 F-9 / 裁决 N）**：`write` 可完整重写既有文件（`vendor/pi-rp/packages/coding-agent/src/core/tools/write.ts:19`），此时真卡已在 `items`、`phantomSeatFor` 把它当障碍 → 骨架排到**另一个座位**（窗口内虚假双卡）。*本期不改*，登记为已知偏差（修它要给帧加 `replace?: true`，属范围扩张）。**`01` MUST 显式登记**（不许静默）。
