## 1. 一句话定位

**`CardSkeleton` 是 `kind:'component'` 幻影的唯一渲染分支**：它只吃一条 `PhantomEntry`，按 `entry.cardKind` 推出的 `chrome` 档画一个**无字的结构化灰块骨架**，填满幻影座位盒（= `CARD_FORMS` 的 `w×h`，`00 §3.3`），用**纯 CSS keyframes** 呼吸；落地帧一到就停在 `landed` 相位等数据接管（`reconcileLanded` 删除），写失败则 320ms 淡出后由 `PhantomLayer` 注销。它**不显示任何正文字符**（`00 §2.3`），**不可点不可拖**（`doc-10 E3`，由既有 `.object--ghost` 壳保证，`index.css:1800`），**不进 `items`/拖拽/footprint**（`00 §6.4`）。

## 3. 行为契约（逐步）

### 步骤 0 — 入口过滤：只有 `component` 到达

`PhantomLayer.tsx:71` 的 `ghostVisibleOn(p.layer, currentLayer)`（`ghost.ts:50`）是本车道的**可见性过滤**，component 不例外（与 `02` 已互认）。`entry.layer` 缺省（`undefined`）时不过滤——这是既有的"容忍旧帧"策略，本批沿用。

**漏了会怎样**：若只为 component 另写过滤器，就出现第二个可见性真相源，层切换时骨架会与真卡不同步（`doc-06 §2.2` 的 encore 事故）。

### 步骤 1 — 定档

```tsx
const shape = skeletonShapeFor(entry.cardKind);
```

- `entry.cardKind` 是服务端用 `parseFrontmatter` + `cardKindOf` 从 `args.content` 现算下发的（`00 §2.1` 裁决 A），前端**只消费**。
- 纯函数内部回退链：`CARD_FORMS[kind]?.chrome ?? CARD_FORMS.default.chrome`（`forms.ts:64-70`，`default` 的 `chrome` 是 `'paper'`）。

**漏了会怎样**：前端若自行从文件名推 kind，`type:component` 会塌成 `note`（`forms.ts:116-123` 的 fallback 分支；web bundle 里 `componentKindResolver === null`），于是锁/门/板/卷轴全画成便签形状——正是本批要消灭的形状跳变（`00 §2.1`）。

### 步骤 2 — `visible === false` 立即 `null`（**非空性关键分支**）

```tsx
if (!shape.visible) return null;   // bare 档：不出骨架（00 §2.3 末行）
```

`bare` 覆盖 `chalk` / `sprite` / `portrait`（`forms.ts:66,68,99`）。这三种 kind 里，`chalk` 有自己的湿墨车道（`WriterInkLayer.tsx`），`portrait` 的素材经 `/api/characters` 投影到 Nook sibling DOM，不经 `write` 落 `.md` 卡（`00 §8 #2`，已结案）。

**这是纵深防御的第二层**：第一层在 `02`（`case 'card_writing'` 对 `chrome==='bare'` 的 kind **不** `registerPhantom`）。原因见 §13 冲突 3：`register` 一旦发生，`phantomSeatFor` 就把该幻影计入 `occupied`（`phantom-seat.ts:55-62`），一个"什么都不画"的幻影会**占住座位**直到落地帧。

**漏了会怎样**：作家 `write` 一张 `type: chalk` 的叙事卡时，服务端**也会**发 `card_writing`（`01` 定案 (A)：服务端零过滤，见 §13 冲突 3），前端就会在成品座位画一个灰盒，**与 chalk 湿墨车道同座位打架**。§10 A3 专门钉死这条。

### 步骤 3 — 壳体不进 `items`

骨架**只**是 `.object--ghost` 壳（`PhantomLayer.tsx:74-86`）里的一层内容。它不写 `data-path` 到 `items`，不参与 `closest('.object')` 命中（`index.css:1798-1803` 注释明写这是 hit-test 契约），不触发 `measure`/footprint 回写。

**漏了会怎样**：违反 `00 §6.4` 与 `AGENTS §7.5` 第 7 条（第三处现算 `cardFormOf` 的碰撞点）。骨架一旦有 `data-path`，`Canvas` 的拖拽派发会把它当真卡，拖出一个不存在的文件。

### 步骤 4 — 渲染 DOM（§5 逐档）

见 §5。**无文字节点**：不渲染 `cardTitle`、不渲染 `label`、不渲染 `CARD_FORMS[kind].label`（`forms.ts:51`）。

**漏了会怎样**：违反 `00 §2.3`"绝不呈现正文字符"；且显示标题等于承认"骨架承载内容"，与裁决 D（不做真流式）的立场自相矛盾。

### 步骤 5 — phase 决定动画状态（§4.3）

### 步骤 6 — 撤离由**数据**驱动，不由计时器驱动

- `land`（`phantom.ts:176-182`）→ `phase='landed'`，**座位不变**；骨架**停住不动**（不再呼吸），等真卡。
- 真卡落地：`file_changed` → `fetchLayer`（`useWorld.ts:154-180`）→ `setState(items)` 与 `reconcileLanded(new Set(items.map(path)))`（`useWorld.ts:170-174`）在**同一次回调**里发生 → 幻影被删。骨架与真卡**不共存**。
- 写失败：`tool_end{isError}` → `evictPhantom`（`useWorld.ts:414-420`）→ `phase='evicted'` → 骨架淡出 320ms → `PhantomLayer` 计时 `drop`（§4.4）。

**不设 `min-dwell`**（`00 §2.5`），**不加人为延时**（`00 §6.3`）。

**漏了会怎样**：若在 `CardSkeleton` 内部用 `useEffect` + `setTimeout` 自行 `drop`，会与 `PhantomLayer` 的清理 effect（`PhantomLayer.tsx:47-69`）争抢同一条幻影，且 chalk 车道已经因为"两个地方计时"被明令禁止（`perform/01 §7`，`PhantomLayer.tsx:41-46` 注释）。计时器**只允许有一个属主**，本车道的属主是 `PhantomLayer`。

## 4. 相位、寿命与动画

### 4.1 相位映射（`phantom.ts:48` 值域不变，`00 §3.2`）

| `entry.phase` | 何时到达 | 骨架表现 | 谁改相位 |
|---|---|---|---|
| `'pending'` | `register`（`phantom.ts:110`）。component 车道**注册即骨架**（`00 §3.2`：不经过 `'writing'`） | 呼吸（pulse），`opacity` 0.55↔0.92 | `useWorld` 的 `case 'card_writing'`（`02`） |
| `'writing'` | component 车道**不会**出现（该档仍归 chalk，`00 §3.2`）。防御性地与 `'pending'` 同渲染 | 同 `'pending'` | — |
| `'landed'` | `land`（`phantom.ts:159`） | **停住**（`animation: none`，`opacity: 1`）：内容已落盘，只等真卡接管 | `useWorld` 的 `case 'chalk_landed'`（`useWorld.ts:468-474`，复用） |
| `'evicted'` | `tool_end{isError}`（`useWorld.ts:420`） | 320ms 淡出（`forwards`），随后被 `drop` | 同上 |

**为什么 `landed` 要停住而不是立刻 `null`**：真实卡片要到 `fetchLayer` 完成后才画出来（`useWorld.ts:170-174`）。若 `landed` 立刻返回 `null`，座位会出现**一段可见的空洞**（真卡还没来）。**实测该空洞 ≈230ms+**（`00` 附 F-4）：`write` 落盘 0.42ms → `fs.watch` ~16ms → 服务端 `WATCH_DEBOUNCE_MS` **150ms**（`event-bridge.ts:13`）→ `/api/layer` 往返 64ms。所以"停住等真卡"不是理论细节，而是**本车道可见窗口的主要构成**（`landed` 后的骨架一直画着，直到 `reconcileLanded` 删除）。这与 chalk 车道的既有行为一致：`ChalkMark` 在 `landed` 时保留节点并加 `.ink-spread`（`WriterInkLayer.tsx:85`），同样靠 `reconcileLanded` 收尾。**注意这不是 `min-dwell`**——它没有时长，边界是**数据到达**（见 §13 冲突 1 对 `00 §2.5` 措辞的解释）。

**可见窗口的实测修正（`00` 附 F-4）**：`00 §2.5` 原稿说"窗口通常是几十毫秒"**是错的**——那只是 `write` 的落盘时间；玩家实际看到的骨架窗口含 `landed` 停住段，合计 **≈230ms+**（写大文件或磁盘慢时更长）。对样式的影响：pulse 周期 1.5s 在这个窗口里**跑不满一个周期**，所以骨架读起来更像"一次浅浅的呼吸"而非循环闪烁——这正是把周期定在 1.5s（§4.3）而非 `.ink-tip` 的 1.1s 的理由之一；若窗口再长（>1.5s），第二次呼吸才出现。

### 4.2 盒子尺寸

```tsx
style={{ height: entry.seat.h }}   // 与 GhostCard.tsx:49 同法
```

宽度由 `PhantomLayer.tsx:81` 的 `width: p.seat.w` 内联给出，`.card-skeleton` 用 `width: 100%` 填满。

- `seat = phantomSeatFor(CARD_FORMS[kind], layer).seat`（`phantom-seat.ts:42`，`00 §3.3`）→ 盒 = `CARD_FORMS` 的声明盒 → **与真卡同形**，过户不跳位。
- **不写死宽度**（`AGENTS §7.5` 第 1 条）。骨架的宽度真相源仍是 `CARD_FORMS`。
- **高度**：这里给内联 `seat.h` 与 `GhostCard` 一致；`AGENTS §7.5` 第 2 条约束的是**真卡外壳**（`.object` 不写死高度、由内容撑开）。骨架**没有内容**，它必须显式取座位盒高，否则高度为 0（`.object--ghost` 父节点没有高度，`100%` 解析为 0）。

### 4.3 pulse：只走 CSS keyframes（`AGENTS §7.6` 红线）

**硬约束**：不进 React state、不进 `rAF`、不进 `useEffect` 计时器、不进 `pointermove`（`AGENTS §7.6` 第 2 条"pointermove 不进 React"）。骨架的呼吸**只有一个 `animation` 声明**，React 只在 `phase` 变化时重渲染一次（`useSyncExternalStore` 推送，`phantom.ts:209-211`）。

```css
/* apps/web/src/index.css —— 追加在 image ghost 段（index.css:1789-1897）之后 */
@keyframes cardSkeletonPulse {
  0%, 100% { opacity: 0.55; }
  50%      { opacity: 0.92; }
}
```

- 只动 `opacity`（合成器友好）；**不动 `transform`**：`.object--ghost` 的子孙若加 `transform` 会新建合成层，且与 `AGENTS §7.5` 第 3 条（旋转只归外壳）的纪律相冲突。
- 周期 **1.5s**：比 `.ghost-card__skeleton` 的 shimmer 1.9s（`index.css:1832`）略快，比 `.ink-tip` 的 1.1s（`index.css:303`）略慢——骨架是"结构在成形"，节奏介于"光扫过"与"笔尖颤"之间。
- **预算**：一个骨架 = 一个 opacity 动画层。并发骨架数 = 并发 `write` 数（通常 1；`00 §2.5` 与附 F-1 实测 `tool_execution_start` 严格串行），远低于 `AGENTS §7.6` 第 1 条警告的"全屏 canvas"级别。

### 4.4 淡出时长与既有常量族的关系

```tsx
// PhantomLayer.tsx 常量区（现有 EVICT_FADE_MS = 700，PhantomLayer.tsx:36 旁边）NEW：
/** 骨架的失败撤离：一次性壳、背后无资产，取 chalk 车道同一预算
 *  （WriterInkLayer.tsx:22 的 EVICT_FADE_MS = 320，配 .ghost--evicting 的 320ms，index.css:311-318）。 */
const SKELETON_EVICT_MS = 320;
```

| 车道 | 常量 | 值 | 配对 CSS | 取值理由 |
|---|---|---|---|---|
| chalk（失败） | `WriterInkLayer.tsx:22` | 320ms | `.ghost--evicting`（`index.css:311-318`） | "不留半成品"（`perform/01 §7`） |
| image（落地/失败） | `PhantomLayer.tsx:36` | 700ms | `.ghost-card--evicted`（`index.css:1841-1844`） | 一张已落地的图淡出是较大视觉事件 |
| **component（失败）** | **`SKELETON_EVICT_MS`（NEW）** | **320ms** | `.card-skeleton--evicted`（NEW，§5.10） | 骨架与 chalk 同属"一次性壳、背后无资产" |

**关系一句话**：`320` 不是新拍的数字，是**沿用 chalk 车道已验证的预算**；`700` 那个值属于"背后已有一张图"的场景，骨架不该用。

`PhantomLayer.tsx:47-69` 的清理 `useEffect` 需改动（**该文件行级属主是 `03`**，与 `02` 已互认）：

```tsx
// 现状 PhantomLayer.tsx:47-69 —— 第 51 行把非 image 全部 skip（component 的 evicted 幻影因此永不被 drop）
// 设计（NEW）： evicted→计时 drop 扩到 image + component；landed-dwell 仍仅 image
for (const p of phantoms) {
  if (p.phase === 'evicted') {
    const budget = p.kind === 'component' ? SKELETON_EVICT_MS
                 : p.kind === 'image' ? EVICT_FADE_MS
                 : undefined;                       // chalk 自撤（WriterInkLayer.tsx:78-82），不重复计时
    if (budget !== undefined) timers.push(window.setTimeout(() => drop(p.toolCallId), budget));
    continue;
  }
  if (p.kind !== 'image') continue;                 // landed-dwell（LANDED_DWELL_MS）仍仅 image
  if (p.asset !== undefined && p.asset === bgSrc) { evict(p.toolCallId); continue; }
  const dwell = p.reused === true ? REUSED_DWELL_MS : LANDED_DWELL_MS;
  timers.push(window.setTimeout(() => evict(p.toolCallId), Math.max(0, p.createdAt + dwell - now)));
}
```

deps 不变（`[phantoms, bgSrc]`，`PhantomLayer.tsx:69`）。

**为什么必须跨到这一行**（`02` 发现的缺口，已互认）：component 幻影**没有** asset，`landed` 分支的 `p.asset === bgSrc` 永不成立；而 `evict` 只改相位不删除（`phantom.ts:164-174`）。若不给 component 一条 `drop` 路径，写失败的骨架会**永挂 DOM**（`ghostVisibleOn` 只看 layer 不看 phase，`ghost.ts:50`）。`phantom.ts:168` 的 `pendingEvict` 缓冲只处理"注册前就失败"的情形，救不了已注册的。**漏了会怎样**：一次失败的 `write` 在画布上留下一个永远呼吸的灰盒，`04` 的浏览器验收"注册表最终为空"直接红。**正常路径不走计时器**：`land` 有 `path`（`phantom.ts:156`）→ `file_changed` → `fetchLayer` → `reconcileLanded` 按 path 删（`useWorld.ts:174`）。

```tsx
      <div className="card-skeleton__lines">
        {shape.lines.map((l, i) => (
          <span key={i} className="card-skeleton__line" style={{ width: `${l.w}%`, height: l.h }} />
        ))}
      </div>
    )}
    {shape.decor.seal && <span className="card-skeleton__seal" />}
  </div>
);
```

- `data-*` 四属性是**给 `04` 的浏览器判据用的实测契约**（已通过 `hub` 同步给 `SKContract`），与本组件渲染逻辑无关，但**不得改名**。
- `key={i}` 安全：`lines` 是无状态静态列表，每次渲染由纯函数新生成（`02` 保证不外泄冻结引用）。
- **不变量**：`decor.*` 全 false 且 `lines=[]` 时**只剩根 div**（`slab`/`board` 接近此形态，靠根 class 的材质表达）。
- `decor.inset` / `decor.grid` / `decor.wash` / `decor.ruled` **不产生额外元素**——它们由根 class 的 CSS 表达（§5.3–5.6）。`02` 的 decor 字段与本文的"元素 vs class"分工必须对齐（§13 冲突 4）。

### 5.10 `landed` / `evicted` 变体

```css
.card-skeleton--landed { animation: none; opacity: 1; }   /* 内容已落盘：停住，等真卡 */
.card-skeleton--evicted {
  animation: cardSkeletonEvict 320ms ease-in forwards;    /* == SKELETON_EVICT_MS（§4.4） */
}
@keyframes cardSkeletonEvict {
  0%   { opacity: 0.92; }
  100% { opacity: 0; }
}
```

- `--evicted` 的 `320ms` 与 `SKELETON_EVICT_MS` **必须同值**（同 `.ghost-card--evicted` 与 `EVICT_FADE_MS` 的既有配对纪律，`PhantomLayer.tsx:34-36`）。
- `--landed` 用 `animation: none`（而非 `paused`）：pause 会保留 `opacity` 的中间帧值，骨架会在某个半透明值上冻结。
- `--landed` 把 `opacity` 钉在 **1**（而非 `--writing` 的脉冲区间 0.55–0.92）：内容已落盘，骨架应当"实"起来迎接真卡——**这个"实"的档位会持续 ≈230ms+**（附 F-4），是本车道最可见的一帧，值得给它满不透明度而不是停在呼吸的低点。

### 5.11 降级：`prefers-reduced-motion`

`index.css` 已有三处同族块（`:1351`、`:1992`、`:2168`）。追加第四处，紧贴骨架段：

```css
@media (prefers-reduced-motion: reduce) {
  .card-skeleton { animation: none; opacity: 0.8; }         /* 少动，不少信息 */
  .card-skeleton--landed { opacity: 1; }
  .card-skeleton--evicted { animation: none; opacity: 0; }
}
```

- 依据既有纪律："less movement, never less information"（`index.css:1990-1991` 注释）。骨架的**形状**是信息，保留；**呼吸**是装饰，去掉。
- `evicted` 在降级下**直接不可见**（`opacity: 0`）；DOM 节点仍在 320ms 后被 `drop`（§4.4），满足 ``docs/perform/03-生图幻影与过户.md` §10.3「验收判据」第 1 行（`getPhantomsSnapshot()` 最终为空）` 的「`getPhantomsSnapshot()` 最终为空」。

- **失败撤离归前端**（`00 §3.7` 裁决 G）：`tool_end{isError}` 已在 `useWorld.ts:803-807` 就近 `evict`；`drop` 由本篇的 `PhantomLayer` 计时完成。

**漏了跨端对齐会怎样**：前端从 `entry.cardTitle` 或文件名反推 kind 会得到 `note`（`forms.ts:116-123`；registry 的 `resolveComponentKind` 最终也 `return 'note'`，`registry.ts:78`），与 `01` 下发的 `kind` 不一致 → 骨架与真卡不同形，过户跳变。
