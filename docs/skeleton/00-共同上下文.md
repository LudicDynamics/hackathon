## 0. 一句话定位

**给"组件卡生成中"补一条与 chalk 湿墨同源、但呈现"结构化骨架"而非"逐字正文"的演出车道：作家 `write` 一张组件卡时，玩家在成品座位先看到与 `CARD_FORMS` 同形的灰块骨架（按 kind 分档、带 pulse），落地那一刻在同一座位换成真卡。**

已存在的两条幻影车道（`kind:'chalk'` 湿墨 / `kind:'image'` 生图）**都解决"还没来"**；本条解决**"正在长"**——参考实现见 `https://app-render-qire930.pages.dev/` 的「使用空数据」档（结构化骨架屏），**不是**它的「开启流式模拟」档（真数据逐字段填充）。

## 1. 边界（做什么 / 不做什么）

### 做
- `write` 落**组件卡**时，产出一条 `card_writing` 演出帧（与 `chalk_writing` 同形族）。
- 前端在成品座位渲染**骨架屏**：形状由服务端给定的 `kind` 从 `CARD_FORMS` 与 `components/registry` 的 kind 语义推出（paper / note / slab / board / panel / scroll / cover 各一档）。
- 复用既有幻影注册表 `lib/phantom.ts`（加第三 `kind:'component'`）、既有 `PhantomLayer` 挂点、既有座位 `phantomSeatFor`、既有过户入口 `land`/`reconcileLanded`。
- 落地（`write` 的 `tool_execution_end`，即既有 `chalk_landed`）时**同座位**换真卡。

### 不做（**划死**）
- **不做真数据流式**（参考站的「开启流式模拟」档）。理由见 §2.4：组件卡有 frontmatter，半截 YAML 渲染进卡片会穿帮，收益/代价不划算。**登记为"将来的可选升级"，不在本批。**
- **不新增排座算法**。座位仍只有 `phantomSeatFor` 一个接缝（`layout/00 §5`）。
- **不改 `write` 工具的落盘/落账**。它继续走 pi-rp 原生 `write` + `tool_result` hook 兜底（`docs/tools/12 §4.2`）。
- **不改 chalk / image 两条既有车道**的任何行为。
- **不碰 `apps/web/src/components/canvas/CardRenderer.tsx` 的真卡渲染**——骨架是独立浮层，真卡渲染一字不动。

## 2. 冻结裁决

### 2.1 裁决 A：`kind` 由**服务端**判定（前端判不出）

**现状事实**（已核验）：
- 组件卡走 pi-rp **原生 `write`**（`extensions/instructions.ts:84,230`：`Write files with \`write\``）——不是自定义工具。
- `write` 的 `args`（含 `path` + `content`）在 `tool_execution_start` **完整到达服务端**（`vendor/pi-rp/packages/agent/src/types.ts:441` `{ toolCallId, toolName, args }`；`agent-loop.ts:388-392` `args: toolCall.arguments`）。
- **前端判不出 component kind**：`apps/web` 从不 import `components/registry`（`grep -rn "COMPONENT_REGISTRY" apps/web/src/` 为空）；它只 import `@airp/shared/forms`（`useWorld.ts:11`）。而 `cardKindOf` 的 registry resolver 是**运行时推入**的（`forms.ts:29-35`），web bundle 里 `componentKindResolver === null` → `type: component` 会塌成 `note`（`forms.ts:116-123`）。
- 服务端**能**判：`@airp/shared` barrel 全量 re-export `./components/index.js`（`packages/shared/src/index.ts:37`），`apps/server` import 该 barrel（`index.ts:9`），故 registry 已加载、resolver 已推入。

**冻结**：`card_writing` 帧的 `kind` 与 `title` **由服务端用 `parseFrontmatter` + `cardKindOf` 从 `args.content` 现算**，随帧下发。前端**只消费**，不得自行从文件名/frontmatter 推 kind（推不准）。

- **漏了会怎样**：前端把所有组件都当 `note` 画骨架 → 锁/门/板/卷轴全是便签形状，骨架与实际落地的卡不同形，过户时形状跳变（正是本批要消灭的观感）。

### 2.2 裁决 B：帧名 `card_writing`，**不叫** `component_writing`

- 帧名与事件 `type` 不共用命名空间（`docs/tools/12 §6.2` 顶部）。`card` 是本仓对"画布上一张卡"的统称（`cards` 表 / `card_position` / `POST /api/card/*`），而 `component` 仅指 19 个注册 kind 中的一个子集（`doc-10`）。帧承载的是"一张卡正在被写"，用 `card_writing` 词根一致。
- 与既有 `chalk_writing` / `chalk_landed` 构成同形族，读起来即知道关系。
- **落地帧不新增**：`write` 的 `tool_execution_end` **已经**广播 `chalk_landed`（`event-bridge.ts:182-192`：`event.toolName === 'chalk' || event.toolName === 'write'`）。本条复用该帧作过户信号，**不改名**（改名要动 `event-bridge` + `useWorld` + 2 处测试 + 门禁，收益为零；`chalk_landed` 的词根债登记在 §7）。

### 2.3 裁决 C：骨架的**形状来源** = `CARD_FORMS.chrome` 分档，**不是**逐 kind 手绘

- 骨架必须"与落定卡同形"。同形的唯一真相源是 `CARD_FORMS`（`forms.ts:70-105`）与它声明的 `chrome` 轴（`bare` / `paper` / `cover` / `note` / `slab` / `board` / `panel` / `scroll`）。
- **骨架是"形状提示"，不是"内容占位"**：它只呈现该 chrome 的**材质语汇**（纸张=纸边+短线组、石板=内阴影+方框、板=格纹、面板=单色块、卷轴=双横边、封面=顶部色带），**绝不呈现正文字符**。
- 分档表（`04` 篇逐条展开，此处冻结映射）：

| `chrome` | 骨架形态 | 覆盖的 kind（`CARD_FORMS` 行） |
|---|---|---|
| `paper` | 纸片 + 3–4 条长短不一的灰线（"信纸"） | `default` / `letter` / `book` / `ledger` / `photo` / `cipher` / `diary` / `thread` |
| `note` | 便签 + 横格 + 回形针 | `note` |
| `slab` | 内阴影石块 + 中央方框 | `lock` / `container` / `trap` / `mechanism` / `anchor` |
| `board` | 深奶油 + 80px 格纹 | `instrument` / `board` |
| `panel` | 浅墨洗 + 等宽条 | `clock` / `tape` |
| `scroll` | 双横边长纸 | `map` |
| `cover` | 纸面 + 顶部材质色带 + 序号印章 | `gate` |
| `bare` | **不出骨架**（`chalk` 走湿墨 / `sprite` 走在场感 / `portrait` 走 room pack） | `chalk` / `sprite` / `portrait` |

- **`bare` 的例外说明**：`portrait`（微动立绘）虽然 `chrome:'bare'`，但它是 room pack 的 `component: portrait`，**有明确生成期**（`generate_image` 或 motion）。本批**不覆盖**它（它走 `image` 车道，`03` 已实现）；§7 登记为待确认。

- **漏了会怎样**：逐 kind 手绘 19 套骨架 → 与 `CARD_FORMS` 形成第二份尺寸/形状表，正是 `AGENTS §7.5` 第 7 条明禁的"第三处现算 `cardFormOf`"。按 chrome 分档则新增 kind 自动获得骨架，零维护。

### 2.4 裁决 D：**不做真数据流式**（本批范围划死）

- 技术可行性已探明：pi-rp 的 `toolcall_delta` 对 `write` 同样流式（`write` 参数形状 `{path, content}` 与 `chalk` 逐字相同，`vendor/pi-rp/packages/coding-agent/src/core/tools/write.ts:15-18`），`chalk-delta.ts::extractContentPrefix` 可直接复用。
- **但不做**，两条硬理由：
  1. **frontmatter 边界脏**：组件卡正文前有 YAML 块（`---` 包裹）。流式途中会渲染出半个 `---`、半个 `title:`，穿过"卡面正文"的 CSS。chalk 是纯散文，没有这个问题。
  2. **组件卡生成不是长任务**：`write` 是**一次性**调用（`write.ts` 的 `guidelines: ["Use write only for new files or complete rewrites."]`），参数 JSON 在百毫秒级完成，不像 `generate_image` 有十几秒的 `generating` 心跳。"流式"的窗口太短，观感收益接近零，而 frontmatter 处理成本是实打实的。
- **登记为"将来的可选升级"**：若日后要，走"延迟确认 + 剥 frontmatter 后追字"（同 `perform/00 §3.2`），**不在本批**。

### 2.5 裁决 E：窗口从 `tool_execution_start` 到 `tool_execution_end`

**时序事实**（已核验）：
- `tool_execution_start`（带完整 `args`）→ `tool_execution_end`（带 `result`）。二者之间就是 `write` 的实际执行时间（落盘），实测 `fs.watch` 在写后 ~16ms 触发（本地 spike），即**窗口通常是几十毫秒级**。
- **这意味着骨架屏多数时候是"一闪"**——除非作家一次 `write` 大文件，或磁盘慢。

**冻结**：
- 骨架**不设最短展示时长**（不做 `min-dwell`）：编造停留会拖慢节奏，且与"内容先落、DOM 才是投影"（`perform/00 §5`）冲突。
- 骨架**在落地帧到达后不得再出现新内容**；DOM 节点的真正删除由 `reconcileLanded`（`phantom.ts:~185`，由 `fetchLayer` 触发）完成——`land` 只改相位到 `landed`、**不删节点**。
  - **勘误（`03` 冲突 1 抓到，2026-09-13）**：初稿写"必须在落地帧到达时立即撤离"是**歧义**——字面读会让人在 `land` 时就 `null` 掉节点，从而在"真卡尚未进入 `items`"的窗口留出**座位空洞**。准确语义 = **停住内容，等 `reconcileLanded` 删**（`03 §4.1` 的"`landed` 停住"）。
- **诚实标注**：本批的主要价值是**正确性**（生成中的卡不再"凭空出现"，而是有位置预告），**不是**"更长的演出"。若评审认为"一闪的骨架无价值"，则本批退化为"仅正确性补丁"——**请评审对此拍板**（§8 未知 1）。
- 若作家一次写多张卡（`write` × N），每张各一条 `card_writing`，各自独立骨架（`toolCallId` 区分）。

> **F-4（实测，见附录）：§2.5 初稿的"几十毫秒"是错的**——因 `land` 后节点停住不删，真实可见窗口 ≈ **230ms+**。§8 未知 1 的前提据此修正。

## 3. 冻结形状

### 3.1 新帧 `card_writing`

```ts
{
  type: 'card_writing',
  source: 'writer' | 'character' | 'functional',  // 见附 F-5/F-6：值域已扩；主路径为 'writer'
  toolCallId: string,               // 过户键，与 chalk_landed.toolCallId 对齐
  kind: string,                     // cardKindOf 的返回值（如 'letter' | 'lock' | 'map'）
  title: string,                    // = entityName(fm, path)：title → name → basename 去 .md（**裁决 J**）
  layer: string,                    // 目标层 id（world/<...> 或 characters/<id>）
  timestamp: string,
}
```

- **不加 `path`**：`tool_execution_start` 的 `args.path` 是**请求**路径；最终路径可能被工具规范化。过户以 `land` 的 `path` 为准（同 `chalk_writing` 的既有纪律：`perform/00 §6b-1`）。
- 但 `layer` **必须**随帧下发：前端排座与过滤都需要它（`phantomSeatFor(size, layer)` 与 `ghostVisibleOn(entry.layer, currentLayer)`）。**推出方式见附 F-2**（`layerOfDir(dirOf(args.path))` 纯函数；**不是** §3.1 初稿误写的 `layerOfPath`——后者需要 layers 记录且对 nook 路径判错）。

### 3.2 `phantom.ts` 的第三 kind

```ts
export type PhantomKind = 'chalk' | 'image' | 'component';
```

- `PhantomEntry` 加两个**可选**字段（不改既有字段语义）：
  ```ts
  /** component 车道：骨架形状档（来自服务端 card_writing.kind）。 */
  cardKind?: string;
  /** component 车道：可选标题占位（来自 card_writing.title）。 */
  cardTitle?: string;
  ```
- `PhantomInit` 同步加 `cardKind?` / `cardTitle?`。
- `register` 的幂等合并（`phantom.ts:91-118`）**必须**一并处理这两个新字段（同 `label`/`elapsedMs` 的写法）。
- **`phase` 值域不变**：`'pending' | 'writing' | 'landed' | 'evicted'`（`perform/00 §8.1`）。component 车道的映射：注册 `'pending'`（骨架）→ `land` 后 `'landed'` → `evict` 后 `'evicted'`。**`'writing'` 档仍归 chalk**（与 image 车道同处理）。

### 3.3 座位

- **唯一 seater**：`phantomSeatFor({ w, h }, layer)`（`phantom-seat.ts:42`）。`{w,h}` 从 `CARD_FORMS[kind]` 取（**与真卡同形**，这是"过户不跳位"的前提）。
- **`occupied` 自动包含本车道幻影**：`phantomSeatFor` 已把"同层全部未撤离幻影"计入障碍（`phantom-seat.ts:55-62`），第三 kind 天然被覆盖，无需改函数。
- **不特判 `SEAT_ANCHOR`**（`layout/02 §8.5`）。
- `flowColumns` 落地后（layout 批在途），本车道**零改动**继续可用（因为只调 seater，不自算）。

### 3.4 落地过户

- 服务端 `write` 的 `tool_execution_end` 已发 `chalk_landed { source, toolCallId, path? }`（`event-bridge.ts:182-192`）。
- 前端 `case 'chalk_landed'`（`useWorld.ts:468-474`）现调 `landPhantom(toolCallId, {path})`。
- **复用同一入口**：component 幻影的 `land` 走完全相同的路径（`phantom.ts:153` 的 `land`，未知 id 静默返回，与 image 车道同）。**不新增过户函数。**
- `file_changed` → `fetchLayer` 落地真实卡后，`reconcileLanded(realPaths)` 撤离幻影（既有，`phantom.ts:181+`）。

### 3.5 渲染接缝

- `PhantomLayer`（`components/canvas/PhantomLayer.tsx`）是**唯一挂点**（`perform/00 §5` 裁决 E）。当前分支：`p.kind === 'image' ? <GhostCard/> : <ChalkMark/>`。
- **本批加第三分支**：`p.kind === 'component' ? <CardSkeleton/> : …`。
- `CardSkeleton` 是**新组件**（`03` 篇定义，`03 §2.1`），放在 `components/narrative/`（与 `GhostCard` 同族）。
- 壳仍走 `.object--ghost`（`pointer-events:none`，不可点不可拖，`doc-10 E3`）。

### 3.6 冻结裁决 F：`chrome:'bare'` 的 kind **前端不注册幻影**

**问题**（`01` 冲突 3 / `02` 冲突 9，两端已 IRC 对齐）：服务端对任何 `write` **零过滤**发帧，故 `card_writing.kind` 可能为 `'chalk'`（`write` 一个 `type: chalk` 文件——scene-init 的开场段正是如此，`extensions/instructions.ts:230`）。若前端无条件 `registerPhantom`，`phantomSeatFor` 会把它计入 `occupied`（`phantom-seat.ts:55-62`）→ **挤走真卡座位**。

**冻结**：
1. **服务端零过滤**（保持 `mapEngineEvent` 是纯映射，不依赖渲染策略——裁决 A 的同一条原则）。
2. **前端在 `registerPhantom` 之前挡**：`const form = CARD_FORMS[kind]; if (!form || form.chrome === 'bare') break;`（`CARD_FORMS` 前端可达：`useWorld.ts:11` import `@airp/shared/forms`）。`chrome:'bare'` = `chalk` / `sprite` / `portrait`（`forms.ts:66,68,99`）。
3. **理由**：`bare` 是无卡面形态（`forms.ts:10-16`："a stroke of ink… no card surface"）。chalk 有**自己的**湿墨车道（`chalk_writing`，只认 `toolName==='chalk'`）；sprite/portrait 走在场感 / image 车道。给它们出"骨架"既无形可依，又会占座。
4. **漏了会怎样**：`.object--ghost` 以 `CARD_FORMS.chalk` 的 460×190 占一个真卡座位 → 其下的真卡被 `flowColumns` 挤到别处 → 落定后跳动。

### 3.7 冻结裁决 G：component 幻影**必须有撤离的 drop 路径**

**问题**（`02` 冲突 5 / 已由 `03` 接受修复）：既有 `PhantomLayer` 的 evict 定时器**只对 `p.kind === 'image'`** 生效（`PhantomLayer.tsx:51` `if (p.kind !== 'image') continue;`），即 component 幻影若 `evict` 后**永不 `drop`**，注册表不排空（违反 ``docs/perform/03-生图幻影与过户.md` §10.3「验收判据」第 1 行（`getPhantomsSnapshot()` 最终为空）` 的"最终为空"判据）。

**冻结**：
1. `PhantomLayer` 的 evict-drop 分支扩到 component 车道，用**独立常量** `SKELETON_EVICT_MS = 320`（与 chalk 的 320ms 淡出同节奏；**不复用** image 的 `EVICT_FADE_MS=700`，因为骨架更轻）。
2. **失败撤离归前端**：`write` 失败的 `tool_end{isError}` 已在 `useWorld.ts:414-415` 就近 `evict`（既有机制）；本批服务端不改（`§1` 不做清单）。

### 3.8 冻结裁决 K：**行数是 `02` 的唯一真相**，`03` 只管材质语汇

**问题**（评审 `RVConsistency` 阻断项 B1）：`02`（`skeletonShapeFor` 的唯一定义方）给了 `LINES_BAND` 逐档区间与推导公式；`03`（渲染方）却在 §5.2/§5.6/§5.7/§5.8 各写了**另一套固定行数**（panel 4 条 / scroll 2 条 / cover 3 条 / paper 4 条），与 `02` 的 `panel [2,5]` / `scroll [0,0]` / `cover [2,4]` / `paper [3,4]` 冲突。同一 kind 两张形状表 = 本批 §2.3 明禁的"第二份形状表"。

**冻结**：
1. **`02` 的 `LINES_BAND` + 推导公式是行数的唯一真相**（`skeletonShapeFor` 是唯一实现）。
2. **`03` MUST NOT** 在文档里写任何固定行数；`03` 只描述**每档的材质/装饰语汇**（纸边 / 内阴影 / 格纹 / 色带 …），行数一律表述为"由 `02` 的 `skeletonShapeFor` 决定"。
3. `03` 里"线：N 条"的表述 MUST 删除或改为引用 `02`。

## 附：主 agent 实测复核（2026-09-13，设计期）

### F-1 多卡并发的 `tool_execution_start` **严格串行**（**读码实测，非推断**）

**问题**（原 §8 未知 4）：作家一轮写 3 张卡时，3 个骨架会不会重叠？

**事实**：
- pi-rp 有两条工具执行路径，**默认是 `parallel`**（`vendor/pi-rp/packages/agent/src/agent.ts:237`：`runtimeOptions.toolExecution ?? "parallel"`；AIRP 未设该值，故生效默认）。
- 但**两条路径都在 for 循环内 `await emit(tool_execution_start)`**：
  - 串行路径：`vendor/pi-rp/packages/agent/src/agent-loop.ts:386-392`；
  - 并行路径：`vendor/pi-rp/packages/agent/src/agent-loop.ts:499-505`（`Promise.all` 在 `:535`，**只并行"执行体"，不并行 `start` 的 emit**）。
- 故 `tool_execution_start` 按 `assistantMessage.content` 顺序**逐个 emit**，前一个 start 完全返回后才有下一个。

**后果（`02` 必读）**：
1. 骨架注册**严格有序** → 每个 `phantomSeatFor` 调用时，前一个骨架**已在注册表里** → `occupied` 已含它 → **不重叠，无需"同批预占"机制**。原 §8 未知 4 的担忧**不成立，关闭**。
2. 但 `tool_execution_end`（= 落地帧 `chalk_landed`）顺序**可能交错**（并行路径由 `Promise.all` 完成序决定）。**过户不能假设"先 start 的先 land"**——每个骨架按自己的 `toolCallId` 独立过户即可（既有机制天然满足）。
3. **`02` MUST NOT** 为"同批骨架预占"新增任何机制（那是为不存在的问题造复杂度）。

### F-2 `layer` 可由纯函数推出，**无需给 `mapEngineEvent` 传 layers**（**读码 + 实测，非推断**）

**问题**（`01` 篇最难决策）：`mapEngineEvent` 是纯映射函数，**拿不到 layers 记录**；`card_writing` 的 `layer` 从哪来？

**事实**：
- `write` 收到的 `args.path` 是**世界根相对路径**（实测：探针剧本 `tools/probe-provider.ts:19` = `'world/baker-street/probe-chalk.md'`；`/api/layer` 的 `LayerItem.path` 同口径）。
- 层 id 的派生是**纯函数**，不需要 layers 记录：`layerOfDir(dirOf(p))` —— `dirOf`（`packages/shared/src/store/layers.ts:46-48`）取目录部分，`layerOfDir`（`layers.ts:37-39`）把 `world` 映回 `map`。
  - 实测：`layerOfDir(dirOf('world/baker-street/evening.md'))` = `'world/baker-street'` ✓；`dirOf('world/README.md')` = `'world'` → `'map'` ✓。
- 对比：`layerOfPath(path, layers)`（`layers.ts:130`）**需要** layers 记录（它做最长前缀匹配），但本用途（单文件 → 它所在层）不需要最长匹配——文件就在它目录所属的层里。

**冻结（对 `01` 的强制）**：
1. `card_writing.layer = layerOfDir(dirOf(args.path))`。**MUST NOT** 给 `mapEngineEvent` 新增 `layers` 形参（那是把纯函数污染成有状态依赖，且签名改动会波及探针与测试）。
2. **边界情形**：`args.path` 缺 `/`（如直接写 `world/x.md`）或位于非层路径（`player/` 等）→ `dirOf` 给 `''`/非层前缀 → `layerOfDir` 返回 `''`。此时 `layer` **省略该字段**，且**前端因此不注册幻影**（见附 F-10 裁决 O——**取代**原先"回退 `layerRef.current`"的写法）。
3. `characters/<id>/**` 的 nook 路径同理推出 `characters/<id>`（`layerOfDir` 是恒等映射，`dirOf` 已给对）。

**对 `02` 的影响**：前端 `case 'card_writing'` 读帧的 `layer`，**推不出合法层时直接不注册**（丢帧——见附 F-10 裁决 O；**勘误**：初稿写"回退 `layerRef.current`"是错的，那会让它错排进当前层并永挂）。`layer` 合法时才走 `phantomSeatFor`。

### F-3 **缺口**：组件卡也可能走 `edit`，本批只覆盖 `write`（**读码发现，非推断**）

**事实**：
- 作家指令原文（`extensions/instructions.ts:84`）：`Look up the kind's contract with get_component before you author a new one, and create or rewrite it with **write or edit**.` —— 即组件卡**新建用 `write`，改写用 `edit`**。
- 但落地帧只认 `chalk || write`（`apps/server/src/engine/event-bridge.ts:182`：`if (event.toolName === 'chalk' || event.toolName === 'write')`）——**`edit` 既无 writing 帧、也无 landed 帧**。
- 初始化器（`scene-init`）走 `write`（`extensions/instructions.ts:230`），无此问题。

**为什么这不是"漏了"，而是需要**裁决**：`write` 与 `edit` 的语义不同——
- `write` **新建**一张卡：卡在 `items` 里**还不存在** → 骨架是"预告一个将出现的东西"，正是本批的价值。
- `edit` **改写**一张已有的卡：卡**已经在画布上** → 若也出骨架，它会**盖在真卡上**，语义变成"这张卡正在被改"。这是**另一个演出**（"改"而非"生成"），观感与实现都不同。

**本批冻结立场（待评审确认，见 §8 未知 5）**：
1. **本批只覆盖 `write`（新建）**。`card_writing` 的触发条件 = `toolName === 'write'`（且 `source === 'writer'`）。
2. `edit` 的改写演出**不在本批**——它需要"已有卡上的进行态"（可能就是 `doc-10 E3` 说的另一种形态），**登记为后续**。
3. **`01` MUST NOT** 把 `card_writing` 的触发条件写成 `chalk || write` 式的宽松集合；**MUST** 精确到 `write`。
4. **`01` MUST** 在文档里显式声明这条缺口（`edit` 改写无演出），**不许静默**——否则读代码的人会以为"组件演出已全覆盖"。
### F-4 §2.5 的「几十毫秒」是错的：真实可见窗口 ≈ **230ms+**（**实测，2026-09-13**）

**实测数据**（真 server + 真 `LocalWorldStore`，world=`templates/wuwu`）：

| 环节 | 实测 |
|---|---|
| `write` 落盘（`fs.writeFileSync` 一张 letter 卡） | **0.42 ms** |
| `fs.watch` 触发 | **~16 ms**（本地 spike） |
| 服务端 `WATCH_DEBOUNCE_MS` | **150 ms**（`apps/server/src/engine/event-bridge.ts:13`） |
| `/api/layer` 往返 | **64 ms**（实测 `/api/layer?layer=map`） |

**结论（修正 §2.5）**：骨架的**可见窗口 ≠ `write` 的执行时间**。因为 `land` 只改相位到 `landed`、**节点停住不删**（§2.5 勘误），真正删除要等整条链：

```
write 落盘(0.4ms) → fs.watch(16ms) → 服务端 debounce(150ms) → 广播 file_changed
  → 前端 fetchLayer(/api/layer ≈64ms) → reconcileLanded 删骨架
≈ 230ms+（不含网络与 React 提交）
```

**这意味着 §8 未知 1 的前提变了**：骨架**不是"一闪"**，而是有 **~200–400ms 的稳定可见窗口**（还不含作家真实 `write` 前 LLM 生成工具调用参数的时间）。**故"值不值得做"的答案倾向"值得"**——请评审**据此**重新判断（原判断基于错误的"几十毫秒"）。

### F-7 **致命竞态**：失败的 `write` 会覆盖 `evict`，骨架永挂（**评审 `RVAdversarial` B1 抓到，已读码确认 2026-09-13**）

**事实链**（全部读码核实）：
1. 服务端同一次 `tool_execution_end` 里**先** push `tool_end`（含 `isError`）、**再**无条件 push `chalk_landed`（`event-bridge.ts:219-255`：`if (event.toolName === 'chalk' || event.toolName === 'write')`，**不判 `isError`**）；两者入同一 `out` 数组、**同序 broadcast**。
2. 前端按序处理：`tool_end{isError}` → `evictPhantom(id)` → `phase='evicted'`（`useWorld.ts:414-421`）；随后 `chalk_landed` → `landPhantom(id,{path})` → **`land()` 无相位守卫**（`phantom.ts:153-161`），直接 `entry.phase = 'landed'` **覆盖 `evicted`**。
3. 故 `PhantomLayer` 的 evicted-drop 分支（裁决 G）**永不触发**；失败的 `write` 不产文件 → `reconcileLanded(new Set(items.paths))` 也**不命中**（`useWorld.ts:174`）→ **骨架永久留在座位**。

**冻结（裁决 L）**：`phantom.ts::land()` **MUST 加相位守卫**：`if (entry.phase === 'evicted') return;`（一行，最小改动，**不动任何其他语义**）。
- **理由**：`evict` 是"这个东西失败了/已被接管"的终局信号（`phantom.ts:163` 注释"Idempotent"），`land` 是"内容到了"。**终局后到达的 `land` 必须被忽略**——否则晚到的 `land` 复活一个已被判死的幻影。
- **对既有 chalk / image 车道的影响**：**无**（chalk 的正常路径 `land` 先于任何 `evict`；仅"失败后又来 `chalk_landed`"这条竞态被修掉，而那本就是泄漏）。
- **MUST** 在 `apps/web/test/` 加断言：`register → evict → land` 后 `phase` 仍为 `'evicted'`（**非空性用例**：不加守卫则变 `'landed'`）。
- **`02` 篇 MUST** 把这条写进 `phantom.ts` 改动清单（与第三 kind 同批）。

### F-8 **前提**：`card_writing` 的过户要求目标文件最终**进 `items`**；`README.md`（kind=`gate`）永不进 `items`（**评审 `RVAdversarial` B3，已读码确认**）

**事实**：`resolveComponentKind` 对 `filename === 'README.md'` 直接 `return 'gate'`（`packages/shared/src/components/registry.ts:77`；无 registry 时 `forms.ts:120` 同），chrome=`'cover'`。但 README **永不进 `items`**：`cardsOfLayer` 排除本层 README（`packages/shared/src/store/layers.ts:106-114`）；其消费处注释逐字 "This layer's own files, **minus its README**"（`packages/shared/src/render/layer-page.ts:144-147`）；look-at 只把 README 作 doors/backdrop（`packages/shared/src/actions/look-at.ts:282-284`）。`reconcileLanded` 的输入是 `items.paths` → **README 路径永不命中** → 骨架永挂（与 F-7 同类泄漏）。scene-init 第 1 步正是先写 `README.md`。

**冻结（裁决 M）**：
1. 前端 `case 'card_writing'` 的守卫**扩到 `kind === 'gate'`**（与 `chrome === 'bare'` 同一守卫位）：`if (form.chrome === 'bare' || kind === 'gate') break;`。
2. **漏了会怎样**：写 README 时注册一个永不被 `reconcileLanded` 移除的 cover 骨架 → 永久污染画布。
3. `02` MUST 在文档写明这条守卫，并给断言。

### F-9 **偏差（登记）**：`write` **覆盖既有卡**时，骨架会在**另一个座位**（**评审 `RVAdversarial` B4，已读码确认**）

**事实**：`write` 的 guidelines 是 `"Use write only for new files or complete rewrites."`（`vendor/pi-rp/packages/coding-agent/src/core/tools/write.ts:19`）——即 `write` **可完整重写既有文件**。此时卡已在 `items`、已在真实座位。`phantomSeatFor` 把该真卡当**障碍**（`phantom-seat.ts:47-56`）→ 骨架被排到**另一个座位** → 窗口内是**虚假的双卡**（旧真卡 + 多余骨架），最终 `reconcileLanded` 按 path 删骨架。

**冻结（裁决 N）**：**本期不改，登记为已知偏差**。理由：①`card_writing` 帧**故意不带 `path`**（§3.1），前端判不了"这是覆盖"；②修它要给帧加 `replace?: true` 字段（服务端在 `start` 时查 `items` 或 stat 文件），属**范围扩张**；③窗口 ~230ms 内的双卡是**轻微**观感问题，不是泄漏。
- **`01` MUST** 登记这条偏差（同 F-3/F-6 的"不许静默"纪律）。
- **将来**若要修：`card_writing` 加 `replace?: boolean`（服务端在 `tool_execution_start` 时 `statKind(args.path)` 判存在），前端对 `replace===true` 跳过骨架或另演"改写中"。

### F-10 **一般化泄漏**：任何"登记了但路径永不进 `items`"的幻影都会永挂（**评审 `RVAdversarial` 反例 5，已读码确认**）

**事实**：`reconcileLanded` 只按 `entry.path ∈ items.paths` 删（`phantom.ts:185-195`）；`PhantomLayer` 的 evicted-drop（裁决 G）只处理"失败"路径。故**任何既非失败、又永不进 `items` 的 `write`**，其骨架都会永挂——F-8（README）只是最常见的一例，一般形式包括：
- `player/` 背包里的 `.md`（不在任何 `world/**` 层）；
- stub 层里的文件（`resolveLayer` 无 README 的层，被排除）；
- 非层目录下的 `.md`（`resolveLayer` 返回 null）。

**冻结（裁决 O）**：**前端注册幻影的前提 = "该 path 会进入某个 `items`"**。实现口径：
1. **`kind === 'gate'` 一律不注册**（F-8 裁决 M，已定）。
2. **`layer` 推不出或推为 `''` 时一律不注册**（F-2 的边界情形：`args.path` 无 `/`、或在 `player/` 等非层路径下——`layerOfDir` 返回 `''`）。**即 F-2 第 2 条的"缺省回退 `layerRef.current`"取消了**——回退到当前层会让它**错排进当前层的 items** 并永挂。
   - **勘误（覆盖 F-2 第 2 条）**：F-2 原写"缺 `layer` 时回退 `layerRef.current`，MUST NOT 丢整帧"——**改为：`layer` 推不出时直接不注册**（丢帧是对的，因为它没有归宿）。
3. **`02` MUST** 在文档里把守卫写成**白名单口径**（"能推出合法层 ∧ chrome≠bare ∧ kind≠gate 才注册"），而非黑名单。
4. **漏了会怎样**：注册表被永不 reconcile 的条目占据 → 违反 ``docs/perform/03-生图幻影与过户.md` §10.3「验收判据」第 1 行（`getPhantomsSnapshot()` 最终为空）` 的「`getPhantomsSnapshot()` 最终为空」；且 `phantomSeatFor` 的 `occupied` 把它们当障碍 → **后续真卡被挤走**。
