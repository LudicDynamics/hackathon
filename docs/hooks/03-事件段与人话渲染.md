## 1. 目标

把一段 `WorldEvent[]` 变成注入块里 `Recently, in the world` 节要印的那几行英文陈述句，并钉死两件事：

1. **渲染是纯函数、可单测、作家与角色共用**（`00` §6.1/§6.3）。全仓今天**没有**任何 per-event 人话渲染器（`packages/shared/src/schemas/events.ts` 只有 15 个 `detail` 形状，**没有**渲染函数；AUDIT §4.2 第 2 条）。这是 B2 **最大的新增件**。
2. **游标在轮边界结算，绝不在 `context` handler 里推进**（`00` §6.2）。`context` 每次 LLM 调用都触发（含工具循环内每一轮，`types.ts:758`；`runner.ts:1133`），在它里面推游标 = 一轮推 N 次 = 等价于没消费。

产出**不含**「下一步」段（`00` §8）——那是 **04** 的 `computeNextStep`；本篇只交出它的输入（§2.4）。

### 2.2 `render/events.ts`（**NEW**，本篇拥有）

```ts
import type { Actor } from '../actions/actor.js';            // 已存在：actions/actor.ts:7
import type { WorldEvent, WorldEventType } from '../schemas/events.js'; // 已存在：schemas/events.ts:9-25, :112-124
import { sanitiseForBlock } from './sanitise.js';            // 00 §14 的唯一消毒函数（本批新建，见 §3.1 第 4 条）

/** The raw read, owned by the injector (01). Declared HERE (not in inject/collect.ts)
 *  so the dependency is one-way: collect → render. The reverse would be a runtime cycle
 *  (collect imports the runtime `renderEventWindow`). */
export interface EventSlice {
  /** Chronological, oldest → newest. `getEventsSince` is ASC by seq (local-store.ts:427). */
  events: WorldEvent[];
  /** True when the reader had no cursor row and this is the layer "latest N" fallback (doc-21 §5.2). */
  coldStart: boolean;
}

/** One surviving line of the window. Superset of 04's `NextStepEvent`
 *  (04 re-exports `Pick<EventWindowLine, 'type' | 'layer' | 'name' | 'actor'>`; it declares no second shape). */
export interface EventWindowLine {
  /** Representative type of the (possibly merged) group. */
  type: WorldEventType;
  /** The group's layer. NON-NULL for layer_entered / layer_initialized / layer_init_failed
   *  (their events set both `layer` and `detail.layer`: actions/layer.ts:72-79, :118-125, :158-165). */
  layer: string | null;
  /** detail.name / detail.itemName when the type carries one; used by 04's triggers and by tests. */
  name?: string;
  /** The group's author (`g.events[0].actor`). 04 gates its interactive-tail case on
   *  `actor.type !== 'writer'` — the writer must never be told to answer its own action (A-12). */
  actor: Actor;
  /** 1 unless rule 1 merged N same-turn + same-type + same-actor events. */
  count: number;
  /** Grouping key for tests: `event.subject ?? detail.path ?? detail.to ?? null`. */
  subject: string | null;
  /** The rendered English sentence. Bare — no bullet, no indent, no trailing newline. */
  text: string;
}

export interface EventWindow {
  /** Merged + capped bare sentences, chronological. 02 prints them as `  - <line>`. Does NOT include `tail`. */
  lines: string[];
  /** `…and N more (older events omitted)`, WITHOUT indent/bullet; null when nothing was dropped.
   *  Split out from `lines` because 02 renders it at a different indent than the bullets. */
  tail: string | null;
  /** The surviving window after all four merges, chronological — the array 04 projects. */
  events: EventWindowLine[];
  /** = lines removed by the cap. */
  dropped: number;
  /** Events whose detail failed to render and fell back to a generic sentence (should be 0 in practice). */
  malformed: number;
}

/** The one entry point the injector memoises (01). Pure. Never throws.
 *  `layerNames` = `{ [layerId]: displayName }`, built ONCE at the turn boundary from
 *  `store.getManifest().layers` (01; same source as `presence.ts::readLayerName`) — it exists so
 *  `layerPhrase` can name a layer WITHOUT the renderer doing I/O (§3.3). */
export function renderEventWindow(
  slice: EventSlice,
  opts: { caps: number; actor: Actor; layerNames: Record<string, string> }
): EventWindow;

/** Single-event sentence. Exported for tests and for `04` if it ever needs one line.
 *  `opts` is required for the same reason as above (only `character_moved` consumes it). */
export function renderEvent(event: WorldEvent, opts: { layerNames: Record<string, string> }): string;

/** `world/<x>/y.md` → words a reader can act on. Pure string op — NO world I/O (doc-21 §3.3). */
export function pathPhrase(path: string): string;

/** A layer id → its human place name. Pure; `names` is the manifest map carried in `opts`.
 *  Same convention as `presence.ts:112 readLayerName` (manifest `layers[id].name`, else the last
 *  dir segment); `map` (the virtual root, `layers.ts:27`) has no dir segment → `the world map`. */
export function layerPhrase(layerId: string, names: Record<string, string>): string;

/** `'The player' | 'The narrator' | 'The world itself' | 'the character "<id>"' | 'The engine'`. */
export function actorPhrase(actor: Actor): string;
```

**四处与 Design01/Design02/Design04 对齐后的最终口径**：

1. **`role` 参数已删。** 渲染与"谁在读"无关——作家与角色的差别在**取哪些事件**（`excludeActor` / `layer` 过滤，`00` §6.1），不在**怎么说**。doc-21 §3.5 举例的"角色视角措辞不同"是历史面板级的多读者设想；注入侧只有作家/角色两个读者，且两者对同一条事件的陈述**逐字相同**。留一个用不上的 `role` 参数就是死参数，删掉。
2. **`tail` 与 `lines` 分开**（02 的 `dynamics` 外壳是 `  - <句>` 的列表 + 缩进不同的尾行 `  …and N more…`，必须可分离）。02 须**同步改它 §3.2 的示例与措辞**：尾句真源是 `EventWindow.tail`（本篇 §3.5 步骤 6 定稿 `…and N more (older events omitted)`），**不是**旧稿的 `the rest are on record`——02 §3.2 与 `00` §4.2 表的字面须回写（A-13）。
3. **`opts.layerNames` 是新入参**（A-17）：`renderEventWindow` / `renderEvent` 都收它，`layerPhrase` 消费它；来源是 01 轮边界建的 manifest 映射（§2.5）。**它不破坏 01/02/04 的既有调用**——只是多一个字段（01 的 `SectionDeps` 加字段、02 的调用点补传）。
4. **`actor: Actor` 在 `EventWindowLine` 上**（A-12）：04 的投影 `Pick<EventWindowLine, 'type'|'layer'|'name'|'actor'>` 依赖它；04 用 `actor.type !== 'writer'` 门控交互尾句。

## 3. 机制与理由

### 3.1 渲染总则（六条不可协商）

1. **每个 type 一个模板，`detail` 路径直读，绝不回读世界目录。** `detail` 自足是 doc-21 §3.3 的硬要求（文件可能已被再次移动/删除，回滚后同一路径指向别的版本；渲染在 hook 阶段做同步 I/O 会卡住 agent）。**所以 from/to 只能印 `pathPhrase(path)`，不能印"柜台"这种卡片显示名**——`entity_moved.detail` 只有被移动者自己的 `name`，没有源/目标卡的名字（`schemas/events.ts:51-58`）。要卡片名就得改 `detail` 加字段，**不在本批**。
2. **路径是"指路牌"，随句附上。** entity / character / interaction 系模板在句尾括注路径：角色读到它就能 `look_at` 取细节（doc-21 §5.2、`00` §7 两层原则）。路径用 `pathPhrase` 压缩（§3.3）。
3. **actor 决定主语，模板决定谓语**（doc-21 §3.2/§3.5）：

| `actor.type` | `actorPhrase(actor)` | 例句形态 |
|---|---|---|
| `player` | `The player` | `The player moved …` |
| `writer` | `The narrator` | `The narrator wrote a new page: …` |
| `god` | `The world itself` | `The world itself edited …`（doc-21 §3.2：上帝改动读作"世界自己变了一下"） |
| `character` | `the character "<actor.id>"` | `the character "watson" moved …` |
| `engine` | `The engine` | 多数 engine 事件的模板自带主语，不需要它 |

4. **动态文本过 `sanitiseForBlock`（`00` §14）**。事件 `detail.name` / `detail.path` / `detail.itemName` / `detail.targetName` / `detail.choice` / `detail.desc` / `detail.near` 间接来自世界文件或**无鉴权的 `POST /api/god-action`**（`routes/world.ts:669-720`），是注入通道。`renderEventWindow` 拿到 `slice` 后**先把这些字段逐个过 `sanitiseForBlock(raw, { maxLength: 120 })`**（`title`/`name` 档），再喂模板；最终句子再整体过一遍 `maxLength: 300` 兜底。剥换行/控制字符是**最重要**的一条——否则 `detail.name` 里的 `\n` 能伪造一条注入结构。消毒在**渲染之前的投影步**做一次，不进 `renderEvent` 的纯模板（纯模板只吃已消毒值，保证逐字可断言）。
5. **层名来自 `opts.layerNames`，不查世界**。`character_moved.from/to` 是**层 id**（`move-to.ts:119-120` / `presence.ts:258-259`），须经 `layerPhrase(id, opts.layerNames)` 映成地名（§3.3）。
6. **主语由 `actor` 决定，不是硬编码**。交互三模板（`choice_selected` / `roll_resolved` / `use_item_on`）与 `character_talked` 主语**必须**用 `${S}`——它们可被 writer / god 触发（`extensions/tools.ts:55` 注册的 `roll_dice` 是作家工具；`/api/dice` 强制时 actor=`god`，`routes/world.ts:551`），硬编码 "The player" 会把作家自己的动作读成玩家做的（A-12）。`character_moved` / `following_changed` 是**例外**：主语是被移动/跟随的角色名本身（见 §3.2.2），与 actor 无关。

> **为什么 `character` 只有 id 没有显示名**：`Actor` 只有 `{ type, id }`（`actions/actor.ts:7-11`），`detail` 里也没有发起者的显示名（`detail.name` 是**被作用对象**的名字，不是 actor 的）。渲染器禁止 I/O，所以只能用 id。id 是稳定标识（`characters/<id>/`），可接受；想印显示名要先把名字写进 `detail`——**不在本批**。

### 3.2 十五个类型的渲染表

`S` = `actorPhrase(event.actor)`；`P` = `pathPhrase(...)`；`L(id)` = `layerPhrase(id, opts.layerNames)`。所有句子**单行、英文、无 emoji、无 markdown 强调**。detail 字段名一律照抄 `packages/shared/src/schemas/events.ts:42-109`（= doc-21 §4），写入侧真实形状已逐条核对（`packages/shared/src/actions/*` 各 `appendEvent` 调用点）；凡 `${name}` / `${choice}` / … 处一律喂 **§3.1 第 4 条消毒后**的值。

**缺字段兜底（机械可断言）**：`renderEvent` 是**不抛**的纯函数，每个模板对缺失字段有确定行为：`detail.name` 缺失 → 退回 `pathPhrase(detail.path)`（§7 #8）；`detail.summary` 缺失 → 模板本就不用它；**枚举内**类型的**其它**契约字段缺失（如 `entity_moved` 少了 `to`）→ 视为写入侧 bug，落到 §3.5.2 的通用兜底句并计 `malformed`。**不**用 `undefined` 字面量拼进句子（会印出 `moved "undefined"`）。

#### 3.2.1 文件与物件（detail 见 `:43-58`）

| type | detail 路径 | 模板 | 例句 |
|---|---|---|---|
| `entity_created` | `path,name,kind,summary?` | kind 分支：`chalk` → ``${S} wrote a new page: "${name}" (${P}).``；`component` → ``${S} placed a prop: "${name}" (${P}).``；`letter` → ``${S} left a letter: "${name}" (${P}).``；`note` → ``${S} left a note: "${name}" (${P}).``；`other` → ``${S} created "${name}" (${P}).`` | `The narrator wrote a new page: "The Counter" (world/baker-street/02-counter.md).` |
| `entity_edited` | `path,name,kind` | kind 分支：`chalk` → ``${S} revised "${name}" (${P}).``；其余 → ``${S} edited "${name}" (${P}).`` | `The narrator revised "A Rainy Night" (world/baker-street/01-rainy-night.md).` |
| `entity_deleted` | `path,name` | ``${S} deleted "${name}" (${P}).`` | `The player deleted "copper-key" (the player's bag).` |
| `entity_moved` | `from,to,name,near?,rewrote,dangling` | ``${S} moved "${name}" from ${P(from)} into ${P(to)}.`` + `near` 时 `` They are now ${near}.`` + `dangling>0` 时补 `` `${dangling} reference(s) elsewhere now point at nothing.` `` | `The player moved "copper-key" from world/baker-street/copper-key.md into the player's bag.` |

- `entity_created` 的 `summary?` **不进句**（那是 `look_at` 的活；注入只报"有这么个东西"，`00` §7）。`kind` 字段是**写入时的**枚举（`schemas/events.ts:46` 含 `letter`），渲染器对它做闭集 `switch`，未知值退到 `other` 模板——**不抛**。
- `entity_edited.kind` 是**开集 `z.string()`**（`:49`），所以模板只对 `chalk` 特判；`chalk.ts:515` 显式写 `kind: 'chalk'`，`delete.ts:186` 写 `eventKind`。它**不参与** kind 分支之外的语义。
- `entity_moved` 的 `from → to`：`player/` 前缀的目标读作 "their bag"，其余读作目的地路径。为保持纯函数与可断言，**只做路径措辞不查世界**：`pathPhrase('player/x.md')` → `the player's bag`（§3.3）。`rewrote` 是引用重写**条数**（`move.ts:197` 传 `rewrote.length`），**不渲染**（叙事无价值，历史面板才有）；`dangling` 有条数时补一句（doc-21 §4.1 要求）。
- `dangling > 0` 时补一句。`dangling` 是 doc-05 §8.3 断链兜底态的作家侧对应（doc-21 §4.1 要求）。措辞**固定**为 `` `${dangling} reference(s) elsewhere now point at nothing.` ``（列数、可断言、可测）——不写"有些地方提到它的现在指不着了"这种不可测的自然语言变体。

#### 3.2.2 角色与在场（detail 见 `:59-71`）

| type | detail 路径 | 模板 | 例句 |
|---|---|---|---|
| `character_moved` | `character,name,from?,to,near?` | 有 `from`：``${name} moved from "${L(from)}" into "${L(to)}".`` + `near` 时 `` They are now ${near}.``；无 `from`（同层重摆）：``${name} shifted position in "${L(to)}".`` + `near` 时同上。 | `Watson moved from "Baker Street" into "Abandoned Orchard".` |
| `following_changed` | `character,name,following` | `following` 真 → ``${name} started following the player.``；假 → ``${name} stopped following the player.`` | `Watson started following the player.` |
| `character_talked` | `character,name,turns` | ``${S} spoke with ${name} (${turns} exchange${turns===1?'':'s'}).`` | `The player spoke with Watson (3 exchanges).` |

- **`character_moved` 主语是被移动的角色本身**（`detail.name`，`move-to.ts:118`），不是 actor。`presence.ts:249-261` 由 engine 落跟随移动时也一样。所以模板**不用 `S`**——用 `name` 直呼，符合叙事（"老周走到壁炉边去了"，doc-21 §4.2）。
- **`from`/`to` 是层 id，不是地名**（A-17，已核）：`move-to.ts:119-120` 写 `from: current.layer` / `to: dest.layer`，`presence.ts:258-259` 同理——两者都是 `'world/baker-street'` / `'map'` 这种 **id**（`layers.ts:32-39` 的 `dirOfLayer` 口径）。直接印 id 会出 `into world/garden` 与退化的 `into map`。所以模板必须过 `L(id)` = `layerPhrase(id, opts.layerNames)`（§3.3）；`layerNames` 由 01 在轮边界建（§2.5）。**这与 §3.1 第 1 条不冲突**：层名不是"卡片显示名"，manifest 的 `layers[id].name` 是层的**自有**称谓，且经 `opts` 传入、渲染器不 I/O。
- `character_talked` 只记发生过、不记内容（doc-21 §4.2）：`turns` 来自 `talk.ts:75`，前端今天没有计数器（`index.ts:146-150` 注释：缺计数则传估算 `1`）。渲染**不区分实测/估算**——那是 `details.turnsEstimated` 的事，注入不需要。
- `following_changed` 的 `following` 是**布尔**（`presence.ts:289`），不是 toggled 语义。

### 3.3 `pathPhrase(path)` —— 纯字符串，绝不 `stat`

**背景（已核）**：`render/spatial.ts::dirPhrase` 要 `Box`（`spatial.ts:42`）；`render/layer-page.ts::basenameOf`（`:112`）只取 basename。**没有任何现成函数**能把一个世界根相对路径变成"哪一层/谁的背包"。本批新写一个**纯字符串**函数（不读世界、不 `stat`——`doc-21` §3.3 禁止渲染期 I/O；唯一 `stat` 是 `local-store.ts:163 statKind`，那是 store 方法，渲染器不调）。

```ts
/** Pure. `path` is world-root relative, POSIX. Never stats, never reads. */
// NEW render/events.ts
export function pathPhrase(path: string): string;
```

规则（按序，先命中先返回）：

| 前缀 | 输出 | 例 |
|---|---|---|
| `player/` | `the player's bag` | `player/copper-key.md` → `the player's bag` |
| `characters/<id>/` | `the character "<id>"` | `characters/watson/README.md` → `the character "watson"` |
| `world/<layer>/…` | `<layer>` 路径原样（**保留全路径**，因为它是指路牌） | `world/baker-street/x.md` → `world/baker-street/x.md` |
| 其余（`world.json`、未知前缀） | 原样 | `world.json` → `world.json` |

> **为什么不压缩 `world/<layer>/x.md` 成 `x.md in "Baker Street"`**：注入块要的是**可 `look_at` 的稳定 id**（`00` §3.1 `items` 用世界根相对路径）。压成自然语言会**丢掉 id**，角色想 `look_at` 还得反推。规则 1/2 之所以例外，是因为 `player/` 与 `characters/` 不在层树里（`world-store.ts:76-79` 明文：`resolveLayer` 对它们返回 `null`），印路径反而是噪音。**层名不查世界**（查了就是 I/O）；`world/<layer>` 的 `<layer>` 就是 id 本身。

#### 3.3.1 `layerPhrase(layerId, names)` —— 层 id → 地名（**纯，无 I/O**）

`character_moved.from/to` 与 `layer_entered/initialized/init_failed.layer` 都是 **层 id**（`'world/baker-street'` / `'map'`）。`pathPhrase` **不处理它们**（它吃的是文件路径，不是层 id）；`layer_entered` 的例句把 `${P(layer)}` 印成 `(world/orchard)` 是对的——那是**指路牌 id**，与文件路径同一格式。但 `character_moved` 的模板要**地名**（"从贝克街走进果园"），故需第二个纯函数：

```ts
/** Pure. `names` = the manifest map carried in `opts.layerNames` (never re-read here). */
// NEW render/events.ts
export function layerPhrase(layerId: string, names: Record<string, string>): string;
```

规则（按序）：

| 输入 | 输出 |
|---|---|
| `names[layerId]` 非空 | 该显示名（`templates/holmes-world/world/baker-street/README.md` 的 `name: Baker Street` → `Baker Street`） |
| `layerId === 'map'`（虚拟根，`layers.ts:27`） | `the world map`（`map` 没有目录段，`dirOfLayer('map')` 返回 `world/`，末段是空——不能印 `""` 也不能印裸 `map`） |
| 其余未知 / 无 manifest 条目 | `layerId` 的末段目录名（`world/baker-street` → `baker-street`），与 `presence.ts:112-121 readLayerName` 的回落**逐字同口径** |

> **口径一致性的机械核验**：`presence.ts::readLayerName` 的 manifest 键是 `layers[layer]?.name`（`presence.ts:114`，`local-store.ts:286 getManifest`），与本函数第一个分支同源。实现单测须断言：对 holmes 模板的每个层，`layerPhrase(id, names) === readLayerName(store, id)`（除 `map` 一个人话特例，两者都已在 `readLayerName` 的 `MAP_LAYER` 分支对齐，`presence.ts:119`）。**消毒**：`names` 的值来自世界文件（`00` §14.2 已列"层 README 的 `name` → 必须消毒"），所以 `layerPhrase` 的输出进入句子前在 §3.1 第 4 条的投影步已被 `sanitiseForBlock` 洗过——本函数只负责取词，不重复消毒。

### 3.4 §5.4 四种合并（固定顺序，`00` §6.3）

doc-21 §5.4 的四条**必须按序**执行，因为后一条的输入是前一条的输出：

1. **同 `turn` + 同 `type` + 同 `actor` → 合并计数**；
2. **同 `subject` 的连续 `entity_edited` → 只留最后一条**；
3. **`entity_created` 后紧跟同 `subject` 的 `entity_moved` → 只说最终落点**（**注**：字面"同 subject"落地为 `created.detail.path === moved.detail.from`，见 §3.5 步骤 5 的理由）；

### 3.5 合并算法（逐步，可直接照写）

输入：`events`（**已按 seq 升序**，`getEventsSince` ASC，`local-store.ts:427`）、`caps`（默认 12）、`actor`、`layerNames`。输出：`EventWindow`。**纯函数、无 I/O、无时钟、不抛**。记 `opts = { caps, actor, layerNames }`。

```
0.  SANITISE（§3.1 第 4 条）
    window = events.map(e => e.detail 的 name/path/itemName/targetName/choice/desc/near 逐个过 sanitiseForBlock(_, {maxLength:120}))

1.  FILTER-SNAPSHOT
    window = window.filter(e => renderEvent(e, opts) !== '')     // 丢掉 world_snapshot（§3.2.5）
    注意：此步只为"不占名额、不参与计数"，不是合并。

2.  MERGE-BY-TURN            (doc-21 §5.4 rule 1)
    groups = []                     // 有序，按 seq 升序
    for e in window:
      mergeable = e.turn !== null and !MERGE_EXEMPT.includes(e.type)
      prev = groups[groups.length - 1]
      sameKey = mergeable and prev !== undefined and prev.open
                and prev.turn === e.turn and prev.type === e.type
                and actorKey(prev.actor) === actorKey(e.actor)
      if sameKey:
        prev.count += 1                 // rule 1: 合并计数（不新增组）
        prev.events.push(e)
      else:
        if prev !== undefined: prev.open = false   // 一旦离开这个 turn/type/actor run，就不能再合
        groups.push({ turn: e.turn, type: e.type, actor: e.actor, events: [e], count: 1, open: true })
    // actorKey(actor) = `${actor.type}:${actor.id ?? ''}`（与 local-store.ts:421-422 的 NOT(...) 同构）
    // 三条约束：
    //  (a) turn 为 null 的事件一律独立成组（doc-21 §3.4："时间窗是猜的，turn 不是"）；
    //  (b) MERGE_EXEMPT 里的 type 一律独立成组（§3.5.1）——否则会把"3 次独立掷骰"合成一句谎话；
    //  (c) `character_moved` 在 MERGE_EXEMPT 里（A-11）：`carryFollowers`（presence.ts:229-270）
    //      对**每个跟随者**各落一条同 turn 同 actor（engine）的 `character_moved`——跟随者跨层是
    //      **日常**形态。若参与 rule-1，落到通用兜底句 `The engine did this N times.`（丢失全部人名）；
    //      豁免后每条各自成句 `Watson moved from "Baker Street" into "Abandoned Orchard".`。
    //      **不走 count 变体**：`carryFollowers` 的每条被移动者不同（name/character 各异），
    //      合成一句「N 个角色移动了」没有叙事价值，且 `countPhrase` 表里没有它的变体。
    // `open` 标志保证合并只在**连续**的同一 (turn,type,actor) run 内发生：中间夹了别的组就断开，
    // 所以同一个 turn 的两个不相邻 run 不会跨过去合并（防跨轮误合）。

3.  RENDER-GROUP
    for g in groups:
      d = g.events[0].detail                     // detail 自足（doc-21 §3.3）
      g.layer   = 组内 events[].layer 全同 ? 该值 : null   // 混合层 → null（04 的 layer_* 触发只吃非空）
      g.name    = d.name ?? d.itemName ?? undefined
      g.actor   = g.events[0].actor              // 04 门控交互尾句用（A-12）
      g.subject = g.events[0].subject ?? d.path ?? d.to ?? null
      g.text    = g.count > 1 ? countPhrase(g, opts) : renderEvent(g.events[0], opts)
    // 字段先算、句子后算：countPhrase 要用 g.name / g.events / opts.layerNames。
    // 句子的 count=1 形态由 renderEvent 给（§3.2 表），count>1 由 countPhrase 给（§3.5.1）。
    // g.layer / g.name / g.actor / g.subject 供 04 的 NextStepEvent 投影与测试使用，不参与句子。

4.  FOLD-EDITED               (doc-21 §5.4 rule 2)
    在 groups 上从左到右扫：
      若 g.type === 'entity_edited' 且 下一组 g2.type === 'entity_edited'
         且 g.subject === g2.subject 且 g2.subject !== null:
           丢掉 g（保留 g2）—— 即"连续同 subject 的 entity_edited 只留最后"。
    "连续" = 在 groups 序列里紧邻；中间只要夹了别的组就不折叠。
    折叠是**迭代到不动点**：3 个连续同 subject 只留最后一个。

5.  COLLAPSE-CREATE-MOVE      (doc-21 §5.4 rule 3)
    再扫一遍（作用在**被 4 折叠后的** groups 上）：
      若 g.type === 'entity_created' 且 下一组 g2.type === 'entity_moved'
         且 g.events[0].detail.path === g2.events[0].detail.from:     // ← 同一个实体
           g.name  = g2.events[0].detail.name ?? g.name
           g.text  = `${actorPhrase(g.actor)} moved "${g.name}" into ${pathPhrase(g2.events[0].detail.to)}.`
           g.type  = 'entity_moved'      // 落点语义：type 让位给 moved（04 只读 type）
           g.actor = g2.events[0].actor  // 落点句的主语归 moved 的 actor（通常是同一个 player）
           g.subject = g2.events[0].detail.to
           丢掉 g2
    // ⚠️ JOIN KEY 不是 `subject`，是 `created.detail.path === moved.detail.from`。
    // 为什么：`entity_created` 的 subject 是**创建处**的路径（create.ts:123 `subject: path`），
    // 而 `entity_moved` 的 subject 是**目的地**（move.ts:200 `subject: to`）。同一个"创建后
    // 立刻被搬走"的实体，两处 subject **永不相等**（A vs B），拿 subject 做键这条规则**永不触发**。
    // 真实身份链是"它从哪搬走的"：created 的 path == moved 的 from。doc-21 §5.4 rule 3 说的
    // "同 subject"要理解为"同实体"，本文按 `path === from` 落地（这是该实体唯一的稳定跨类型标识，
    // 且都在 `detail` 里、不需要回读世界）。
    // 若 created 在 A、moved 是 A→B：path(A) === from(A) → **折叠**（正确：读者只需知道它在 B）。
    // 若 moved 的 from 是别处（不是刚创建的那个）：**不折叠**。

6.  CAP                       (doc-21 §5.4 rule 4)
    dropped = max(0, groups.length - caps)
    if dropped > 0:
      kept = groups.slice(-caps)              // 取最近 caps 条（groups 已按 seq 升序）
      tail = `…and ${dropped} more (older events omitted)`
    else:
      kept = groups; tail = null
    // 游标照推到最新（rule 4）：由 §4 的 settleTurnCursor 保证，不在此函数里。
    // ⚠️ 尾句**不承诺**"记录还在、作家能翻"（A-13）：本仓没有历史面工具（`extensions/tools.ts`
    //    无任何读事件表的工具），且游标推到 `getMaxSeq()` 后这批事件**永不重现**。旧措辞
    //    `the rest are on record` 会诱导作家去找一个打不开的记录。新措辞 `(older events omitted)`
    //    只**明说被省略**，不指示去哪找。

7.  OUT
    lines  = kept.map(g => g.text)
    events = kept.map(g => ({ type: g.type, layer: g.layer, name: g.name, actor: g.actor,
                             count: g.count, subject: g.subject, text: g.text }))
    return { lines, tail, events, dropped, malformed }
```

#### 3.5.1 `countPhrase(g, opts)` —— 合并 N 条成一个句子

**判据（doc-21 §5.4 rule 1 原文）**：`player` 拖 4 件进背包，应出 ``The player moved 4 items into their bag.``，不是 4 行。所以 rule-1 合并必须**改句子**，不是加 "×N" 后缀。

| type | count > 1 时的句子 |
|---|---|
| `entity_moved` | ``${S} moved ${count} items into ${commonDest}.``（`commonDest` = 组内 `detail.to` 全同时的 `pathPhrase`，否则 `their bag`） |
| `entity_created` | ``${S} wrote ${count} new pages.``（`kind` 全 `chalk`；否则 ``${S} created ${count} things.``） |
| `entity_deleted` | ``${S} deleted ${count} things.`` |
| `entity_edited` | ``${S} edited ${count} entries.`` |
| `character_talked` | ``${S} spoke with ${name} (${totalTurns} exchanges).``（`totalTurns` = 组内 `turns` 之和；`name` 取自组内第一条） |
| 其余 type | 退回：``${S} did this ${count} times.``（通用兜底，见 §3.5.2） |

**为什么只对 5 个 type 做 count 变体**：这 5 个是玩家/作家**一次动作落多条**的现实形态（连拖、连续写）。其余 type 同 turn 同 type 多条时，语义是"确实发生了 N 次独立动作"，合并成一句会**说谎**（3 次掷骰是 3 个不同的骰子，不是"掷了 3 次"）——它们全在 `MERGE_EXEMPT` 里（§3.5.1 下方）。`character_moved` 也豁免（A-11），理由见步骤 2 注释：`carryFollowers` 的多条被移动者各不相同，合成一句丢失全部人名。

**rule-1 的 key 与豁免（本批拍板）**：

- **key = `(turn, type, actor)`**，照 doc-21 §5.4 rule 1 字面，**不加 `subject`**。理由：连拖 4 件 `entity_moved` 的 `subject` **各不相同**（每件一个路径），加进 key 就**合并不了**，与 doc-21 的示例（"玩家把 3 件东西收进了背包"）直接矛盾。
- 代价是 `roll_resolved` 等 type 的"不同 subject 多条"会被误合，所以配一份**豁免名单**：
  ```ts
  // NEW render/events.ts
  /** Types for which rule-1 merging would LIE ("N independent actions", not one bulk action). */
  export const MERGE_EXEMPT: readonly WorldEventType[] = [
    'roll_resolved', 'choice_selected',
    'layer_entered', 'layer_initialized', 'layer_init_failed',
    'following_changed', 'character_moved',
  ```
  名单内的 type **各自独立成组**（`count` 恒 1）。名单 = 全部 type 减去 §3.5.1 表里那 5 个"动作聚合型"。
- **为什么这是"实现细化"而不是"改写 doc-21"**：doc-21 rule 1 的**目的**是"一轮落三篇板书合成一句"；豁免名单只是指出哪些 type **不该**被这条规则覆盖。目的不变。**但 doc-21 §5.4 字面没写豁免**，落地时要回写 doc-21（登记在 §9 待确认 3）。

#### 3.5.2 为什么合并必须在**渲染之后**也说得通

合并改的是**句子**（§3.5.1），所以实现顺序应是：**先分组计数 → 再决定每组的句子**（`renderEvent` 给 count=1 的基句，`countPhrase` 给 count>1 的聚合句）。本批**不**采用"先渲染每条再拼"（那样 4 件会变成 4 句，再靠 §5.4 rule 1 去掉——会丢掉"合进一句"的信息）。

`malformed` 计数：`renderEvent` 对未知 type 或 detail 缺字段**不抛**，返回**通用兜底句**，累计计入 `malformed`。通用兜底句**定稿**为 `` An unrecorded kind of change happened (${type}). ``（单行、可断言；`${type}` 是枚举外的原始字符串，**也要过 `sanitiseForBlock`**——它同样来自事件表）。**正常情况下恒 0**，非 0 说明事件表里出现了枚举外的 type（写入侧 bug），探针应把它当失败（`06` §6.3）。

### 4.1 读法一：作家（游标增量）

```

          actions/actor.ts:53-59（已存在，本批首次有生产调用点）

### 4.4 为什么**不能**在 `context` handler 里推进（本节的要害）

`context` 事件**每次 LLM 调用**都触发（`types.ts:758`「Fired before each LLM call」；`runner.ts:1131-1160` 遍历 handler、`structuredClone` 后接受替换数组）。一次 agent run 内**每个工具循环轮**都会再触发一次（AUDIT §S2 附带发现），且 `previewPrompt()` 也会触发（`agent-session.ts:1849-1856` → `runner.emitContext`）。

所以若把 `writeCursor` 写在 `context` handler 里：

```
第 1 次 context 调用：读 slice → 渲染 → writeCursor(maxSeq=M1)   ✅
第 2 次 context 调用（同一轮的第一次工具返回后）：读 cursor=M1
        → getEventsSince(M1) → 空 → dynamics 节消失 ❌
第 3 次 context 调用：同上 ❌
```

**现象**：一次叙事里若作家调 3 个工具，第 2 次之后的 LLM 调用看到的事件段**丢掉**了本轮新事件（因为第 1 次调用已把游标推到本轮最大 seq，而第 2 次调用的 payload 是**从同一 state 重新组装**的——`context` 注入本身无状态，AUDIT §S2/§3.2）。更糟的是"注入即消费"会变成"每个 LLM 调用都消费一次"，同一批事件在**第一次工具循环**就可能被念了又念或直接吞掉。

**定案**（`00` §6.2 的"一个坑"原文）：**游标推进必须在轮边界的那一次结算里做**（`06` §4.1 的缓存计算），`context` handler **只读缓存、只拼字符串**（`00` §2 硬约束 1/2）。`context` handler 里**绝不出现 `writeCursor`**。

### 4.5 为什么在轮边界推 `getMaxSeq()` 是安全的（即使本轮流没走完）

轮边界（`agent_start`，`agent-session.ts:1032-1038`）是**用户轮**的起点（`turn_start` 是其内的工具循环轮，`:1055-1061`）。在轮边界推 `getMaxSeq()` 的语义是"**上一轮结束以来积累的变化，这一轮的注入已经全部念过了**"。

- 本轮的**新**事件（作家本轮自己写的）由 `excludeActor: {type:'writer'}` 排除，**不会**被下轮重复念。
- 玩家 UI 在本轮中途落的事件（`layer_entered` 等）：它们发生在轮边界**之后**，seq 大于结算时的 `M1`，所以**下轮**才会被念到——这正是想要的（本轮那些事件发生时，本轮的注入**已经发生**了）。
- **`steer` / `followUp` / `sendCustomMessage({triggerTurn:true})` / 续写重试**这四类**不触发** `before_agent_start`（AUDIT §2.1），且 `steer`/`followUp` 连 `agent_start` 也**不进** `prompt()`（`:2052-2055` 直接 return）。**后果**：这些轮没有轮边界结算 → 游标不动 → 那些轮**看不到新事件**。**这是已知且接受的**：`00` §9.2 已定"一个进程一个会话、B2 最小版不做 `session_start`/`leaf_changed` 保险"。登记在 §9 待确认 2。

## 5. 空事件段与读失败的明确行为

### 5.1 空事件段（`slice.events.length === 0`）

| 情形 | `renderEventWindow` 返回 | 02 的 `dynamics` 采集器 |
|---|---|---|
| 游标已到最新、无新事件 | `{ lines: [], tail: null, events: [], dropped: 0, malformed: 0 }` | 返回 `null` → **整节缺席**（`00` §4.1："空节整节缺席"） |
| 全部事件都是 `world_snapshot`（步骤 1 被滤掉） | 同上（`lines: []`） | 同上 |
| 角色首次打开、本层无任何事件 | 同上（`coldStart: true`，但 `lines: []`） | 同上 |

**关键裁决**：**事件段空 ≠ 注入块空**。事件段空只让 `dynamics` 节缺席；其余节（`viewpoint`/`layer_files`/`cast`/…）照常。**只有所有节都空**才输出 `[World state: nothing to report yet]`（`00` §4.3）——那个哨兵是 **01 的 `renderState`** 的事，不是本篇。

**"什么都没发生"的提示**由 **04** 的 `computeNextStep` 给（`00` §8 情形 3：明说"世界无变化，不要为了填空而写"）。本篇**不产出**任何祈使句——`lines` 里永远只有陈述句（doc-21 §3.5）。

### 5.2 读取失败（`getEventsSince` / `readCursor` 抛）

**纪律（`00` §11）：事件表读取失败 → `dynamics` 节缺席，其余节照常；绝不因为注入失败而炸一轮。**

| 失败点 | 行为 | 依据 |
|---|---|---|
| `readCursor(reader)` 抛 | 按 `seq = 0` 继续（等价"首次"）；warn 一次 | 读游标失败不该让整节消失；0 是 `readCursor` 的既定无行语义（`local-store.ts:444`） |
| `getEventsSince(seq)` 抛 | 抛给 01 的 `SectionDeps.events()` 调用点 → 该节 try/catch 吞掉 → `dynamics` 缺席 | `00` §11 第一行；02 的采集器逐节 try/catch（三层兜底第一层） |
| `writeCursor(reader, seq)` 抛（结算时） | `settleTurnCursor` **内部吞掉**，warn 一次，**不抛给轮边界** | 游标写失败最坏是"下轮重复念一遍"，**重复念**远好过**炸一轮**（`00` §11 共同纪律） |
| `getMaxSeq()` 抛 | `settleTurnCursor` 视为 `advance: false`（不写），warn | 同上 |
| `renderEvent` 遇未知 detail 字段缺失 | 不抛，返回通用兜底句，计 `malformed` | §3.5.2 |

**为什么"读失败 → 缺席"而不是"读失败 → 报错给模型"**：`00` §11 末句"看不见的注入比错误的注入好；错误的注入比炸一轮好"。**错误的注入**会是"世界没有变化"——而事实是世界可能变了，只是读不到；这会引导作家**装傻**（doc-05 §5.1 最忌）。**缺席**至少让作家按"没有事件段"行事（他仍能看到状态块的当前值）。

### 5.3 游标与"重复念"的取舍（为什么不 clamp）

`writeCursor` 是**裸写、无单调夹取**（`local-store.ts:447-448` 注释："Pushing backwards is legal"）。这允许 §4.3 调用点 3 的**回退式**写入（pin 到 open-time 高水位）。代价是：一次意外的 `seq` 更小会**重复念**一段事件。裁决：**接受**，因为：

1. 重复念一段事件，作家会看到两遍同一句——**轻微**，且下一轮就恢复；
2. 若 clamp 掉回退，调用点 3 的 pin 语义就没了（角色会漏报开聊期间发生的事件）——那是**实质**的叙事 bug。

## 6. 与回滚的交互（doc-21 §6）

doc-21 §6 定了三件事：

1. 事件表 **append-only**，回滚不删事件；
2. 回滚追加一条 `world_rolled_back`（`actor_type = engine`）；
3. **所有 `read_cursors` 推到最新** —— 否则作家下一轮会把回滚前那段历史当"刚发生的"再念一遍。

**A-8 定论：`world_rolled_back` 不过滤，必须能被作家念到。** 03 的窗口里**只**滤 `world_snapshot`（§3.2.5，`renderEvent` 返回 `''`）；`world_rolled_back` **有句子**（§3.2.5 表）且**留在 `eventWindow.events` 里**。理由：推平游标会把回滚事件前的历史全吞掉，若连回滚句也滤掉，作家将**永远不知道**世界被推回去了（§6.2）。**与 04 的边界**：`04:367` 曾写"`world_snapshot` / `world_rolled_back` …在注入前就被 03 过滤，本函数不重复过滤（单一职责：03 过滤，本文判定）"——**该断言就 `world_rolled_back` 而言是错的**，已同步 04 改为："`world_snapshot` 03 渲染成空串、窗口里不出现；`world_rolled_back` 03 不过滤、以 `type='world_rolled_back'` 出现在 `events`，但 04 的 `unseenCreation` 与队尾判定只匹配 `layer_*` 与交互三类，天然不匹配它"。

### 6.1 B2 要不要**实现**这条？——裁决：**不实现，但登记锚点**

**理由（已核）**：

- **回滚本身今天不存在**：`snapshotWorld` / `rollbackWorld` 在 `packages/shared/src/actions/service.ts:71-72` 只有**接口签名**，登记在 `ACTION_METHODS`（`:99-100`），**没有任何 handler**（AUDIT §4.3："`snapshotWorld`/`rollbackWorld` 在 `service.ts` 只有签名与登记，没有 handler"）。没有回滚，就没有要推平的游标。
- `getAllReadCursors`（`local-store.ts:464`，`world-store.ts:88-89`）**已存在**，注释就是为这条准备的。所以**数据层已就绪**，缺的只是调用点。

> **已落地（2026-09-14，B7）**：不再是"将来的调用点"。`pushAllCursorsToMax` 这个自由函数**已删除**——它无法进 store 的事务，而 §6.2 要求"append 与推游标同事务"。改为 `LocalWorldStore.appendEventAndPushCursors(args)`：一次 `historyDb` 事务里 append `world_rolled_back` + `UPDATE read_cursors SET seq = <该事件 seq>`，由 `actions/world.ts::rollbackWorld` 调用（doc-16 B7）。下方 §6.2 的顺序规则因此由**实现内建**，不再依赖调用者自觉。

### 6.2 `world_rolled_back` + 推平游标**够不够**？

**够——前提是投递顺序正确**：回滚事务必须**先** `appendEvent(world_rolled_back)`、**再** `pushAllCursorsToMax`（这样推到的最新 seq **包含**回滚事件本身），两者在**同一个 `historyDb` 事务**里（否则两个进程间会看到"游标已推、回滚事件还没落"的中间态，作家那一轮会既看不到回滚、也看不到回滚前的事件——**静默吞掉**）。

- **为什么不只是"推平游标"就够**：推平游标只保证"回滚前的事件不再被当新的念"。但这会**连 `world_rolled_back` 一起吞掉**（若回滚事件 seq ≤ 推平的 seq，作家永远看不到"世界被推回去了"）。所以作家**必须**能看到 `world_rolled_back`——即推平的 seq 要**恰好等于** `world_rolled_back.seq`（`getMaxSeq()` 在 append 之后调用，自然满足）。
- **回滚后文件回退、事件不回退**：`entity_moved`（回滚前的）仍会在事件表里，回滚后的作家读到的是"世界被推回到快照 X"，而**状态块**（`layer_files` 等）报的是回退后的**当前值**——两者不矛盾，因为状态块答"现在什么样"，事件段答"怎么变成这样的"（doc-21 §0/§1、doc-22 §1）。这是 `world_rolled_back` 存在的唯一理由：**给"怎么变的"一个明确的句子**。

### 6.3 回滚后 `coldStart` 的边界

回滚**不删** `read_cursors` 行，只改 `seq`。所以回滚后 `readCursor('writer')` 仍返回非 0（= 回滚事件 seq），**不会**误入 §4.2 的 `coldStart` 分支。**这是对的**：回滚不该让任何读者"重新从创世读起"。
