# 02 分节表与渲染

> 本篇是 `00-共同上下文.md` §3（分节契约）/§4（装配与上限）的**内容实现细则**：作家 6 节 + 角色 4 节各自的**确切英文输出、来源函数（file:line）、条目上限、空态行为**，以及"复用还是新写"的逐项裁决。
> 跨篇共享的形状（`Section`、线格式、上限表、游标语义、失败纪律）**一律以 00 为准**，本篇只引用其节号，不重述。
> 关联：`03`（事件段人话渲染——本篇 `dynamics` 节的正文由它产出）、`01`（`Section`/`SectionDeps`/`collectSections`/`renderState` 与三维兜底）、`05`（`viewpoint` 表 + 共享量化函数）、`06`（扩展注册与 `sectionsFor` 选择）、`AUDIT-doc-22体检.md` §4（落点核查）。

---

## 0. 一句话

**分节表是一个数组常量，每节 = 一个纯采集函数；采集返回 `null` 表示"这节缺席"，`text` 自足到连自己的标签都带上，永不输出 "(none)"。**

---

## 1. 目标

1. 把 00 §3.2/§3.3 的两张 key 表落成**可以直接照抄的渲染格式**：每个 key 有一行稳定的英文标签、一段自足的英文正文、一个来源函数、一个条目上限、一个空态。
2. 把 `AUDIT §4.1/§4.2/§4.3` 里"哪些能复用、哪些必须新写"的结论**收成签名**，让实现者不再做设计决策。
3. 定死 `dirPhrase` 喂 presence 的那一处（00 与 AUDIT 都点名，但都没给结论）。
4. 定死 barrel 导出改动（否则 `extensions/context.ts` 与前端**都够不到** `render/*`）。

**非目标**：事件段人话渲染器（`03`）、`next_step` 措辞（`04`）、`viewpoint` 表与 sanitize（`05`）、扩展接线与缓存（`06`/`01`）。本篇只定义**节的边界**。

## 2. 契约（形状与签名）

### 2.1 从邻居篇目借来的形状（本篇**不**重复声明）

```ts
// NEW packages/shared/src/render/state.ts —— 01 篇拥有，本篇 import
interface Section {
  key: string;        // 冻结字符串；00 §3.1
  title: string;      // 元数据：日志 / 测试 / 诊断用，renderState 不打印
  text: string;       // 自足正文（含自己的标签行），renderState 逐字打印
  items?: string[];   // 稳定 id（世界根相对路径 / 角色 id）
}

// NEW packages/shared/src/inject/collect.ts —— 01 篇拥有，本篇 import
interface SectionDeps {
  store: LocalWorldStore;
  actor: Actor;
  reader: string | null;        // readerOfActor(actor) 的产物；01 算一次
  layer: string | null;         // 01 每轮解析一次（writer: viewpoint.layer；character: getPresenceOf）
  viewport: ViewpointRecord | null; // 05 的 readViewpoint() 返回类型；01 从 inject/collect.ts re-export
  now: number;                  // 一次性时钟
  caps: SectionCaps;            // 见 §2.2（本篇拥有）
  events(): Promise<EventSlice>;    // MEMOISED 原始切片（测试/其他消费者）
  eventWindow(): Promise<EventWindow>; // MEMOISED：03 的合并+开窗结果，dynamics 与 next_step 共用
}
```

**两条纪律（与 01 商定，2026-09-12）**：

- `renderState(sections)` **逐字打印 `s.text`，不打印 `s.title`**。因此每个采集器的 `text` **必须自足到包含自己那行标签**（00 §3.1 "text 必须自足"、§4.1 线格式）。
- `dynamics` 采集器**调 `deps.eventWindow()`** 取 `.lines`/`.tail`（01 的备忘录；形状由 03 定：`{ lines; tail; events; dropped; malformed }`，`lines` 已合并、已按 cap 截断）。**本篇不再二次截断**，只加标签与缩进。`deps.events()` 是原始切片，留给测试/其他消费者。**两者都不由本篇直接调 `store.getEventsSince`、不自己读游标。**

**不复用** `render/layer-page.ts:127` 的 `LayerItem`（字段名是 `fm`，且带 `box`/`z`）——注入块采集只需要 `{ path: string; fm: Record<string, any> | null; body: string }` 三件（`bag` 的 `BagItem` 即此形），不把"画布卡"的语义拖进来。`summaryOf` / `kindWordOf` 的入参是 `(fm, body)` / `(fm, path)`，与 `LayerItem` 无关，可直接喂。**也不调** `extensions/toolkit/deps.ts:51 currentLayer`（AUDIT §4.4 登记的重复实现，本批由 `deps.layer` 取代）。`EventSlice` / `EventWindow` / `NextStepEvent` / `NextStepFacts` 都是 01/03 拥有的类型，本篇只 import 使用。

### 2.2 本篇拥有的新增类型与常量（NEW，落在 `packages/shared/src/render/sections.ts`）

`collect` 内部自取 `deps.caps`（上限语汇是节私有的，见 §3），`renderState` 不做二次截断。`SectionSpec.key` 与 `Section.key` 同源字面量。

### 2.3 纯函数边界

- **采集（有 I/O）**：`collect*` 只在**轮边界**跑一次（00 §2.2）；每节包在 01 的逐节 try/catch 里（00 §11 三层兜底第一层）。
- **渲染（纯）**：节内的**行渲染**（`layerLine` / `castLine` / `bagLine` / `chalkLine`）是独立导出的纯函数，可单测；节正文拼装本身也是纯字符串运算。
- **`context` handler 只读缓存串**（评审 A-21）：它**不调 `renderState`**、不 `collectSections`、不做任何 I/O——只从轮边界缓存里取**已渲染好的字符串**并追加（01 §2.1 的唯一 handler 体）。`renderState` 在**轮边界**（`agent_start`）跑一次，结果是纯字符串；`context` 每次 LLM 调用都触发（含 `previewPrompt`），所以它必须是 O(1) 的拼接。**本篇不碰 hook。**

## 3. 机制与理由（逐节）

> **格式约定**（全篇一致，测试按字面断言）：
> - 上面每节的"确切输出"**就是** `Section.text` 的内容（含标签行）。标签行紧跟一个空格再进正文；多行节第一行只放 `标签 (n):`，条目行另起。
> - 条目行 = **两个空格**缩进（与 `renderLayerBlock:180` 的 `  ${path} — …` 同款，让"这是清单"一眼可辨）。
> - 路径一律**世界根相对路径**（可直接 `look_at`），分隔符 ` — `（em dash）与 ` · `（中点），与 `layer-page.ts:180` 一致，不引入第二套。
> - `…and <N> more` 用两个空格缩进，与条目行齐平。

#### `viewpoint` — 单行

**确切输出**（`?"` = 命中才有；`deps.layer === null` 或 `deps.viewport === null` → 整节缺席）：

```
Viewpoint: the player is in "<layer name>", <focus>. The player has selected "<path>". When the player says "this", they mean the selected card first, then whatever is in view.
```

- `<layer name>`：`actions/presence.ts:112 readLayerName(store, layer)`（已有；manifest 的 `layers[id].name`，缺失退化为目录名）。**不报层 id**（人话优先）；`items` 里放层 id。
- `<focus>`：**本篇从 `deps.viewport.focus`（已解码的视口中心点 `{x,y} | null`，05 §2.3）渲染成人话**——调 §3.3 的 `presencePhrase(focus, 本层卡片锚点)`，与 `cast` 用同一套词表。**本篇不解析 `focus` 列**（05 §2.3：`readViewpoint` 已 `decodeCentre`）；**05 只把中心量化编码进库，人话是渲染结果**（05 §2.1）：`focus` 为 `null`（视口未知）→ 降级为 `in view`（仍自足）。
- **不灌坐标**（00 §5.1 裁决）——需要精确摆位走 `look_at`（00 §7）。
- 选中句：`deps.viewport.selected`（已 sanitize 到 ≤24）。多个 → `"a" and "b"`；空 → **整句省略**。**今天 `selected` 恒为 `[]`**（`apps/web` 尚无选中模型，05 §5.6），所以该句**当前永不出现**——保留它是为了让选中模型上线后零改动，不是死分支（判据与 05 一致）。
- 末句是**指代消解**，00 §12.4 明文允许的两类例外之一（另一类是 `next_step`）。它依附于"选中/视口"这一当下的值，因此即使 `selected` 为空也保留。
- **不渲染 `bag_count`**：清单归 `bag` 节（05 §2.3 定案：`bagCount` 只作节流键/一句计数）。`viewpoint.bag_count`（00 §5.1）在注入块里不出现——否则同一事实有两个渲染点。

#### `standing` — 单行

**确切输出**：

```
Standing: you are in "<layer name>", <presence phrase>. <player clause>
```

- 采集：`store.getPresenceOf(actor.id!)`（`local-store.ts:1097`，**同步**）。有行 → 层 = `row.layer`，方位用 §3.3 的 `presencePhrase`。
- 无 presence 行 → 退化到 `world.json` 的 `home`：调 `resolveHome`（`presence.ts:203-213`），**但判据必须读返回值的 `.fromHome`，不能读 `home` 字段是否存在**（评审 A-4）：`resolveHome` **永不返回 `null`**——`home` 缺失/为空/指向非真层时它一律回落 `{ layer: MAP_LAYER, fromHome: false }`。所以"`home` 也无 → `null`"这条分支按字面写**永远走不到**，会让一个从未摆放、也没有 home 的角色稳定地被告知"你在 `map`、right where you belong"。**正确判据**：

```ts
const home = resolveHome(store, actor.id!);
if (!home.fromHome) return null;              // 无真 home → 整节缺席（评审 A-4）
layer = home.layer;                            // 有真 home → 用它的层
```

### 3.3 `dirPhrase` 喂 presence 的裁决（AUDIT §4.3）

**背景（已核）**：`dirPhrase(subject: Box, anchor: Box)`（`spatial.ts:42`）的阈值全部经 `normalDistance`（`:20`）——分母是 `(a.w+b.w)/2`、`(a.h+b.h)/2`，**必须两边都有 w/h**；某个 Box 宽为 0 会把 `direction` 与 `d` 同时除成 `Infinity`/`NaN`。presence 是**点**（`world-store.ts:31-33` 明文：`x`/`y` 是头像**中心**），喂不进。

**三个候选**：

| 方案 | 代价 |
|---|---|
| A. 给角色合成伪 Box | 需要定 w/h；定错则方位词全偏 |
| B. 新写点锚变体 | 复制一套阈值与词汇 → **第二套约定**（原则禁止） |
| C. 只对已摆放卡片复用 | 角色方位正是本节存在的理由，C 等于没做 |

**裁决：选 A，伪 Box 尺寸取 `CARD_FORMS.sprite`（`schemas/forms.ts:68` → `{ w: 176, h: 196 }`）。**

理由：
1. **这不是编造的尺寸**——引擎自己的 presence 占位模型就是它：`seatPresence`（`local-store.ts:1001`）第 1005 行 `const { w, h } = CARD_FORMS.sprite;`，并用它做碰撞检测（`:1041`）。注入块用同一尺寸 = "用引擎自己的碰撞模型说人话"。
2. `dirPhrase` 的阈值是**相对**的（`normalDistance` 归一化到"平均箱宽"），伪 Box 只需与锚点卡片同量纲；`CARD_FORMS.sprite`（176×196）与 `chalk`/`note`（460×190 / 200×168，`:66`,`:73`）同量纲，不会把"隔壁"误判成"很远"。
3. B 会复制 `doc-03 §5.4` 冻结的词汇与 0.4/1.0/2.5 三档阈值——两套阈值必然漂移（原则：不许在既有约定旁加第二套）。

**新签名**（NEW，加进 `packages/shared/src/render/spatial.ts`）：

```ts
import { CARD_FORMS } from '../schemas/forms.js';

/** 角色的落点 Box：x/y 是头像中心（world-store.ts:31），尺寸取引擎的 presence 占用（local-store.ts:1005）。 */
export function spriteBox(at: { x: number; y: number }): Box {
  const { w, h } = CARD_FORMS.sprite;          // schemas/forms.ts:68
  return { x: at.x - w / 2, y: at.y - h / 2, w, h };
}

/** `normalDistance` 现为私有（spatial.ts:20），改加 `export`，供 presencePhrase 共用同一距离度量。 */
export function normalDistance(a: Box, b: Box): number;   // 仅加 export，体不改

export interface Anchor { path: string; box: Box; name: string }

/** 一个点相对最近锚点的方位短语 + 锚点名。无锚点返回 null。 */
export function presencePhrase(
  at: { x: number; y: number },
  anchors: Anchor[]
): { dir: string; anchorPath: string; anchorName: string } | null {
  if (anchors.length === 0) return null;
  const subject = spriteBox(at);
  let best = anchors[0];
  let bestD = normalDistance(subject, anchors[0].box);
  for (const a of anchors.slice(1)) {
    const d = normalDistance(subject, a.box);
    if (d < bestD) { bestD = d; best = a; }
  }
  return { dir: dirPhrase(subject, best.box), anchorPath: best.path, anchorName: best.name };
}
```

`dirPhrase` 的输出词表**原样使用**（`right on top of` / `overlapping` / `next to` / `above of` / `far above-left of`，`spatial.ts:52-56`）——与 `look_at` 的 Layout 段（`layer-page.ts:199-202`）逐字一致，一份词汇两处用（doc-22 §2 第 9 条）。

**行渲染映射**（`castLine`，纯函数，导出可单测）：

```ts
export function castLine(
  id: string,
  at: { x: number; y: number },
  anchors: Anchor[],
  opts: { following?: boolean; role: 'writer' | 'character' }
): string {
  const p = presencePhrase(at, anchors);
  const where = p ? `${p.dir} "${p.anchorName}"` : 'somewhere in this layer';
  const tail = opts.role === 'writer' && opts.following ? ' · following you' : '';
  return `  ${id} — ${where}${tail}`;
}
```

- 锚点集合 = 本层已摆放卡片的 `{ path, box, name }`（`box` 是 top-left 矩形，直接可用；来自 `store.getLayerCards(paths)`）。
- **无卡片时**（空层 / 全部未摆放）退化为 `somewhere in this layer`——仍自足且诚实（不假装知道方位）。

### 3.4 确定性排序（AUDIT §4.3）

**背景（已核）**：`cardsOfLayer`（`layers.ts:102`）遍历 `allFiles` 后**原样返回**，不排序；`listFiles`（`local-store.ts:176`）走 `fs.readdir`（`:182`）**无排序**。所以"按时间排"不能依赖任何现状。

**裁决：按文件名前导序号排序，无序号者排在有序号者之后，同档按路径码点升序。** 板书命名是 `序号-标题.md`（`doc-05-AIRP产品构想.md:299`），序号即时间序。

```ts
/** 文件名前导整数（`02-counter.md` → 2），无前导数字返回 null。 */
export function ordinalOf(path: string): number | null {
  const base = path.split('/').pop() ?? path;
  const m = base.match(/^(\d+)[-_]/);
  return m ? Number(m[1]) : null;
}

/** 稳定、无 locale 依赖：有序号在前且小的在前；同档按码点升序。 */
export function compareCards(a: string, b: string): number {
  const oa = ordinalOf(a), ob = ordinalOf(b);
  if (oa !== null && ob !== null && oa !== ob) return oa - ob;
  if (oa !== null && ob === null) return -1;
  if (oa === null && ob !== null) return 1;
  return a < b ? -1 : a > b ? 1 : 0;
}

/** 背包/清单的纯路径序（不解析序号）。 */
export function comparePaths(a: string, b: string): number {
  return a < b ? -1 : a > b ? 1 : 0;
}
```

- `layer_files`：`cardsOfLayer(...)` 结果先 `sort(compareCards)` **再截断**。截断必须在排序后，否则"前 12 条"每轮不同（`readdir` 顺序不稳）→ `items` 抖动 → 测试不稳定。
- **不用 `localeCompare`**：不同 ICU 数据下对非 ASCII（中文文件名）结果不同，跨进程（server / agent）不一致；码点比较是确定性的。
- 角色侧 chalk 的"按时间排"用同一函数——角色看的是同层同一批文件，序号即时间。**不引入 mtime**（mtime 只用于跨层的 `recent_chalk`，§4.1）。

> **⚠️ 实测：当前模板几乎不用序号**（评审 A-27）。`templates/holmes-world/world/baker-street/` 下的文件名是 `evening.md` / `raindrops.md` / `late-night.md`，**无前导数字** → `ordinalOf` 在这些真实文件上**恒为 `null`**，排序实际退化为**纯路径码点升序**。这不是错误（码点序同样确定性、同样可断言），但必须写明：
> - **确定性成立**（这是本节唯一硬要求）——`readdir` 顺序不稳，码点序稳定；
> - **"序号即时间序"只在作者真的用序号命名时成立**；模板不这么命名，所以当前 `layer_files` 的**语义是"稳定但无序"**，不是"按时间"。
> - 因此测试断言必须对**码点序**写，不能对"时间序"写；`doc-05` 的 `序号-标题.md` 是**给作者的建议命名**，不是仓库现状。
> - 若将来要真时间序，须走 `filesByMtime`（`recent_chalk` 已用），**不要在 `layer_files` 里偷偷加 mtime 读**（那是每轮 I/O，且与"清单"语义不符——清单要的是"有这些"，不是"最近在写")。

### 3.5 装配顺序与线格式（引用 00 §4.1）

`renderState(sections, facts: NextStepFacts)`（01）拼成一条消息；**每节的 `text` 自带标签**，节间空一行。`facts` 承载 `role`（`'writer' | 'character'`）与 `next_step` 的事实依据；`role` 决定下面最后一行那句"全部缺席"的 sentinel 措辞（作家 / 角色两版）。**`renderState` 是同步纯函数**——`facts` 由 `await buildNextStepFacts(deps, sections)`（01）**先**产出再传入（评审 A-7：不得把 Promise 当 `NextStepFacts` 用）。调用点在轮边界，不在 `context` handler（§2.3）。

## 5. Barrel 导出改动（**跨端同批**）

**问题（已核）**：`packages/shared/src/index.ts`（全文 40 行）导出 schemas / store / db / actions / rules / components，**唯独没有 `./render/*`**（AUDIT §4.2 第 1 条）。扩展通过**相对路径** `../packages/shared/dist/index.js` 导入，前端通过包名 `@airp/shared` 导入。**两条路径都过这份 barrel**——所以 `render/spatial.ts::dirPhrase`、`render/layer-page.ts::summaryOf` 目前扩展与前端**都够不到**。

> **唯一 union 的真源是 `00 §15`**（评审 B-1：四篇曾各列一份互不相同的清单，其中 06 的五行**漏了它自己 import 的模块**，而漏导出是**静默的**）。**本篇不再自列清单**——本篇相关的两条是 `'./render/sections.js'`（`sectionsFor` / `WRITER_SECTIONS` / `CHARACTER_SECTIONS` / `SECTION_CAPS`，本篇产出）与 `'./render/viewpoint.js'`（05 的共享量化函数），二者都已在 `00 §15` 的 11 行 union 里。**落地时由第一个 PR 一次性合入 `00 §15` 的全部 11 行**，不按"谁先落地谁加自己那几行"分散提交（那正是清单漂移的成因）。

**命名冲突核查（已做，结论：无冲突）**：全仓扫描 `Box` / `basenameOf` / `LayerItem` / `summaryOf` / `SUMMARY_CAP` / `BODY_CAP` / `Section` / `SectionKey` 的导出，除 `render/` 外**没有别处**导出同名符号。所以 `export *` 不会触发 "Duplicate identifier"。

**副作用（必须同批，跨端）**：`render/layer-page.ts` / `render/spatial.ts` 目前**无任何生产 import**；加 barrel 后前端与扩展第一次够得到，`pnpm --filter @airp/shared build` 会把它们编进 `dist/`。扩展侧改完必须**重建 shared** 才可见（AGENTS.md §6.5）。

## 8. 边界与失败模式

| 情形 | 行为 | 依据 |
|---|---|---|
| 单节采集抛错 | 01 的逐节 try/catch：`warn` stderr + **该节缺席**，其余照常 | 00 §11 第一层 |
| `deps.layer === null`（writer 且 viewpoint 无行） | `viewpoint` / `layer_files` / `cast` 缺席；**`bag` / `recent_chalk` / `dynamics` 照常**（它们不依赖当前层） | 00 §4.3/§11 |
| `player/` 不存在或空 | `bag` 节缺席 | 00 §4.3 |
| 本层无 md | `layer_files` 节缺席 | 00 §4.3 |
| 本层无 presence | `cast` 节缺席 | 00 §4.3 |
| 无历史 md | `recent_chalk` 节缺席 | 00 §4.3 |
| `deps.eventWindow()` 抛错 | `dynamics` 节缺席（01 兜） | 00 §11 |
| 全部节缺席 | `renderState` 输出单行 "nothing to report yet"（作家）/ "nothing has happened here yet"（角色） | 00 §4.3 |
| 整块组装失败 | 01 返回原 messages，**不注入**，warn 一次 | 00 §11 |

**本节表自身的两条纪律**：
1. `collect*` **绝不抛错到 `context` handler**（00 §2.1）——所有 I/O 在轮边界，逐节 try/catch 在 01。
2. `text` 里**不出现祈使句**，除 `viewpoint` 的指代消解末句（00 §12.4 明文例外）。清单行、`+` 行、`…and N more` 都是陈述。

**与 03 / 05 的重叠边界（已与 peer 约定）**：
- `dynamics` 的正文明细（人话陈述句、合并去重、cap、尾句措辞）属 **03**（`renderEventWindow` → `{ lines, tail, dropped, … }`）；02 只定外壳（标签 `Recently, in the world`、`  - ` 缩进、`  ${tail}` 缩进、空态），**不二次截断**。
- `viewpoint` 节的 `<focus>`：05 只提供**已解码的中心点**（`ViewpointRecord.focus`），**人话由 02 渲染**（§3.1，复用 `presencePhrase`）；02 不算量化、不 import `viewpoint.ts`（除非实现时选择用它解码，那也只读 `decodeViewRect`）。
- 游标读取/推进属 **01**（`deps.eventWindow()`）与 **03**（`settleTurnCursor`）；02 不读不写游标。

## 10. 待确认项

1. **~~`viewpoint.bag_count` 是否进注入块~~（已由 05 解决）**：05 §2.3 定 `bagCount` **只作一句计数/节流键**，清单归本篇 `bag` 节（与 00 §3.2 一致）。本篇 `viewpoint` 节**不渲染它**，已定。
2. **`recent_chalk` 的 `…and N more` 尾句**：00 §4.2 的"超出时"栏写的是"取最近 8"（无尾句），与 `layer_files`/`bag` 不同。本篇按 00 字面执行（无尾句）；若试玩发现模型误以为"只有 8 篇"，再加。
3. **`cast` 的锚点是否含子层门卡**：本篇只用本层已摆放卡片（`getLayerCards`）。若角色方位需要"在通往果园的门附近"这种，须把 `childLayers`（`layers.ts:117`）的 README 也加进锚点——**留白**，第一版不做。
4. **`ordinalOf` 支持的前导格式**：本篇认 `^(\d+)[-_]`（`02-counter.md` / `02_counter.md`）。若模板实际用零填充或不同分隔符，须同步正则。**待实现时对模板实测**（`templates/holmes-world/world/baker-street/evening.md` 无前导数字，落在"同档按码点"分支）。
5. **角色 `standing` 在 `home` 回退时的方位词**：本篇定 `right where you belong`；若 04 的措辞定稿觉得该句与"玩家在你面前"冲突，由 04 裁决。
6. **~~`focus` 的锚点 vs 中心~~（已由 05 解决）**：05 §2.3 定 `ViewpointRecord.focus` 就是**视口中心**（`decodeCentre` 解出），不是矩形左上角——本篇原以为可能是锚点，现已核为同坐标系。`presencePhrase` 直接喂，无近似。
7. **`deps.viewport.bagCount` 与 `bag` 节计数的一致性**：`bag` 节的 `<n>` 来自实时 `listBackpack`，而 `viewpoint.bagCount` 是前端上报快照——两者可能瞬时不同。本篇以实时为准（`bag` 节）；`bagCount` 只作节流键（05 §2.3）。**不冲突，登记备查。**
