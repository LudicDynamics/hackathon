## 0. 一句话

**每轮注入 = 一个自足的状态块（当前值，全量）+ 一个事件段（变化，游标增量）+ 一句"下一步"（祈使，由事实推出）；三者拼成一条消息，挂在 `context` 钩子上，**只在它所属的那一次 player 请求（一个 trace：`agent_start` → `agent_end`/settled）的首个 provider 请求里存在——一个 trace 恰好注入一次**。

## 1. 与 doc-22 的两处相反（**先看这里，否则会照错文档写**）

| # | doc-22 的说法 | 本文的裁决 | 依据 |

## 2. 四条硬约束（违反即返工）

1. **`context` handler 必须纯、廉价、无副作用。** 它在**每次 LLM 调用**前触发（含工具循环内的每一轮），且会被 `previewPrompt()`（`/prompt` 预览）调用。**不做磁盘扫描、不写任何东西**。
2. **重活（扫目录 / 读两个 db / 渲染）只在轮边界算一次**，结果缓存；`context` 只做字符串拼接。轮边界 = `agent_start`（或 `before_agent_start`，见 §6.2）。
3. **绝不把注入文本写进会话条目、绝不碰 `systemPrompt`。** 前者会累积（S1），后者炸 prompt 缓存。
4. **一个 trace 内块恰好注入一次。** `context` handler 每次 LLM 调用**都会被调用**（约束 1），但只在该 trace 的**第一个** provider 请求（引擎 `turnIndex === 0`）**产出**块；其后一律返回 `undefined`。**触发 ≠ 注入**——「handler 被调用 N 次」不等于「块出现 N 次」。`previewPrompt()` 也不得消耗它（判据与理由见 `docs/hooks/07-注入粒度修复设计.md §4.4`）。

## 3. 分节契约

### 3.1 形状

```ts
interface Section {
  key: SectionKey;    // 稳定标识。**全集 = 作家 6 节 ∪ 角色专属节**：viewpoint / layer_files / cast / bag / recent_chalk / dynamics / standing（`standing` 只在 CHARACTER_SECTIONS 里；02 §2.2 是联合类型真源）
  title: string;      // 节标题（渲染用）
  text: string;       // 该节的正文（已渲染，自足）
  items?: string[];   // 可选：可枚举项的**稳定 id 列表**（如路径）。B2 不用它做 diff，但 tool 侧与测试要用
}
```

> **`next_step` 不是 `Section.key`。** 它不在任何节表里（§3.2/§3.3 的表只列状态节），而是装配器在 `dynamics` 之后**追加**的一节，`renderState` 不为它打印 title（§8）。`SectionKey` 联合类型**不含** `next_step`——实现者若按旧注释把它加进联合类型，会与 02 的 `SectionKey` 定义冲突。

- `key` **一旦定下不得改**（测试、日志、诊断都按它断言）。
- `text` 必须**自足**：读者不依赖任何"上一轮"就能理解。
- `items` 里的 id 用**世界根相对路径**（`world/baker-street/copper-key.md`）或角色 id；不要放渲染后的句子。

### 3.2 作家 6 节 + "下一步"（B2）

| key | 标题 | 来源（真实落点） | 节型 | 纪律 |
|---|---|---|---|---|
| `viewpoint` | 玩家视点 | `canvas.db` 的 `viewpoint` 单行表（前端上报，§5） | 单行 | 人话方位；**不灌原始坐标**（坐标只走 `look_at` 工具，§7） |
| `layer_files` | 本层现有 | `store/layers.ts::cardsOfLayer` + `render/layer-page.ts::renderLayerBlock` | 清单 | 只列路径 + 一行这是什么，**不灌全文**；条目上限 §4 |
| `cast` | 在场角色 | `canvas.db` 的 `presence`（`getPresence`） | 清单 | 谁在这层、大致在哪、谁在跟随；**不报角色背包** |
| `bag` | 玩家背包 | 扫 `player/`（复刻 `GET /backpack` 的逻辑，抽 helper） | 清单 | 只列不灌，条目上限 §4 |
| `recent_chalk` | 最近板书 | 跨层按 mtime 取最近 N 篇 | 清单 | 路径 + 首行 |
| `dynamics` | 世界动态 | `history.db` 事件表（`getEventsSince` + 游标，§6） | 游标 | 人话陈述句、合并去重、上限 §4 |
| `next_step` | （无标题，见 §8） | 由前六节 + 事件段推出 | 祈使 | **永远最后一节**；只陈述"什么悬着"，不替 agent 做决定；**只在首个 provider 请求出现一次**；续接请求不重贴（01 §3.3） |

### 3.3 角色 4 节 + "下一步"（B3）

| key | 与作家的差异 |
|---|---|
| `standing` | 替代 `viewpoint`：换成**角色自己**的位置 +「玩家此刻在你面前」；**不报玩家的相机/视口** |
| `layer_files` | 同作家；层内 chalk 按**时间**排（`cardsOfLayer` 不排序，须自己排，见 AUDIT §4.3） |
| `cast` | 「还有谁在」——**排除自己** |
| `dynamics` | 本层过滤（`getEventsSince(seq, {layer})`），首次取最近 N 条，**关遮罩时推进游标**（§6.3） |
| `next_step` | 角色版："你刚被打开，玩家在场，你知道这层发生过什么，你该开口说什么" |

**角色不注入 `bag`**：玩家的口袋不在角色视野里。（省 token + 合乎叙事，**不是权限门禁**——角色真要 `look_at player/` 也拦不住，doc-05 §4.1。）

**同一份扩展、同一张事件表。** 分节表按 `AIRP_AGENT_ROLE` 选（`writer` → 6 节；`character:<id>` → 4 节），**不是两个扩展文件**。

## 4. 装配与条目上限

### 4.1 线格式（渲染成一条消息的 `content`）

**真源是 `02 §7.1`（作家块）与 `02 §7.2`（角色块）**——那两处是逐字的、可被 golden 测试断言的完整样例。本节只给结构骨架，**任何字面冲突以 02 §7 为准**（`02` 负责渲染，本契约负责形状）：

```
[World state]

<每节：可选 title 行 + 缩进两空的条列；空节整节缺席>

<最后：next_step 段（无 title，§8）>
```

硬规则（可机械核验，`tools/check-hooks-docs.mjs` 检查字面量）：

- **首行恒为 `[World state]`**（方括号、无冒号）。
- **英文**（喂给模型的注入块是产品内容，AGENTS.md §1.1）。
- 节标题是固定的英文词（`Viewpoint` / `In this layer` / `Present` / `In the player's bag` / `Recent writing` / `Recently, in the world` / `Standing` / `Also here`），**便于测试断言**；改动即破坏 golden。
- 空节**整节缺席**（不输出"（无）"）。
- 清单节的条列语法以 `02 §7.1` 为准（两空缩进；`In this layer`/`In the player's bag` 的条列前缀由 02 定，不在本契约重述）。
- **事件段印路径形式**（`"world/baker-street/copper-key.md"`），**不是**卡片显示名——`detail` 拿不到显示名（`schemas/events.ts:51-58`）。

### 4.2 条目上限（**保证有界**，但不是"唯一"保证）

| 节 | 上限 | 超出时 |
|---|---|---|
| `layer_files` | 12 | 截断 + 末行 `…and N more` |
| `bag` | 12 | 同上 |
| `cast` | 8 | 同上 |
| `recent_chalk` | 8 | 取最近 8 |
| `dynamics` | 12 | 取最近 12 + `…and N more (older events omitted)` |

> **尾句不得承诺"还能查到"（评审 A-13）**：游标在注入成功后即推到 `getMaxSeq()`，被折叠的事件**永不重现**，且**没有历史面工具**。旧措辞 `the rest are on record` 指向一个作家打不开的记录，故改为 `(older events omitted)`——**只说省略，不暗示可取**。

> **两点更正（评审 A-9）**：①上限保证的是"**渲染后**的块有界"，**读取**必须另有界——热路径**不得**对 `getEventsSince` 做**无 LIMIT** 的全量取用后再截断（见 §6.1）。②"有界性唯一保证"的说法**过头**：读取与缓存生命周期同样是边界的一部分。

上限是**配置常量**（不是硬编码字面量），试玩时按实际 token 占用调。**改上限要同步改本文的表。**

### 4.3 空注入

- 所有节都无内容（新世界、无事件、无视点）→ 输出 `[World state: nothing to report yet]`（角色版措辞不同）。**不要返回空字符串**：一条空消息会让模型困惑；显式说"没事"。
- 整个注入块组装失败 → **不注入**（返回原 messages），并 `stderr` warn 一次。**绝不因为注入失败而炸一轮。**

## 5. 视点链路（B2 独有）

### 5.1 表

```sql
CREATE TABLE IF NOT EXISTS viewpoint (
  id         TEXT PRIMARY KEY DEFAULT 'singleton',
  layer      TEXT NOT NULL DEFAULT '',   -- 当前层 id（世界根相对，如 world/baker-street；'' = 不在任何层）
  focus      TEXT NOT NULL DEFAULT '',   -- **编码的视口中心**：'x:y'（不是人话！人话是渲染产物，见下）
  focus_x    INTEGER NOT NULL DEFAULT 0, -- 视口几何的镜像列（供摆位/调试；注入不用）
  focus_y    INTEGER NOT NULL DEFAULT 0,
  focus_w    INTEGER NOT NULL DEFAULT 0,
  focus_h    INTEGER NOT NULL DEFAULT 0,
  selected   TEXT NOT NULL DEFAULT '[]', -- JSON 字符串数组：选中的卡片路径
  bag_count  INTEGER NOT NULL DEFAULT 0,
  at         TEXT NOT NULL               -- ISO 时间戳，做 TTL
);
```

> **DDL 真源 = `05 §2.2`**（05 拥有视点链路）。本契约与它字面一致；冲突以 05 为准并回写本文。`id` 单行 = `'singleton'`。
>
> **⚠️ `focus` 存的是编码几何 `'x:y'`，不是人话**（评审 B-4 的裁决）。**人话方位是 `02` 从解码后的中心点渲染出来的**——它由 `render/spatial.ts::dirPhrase` 生成，**永远不进这张表**。这样做的理由有二：①**安全**——浏览器来的自由文本若直接存进 `focus` 再原样灌进注入块，就是一条提示注入通道（评审 INJ-01）；②**单一真相源**——人话的措辞归渲染器，存词就等于把措辞冻结在写侧。

**单行表**（`doc-05 §6` 单玩家世界）。**不属于世界**：快照不打包、回滚不还原——它是"此刻玩家在看哪"。`at` 超过 **10 分钟**视为离开，该节**整节缺席**（不报陈旧值）。

> **关于坐标 vs 人话**：doc-22 主张"不给坐标"，doc-02 §3.2 照抄 Nodesign 写了坐标矩形。**裁决**：**注入块给人话方位**（渲染产物），**坐标不进注入块**；需要精确摆位时走 `look_at` 工具。但**存的是坐标**（编码中心，见上）——两者不矛盾：存的是机器量，看的是人话。

### 5.1.1 视点 TTL 的**级联**与心跳（评审 A-3）

`deps.layer` 派生自 `viewport.layer`。若 TTL 到点而玩家仍在原层静坐，**不能**只让 `viewpoint` 节缺席就完事——`layer_files` 与 `cast` 也会陪着消失。两种修法（`05` 定案）：**(a)** 前端加**慢心跳**（身于 TTL 的周期重发一次），或 **(b)** 把"当前层"与"视点新鲜度"解耦（层独立读）。**无论选哪个，本契约 §11 的失败表必须登记这条级联**，不能只写"`viewpoint` 节缺席"。

### 5.2 上报（`POST /api/viewpoint`）

- 前端**只在语义级变化时发**，最快 **1.2s** 一次（+ §5.1.1 的心跳）；
- 服务端**一律 sanitize**——详见 §14（**消毒是内容级的，不只是长度级的**）；
- 写入 `viewpoint` 单行表。

> **更正（评审 INJ-03）**：`POST /api/viewpoint` **不是**注入链路上"唯一的外部输入"。它是唯一**新增的浏览器直连**输入，但注入块同时印世界文件内容（`entityName` 的 `title`、层 README 的 `name`、事件 `detail.name`），而 `POST /api/god-action`（`routes/world.ts:669-720`）**无鉴权**接受任意 frontmatter/body。所以消毒必须**对所有进入注入块的动态文本**生效，不只在 view endpoint（§14）。

### 5.3 共享量化函数

**前端与服务端必须用同一个 TS 函数**（doc-22 说"同一个"，Nodesign 实际是两处内联表达式——我们要真做到）。落点：`packages/shared/src/render/`（新文件或 `spatial.ts`）。前端 import 它（Vite 直接吃 TS），服务端同一份。**测试断言两侧输出逐字一致。**

## 6. 事件段与游标

### 6.1 读取

- **作家**：`getEventsSince(cursor, { excludeActor: { type: 'writer' } })`——不把自己刚写的念给自己听；
- **角色**：`getEventsSince(cursor, { layer: <本层>, excludeActor: { type: 'character', id: <自己> } })`；
- reader id 用 `actions/actor.ts::readerOfActor`（`'writer'` / `'character:<id>'`）——**已有、无生产调用点，本批首次使用**。
- **⚠️ 读取必须有界（评审 A-9）**：`getEventsSince`（`local-store.ts:408-429`）是 `SELECT * WHERE seq > ? ORDER BY seq ASC`，**无 LIMIT**。热路径**不得**先全量取出再在渲染器里截断——必须先限量（按层走 `idx_events_layer`，或加 `LIMIT`）再取。**冷启动同理**：角色首开"本层最近 12 条"必须**按层**查（`getEvents` 不按层过滤，`local-store.ts:475`），不能全局取 36 条再 filter（评审 A-2）。

### 6.2 游标推进时机（**关键**）

| 角色 | 何时推进 | 理由 |
|---|---|---|
| 作家 | **注入成功后**推到 `getMaxSeq()` | 注入即消费（doc-21 §5.4）。走 `context` 后文本不落盘，"注入即消费"才严格成立 |
| 角色 | **关遮罩时**推进，不是打开时 | 打开时推进的话，一次崩溃或误点就把这段永久吞掉（doc-21 §5.2） |
**三个坑**：
1. `context` 在**每次 LLM 调用**都触发，所以"注入成功"会重复判定。**游标推进必须在轮边界的那一次结算**（轮边界缓存里做），**不在 `context` handler 里做**——否则工具循环里每轮都推一次，等于没消费。
2. **⚠️ 角色进程也加载这个扩展**（`launch.ts:129-130` 展开 `extensionArgs`），`readerOfActor` 对角色返回 `character:<id>`。所以轮边界的结算**必须有 `actor.type === 'writer'` 守卫**——否则角色进程每轮就把角色游标推到 `getMaxSeq()`，正是上表**明令禁止**的"开遮罩时就推进"（评审 B-3）。**只要 `if (block && reader)` 是 bug。**
3. **角色游标的拥有者是 `03`（事件段篇）**，不是 06（接线篇）。两篇曾互相推诿（`03:592` 说归 server/06，`06:452` 说由 03 定）——**本契约写死：归 03 定，06 只负责把 03 定的调用挂上**。且落地必须**登记两个前端发送方**：`character_start`（开遮罩，触发角色进程 spawn + 开时高水位 pin）与 `character_stop`（关遮罩，触发结算）。
   > **2026-09-12 核实更正**：本句原写"今天 `apps/web` 一个都没有（`grep -rn character_start apps/web/src` 零命中）"——**已为假**。两个发送方均已落地：`apps/web/src/App.tsx:122`（`character_start`）与 `:127`（`character_stop`）；服务端 `apps/server/src/index.ts:119-141`（高水位 pin + spawn）与 `:165-203`（`settleTurnCursor` + stop）亦已实现。该断言写于契约起草时、核实后未回写，正是"文档对现状的断言有保质期"的实例。核实记录见 `docs/wiring/前端接线体检.md §6`。


### 6.3 合并与上限

按 doc-21 §5.4 **固定顺序**：①同 `turn`+`type`+`actor` 合并计数 → ②同 `subject` 连续 `entity_edited` 只留最后 → ③`entity_created` 紧跟同 `subject` 的 `entity_moved` 只说落点 → ④仍超 12 条取最近 12 + 补一句，**游标照推到最新**。

**人话渲染器要新写**（全仓不存在，AUDIT §4.2）：`WorldEvent` → 一句英文陈述。落点 `packages/shared/src/render/events.ts`（新），**纯函数、可单测**，作家与角色共用。

## 7. 两层原则（复用，别再造一套）

**注入负责让 agent 知道"有这么个东西"，工具负责让它"看清楚"。**（doc-05 §1 懒加载、doc-22 §7、B3 §6.4 同一条。）

- 清单节只给**路径 + 一行摘要**，正文一律 `look_at` / `read` 自己取；
- `look_at` 已经会返回结构化位置与互动字段（B1），**不要**在注入块里重复它；
- 需要精确坐标（摆位）时，**只有工具给**。

## 8. "下一步"段（doc-12 #6 的措辞落点）

**拍板：本批一并定**（用户 2026-09-12 确认）。这是 doc-22 §10 自认"优先级最高的待设计项"，也是 doc-12 标着**待办**的 #6。

- **位置**：永远在注入块的**最后一节**，跟着事件段走；位置不变；但整块每 trace 只交付一次——续接请求不带本句；
- **性质**：**祈使的**，且**只能由事实推出来**——不许空泛的"请继续推进剧情"；
- **三类情形**：
  1. 事件段最新一条是 `choice_selected` / `use_item_on` / `roll_resolved` → "玩家选了 B / 掷出 14，**这一结果还没有被叙事回应**"；
  2. 有刚生成、玩家还没看过的东西 → "第一幕已落，玩家尚未进入该层"；
  3. **什么都没发生** → 明说"世界无变化，**不要为了填空而写**"（同样重要，是"事件不打断作家"的提示词侧配套）；
- **边界**：只陈述"什么悬着"，**不替 agent 做决定**（不写"你应该让老板娘开口"）。
- **正文字数与文风**：按 `doc-23` 的九条写法。**措辞定稿写在本批的 04 篇**，`extensions/instructions.ts` 的 `WRITER_INSTRUCTION` / `CHARACTER_INSTRUCTION` 引用它（平台口径只此一份，doc-23 §3.1）。

## 9. 身份与进程

- **一个扩展文件** `extensions/context.ts`（会被 `presets.ts::extensionArgs` 扫到——它只扫**顶层** `extensions/*.ts`；子目录不被当扩展加载）；
- 身份靠 `AIRP_AGENT_ROLE`（`writer` / `character:<id>`），由 `airpEnv()` 注入；
- **模块级状态 = 进程级 = 会话级**（一个 agent 一个进程）。
- **⚠️ 但「模块级」是 per-extension-file 的，不是 per-process**（Design06 实测 + 主控复核）：loader 对**每个**扩展文件各建一个 `createJiti(..., { moduleCache: false })`（`loader.ts:500`，调用点 `:556`），所以**两个顶层扩展文件不共享模块状态**。实测：同一 `shared.ts` 里的计数器，`extensions/toolkit/actor.ts` 读到 1、`extensions/context.ts` 读到 1（各自独立）。
  - **后果**：`extensions/context.ts` **不能**复用 `extensions/toolkit/deps.ts` 的 worldStore 缓存/`actor.ts` 的 actor 缓存——那是另一个模块实例。若确实要共享，只能由一个文件导出 getter 供另一个 import（注意 `@airp/shared` 在 `extensions/` 下**不解析**，必须相对路径 import，见 `extensions/tools.ts:14-18`）。

### 9.1 子代理不继承 hook（**已知且要写进注释**）

`subagent/run.ts:81-83` 起子会话时 `extensions: []`，只转发 `tool_*` handler。**scene-init 子代理（B5）拿不到注入**——这是对的（初始化器要 brief 不要视点），但**实现者必须知道**，否则会以为"父扩展的 hook 在子代理里跑"。

### 9.2 缓存失效

轮边界缓存键 = `sessionId`。`session_compact` **不需要**清缓存（每轮全量，无指纹）。但 `/new`、`/resume`、`/fork`、`/tree` 换分支**不触发 `session_compact`**——若要保险，另挂 `session_start` + `leaf_changed`。**B2 最小版可以不做**（一个进程一个会话），但要在注释里写清这是有意的简化。

## 11. 失败语义

| 情形 | 行为 |
|---|---|
| 单节采集失败 | `warn` 到 stderr + **该节缺席**，其余照常（**三层兜底**：逐节 try/catch → 采集器只在有内容时 push → 外层整块 null 不注入） |
| 视点表不存在 / 无行 / TTL 过期 | `viewpoint` 节**缺席**，**且级联**：`layer_files` / `cast` 同缺席（`deps.layer` 派生自 `viewpoint.layer`，评审 A-3）。`bag` / `recent_chalk` / `dynamics` **不受影响**（不依赖当前层） |
| 事件表读取失败 | `dynamics` 节缺席 |
| 注入块整体组装失败 | **不注入**（返回原 messages），warn 一次 |
| `viewpoint` 上报非法 | 拒绝整份，**不更新旧值**（旧值继续按 TTL 生效） |

**共同纪律：注入永远不能让一轮失败。** 看不见的注入比错误的注入好；错误的注入比炸一轮好。

## 12. 反模式（MUST NOT）

1. **MUST NOT** 把注入挂 `before_agent_start` 的 `message`（会累积，S1）。
2. **MUST NOT** 在 `context` handler 里做 I/O（每次 LLM 调用都跑，含 `previewPrompt`）。
3. **MUST NOT** 把正文灌进清单节（第二真相源，doc-05 §8.5）。
4. **MUST NOT** 在状态块里写规则/指令（除 §8 的"下一步"与指代消解那一句）——规则住 preset（缓存的 system prompt），每轮重述 = N 倍重复。
5. **MUST NOT** 引入 `get_state` / `set_state` / `state_update` / `watch_state`，也不建状态文件/命名空间（doc-20 §2.3，AGENTS.md §3.2）。
6. **MUST NOT** 写 `state_changed` 之类的事件——事件表只记变化，当前值走状态块（doc-21 §8）。
7. **MUST NOT** 把"角色场景简报"造出来（doc-22 §8 / doc-12：**没有这个层**）。
8. **MUST NOT** 让 `fs.watch` 写事件表（doc-21 §2.1）。
9. **MUST NOT** 用差分/指纹做去重（无状态注入下无指代对象，§1 裁决 2）。
10. **MUST NOT** 假定注入块会留在 transcript 里——它每轮重算。
11. **MUST NOT** 在同一 trace 的续接请求里重复注入块（含重复 `next_step` 祈使句）——它已陈旧，且会把已验证的祈使变成假指令（01 §3.3）。

## 14. 注入面消毒（**新增，评审 B-6/INJ-01~03**）

**注入块里出现的每一段动态文本，都必须过同一个消毒函数。** 威胁模型不是"只有 `POST /api/viewpoint`"——注入块同时印世界文件内容（`entityName` 的 `title`、层 README 的 `name`、事件 `detail.name`），而 `POST /api/god-action`（`routes/world.ts:669-720`）**无鉴权**接受任意 frontmatter/body（`index.ts:23` 挂 `cors()`、`:175` 绑 `0.0.0.0`）。**这是第二条注入通道，旧威胁模型漏了它。**

### 14.1 唯一消毒函数

```ts
// packages/shared/src/render/sanitise.ts（新）——注入块里所有动态文本的唯一入口
export function sanitiseForBlock(raw: unknown, opts: { maxLength: number }): string;
```

规则（**内容级，不只是长度级**）：

1. **剥换行与所有控制字符**（`\n\r\t` 与 C0/C1）→ 单空格。**这是最重要的一条**——注入靠换行与块边界伪造结构。
2. **收敛引号**：把 `"` `'` `` ` `` `\` 折成安全形式（或整体剥除），**破坏引号逃逸**。
3. **限长**（`maxLength` 由调用方给：`layer` ≤ 300、`title`/`name` ≤ 120、`selected` 项 ≤ 300）。
4. **拒绝整段**：`layer` 仍须满足 `isPlausibleLayer`（`map` 或 `world/` 开头、段非空非 `.`/`..`），但**在此之上必须再过 1–3**。

### 14.2 谁必须调用它

| 文本 | 来源 | 必须消毒 |
|---|---|---|
| `viewpoint.layer` | 浏览器 | ✅（`isPlausibleLayer` + 14.1） |
| `viewpoint.focus` | 浏览器 | ✅（但存的是编码几何，见 §5.1，**本就不该有散文**） |
| `viewpoint.selected[]` | 浏览器 | ✅ |
| `entityName(fm, path)`（`rules/interactive.ts:383-387`，`title.trim()` **不限长**） | 世界文件 | ✅ |
| 层 README 的 `name`（`presence.ts:112-121` `readLayerName` 回落印末段） | 世界文件 | ✅ |
| 事件 `detail.name` / `detail.path` | 事件表（间接来自世界文件或 god-action） | ✅ |

**验证方式**：`tools/check-hooks-docs.mjs` 之外，实现期加一条单测：构造含 `\n\nIgnore previous instructions` 的 `layer`/`title`，断言渲染出的块**不含**换行且该句被折平。**这是探针 A 系列之外必须新增的一条。**

## 15. barrel 导出 union（**新增，评审 B-1**）

`packages/shared/src/index.ts` 今天**没有** `export * from './render/*'`，也**没有** `inject/*`（文件止于 `./actions/talk.js`）。TS 的 `export *` **不支持 glob**，逐文件列出是唯一写法——代价是**加文件必须加行**，否则新模块**静默不可达**。

**本批唯一 union（12 条，权威定义在这里；各篇只许回指，不许自列）：**

```ts
// packages/shared/src/index.ts —— B2/B3 本批新增（在现有 export * 之后追加）
export * from './render/spatial.js';      // dirPhrase（02 的 presencePhrase 依赖；扩展 + 前端共用）
export * from './render/layer-page.js';   // summaryOf / kindWordOf / renderLayerBlock
export * from './render/state.js';        // Section / renderState / SectionKey（01）
export * from './render/sections.js';     // WRITER_SECTIONS / CHARACTER_SECTIONS / sectionsFor / SECTION_CAPS（02）
export * from './render/events.js';       // renderEventWindow / EventWindowLine（03）
export * from './render/next-step.js';    // computeNextStep / NextStepFacts（04）
export * from './render/viewpoint.js';    // ViewRect / quantiseViewRect / encodeViewRect / decodeViewRect / viewpointKey / VIEWPOINT_MIN_INTERVAL_MS（05）
export * from './render/sanitise.js';     // sanitiseForBlock（§14）
export * from './inject/turn-cache.js';   // readTurnBlock / writeTurnBlock（01）
export * from './inject/collect.js';      // collectSections / makeSectionDeps / buildNextStepFacts（01）
export * from './store/cursor.js';        // settleTurnCursor（03；作家扩展侧与角色 server 侧共用，故住 shared）
export * from './actions/backpack.js';    // listBackpack（02；server 路由 GET /backpack 经桶名 import，故必须导出）
```

**（共 12 行——原说"11 行"漏了 02 的 `actions/backpack.js`：`apps/server` 走包名 `@airp/shared`，exports map 只开 `.` 与 `./forms`，所以路由够不到新 helper，必须由本 union 导出。L3 实施反馈，2026-09-12。）** 归属：**由落地这批的第一个 PR 一次性合入全部 12 行**（单一负责方），因为漏一行是静默的、且四篇都会碰同一个文件；后续篇加文件时**必须同时加行**。

**机械核验**：`node tools/check-hooks-docs.mjs` 的 `barrel-union` 检查会 diff 各篇列出的清单与本文的 union——**任一篇不全即 fail**。改 union 必须同步改本节的代码块（脚本读的就是它所在文档的 barrel 块）。

### 15.1 扩展侧的 import 路径（**唯一写法**）

`extensions/context.ts`（**顶层**，非 `extensions/toolkit/*`）一律 `import { … } from '../packages/shared/dist/index.js'`——**走 barrel，不走深路径**（`extensions/tools.ts:13-16` 是范例）。`@airp/shared` 在 `extensions/` 下**不解析**。`extensions/toolkit/*` 的相对深度不同（`../../`），但**barrel 约定相同**。
