## 0. 一句话

**每轮注入 = 一个自足的状态块（当前值，全量）+ 一个事件段（变化，游标增量）+ 一句"下一步"（祈使，由事实推出）；三者拼成一条消息，挂在 `context` 钩子上，只在本次 LLM 请求里存在。**

## 1. 与 doc-22 的两处相反（**先看这里，否则会照错文档写**）

| # | doc-22 的说法 | 本文的裁决 | 依据 |
|---|---|---|---|
| **1** | 注入挂在 `before_agent_start` 的 `message` | **改挂 `context`** | 实测：`before_agent_start` 的 message 被持久化成 `custom_message` 会话条目，**第 N 轮上下文里有 N 个块**（`agent-session.ts:2107-2125` → `agent-loop.ts:110-113` → `agent-session.ts:936`）。`context` 返回替换数组**不落盘**（`agent-loop.ts:287-296` 只看不改），是引擎唯一的临时注入接缝。见 AUDIT S1/S2 |
| **2** | 逐节指纹 diff，只报变化的节 | **放弃差分，改为每轮全量** | `context` 注入**无状态**：请求 N 的载荷里没有第 N-1 轮的块，差分**没有指代对象**。有界性改由**条目上限**保证 |

**doc-22 的目标（每轮知道世界什么样、刚变了什么、且上下文不无界增长）仍然成立**——本文只是把它的手段换成能兑现的那个。doc-22 撤销 summary 压缩层的结论**保留**，但理由从"注入块天生有界"改为"注入走临时路径，每轮恰好一份"。

## 2. 三条硬约束（违反即返工）

1. **`context` handler 必须纯、廉价、无副作用。** 它在**每次 LLM 调用**前触发（含工具循环内的每一轮），且会被 `previewPrompt()`（`/prompt` 预览）调用。**不做磁盘扫描、不写任何东西**。
2. **重活（扫目录 / 读两个 db / 渲染）只在轮边界算一次**，结果缓存；`context` 只做字符串拼接。轮边界 = `agent_start`（或 `before_agent_start`，见 §6.2）。
3. **绝不把注入文本写进会话条目、绝不碰 `systemPrompt`。** 前者会累积（S1），后者炸 prompt 缓存。

## 3. 分节契约

### 3.1 形状

```ts
interface Section {
  key: string;        // 稳定标识：viewpoint / layer_files / cast / bag / recent_chalk / dynamics / next_step
  title: string;      // 节标题（渲染用）
  text: string;       // 该节的正文（已渲染，自足）
  items?: string[];   // 可选：可枚举项的**稳定 id 列表**（如路径）。B2 不用它做 diff，但 tool 侧与测试要用
}
```

- `key` **一旦定下不得改**（测试、日志、诊断都按它断言）。
- `text` 必须**自足**：读者不依赖任何"上一轮"就能理解。
- `items` 里的 id 用**世界根相对路径**（`world/baker-street/copper-key.md`）或角色 id；不要放渲染后的句子。

### 3.2 作家 6 节 + "下一步"（B2）

| key | 标题 | 来源（真实落点） | 节型 | 纪律 |
|---|---|---|---|---|
| `viewpoint` | 玩家视点 | `canvas.db` 的 `viewpoint` 单行表（前端上报，§5） | 单行 | 人话方位；**不灌原始坐标**（坐标只走 `look_at` 工具，§7） |
| `layer_files` | 本层现有 | `store/layers.ts::cardsOfLayer` + `render/layer-page.ts::renderLayerBlock` | 清单 | 只列路径 + 一行这是什么，**不灌全文**；条目上限 §4 |
| `cast` | 在场角色 | `canvas.db` 的 `presence`（`getPresence`） | 清单 | 谁在这层、大致在哪、谁在跟随；**不报角色背包** |
| `bag` | 玩家背包 | 扫 `player/`（复刻 `GET /backpack` 的逻辑，抽 helper） | 清单 | 只列不灌，条目上限 §4 |
| `recent_chalk` | 最近板书 | 跨层按 mtime 取最近 N 篇 | 清单 | 路径 + 首行 |
| `dynamics` | 世界动态 | `history.db` 事件表（`getEventsSince` + 游标，§6） | 游标 | 人话陈述句、合并去重、上限 §4 |
| `next_step` | （无标题，见 §8） | 由前六节 + 事件段推出 | 祈使 | **永远最后一节**；只陈述"什么悬着"，不替 agent 做决定 |

### 3.3 角色 4 节 + "下一步"（B3）

| key | 与作家的差异 |
|---|---|
| `standing` | 替代 `viewpoint`：换成**角色自己**的位置 +「玩家此刻在你面前」；**不报玩家的相机/视口** |
| `layer_files` | 同作家；层内 chalk 按**时间**排（`cardsOfLayer` 不排序，须自己排，见 AUDIT §4.3） |
| `cast` | 「还有谁在」——**排除自己** |
| `dynamics` | 本层过滤（`getEventsSince(seq, {layer})`），首次取最近 N 条，**关遮罩时推进游标**（§6.3） |
| `next_step` | 角色版："你刚被打开，玩家在场，你知道这层发生过什么，你该开口说什么" |

**角色不注入 `bag`**：玩家的口袋不在角色视野里。（省 token + 合乎叙事，**不是权限门禁**——角色真要 `look_at player/` 也拦不住，doc-05 §4.1。）

**同一份扩展、同一张事件表。** 分节表按 `AIRP_AGENT_ROLE` 选（`writer` → 6 节；`character:<id>` → 4 节），**不是两个扩展文件**。

## 4. 装配与条目上限

### 4.1 线格式（渲染成一条消息的 `content`）

```
[World state]

Viewpoint: the player is in "Baker Street", near the counter. In their bag: brass key.
In this layer: README.md, 01-rainy-night.md, 02-counter.md, copper-key.md
Present: Watson (near the counter, following you)
Recently, in the world:
- The player moved "copper-key.md" from the counter into their bag.
- A dice check on "Deduction" rolled 62 (passed).

You have not yet narrated the dice result above. Handle the player's action for this turn.
```

- **英文**（喂给模型的注入块是产品内容，AGENTS.md §1.1）。
- 节标题用稳定的英文词，便于测试断言。
- 空节**整节缺席**（不输出"（无）"），**但**：一节都没内容时输出一行 `[World state: unchanged this turn]`（见 §4.3）。

### 4.2 条目上限（**有界性的唯一保证**）

| 节 | 上限 | 超出时 |
|---|---|---|
| `layer_files` | 12 | 截断 + 末行 `…and N more` |
| `bag` | 12 | 同上 |
| `cast` | 8 | 同上 |
| `recent_chalk` | 8 | 取最近 8 |
| `dynamics` | 12 | 取最近 12 + `…and N more; the rest are on record` |

上限是**配置常量**（不是硬编码字面量），试玩时按实际 token 占用调。**改上限要同步改本文的表。**

### 4.3 空注入

- 所有节都无内容（新世界、无事件、无视点）→ 输出 `[World state: nothing to report yet]`（角色版措辞不同）。**不要返回空字符串**：一条空消息会让模型困惑；显式说"没事"。
- 整个注入块组装失败 → **不注入**（返回原 messages），并 `stderr` warn 一次。**绝不因为注入失败而炸一轮。**

## 5. 视点链路（B2 独有）

### 5.1 表

```sql
CREATE TABLE IF NOT EXISTS viewpoint (
  id         TEXT PRIMARY KEY DEFAULT 'singleton',
  layer      TEXT,              -- 当前层 id（世界根相对，如 world/baker-street）
  focus      TEXT,              -- 人话方位（如 'near the counter'）——前端算好，不是坐标
  selected   TEXT,              -- JSON 字符串数组：选中的卡片路径
  bag_count  INTEGER NOT NULL DEFAULT 0,
  at         TEXT NOT NULL      -- ISO 时间戳，做 TTL
);
```

**单行表**（`doc-05 §6` 单玩家世界）。**不属于世界**：快照不打包、回滚不还原——它是"此刻玩家在看哪"。`at` 超过 **10 分钟**视为离开，该节**整节缺席**（不报陈旧值）。

> **关于 `focus` vs 坐标**：doc-22 主张"不给坐标"，doc-02 §3.2 照抄 Nodesign 写了坐标矩形。**裁决**：注入块给**人话方位**（`focus`），**坐标不给**；需要精确摆位时走 `look_at` 工具（它能返回结构化的位置与方位）。理由：注入要的是"指代消解"，摆位是工具的事（doc-22 §7 的两层）。**前端上报时在浏览器侧把相机/选中折算成人话**——但量化必须用**共享函数**（§5.3）。

### 5.2 上报（`POST /api/viewpoint`）

- 前端**只在语义级变化时发**，最快 **1.2s** 一次；
- 服务端**一律 sanitize**（这是注入链路上**唯一的外部输入**）：数值 clamp、字符串限长、数组截断（上限 24）；
- 写入 `viewpoint` 单行表。

### 5.3 共享量化函数

**前端与服务端必须用同一个 TS 函数**（doc-22 说"同一个"，Nodesign 实际是两处内联表达式——我们要真做到）。落点：`packages/shared/src/render/`（新文件或 `spatial.ts`）。前端 import 它（Vite 直接吃 TS），服务端同一份。**测试断言两侧输出逐字一致。**

## 6. 事件段与游标

### 6.1 读取

- **作家**：`getEventsSince(cursor, { excludeActor: { type: 'writer' } })`——不把自己刚写的念给自己听；
- **角色**：`getEventsSince(cursor, { layer: <本层>, excludeActor: { type: 'character', id: <自己> } })`；
- reader id 用 `actions/actor.ts::readerOfActor`（`'writer'` / `'character:<id>'`）——**已有、无生产调用点，本批首次使用**。

### 6.2 游标推进时机（**关键**）

| 角色 | 何时推进 | 理由 |
|---|---|---|
| 作家 | **注入成功后**推到 `getMaxSeq()` | 注入即消费（doc-21 §5.4）。走 `context` 后文本不落盘，"注入即消费"才严格成立 |
| 角色 | **关遮罩时**推进，不是打开时 | 打开时推进的话，一次崩溃或误点就把这段永久吞掉（doc-21 §5.2） |

**一个坑**：`context` 在**每次 LLM 调用**都触发，所以"注入成功"会重复判定。**游标推进必须在轮边界的那一次结算**（轮边界缓存里做），不在 `context` handler 里做——否则工具循环里每轮都推一次，等于没消费。

### 6.3 合并与上限

按 doc-21 §5.4 **固定顺序**：①同 `turn`+`type`+`actor` 合并计数 → ②同 `subject` 连续 `entity_edited` 只留最后 → ③`entity_created` 紧跟同 `subject` 的 `entity_moved` 只说落点 → ④仍超 12 条取最近 12 + 补一句，**游标照推到最新**。

**人话渲染器要新写**（全仓不存在，AUDIT §4.2）：`WorldEvent` → 一句英文陈述。落点 `packages/shared/src/render/events.ts`（新），**纯函数、可单测**，作家与角色共用。

## 7. 两层原则（复用，别再造一套）

**注入负责让 agent 知道"有这么个东西"，工具负责让它"看清楚"。**（doc-05 §1 懒加载、doc-22 §7、B3 §6.4 同一条。）

- 清单节只给**路径 + 一行摘要**，正文一律 `look_at` / `read` 自己取；
- `look_at` 已经会返回结构化位置与互动字段（B1），**不要**在注入块里重复它；
- 需要精确坐标（摆位）时，**只有工具给**。

## 8. "下一步"段（doc-12 #6 的措辞落点）

**拍板：本批一并定**（用户 2026-09-12 确认）。这是 doc-22 §10 自认"优先级最高的待设计项"，也是 doc-12 标着**待办**的 #6。

- **位置**：永远在注入块的**最后一节**，跟着事件段走；
- **性质**：**祈使的**，且**只能由事实推出来**——不许空泛的"请继续推进剧情"；
- **三类情形**：
  1. 事件段最新一条是 `choice_selected` / `use_item_on` / `roll_resolved` → "玩家选了 B / 掷出 14，**这一结果还没有被叙事回应**"；
  2. 有刚生成、玩家还没看过的东西 → "第一幕已落，玩家尚未进入该层"；
  3. **什么都没发生** → 明说"世界无变化，**不要为了填空而写**"（同样重要，是"事件不打断作家"的提示词侧配套）；
- **边界**：只陈述"什么悬着"，**不替 agent 做决定**（不写"你应该让老板娘开口"）。
- **正文字数与文风**：按 `doc-23` 的九条写法。**措辞定稿写在本批的 04 篇**，`extensions/instructions.ts` 的 `WRITER_INSTRUCTION` / `CHARACTER_INSTRUCTION` 引用它（平台口径只此一份，doc-23 §3.1）。

## 9. 身份与进程

- **一个扩展文件** `extensions/context.ts`（会被 `presets.ts::extensionArgs` 扫到——它只扫**顶层** `extensions/*.ts`；子目录不被当扩展加载）；
- 身份靠 `AIRP_AGENT_ROLE`（`writer` / `character:<id>`），由 `airpEnv()` 注入；
- **模块级状态 = 进程级 = 会话级**（一个 agent 一个进程）。
- **⚠️ 但「模块级」是 per-extension-file 的，不是 per-process**（Design06 实测 + 主控复核）：loader 对**每个**扩展文件各建一个 `createJiti(..., { moduleCache: false })`（`loader.ts:500`，调用点 `:556`），所以**两个顶层扩展文件不共享模块状态**。实测：同一 `shared.ts` 里的计数器，`extensions/toolkit/actor.ts` 读到 1、`extensions/context.ts` 读到 1（各自独立）。
  - **后果**：`extensions/context.ts` **不能**复用 `extensions/toolkit/deps.ts` 的 worldStore 缓存/`actor.ts` 的 actor 缓存——那是另一个模块实例。若确实要共享，只能由一个文件导出 getter 供另一个 import（注意 `@airp/shared` 在 `extensions/` 下**不解析**，必须相对路径 import，见 `extensions/tools.ts:14-18`）。

### 9.1 子代理不继承 hook（**已知且要写进注释**）

`subagent/run.ts:81-83` 起子会话时 `extensions: []`，只转发 `tool_*` handler。**scene-init 子代理（B5）拿不到注入**——这是对的（初始化器要 brief 不要视点），但**实现者必须知道**，否则会以为"父扩展的 hook 在子代理里跑"。

### 9.2 缓存失效

轮边界缓存键 = `sessionId`。`session_compact` **不需要**清缓存（每轮全量，无指纹）。但 `/new`、`/resume`、`/fork`、`/tree` 换分支**不触发 `session_compact`**——若要保险，另挂 `session_start` + `leaf_changed`。**B2 最小版可以不做**（一个进程一个会话），但要在注释里写清这是有意的简化。

## 10. 存储与只读（**修正 doc-22**）

- 视点 → `canvas.db` 新 `viewpoint` 单行表（§5.1）；
- 缓存 → **agent 进程内存**（模块级），不落盘；
- **doc-22 §6 说"扩展侧只读打开"——不成立**：`LocalWorldStore` 构造时**读写打开两个 db 并跑 DDL**（`local-store.ts:63-72`），扩展用的就是它。本批要么**新开一条 `{readonly:true}` 路径**，要么**接受读写**并在注释里说明为什么（扩展本来也要写事件表 / 游标）。**选后者**：扩展确实要写 `read_cursors`，纯只读做不到。写进注释，别假装是只读。

## 11. 失败语义

| 情形 | 行为 |
|---|---|
| 单节采集失败 | `warn` 到 stderr + **该节缺席**，其余照常（**三层兜底**：逐节 try/catch → 采集器只在有内容时 push → 外层整块 null 不注入） |
| 视点表不存在 / 无行 / TTL 过期 | `viewpoint` 节**缺席** |
| 事件表读取失败 | `dynamics` 节缺席 |
| 注入块整体组装失败 | **不注入**（返回原 messages），warn 一次 |
| `viewpoint` 上报非法 | 拒绝整份，**不更新旧值**（旧值继续按 TTL 生效） |

**共同纪律：注入永远不能让一轮失败。** 看不见的注入比错误的注入好；错误的注入比炸一轮好。

## 12. 反模式（MUST NOT）

1. **MUST NOT** 把注入挂 `before_agent_start` 的 `message`（会累积，S1）。
2. **MUST NOT** 在 `context` handler 里做 I/O（每次 LLM 调用都跑，含 `previewPrompt`）。
3. **MUST NOT** 把正文灌进清单节（第二真相源，doc-05 §8.5）。
4. **MUST NOT** 在状态块里写规则/指令（除 §8 的"下一步"与指代消解那一句）——规则住 preset（缓存的 system prompt），每轮重述 = N 倍重复。
5. **MUST NOT** 引入 `get_state` / `set_state` / `state_update` / `watch_state`，也不建状态文件/命名空间（doc-20 §2.3，AGENTS.md §3.2）。
6. **MUST NOT** 写 `state_changed` 之类的事件——事件表只记变化，当前值走状态块（doc-21 §8）。
7. **MUST NOT** 把"角色场景简报"造出来（doc-22 §8 / doc-12：**没有这个层**）。
8. **MUST NOT** 让 `fs.watch` 写事件表（doc-21 §2.1）。
9. **MUST NOT** 用差分/指纹做去重（无状态注入下无指代对象，§1 裁决 2）。
10. **MUST NOT** 假定注入块会留在 transcript 里——它每轮重算。
