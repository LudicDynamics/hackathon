# 05 — 视点链路（B2 独有）

> 本篇只写视点这一条链路：`viewpoint` 表 DDL、`POST /api/viewpoint` 的 sanitize、**共享量化函数**、前端上报 hook、TTL。
> 跨篇共享的形状（`Section`、线格式、条目上限、失败语义、身份与游标）**一律不在此重述**，引用 `00-共同上下文.md` 的节号；冲突以 00 为准。
> 关联：`00 §5`（视点链路契约）、`00 §9`（身份与进程）、`00 §11`（失败语义）、`00 §7`（两层原则）、`AUDIT §1/§3.1/§3.4`、`doc-22 §5/§6`、`doc-02 §3.2`、`docs/hooks/06-接线与生命周期.md`（接线口径）。

---

## 0. 一句话

**前端把"此刻在看哪"按 1/8 视口折成规范化的几何（视口中心点）上报；服务端 sanitize 后写进 `canvas.db` 的 `viewpoint` 单行表；扩展装配时把它渲染成人话方位词注入。坐标进库、人话进提示词——两者不是一回事。**

---

## 1. 目标

1. 让作家每轮说清"玩家在哪一层、在看什么"，从而消解玩家句里的"这个 / 这里 / 那张"（`doc-02 §3.2`）。
2. 相机抖动**不算变化**：换算后的视口矩形挪不到 1/8 视口就丢弃（`doc-22 §5` 闸 2）。
3. 前端与服务端对"什么算变化 / 量化成什么"**只有一份实现**（`00 §5.3`；`AUDIT §1` 指出 Nodesign 是两处内联表达式，是反面教材）。
4. 上报是注入链路上唯一**新增的浏览器直连**输入（`00 §5.2` 的更正）；世界文件与 `god-action` 是**既有**通道。凡进入注入块的动态文本，统一过 `00 §14` 的 `sanitiseForBlock`。
5. 视点**不属于世界**：不进快照、不随回滚还原、重启即作废（`00 §5.1`）。

非目标：不报角色背包（`00 §3.2`）；不做多人（`doc-05 §6` 单玩家世界）；不做运行时可选节（`00 §12` 第 4 条）。

## 2. 契约

### 2.1 进库的数字 vs 进提示词的人话（核心裁决）

`AUDIT §3.1` 记录的口径冲突：`doc-22 §3.1/§5` 主张"给人话方位、不给坐标"，`doc-02 §3.2` 照抄 Nodesign 写了 `视口 (1234,567) 1920×1080 缩放 1.00`。裁决分两半：

| 问题 | 裁决 | 依据 |
|---|---|---|
| **注入块里出现什么** | **只出现人话方位词**，坐标数字一个都不出现 | `00 §5.1`、`00 §7`。注入要的是指代消解，不是几何 |
| **表里存什么** | **相机派生的几何**（视口中心点 + 尺寸；数字），由扩展渲染成人话 | 下列三条 |

存数字而不是存成品句子，理由三条：

1. **人话是渲染结果，不是状态。** `doc-21 §3.5` 已为事件表定下同一条纪律（"不存渲染后的句子"）。视点若存 `near the counter` 这种成品，措辞一改就要数据迁移；而措辞归 `02-分节表与渲染` 所有（`00 §13`），不该被冻结在 `canvas.db` 里。
2. **人话上不了线是安全属性。** `00 §5.2`（更正后）把本路由定为注入链路上唯一**新增的浏览器直连**输入，并要求所有进块文本过 `00 §14` 的 `sanitiseForBlock`。若前端可提交自由文本并原样进提示词，任何被劫持/重放的客户端都能把英文祈使句灌进作家上下文。存**机器规范化的数字**、渲染发生在扩展侧，线上就永远没有散文。
3. **共享函数是几何函数。** `00 §5.3` 要的"同一份量化函数"本质就是"相机 → 规范化几何"这个纯函数（1/8 视口网格，§3.2）。存人话等于把渲染结果烧进库，两端再无法断言"逐字一致"。


### 2.2 `viewpoint` 表 DDL（最终）

落点：`packages/shared/src/db/schema.ts::initCanvasDatabase`（`schema.ts:3-87`），与 `presence` / `links` 同级，在末尾 `CREATE INDEX idx_links_layer`（`schema.ts:86`）之后追加：

```sql
-- The player's viewpoint (00 §5.1). NOT part of the world: one singleton row,
-- never snapshotted, never rolled back, dead after 10 minutes (the TTL lives
-- in readViewpoint, not here). A single-player world (doc-05 §6) is why one row
-- suffices; a future multiplayer world adds `player_id` and drops the DEFAULT.
CREATE TABLE IF NOT EXISTS viewpoint (
  id         TEXT PRIMARY KEY DEFAULT 'singleton',
  layer      TEXT NOT NULL DEFAULT '',   -- 当前层 id（世界根相对，如 world/baker-street；'' = 不在任何层）
  focus      TEXT NOT NULL DEFAULT '',   -- **编码的视口中心**：'x:y'（不是人话！人话是渲染产物，见下）
  focus_x    INTEGER NOT NULL DEFAULT 0, -- 视口几何的镜像列（供摆位/调试；注入不用）
  focus_y    INTEGER NOT NULL DEFAULT 0,
  focus_w    INTEGER NOT NULL DEFAULT 0,
  focus_h    INTEGER NOT NULL DEFAULT 0,
  selected   TEXT NOT NULL DEFAULT '[]', -- JSON 字符串数组：选中的卡片路径
  bag_count  INTEGER NOT NULL DEFAULT 0,
  at         TEXT NOT NULL               -- ISO 时间戳，做 TTL
);
```

**列裁决：**

| 列 | 收 | 理由 |
|---|---|---|
| `layer` | 收 | 两个探针点（§2.6）与 `viewpoint` 节都要它。取值是 web 侧 `useWorld().layer` 原样（`apps/web/src/state/useWorld.ts:65` `INITIAL_LAYER = 'map'`；子层是 `world/<dir>`，见 `apps/web/src/App.tsx:294` 的拼接），与 `GET /api/layer?layer=` 同一 id 空间（`apps/server/src/routes/world.ts:280`） |
| `focus`（+ `focus_x/y/w/h`） | 收，存**编码中心**（`focus`），并镜像成四列整数（DDL 与 `00 §5.1` **逐字一致**） | §2.1。`focus` 是 `readViewpoint` 的权威来源；四列是给 SQL/诊断用的**同值镜像**（如"玩家是否在看某张卡附近"），单行表开销可忽略。`focus = ''` = 视口未知。**不做 1/8 量化**（中心点不是位移） |
| `selected` | 收 | `doc-02 §3.2` 消解优先级第一位是"选中的"。**今天前端没有选中模型**（§5.6），列先留着 |
| `bag_count` | 收 | 前端现成（`apps/web/src/App.tsx:28,103` 的 `backpackItems.length`，经 `:366` 传给侧栏）。**只作一句计数**；清单归 `02` 的 `bag` 节，同 `00 §3.2` |
| `at` | 收 | TTL。**服务端时钟**，见 §4.2 |

**为什么中心点而不是矩形**：`ViewpointRecord.focus` 的契约就是"视口中心"（§2.3），消费方 `02` 要的是"玩家在看哪一点"，以便与卡片盒做方位比较；尺寸在注入块里不出现（§2.1）。`focus_w/h` 只作诊断镜像。**列名 `focus` 与 `00 §5.1` 一致**（本节即 DDL 真源）；若后续改名（如 `view_rect`），同步本节与 `ViewpointRecord` 即可。

**不加 `camera` / `zoom` 两列**（`AUDIT §3.4` 提 Nodesign 存了。`zoom` 是它相机模型的中间量：我们只从它派生矩形后即丢，本表根本看不见 `zoom`）。**不加 `openWindow` / `openPage`**：`openPage` 在 Nodesign 是死字段（`AUDIT §3.4`）；AIRP 没有"产物窗口"这一层。

**迁移纪律**（跟 `presence` / `links` 一致，`schema.ts:24-27`）：`initCanvasDatabase` 在**每次 store 构造**时跑（`local-store.ts:63-72`）。本表是**新增**且 `CREATE TABLE IF NOT EXISTS`，不会 DROP 任何东西；**不得**为它写任何 shape-probing rebuild（没有历史包袱）。

### 2.3 `ViewpointRecord` 与 `readViewpoint`（冻结签名）

`ViewpointRecord` 与 store 方法名已与 `Design06`、`Design03` 对齐（`00 §5.1/§5.3` 定案）。落点 `packages/shared/src/store/world-store.ts`（接口，紧邻 `PresenceRecord`，`world-store.ts:34-41`）：

```ts
/** The player's viewpoint row, decoded (00 §5.1). `focus` is the view CENTRE. */
export interface ViewpointRecord {
  /** Layer id verbatim from the browser: 'map' or 'world/<dir>'. */
  layer: string;
  /** Viewport centre in world coords, or null when the browser reported no camera. */
  focus: { x: number; y: number } | null;
  /** Selected card paths (world-root relative). */
  selected: string[];
  /** Player's backpack size at report time; the LIST is section 02's `bag`. */
  bagCount: number;
  /** ISO report time, server clock. */
  at: string;
}
```

接口成员（`world-store.ts:50-174`，加在 `getPresenceOf` 附近的 presence 组里）：

```ts
/** The singleton viewpoint row, or null when the table is absent / empty / stale. */
readViewpoint(now?: number): ViewpointRecord | null;
```

**为什么是 store 方法而不是自由函数**（答复 `Design06` 的提问，已 IRC 确认）：两个待合并的探针点手里都已经有 `store`（`look-at.ts:171-181` 的 `ctx.store`、`deps.ts:51-60` 的 `worldStore(ctx)`），合并成本就只剩"删掉重复的 SQL"。若做成自由函数，两处仍要各写一次"取 store"的样板，等于没合并。

**为什么同步（不返回 Promise）**：走 `queryCanvas`（`local-store.ts:323-326`，`stmt.all()` 同步），与 `getPresence`（`local-store.ts:1087`）同一形状。作为 store 方法却是**唯一**的同步读，用注释交代清楚（`LocalWorldStore` 的约定是 async，见 `world-store.ts:52-133`；这里是同步的 `getLayerCards` 家族，`:91`、`:504`）。

**实现（`packages/shared/src/store/local-store.ts`）—— 表不存在是常态，探一下，别让异常穿出去：**

```ts
/**
 * The singleton viewpoint row (00 §5.1). The table only exists once B2 has run
 * `initCanvasDatabase`, and a world that never saw a browser has no row — both
 * are ordinary, so the probe swallows its failure (same judgement as
 * `readPresence`, look-at.ts:285-305: an empty answer beats a throw).
 *
 * TTL is applied HERE and never written back: expiry means "the player is gone",
 * which is a fact about the clock, not a state change worth persisting.
 */
readViewpoint(now: number = Date.now()): ViewpointRecord | null {
  let row: Record<string, unknown> | undefined;
  try {
    row = this.queryCanvas('SELECT layer, focus, selected, bag_count, at FROM viewpoint LIMIT 1')[0];
  } catch {
    return null; // no table (any world that predates B2)
  }
  if (!row) return null;
  const at = String(row.at ?? '');
  const atMs = Date.parse(at);
  if (!Number.isFinite(atMs) || now - atMs > VIEWPOINT_TTL_MS) return null; // stale → absent
  return {
    layer: typeof row.layer === 'string' ? row.layer : '',
    focus: decodeCentre(typeof row.focus === 'string' ? row.focus : ''),
    selected: parseSelected(row.selected),
    bagCount: Number(row.bag_count ?? 0) || 0,
    at,
  };
}
```

`VIEWPOINT_TTL_MS = 10 * 60 * 1000`（10 分钟，`00 §5.1`）放在 `local-store.ts` 模块级并导出（测试要引用同一个数）。`decodeCentre` / `parseSelected` 是本文件**私有**小函数，**必须对坏数据免疫**：

- `decodeCentre(text)`：空串 / 非 `x:y` 两段 / 非有限数 → `null`（不抛）；
- `parseSelected(v)`：非字符串 / JSON 解析失败 / 非数组 → `[]`；数组内非字符串项被丢弃。

**`focus` 不做 1/8 量化**：`quantiseViewRect` / `encodeViewRect` 是给**位移**（视口左上角）用的；中心点不是位移，量化它只会让 `focus` 与 `focus_x/y` 镜像出两个不同数。

### 2.4 写入：`POST /api/viewpoint`

落点：`apps/server/src/routes/world.ts`，**正是 `:466-470` 那条注释预留的位置**（注释说"/api/viewpoint belongs to B2 / doc-22 §9"）。路由挂载前缀 `/api`（`apps/server/src/index.ts:56-58`）。

```
POST /api/viewpoint
  body: { layer?: string, camera?: { x: number; y: number; w: number; h: number }, bagCount?: number, selected?: string[] }
  200 : { ok: true, at: '<ISO>' }        // 写了
  400 : { ok: false, code: 'invalid_argument', error: '...' }   // 整份拒绝，旧值不动
```

```ts
// The player's viewpoint (00 §5). Replaces the B1 placeholder comment above.
// No event, no WS frame: this is a current-value report, not a world change
// (doc-21 §8 — there is no `state_changed`; doc-22 §6 — the row is not the world).
router.post('/viewpoint', (req, res) => {
  const store = getActiveStore();
  if (!store) return res.status(400).json({ error: 'No active world' });
  const v = sanitizeViewpoint(req.body);
  if (!v) {
    return res.status(400).json({ ok: false, code: 'invalid_argument', error: 'viewpoint report rejected' });
  }
  const at = store.writeViewpoint(v); // the ONE writer; returns the server-stamped `at`
  res.json({ ok: true, at });
});
```

**同步 handler**（不 `await`）：`writeViewpoint` 走 `execCanvas`（`local-store.ts:328-331`），与 `arrange` 系列的同步写法一致；`reply()`（`world.ts:45-63`）是给 `ActionError` 用的，本条不是 action，**不写事件、不走 action 层**（`doc-21 §8`：事件表只记变化）。

`sanitizeViewpoint` 与 `writeViewpoint` 的落点见 §4.1 / §2.5。**200 的 `at` 来自 `writeViewpoint` 的返回值**——`sanitizeViewpoint` 不产出 `at`（它只归一化输入，`at` 是服务端时钟盖章，§4.1 表末行），路由不读 `v.at`（`v` 里没有这个字段）。**body 只回 `at`**：前端 fire-and-forget（§5.3），不需要回显。

### 2.5 `writeViewpoint`（store 方法）

```ts
/** Overwrite the singleton viewpoint row (00 §5.1). The server owns `at`.
 *  `focus` is the view CENTRE in world coords — the `focus` COLUMN keeps that
 *  wire-encoded form for symmetry, and the EXPLICIT x/y columns keep it
 *  queryable by SQL. */
writeViewpoint(v: {
  layer: string;
  focus: { x: number; y: number; w: number; h: number } | null;
  selected: string[];
  bagCount: number;
}): string {
  const at = new Date().toISOString();
  this.execCanvas(
    `INSERT INTO viewpoint (id, layer, focus, focus_x, focus_y, focus_w, focus_h, selected, bag_count, at)
     VALUES ('singleton', ?, ?, ?, ?, ?, ?, ?, ?, ?)
     ON CONFLICT(id) DO UPDATE SET
       layer = excluded.layer, focus = excluded.focus,
       focus_x = excluded.focus_x, focus_y = excluded.focus_y,
       focus_w = excluded.focus_w, focus_h = excluded.focus_h,
       selected = excluded.selected, bag_count = excluded.bag_count, at = excluded.at`,
    [
      v.layer,
      encodeCentre(v.focus),
      // The mirror columns are NOT NULL INTEGER (00 §5.1): 0 when unknown, and
      // rounded so they match `focus`'s 'x:y' exactly (same value, two forms).
      v.focus ? Math.round(v.focus.x) : 0, v.focus ? Math.round(v.focus.y) : 0,
      v.focus ? Math.round(v.focus.w) : 0, v.focus ? Math.round(v.focus.h) : 0,
      JSON.stringify(v.selected), v.bagCount, at,
    ]
  );
  return at;
}
```

`at` 由**服务端**生成，不信任客户端时间（`00 §5.2` "一律 sanitize"；客户端的时钟可能明显偏斜，会让 TTL 立刻过期或永不过期）。

**为什么 `focus` 列存"编码中心"而不是矩形**：入库的矩形已经被 `sanitizeViewpoint` 折成中心（§4.1），服务端不会再拿到原始的 `top-left + w/h` 组合——这是 §2.1 "存中心点" 决定的**直接后果**，不是设计缺陷。`encodeCentre({x,y})` 是一个**按需在写侧内联**的极简编码（`${Math.round(x)}:${Math.round(y)}`，约 3 行，不导出），**不**复用 `encodeViewRect`（那是宽高矩形、走 1/8 量化网格、且带步长字段）。因此 §11.1 的 grep 纪律只约束 `quantiseViewRect` 家族的使用方（前端 hook + 路由 sanitize），不约束 `writeViewpoint`。

若某天要重游"存整矩形"，把 `focus_x..focus_h` 四列填满即可——**DDL 已经预留**，无需再迁移。

## 3. 共享量化函数（`00 §5.3`）

### 3.1 落点与签名

落点：**`packages/shared/src/render/viewpoint.ts`**（新文件）。

选 `render/` 而不是 `extensions/` 或 `spatial.ts` 的理由：

- `00 §9` 实测：**模块级状态是 per-extension-file**（loader 对每个扩展文件各建 `createJiti({moduleCache:false})`）→ 放在 `extensions/` 下的东西只对 `extensions/context.ts` 一个文件可见，**根本不满足"共享"**。`packages/shared/` 才是真共享面。
- **不塞进 `spatial.ts`**：那个文件是 `doc-03 §5.4` 的方位词器（box→词），词汇与阈值被 `doc-03 §13.1` 冻结（`spatial.ts:1-9`）。视口量化是另一回事（相机→矩形→格），混进去会让两个冻结契约互相牵连。
- 服务端（`apps/server`）与前端（`apps/web`）**都已经依赖 `@airp/shared`**：`apps/server/package.json:11`、`apps/web/package.json:11` 都是 `"@airp/shared": "workspace:*"`，前端已在用（`apps/web/src/components/canvas/CanvasObject.tsx:4` `@airp/shared/forms`）。**`render/*` 目前够不到**（见 §3.4），必须加导出。

**为什么仍然是净新增文件**：`apps/web` 与 `apps/server` 之间今天**没有任何直接共享的 TS**——`apps/web/src/lib/camera.ts:76-81` 的 `hashInt` 是 `apps/server/src/routes/world.ts:70-71` `hashInt` 的手抄副本，注释明说要保持同构。`00 §5.3` 要终止的正是这种模式，`viewpoint.ts` 是第一个真正做到的文件。

签名（**纯函数、无 I/O、无 DOM、无 Date**）：

```ts
/** An axis-aligned world-space view rectangle. Matches the camera model of
 *  apps/web/src/lib/camera.ts (screen = world * z, centred): the visible world
 *  rect's top-left is (cam.x - vw / (2 * z), cam.y - vh / (2 * z)). */
export interface ViewRect { x: number; y: number; w: number; h: number; }

/** The 1/8-viewport grid step for a rect ('doc-22 §5' gate 2). Pure; the ONE
 *  definition of "the camera moved" on both ends of the wire. */
export function viewStep(w: number, h: number): { sx: number; sy: number };

/** Floor a view rect onto its own 1/8 grid. Sub-step motion collapses to the
 *  same output. Called by the browser BEFORE it decides to report. The server
 *  does NOT re-quantise the wire rect — it does not need it: `sanitizeViewpoint`
 *  folds the rect to a CENTRE, and a centre is not a displacement (§2.3). */

/** The wire form: 'x:y:sx:sy' (integers). '' when there is no view rect. */
export function encodeViewRect(rect: ViewRect | null): string;

/** Inverse of encodeViewRect. Anything that is not exactly 4 integer fields → null. */
export function decodeViewRect(text: string): { x: number; y: number } | null;

/** The stable change key for a report: quantised layer + camera + selected +
 *  bagCount. Two reports with the same key are the same viewpoint (doc-22 §5,
 *  gate 1: the browser only POSTs when this changes). */
export function viewpointKey(input: {
  layer: string;
  camera: ViewRect | null;
```

### 3.2 量化规则（同一份定义，两端共用）

Nodesign 的两处内联（反面教材，`AUDIT §1`）：

- 前端 `~/projects/Nodesign/web/src/components/canvas/useViewpointReport.js:33`：`Math.round(camera.x / Math.max(1, camera.w / 8))`
- 服务端 `~/projects/Nodesign/server/engine/agent/turn-state.js:160-163`：`Math.round(vp.camera.x / Math.max(1, vp.camera.w / 8)) * Math.round(vp.camera.w / 8)`

两者**表面相似、实际不同**：前端只把**商**拿去拼 key（`x` 从未被量化回去）；服务端把商**乘回步长**得到量化坐标。所以前端判定"没变"用的是格子号，服务端注入用的是**格子左下角坐标**——同一份视觉状态在两处得到**两个不同数**。共享函数必须把这两件事分开、且只定义一次：

```ts
/** doc-22 §5: a step of one eighth of the viewport. `Math.max(1, …)` keeps a
 *  degenerate viewport (a collapsing pane) from producing a zero/NaN step. */
export function viewStep(w: number, h: number): { sx: number; sy: number } {
  return { sx: Math.max(1, w / 8), sy: Math.max(1, h / 8) };
}

/** Floor onto the grid — NOT Math.round. `floor` covers a strictly half-open
 *  cell `[k*sx, (k+1)*sx)`, so a given output means exactly "inside this cell",
 *  with no boundary flicker between two adjacent readings. It is also
 *  idempotent (`q(q(r)) === q(r)`), which `Math.round(x/s)*s` is not for
 *  non-integer steps — and our steps ARE non-integer (1600 / 8 = 200,
 *  900 / 8 = 112.5). */
export function quantiseViewRect(rect: ViewRect): ViewRect {
  const { sx, sy } = viewStep(rect.w, rect.h);
  return {
    x: Math.floor(rect.x / sx) * sx,
    y: Math.floor(rect.y / sy) * sy,
    w: rect.w,
    h: rect.h,
  };
}
```

**`w/h` 不量化**：视口尺寸变了就是变了（`doc-22 §5` 的 1/8 只约束**位移**）。`w/h` 的步长只用来**定义位移的粒度**，这一点与 Nodesign 一致（`turn-state.js:163` 保留 `w: vp.camera.w`）。

**为什么不用 `Math.round`**（与 Nodesign 的一处有意偏离）：`Math.round` 会在两个相邻格子之间来回跳（相机停在 `k*sx + sx/2` 附近抖动时，量化值在 `k` 与 `k+1` 间反复）；更糟的是对**非整数步长**它不幂等（`sx = 112.5` 时 `round(round(x/sx)*sx/sx)*sx` 会二次移动），而 `Math.floor` 恒幂等。`floor` 同时让命题"量化值相等 ⇔ 位移 < 1 步"干净成立——这正是 §11.1 要证明的东西。这是**语义收紧**，不是行为兼容；两端一起改所以不会错位。

### 3.3 编码与 key

```ts
/** 'x:y:sx:sy', each component `Math.round`ed (the step is fractional: 900/8
 *  is 112.5 — the wire must stay ASCII-integer). `sx:sy` is the step for the
 *  reported `w/h`, so the viewport SIZE survives the round-trip inside a
 *  quantised bound. Deterministic across both ends. */
export function encodeViewRect(rect: ViewRect | null): string {
  if (!rect) return '';
  const q = quantiseViewRect(rect);
  const { sx, sy } = viewStep(rect.w, rect.h);
  return `${Math.round(q.x)}:${Math.round(q.y)}:${Math.round(sx)}:${Math.round(sy)}`;
}
```

`sx:sy` 让视口**尺寸**跨线存活（量化到整数步长），而不必再单列 `w/h`。`decodeViewRect` 只回 `{x,y}`（`focus` 的消费方只需要"看哪"），**`<= 4` 段一律 `null`**——这条（"非 4 段即 null"）正是 §11.1 那条 `decodeViewRect('1:2:3') === null` 断言覆盖的契约，不是"逐字往返"。

```ts
export function viewpointKey(input: {...}): string {
  const cam = input.camera ? encodeViewRect(input.camera) : '';
  return `${input.layer}|${cam}|${input.selected.join(',')}|${input.bagCount}`;
}
```

`viewpointKey` 供 `useViewpointReport` 判"要不要发"（§5.2），也是测试里断言"两次读数等价"的抓手。

## 4. 服务端 sanitize

### 4.1 落点与规则表

`apps/server/src/routes/world.ts` 模块级（`hashInt` 一带，`:65-75` 附近），紧邻 §2.4 的路由。

```ts
/** SHAPE gate only (00 §14.1 rule 4): the value must LOOK like a layer id.
 *  NOT dot-relative like `assertWorldPath` (presence.ts:29) — relative paths are
 *  meaningless outside the action layer. This is NECESSARY, NOT SUFFICIENT: it
 *  does not reject newlines / quotes / backticks / injected prose, and the value

  if (layer === 'map') return true; // MAP_LAYER, store/layers.ts:27
```

**`isPlausibleLayer` 是形状闸，不是消毒**（评审 B-6 / INJ-01）。它只保证"像层 id"；`layer` 进块前、`selected[]` 进块前，**都必须再过 `00 §14.1` 的唯一消毒函数** `sanitiseForBlock(raw, { maxLength })`（第四条规则：先满足本闸，再在其上过 1–3）。消毒是**折平**（剥换行/控制字符 → 单空格、收敛引号、限长），不是拒绝——形状合法的层 id 被清洗后照常入库：

```ts
import { sanitiseForBlock } from '@airp/shared'; // 00 §14；barrel 里由 00 §15 拥有

// inside sanitizeViewpoint, after the shape gate:

```

`num()` **不能照抄 Nodesign 的 `Number(v)`**：`Number(null) === 0` 且 `Number('') === 0`，两者都有限，会让 `camera: { x: null, … }` **通过**校验——而 `00 §11` 要求它整份拒绝（§11.3 专门测这条）。所以 `num` 必须**先要类型**：

```ts
/** Clamp a numeric field, or null when it is not a real finite number.
 *  NOT Nodesign's `Number(v)`: `Number(null)`/`Number('')` are 0 and would let a
 *  null camera component through — 00 §11 requires the whole report be refused. */
function num(v: unknown, min: number, max: number): number | null {
  if (typeof v !== 'number' || !Number.isFinite(v)) return null;
  return Math.min(max, Math.max(min, v));
}
```

`str(v, n)`：非字符串或超长 → `null`（沿用 `Nodesign viewpoint-store.js:32`）。

| 字段 | 规则 | 非法时 | 依据 |
|---|---|---|---|
| `layer` | `typeof === 'string'` 且 `length ≤ 300` 且**形状**过 `isPlausibleLayer()` 且**内容**过 `sanitiseForBlock(…, {maxLength:300})` | **整份拒绝**（形状不合法）/ **折平**（内容可疑） | 空字符串是合法的"未进入任何层"；非空但不合形 = 伪造（`00 §14.1` 第 4 条：形状闸之上再过 1–3） |
| `camera` | 缺省 / `null` → `null`（合法，视口未知）；否则必须是对象，且 `x/y` 是 `[-1e6, 1e6]` 内的有限数、`w/h` 是 `[1, 1e5]` 内的有限数（**用上面的严格 `num`，`null`/`''` 一律算非法**） | **任一分量非法 → 整份拒绝**（不是逐项置 null） | `Nodesign viewpoint-store.js:26-31`：`if (camera && Object.values(camera).some(v => v === null)) return null`。一个半残的矩形会让渲染方画出边界怪东西；要么整块可信、要么不要 |
| `bagCount` | 有限整数，clamp 到 `[0, 999]` | clamp | `00 §5.2` 数值 clamp |
| `selected` | 数组 → 只留 `string` 且 `length ≤ 300`；逐项 `sanitiseForBlock(…, {maxLength:300})`；`slice(0, 24)` | 非数组 → `[]` | `00 §5.2` "数组截断（上限 24）"；**`selected[]` 是第二条注入面**（`02` 用引号回显，评审 INJ-02），必须过 `00 §14` |
| `at` | **忽略请求里的值**，服务端 `new Date().toISOString()` | — | §2.5；TTL 不能被客户端时钟操纵 |

顶点数（`1e6` / `1e5`）直接照 `Nodesign viewpoint-store.js:28-29`；这些数只是荒诞值护栏，真实画布的坐标在 `SEAT_ANCHOR = {x:960, y:540}`（`local-store.ts:21`）量级。

```ts
/** The one NEW browser-direct input on the injection path (00 §5.2, 更正后 —
 *  world files / `god-action` are pre-existing channels, §14). Rejects the WHOLE
 *  report on a malformed camera — a half-believed rect is worse than none.
 *  Every accepted STRING is then folded through `sanitiseForBlock` (00 §14). */
function sanitizeViewpoint(raw: unknown): {
  layer: string;
  focus: ViewRect | null;
  selected: string[];
  bagCount: number;
} | null {
  if (!raw || typeof raw !== 'object') return null;
  const body = raw as Record<string, unknown>;

  const rawLayer = typeof body.layer === 'string' && body.layer.length <= 300 ? body.layer : '';
  if (rawLayer !== '' && !isPlausibleLayer(rawLayer)) return null;
  // Content-level pass (00 §14.1 rules 1-3): fold newlines / control chars /
  // quotes and cap length. The shape gate above is NOT enough (INJ-01).
  const layer = sanitiseForBlock(rawLayer, { maxLength: 300 });

  let focus: ViewRect | null = null;
  if (body.camera !== undefined && body.camera !== null) {
    if (typeof body.camera !== 'object') return null;
    const c = body.camera as Record<string, unknown>;
    const x = num(c.x, -1e6, 1e6);
    const y = num(c.y, -1e6, 1e6);
    const w = num(c.w, 1, 1e5);
    const h = num(c.h, 1, 1e5);
    if (x === null || y === null || w === null || h === null) return null;
    // The wire sends the world-space visible rect's TOP-LEFT. `focus` is the
    // CENTRE in WORLD coords (ViewpointRecord's contract): `camera.x` already
    // equals `cam.x - vw / (2 * z)` (see apps/web/src/state/useCamera.ts:82-90
    // and lib/camera.ts:57-74), so the centre is x + w / 2.
    focus = { x: x + w / 2, y: y + h / 2, w, h };
  }

  const rawBag = num(body.bagCount, 0, 999);
  const bagCount = rawBag === null ? 0 : Math.trunc(rawBag);

  const selected = (Array.isArray(body.selected) ? body.selected : [])
    .filter((s): s is string => typeof s === 'string' && s.length <= 300)
    .slice(0, 24)
    .map((s) => sanitiseForBlock(s, { maxLength: 300 }));

  return { layer, focus, selected, bagCount };
}
```

**`focus` 为什么折成中心点而不留矩形**：`ViewpointRecord.focus` 的契约就是"视口中心"（§2.3），消费方 `02` 要的是"玩家在看哪一点"，以便与卡片盒做方位比较。尺寸在注入块里不出现（§2.1），只作 `focus_w/h` 诊断镜像。中心点 = `top-left + w/2`（与 `apps/web/src/lib/camera.ts:57-74` 的 `screenToWorld` 同一"`cam` 在视口中心"约定，`worldTransform` `:72-74` 可证）。

**服务端不再量化**：量化（1/8 视口网格）是**位移**的粒度属性，在浏览器侧对**矩形左上角**做一次（§5.3），服务端收到已量化的矩形后只折中心。这就是 §11.1 那条 grep 允许 `world.ts` 出现 `Math.round`（`encodeCentre` 的取整）但不出现 `/ 8` 的原因——它没有第二份量化实现。

**边界情形**：`bagCount` 缺失 → `0`（新玩家空背包）；`selected` 缺失 → `[]`；`camera` 缺失 → `focus = null`，`viewpoint` 节仍可只报"玩家在 `<layer>`"（措辞归 `02`）。

### 5.3 行为（变化触发 + 1.2s 节流 + fire-and-forget）

```ts
export function useViewpointReport({ camera, layer, bagCount, enabled = true }: UseViewpointReportInput): void {
  const lastRef = useRef({ key: '', at: 0, timer: null as ReturnType<typeof setTimeout> | null });

  useEffect(() => {
    if (!enabled) return undefined;

    const send = (payload: ViewpointReport) => {
      lastRef.current.at = Date.now();
      lastRef.current.timer = null;
      // fire-and-forget: a dropped report is one stale minute at worst (00 §11).
      void fetch('/api/viewpoint', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(payload),
      }).catch(() => { /* one lost frame of viewpoint is not worth a toast */ });
    };

    const check = () => {
      const cam = camera.getCam();          // useCamera.ts:159
      const vp = camera.getViewport();      // useCamera.ts:161
      if (!vp.w || !vp.h || !Number.isFinite(cam.x) || !Number.isFinite(cam.y) || !Number.isFinite(cam.z)) {
        return;                              // nothing sane to report yet
      }
      // World-space visible rect — the SAME camera model as lib/camera.ts:57-74
      // (screen = world * z, centred on cam). Quantised by the shared function.
      const rect = quantiseViewRect({
        x: cam.x - vp.w / (2 * cam.z),
        y: cam.y - vp.h / (2 * cam.z),
        w: vp.w / cam.z,
        h: vp.h / cam.z,
      });
      const key = viewpointKey({ layer, camera: rect, selected: [], bagCount });
      const st = lastRef.current;
      const silentFor = Date.now() - st.at;
      // Slow heartbeat (00 §5.1.1): report on the clock even when the key is
      // unchanged, or the 10-min TTL expires and cascades layer_files / cast away.
      if (key === st.key && silentFor < VIEWPOINT_HEARTBEAT_MS) return;

      const payload = { layer, camera: rect, bagCount, selected: [] as string[] };
      const wait = Math.max(0, VIEWPOINT_MIN_INTERVAL_MS - (Date.now() - st.at));
      if (st.timer) clearTimeout(st.timer);
      // Record the key NOW, before the timer: otherwise a moving camera keeps
      // re-arming the timer and the trailing edge can starve forever.
      st.key = key;
      st.timer = wait === 0 ? (send(payload), null) : setTimeout(() => send(payload), wait);
    };

    const unsubscribe = camera.subscribe(check); // fires immediately with the current view (useCamera.ts:164)
    return () => {
      unsubscribe();
      if (lastRef.current.timer) { clearTimeout(lastRef.current.timer); lastRef.current.timer = null; }
    };
  }, [camera, layer, bagCount, enabled]);
}
```

**与 Nodesign 的三处差异（都要写进实现的注释）：**

1. **触发源**：Nodesign 把 `cam` 当 props 放依赖数组（`useViewpointReport.js:44`），React 每次渲染重跑 effect。AIRP 的相机**不在 React 状态里**（`useCamera.ts:20-22`），必须 `subscribe`（`useCamera.ts:162-168`）。`subscribe` 自带"立即用当前 view 调一次"，所以**首帧就会报到一次**，不需要额外的 mount 上报。
2. **key 立即写入**：Nodesign 把它放在 `send()` 里（`useViewpointReport.js:37`）。节流窗口内的抖动会让 `check` 反复通过（key 还是旧值）→ 每次都清/重设定时器 → 相机持续动时**可能一直不发**（尾沿饥饿）。先写 key 则"窗口内只认第一次变化"，1.2s 后必发一次。
3. **量化用共享函数**，不用内联表达式（`00 §5.3`）。
4. **慢心跳**（§5.3.1）：Nodesign 只在语义变化时发，静坐时 TTL 到点就断链；AIRP 另加一个与语义无关的定时重发。

**为什么是 1.2s**：`doc-22 §5` 闸 1、`doc-02 §3.2`。注入侧另有 10 分钟 TTL（§6），两者不是一回事：1.2s 是**上报频率**上限，TTL 是"多久算离开"。

### 5.3.1 慢心跳（`00 §5.1.1`，评审 A-3 定案 (a)）

**裁决：选 (a) 慢心跳，解耦层与新鲜度另案。** 理由：`deps.layer` 派生自 `viewpoint.layer`，若玩家**静坐**在同一层 11 分钟而前端只在语义变化时上报，TTL 到点会让 `viewpoint` 节缺席，并**级联**带走 `layer_files` / `cast`（`00 §11` 第 2 行）——三节同时消失，比"视点过期"严重得多。心跳用最低成本把 TTL 钉在"玩家真的关了页面"这件事上，而不必改动 03/06 的按层读取路径。

**周期与触发条件**（两段式）：

1. **周期**：`VIEWPOINT_HEARTBEAT_MS = 5 * 60 * 1000`（TTL 的一半；§3.1）。半个 TTL 留出一整次心跳丢失的余量——丢一拍仍有 5 分钟才过期。
2. **触发条件**：与语义无关。`setInterval` 或 `check` 内的"距今 ≥ 心跳周期且 `enabled`"两选一；最小实现是 `check` 里加一个 `now - st.at >= VIEWPOINT_HEARTBEAT_MS` 的分支，**不比对 `key`**，直接 `send` 当前读数（`key` 相同也发，这正是心跳与变化上报的区别）。`enabled=false`（眼睛页）时同样不发。
3. **失败/离线**：页面关闭即无心跳 → TTL 正常生效（这正是想要的）；心跳请求本身 fire-and-forget，失败再等半周期。

落地实现者的注释要求：心跳**不得**改变 1.2s 节流语义（节流管变化上报的密集度，心跳管静默期的下限）；两者共用 `send`，但心跳分支跳过 `key === st.key` 的短路。

### 5.4 `?eye=1` 排除（落地日的工作）

`doc-02 §3.3` 定：agent 的眼睛模式复用**玩家看的同一张画布页**（`?eye=1`），页面摆好相机后打 `data-eye-ready` 标记供截图。**那张页面上报就会撒谎**——那是 agent 在看，不是玩家在看。

**现状（已核实）**：`grep -rn "eye\|data-eye-ready\|searchParams\|URLSearchParams\|location.search" apps/web/src` → **零命中**。前端**没有任何** eye-mode 消费者，`?eye=1` 也没有读者（`docs/tools/03-look-at与画布感知.md:781` 记载了同一实测结论）。所以本批只冻结**契约**，落地日一次性接上：

1. 在 `App.tsx` 顶层读一次 `new URLSearchParams(location.search).get('eye') === '1'`；
2. 把它作为 `enabled={!isEyeMode}` 传给 `useViewpointReport`；
3. 同一处顺带把 `data-eye-ready` 标记补上（`doc-02 §3.3`，属眼睛模式批次，不属本批）。

**必须写成注释的理由**：flag 一旦漏掉，agent 自己的眼睛页会持续覆盖玩家的视点上报，症状是"玩家视点莫名跳到 agent 想看的地方"——离病因很远，值得一行注释。

## 6. TTL

1. **10 分钟**（`00 §5.1`），常量 `VIEWPOINT_TTL_MS` 落 `packages/shared/src/store/local-store.ts` 并导出（只有 store 与测试用它）。
2. **判定在读取侧**（`readViewpoint(now?)`，§2.3），**不在写入侧、不落盘清理**。理由：过期是关于时钟的**事实**，不是值得持久化的状态变化（`doc-21 §8`：事件表只记变化；而这里连事件都不该有）。
3. **过期 = 该节整节缺席，且级联**（`00 §5.1.1` / `00 §11` 第 2 行，评审 A-3）。`readViewpoint` 返回 `null` 后，**`viewpoint` 节缺席会连带 `layer_files` 与 `cast` 缺席**——`deps.layer` 派生自 `viewpoint.layer`。`bag` / `recent_chalk` / `dynamics` **不受影响**（不依赖当前层）。防线是 §5.3.1 的慢心跳：玩家真在坐着时**不该**出现这种级联。
4. **三种缺席同形**：表不存在 / 无行 / 过期，都 `return null`。消费侧不需要区分（"看不见的注入比错误的注入好"，`00 §11`）。
5. **测试要能操纵时间**：`readViewpoint(now?)` 的 `now` 参数就是为此——测试传 `at + 10 * 60 * 1000 + 1` 断言 `null`，不需要假时钟。

```js
  body: JSON.stringify({ layer: 'map', selected: Array.from({ length: 40 }, (_, i) => `world/x/${i}.md`) }),
});
assert.equal(capped.status, 200);
assert.equal(store.readViewpoint().selected.length, 24);

// A layer that is not world-root relative is rejected outright.
const forged = await fetch(`${base}/viewpoint`, {
  method: 'POST', headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ layer: '../../etc' }),
});
assert.equal(forged.status, 400);
```
