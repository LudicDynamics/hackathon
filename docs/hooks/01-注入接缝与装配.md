# 01 — 注入接缝与装配（`context` 接线 · 轮边界缓存 · 纯函数切分 · 三层兜底）

> 本篇是 B2/B3 设计批次的第 01 篇，只写**装配管线**：注入挂在哪个钩子、一次轮边界怎么算一次、`collectSections` 与 `renderState` 的边界与签名、三层 fail-soft、以及哪些代码必须落在 `packages/shared/` 才能单测。
> 跨篇共享的形状（`Section`、线格式、条目上限、视点表、游标语义、失败纪律）一律以 **`docs/hooks/00-共同上下文.md`** 为准，本文只按节号引用，不重述。分节表**内容**（键名、英文格式、来源函数、上限、方位词）归 **02**；`WorldEvent` → 人话渲染器归 **03**；`next_step` 措辞与 `computeNextStep` 归 **04**；`viewpoint` 表 / `readViewpoint` / sanitize 归 **05**；扩展注册、身份解析、缓存失效钩子集、只读裁决、探针归 **06**。
> **本节（§2.1）的 handler 体是全批次唯一版本**：06 只负责把它落到 `extensions/context.ts`，**不得另写一份**。06 自己的骨架曾出现 `[...event.messages, block]`（丢掉第 1 步的过滤）与零参 `stateBlockForThisTurn()`——那两点都与本节冲突（评审 A-6）。06 必须原样引用本节，特别是 (1) **过滤旧块**与 (2) **用 `ctx.sessionManager.getSessionId()` 读缓存**两步。
>
> 结论先行（六条拍板）：
> 1. **注入挂在 `pi.on('context')`**（`runner.ts:1133-1163`），handler **只做字符串取值 + 拼一条消息**，零 I/O（契约 §1 裁决 1 / §2 约束 1）。
> 2. **重活只在 `agent_start` 算一次**（`agent-loop.ts:109`，信号由 `agent-session.ts:1032-1037` 转发），结果写进**轮边界缓存**；`context` 只读缓存。
> 3. **缓存实现落在 `packages/shared/`**（NEW `inject/turn-cache.ts`）：键 = `sessionId`，单槽无条件覆写，无 LRU、无指纹（契约 §9.2，AUDIT §3.2）。
> 4. **纯函数切分**：`collectSections`（有 I/O、逐节 fail-soft）→ `buildNextStepFacts`（读备忘录、纯计算）→ `renderState`（**纯、同步、永不抛、永不返空串**）。三者都在 `packages/shared/`，扩展只调用。
> 5. **三层兜底**：逐节 `try/catch`（丢一节）→ 采集器只在有内容时返回非 null（空节整节缺席）→ 轮边界外层 `try/catch` 整块置 null（不注入）。契约 §11 的机器化。
> 6. **对 `event.messages` 先过滤再追加**：丢掉任何既有 `role:'custom' && customType==='airp_world_state'` 的消息，再尾追加本条。这样"每请求恰好一份"是**本地机制**，不靠引擎不累积的承诺（S2 是实测事实，但我们不把它当前提）。

## 2. 契约：`context` 接线

### 2.1 handler 的精确语义

> **唯一版本声明（评审 A-6）**：下面的 handler 体是**全批次唯一**的实现，06 落到 `extensions/context.ts` 时**必须原样引用**，尤其两个不可省掉的步骤：**(1) 过滤掉既有同 `customType` 的旧块**（否则"每请求恰好一份"失效），**(2) 经 `ctx.sessionManager.getSessionId()` 读缓存**（不是零参读取）。06 早期骨架里的 `[...event.messages, block]` 与 `stateBlockForThisTurn()` 与之冲突，作废。

```ts
// extensions/context.ts —— 由 06 建立该文件；本节的 handler 体由 01 定义。
// 依赖（NEW）：readTurnBlock / WORLD_STATE_CUSTOM_TYPE / collectSections /
// buildNextStepFacts / renderState / makeSectionDeps —— 见 §7 文件清单。
// 签名即 pi-rp 的 ExtensionHandler：`(event, ctx)`（`types.ts:1319`）。
// 只收 `(event)` 的单参写法拿不到 `ctx.sessionManager` —— 评审 A-26 即此处正文/签名不一致。
pi.on('context', (event, ctx) => {
  // (1) 过滤：丢掉任何既有的本类注入块。
  //     机制上这是不可达的（context 路径不落盘，S2），但把它当断言写下来：
  //     引擎若将来改语义、或别的扩展用同一 customType 持久注入，这里仍然保证
  //     「每请求恰好一份」是本地不变量，而不是对引擎行为的假设。
  const kept = event.messages.filter(
    (m) => !(m.role === 'custom' && m.customType === WORLD_STATE_CUSTOM_TYPE)
  );

  // (2) 取本轮缓存（同步、纯内存；sessionId 取自 ctx，见 §3.2）。
  const text = readTurnBlock(ctx.sessionManager.getSessionId());
  if (text === null) return;            // 组装失败 / 无槽 → 不注入（契约 §11）

  // (3) 尾追加一条自定义消息；不插中间、不碰 systemPrompt（契约 §2 约束 3）。
  return {
    messages: [
      ...kept,
      {
        role: 'custom' as const,
        customType: WORLD_STATE_CUSTOM_TYPE,
        content: [{ type: 'text' as const, text }],
        display: false,                 // 不进画布（契约 §2 约束 3）
        timestamp: Date.now(),          // CustomMessage 必填（messages.ts:112）
      },
    ],
  };
});
```

### 2.2 消息对象逐字段（冻结）

| 字段 | 值 | 依据 / 理由 |
|---|---|---|
| `role` | `'custom'` | `context` 路径下唯一能带 `customType` 的角色（AUDIT「S2 的附带发现」） |
| `customType` | `'airp_world_state'`（`WORLD_STATE_CUSTOM_TYPE`） | 冻结字符串；策略解析按它查（`messages.ts:269`），本地过滤按它丢（§2.1 第 1 步） |
| `content` | `[{ type: 'text', text }]` | 与 `CustomMessage.content` 联合类型一致（`messages.ts:109`）；与 06 §2.3 同款 |
| `display` | `false` | 契约 §2 约束 3：注入块绝不进画布（doc-05 §5） |
| `details` | **省略** | 只在 `display:true`（渲染）或持久化（`appendCustomMessageEntry`，`agent-session.ts:936`）时有消费者；本路径两者都不发生。将来若要给 `/prompt` 诊断留结构化数据，**才**补 `details` 并保持 `display:false` |
| `timestamp` | `Date.now()` | 类型必填；"纯"指无 I/O、无共享状态写入，不指引用透明 |

### 2.3 返回值的语义（引擎侧已核实）

- `runner.ts:1135` 先 `structuredClone(messages)`，handler 拿到的 `event.messages` **已经是副本**；
- `runner.ts:1146-1148`：只有返回对象**带 `messages` 字段**时才替换 `currentMessages`；返回 `undefined` 或 `{}` 等于不改；
- 替换数组**只喂给本次 provider 请求**，不写会话条目（`agent/src/agent-loop.ts:289-292` `transformContext` → `sdk.ts:443` `emitContext` → `:448` 返回给 `convertToLlm`）。这就是"每轮恰好一份、天然有界"的机制。
- **尾追加**而非插入：尾部追加对 prompt 缓存友好（AUDIT §3.1 对照表）。
- `context` 的 handler 第二参是标准 `ExtensionContext`（`types.ts:1319` `ExtensionHandler`），`ctx.sessionManager.getSessionId()` 同步无 I/O（`session-manager.ts:1037`）。

### 2.4 `renderContent`：本批不注册

`convertToLlm` 把 custom 转成普通 `user` 消息时会**丢掉 `customType`**（`messages.ts:268-294`；AUDIT §2.3 坑 3），所以"跨 seam 的身份"只能靠 `renderContent` 包一层标记。

**本批不需要**，理由与 06 §2.4 一致但给出更精确的边界：

- `customType` 的作用有**两个**，只有第二个受 seam 影响：
  1. **策略解析**（必需）——`convertToLlm` 在**转之前**按 `m.customType` 查 policy（`messages.ts:269`），所以 `compaction:'exclude'` 生效与否**只看声明**，与 seam 无关；
  2. **身份跨 seam 存活**（本批不需要）——注入块从不落盘、从不被回读，没有任何"存储往返"需要活下来。跨 seam 的身份由**文本首行的固定标记** `[World state]`（§4.2）承担。
- **前置条件（写进 `context.ts` 注释）**：若将来有人把注入块改走持久路径（`sendCustomMessage` / `before_agent_start` 的 `message`），**必须**同时补 `renderContent`，否则同一份文本会在 seam 上失去可辨识性。
- `registerCustomType` 的声明归 06 §2.1/§2.2（含"先声明者胜"，`loader.ts:210-214`）；本文只依赖其结论。

## 3. 轮边界缓存

### 3.1 轮边界锚：`agent_start`（`before_agent_start` 否决）

| 候选 | 触发次数 | 裁决 |
|---|---|---|
| `before_agent_start` | 每用户轮恰好一次（`agent-session.ts:2108`，唯一调用点） | **否决**：它的 `message` 会被持久化成 `custom_message` 会话条目并**逐轮累积**（`agent-session.ts:2107-2127` → `agent-loop.ts:110-113` → `agent-session.ts:936`，AUDIT S1 实测 3 轮见 3 块）。契约 §12 第 1 条 |
| `agent_start` | 每次 agent run 恰好一次（`agent/src/agent-loop.ts:109`；续写走 `:138`） | **采用**。事件体无 result 类型（`types.ts:800-802`），结构上无法误注入 |
| `turn_start` | 工具循环内每轮都触发 | 否决：轮边界要的是"每 run 一次"，且 `tools.ts` 已为 turn 锚注册（`extensions/toolkit/turn.ts:16-20`），跨扩展文件读不到其模块状态（契约 §9） |

**关键时序保证**：`agent_start` 的 emit 是 **await 的**，且发生在该 run 的第一次 provider 请求之前：

```
agent-loop.ts:109   await emit({ type: 'agent_start' })
  -> agent-session.ts:926   await this._emitExtensionEvent(event)        (awaited)
     -> agent-session.ts:1037   await this._extensionRunner.emit(...)   -> our handler
agent-loop.ts:116   await runLoop(...)      <- only THEN the first streamAssistantResponse
  -> agent/src/agent-loop.ts:290-291   config.transformContext(messages)
     -> sdk.ts:443   runner.emitContext(messages)   <- our context handler
```

所以 `agent_start` handler 即使是 `async`（要做 I/O），也**必然在第一个 `context` 之前完成**——缓存不会是"上一轮的"。这是把重活放 `agent_start` 的前提，本文冻结它。

### 3.2 缓存的实现契约（**01 拥有实现**）

**落点**：NEW `packages/shared/src/inject/turn-cache.ts`（不是 `context.ts` 里的裸模块变量）。理由：可以脱离引擎单测（write/read/会话不匹配/复位），且与 Nodesign 把 turn memory 的读写导出给测试的做法同构（`~/projects/Nodesign/server/engine/agent/turn-state.js:60-86`）。

```ts
// packages/shared/src/inject/turn-cache.ts (NEW, 01)
/**
 * Per-run state-block cache. Key = sessionId (00 §9.2).
 *
 * ONE slot, unconditionally overwritten at every turn boundary. There is NO LRU
 * and NO history: unlike Nodesign's `memory` Map (turn-state.js:49-51, MAX 300
 * sessions), we keep nothing to diff against, so there is nothing to evict and
 * nothing to leak. A long-lived multi-session process needs only the newest block.
 *
 * Module-level state is per-extension-file, not per-process: pi-rp builds one
 * jiti instance per extension file with `moduleCache:false`
 * (vendor/pi-rp/packages/coding-agent/src/core/extensions/loader.ts:503-509,
 * call site :556) — 00 §9. Only `extensions/context.ts` reads this module.
 */
interface Slot { sessionId: string; text: string }        // text is never '' (see §4.2)

let slot: Slot | null = null;

/** Called ONCE per run, at the `agent_start` boundary (06 §4.1). null = assembly failed. */
export function writeTurnBlock(sessionId: string, text: string | null): void {
  slot = text === null ? null : { sessionId, text };
}

/** Pure memory read. null = no slot, or the slot belongs to another session → do not inject. */
export function readTurnBlock(sessionId: string): string | null {
  return slot !== null && slot.sessionId === sessionId ? slot.text : null;
}

/** Test seam — mirrors `resetTurnStateMemory` (turn-state.js:300-302) in spirit, without sessions. */
export function resetTurnCacheForTests(): void { slot = null; }
```

**生命周期（一句话）**：`agent_start` →（异步采集）→ `writeTurnBlock(sessionId, block|null)` → 该 run 的每个 `context` 请求 `readTurnBlock(sessionId)`。

| 问题 | 答案 | 依据 |
|---|---|---|
| 键是什么？ | `sessionId`（`ctx.sessionManager.getSessionId()`，`session-manager.ts:1037`；`toolkit/turn.ts:31` 已用同一 API） | 契约 §9.2 |
| 什么时候写？ | 每 run 一次，在 `agent_start` handler 末尾 | §3.1 |
| 什么时候读？ | 每次 `context` 触发（含工具循环内每个请求、含 `previewPrompt`） | `runner.ts:1133` |
| 为什么不用 Map / LRU？ | 无差分、无历史 → 没有可淘汰的东西；单槽即最小正确实现 | AUDIT §3.2 裁决 2 |
| 会话不匹配怎么办？ | `readTurnBlock` 返回 `null` → 不注入（**不重算**） | §3.4 |
| 缓存会落盘吗？ | 不会，纯进程内存 | 契约 §10 |
| 失效钩子？ | **无**。每轮边界无条件覆写，不存在"沿用上一轮"的路径 | **归 06 §4.3**（本文只假定其结论） |

### 3.3 风险一：`context` 在工具循环的**每个**请求都触发

`agent-loop.ts:174-260` 的内层循环对每次工具调用后**再发一次** `streamAssistantResponse` → 再走一次 `transformContext` → 再触发一次 `context`。所以一个含 3 次工具调用的 run 里，我们的 handler 会跑 4 次。

**行为**：4 次都返回**同一段文本**（缓存同值）。这是**期望行为**——每个 provider 请求都要自足（注入块不落盘，请求 N 看不到请求 N−1 的块）。

**MUST NOT**：在 `context` 里重算（每请求扫盘 + 读两个 db，契约 §2 约束 1）；也**MUST NOT** 在 `context` 里推进游标（契约 §6.2「一个坑」：工具循环里每轮都推等于没消费）。游标结算归 03（§4.6）、由 06 §4.1 在**轮边界**调用一次。

### 3.4 风险二：`previewPrompt()` 也会触发

`agent-session.ts:1850-1857` 的 `previewPrompt()`（`/prompt` 预览，调用点 `commands/builtins.ts:436`）**直接** `emitContext`，**不经过 `agent_start`**。后果：

- 它拿到的是**上一次 `agent_start` 写下的块**；若刚换过分支（`/tree`）而本 run 还没开始，它会显示上一分支的块；
- 这条路径**不喂模型**，纯诊断。

**裁决**（与 06 §4.3 一致）：为它挂 `session_start` / `leaf_changed` 不值——**有意简化**，前提是"一个进程一个会话"（契约 §9；`launch.ts` 用 `--session` / `--continue` 钉住一个会话文件）。写进 `context.ts` 注释；若将来长驻进程多会话复用，补 06 §4.3 的两个清空钩子。

**同一风险的另一面**：`sessionId` 不匹配时 `readTurnBlock` 返回 `null`，于是**不注入**而不是注入陈旧块——这是安全侧的取舍（看不见的注入优于错误的注入，契约 §11）。

### 3.5 风险三：steer / followUp 中途插入的消息看到的是**本 run 起点**的块

`agent-loop.ts:259` / `:263` 的 steering / follow-up 消息在 **loop 内部**被取出，**不再触发 `agent_start`**（AUDIT §2.1 已核实：`agent-session.ts:2052-2055` 直接 return；`sendCustomMessage({triggerTurn:true})` 走 `_runAgentPrompt` 不触发 `before_agent_start`；续写走 `_runAgentContinue`）。

所以那一段插入的对话看到的是**同一份块**（run 起点算的）。**接受**，理由：
1. 块在时间上只陈旧几十秒，且世界变化会经 `dynamics` 出现在**下一次 run**；
2. 若为此在 `context` 里检测"块是不是本请求初次"并重算，就把 I/O 搬回了每次请求（违反契约 §2 约束 1）；
3. 有界性优先于新鲜度的极值（AUDIT §3.2 的"有界 > 省 token"同理）。

登记为待确认项 6。

## 4. 纯函数切分

### 4.1 `collectSections`（有 I/O，逐节 fail-soft）

```ts
// packages/shared/src/render/sections.ts (NEW, 02) —— SectionSpec / SectionCaps / SECTION_CAPS / sectionsFor
// packages/shared/src/render/state.ts    (NEW, 01) —— Section / renderState
// packages/shared/src/inject/collect.ts  (NEW, 01) —— 本节全部
import type { LocalWorldStore } from '../store/local-store.js';
import type { Actor } from '../actions/actor.js';
import type { ViewpointRecord } from '../store/world-store.js';   // 05 的类型，由本模块 re-export
import type { Section } from '../render/state.js';
import type { SectionSpec, SectionCaps } from '../render/sections.js';
import { renderEventWindow, type EventSlice, type EventWindow } from '../render/events.js';  // 03 冻结

/** What 02's collectors receive. Frozen with 02 (2026-09-12). */
export interface SectionDeps {
  store: LocalWorldStore;
  actor: Actor;
  reader: string | null;              // readerOfActor(actor); null = never reads events
  layer: string | null;               // resolved ONCE per turn by this module (§4.4)
  viewport: ViewpointRecord | null;   // 05's store method result; null = absent/stale
  now: number;                        // one clock read per turn
  caps: SectionCaps;
  /**
   * `{ [layerId]: displayName }`, built ONCE per turn from `store.getManifest().layers`
   * (`local-store.ts:286`; same source `presence.ts::readLayerName` uses). 03's renderer
   * consumes it to print a LAYER NAME where an event carries only a layer id (评审 A-17:
   * `detail.from/to` are ids, so `from world/baker-street` must become the display name).
   * Pure data; the fallback for a missing/stub layer MUST mirror `readLayerName`
   * (`presence.ts:112-121`) — shared helper, never a second copy of the fallback chain.
   */
  layerNames: Record<string, string>;
  /** MEMOISED: exactly one event read per turn, shared by dynamics + next_step. */
  events(): Promise<EventSlice>;
  /** MEMOISED: the merged/windowed/rendered view (03). Same underlying read as events(). */
  eventWindow(): Promise<EventWindow>;
}

/** collectSections' argument = SectionDeps + the section table (02's `sectionsFor(actor)`). */
export interface CollectContext extends SectionDeps { specs: readonly SectionSpec[] }

/**
 * Runs every spec, in table order, each inside its own try/catch (layer 1).
 * A spec returning null contributes NOTHING (layer 2). Never throws for a
 * section failure; a `warnOnce` line goes to stderr the first time each fails.
 */
export async function collectSections(ctx: CollectContext): Promise<Section[]>;

/**
 * Builds the memoised deps for one turn. Called once at the turn boundary.
 * `layerNames` is NOT an option: this function derives it once from
 * `(await store.getManifest()).layers` (local-store.ts:286) — one extra read per
 * turn, shared by 03's renderer (评审 A-17).
```

### 4.2 `renderState`（纯、同步、永不抛、永不返空串）

```ts
// packages/shared/src/render/state.ts (NEW, 01) —— PURE. No I/O, no clock, no module state.
import type { NextStepFacts } from './next-step.js';    // NEW, 04
import { computeNextStep } from './next-step.js';       // NEW, 04

/** 00 §3.1. `key` is frozen; `title` is metadata only; `text` is self-contained. */
export interface Section {
  key: string;
  title: string;
  text: string;
  items?: string[];
}

/** 00 §4.1 — the frozen marker the probe counts (06 §6.3 A1). */
export const STATE_HEADER = '[World state]';
export const STATE_EMPTY_WRITER = '[World state: nothing to report yet]';
export const STATE_EMPTY_CHARACTER = '[World state: nothing has happened here yet]';

/**
 * Renders the self-contained block for ONE turn (00 §1: every turn is a FULL
 * state block — no diff, no fingerprint). Pure and total: it never throws and
 * never returns ''. `text` fields are printed VERBATIM (02 §2.1: each section's
 * text contains its own label line); `title` is never printed.
 *
 * @param facts 04's NextStepFacts; `facts.role` also selects the empty-block wording.
 */
export function renderState(sections: readonly Section[], facts: NextStepFacts): string {
  const body = sections.map((s) => s.text).join('\n\n');
  const next = computeNextStep(facts);                    // '' = no imperative
  if (body === '' && next === '') {
    return facts.role === 'character' ? STATE_EMPTY_CHARACTER : STATE_EMPTY_WRITER;
  }
  const parts = [body, next].filter((p) => p !== '');
  return `${STATE_HEADER}\n\n${parts.join('\n\n')}`;
}
```

**线格式（与 02 §3.5 逐字一致，00 §4.1 为源）**：

```
[World state]

<Section 1 text>
<Section 2 text>                <- 节间空一行；每节 text 自带标签行
<next_step 正文，无标签>          <- 与前一节空一行，永远最后（00 §8）
```

- 结尾不追加换行（`join` 自然收尾）；空节**整节跳过**，不为缺节留空行。
- **一节都没有且 `next_step` 也为空** → 整块替换为一行 sentinel（00 §4.3："显式说没事"，**不返回空串**——空消息会让模型困惑）。角色版措辞不同（`STATE_EMPTY_CHARACTER`）。
- `renderState` **不打印 `title`**（02 §2.1 协商结论）：`title` 只给日志 / 测试 / 诊断。
- **调用两处**：`agent_start` handler（06 §4.1）与单体测试。`context` handler **不调用**它（它只读缓存字符串）。

### 4.3 为什么 `renderState` 永不返 `''` 是硬约束

`readTurnBlock` 用 `null` 表示"别注入"，用字符串表示"注入这段"。若 `renderState` 可能返回 `''`，两者在缓存里就混成一个值，`context` handler 无法区分"采不到"与"没内容"，而且会把空消息塞进载荷。**契约 §4.3 的三条（空节缺席 / 一节都无 → sentinel / 整块失败 → 不注入）在这里各得其位。**

### 4.4 `layer` 与身份解析（每轮一次，收成一处）

**事件读取（`events()` / `eventWindow()` 的底层，一次）**：

```ts
// readEventSlice —— the ONLY event read per turn.
export async function readEventSlice(store, reader, { layer, excludeActor, caps }): Promise<EventSlice> {
  const cursor = await store.readCursor(reader);              // local-store.ts:440; 0 = "from genesis"
  if (cursor > 0) {
    // HOT PATH — MUST be bounded (评审 A-9). `getEventsSince`（local-store.ts:408-429）
    // 是 `SELECT * WHERE seq > ? ORDER BY seq ASC`，没有 LIMIT；若先全量取出、再在
    // 渲染器里截断，读取量就随会话增长（游标在 steer/followUp 轮不推进，每轮重读
    // 越来越长的一段）。契约 §6.1 明令：**必须先限量再取**。落点 = 给 store 方法加
    // `limit`：SQL 内侧 `ORDER BY seq DESC LIMIT ?` 取最近 caps 条，外层再 `ORDER BY
    // seq ASC` 交回升序 —— 读多少由 `caps` 决定，不由历史长度决定。
    const events = await store.getEventsSince(cursor, { layer, excludeActor, limit: caps });
    return { events, coldStart: false };
  }
  // COLD START (no cursor row): bounded AND LAYER-SCOPED (评审 A-2 / A-9).
  // `getEvents`（local-store.ts:475）**不按层过滤** —— 全局 `caps*3` 条 DESC 再在 JS
  // 里 `.filter(layer)`，在"别的层很热"时过滤后可能为 0，于是刚打开的角色被告知
  // "这里无事欠答"。必须**按层查**：复合索引 `idx_events_layer` 已存在
  // （`db/schema.ts:131`，`(project_id, layer, seq)`）。落点 = 给 `getEvents` 加可选
  // `{ layer }`（保持 `getEvents(limit)` 的向后兼容）。
  const desc = layer === undefined
    ? await store.getEvents(caps)                     // writer：全局最近 caps
    : await store.getEvents(caps, { layer });         // character：本层最近 caps
  const asc = desc.slice().reverse();
  return { events: asc.filter((e) => !isActor(e, excludeActor)), coldStart: true };
}
```

- **层过滤只对角色生效**（契约 §6.1）：writer 读全天下的 dynamics，`deps.layer`（玩家视点层）**不**作为过滤条件；角色才传 `{ layer: deps.layer ?? undefined, excludeActor: actor }`。两边都 `excludeActor: actor`（不把自己刚写的念给自己听）。
- **热路径的 `limit` 与冷启动的 `{ layer }` 是 store 侧的新增参数**（`packages/shared/src/store/local-store.ts`，01 落点，见 §10.2）：`getEventsSince` 加 `limit`（内侧 DESC + LIMIT，外侧 ASC），`getEvents` 加可选 `{ layer }`。**不接受**"先全量取再截断"的替代实现——那正是 A-9 的缺陷。02 §3.2 / 03 §（游标首段）里"`getEvents(limit*3)` 再 filter 本层"的旧写法**按本条更正**：冷启动一律按层查，不再全局取后 JS 过滤（契约 §6.1）。
- **冷启动分支属 01**（它拥有 `events()`）；02 的 `dynamics` 只消费 `deps.eventWindow()`（02 §3.2）。窗口大小、合并与上限由 03 的 `renderEventWindow` 施加（返回 `{lines, tail, events, dropped, malformed}`）；**读取量由本函数的 `limit`/`{layer}` 保证有界**（不再靠 `caps * 3` 的经验系数）。
- `reader === null`（`readerOfActor` 对 player/god/engine 返回 null；本批不会出现，但函数保持总定义）→ `deps.events()` 直接返回 `{ events: [], coldStart: false }`，不读库。

### 4.7 备忘录的实现（`makeSectionDeps` 内，只跑一次）

两处访问器共享**同一个 promise**，所以每轮恰好一次 DB 读、一次渲染：

```ts
// inside makeSectionDeps —— the memoisation that makes §4.4/§4.1 cheap.
let slicePromise: Promise<EventSlice> | null = null;
let windowPromise: Promise<EventWindow> | null = null;

// ONE manifest read per turn (03 §9 待确认 7 / 评审 A-17). `layerNameMap` is a local

const layerNames = layerNameMap((await store.getManifest()).layers);

const events = () =>
```

## 6. 断言契约（执行归 06 §6.3，本文冻结不变量）

唯一探针是 `tools/probe-inject.mjs`（NEW，**06 全权**，06 §6.1/§6.3/§6.6 两段交付）。01 不另造探针，只冻结它必须编码的**接缝不变量**：

> 用 `writerLaunch`（`apps/server/dist/engine/launch.js`，`launch.ts:70-93`）起**真作家**，灌确定性 provider，连发 **3 个用户轮**；对**每一个** provider 请求 N 的 **wire messages**（`convertToLlm` 之后、模型真正看到的数组，口径同 AUDIT S1/S2）断言：
> 1. 文本里 `[World state`（`STATE_HEADER`，§4.2）出现次数 **>= 1**（06 A1）；
> 2. 对**每一个**请求，出现次数 **=== 1**（含第 2 轮工具循环带来的**每一个**子请求）（06 A2/A4）；
> 3. 第 k 个用户轮的请求里仍是 **1**（**不是 k**）——AUDIT S1 的观测是"第 3 轮看到 3 个块"，这里断言 1 个（06 A3）；
> 4. 跑完后 session jsonl（`<worldRoot>/.airpworld/sessions/*.jsonl`）里 `airp_world_state` 出现次数 **=== 0**（不落盘，06 A5）；
> 5. 失败注入（删 `viewpoint` 行 / store 不可读）时 3 轮**全部正常完成**（06 A8）。

**为什么 01 要出这条契约而不是只写"交给 06"**：第 2、3 条直接对应本文件 §2.1 的过滤步骤与 §3.2 的缓存读取；如果实现时有人把过滤删了、或在 `context` 里重算 / 推进游标，**探针的计数正是唯一能抓住它的观测点**。06 §6.3 的 A1–A8 是这条契约的超集，以 06 为准。

**不变量的一句话形式**：`forall 请求 : count(customType === 'airp_world_state') === 1`，且该计数**不随轮次增长**。

### 7.1 阻塞项：barrel 导出

`packages/shared/src/index.ts` 今天**没有** `export * from './render/*'`，也**没有** `inject/*`（已核：文件止于 `./actions/talk.js`）。本批**必须**加，且**跨端同批**（否则扩展与前端都 import 不到）。

## 9. 待确认项

1. **`readTurnBlock` 读不到槽时是否该重算？** 本文选**不重算**（返回 null -> 不注入）。情景：`previewPrompt()` 在首次 `agent_start` 前触发，或分支切换后的预览 -> 预览里没有块。**若明月希望 `/prompt` 预览总是有块**，就让 `context` handler 在 `readTurnBlock === null` 时做一次同步降级（仅渲染**无 I/O** 的 sentinel），但那会让预览显示误导性的"没事"。**默认：不重算。**
2. **单槽缓存在"多会话同进程"下会互相顶掉吗？** 不会：`readTurnBlock` 比对 `sessionId`，不匹配即 `null`。但代价是**第二个会话永远看不到块**（它自己的 `agent_start` 会写槽）。契约 §9 已定"一进程一会话"，故不修；登记以便将来长驻进程多会话时换成 `Map<sessionId, string>`（那时才需要 LRU）。
3. **`details` 是否该带上节 `items`？** 本文选**省略**（无消费者）。若 06 的探针想按结构化字段断言而非文本计数，可让 `context` handler 附 `details: { keys: sections.map(s=>s.key) }` 并保持 `display:false`——但**必须**同时确认它不被持久化（`display:false` + `context` 路径已保证）。**默认：省略，探针按文本标记计数。**
4. **`warnOnce` 的落点**：本文放 `inject/collect.ts`。06 的 `context.ts` 也想 warn 一次（身份退化）。**建议**：`warnOnce` 做成 `inject/collect.ts` 的导出，`context.ts` 相对路径 import 它（但注意 per-extension-file 模块状态——两个文件各自一份去重表，**不会**互相抑制）。若 06 更想要独立实现，二者不冲突（消息前缀不同）。
5. **冷启动读取（已按 A-2/A-9 更正）**：不再是"全局 `caps * 3` 条 DESC 再 JS 过滤本层"——那在火热层场景过滤后可能为 0。现为**按层查**：writer 用 `getEvents(caps)`（全局最近 caps），角色用 `getEvents(caps, { layer })`（本层最近 caps，走 `idx_events_layer`）。`caps * 3` 的经验系数随之删除（它补偿的是"先全局再过滤"的丢失率，按层查后不再需要）。热路径同理加了 `limit`（§4.4）。**待确认仅剩**：`getEventsSince` 的 `limit` 是取"最近 caps 条"还是"最早 caps 条 + 补尾句"——本文取**最近 caps 条**（lost old ones 由 `…and N more; the rest are on record` 表达，契约 §4.2），游标照推到 `getMaxSeq()`（03/00 §6.3）。
6. **steer / followUp 段看到 run 起点块**（§3.5）：本文接受该陈旧度。若试玩中"玩家中途插话，作家答的是旧状态"成为问题，**解法是把轮边界下移到"每条 user 消息"**——但那与"重活每 run 一次"冲突，需要重新设计（**不在本批**）。
