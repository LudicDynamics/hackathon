## 1. 目标

试玩里 agent 卡壳的典型形态不是**不知道**，而是**知道了却不动**（doc-12 §"#6 展开"）。`00` §3.2/§3.3 的前六节（作家）/ 前四节（角色）解决"世界什么样"，事件段解决"刚变了什么"，但注入块末尾什么都不说时，作家会再写一段风景、角色会再寒暄一句。

本文产出一段**每轮计算、随事实变化、永远在注入块最后一节**的英文祈使句，并把它**怎么读**（stance）写成平台正文放进 `extensions/instructions.ts`。两件事分开：

| 层 | 内容 | 落点 | 何时写 |
|---|---|---|---|
| **计算段**（实例） | 本轮实际悬着什么（具体到事件类型） | `packages/shared/src/render/next-step.ts`（NEW，纯函数） | 每轮重算，跟着注入块走 |

## 2. 契约（形状与签名）

### 2.1 `computeNextStep`（NEW，纯函数）

```ts
// packages/shared/src/render/next-step.ts  (NEW)
import type { WorldEventType } from '../schemas/events.js';
import type { Actor } from '../actions/actor.js';   // 已存在：actions/actor.ts:7

export type NextStepRole = 'writer' | 'character';

/**
 * Minimal event view. 03's `EventWindowLine` is a superset, so project it rather
 * than declaring a second shape (03 owns `EventWindowLine`, `render/events.ts`):
 *   export type NextStepEvent = Pick<EventWindowLine, 'type' | 'layer' | 'name' | 'actor'>;
 * `actor` is carried so the case-1 tail test can drop writer-authored events
 * (§3.1, review A-12); every `EventWindowLine` satisfies the projection.
 */
export type NextStepEvent = Pick<EventWindowLine, 'type' | 'layer' | 'name' | 'actor'>;

export interface NextStepFacts {
  role: NextStepRole;
  /** Chronological, oldest→newest. Already merged + capped + self-excluded by 01/03. */
  events: NextStepEvent[];
  /** Player's layer (writer) / own layer (character). null = unknown. */
  currentLayer: string | null;
  /** A layer was generated this window and the player has not entered it (§2.2 predicate). */
  unseenCreation: boolean;
  /** No events this window (01 owns the predicate: `quiet = events.length === 0`; §2.2). */
  quiet: boolean;
}

/** Pure. Returns the closing imperative for this turn; '' = nothing is owed. */
export function computeNextStep(facts: NextStepFacts): string;
```

**不变量（写进函数的 doc comment，逐条被 §6 的单测断言）：**

- 纯：无 I/O、无时钟、无随机、不读 store。同 `facts` 必得同串。
- 只读 `events` 的**队尾**与**类型集合**；**绝不解** `detail`（细节在 03 渲染出的 bullet 里，本文只给判据句）。
- 返回 `string`：**非空即入块**，`''` 即**该节缺席**（`00` §4.1"空节整节缺席"）。
- **不为 role 之外的因素分支**：一个函数服务两角色，按 `facts.role` 选措辞表。

### 2.2 调用点与返回值语义（与 01 的边界）

- `render/state.ts::renderState(sections, facts)`（**01 负责**）在**最后**调 `computeNextStep(facts)`，把非空结果作为**无标题的末节**追加（`00` §8"永远最后一节"）。
- 若 `sections` 为空**且** `computeNextStep` 返回 `''` → 由 `renderState` 输出角色专属哨兵（`00` §4.3）；本文不管哨兵措辞。
- **两条路径都调**（作家与角色）：角色的三分支见 §3.2，不由 01 代劳。
- `unseenCreation` 由 **01 的 collect** 计算（它持有全量 `WorldEvent` 后才收窄到 `NextStepEvent`），谓词固定为：**存在 `type ∈ {layer_initialized, layer_init_failed}` 的层 L，其后没有 `detail.layer === L` 的 `layer_entered`，且 `L !== currentLayer`**。`NextStepEvent.layer` 对 `layer_*` 行**保证非空**（01 从 `detail.layer` 读入；`actions/layer.ts:118-125` / `:158-165` / `:72-79` 三处都设了 `layer`）。本文只消费这个布尔，不重算。
- `currentLayer` = `deps.layer`（由 `viewpoint.layer` 派生，05 提供）。**注意 `00` §11 的级联**：视点 TTL 过期或表无行时，`viewpoint` 节缺席**且** `layer_files` / `cast` 同缺席，`deps.layer` 落 `null`。此时 §6.1 把依赖 `currentLayer` 的分支视为不命中；但 **`quiet` 只由事件窗口判定（`00` §11 的 `bag`/`recent_chalk`/`dynamics` 不受 TTL 影响），视点过期本身不会把 `quiet` 置真**。
- **`quiet` 的谓词归 01**：`quiet = events.length === 0`（不再与"有无非 `next_step` 节"取合取——那个合取是死代码，评审 A-1；全空世界由 `renderState` 短路成哨兵、根本不打印本节）。本文只消费。

## 3. 最终英文措辞（定稿）

### 3.1 作家（`role: 'writer'`）

**判定优先级（顺序固定，取第一个命中）：**

1. `events` 非空、**队尾**事件 `type ∈ {choice_selected, use_item_on, roll_resolved}`、**且 `tail.actor.type !== 'writer'`** → 情形 1（按类型选串）；
2. 否则 `unseenCreation === true` → 情形 2（**在 quiet 之前**，`00` §8 的枚举顺序如此）；
3. 否则 `quiet === true` → 情形 3；
4. 其余（有变化但非上述三类，如队尾是 `entity_moved`）→ `''`，**该节缺席**。

> 判据依据 `00` §8 情形 1 的原文"事件段**最新一条**是 `choice_selected` / `use_item_on` / `roll_resolved`"——所以用**队尾类型**判定，不需要"是否被叙事回应"的探测器（事件表里没有"已回应"这种类型，`schemas/events.ts:9-26` 的十五类里也没有）。
>
> **`actor.type !== 'writer'` 守卫（评审 A-12）不可省**：这三类可由 **writer 自己**触发（`roll-dice.ts:18` 在作家工具面；`/api/dice` 强制时 actor=`god`）。若不加守卫，作家把自己刚做的选择读成"玩家做的"并被告知去回应**自己的**动作。`00` §6.1 的 `excludeActor: {type:'writer'}` 已在**读取**层滤掉 self（01 §4.4），此处是**第二道**、防未来某条路径把作家动作漏进窗口。

**情形 1 — 玩家动作未被回应**（三串，按类型选）：

`choice_selected`:
```
The player has just made a choice, and nothing has narrated what it led to. Answer that choice this turn before moving on.
```

`use_item_on`:
```
The player has just used an item on something, and no narration has reported what happened. Resolve it this turn.
```

`roll_resolved`:
```
A dice check has just resolved, and no narration has reported the result. Report the outcome this turn.
```

**情形 2 — 刚生成、玩家尚未进入的内容**：
```
A new layer has been generated and the player has not entered it yet. Its opening is already on disk, so do not write it again; deal with the player where they are now.
```

**情形 3 — 什么都没发生（quiet）**：
```
Nothing in the world has changed this turn and no action is owed. Respond to the player, but do not manufacture an event, a clue, or a stranger just to give the turn something to say.
```

> 写法依据：情形 1 的三串是"事实 + 悬置"（`00` §8 边界：只陈述"什么悬着"；"Answer that choice this turn"是管线动作，不是替 agent 决定剧情）；情形 2 的名字即判据（doc-23 §2.3），并把**最易犯的后果**写进去——重复生成（doc-23 §2.2：scene-init 已落盘，重写＝第二真相源，doc-05 §8.5）；情形 3 是 doc-23 §2.7 的"不做也是合法输出"（doc-12 #6 的"不要为了填空而写"）。

### 3.2 角色（`role: 'character'`）

**判定优先级：**

1. 队尾事件 `type ∈ {choice_selected, use_item_on, roll_resolved}` 且 `tail.actor.type !== 'writer'` → 情形 C1；
2. 否则 `events.length > 0` → 情形 C2；
3. 否则 → 情形 C3（**角色的默认分支**；角色被打开后总有话可说，所以**不返回 `''`**）。

> **C2 的判据是 `events.length > 0`，不是 `unseenCreation`（评审 A-14）**：角色的 `dynamics` 窗口本就是**本层过滤 + 排除自身**（`00` §6.1），所以窗口里**任何**存活的一条都恰好是"这里在你关着的时候变过、且不是你干的"。用 `unseenCreation`（只看 `layer_initialized`/`layer_init_failed`）会让 C2 **永不触发**——"作家关着时写的内容"只产 `entity_created` / `entity_edited`，角色于是拿到 C3"无事欠答"，随后可自相矛盾。`unseenCreation` 只服务作家情形 2（"刚生成、玩家尚未进入"），与 C2 **是两回事**。

**C1 — 玩家刚做的事还悬着**：
```
Something the player did here is still unanswered. You were present for it, so react to it as yourself and in your own voice.
```

**C2 — 你关着的时候这里变了**：
```
Things in this place changed while you were closed. You need not bring them up; you must not contradict them.
```

**C3 — 本轮无事可应**：
```
Nothing here is owed an answer right now. A short line, or saying nothing, is a real answer; do not invent a past that did not happen to fill the silence.
```

> 写法依据：C2 是 doc-23 §2.6 的"默认 + 例外"写法（默认不提、硬约束是不矛盾）——比"注意保持连续性"这种形容词可执行（doc-23 §2.3）；C3 明写"沉默是合法输出"（doc-23 §2.7），这是角色侧最容易为了交差而编造前史的地方。
>
> **角色不注入 `bag`、也不注入玩家相机**（`00` §3.3），所以 C1/C2 的措辞**不提"玩家的口袋/视野"**，只说 "here / this place"。

### 3.3 平台正文（stance，写一次）

`NEXT_STEP_RULES`（NEW，追加进 `WRITER_INSTRUCTION`；resident）：
```
[The closing line of the world state]
Every world-state block ends with one plain line saying what is still owed this turn. It is computed from the event log at the moment of your request, so trust it over your own recollection of the turn.

Read it as a fact, not a script. It names what is outstanding; how you resolve it is your call, and it never tells you what a character should say or do. An unresolved player action has to be answered before you move on. A line that says nothing changed means nothing is owed, and a quiet turn is a legitimate turn.

Anything the line points at that you have not read is one look_at away. Never guess the contents of a path you have not opened.
```

`CHARACTER_NEXT_STEP_RULES`（NEW，追加进 `CHARACTER_INSTRUCTION`；resident）：
```
[Being opened]
You are opened into a face-to-face exchange with the player: this is live conversation, not a report of one. Your identity, personality, and memory files are who you are; the world state above is only what is current around you.

The last line of the state block says what is owed right now. Treat it as a fact about this place, never as a cue to perform.

You are allowed to say little. One short line, or nothing, when there is nothing to react to is a real answer; inventing a past that did not happen is not.
```

> **为什么 stance 与实例不重复**（doc-23 §2.9）：stance 写**怎么读这一句**（事实不是剧本、quiet 合法、细节走 `look_at`）——常量，每轮成立，进缓存的 system prompt；实例写**本轮具体悬着什么**——每轮不同，进注入块。两者文本零重叠。
>
> **`00` §8 说角色版含"你刚被打开、玩家在场、你该开口说什么"**：其中"刚被打开 + 玩家在场"已由 `standing` 节（`00` §3.3）承担，实例段再写一遍就是 doc-23 §2.9 的"同一条写两遍"；故把它落在 `CHARACTER_NEXT_STEP_RULES` 的 `[Being opened]` 段（resident，常驻一份），实例段只带本轮判据。**`00` §8 本身即要求措辞经 `instructions.ts` 引用，这与 §8 一致，不是例外。**

## 4. `hiddenOverrides.compaction` 定稿

### 4.1 必须保住的持久事实（doc-14 §体验目标补充 3）

doc-14 点名三类必须被记住的东西：**承诺 / 骰子结果 / 关系变化**。逐条映射到"谁要记得"：

| 持久事实 | 事件表里的形状（`schemas/events.ts`） | 谁必须记得 | 为什么摘要会给它兜底 |
|---|---|---|---|
| **承诺 / 约定**（"玩家答应老周明天再来"） | 无专门类型——落在 chalk 正文与对话里 | 作家 | 事件表记"发生过"（`character_talked`），不记"约定了什么"（doc-21 §4.2：内容只在 `entries`）；所以承诺**只能靠 transcript 摘要保住** |
| **骰子结果**（"掷出 62 通过"） | `roll_resolved{ dice, desc, expect, result, passed }` | 作家 | 事件段念过就推游标（`00` §6.2"注入即消费"）；第 50 轮不再注入 → 摘要必须保住它 |
| **关系变化**（"老周现在信得过玩家了"） | `following_changed{ following }` 只记跟随，不记态度 | 作家 + 角色 | 态度写在 chalk / 对话里；两者都靠各自 transcript 摘要 |

**一个反直觉但要写进 doc 的事实**：`00` §1 裁决 2 让注入块**每轮全量**——但那只是"当前值"（世界里现在有什么）。**因果**（doc-14 三类）不进状态块（`00` §12 反模式 4 禁止在状态块写规则/叙事），事件段又"注入即消费"。所以**摘要压缩是这三类事实的唯一长期归宿**——这正是后端实现计划 §6.6"compaction 之后状态块补不回因果"那句的落点。**不要**因此新建 journal（doc-12 "journal 为什么不做"已撤销）。

`m` 具体写法：把"必须保住什么"写成**判据清单**，不是"请仔细总结"（doc-23 §2.3）。

> ⚠️ 摘要的**输入**由引擎从 session entries 生成，**不经过 slot**；preset 能影响的只有 `regex` 规则（`_applyPresetToCompactionPreparation`，`agent-session.ts:3220-3241`）与自定义消息策略（`convertToLlm(..., forSummarization=true)` 丢弃 `compaction:"exclude"` 的类型，`compaction.ts:674`）。**本批不设 `regex`、也不给注入块注册 `compaction:"exclude"` 之外的东西**（`registerCustomType` 归 06），故摘要输入就是完整 transcript——这正是我们要的（承诺/骰子/关系都在 transcript 里）。**别顺手给 preset 加 `regex` 规则去"精简"摘要输入**：那会静默删掉 doc-14 的三类持久事实。

### 4.3 角色 preset（`presets/character.json`）

角色该保住的东西**不同**——角色**不知道**玩家在哪层、背包里有什么（`00` §3.3），也不该记得作家的全知视角。它要记的是**"我对玩家的态度怎么变的"**（后端实现计划 §6.6 原话）与它自己说过的话。所以角色版摘要**刻意不设** `Scene` / `Open threads` / `Canon facts` 这些全知段。

```json
{
  "schemaVersion": 1,
  "id": "character",
  "name": "Character",
  "description": "AIRP standalone character-dialogue preset",
  "hiddenOverrides": {
    "compaction": {
      "systemPrompt": "You are the continuity record for a single character in an interactive story. You read a scene of dialogue and produce a summary of what THIS character knows, felt, and said. Do NOT continue the conversation, do NOT speak as the character, and do NOT include anything the character could not have witnessed. Output ONLY the structured summary.",
      "initialPrompt": "<conversation>\n{conversation}\n</conversation>\n\nSummarize the conversation above as the memory of this one character. Use this EXACT format:\n\n## Who I am to the player\n[How this character feels about the player right now: warmth, suspicion, debts, grudges. \"(no change)\" if nothing shifted.]\n\n## What was said and promised\n[Anything this character promised, refused, or was promised. Verbatim where it matters.]\n\n## What I know about the scene\n[Only things this character saw or was told. Never add what the Writer knows.]\n\n## What I was asked and did not answer\n[An unanswered question or an unfinished exchange. \"(none)\" if none.]\n\nKeep each section to a few lines. Preserve exact names and item names.",
      "updatePrompt": "<previous-summary>\n{previous_summary}\n</previous-summary>\n\n<conversation>\n{conversation}\n</conversation>\n\nFold the new turns above into the existing summary in <previous-summary>. Rules:\n- PRESERVE every change in \"Who I am to the player\" and \"What was said and promised\"; never quietly drop one.\n- UPDATE \"What I know about the scene\" — this character's knowledge grows, it does not reset.\n- Remove an entry from \"What I was asked\" only once it has been answered.\n- Keep this strictly to what the character witnessed; do not import anything else.\n\nUse the SAME format as the previous summary.",
      "turnPrefixPrompt": "<conversation>\n{conversation}\n</conversation>\n\nThis is the OPENING of an exchange too large to keep whole; the recent part is retained. Summarize only what the retained part needs: what this character was asked, what it promised, and how it feels about the player right now. Be very short.",
      "branchSummaryPrompt": "<conversation>\n{conversation}\n</conversation>\n\nSummarize this abandoned exchange so this character can be reopened without losing it. Keep only:\n\n## Where we left off\n[The last thing said.]\n\n## What I promised or refused\n[Verbatim, or \"(none)\".]\n\nKeep it to a few lines. Preserve exact names."
    }
  },
  "items": [
    { "kind": "slot", "id": "character-instruction", "slot": "system-char" },
    { "kind": "slot", "id": "chat-history", "slot": "chat-history" }
  ]
}
```

> 角色版**必须**保住"## Who I am to the player"这种**态度**——因为态度不进事件表（`following_changed` 只记跟随，`schemas/events.ts:66`），也不进状态块（`00` §12 反模式 4）。这是角色记忆力唯一能撑过 compaction 的地方。

## 5. **关键陷阱**：角色 preset 覆盖（AUDIT §4.3）

### 5.1 陷阱本体（file:line）

`characterLaunch` 的角色 preset **优先取世界侧的 `characters/<id>/preset.json`**，仓库 `presets/character.json` 只是**兜底**：

```ts
// apps/server/src/engine/launch.ts:109-113
const characterPreset = path.join(worldRoot, 'characters', characterId, 'preset.json');
const presetId = installPreset(
  worldRoot,
  fs.existsSync(characterPreset) ? characterPreset : path.join(repoRoot, 'presets', 'character.json')
);
```

`installPreset`（`presets.ts:32-39`）把选中的文件**拷贝**进 `<worldRoot>/.airpworld/prompt-presets/<id>.json`，再只按 `id` 交给引擎。**于是**：一个自带 `preset.json` 的角色，**永远不看** `presets/character.json`。

**当前实况**（已核实）：模板世界 8 个角色目录里有 **6 个**自带 `preset.json`（还有 `worlds/test-school/characters/七海/preset.json`）：

| 世界 | 自带 preset.json | 无（落仓库兜底） |
|---|---|---|
| `templates/cthulhu` | `old-sailor` | `strange-innkeeper` |
| `templates/holmes-world` | `constable`、`watson` | — |
| `templates/magic-academy` | `archivist`、`seraphina` | — |
| `templates/school-romance` | `nanami` | `hall-monitor` |
| `worlds/test-school` | `七海` | `风纪委员` |

→ **只改 `presets/character.json` 会静默失效**：模板世界里 **8 个角色目录有 6 个自带 `preset.json`**（AUDIT §4.3 说"7 个里 6 个"，那是把 `worlds/test-school/characters/七海/preset.json` 也计入；**本批的实况是 8 个角色目录、6 个自带**，见 §5.1 表）。这是 doc-22 §9"角色 preset 配 compaction"字面执行时的坑。

### 5.2 两条路线

**路线 A — 逐个改角色 preset。** 在每个 `characters/<id>/preset.json` 里也抄一份 `hiddenOverrides.compaction`。
- 代价：**N 份重复**。doc-23 §2.9 的"同一条纪律写两遍，改的时候必然只改一处"在此放大成**跨 N 个角色的两遍**，必然改一处漏 N-1 处；每个新角色还要记得抄。

**路线 B — 把平台口径下沉到 `extensions/instructions.ts` 的 slot。** 让预设只带世界/角色特有内容 （doc-23 §3.1 的纪律）。
- **这条路对 `compaction` 字段走不通**：五个字段是引擎在摘要那一次 LLM 调用里**单独取** `_activePreset.hiddenOverrides.compaction` 的（`agent-session.ts:3133` / `:3480` / `:4835`），**不经过 slot 渲染管线**。slot 能承载的是**给 agent 读的提示词正文**（本项目 §3.3 的 stance 常量），不是**给摘要那次调用用的提示词**。
- 所以 doc-22 §9 那句"这一项确实在 preset JSON 里，不在 `extensions/instructions.ts`"是对的——**compaction 五字段无法用路线 B 消灭重复**。

### 5.3 裁决与理由

**推荐：compaction 五字段走 A（逐份铺），但用"单一真源模板 + 机械核验"把风险压到可接受；平台 stance §3.3 走 B。** 理由：

1. **引擎不支持 preset 继承/合并**（`loader.ts:152-246` 只做单文件 normalize，无 `extends`/`base`；本批已核实 `types.ts` 的 `PromptPreset` 也无继承字段）。**B 无法替代 A**——这是硬约束，不是取舍。
2. **但重复可以被钉住**：把 `presets/character.json` 定为角色 preset 的**唯一真源模板**，任何 compaction 修改 **同 commit** 铺到全部 `templates/*/characters/*/preset.json` 与 `worlds/*/characters/*/preset.json`；用 §5.4 的 parity 测试在 CI 里断言逐字一致。**没有测试的重复会静默腐烂**（doc-23 §4.4 末句）——这是路线 A 唯一的失败模式，且可被一个纯文件断言消除。
3. **AB 的分工线**：**给摘要那次调用**的提示词 → preset（A）；**给 agent 读**的 stance/规则 → `instructions.ts`（B）。两者不交叉，正是 §1 那张表。

> **落地规则（写进 AGENTS.md，由 06 的同步清单挂一行指向本文）**：`presets/character.json` 是角色 preset 的**唯一真源模板**，新建角色**从它复制**。修改 `hiddenOverrides.compaction` 必须 **同 commit** 改 `presets/character.json` + 全部模板/world 角色 preset，并跑 `character-preset-parity.test.mjs`。

### 5.4 兜底测试（NEW）

`apps/server/test/character-preset-parity.test.mjs`（NEW）——纯文件断言，无引擎：

```
1. 读 presets/character.json 的 hiddenOverrides.compaction.systemPrompt 为基准。
2. glob 全部 templates/*/characters/*/preset.json 与 worlds/*/characters/*/preset.json。
3. 对每个：若它带 hiddenOverrides.compaction → 断言 systemPrompt 与基准逐字相等；
```

## 6. 边界与失败模式

### 6.1 `computeNextStep` 的失败纪律（与 `00` §11 同一条）

| 情形 | 行为 |
|---|---|
| `facts` 残缺（自相矛盾，如 `events` 为空却 `quiet===false`——按 §2.2 的谓词不该出现，出现即 01 采集层坏了） | 落到"无可陈述"分支：作家返回 `''`（该节缺席），角色返回 C3。**不抛异常**（注入永远不能让一轮失败，`00` §11）——本函数**不校验** facts，只按字段取值、取不到就走兜底 |
| `currentLayer === null` 且 `unseenCreation` 依赖它 | 该分支视为不命中（宁可沉默也不要错误祈使） |
| 队尾事件是未知/新增类型（未来枚举扩张） | 走"其余"分支（作家 `''`；角色 C3）。**类型集合判定用白名单，不是黑名单**——新增事件类型默认不触发祈使，直到有人显式加它 |
| 字符串里有 player/character 名字 | **不插入**——本函数只产出固定串，不消费 `name`（避免歧义与"编造角色开口"）。`name` 只在 03 的 bullet 里 |

### 6.2 compaction 的失败模式

| 情形 | 行为 |
|---|---|
| preset 的 `hiddenOverrides.compaction` 写错字段名 | **静默忽略**（`loader.ts:231-239` 只认五个已知键，未知键不进 `overrides`）。→ 必须靠 doc-23 §4.4 的测试断言字段存在 |
| 某个模板角色 preset 未同步 compaction | **静默失效**（§5.1）。→ §5.4 的 parity 测试兜底 |
| `{previous_summary}` 写在 `turnPrefixPrompt` / `branchSummaryPrompt` | 原样留在文本里（§2.4）—— 不是崩溃，是摘要里出现一个字面占位符，模型会困惑。**别写** |
| `systemPrompt` 想改分支摘要 | 不生效（`branch-summarization.ts:377`）—— 不是失败，是引擎不接。别依赖 |
| compaction 摘要 API 调用本身失败 | 引擎行为，不在本文范围（`completeSummarization` 走的 retry 见 `compaction.ts:581-600`） |

### 6.3 「下一步」不应触发的情形（防误报）

- 队尾是 `layer_entered`（玩家刚进新层）→ **不是**"刚生成尚未进入"（那不是 `unseenCreation`，其谓词见 §2.2）；作家走"其余"分支 `''`。作家在这一轮本就有明确的对话输入，不需要祈使（`00` §8 三类情形之内不含它）。
- 队尾是 `character_talked` 这类"已闭合"事件 → `''`（玩家刚聊完，不需要作家动作——聊的是角色，不是作家）。
- `world_snapshot` / `world_rolled_back`（detail 形状 `schemas/events.ts:107-108`，类型 `:23-24`）**两者待遇不同**（03 §3.2.5）：`world_snapshot` 被 03 在合并前滤掉（`renderEvent` 返回 `''`，§3.5 第 0 步），**到不了**本函数；`world_rolled_back` **不被过滤**——它渲染出 `The world was rolled back to the "…" snapshot.` 并进入窗口（03 §3.2.5 明写"必须能被作家念到"）。所以本函数的队尾判定**会**见到它，落到"其余"分支 → 作家 `''`（它既不是三类交互、也不是 `unseenCreation`）。**单一职责：03 只滤 `world_snapshot`，本文只判类型**——不要在这里补一层过滤。
