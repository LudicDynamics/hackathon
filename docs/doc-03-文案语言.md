# NoDesign 文案语言分析：亲和力是设计出来的，不是文风

> 明月提出的观察：整个项目的语言口语化、亲和、自然，特别是提示语。
> 本文验证并拆解这个特点：它出现在哪三层、为什么这么设计、手法是什么。
> 只讲思路，不贴源码（引用个别原文短句作为证据，属合理引用）。

---

> **2026-08-30 本地优先追加批注**：AIRP 架构从"纯云端"调整为"本地开源自部署"，对文案语言没有直接影响——"人话"哲学不依赖部署方式。但新增的扩展系统引入了一个新文案场景：扩展安装/卸载/权限提示的文案同样要遵循"人话"原则（"这个扩展要读写你的世界文件，你同意吗？"而不是"请求 filesystem.write 权限"）。

## ⚠️ AIRP 批注（2026-08-30 带着产品上下文回看）

**这是四份分析中继承度最高的一份——AIRP 的"人话"哲学完全继承，而且比 Nodesign 更极致。** 理由：AIRP 的用户不只是"用工具的人"，而是"活在世界里的玩家"，人话的要求只高不低。

继承且更极致的点：
- **§3.3 诚实协议** → 直接写入作家提示词骨架（"没验证就明说，不假装 OK"），已是 AIRP 叙事规则第一条（doc-05 §4.2）；
- **§3.4 拒绝话术（转告+不重试+带转向）** → AIRP 的世界逻辑拒绝（角色拒绝玩家的请求、世界规则不允许）同样由作家/subagent 转告玩家，且带"教你怎么做对"；
- **§3.1 把用户当人介绍** → AIRP 的作家拿到的不是"圈选数据"而是"玩家此刻在看哪、做了什么"，人话注入是作家懒加载的输入格式；
- **§6 手法表 10 条全部适用**。

AIRP 新增的文案场景（Nodesign 没有）：
1. **NPC 现编对话**——背景角色的话由作家随口现编，同样要自然（"摊贩老头冲你笑了笑，继续摆弄他的水果"）；
2. **角色记忆与小天地**——角色写在小天地（自己根目录）里的内容是"角色的视角"，语气要像角色本人（不是作家代笔）；小天地里玩家留痕的提示（"角色留下了东西"）同样不端着；
3. **遮罩对话界面**——角色遮罩（特写态）的 UI 文案不端着；角色流式台词节奏即性格；
4. **旁白与对话的分工**——旁白是作家的声音（叙述质感），对话是角色的声音（个性）——人话哲学下还要加一层"谁的声音"；
5. **叙事 frontmatter 的文案**——choice 选项的措辞、status 快照的字段名，都是玩家直接读的"人话"，不是技术标签（doc-05 §3.1）。

**一句话**：doc-03 的结论"让双方都少猜，是一切亲和力的来源"——在 AIRP 里玩家猜的是"世界怎么回应我"，所以人话哲学直接成为世界体验的一部分，不只是 UI 质感。


## 1. 验证结论：这不是文风，是三层的系统性设计

口语化不是作者随手写出来的风格，而是贯穿**三个层面**的一致选择，且各层的口语化各有不同的服务对象：

| 层 | 说给谁听 | 特点 |
|---|---|---|
| **UI 文案**（按钮/占位/空态/toast） | 用户 | 不端着、给下一步、预判焦虑 |
| **Agent 提示语**（系统注入/工具返回/协议） | Agent（但 Agent 会"原话转告用户"） | 把用户当人介绍、教 Agent 诚实与转述 |
| **代码注释与文档**（贯穿全仓） | 未来的维护者（含 AI） | 事故叙事、决策因果、人话概念名 |

而且"**人话**"本身是项目里反复出现的正式概念名（Design Principle §8"人话/AI 双视图"、motion 模块"给 agent 的人话"、board-place"翻译成一句人话"、quota"用户看得懂 token，看不懂 $0.87 意味着多少对话"）——它不是形容词，是一类设计产物的名字。

## 2. 第一层：UI 文案 —— 不端着 + 给下一步 + 预判焦虑

### 2.1 按钮 title 就是一句同事的话

- `不逛了 —— 关掉浏览器并把桌面上那张卡收走（在站点上的登录留着）`
- `好了继续 —— 把控制权交回 agent（它正等着）`
- `我来接手 —— 点击/滚动/打字会直接发到那个浏览器里`
- `接手中：点一下这块画面再打字（键盘只在这里生效）`

不是"停止浏览会话"、"恢复自动控制"，而是"不逛了"、"它正等着"——**把 Agent 当"正在等你的同事"**，而不是"系统组件"。

### 2.2 空态不报"空"，给下一步

- `还没写，点开写项目档案`
- `还没有文件，点开上传`
- `还没有评论。点击画布上任意元素 → 在弹出的浮卡里写评论。`
- `这个文件夹是空的`

每个空态都是"现在缺什么 + 去哪做"。经典空态文案"暂无数据"在这里一个都没有。

### 2.3 预判用户会不会焦虑，提前安抚

- `静止的页面不会一直传帧 —— 画面不动是正常的，不是卡住了。`
- `浏览器空闲 5 分钟会自己休息（登录态留着）。打开之后你可以直接接手操作，agent 下次也接着用这一页。`
- `还没有可用的模型：到「设置」填 API Key（或本机 claude login），或者配一个模型插槽`（错误响应直接指路，不让人去选择器里瞎找）

用户看着"画面不动"的第一反应是"卡了？"——文案替他把这个疑问说出来并解答。**写文案的人站在用户产生疑问的瞬间，而不是站在功能完成的瞬间**。

### 2.4 界面词表本身就口语化

- API Key 叫"**钥匙**"；连接测试叫"**体检**"（体检中…/体检失败）；"加一个/加一行"；
- 表单引导："① 服务商（接口地址 + 钥匙）② 模型（每一行 = 模型选择器里的一项）"；
- 提示里用"如 deepseek-chat"而不是"例如：deepseek-chat"；
- 英文词表（en.js）刻意保留这份活泼："钥匙 → Key"、"体检 → Check"——翻译不把活泼磨平。

### 2.5 状态提示用口语动作而非状态名

- 浏览器状态行：`agent 还没开始浏览` / `浏览器已经关了` / `出错了`
- 暂停提示：`Tweaks（agent 还没暴露参数 — 跟它说一句让它 expose_tweaks）`——连"让 Agent 干活"都说成"跟它说一句"。

## 3. 第二层：Agent 提示语 —— 把用户当人介绍，教 Agent 诚实

这一层最精彩：**给 Agent 的提示语也在说人话，而且是在"教 Agent 怎么跟用户说人话"**。

### 3.1 圈选协议：把"用户圈了一块"讲成一个故事

> "先看图 —— 图是他当时看着的画面，元素清单只是索引。**他可能一个字没写，框本身就是话**。"

一句话同时做了三件事：告诉 Agent 先看什么、为什么（图是当时的画面）、以及"用户留空不等于没诉求"。**"框本身就是话"**——把产品的核心交互哲学直接写进给 Agent 的提示词。

### 3.2 视点上报表：教 Agent 消解"这个/这里"

> "用户此刻在画布上：…他说「这个/这里/这张」多半指 选中的 > 开着的窗 > 视口里的东西。"

不是丢坐标，而是把"用户的心智"翻译给 Agent——用户不会说"第 3 象限 42% 处"，会说"这个"。

### 3.3 诚实协议：教 Agent 不假装 OK

> "没验证就明说没验证，不要说'应该没问题'。看不出来也直说'我看着差点意思但说不清，想听你的反馈'，比假装 OK 有用。"

这是**给 Agent 的指令，同时也是产品价值观**：AI 协作里"假装成功"是最贵的失败，所以连提示词都在教 Agent 承认不确定。这与代码层"消灭一切看起来成功了但实际没成功"的纪律是同一枚硬币。

### 3.4 拒绝话术 = 转告 + 不重试（把 Agent 当传话筒，不当报错器）

工具被能力/档位/配额拦住时，返回的不是技术错误，而是"**给用户的话**"：

- `这个账号当前档位不包含生图。原话转告用户，不要重试、不要换别的生图工具。`
- `今天的额度用完了（生图按 $0.20/张计入每日额度），明天零点刷新。原话转告用户，这轮别再生图。`
- `盒子不在线工具会明说——转告用户等开机，没有自动备胎。`
- `把这句话原话转告用户，装好后重启 Nodesign 再试；不要重试本工具。`

刻意不让裸的 ENOENT/500 漏到用户面前（注释原话："不让裸的 ENOENT / 500 漏到 agent 面前"）；同时命令 Agent **不要重试**（重试是白烧 token 的循环）。拒绝语还带转向建议——"**教 Agent 换做法，不只拒绝**"。

### 3.5 给 Agent 看的解释也用人话

- `模型对"组 2 在组 1 左侧、同高"这种话的理解远好于读坐标`——工具把坐标翻译成人话再给 Agent；
- `配置错了端点会拒演并报人话，照改就是`（SKILL.md）——连"会报错"都说成"报人话"。

## 4. 第三层：代码注释与文档 —— 事故叙事 + 决策因果

全仓注释不是"这段做什么"，而是"**这里曾经出过什么事，所以我们这么写**"：

- `他可能一个字没写，框本身就是话`（圈选协议注释）
- `那正是以前镜头横跳的原因`（在场跟随规则的因果）
- `看着 deck 没法跟 agent 说话就不是这个工具了`（层叠上下文的动机）
- `二十份产物的桌面会把风扇吹起来`（iframe 限流的动机）
- `静默少东西是导出最贵的失败方式`（导出 toast 纪律）
- `"这张不对、那张也不对、还有那个"，逐条起轮 = 三轮并发抢同一批文件`（攒批功能的动机）
- `一个 turn 做 30 件事停不下来`（HANDOVER 里对 SDK preset 坑的描述）

文档层面同样如此：README 用"哪里错了圈哪里"当标题；PLAN.md 的决策档案写"用起来很怪"（用户原话）当约束证据。**注释在讲事故与因果，读者（包括未来的 AI 维护者）记住的是"为什么"，而不是"是什么"。**

---

## 5. 为什么这样设计（产品层面的洞察）

1. **AI 协作产品最大的信任危机是"假装成功"**：所以文案系统性地站在"诚实"一边——教 Agent 说"没验证就是没验证"、把失败原因讲成人话、给下一步。口语化不是可爱，是**降低用户判断成本**：一眼看懂当前状态、为什么、该怎么办。
2. **用户不该被技术词汇挡在门外**：quota 注释直接写明动机——"用户看得懂 token，看不懂 $0.87 意味着多少对话"。工具/档位/额度这些系统概念全部翻译成动作和后果。
3. **Agent 是"同事"不是"系统"**：文案里的 Agent 有期待（"它正等着"）、有状态（"还没开始浏览"）、可以被"跟它说一句"。这把 Agent 的异步行为拟人成可预期、可对话的存在——与画布上精灵/在场感的设计同源。
4. **提示词即产品文案**：给 Agent 的协议用讲故事的方式写（"先看图…框本身就是话"），因为 Agent 也是"读者"，故事比指令更不容易被误解。
5. **口语化有测试兜底，不会退化**：README 明列"用户可见文案的措辞检查"为自动化测试之一；档位拒绝语的措辞有 lint 钉着（"只说当前档位不包含，不给任何去哪里要资格的路径"）；英文词表有对账 lint 防静默失配。**亲和力不是靠自觉，是靠测试保护的文化。**

## 6. 可借鉴清单：AI 协作产品的文案手法

| # | 手法 | 例子（思路级） | 适用场景 |
|---|---|---|---|
| 1 | **空态 = 缺什么 + 下一步** | "还没写，点开写项目档案" | 一切空态/引导 |
| 2 | **预判焦虑并解答** | "画面不动是正常的，不是卡住了" | 异步、慢、静默的操作 |
| 3 | **技术词翻译成动作** | 钥匙/体检/跟它说一句 | 配置、状态、报错 |
| 4 | **错误 = 转告语 + 不重试指令** | "原话转告用户，不要重试" | 工具/能力/配额被拦 |
| 5 | **拒绝带转向** | "生图改走 generate_image；要用本地产线得先开机" | 一切 deny 路径 |
| 6 | **把 Agent 当人称** | "它正等着" / "跟它说一句" | 一切涉及 Agent 的 UI |
| 7 | **给 Agent 的协议用故事写** | "先看图，他可能一个字没写，框本身就是话" | prompt 注入/工具说明 |
| 8 | **诚实协议显式写** | "没验证就明说没验证" | 教 Agent 与用户打交道的规则 |
| 9 | **注释写事故与因果** | "那正是以前镜头横跳的原因" | 全仓注释纪律 |
| 10 | **措辞用测试钉住** | 拒绝语 lint、词表对账 lint | 防止口语化文化退化 |

---

## 7. 一句话总结

> NoDesign 的口语化不是"文风活泼"，而是**"人话"作为一种产品价值观的三层落地**：UI 文案让用户秒懂状态与下一步，Agent 提示语教 Agent 诚实转述，代码注释让维护者记住"为什么"。它和"消灭假成功""不给必然失败的交互"是同一条设计主线——**在 AI 协作里，让双方（人和 Agent）都少猜，是一切亲和力的来源。**
