### 2.2 snapshot JSON 的形状（**逐字对齐 `store.ts:95-110` 的 `ExportSnapshot`**）

```ts
// vendor/pi-rp/packages/memory/src/store.ts:95-110
export interface ExportSnapshot {
  nodes: MemoryNode[];                                          // 见 2.3
  revisions: Array<{
    node_id: string;
    version: number;
    uri: string | null;
    content: string;
    editor_source: string | null;
```

## 3. 行为契约·逐步（每一步都写「漏了会怎样」）

### 3.1 规模决策：**48 节点**（轻于埃利亚斯的 73）

**问题（`00 §8` 待拍板项 4）：对齐 73 还是更轻？本文定：48——约 66%，仍轻于埃利亚斯的 73。**（本批 2026-09-15 契约升级：明月记忆库接任「人格真相源」，group A 从 12 扩到 16，见 §11 C5。）****

理由三条，缺一不可：

1. **角色动机（决定性）**。埃利亚斯的 73 节点是他「用整理对抗失控」的**人格投射**——越全、越精确、越冷，越像他。明月是**反命题**：她的记忆是「一本笔记，记的全是人」，笔记就该是**薄的、热的、只留有事的人的**。给她建 73 节点等于把她写成第二个埃利亚斯，直接抹掉 `00 §2.0` 的三分工。
2. **功能充分性**。本批可玩窗口 = 9/3–9/5 的短闭环（`00 §4`）。库只需支撑：(a) 出场地（`frontier-lab`）、(b) 观察埃利亚斯（白兰花 + 她对他反应的注意）、(c) 初识玩家、(d) 日常「记人」的质感。48 节点全数覆盖；扩库后 group A 承载全部人格正文，其余四组只留观察与世界观，不注水。

> **扩库后保留的 5 个新增 identity 节点的理由（每个都无 01 移交正文对应，属补侧面的自决项，见 §11 C9）**：`language`（中英来回是她的岗位核心能力，`00 §3.1` 冻结事实，无节点承载则人设缺一角）；`work_ethic`（她「把小事做在前面」的动机，`00 §3.1`「为什么是她做这个岗」的延伸）；`self_reflection`（她「有温度的存活」命题的内省落点，`00 §2.0`）；`wants`（未实现的私人渴望，给 05 关系推进留钩子）；`relationship_pattern`（她「停在熟」的边界机制，`00 §3.1`「观察但不越界」的内化）。**这 5 条互不重复、也未被既有节点覆盖**，故保留；其余 4 条疑似重复的一律删（C9）。
3. **引擎成本**。`awaken` slot 把**每条 awaken_uri 的全文**塞进系统提示（`slots.ts:49-90`），`index` slot 每个根节点一行（`slots.ts:116-128`）。节点越多，每次开局的 prompt 越重。轻库 = 更快的冷启动 + 更聚焦的召回池。

> **不做**：不为了「看起来和埃利亚斯一样丰富」而注水。注水节点会污染 `recall` 的召回面（多一个无关节点就多一个误召）。

### 3.2 构建 step-by-step

| 步 | 动作 | 漏了会怎样 |
|---|---|---|
| S1 | 读 `blueprint.json`（节点表，§4） | 没有蓝图源，库无法复现，改一条记忆要手抠 db |
| S2 | 为每节点生成稳定 `node_id`（UUIDv4），建立 `uri → node_id` 映射 | 无映射则 `parent_id` 无法解析为 UUID，树塌成孤儿 |
| S3 | 用 `uri.split("://")[0]` 派生 `domain`（恒为 `core`） | `domain` NOT NULL，漏了直接 INSERT 失败 |
| S4 | 把 `parent_uri` 解析成父节点 `node_id`，写入 `parent_id` | ⚠️ 若错写 parent_uri（而非 node_id），`import()` 逐字绑定 → `verify #7 无孤儿 parent_id` 失败 |
| S5 | 对每节点算 `content_hash = FNV-1a(content)`（按 UTF-16 code unit 迭代） | ⚠️ `import()` **不重算**（`store.ts:1278`）；hash 错 → 后续 `revise`/增量更新检测失效（且 verify 的 7 字段对账**不覆盖它**，见 §7.3 追加核验） |
| S6 | 写 `world_ts`：默认 `null`，仅蓝图标了日期的节点写值 | ⚠️ 批量填世界钟 → 每条记忆都声称发生在 2020-09-03（§3.3） |
| S7 | 写 `updated_ts`：按蓝图 `recency` 单调递增，让 `recent` slot 出对的 5 条 | 全同时间戳 → `recent` 退化成随机 5 条（`slots.ts:99` 按 `updated_ts DESC`） |
| S8 | 组 `kv = { schema_version:"2", world_time:"2020-09-03", awaken_uris: JSON.stringify([...]) }` | 漏 `world_time` → awaken slot 不渲染「当前世界时间」行（`slots.ts:86-88`）；漏 `awaken_uris` → awaken slot 渲染空块，`verify #10` 失败 |
| S9 | `aliases=[]`，`edges=[]`（对齐埃利亚斯实测值：alias 0 条、edge 0 条） | 编造 alias/edge 指向不存在目标 → `import()` 校验失败**整体回滚**（`store.ts:1301-1318`） |
| S10 | 组 `glossary`：关键词 → 既有 `node_id`（§4.4） | 引用不存在的 node_id → 整体回滚（`store.ts:1320-1327`）；且专有名词在 jieba 分词后会碎，召回失灵（`reindexNode` 追加整词，`store.ts:1411-1428`） |
| S11 | 写 `snapshot.json` | — |
| S12 | `import_to_pi_memory.mjs` 写库（FTS 由 pi 的 jieba 分词建） | ⚠️ 手搓 INSERT 会漏分词 → 检索静默失效；`import()` 内部走 `reindexNode()` 才是对的 |
| S13 | `verify_migration.mjs` + §7.3 追加核验 | 只信 import 摘要 = 交付未证 |

### 3.3 `world_ts` 纪律（**硬要求，本批最贵的坑**）

| | 存哪 | 含义 | 该不该批量填 |
|---|---|---|---|
| **世界钟** `world_time` | `memory_kv` 一个键 | 整个世界的「当前日期」，渲染成 `> 当前世界时间: 2020-09-03` | ✅ 给**一个**值 |
| **发生于** `world_ts` | 每个节点的列 | 这条记忆**发生在哪天** | ❌ **绝不批量填** |

**铁律：`world_ts` 默认全 NULL；只有确有事件锚点的节点才写时间；绝不拿世界钟批量填。**
批量填的后果：每条记忆都声称发生于 2020-09-03 → 相对时间全部显示「今天」，`formatRelativeWorldTime` 加权全错，且唤醒了埃利亚斯创伤日期（`2007-10-28`）的同日语义。

**本批实测对齐**：埃利亚斯 73 节点里仅 **6 条**非 NULL（`childhood_trauma_2007`/`white_orchid_2007`/`freesia_2007`/`relationship/lucas` = `2007-10-28`；`world/singularity` = `2018-06-01`；`world/stellar` = `2020-06-15`）。明月取同样的稀疏姿态——48 节点里 **仅 2 条**写时间（见 §4.3）。

### 3.4 `recent` slot 与 `updated_ts`

`recent` slot 走 `store.listRecentNodes(snippetCount)` → `ORDER BY updated_ts DESC`（`slots.ts:99`、`store.ts:1208-1212`）。因此 `updated_ts` **不是随便填的作废字段**，而是「她最近在想什么」的排序键。构建脚本按蓝图 `recency` 字段（整数，越大越新）生成 `updated_ts`，使 `recent` slot 恰好浮出本批最该被想起的 5 条（§4.5）。

## 7. 错误边界（矩阵）与独立核验方案

### 7.1 构建/写库阶段错误矩阵

| 情况 | 报错位置 | 写入结果 |
|---|---|---|
| 缺 `nodes`/`kv`/… 六个顶层键之一 | `import()` 迭代时 TypeError | **无写入**（事务未提交） |
| `domain` 为 `null`/缺 | `nodes.domain NOT NULL` | **无写入** |
| `source` 不在 `{auto,manual,import}` | `CHECK(source IN …)` | **无写入** |
| `parent_id` 指向不存在的 node_id | 不清算——`import()` 逐字绑定，**不校验 parent**（`store.ts:1262`） | **写入成功但树孤儿** → 被 §7.3 追加核验拦下 |
| `alias.target_node_id` / `edge.target_uri` / `glossary.node_id` 指向缺失 | `import()` 抛错，**整个事务回滚**（`store.ts:1303-1327`） | **无写入** |
| `content_hash` 与 content 不匹配 | `import()` **不重算**，静默绑定 | **写入成功但 hash 错** → 被 §7.3 追加核验拦下 |

> 结论：`import()` 只兜住「引用完整性」；**树孤儿与 hash 错必须靠 §7.3 追加核验**（既有 `verify_migration.mjs` 的 7 字段对账**不含 `content_hash`**，见 `verify_migration.mjs:41-52`）。

### 7.3 追加核验（NEW，`verify_mingyue.mjs`；**机械可执行**）

既有脚本不覆盖的三项，写成一份小脚本（也可内联进 build 的 `--check`）：

```js
// 追加核验 —— 用 pi 真库打开，独立重算
// 用法: node verify_mingyue.mjs <snapshot.json> <memory.db> <pi-memory src/index.ts>
const { openMemoryStore } = await import(process.argv[4]);
const src = JSON.parse(readFileSync(process.argv[2], "utf-8"));
const s = await openMemoryStore(process.argv[3]);
const nodes = s.listNodes();

// A1 规模：48
assert(nodes.length === 48, `nodes=${nodes.length}`);

// A2 world_ts 纪律：非空 == 2，且两两不同（==1 即被世界钟批量污染）
const withTs = nodes.filter(n => n.world_ts);
```
