## 共用验收口径

- **先导入，再进入一级视图**。先知道我是谁、在哪里、为什么动；不先给空画布或世界配置表。前五个世界的详细设计见 [doc-24](doc-24-五世界可玩Demo体验设计.md)，第六个见 [doc-25](doc-25-未写之门Demo.md)。
- 每个短闭环都要让 A「世界活着」、B「角色认识我」、C「我改变了世界」落到可指认的同一条因果链：玩家行动 → 角色引用行动 → 另一物件 / 场景改变 → 短回报。未写之门可由通话者承担 B；跳过通话的路径不能声称已验证 B。
- 时间表是**设计预算**，不是模型测速或强制倒计时。主线以短体验完成为准；自然生成段按 1–2 分钟安排，一次只展开一个有用的小场景，不硬塞新城、新角色、立绘和 CG 四连生成。
- README 是场景配置与场景 Chalk 的承载处；层由目录扫描。可扩展处才给 Chalk 生成入口；普通查看不自动生成子目录。道具文件门槛与 Writer 对 RP 的判断分别验收，不能把文件存在等同剧情正确。
- 文字 / README / 可行动的 Chalk 先到，图片随后。图片失败保留文字路径，不自动反复收费重试；回访不重造地点、人物或已确认事实。当前同步生图会占用 Writer 队列，不能把“文字可读”宣传成“后续 RP 完全不等待”。
- 实时生成的人物 Markdown 可由 Writer 演出；独立 Character Agent 还需角色注册、上下文与前端接线，不能仅凭一个人物文件宣称完成。
- 核心事实、代价和可生成边界由上帝模式预写，Writer 补玩家行动带来的结果，不偷换凶手、不替玩家作最终选择。TTS / Voice Agent 不作为这轮骨架验收前置。
- 文档中文；日语世界正文、提示词与演示文案需分别迁移。当前只有 `first-snow-jp` 的独立日语版本在此轮样板范围内；复用图片不等于其他五个世界已完成日语化。

## 如何记录一次真实验收

每次使用新存档，记录模板与 Git 版本、所选路径、关键行动、实际落盘文件、重复进入结果，以及 5173 上玩家看到的画面。分别标注「设计」「静态 / 离线验证」「真实模型」「浏览器实玩」，不互相替代。

涉及外部生成时，另记已授权的服务和模型（不记密钥）、请求开始 / 首段可玩文字 / 图片落盘时间、失败信息。1–2 分钟未达到就记真实数值，不用预写结果冒充 AI 输出；费用与服务授权沿用独立生成测试流程，不由本验收文档扩大。

本次新增五份文档并保留初雪样板；新增文档的“当前记录”来自 2026-09-13 的模板与代码文档核对，**没有在本轮运行付费模型或生成新的游玩存档**。
