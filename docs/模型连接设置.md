# 模型连接设置

启动作家／角色时，`engine/provider-config.ts` 将版本管理中的 `config/deepseek-models.example.json` 缺失模型合入本地表；保留已有 provider、密钥引用及同名模型设置。上传无需携带本地 `.pi/agent/models.json`。手动修改环境文件后需重启后端；仅刷新网页不会更新进程环境。

前端 `Server connections` 增加 DeepSeek V4.1 Flash（`DEEPSEEK_API_KEY`）。作家与角色的环境变量白名单均透传此 key；不修改 pi-rp，不自动切换正在运行的世界模型。未接入 MiniMax。

仅 localhost 可读写连接设置。GET 只返回密钥是否存在，POST 空值保留现值。存在 `.local.env` 时优先写入它，否则写入 `.env.local`；文件权限为 0600。启动加载顺序为 `.local.env`、`.env.local`、`.env`，已存在的进程环境变量优先。两个本地文件均不提交。

保存密钥后需要重启现有 Agent，才能继承新环境并刷新可用模型；随后在 `Agents → Model` 为作家／角色分别选择。配置成功不等于 API 授权成功，未输入真实密钥时不进行付费调用。

使用官方模型 id `deepseek-flash`，不是 `deepseek-v4.1-flash`。本地 `.pi/agent/models.json` 注册该名称；无密钥版本的参考配置在 `config/deepseek-models.example.json`，已有模型表应合并 providers.deepseek，不覆盖其他 provider。配置使用文本输入及保守请求上限，不代表模型能力极限。模型表只引用 `$DEEPSEEK_API_KEY`，不存放密钥。

模型名称和服务地址见 [DeepSeek 官方接入文档](https://api-docs.deepseek.com/)。`.local.env` 提供注释形式的默认模型配置，填好 key 后再启用，避免无密钥切换使现有世界无法使用。已有存档的模型偏好优先，需要在 Agents 面板中分别切换作家／角色。
