## 1. 一句话架构

**扩展跑在 agent 进程内，server 跑在另一个进程；两者不直接通信，共享的唯一通道是世界的文件系统 + 两个 SQLite。**

```
┌────────────── server 进程 ──────────────┐     ┌─────────── agent 进程（writer / character）───────────┐
│ Express 路由 + ws 广播                   │     │ extensions/*.ts（jiti 直跑 TS，无构建步骤）            │
│  · new LocalWorldStore(worldRoot)        │     │  · new LocalWorldStore(ctx.cwd)   ← 同一个世界目录      │
│  · fs.watch → file_changed               │     │  · registerTool(AIRP 动作工具)                          │
│  · 尾部读 events 表 → world_event 广播   │     │  · appendEvent(...)（工具自己落账）                     │
└───────────────┬─────────────────────────┘     └───────────────────┬───────────────────────────────────────┘
                │                                                    │
                └──────────► <worldRoot>/{*.md, canvas.db, history.db} ◄──────────┘
                             （WAL，两侧各自开连接）
```

**由此推出的硬约束**：

- 动作实现 MUST 以"传入一个 `WorldStore`"为形状，**两个进程各自 new 一个**。工具实现内部 MUST 自闭环（落盘 + 落账），不得依赖"server 会替我补"。
- 扩展 MUST NOT 假设自己连着 WebSocket。工具想把"演出帧"推给前端，只能靠 **返回值 `details`**（经 pi-rp `tool_execution_end.result` 流到 server 的 `onEvent`）或**落一条事件**（server 尾部读表后广播）。
- 扩展 MUST NOT 用 `process.cwd()` 之外的路径猜世界根：**cwd 就是世界根**（`launch.ts` 保证），但仍优先用 `ctx.cwd`。

## 2. 文件与路径契约（冻结）

### 2.1 路径格式

- 一律**世界根相对路径**、POSIX `/`、无前导 `./`、无绝对路径。
  - `world/baker-street/evening.md`、`player/copper-key.md`、`characters/watson/letter.md`。
- 工具的 path 参数 MUST 接受这种格式；接受后 MUST 经 `WorldStore` 的路径解析（已剥 `../`），**不得**自行拼绝对路径。
- 目录目标（`world/baker-street/`）用**目录路径**表达，不带末尾 `/`。
- 资源路径同样以世界根为基准，一律写 `.airpworld/assets/…`（含 `.airpworld/` 前缀）。

### 2.2 世界目录结构

```text
<worldRoot>/
├── world.json                 # manifest（世界级事实；没有 layers 字段）
├── world/                     # 层树：world/**/ 每个目录 = 一个层
│   ├── README.md              # map 层的场景配置（type: readme）
│   └── <layer>/
│       ├── README.md          # 该层的场景配置；无 README = stub 层
│       └── *.md               # chalk / note / letter / gate / component
├── characters/<id>/           # 角色小天地（根目录本身即小天地）
│   ├── preset.json            # 配置，不算内容
│   ├── README.md identity.md appearance.md personality.md
│   └── *.md                   # 角色留痕
├── player/                    # 玩家背包 ≡ 玩家小天地
│   └── *.md
└── .airpworld/                # 系统目录（任何工具都不遍历它）
    ├── canvas.db  history.db                # 见 §4
    ├── assets/                              # 二进制资源 / 生成图片（**内容**，只是不可被工具遍历）
    ├── prompt-presets/  sessions/           # 引擎用
```

**层由目录扫描派生，不在 `world.json` 声明**（唯一真相源 = 目录树；派生逻辑 `packages/shared/src/store/layers.ts`）。工具 MUST NOT 假设 `world.json` 里有 `layers`。

### 2.3 chalk 文件命名（冻结）

新建 chalk 的默认路径：**`<layerDir>/NN-<slug>.md`**，`NN` 为两位零补序号（该目录内已有 `NN-*` 的下一个空号，从 `01` 起），`slug` 为标题的 kebab-case ASCII（`kitchen-look.md`）。`chalk` 工具 MUST 支持显式 `path` 覆盖默认命名；显式 path 冲突时 MUST 报错而不是覆盖（见 §7.4）。

> 现存模板（`evening.md` / `late-night.md`）是无序号的历史遗留，**不迁移**——引擎对既有文件只读不改名。

### 2.4 可移动实体（冻结）

`move` 的适用对象 = **一个单文件 `*.md`**，位于 `world/`、`player/`、`characters/<id>/` 之下，且**文件名不是 `README.md`**。

- `README.md` = 层门牌 / 场景配置，**不可移动**（它是层的身份，不是物件）。
- `gate` 由 README 派生，因此天然不可移动。
- 前端 UI 只把 `note` / `letter` 卡片渲染为可拖拽（doc-10 E5 的 `BAG_TYPES` 是**呈现层**约束）；引擎层不额外加类型白名单。**这是对 doc-10 E5 的一处刻意放宽**，理由：引擎的"移动"是文件语义，不能因为它认不出某个题材包组件就拒绝移动。

### 2.5 保留前缀

以下前缀对工具不可遍历：`.airpworld/`（系统）、`node_modules/`、任何以 `.` 开头的项。`look_at` 列目录时 MUST 过滤它们。但 store 的路径解析 MUST 放行 `.airpworld/assets/**`（资产的读写），并 MUST 拒绝含 `..` 段与 `node_modules` 段的路径。

## 3. 身份契约（冻结）

```ts
/** 事件的发起者。五个值，god 单列（doc-21 §3.2）。 */
export type ActorType = 'player' | 'god' | 'writer' | 'character' | 'engine';
export interface Actor { type: ActorType; id?: string }   // id 仅 character 有
```

**扩展侧怎么知道我是谁**：读环境变量 `AIRP_AGENT_ROLE`（B0 留的 `airpEnv()` 是唯一注入点）。

| 值 | 谁 | 由谁设置 |
|---|---|---|
| `writer` | 作家主 agent | `writerLaunch` 新增 |
| `character:<id>` | 角色 agent | `characterLaunch` 新增 |
| `scene-init` / `nook-init` | 初始化子代理 | 子代理继承父进程 env；B1 只要求 writer/character 两个值落地 |
| （未设置） | 兜底 = `writer`，并在 stderr warn 一次 | — |

**HTTP 路由侧**：由请求体或路由决定——`/api/*` 的玩家操作用 `player`；上帝模式路由用 `god`。

> **pi-rp 事实**：角色 agent 与作家 agent 是**两个独立进程**、各自加载同一份 `extensions/*.ts`；`AIRP_AGENT_ROLE` 是它们唯一的身份差。子代理（`spawnAgent` / `subagent`）与父进程同进程，**继承同一份 env**，因此 `scene-init` 子代理看到的 role 仍是 `writer`——凡涉及"角色默认移动自己"这类默认值逻辑，MUST 以 `AIRP_AGENT_ROLE` 为准，且对未识别值安全降级。

## 4. 存储契约（冻结）

| 库 | 文件 | 谁写 | 放什么 |
|---|---|---|---|
| canvas.db | `.airpworld/canvas.db` | server 与扩展都可写 | 画布**状态**：`cards` / `links` / `presence` / （新增）`viewpoint` |

### 4.2 谁能落账

**经过引擎动作函数的工具自己落账；`tool_result` hook 只兜原生 `write` / `edit`。两份名单 MUST 互斥**（doc-21 §2），否则 `chalk` 被落两次。

| 入口 | 覆盖 | 落账位置 |

| A 动作层工具 | `chalk` `move` `move_to` `choose` `roll_dice` `use_item_on` `set_following` `delete` | 动作函数内部 |

## 5. 事件契约（冻结，取自 doc-21 §4）

### 5.1 表结构（要改成）

```sql
CREATE TABLE events (
  seq        INTEGER PRIMARY KEY AUTOINCREMENT,   -- 游标唯一依据
  id         TEXT NOT NULL UNIQUE,                -- evt-xxxxx
  project_id TEXT NOT NULL,
  type       TEXT NOT NULL,
  actor_type TEXT NOT NULL,                       -- player|god|writer|character|engine
  actor_id   TEXT,
  layer      TEXT,
  subject    TEXT,
  turn       TEXT,
  detail     TEXT NOT NULL,                       -- JSON，按 type 定形
  created_at TEXT NOT NULL
);
CREATE INDEX idx_events_seq   ON events(project_id, seq);
CREATE INDEX idx_events_layer ON events(project_id, layer, seq);

CREATE TABLE read_cursors (
  reader     TEXT PRIMARY KEY,                    -- 'writer' | 'character:<id>'
  seq        INTEGER NOT NULL,
  updated_at TEXT NOT NULL
);
```

**世界目录还没有真实存档 → 直接改 `CREATE TABLE`，不写迁移脚本**（doc-21 §7 明写）。旧 `events` 的 `id/project_id/type/payload/created_at` 五列要**整体替换**为上面十列；`payload` → `detail`。

### 5.2 十五个封闭类型与 `detail` 形状

| type | detail（冻结字段名） |
|---|---|
| `entity_created` | `{ path, name, kind: "chalk"\|"component"\|"note"\|"letter"\|"other", summary? }` |
| `entity_edited` | `{ path, name, kind }` |
| `entity_deleted` | `{ path, name }` |
| `entity_moved` | `{ from, to, name, near?, rewrote: number, dangling: number }` |
| `character_moved` | `{ character, name, from?, to, near? }` |
| `following_changed` | `{ character, name, following: boolean }` |
| `character_talked` | `{ character, name, turns: number }` |
| `choice_selected` | `{ path, name, choice, index }` |
| `roll_resolved` | `{ path, name, dice, desc, expect, result, passed }` |
| `use_item_on` | `{ item, itemName, target, targetName }` |
| `layer_entered` | `{ layer, name, first: boolean }` |
| `layer_initialized` | `{ layer, name, by, files: string[] }` |
| `layer_init_failed` | `{ layer, reason, fallback }` |
| `world_snapshot` | `{ snapshot, reason }` |
| `world_rolled_back` | `{ snapshot, to }` |

**`detail` 必须自足**（doc-21 §3.3）：除路径外 MUST 带**当时的 `name`**，渲染人话时不许回读世界目录。但**不存正文**。
`detail` MAY 额外带可选键（如 `component` / `secondLayer`），既有键名与枚举不变。

**失败不落**（doc-21 §3.6）：工具返回 `isError` 时不落事件。唯一例外 `layer_init_failed`。

### 5.3 server 尾部读表 → WS（冻结）

tools 与扩展不能直连 WS。**统一通道：server 尾部读 `events` 表**。

- server 维护进程内 `lastSeq`；在 `fs.watch` 触发时（以及一个 ~1s 的兜底定时器）调 `getEventsSince(lastSeq)`；
- 有新事件 → `lastSeq` 推进 → 逐条 `broadcast({ type: 'world_event', event })`；
- `.airpworld/` **不再整体过滤**（现在 `event-bridge.ts:138` 过滤掉了它，这会让 history.db 的变化永远看不见）；改为只过滤 `.airpworld/assets/` 与 `.airpworld/sessions/`。

**帧名与事件 `type` 不共用一个命名空间**（doc-21 §7）：演出帧（`chalk_writing` / `writer_delta` / `roll_resolved`…）是瞬时传输帧；世界事件统一包在 `world_event` 里。前端靠这个分"这是演出还是历史"。

> `roll_resolved` 同时作为**演出帧名**与**事件 type** 存在，是唯一的历史遗留重叠。冻结处理：演出帧改名 `dice_result`（只走 WS、不带 event 行），事件仍是 `roll_resolved`。

## 6. 工具注册契约（冻结）

> `01 §5` 的方法表是**索引**；工具的输入形状以各自的 `NN-*.md` 为准，两者不一致时以工具文档为准并回写 `01 §5`。

### 6.1 文件布局

```text
extensions/
├── instructions.ts          # 已有：4 个 slot（B1 不动）
├── tools.ts                 # 新建：唯一的 registerTool 入口（extensionArgs 只扫顶层 *.ts）
└── toolkit/                 # 新建：工具实现与共享 helper（子目录 => 不被当扩展加载）
    ├── actor.ts             # Actor 解析（env / 参数）
    ├── store.ts             # 打开世界 store 的单例 helper
    ├── result.ts            # ToolResult 构造 helper（ok / fail）
    ├── <每个工具一个文件>.ts
    └── ...
```

- `extensionArgs`（`presets.ts:91`）只扫 `extensions/` 下**顶层的** `.ts`/`.js` 文件；`toolkit/` 是目录，**不会被当扩展加载**——这正是把它放子目录的理由。
- `extensions/tools.ts` 的 default export 里逐个 `pi.registerTool(...)`，实现从 `./toolkit/*.ts` import。
- **扩展直跑 TS，无构建步骤**（jiti）。改完重启 agent 进程即生效。
- 扩展要 import 共享代码：**相对路径** `../packages/shared/dist/index.js`（已实测可从 `extensions/` 下被 jiti 解析）。**不要**用包名 `@airp/shared`（`extensions/` 不在 pnpm workspace 里，解析不到）。
  > 因此 `packages/shared/src/` 一改就 MUST `pnpm build`，否则扩展跑的是旧 `dist`（AGENTS.md §6.5 红线）。

### 6.2 工具定义形状

```ts
import { Type } from 'typebox';                 // loader 的 virtualModules 已别名
import type { ExtensionAPI } from '@earendil-works/pi-coding-agent';

pi.registerTool({
  name: 'move_to',
  label: 'Move To',
  description: '…（给模型看的：做什么、何时用、何时别用）',
  parameters: Type.Object({
    character: Type.Optional(Type.String({ description: '…' })),
    destination: Type.String({ description: '…' }),
    near: Type.Optional(Type.String({ description: '…' })),
  }),
  // 可选：让工具进入 system prompt 的 Available tools / Guidelines 段
  promptSnippet: '…一行…',
  promptGuidelines: ['Use move_to when …'],   // 必须点名工具名，不要写 "use this tool"
  async execute(toolCallId, params, signal, onUpdate, ctx) {
    return { content: [{ type: 'text', text: '…' }], details: { … } };
  },
});
```

**返回形状（冻结）**：

```ts
interface ToolResult {
  content: Array<{ type: 'text'; text: string }>;   // 给模型看的人话结果，英文
  details?: Record<string, any>;                    // 给引擎/前端用的结构化结果，稳定字段
  isError?: boolean;                                // 失败：必须是可见失败，不许静默降级
}
```

- **文本语言 = 英文**（提示词与工具面全英文，见 AGENTS.md §1.1）。
- 文本 MUST 说明**实际发生了什么**，并返回后续动作需要的**稳定路径**。
- `details` 的字段名一旦被 server 映射消费，MUST 保持稳定；建议含 `{ path?, event?, ... }`。
- **错误不得静默降级成成功**：抛错或返回 `isError:true` + 可读原因。

### 6.3 参数与工具面的纪律

- `tools.allow` 是**过滤器不是扩展器**（pi-rp 约束 C2）：preset 里写 `allow:["chalk"]` **加不出** `chalk`。AIRP 的 preset **不写 allow**。
- 工具名 MUST 与 doc-20 §1 一致：`look_at` `view_canvas` `chalk` `move_to` `move` `choose` `roll_dice` `use_item_on` `set_following` `link` `arrange` `delete` `get_component` `show` `generate_image`。
- **不要造内建工具的同义词**（如 `write_world_file`）：初始化器开箱就有 `write`/`edit`（pi-rp C1 已修）。
- 子代理继承扩展工具：R1 (`subagent`) 自动继承父会话工具；R2 (`spawnAgent`) 需显式传 `customTools`（pi-rp `dfebadcd3`）。工具实现因此 MUST 自闭环，不假设"只有作家会调"。

## 7. 每篇工具文档 MUST 有的结构

1. **一句话与定位**——解决什么、在 doc-20 的哪一条、谁是调用者（作家/角色/玩家 UI）。
2. **签名与参数**——完整 TypeScript 形状 + 每个参数的类型、必需性、语义、示例值。
3. **行为契约（逐步）**——编号步骤；每步写"漏了会怎样"（doc-23 §2.4）。
4. **文件与副作用**——改哪些文件、什么命名、frontmatter 骨架、写盘原子性。
5. **落账**——事件 type、`actor`、`subject`、`layer`、`turn`、`detail` 全字段；失败时是否落、落什么。
6. **WS / 前端**——工具 `details` 里带什么、server 怎么映射成帧、前端拿到后演什么。
7. **错误与边界**——所有失败模式 + 精确错误文案（英文）+ 是否 fallback；**不静默降级**。
8. **要实现/修改的代码落点**——精确到文件与函数：`packages/shared/src/actions/*.ts`、`extensions/toolkit/*.ts`、`routes/world.ts`、`schemas/*.ts`。
9. **与现存实现的差异**——现状（带文件:行）+ 要改成什么 + 迁移影响（旧调用点）。
10. **验收与测试**——可执行判据（探针能断言什么 / 单测什么纯函数 / 手测什么场景）。
11. **发现的冲突 / 需要修订的上位文档**——见 §0。
12. **仍然未知 / 留给评审拍板的**——不许假装没有。

**事实要带证据**：写"现状是 X"必须给 `文件:行`；写"pi-rp 行为是 Y"必须给源码或上游文档路径。**推断要标注 `[推断]`**。

## 8. 反模式（MUST NOT）

- ❌ 在 Express 路由里另写一套骰子 / 移动 / choice 规则——MUST 复用 01 的动作服务（doc-20 §12 / plan §4）。
- ❌ 用 `bash mv` / 原生 `write` 模拟 `move` / `chalk`——MUST 走引擎动作函数（doc-20 §5）。
- ❌ 引入 `get_state` / `set_state` / `state_update` / `watch_state` / 状态文件 / 状态命名空间——**绝对不做，非暂缓**（doc-20 §2.3）。
- ❌ 造 `inspect` / 通用 `interact` / `speak_to` / `remember` / `leave_trace`；拆 `take/drop/place/give` 或 `invite/follow/leave`。
- ❌ 动作路由里直接 `writer.prompt(...)` 打断作家——**不打断、不自动起 turn**（doc-05 §5.1、doc-21 §5.5）。`use_item_on` 是否用 `followUp` 破例，见 `08-*` 的取舍登记。
- ❌ 在工具文本或事件 `detail` 里塞全文——事件只带 `path` + `name` + 至多一行摘要。
- ❌ 让 `fs.watch` 写事件表（doc-21 §2.1）。
- ❌ 在 `world.json` 里声明 `layers`。
- ❌ 给角色加"只能写自己目录"的权限门禁（doc-20 §1.1：能力不按身份裁）。

## 10. 需要一并修掉的既有问题（B1 范围内）

## 11. 评审门

12 篇文档产出后，评审依次检查：

1. **跨文档一致性**：同一路径/事件/字段名，各文档写法是否一致？

6. **可实施性**：代码落点是否精确到文件与函数名？
7. **诚实性**：未知项有没有被伪装成已定？
