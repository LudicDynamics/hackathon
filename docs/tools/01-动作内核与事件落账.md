## 1. 一句话与定位

**`packages/shared/src/actions/` 是"校验 → 落盘 → 落账 → 返回"的唯一实现处：server 的 HTTP 路由与 agent 的扩展工具各自 new 一个 `WorldStore`，但都调用同一个 `createActionService(store, actor)`——因此 UI 与 Agent 不可能跑出两套骰子、两套移动、两套 choice 语义。**

它在 `doc-20` 里的位置：`doc-20 §12` 最后一句「实现顺序：先抽互动字段与动作服务，再注册 Agent 工具，最后让现有 HTTP 路由复用动作服务」。这句话的产物就是 `actions/`。

三类调用者：

| 入口 | 调用者 | 进程 | actor 来源 |
|---|---|---|---|
| A 动作层工具 | 作家 agent / 角色 agent（`extensions/toolkit/*.ts` 薄壳） | agent 进程 | `AIRP_AGENT_ROLE` → `resolveAgentActor()` |
| C 玩家 UI 路由 | `apps/server/src/routes/world.ts` | server 进程 | 路由决定（`player` / `god`） |
| E 引擎 | 初始化 / 快照 / 回滚 / hook（B2 `tool_result`） | 两侧都有 | 显式传 `{type:'engine'}` 或 `{type:'writer'}` |

**这一层不认识 HTTP、不认识 WebSocket、不认识 pi-rp。** 它只认识 `WorldStore` + `Actor` + `turn`，返回 `{ text, details }` 或抛 `ActionError`。演出帧、`isError`、`content[].text` 的包装都是调用者的事（A 入口归 `extensions/toolkit/result.ts`，C 入口归路由）。

### 2.2 `types.ts`

```ts
import type { WorldEvent } from '../schemas/events.js';
import type { WorldStore } from '../store/world-store.js';
import type { Actor } from './actor.js';

/**
 * Everything an action needs, and nothing else.
 * Deliberately transport-free: no HTTP req/res, no WebSocket, no pi-rp types.
 * Frozen fields: store / actor / turn / now? / rng?. No AbortSignal, no progress channel.
 */
export interface ActionContext {
  store: WorldStore;
  /** Who is acting (00 §3). */
  actor: Actor;
  /**
   * Merge anchor (doc-21 §3.4). One agent turn, or one HTTP request.
   * Opaque string; the action layer never parses it, only forwards it.
   */
  turn: string;
  /** Injectable clock for tests; defaults to () => new Date().toISOString(). */
  now?: () => string;
  /** Injectable uniform [0,1) source for `rollDice`; defaults to Math.random. */
  rng?: () => number;
}

export type ActionDetails = Record<string, any>;

/**
 * The single return shape of the whole action layer.
 * `text` is the human-facing English line (00 §6.2); `details` is the stable
 * structured payload the router and the toolkit wrap differently.
 * `event` is OPTIONAL: read-only actions (lookAt / viewCanvas / getComponent /
 * showComponent) write nothing and therefore carry no event.
 */
export interface ActionResult<TDetails extends ActionDetails = ActionDetails> {
  text: string;
  details: TDetails & { event?: WorldEvent };
}
```

**为什么 `text` 在动作层而不是在工具壳里生成**：`doc-20 §10` 要求「文本必须说明实际发生了什么，并返回后续动作需要的稳定路径」。如果文本在工具壳里拼，UI 入口（C）就会拿到另一套话术，而 `doc-20 §12` 明禁两套语义。文本跟着事实走，因此在事实产生处产生。

**为什么 `details.event` 可选**：`b1-design-10` 已确认 `get_component` 是只读动作；强行要求 `event` 会逼它伪造一条事件，直接违反 `doc-21` 准入三问。

**`rng` 只服务于可测性**：`rollDice` 是本层唯一的随机源，注入 `rng` 让单测与探针能断言确定的 `result`/`passed`，而不用把 `Math.random` 打桩到全局。**纯规则函数（`rules/dice.ts` 的 `rollOnce` / `evaluateExpect`）无论如何都显式收 `rng` 参数**（归 07）——`ActionContext.rng` 只是把它接到 `Math.random` 的那根线。

### 2.3 `actor.ts`

```ts
/*** 事件的发起者。五个值，god 单列（doc-21 §3.2）。 */
export type ActorType = 'player' | 'god' | 'writer' | 'character' | 'engine';
export interface Actor { type: ActorType; id?: string }   // id 仅 character 有

/** The ONLY env var that carries agent identity (00 §3). */
export const AGENT_ROLE_ENV = 'AIRP_AGENT_ROLE';
export const CHARACTER_ROLE_PREFIX = 'character:';

/**
 * Pure. Maps a raw `AIRP_AGENT_ROLE` value onto an Actor.
 * Never throws — an unknown role must not take down an agent process.
 */
export function resolveAgentActor(raw: string | undefined): {
  actor: Actor;
  /** Human-readable warning the caller logs ONCE; null when nothing is off. */
  warning: string | null;
};

/** Stable reader id for read_cursors (doc-21 §5.1/§5.2): 'writer' | 'character:<id>'. */
export function readerOfActor(actor: Actor): string | null;

/** 'player' | 'god' | 'writer' | 'watson' — log / history-panel label. */
export function actorLabel(actor: Actor): string;

/** 'player' | 'character:watson' — the compact form for detail fields that need it. */
export function actorRef(actor: Actor): string;
```

降级表（实现即此表）：

| `AIRP_AGENT_ROLE` | `Actor` | `warning` |
|---|---|---|
| `writer` | `{type:'writer'}` | `null` |
| `character:watson` | `{type:'character', id:'watson'}` | `null` |
| `character:`（空 id） | `{type:'writer'}` | `"AIRP_AGENT_ROLE='character:' has an empty id; falling back to writer"` |
| `scene-init` / `nook-init` | `{type:'writer'}` | `null`（合法值；子代理继承父 env，见 00 §3） |
| `undefined` / `''` | `{type:'writer'}` | `"AIRP_AGENT_ROLE is not set; falling back to writer"` |
| 其它任意串 `foo` | `{type:'writer'}` | `"Unknown AIRP_AGENT_ROLE='foo'; falling back to writer"` |

**`resolveAgentActor` 自己不打日志**——纯函数才可单测。`extensions/toolkit/actor.ts`（12 的文件）持有模块级 `let warnedOnce = false`，只把 `warning` 写到 `process.stderr` 一次。理由：init 子代理与父进程同进程，若不 warn-once，一次 scene-init 会在 stderr 刷十几行。

### 2.4 `errors.ts`

```ts
export type ActionErrorCode =
  | 'invalid_argument'      // 参数形状/取值非法
  | 'invalid_path'          // 路径不合规范（绝对路径、越出世界根、保留前缀）
  | 'not_found'             // 目标文件/目录/实体不存在
  | 'already_exists'        // 目标已存在，且本动作不许覆盖
  | 'not_movable'           // 违反 00 §2.4（README / 目录 / 世界外）
  | 'not_interactive'       // 目标没有 choice / roll_dice 字段
  | 'choice_not_found'      // 序号或文本对不上任何选项
  | 'malformed_entity'      // 文件存在，但声明的结构坏了（无 frontmatter / 字段缺失）
  | 'invalid_field_value'   // 某个已声明字段的值不可用（1d100x / expect 解析不了）
  | 'dice_already_rolled'   // doc-20 §7：已有 result 的骰子拒绝重掷
  | 'dice_forced_not_allowed' // forcedResult 仅 god 可用（doc-21 §4.3）
  | 'near_out_of_layer'     // `near` 不属于目标层（doc-20 §4）
  | 'no_free_seat'          // 排座失败
  | 'unsupported'           // 合法但本阶段未实现
  | 'write_failed'          // 落盘失败（含原子写失败）
  | 'event_failed'          // 落账失败（落盘已成功，账没落上）
  | 'internal';

/**
 * The ONLY failure channel of the action layer.
 * Convention (00 §8 / doc-21 §3.6): throwing means nothing was appended;
 * a caught ActionError MUST NEVER be downgraded into a success result.
 */
export class ActionError extends Error {
  readonly code: ActionErrorCode;
  readonly httpStatus: number;
  readonly details: ActionDetails;
  constructor(args: { code: ActionErrorCode; message: string; details?: ActionDetails });

  /** Wrapper for the A entry (00 §6.2 frozen ToolResult shape). */
  toToolResult(): {
    content: [{ type: 'text'; text: string }];
    isError: true;
    details: ActionDetails;
  };
  /** Wrapper for the C entry. */
  toHttp(): { status: number; body: { ok: false; code: ActionErrorCode; error: string } };
}

/** One-line call site for the hot paths. */
export function fail(code: ActionErrorCode, message: string, details?: ActionDetails): never;
```

```ts
  actor: Actor;

  detail: WorldEventDetail<T> & Record<string, any>;

  layer?: string;
  turn?: string;
```

### 2.7 `WorldStore` 事件 API（冻结 + 五处新增）

00 §4.1 的冻结形状逐字落成：

```ts
// packages/shared/src/store/world-store.ts
// === 事件层（取代 appendWorldEvent；getEvents 保留但改成 seq 排序）===
appendEvent(args: AppendEventArgs): Promise<WorldEvent>;   // 返回带 seq 的完整事件
getEventsSince(seq: number, opts?: { layer?: string; excludeActor?: Actor }): Promise<WorldEvent[]>;
getMaxSeq(): Promise<number>;
readCursor(reader: string): Promise<number>;               // 无记录 → 0
writeCursor(reader: string, seq: number): Promise<void>;
getEvents(limit?: number): Promise<WorldEvent[]>;          // 倒序，历史面板专用

// —— 00 §4.1 未列、但 01 判定必需的五处新增（理由见紧随的列表与 §13 冲突 5）——
/**
 * Layer id a world path belongs to, or null when the path is NOT in the layer
 * tree (`player/**`, `characters/<id>/**`, `world.json`). `world/**` → layerOfDir.
 * Mapping a bag path to 'map' would be a lie (doc-22 §3.2 expects it excluded).
 */
resolveLayer(path: string): Promise<string | null>;
/** Every cursor row — rollback must push them ALL to the max seq (doc-21 §6). */
getAllReadCursors(): Promise<Array<{ reader: string; seq: number }>>;
/** Same-dir temp file + rename; original untouched on failure; throws on error. */
writeFileAtomic(relPath: string, content: string | Buffer): Promise<void>;
/** Binary read — `readFile` is utf-8 only (local-store.ts:71); PNG/asset tiers need base64. */
readFileBase64(relPath: string): Promise<string>;
// `writeFile` is widened in the same pass: content: string | Buffer.
```

五处新增（`resolveLayer` / `getAllReadCursors` / `writeFileAtomic` / `readFileBase64` / `writeFile` 放宽）的理由：

- `resolveLayer` —— `layer_entered` 的 C 入口与全部动作填 `layer` 都要它；现在 `deriveLayer` 是 private（`local-store.ts:456`）。
- `getAllReadCursors` —— 回滚要把**全部**游标推到最新（`doc-21 §6`）。
- `writeFileAtomic` —— 改写既有文件不许留下半截（`rollDice` 回写、`writeChalk` 追加、`editEntity`）。
- `readFileBase64` —— `readFile` 是 utf-8 only（`local-store.ts:71`），`view_canvas` 的图片层要返回 `ImageContent` 块。
- `writeFile(Buffer)` —— `generateImage` 写二进制资源。


**`seq` 是游标的唯一依据**（doc-21 §3.1）。`created_at` 是毫秒 ISO 串，同一轮三次落账完全可能同毫秒；任何 `WHERE created_at > ?` 的写法都会重复念或漏念。实现层**禁用 `created_at` 做任何区间筛选**——`getEvents(limit)` 里现有的 `ORDER BY created_at DESC`（`local-store.ts:264`）也要改成 `ORDER BY seq DESC`：同毫秒下 `created_at` 排序不稳定，历史面板的条序会随机抖动。

## 3. 行为契约（逐步）

### 3.1 每个动作方法的五步骨架

所有方法 MUST 遵守，顺序不可换；每步的"漏了会怎样"就是它存在的理由。

1. **解析输入**：路径先过 `00 §2.1` 的路径纪律（世界根相对、POSIX `/`、无前导 `./`、无绝对路径），非法立即 `fail('invalid_path', …)`。
   *漏了会怎样*：`path.join(worldRoot, '/etc/passwd')` 会跳出世界根，工具变成越权写入通道。
2. **读取现状并校验**：本方法需要知道的全部文件 MUST 在读之前读完（存在性、frontmatter、当时的 `name`、受影响引用）。
   *漏了会怎样*：先写后校验 = 半完成状态，`move` 会出现"文件已挪走、目标冲突没查"的黑洞。
3. **落盘**：文件写入 / `canvas.db` 更新。**改写既有文件 MUST 用 `writeFileAtomic`**（新建文件可直接 `writeFile`）。
   *漏了会怎样*：agent 被 kill 时留下半截 markdown，下一轮 `look_at` 读到语法残骸；server 的 `fs.watch` 还会广播一个瞬时的半成品状态。
4. **落账**：调用 `store.appendEvent` 一次，且**只一次**。`detail` 自足（`00 §5.2`：带 `path` + 此刻的 `name`），不带正文。
   *漏了会怎样*：世界变了但作家/角色/历史面板都不知道——`doc-21 §1` 第三问判死。
5. **返回 `{ text, details }`**：`text` 英文、说清发生了什么、带稳定路径；`details` 带 `path` 与 `event`。
   *漏了会怎样*：模型只看到 "Done."，下一句就瞎指一个路径。

**失败语义（贯穿五步）**：任何一步失败 → 抛 `ActionError`，**绝不落事件**。唯一例外是 `recordLayerInitFailed`（§3.6）。

### 3.2 `appendEvent` 的实现契约

```ts
// packages/shared/src/store/local-store.ts（替换 appendWorldEvent，243-260 行）
async appendEvent(args: AppendEventArgs): Promise<WorldEvent> {
  const projectId = await this.projectId();          // manifest.id，进程内缓存一次
  const now = new Date().toISOString();
  this.historyDb.exec('BEGIN IMMEDIATE');
  try {
    const info = this.historyDb.prepare(`
      INSERT INTO events (id, project_id, type, actor_type, actor_id, layer, subject, turn, detail, created_at)
      VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
    `).run('', projectId, args.type, args.actor.type, args.actor.id ?? null,
           args.layer ?? null, args.subject ?? null, args.turn ?? null,
           JSON.stringify(args.detail), now);
    const seq = Number(info.lastInsertRowid);
    this.historyDb.prepare('UPDATE events SET id = ? WHERE seq = ?').run(`evt-${seq}`, seq);
    this.historyDb.exec('COMMIT');
    return { seq, id: `evt-${seq}`, projectId, type: args.type, actor: args.actor,
             layer: args.layer ?? null, subject: args.subject ?? null, turn: args.turn ?? null,
             detail: args.detail, createdAt: now };
  } catch (err) {
    this.historyDb.exec('ROLLBACK');
    throw new ActionError({ code: 'event_failed', message: `Failed to append event '${args.type}': ${msg(err)}` });
  }
}
```

四个要点：

- **`id = evt-<seq>`**：`seq` 由 AUTOINCREMENT 给，因此 `id` 天然唯一且可排序。两步写（INSERT + UPDATE）包在 `BEGIN IMMEDIATE` 里——`IMMEDIATE` 立刻抢写锁，避免两侧进程同时升级锁导致 `SQLITE_BUSY` 重试（`busy_timeout=5000` 已在 `db/schema.ts:42-43` 设）。
- **`project_id` 每进程缓存一次**：现在 `appendWorldEvent` 每次 `await this.getManifest()`（`local-store.ts:244`），而 `getManifest` 会 `readFile('world.json')` + 全目录 `scanLayers()`（`local-store.ts:189/195`）。一次 `chalk` 落账要扫两遍目录，白烧的 I/O。
- **`actor_id` 为 NULL 而非空串**：`excludeActor` 的 SQL 用 `COALESCE(actor_id,'') = ?` 比较，NULL 与 `''` 混用会让 `excludeActor:{type:'writer'}` 失效。
- **行→对象的映射集中在一个私有 `rowToEvent(row)`**（`actor_type → actor.type`、`created_at → createdAt` 等），不要在每个方法里各写一遍。

### 3.3 `getEventsSince` 的实现契约

```ts
async getEventsSince(seq: number, opts: { layer?: string; excludeActor?: Actor } = {}): Promise<WorldEvent[]> {
  const projectId = await this.projectId();
  const where = ['project_id = ?', 'seq > ?'];
  const params: any[] = [projectId, seq];
  if (opts.layer !== undefined) { where.push('layer = ?'); params.push(opts.layer); }
  if (opts.excludeActor) {
    where.push(`NOT (actor_type = ? AND COALESCE(actor_id, '') = ?)`);
    params.push(opts.excludeActor.type, opts.excludeActor.id ?? '');
  }
  const rows = this.historyDb.prepare(
    `SELECT * FROM events WHERE ${where.join(' AND ')} ORDER BY seq ASC`
  ).all(...params);
  return rows.map((r) => this.rowToEvent(r));
}
```

- **正序返回**：消费侧（doc-22 事件段）按时间顺序渲染；倒序只留给 `getEvents`。
- **`layer` 过滤是"省 token"，不是门禁**（`doc-21 §8`）：角色读到别层事件不算越权，只是没必要。
- **`excludeActor` 用 `NOT (type AND id)`**，不能写成 `OR`——否则 `{type:'writer'}` 会把全部角色事件也滤掉。
- **角色首开无游标**的规范用法（`doc-21 §5.2`，B3 照抄）：
  ```ts
  const recent = await store.getEventsSince(0, { layer, excludeActor: { type: 'character', id } });
  const window = recent.slice(-12);      // 本层最近 12 条，正序
  ```
  单机小存档（事件量级几百条），全量扫再切片是**刻意**的：不为一个罕见路径加索引之外的查询。B3 实测卡顿再加 `getRecentEventsInLayer`（登记在 §12）。
- **`getMaxSeq`**：`SELECT COALESCE(MAX(seq), 0) FROM events WHERE project_id = ?`。这是 server 尾部读表与游标推进的唯一源头（§3.8）。

### 3.4 游标读写契约

```ts
async readCursor(reader: string): Promise<number> {
  const row = this.historyDb.prepare('SELECT seq FROM read_cursors WHERE reader = ?').get(reader) as { seq?: number } | undefined;
  return Number(row?.seq ?? 0);          // 无行 → 0 = "从创世读起"
}
async writeCursor(reader: string, seq: number): Promise<void> {
  this.historyDb.prepare(`
    INSERT INTO read_cursors (reader, seq, updated_at) VALUES (?, ?, ?)
    ON CONFLICT(reader) DO UPDATE SET seq = excluded.seq, updated_at = excluded.updated_at
  `).run(reader, seq, new Date().toISOString());
}
async getAllReadCursors(): Promise<Array<{ reader: string; seq: number }>> {
  return this.historyDb.prepare('SELECT reader, seq FROM read_cursors').all() as any[];
}
```

- **`reader` 必须由 `readerOfActor(actor)` 生成**（`'writer'` / `'character:<id>'`），不是调用者随手起名——否则同一角色的两个进程会各写一个游标。
- **游标写失败不重试、不吞**：抛 `ActionError('write_failed')`。B2 注入成功后推游标（`doc-22 §3.1`），推动失败必须暴露出来，否则下次重复念一整段。
- **游标不做隐式单调钳制**：`writeCursor` 裸写，不回退保护、不 `Math.max`。回滚要把游标推到最新（`doc-21 §6`）本就满足；隐式钳制只会让"游标为什么没动"变成要读源码才能回答的问题。单调是**调用者纪律**。
- **推游标 ≠ 世界变化**：只写 `read_cursors`，**永不**为它落一条事件。

### 3.5 `Actor` 的接线契约

**扩展侧（A 入口）** —— `extensions/toolkit/actor.ts`（12 的文件）：

```ts
const { actor, warning } = resolveAgentActor(process.env[AGENT_ROLE_ENV]);
if (warning && !warnedOnce) { warnedOnce = true; console.error(`[airp] ${warning}`); }
```

**为什么读 `process.env` 而不是某个 pi API**：`00 §3` 已冻结 `AIRP_AGENT_ROLE` 是唯一注入点；pi-rp 没有"我是谁"的扩展 API。角色 agent 与作家 agent 是**两个独立进程**、各自加载同一份 `extensions/*.ts`，env 是它们唯一的身份差（`00 §3` pi-rp 事实）。`launch.ts:69/100` 现在都没设这个 env，归 12 补。

**HTTP 侧（C 入口）** —— 路由显式传，**不走 env**：

| 路由 / 触发点 | actor |
|---|---|
| `POST /api/move` `/use-item`、卡片拖动 | `{ type: 'player' }` |
| `POST /api/dice` | `player`；**仅当 body 带 `forcedResult` 时**才是 `god`（`b1-design-07` 定：`doc-21 §4.3` 靠 `actor_type=god` 区分伪造结果，若上帝模式的普通点击也记 `god`，这个区分就死了） |
| `POST /api/choose` | `{ type: 'player' }` |
| `POST /api/god-action`、上帝模式改写文件 | `{ type: 'god' }` |
| `POST /api/layer/enter`、关闭角色直聊 | `{ type: 'player' }` |
| 初始化完成 / 失败、快照 / 回滚 | `{ type: 'engine' }` |

**为什么 god 不并进 player**：`doc-21 §3.2` 定了渲染口径不同——上帝改动对作家说成"世界自己变了一下"（玩家角色当时并不在场做这件事），历史面板也要能一眼筛出。

### 3.6 失败语义

| 情形 | 结果 | 落事件？ |
|---|---|---|
| 参数非法 / 路径非法 | `ActionError('invalid_argument' / 'invalid_path')` | 否 |
| 目标不存在 | `ActionError('not_found')` | 否 |
| 目标已存在且不许覆盖 | `ActionError('already_exists')` | 否 |
| 实体没有 `choice` / `roll_dice` | `ActionError('not_interactive')` | 否 |
| 骰子已有 `result` | `ActionError('dice_already_rolled')` | 否 |
| 非 god 传了 `forcedResult` | `ActionError('dice_forced_not_allowed')` | 否 |
| 落盘失败（磁盘 / 权限） | `ActionError('write_failed')` | 否（还没到落账那步） |
| **落盘成功、`appendEvent` 抛错** | `ActionError('event_failed')` | 否——**账没落上，文件变了** |
| **层初始化失败** | `recordLayerInitFailed` 正常返回，调用者映射成 `isError:true` | **是**（`layer_init_failed`，`doc-21 §3.6` 唯一例外） |

`event_failed` 是全层最难受的一种失败：世界确实变了（文件已落盘），但事件表没有它。**明确定案：不补偿、不回滚文件、不写"补偿事件"。** 补偿把 `appendEvent` 变成有两条失败路径的东西，而写补偿事件同样可能失败，递归无底。做法是把 `event_failed` 的英文文案写清事实（`File was written but the world event could not be recorded`），让模型/玩家立刻看到不一致，人工可修。登记在 §12 待评审。

**"不静默降级成成功"的落地**：`ActionResult` **没有 `ok` 字段**——成功就是正常返回，失败就是抛异常。`service` 不 catch 任何 `ActionError`；只有工具壳（`extensions/toolkit/result.ts`）与路由在最外层各 catch 一次，映射成 `isError:true` / HTTP 状态码。

### 3.7 `turn` 锚：怎么拿到 agent 的 turn id

**A 入口（agent 工具）**
pi-rp **没有**把 turn id 交给工具执行体。证据：`ToolDefinition.execute(toolCallId, params, signal, onUpdate, ctx)`（`vendor/pi-rp/packages/coding-agent/src/core/extensions/types.ts:538-544`）的 `ctx` 是 `ExtensionContext`（同文件 `:315`），它只有 `sessionManager`、`ui`、`mode`、`cwd`、`signal`……**没有 `turnIndex`**。可得的两块拼图：

1. `ctx.sessionManager.getSessionId()` —— `ExtensionContext.sessionManager`（`types.ts:325`）是 `ReadonlySessionManager`（`core/session-manager.ts:217-233`），`getSessionId(): string` 在 `:1037`。
2. 轮次序号**只通过扩展事件暴露**：`turn_start` / `turn_end` 各带 `turnIndex: number`（`types.ts:828-840`）；发射点在 `core/agent-session.ts:1055-1074`（`turn_start` 时用 `this._turnIndex`，`turn_end` 后 `++`）。`_turnIndex` 是私有字段，没有任何 API 读它。

**定案（A 入口）**：

```ts
// extensions/context.ts（B2 建）——模块级，进程 = 会话（doc-22 §4 的先例）
let currentTurnIndex = -1;
pi.on('turn_start', (e) => { currentTurnIndex = e.turnIndex; });   // types.ts:1364
// extensions/toolkit/actor.ts
export function currentTurnAnchor(ctx: ExtensionContext): string {
  const sess = ctx.sessionManager.getSessionId();
  return currentTurnIndex < 0 ? `turn:${sess}:adhoc` : `turn:${sess}:${currentTurnIndex}`;
}
```

形状 `turn:<sessionId>:<turnIndex>`——`sessionId` 让重启/换会话后不会把两轮的 turn 撞成同一个合并组，`turnIndex` 是同一会话内的轮次序号。`adhoc` 是"turn_start 还没到就调了工具"的降级（少数情况：扩展在 `before_agent_start` 里自己调动作，那时没有轮次）。

> **`[推断]`**：`turn_start` 在工具执行之前必然已经发过（工具只能在一轮里被调用），所以 `currentTurnIndex >= 0` 在正常路径上恒成立；`adhoc` 只兜理论边界。

**降级方案（若 12 不建 `context.ts`）**：只用 `sessionId`，`turn: sess:<sessionId>`。合并规则（`doc-21 §5.4` 第 1 条：同 `turn` + 同 `type` + 同 `actor` 合并计数）会变成"整个会话合并"——玩家 20 轮里拿 5 次东西会被念成"玩家把 5 件东西收进了背包"。**这是可见的语义损失，不是等价降级**，所以 `turn_start` 监听是 A 入口的 MUST。

**C 入口（HTTP 路由）**：

```ts
// routes/world.ts —— 每个请求一个 anchor，一个请求内的多个动作共用
const turn = `req:${randomUUID()}`;
const svc = createActionService(store, { type: 'player' }, { turn });
```

`requestId` 用 `randomUUID()` 而非递增计数：两侧进程各自递增会撞号；一次请求 id 只需要唯一与稳定，不需要有序。

**E 入口（引擎）**：初始化传 `turn: init:<layer>:<timestamp>`；快照/回滚传 `turn: world:<snapshotId>`。**推断标注**：这两处由各自文档（11 / 16）定，01 只要求"非空且唯一"。

### 3.8 事件广播通道（store 侧要提供什么）

工具在 **agent 进程**写 `history.db`；WS 在 **server 进程**。两者不直接通信，**唯一通道是 server 尾部读 `events` 表**（`00 §5.3`）。01 只定 store 侧提供什么、13 定 server 侧怎么轮询：

store 侧（本层）：

- `getMaxSeq()` —— server 首次启动时对齐 `lastSeq`（不回放历史，只从当前尾部开始，否则前端会重演今天之前的全部事件）。
- `getEventsSince(lastSeq)` —— 无过滤版本的增量拉取，**正序**；server 逐条 `broadcast({ type: 'world_event', event })`。
- 不提供订阅、不提供回调——**server 不持有 store 的事件订阅**。三个方法足够，理由：`fs.watch` 加 ~1s 兜底定时器（`00 §5.3`）已经是触发源，多一条 push 通道就多一处竞态。

**store 侧必须保证的一件事**：`appendEvent` 返回**已经 COMMIT** 的事件。server 读表可能发生在提交后的任意毫秒，读不到就说明 fs.watch 的 debounce 还没到（~1s 兜底会补上）；读到的 `seq` 一定单调。若 `appendEvent` 在 COMMIT 前返回，server 可能读到 `seq=n` 却没读到 `seq=n-1`（还在另一个连接的事务里），游标就会跳过它。

**`fs.watch` 永不写事件表**（`doc-21 §2.1`）：watcher 只做前端重取的触发器。server 的 `.airpworld` 过滤要改成只滤 `.airpworld/assets/` 与 `.airpworld/sessions/`（`event-bridge.ts:138` 现在整体滤掉，detail 归 12）。

### 3.9 `layer` 与 `subject` 怎么定

| 字段 | 取值 | 谁算 |
|---|---|---|
| `layer` | 事件发生在哪一层 | `store.resolveLayer(path)`，内部 = `layerOfPath(path, await scanLayers())`（`layers.ts:126-135`） |
| `subject` | 主要目标路径（稳定 id，可空） | 各动作自己给（见 §4 表） |

规则：

- **`resolveLayer` 返回 `string | null`**：`world/**` → `layers.ts::layerOfDir(dirname(path))`（`world/README.md` 与 `world/inn/x.md` → `map` / `world/inn`）；`player/**`、`characters/<id>/**`、`world.json` → **`null`**。**不许把背包/小天地塞进 `'map'`**——那是假话，而且会让角色侧的层窗口（`doc-21 §5.2`）把玩家的口袋动静当成"本层发生的事"念给它听，与 `doc-22 §3.2`「角色不注入 bag」直接矛盾。[本文修正了此前的 draft 口径，见 §13 冲突 10]
- **`layer` 是给过滤用的，不是给渲染用的**。允许 `null`（背包内移动、快照事件、跨层 move）。凡是"发生在某一层"的动作 MUST 填；`world_snapshot` / `world_rolled_back` 填 `null`。**`getEventsSince({layer})` 永不匹配 `NULL` 行**——因此背包事件不会进任何层窗口，这正是想要的。
- **`entity_moved` 的 `layer` 是例外规则**：取 `resolveLayer(from) ?? resolveLayer(to)`——**只要有一端在层树里，就取那一端**。所以 `world/inn/key.md → player/key.md` 的 `layer = 'world/inn'`（角色在壁炉边看得见"钥匙被拿走了"，正是 `doc-21 §3.5` 那条角色读法「他把柜台上那把铜钥匙收走了」能触发的前提）；只有两端都不在层树里（背包内挪文件、角色小天地之间）才 `layer = null`。
- **`subject` 是"这个事件在讲哪个东西"**，不是"发生在哪个文件"——`move` 的 `subject` 用**新路径** `to`（合并规则第 3 条 `entity_created` 后紧跟同 `subject` 的 `entity_moved` 靠它，`doc-21 §5.4`）；`entity_created` 用 `path`；`use_item_on` 用 `target`。
- **`layer_entered` / `layer_initialized` / `layer_init_failed` 的 `layer` 就是事件主语**，`subject` 同值。
- **`resolveLayer` 加进接口的理由**：现在只有 `LocalWorldStore.deriveLayer` 是 private（`local-store.ts:456`），server 与扩展都需要它（`layer_entered` 的 C 入口、动作层填 `layer`）。不导出就得在 server 再扫一遍目录。

## 6. 引用重写的接口（`refs.ts`，实现归 04）

### 6.1 现状审查（`local-store.ts:136-179`，即任务点名要审的地方）

```ts
// 现状：move() 的引用重写，local-store.ts:146-161
const allMdFiles = (await this.listFiles()).filter((f) => f.endsWith('.md'));
const oldName = path.basename(from);         // ← 例如 'copper-key.md'
for (const file of allMdFiles) {
  const content = await this.readFile(file);
  if (content.includes(from) || content.includes(oldName)) {
    const updated = content.replaceAll(from, to);   // ← 只替换完整路径
    if (updated !== content) { await this.writeFile(file, updated); rewrote.push(file); }
    else { dangling.push({ file, target: from }); }
  }
}
```

四个已确认的缺陷，每个都能在真实世界内容上触发：

| # | 缺陷 | 触发场景 | 后果 |
|---|---|---|---|
| 1 | `replaceAll(from, to)` 是**子串**替换 | `from = 'world/inn/key.md'`，另一文件写 `world/inn/key.md.bak` 或 `.../key.md#frag` | 造出一个不存在的路径 |
| 2 | `includes(oldName)` 判据 + 只 `replaceAll(from)` | 文件里出现裸文件名 `key.md`（正文注释、`link_to: key.md`） | **进了分支却什么都没换**，被记成 `dangling`；作者以为改过了 |
| 3 | `replaceAll` 不区分**引用位置** | 正文里写"他把 key.md 忘在了柜台" | 这句话被静默改写，叙事文本被篡改 |
| 4 | `dangling` 无 `reason`，`rewrote` 无位置 | 前端/作家无法区分"提到但指不着"与"读不了" | `entity_moved` 的 `dangling` 计数没法让人话渲染说清 |

**核心问题：把"引用"当成"字符串出现"。** `replaceAll` 对路径是危险的，对裸文件名是沉默错误的。

### 6.2 接口（冻结形状）

```ts
// packages/shared/src/actions/refs.ts
export type RefKind =
  | 'frontmatter-path'   // YAML 里明确指路径的键
  | 'link_to'            // chalk frontmatter link_to
  | 'append_to'          // chalk frontmatter append_to
  | 'gate-target'        // gate frontmatter target
  | 'markdown-link'      // [text](path)
  | 'asset-ref'          // ![alt](path) / bg: path
  | 'body-mention';      // 正文里的裸提及 —— 永不自动改写

/** One located reference. `start/end` are char offsets into the file's raw text. */
export interface RefSite {
  file: string;
  kind: RefKind;
  target: string;        // 规范化后的世界根相对路径，或裸文件名（body-mention）
  start: number;
  end: number;
  raw: string;           // 原文切片，用于精确替换
}
// DanglingRef is DEFINED once in schemas/events.ts (WorldStore.move returns it, and
// store/ must not import from actions/). refs.ts re-exports it:
import type { DanglingRef } from '../schemas/events.js';
export type { DanglingRef };
export interface RewriteResult {
  rewrote: string[];
  dangling: DanglingRef[];
}

/** Pass 1: locate every site that points at `from` (or its bare basename). Read-only. */
export function scanRefs(store: WorldStore, from: string, to: string): Promise<RefSite[]>;

/** Pass 2: rewrite ONLY at the recorded offsets. Never `replaceAll`, never bare-basename `includes`. */
export function rewriteRefs(
  store: WorldStore, from: string, to: string, sites: RefSite[]
): Promise<RewriteResult>;

/** Pure resolver: is `ref` a path (absolute-in-world or relative to `currentFile`)? Unambiguous? */
export function resolveRefTarget(
  ref: string, currentFile: string, allFiles: Set<string>
): string | null;
```

### 6.3 纪律（实现时必须守住）

1. **两趟，不是一趟**：`scanRefs` 先算全部 `RefSite`（含偏移），`rewriteRefs` 再按偏移替换。**一趟扫描 + 边走边改**会让后面的偏移全部失效（这正是现状错误的根源之一）。
2. **`body-mention` 永不自动改写**。裸文件名出现在正文里就是叙事文本，改它 = 篡改叙事。它只贡献 `dangling`（`reason: 'ambiguous'`），由作家看到 `entity_moved.dangling > 0` 后自己决定要不要改。**这是对 00 §2.4 与 doc-05 §8.3 断链兜底的交待。**
3. **同一文件多处引用合并成一次写盘**：按 `file` 分组，从后往前替换（偏移倒序），一次 `writeFileAtomic`。
4. **`from`/`to` 一律先规范化**（`00 §2.1`），再做前后缀比对；比较用"路径段边界"而不是 `includes`（`.../key.md` vs `.../key.md.bak` 必须区分）。
5. **`dangling` 元素形状冻结为 `DanglingRef`**；`entity_moved.detail` 只存**计数** `rewrote` / `dangling`（`00 §5.2` 已冻结），明细留在返回值里。理由：`detail` 要自足但不要膨胀，计数已足够渲染"有 n 处提到它的地方现在指不着了"。

> **实现细节与全部边界（含目录级 `to`、跨层目标、资源引用、`gate.target`）归 `04-move与delete.md`。** 01 只冻结这五个导出名与 `DanglingRef` 的字段。

### 7.3 边界的统一处理

- **空路径 / 空字符串**：`invalid_argument`（不是 `not_found`）——空路径是调用错误，不是世界缺东西。
- **`from === to`**：`moveEntity` 直接 `invalid_argument`（`Cannot move a file onto itself`）；不做空操作成功。
- **保留前缀**：`node_modules/` 与以 `.` 开头的段 → `invalid_path`；**唯一例外是 `.airpworld/assets/**`**（资产的读写，见 §10.1）。工具**不可遍历** `.airpworld/`，但 store 的路径解析 MUST 放行这个子树（评审 B-2；`00 §2.5` 已同步改口径）。**这是 01 唯一与"权限"有关的检查，且它防的是路径语义错误，不是身份门禁**（`doc-20 §1.1` 明文：能力不按身份裁）。
- **`resolvePath` 必须收紧（安全修复，证据见 §9）**：现在的实现只剥**前导** `../`（`local-store.ts:67`），`path.join` 之后照样能逃出世界根。收紧后按顺序：

  ```ts
  // local-store.ts::resolvePath —— 校验在 join 之前，断言在 join 之后（两层）
  private resolvePath(relPath: string): string {
    if (!relPath) throw new ActionError({ code: 'invalid_argument', message: 'Path must not be empty' });
    if (path.isAbsolute(relPath)) throw new ActionError({ code: 'invalid_path', message: `Path must be world-relative, got "${relPath}"` });
    if (relPath.includes('\\'))    throw new ActionError({ code: 'invalid_path', message: `Path must use POSIX separators, got "${relPath}"` });
    const segs = relPath.split('/').filter((s) => s !== '' && s !== '.');
    if (segs.includes('..'))       throw new ActionError({ code: 'invalid_path', message: `Path must not contain "..", got "${relPath}"` });
    const inAssetTree = segs[0] === '.airpworld' && segs[1] === 'assets';
    if (!inAssetTree && (segs.some((s) => s.startsWith('.')) || segs.includes('node_modules')))
      throw new ActionError({ code: 'invalid_path', message: `Path is inside a reserved directory: "${relPath}"` });
    const abs = path.join(this.worldRoot, segs.join('/'));
    // Belt: even after normalization, never leave the world root.
    if (abs !== this.worldRoot && !abs.startsWith(this.worldRoot + path.sep))
      throw new ActionError({ code: 'invalid_path', message: `Path escapes the world root: "${relPath}"` });
    return abs;
  }
  ```

  **为什么必须修而不是在每个动作里防**：`look_at` 收的是**模型给的路径**（`doc-20 §3`），`move` / `choose` / `roll_dice` 同样。当前实现把 `../` **静默剥掉**——`resolvePath('../etc/passwd')` 变成 `<root>/etc/passwd`，是静默降级；而 `resolvePath('a/../../etc/passwd')` 在 `path.join` 归一化后**真的逃出世界根**。**这是 B1 范围内唯一的安全修复**，登记为 §9 首行。
- **同一进程内并发同文件**：动作层不加锁。WAL + 原子写已经保证不出现半截文件；两个动作同时改同一文件时后写的赢——这与"文件即真相"一致，登记在 §14。

```ts
      actor_type TEXT NOT NULL,
      actor_id   TEXT,
      layer      TEXT,
      subject    TEXT,
      turn       TEXT,
      detail     TEXT NOT NULL,
      created_at TEXT NOT NULL
    );
    CREATE INDEX idx_events_seq   ON events(project_id, seq);
    CREATE INDEX idx_events_layer ON events(project_id, layer, seq);
  `);
}
db.exec(`
  CREATE TABLE IF NOT EXISTS read_cursors (
    reader     TEXT PRIMARY KEY,
    seq        INTEGER NOT NULL,
    updated_at TEXT NOT NULL
  );
`);
```

**为什么是形状探测而不是无条件 `DROP`（B-4 修复）**：`initHistoryDatabase` 在 `LocalWorldStore` 的构造函数里被调用——**每次 server 重启、每次 `/api/worlds/load` 切世界都会跑一遍**（`local-store.ts:63`）。无条件 `DROP TABLE IF EXISTS events` 会在每次启动清空历史：世界历史、历史面板、尾部读表游标所服务的一切都会丢。改成"查 `PRAGMA table_info(events)`，缺 `seq`/`actor_type` 才 `DROP` + 重建"后：旧五列库一次性换成十列，新形状库直接跳过。这仍不是版本迁移脚本——只是一次列存在性检查，符合 `00 §5.1` 的"B1 不做迁移"；`read_cursors` 用 `CREATE TABLE IF NOT EXISTS`，可每次执行。

**`DROP` 仍然会丢现有开发库的历史事件**——**可接受**，因为：① 世界目录还没有真实存档（`00 §5.1` 明文）；② 旧事件全是 `payload` 形状的散字符串，本来就要重编号；③ 这次重建只在**旧形状库上发生一次**，之后启动都跳过。**评审若要求保留开发库，改法是 `ALTER TABLE events RENAME TO events_legacy_b0`（保留可查）而不是逐行迁移。**

**`entries` 表不动**：会话逐字记录（`doc-05 §8.6`）与事件表是两张表，B1 不碰（`doc-21 §1.1`）。

- `resolvePath('../etc/passwd')` → 被静默剥成 `<root>/etc/passwd`（**静默降级**，`00 §8` 明禁）；
- `resolvePath('/etc/passwd')` → `path.join(root, '/etc/passwd')` = `<root>/etc/passwd`（这一条被 `path.join` 关住了，但调用方传绝对路径本身仍是错误信号）；Windows 上 `C:\x` 会逃逸。

**动作层仍然各自校验一次**（`b1-design-03` 的做法正确）：store 的校验是最后一道，动作层的校验给出更精确的错误文案与更早的失败点（§3.1 第 1 步）。

## 10. 文件与副作用

### 10.1 动作层允许触碰的东西（白名单，超出即 bug）

| 目标 | 谁写 | 原子性 |

### 10.2 `moveEntity` 的副作用顺序（最复杂的一个，其余类比）

1. 读 `from` 内容与前 frontmatter（取 `name`）→ 2. 校验目标不存在 / `near` 同层 → 3. `fs.rename` → 4. `rewriteRefs`（可能写多个文件）→ 5. `renameCardPosition`（`canvas.db`）→ 6. `seatUnplaced`/`saveCardPosition`（按 `near` 或空位）→ 7. `appendEvent('entity_moved')`。

**3 与 7 之间任何一步失败都会让"文件已动、账没落"**：这不是可回滚的（回滚 rename 会覆盖玩家在那一瞬的另一次移动）。处理方式与 `event_failed` 一致：**报错说清事实，不回滚**。`renameCardPosition` 迁移失败（`routes/world.ts:298-302` 现在只 warn）**改为抛 `ActionError('internal')`**——静默跳过会让同一卡片出现两个座位（正是那句话注释在防的 bug）。

### 10.3 写盘原子性的实现（`writeFileAtomic`）

```ts
async writeFileAtomic(relPath: string, content: string | Buffer): Promise<void> {
  const abs = this.resolvePath(relPath);          // 收紧后的版本：非法路径抛 ActionError
  await fs.mkdir(path.dirname(abs), { recursive: true });
  const tmp = `${abs}.tmp-${process.pid}-${randomUUID().slice(0, 8)}`;
  try {
    await fs.writeFile(tmp, content);
    await fs.rename(tmp, abs);                    // 同目录 rename = 原子
  } catch (err) {
    await fs.rm(tmp, { force: true });            // 清理临时文件，原文件未被触碰
    throw new ActionError({ code: 'write_failed', message: `Failed to write "${relPath}": ${msg(err)}` });
  }
}
```

**临时文件名带 `pid` + 随机段**：两侧进程可能同时改同一文件，固定 `.tmp` 名会互相踩。

## 11. WS 与前端

### 11.1 两条通道，别混

```
① 演出帧（瞬时）  扩展 execute 的返回值 details
                  → pi-rp tool_execution_end.result
                  → server onEvent → event-bridge.mapEngineEvent → WS 帧
② 世界事件（历史）扩展 appendEvent 写 history.db
                  → server 尾部读表 → WS { type: 'world_event', event }
```

**这一层（`actions/`）只负责让两条都拿到正确的原料**：`details` 里有稳定字段，`event` 里字段自足。**它不选通道、不发 WS。**

### 11.2 `details` 里 server 会消费的字段（稳定契约）

`00 §6.2` 要求 `details` 建议含 `{ path?, event? }`。01 补齐为：

| 字段 | 类型 | 谁用 |
|---|---|---|
| `path` | `string` | event-bridge 的 `chalk_landed`（`event-bridge.ts:81-87` 从 `event.result.path` 取）；前端定位卡片 |
| `event` | `WorldEvent` | 兜底：若尾部读表延迟，前端也能立刻拿到这条事件（**不替代** `world_event` 帧——两处都到会重复，前端按 `event.id` 去重） |
| `frame` | `Record<string, any>` | **只用于 `showComponent`**：`{ name, layer?, path?, props? }`，12 的桥映射成演出帧 |
| 动作专属字段 | — | `moveEntity`：`from/to/rewrote/dangling`；`rollDice`：`result/passed/dice/expect`；`chooseOption`：`choice/index`；`writeChalk`：`created/appended` |

**`event.id` 去重是必须的**：`details.event` 与尾部读表是同一行的两副本，前端不按 `id` 去重会把每条动作事件演两遍。

### 11.3 帧名与事件 type 的命名空间（`00 §5.3`）

- 演出帧：`writer_delta` / `character_delta` / `writer_message` / `character_message` / `tool_start` / `tool_end` / `chalk_writing` / `chalk_landed` / `canvas_patched` / `card_position` / `file_changed` / `writer_idle` / `character_idle`。
- `roll_resolved` 帧 → **改名 `dice_result`**（`00 §5.3` 冻结；只走 WS、不带 event 行）。
- 世界事件统一 `{ type: 'world_event', event }`。

**`use_item_on` 与 `entity_moved` 也重叠**：`routes/world.ts:411` 广播 `{type:'use_item_on', event}`、`:303` 广播 `{type:'item_moved', result}`——这是与 `roll_resolved` 同类的旧重叠，`doc-21 §7` 只点了 `roll_resolved` 一个。**建议一并处理**（见 §13 冲突 6）。

### 11.4 前端拿到后演什么

| 事件 type | 前端反应 |
|---|---|
| `entity_created` | 卡片落地动画（`chalk_landed` 帧已在演，事件只推历史面板） |

### 11.5 server 侧要建的三件事（归 12）

2. `fs.watch` 触发 + ~1s 兜底定时器 → `getEventsSince(lastSeq)` → 逐条 `world_event`。
3. `.airpworld` 过滤改成只滤 `assets/` 与 `sessions/`（`event-bridge.ts:138`）。

## 14. 仍然未知 / 留给评审拍板的

1. **`event_failed` 的处理是否够**（§3.6）：定案是"不回滚、不补偿、报错说清"。若评审要求可恢复，则须给 `appendEvent` 加一条"重试队列"——但那会把事件表从"唯一日志"变成"至少要送达的队列"，语义变重。**请拍板。**（评审裁决：**DEFER**——留实现期，见 `REVIEW-评审报告.md` D-1。）
2. **`resolveLayer` 对 `player/**` / `characters/**` 返回 `null`** —— **已定案（2026-09-12）**：返回 `null`（`b1-design-07` 指出旧 draft 的 `'map'` 是假话）。但由此推出一个必须同时定清的例外，见 §3.9 的 `entity_moved` 规则：**物件在两个"非层"位置之间移动才 `layer = null`；只要有一端在层树里，就取那一端**。理由：`doc-21 §3.5` 的渲染表里，角色的读法就是「他把柜台上那把铜钥匙收走了」——说明 `world/inn → player` 这次移动**必须**进角色在 `world/inn` 的窗口，否则那条渲染例子根本触发不了。**待 05/12 确认这条读法。**
3. **`turn` 锚的粒度**：一轮作家写 3 篇 chalk → 同 `turn` → 注入时合并成"作家落了 3 篇板书"（合 `doc-21 §5.4`）。但玩家一次拖 4 件 → 同 `req:` turn → "玩家把 4 件东西收进了背包"。**这是期望行为还是太粗？** 若希望"一次工具调用 = 一个 turn"，A 入口改用 `turn:${session}:${turnIndex}:${toolCallId}`——代价是同一轮的板书不再合并。（评审裁决：**DEFER**——属可调参数，实测后定，见 D-2。）
4. **`snapshotWorld` / `rollbackWorld` 的实现**：签名已冻结，赛后才实现（`doc-16` 状态：待设计）。本层给的是"回滚时 `getAllReadCursors()` 全推到 `getMaxSeq()`"的 store 支撑，**回滚 body 本身不在 B1**。
5. **`getRecentEventsInLayer(layer, limit)` 是否需要**（§3.3）：现在用 `getEventsSince(0,{layer}).slice(-12)`。事件上万条时需要，现在不需要。**建议暂不加，实测再说。**
