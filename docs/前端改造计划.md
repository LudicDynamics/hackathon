## 5. P2 多模态（doc-19 的 P0，9h）

> 两份画布原型里**无处可抄**，必须自研。照着原型打磨到"好看"，交出去的还是一个静态画布。

### T2.0 演出时钟（1h · `lib/motion.ts`）——**所有演出的前置**

现在 P2、P3、P5 的动效如果各写各的，跳过与调速会各做一遍。先落一个时钟，照 `app/src/motion.js`：

- `wait(ms)` / `animate(el, frames, ms)` / `stream(el, text, ms)` 三个原语，全部可取消；
- `skip` 立即完成当前动画与逐字文本，**但不撤销已提交的命令、不重掷骰子**；
- `speed` 0.7 / 1 / 1.7×；`prefers-reduced-motion` 作默认值，用户可显式再关；
- `visibilitychange` 时停钟并 `pause()` WAAPI 动画；
- 提示音用 Web Audio 合成（不占音频资产额度）。

配套把 `MOTION.md` 那张时长表抄进本节作为演出基准：跨层 270+480ms、掷骰 ~1.2s、发卡 540+300ms、角色唤起 300ms + 文本长度。

### T2.1 全景声场（2.5h · `lib/audio.ts` + `state/useAudio.ts`）

Howler 三层（doc-19 §2.1）：

| 层 | 内容 | 触发 |
|---|---|---|
| L1 Ambient | `rain` / `fireplace` / `cellar-drip` | 切层时按该层 README 的 `ambient` 字段交叉淡入淡出 **1.5s** |
| L2 BGM | `calm` / `tense` / `crisis` | 按当前层 README 的 `bgm` 字段平滑切换增益（`[emo:]` 只走瞬时 stinger，绝不改主轨） |
| L3 Foley | 9 个短音效（见 §12；`gate-open` / `page-turn` 有素材但本批无调用点） | 拖拽 / 卡片落定 / 掷骰 / 检定成功 / 大失败 / 落墨 / 选项点选 / 用物（拖到目标）/ 门卡过场 |

要点：全局单例；首次用户交互后才 `unlock()`；顶栏留一枚静音开关（演示现场必须能一键静音）。

### T2.2 2.5D 视差与粒子（2h · `SceneBackdrop.tsx` + `ParticleLayer.tsx`）

现状只有 `perspective:1200px` 和鼠标 ±3deg 倾斜。补：

- **三层速率分离**：前景浮层 1.35x 反向位移、中景（物件层）1.0x、远景背景 0.25x；
- **远景**：读 `/api/layer` 的 `bg`，`.webm/.mp4` 走 `<video autoplay loop muted playsinline>`，图片走 `<img>`，缺省走材质底纹；
- **前景粒子**：约 40 行的 Canvas 粒子层（室内浮尘 / 室外雨丝雪花），按 README 的 `bgStyle.tone` 选类型，性能预算 < 2% CPU；
- **vignette**：边缘物理暗角。

### T2.3 掷骰仪式（2h · `narrative/DiceCeremony.tsx`）

现在是 60px 骰子嵌在 chalk 卡里。升级为全屏仪式（doc-19 §3.3）：

```
点击骰子卡 → 全屏压暗 40% + 悬念滚奏
           → 按住蓄力（蓄力条 + 音高升高）→ 释放
           → 大号 2.5D 骰子翻滚 1.2s + 实木撞击拟音
           → 服务端真随机 + expect 判定
           → 大成功：金光爆裂 + 华丽和弦 / 大失败：猩红裂痕 + 断弦 + 全屏震颤
           → 回写 frontmatter.result + 落事件表 → 卡片落定
```

#### 布局（参考 `画布世界v1-yoshi.html` L584–640）

```
┌───────────────────────────────────────────────┐
│  （画布压暗虚化，仍隐约可见炉火与便签）          │
│                                               │
│   ┌────────┐                   ┌────────┐    │
│   │ 立绘 A │                   │ 立绘 B │    │   ← 贴底、分列左右
│   │  .lit  │                   │  压暗  │    │      说话方亮起并上浮
│   └────────┘                   └────────┘    │      非说话方 saturate(.35)
│                                               │        brightness(.6) + translateY(12px)
│        ╭─[ 名牌 · 红笔圈 ]────────────╮       │
│        │ （斜体小字：必要的描述行）      │       │   ← 旁白在框上沿，不占正文
│        │  逐字流式的台词……          ▾ │       │   ← 固定 min-height，流式时不跳动
│        │ ┌─────────────────────────┐ │       │
│        │ │ 对他说点什么…            │ │       │   ← 玩家输入是框内底部一行
│        │ └─────────────────────────┘ │       │
│        ╰─────────────────────────────╯       │
└───────────────────────────────────────────────┘
```

要点逐条：

| 元素 | 规格 |
|---|---|
| **遮罩底** | **暖黑** `rgba(41,40,32,.55)` + 画布 `blur`，不是中性黑、不是独立背景图 |
| **立绘舞台** | `flex; align-items:flex-end; justify-content:space-between; padding:0 6vw` —— 贴底分列左右；尺寸 `min(40vh, 26vw, 360px) × min(64vh, 560px)` |
| **左右差分** | **核心不是"两张图并排"，是谁说话谁亮**：非说话方 `filter:saturate(.35) brightness(.6)` + `translateY(12px)`，说话方 `.lit` 归零，`transition .35s` |
| **立绘槽分配** | 按角色在这场戏里出现的顺序分左右，先到先得 |
| **对话框** | 底部一张**微微歪着的纸**（`rotate(-.4deg)`，`width: min(720px,78vw)`，`bottom:5.5vh`），纸材质与信 / 便签同族（token 复用）；**从底部升入**，不是屏幕正中淡入 |
| **名牌** | 浮在框左上角外沿，v1 用红笔圈标"谁在说话"——**我们改用 v2 语汇**（墨底纸字或 rust 描边），别把红笔带回来（§10.2） |
| **台词区** | `line-height:2`，**固定 `min-height` 约 3.2em**——逐字流式时框体不跳动 |
| **旁白** | 框上沿斜体小字的描述行，不混进台词（doc-06 §3.2：导演不介入演员的戏） |
| **玩家输入** | **框内底部一行**（纸条通道内嵌），不是右半边独立的输入区 |
| **选项** | 任意实体可带 choice；角色可在直聊中选择，是快捷方式不是唯一通道 |
| **不做** | 聊天气泡、消息历史滚动区、头像 + 昵称的 IM 行式布局、属性栏 / 亲密度 HUD |

> 历史记录去哪了？**不做 transcript**。对话的后果由画布揭示（下方第 4 条连续性），需要回看时走 T4.1 的 DetailPanel——对话落盘成组件后按"类型章 + 全文 + 回跳 + 续写"读，而不是在遮罩里堆聊天记录。

#### 四条连续性（doc-06 §3.4）

1. **视觉连续**：画布不卸载，套 `filter: brightness(.35) blur(6px)`——你仍隐约看得见炉火与便签，知道自己还在临江旅店；
2. **运动连续**：进入 = `flyTo` 锚点推进到角色头像 → 压暗虚化 → 对话框从底部升入；退出对称逆播 + 相机弹回（`useCamera` 的层级记忆已就绪）；
3. **空间连续**：立绘出现在**该角色头像所在的那一侧**，不是固定左边；
4. **结构连续**：对话期间世界不停，退出后画布上应能看到新落地的东西（**money shot：这场对话改变了画布**）。

### T4.3 门后过场的三段式

- **① 锚点推进**（420ms）：`cam = gc − p(t)/z(t)`，门中心全程被相机咬住，不中途漂移；

- **③ 新画布从同一缩放起步展开**（零断崖），终点是该层的记忆相机（第一次进入则 fit）；

### T4.8 排座 v2

服务端 `seatUnplaced` 现在是纯螺旋。升级三点：

1. **实测碰撞体积**：离屏 `visibility:hidden` 量 `offsetWidth/Height`，文字自然换行真实生效（纯估算会把长 chalk 排叠）——这一步在前端做，结果随 `/api/card/position` 落库；
2. **四级落座**：①庭院∩视口（最好）→ ②视口内 → ③庭院内 → ④锚点旁兜底。核心原则是**「作家必须在玩家看得见的地方写」**；

### T4.9 拾笔

作家演出结束后收笔，笔搁在纸上成为**可拾取的化身**。两种通道语义不同：

| 通道 | 指代 | 回应落在哪 |
|---|---|---|
| 输入条递纸条 | 无指代，说给世界听 | 画布上（推进剧情） |
| 拾笔指物 | 有指代，说给这份文件听 | **长在指代物旁**，不落画布中央 |

后者才是"私聊"的正确形态，也是提组件级需求（"把这封信改成更早的日期"）的入口。

### T4.10 chalk anchor

chalk 文件的 frontmatter 支持 `anchor: <path>`，把这段字**贴在某个实体身侧**而不是自由落座；hover 时画一条虚线连到锚点并高亮它。语义是"对任何东西进行 chalk；板书自己也是实体，可圈选、可改写、可再被 chalk"。需要在 `doc-09` 的 frontmatter schema 里补这个字段。

## 9. 可选：卡牌玩法最小版（4h，**待拍板**）

`app/docs/GAMEPLAY.md` 参考《苏丹的游戏》的桌面语法，正面回应 Supercell 那条 "traditional game feature"：

```
总值 = D6 + 角色属性 + 辅助加值 + 银币投入 + 2 × 专注投入
```

地图上的事件 → 展开为局部小玩法 → 选行动角色卡 + 放辅助卡 + 投入有限资源 → **掷骰前显示公式与成功率** → 结果变成世界里的新线索卡。定位那句说得准：**「卡牌是一种可操作的实体呈现，而不是另一套不相干的数据。」**

- **做的理由**：把"掷骰"从一个按钮变成一次有决策的操作，而掷骰本来就在 P2 清单里，增量主要是投入面板与资源账；
- **不做的理由**：这是全表最大的一块新工作量，且要新增资源状态（银币 / 专注）与事件先决条件，会牵动 frontmatter schema；
- **最小版建议**：一个事件 × 三张卡 × 一次资源投入，只在 baker-street 的「解读信件」上做一例，验证手感再决定是否铺开。

### 10.2 ⚠️ 三套皮肤在打架——只抄机制，不抄皮肤

### 10.4 作家的剧情与手艺走 skills（已落地）

**不引入任何"只给作家看"的隐藏字段。** 作家知道而玩家不必关心的东西——剧情、生图、组件叙事、揭示节奏、玩法咬合——一律做成 skill：

| 层 | 位置 | 放什么 |
|---|---|---|
| 项目级 | `<repo>/skills/` | 通用教程，所有世界共享 |
| 世界级 | `<world>/skills/`（与 `world/` 同级） | 该世界自己的文风与剧情，随世界包分发 |

两层在启动作家进程时一起用 `--skill <dir>` 传入（`presets.ts::skillArgs`，目录不存在就不传）；preset 里加的是 **`skills` slot**（`{"kind":"slot","id":"skills","slot":"skills"}`），不是顶层 `skills` 字段——后者是 glob allow/deny 的资源策略，用它就得维护白名单。已给 `writer` / `scene-init` / `nook-init` 加上，`character` 不加。

这比隐藏字段好在：零引擎改动（pi-rp 已实现 Agent Skills 标准）、渐进披露（system prompt 只常驻一行 description，正文按需 read）、可复用可组合。
