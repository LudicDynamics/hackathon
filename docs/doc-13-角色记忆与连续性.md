# doc-13 角色会话连续性（暂缓）

> 状态：**暂缓（2026-09-12）**。不建设 AIRP 角色记忆系统；只保留 pi-rp 会话本身的连续性，以及角色 spawn 时由 hook 报的"本层有哪些文件 + 最近变了什么"。
>
> ⚠️ **别把本文件的"暂缓"和 state 搞混**：角色**记忆系统**是"暂缓"（可基于试玩失败重新立项）；而 **state / 状态文件 / `get_state` 系列是"绝对不做"**——架构不相容，不是排期（doc-20 §2.3）。
> 关联：doc-05 §4.1（懒灵魂与小天地）、doc-06 §3（遮罩）、doc-20 §1.2（角色行动生命周期）。

## 当前边界

- 角色是**懒灵魂**：玩家打开直聊才 spawn，关闭后回收；
- 角色读取 preset 身份/性格文件；世界内容**要看什么就直接读**（`look_at` / `read`），hook 只给文件清单与最近动态，不注入 state、knowledge 或"场景简报"；
- pi-rp 的 chat history/session 可以保存已经发生的对话，但 AIRP 不在其上再建设摘要、游标、长期记忆目录或自动写回；
- 小天地是普通世界内容。角色要留下信、作品或痕迹时直接使用 `write / edit / chalk`，不把它包装成“记忆写回”。

## 暂不实现

- `characters/<id>/memory/` 目录协议；
- `remember`、`leave_trace` 等专用工具；
- 对话摘要、自动事实抽取、角色记忆游标；
- 角色间通信和角色后台自主行动。

> 以上是"暂缓"（可基于失败案例重新立项）。**下面这些是"绝对不做"，不在本文件的暂缓范围**：
>
> - **任何状态文件 / 状态命名空间 / 状态读写工具（`get_state` / `set_state` / `state_update` / `watch_state`）**——`status` 只是某一篇 chalk/实体的快照，读它 = 读那个文件（doc-20 §2.3、doc-05 §8.5）；
> - **独立状态栏 UI**。


## 将来重启本专题的条件

只有当实际试玩证明“会话历史 + 主动读世界”仍不足以维持角色连续性时，再基于具体失败案例立项。届时先定义用户体验缺口，再决定是否需要记忆数据结构；本文件当前不提供预设答案。**注意不要把它和"summary 压缩层"混为一谈**——那一层已于 2026-09-12 撤销：它要压的就是事件段（doc-21）+ 状态块（doc-22），而这两者天生有界、不随轮次增长，没有压缩的对象（理由见后端实现计划 §6.6）。真要压的是画布上的叙事正文（doc-08 `fold_chalk`，且明文是**无损重组**）和会话 transcript（pi-rp 自己的 compaction）。
