# 夜辉 D10 投骰与结果

2026-09-13：前端使用 `assets/models/arcane-d10/noctiluca-d10.glb`（用户口述 arcne-d10）。Three.js / GLTFLoader 按需加载模型，Vite 打包发布同一资产；不复制模型或改变引擎随机规则。

## 演出与读数

玩家弹窗整体为绒面骰盒：标题、投骰区、结果与 Done 共用一张纹理底面和缝线边框；D10Stage 的 integrated 模式隐藏内层盘沿，仅保留骰子与接触阴影，避免盒中套盒。

投骰场景采用紫黑渐变背景、深紫桌面与冷紫环境光，暖色主光保留金属数字的辨识度。

投掷手感：骰子从盘外 x=±6.2、z≈3.5 抛入，横向速度 9–11，主翻滚轴角速度 14–22 rad/s；线性/角阻尼为 0.08/0.10。绒面接触摩擦 0.5、回弹 0.25，有限高度盘沿允许越沿入场；飞出盘外的轨迹会重新模拟。透明演出层替代实色卡片盒，绒面与缝线盘沿在 Three.js 场景中绘制。绒面使用用户指定的 `exec-05bb3e62-c438-4335-b018-763af2bb6e48.png`，原图复制到 `apps/web/src/assets/textures/dice-tray-suede.png` 随 Vite 打包；盘底与盘沿共用颜色与凹凸贴图，紫色材质调色，原图不改。

玩家点击 Roll the Dice 后立即请求 `POST /api/dice`，只传 `{path}`。收到裁决后用 Cannon ES 模拟凸多面体与桌面、边界和另一颗骰子的碰撞，睡眠停稳后按 60 Hz 轨迹播放翻转、弹跳和落定，结果对应的数字面朝上；D10Stage 与 Agent 的 DiceCeremony 共用。玩家结果由 Done 关闭，Agent 演出落定后停留 4 秒。落定时刻以 D10Stage 的 `onLanded` 为准：加载模型与模拟期间仪式保持翻滚态，不按固定计时提前结算或收场；落定后不重建场景。加载与模拟超过 10 秒改用数字显示。服务端投骰时立即落库（权威结果先于演出，引擎不变）；前端从发出投骰请求起到该卡片的仪式结束前，卡上的读数、结果记录与骰子卡结果都保持隐藏（`dice-ceremony.ts` 的 reveal hold；请求结束 2 秒内未收到仪式则解除）。使用系统减少动态效果设置时跳过旋转。WebGL 不可用或模型加载超时以数字显示已提交结果；动画不产生随机点数，不写世界。

- `1d10`：一颗模型，实际骰面 0–9，0 读作 10。
- `1d100`：两颗同款 D10，左侧 ×10，右侧 ×1；模型仍刻 0–9，用标注区分位权。例如 6、2 → 60 + 2 → 62；0、0 → 100；1、0 → 10。
- 附加修正值不改变物理骰面；最后大号总分使用后端 result。共享 `parseDiceType` 只用于选择展示方式，不在前端另建随机或判定规则。
- 其他骰型暂用数值演出，保留逐骰 rolls 和最终 result，不伪装为 D10。
- 帧循环只在投骰时运行，落定停止；画布限定 480×260 CSS 像素，DPR 上限 1.5，卸载释放 GPU 资源。Done 弹窗隔离 pointerdown/up、wheel 与键盘事件，防止 React portal 冒泡到 Canvas 的拖拽捕获；Escape 可关闭。

落定方向由建模脚本的面序与编号推导，执行 Blender Z-up → glTF Y-up 转换。`d10-pose.ts` 将该面的法线对准镜头、数字上方向对准画面上方。Cannon ES 使用同一建模几何的凸包，以 120 Hz 步长模拟到睡眠。读出朝上面后，用骰体的严格旋转对称变换修正整段轨迹的初始朝向，保留完整碰撞过程，使最后朝上的实际模型数字匹配后端结果。100 对面映射均检查凸包顶点不变。斜靠或无法停稳时最多重试三次模拟，失败显示真实数字，不重掷后端。

## 唯一结果与 Chalk

`packages/shared/src/actions/roll-dice.ts` 的 rollDice 产生 `{dice,rolls,result,passed,crit,fumble}`。玩家 HTTP 返回 details；Agent 工具经 event-bridge 发 dice_result。两者都先把 result / passed 写回原实体的 `roll_dice` frontmatter，再落一条 `roll_resolved` 事件。

如果检定由 Chalk 发起，ChalkCard 在正文下直接显示 `1d100 → 62 · ✓/✗`，不必 hover，刷新仍能从原文件读取。检定在物品上时仍写回那个物品；不会额外伪造 Chalk。作家下一轮从事件段与原文件读到裁决，可用 chalk 工具叙述后果；默认不会因为动画结束自动调用作家。
