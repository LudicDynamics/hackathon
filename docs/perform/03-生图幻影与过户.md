## 1. 一句话与定位

**服务端早已广播两条生图帧（`event-bridge.ts:92-108` / `:177-188`），前端零消费——`useWorld` 的 `switch` 里没有任何 `case` 接它们，所以 `pnpm check:ws` 报两条 DARK（`event-bridge.ts:97`、`:178`）。本文把这两条帧接成一条完整的演出动线：进度帧落一张「幻影卡」（shimmer 骨架 + stage 文案 + 心跳），落地帧在同一座位上换真图 / 或在失败帧上淡出撤离。**

生图是**唯一**长时（3–15s，`[推断]`）且**写盘不触发 `file_changed`** 的工具——见 §3 事实 1。所以这两条帧不是"锦上添花的动画"，是**玩家唯一能知道"图好了"的通道**（契约 §6b-3）。少了它们，生图在画布上表现为"什么都没发生"。

**本批只做前端**：服务端发射面（`mapEngineEvent` 的 `tool_execution_update` 分支与 `generate_image` 落地分支）已落地并有测试（`apps/server/test/map-engine-event.test.mjs:137-171`）。§8 的代码落点全部在 `apps/web/src/**`。

## 3. 行为契约（逐步，每步写"漏了会怎样"）

**事实基线（先钉死，否则设计会走错）**：

1. **生图写盘不产生 `file_changed`**：watcher 显式忽略 `.airpworld/assets/`（`event-bridge.ts:373-377`，注释逐字 "assets (the `image_landed` frame already announced them)"）。→ **`image_landed` 是前端唯一的"图好了"通道**（契约 §6b-3）。*漏了会怎样*：玩家永远不知道图回来了；底图换掉只能等下一次全量重取。
2. **`generate_image` 不落事件、不建卡**（`doc-11 §5.1:353-368`）：它只往 `.airpworld/assets/gen/` 写一个二进制文件。**画布上真正的变化由之后的 `editEntity(README, {bg})` 带来**（`doc-11 §4.4:332-341`），那一步才产生 `entity_edited` + `file_changed`。→ `image_landed` ≠ "底图已换"，它是**投影**（§5、§11 冲突 4）。
3. **幻影必须是浮层，不能从 `items` 找**（契约 §6b-1、§5）：`image_generation_progress` 到达时目标实体（若有）尚未落盘，`items` 里没有它。→ 幻影只挂在 `phantom.ts` 注册表上（契约 §8），`PhantomLayer` 独立渲染。

### 3.3 "数据先落，DOM 才是投影"（契约 §5 / `doc-06 §2.2`）

生图这条链路特殊：**图不会变成一张卡**（事实 2）。所以"真实重取接管"的对象不是卡，而是**层的底图 `bg.src`**：

```text
image_landed(asset) ──► 幻影 phase='landed'（真图在幻影座位上）
        │
        └─ 作家随后 editEntity(README, { bg: asset })
                 └─► entity_edited（落账）+ file_changed（README 写盘）
                          └─► useWorld fetchLayer → worldState.bg.src === asset
                                   └─► PhantomLayer 观察到 → evict(toolCallId)   ← 投影退场
```

- `PhantomLayer` 用 `bgSrc` prop（来自 `Canvas` 的 `worldState.bg.src`；`Canvas` 渲染 `SceneBackdrop` 时用的同一个 `bg`，**锚句：`Canvas.tsx` 的 `<SceneBackdrop … bg={bg} />`**）比对 `entry.asset`，命中即 `evict`。**不改 `fetchLayer`**（它是 01/02 共用的热路径）。
- **兜底**：`LANDED_DWELL_MS`（建议 `15_000`，`[推断]`）后无条件退场——作家可能压根不写 `bg:`（`doc-11 §12 待评审 6` 承认"生成+挂载"不是一次动作）。没有这条，幻影会永久占座。
- **座位不变**：从 `pending` 到 `landed` 再到 `evicted`，`seat` 全程不变（`land` 不传 `seat`）。

### 3.4 `reused:true` 的表现差异

`reused` 表示**同名文件已在盘上**（`generate-image.ts:358-359`）。但要**先看清一件与文档不符的事实**（§11 冲突 2）：`reused` 只省下**写盘**，**不省 provider 调用**——`provider.generate(...)` 排在 `outputPathFor(...)`/`statKind(...)` **之前**（`:339` vs `:349-359`）。所以：

- **进度帧照常流**（provider 真的被调了），幻影照常出现、心跳照常打；
- 落地时**不播"新图诞生"的强调**；只贴一枚安静封条「Already had this image」（不抢戏）；
- 停留时间缩短（建议 `5_000`）——没有新东西可揭晓，让它快点退场；
- **不隐藏信息**：这与 `doc-11 §3.3:167` 的意图（"不是静默降级"）一致；`reused` 是真相，UI 必须说出来。

**验收影响**：复现 `reused` 需要真实 key（因为 provider 仍被调）；见 §10.3 的 4 号用例标"需 key"。

### 3.5 失败撤离（与 `01` 共用入口）

`tool_end` 到达时，若 `isError === true`，对**该 `toolCallId`** 调现有单参 `evict` ——一个分支同时覆盖 `chalk`（`01`）与 `image`（`03`），无需按工具名分叉，因为 `evict` 对不存在的 id 是 no-op；失败原因由淡出组件根据 source/tool 状态显示，不扩展 registry API。

```ts
case 'tool_end': {
  // writer busy is updated by UX03 acceptWriterFrame; this branch only evicts failed phantom.
  if (msg.isError === true && typeof msg.toolCallId === 'string') {
    evict(msg.toolCallId);
  }
  break;
}
```

- **为什么成功路径也能撤销**：`tool_end` 对**每个**工具都发（`:116-122`，无 `isError` 前置）。成功时该 id 的幻影已由 `land` 进入 `landed`，`evict` 只会把它按退场纪律收走，不产生"半成品"。
- **无模型的天然验收**：`generate_image` 在**任何失败前**就发了 `resolving` 进度帧（工具壳 `:79-82` 在动作调用之前），所以"幻影出现 → 失败 → 淡出"这条路径**无需 API key 就能在浏览器里跑通**（§10.3 用例 1）。
- **漏了会怎样**：没配模型时画布上永远留一张闪着的骨架卡（"半成品不留画"，`doc-10 E3:45`、`doc-11 §6.3:452`）。

### 8.5 `phantomSeatFor` —— 排座 helper（**NEW，属主 `03`，可导出**）

```ts
/** Local seat for a new ghost: shared flowColumns over current items
```

**属主与导出（裁决 D / R1-03）**：`phantomSeatFor` **归本文（`03`）**，MUST 是**可导出符号**，供 `01` 的 chalk 幻影直接调用；`01` MUST NOT 自造 `nextInkSeat` 或第二份排座（契约 §5）。**落点**：`NEW apps/web/src/lib/phantom-seat.ts`（`lib/seat.ts` 旁），**不是** `useWorld.ts` 内的私有函数——私有就不可被 `01` 引用。`Box` 类型取自 `lib/collide.ts` 的 `makeBox` 返回类型。

**输入来源（签名只有 2 参，故 `phantomSeatFor` 不能读 `useWorld` 的 `stateRef`）**：`phantom-seat.ts` 自持一份**当前层 items 镜像**，由 `useWorld` 在 `fetchLayer` 成功后（即 `stateRef.current = next` 那一处，`useWorld.ts` 的 `fetchLayer` 成功分支，**`[行号待复核]`**）调用 `publishSeatItems(layer, items)` 写入；`phantomSeatFor` 读它 + 注册表快照。签名（`NEW`，同模块）：

```ts
/** `useWorld` 在每次 `fetchLayer` 成功后发布当前层的 rows（`LayerItem[]`）。
 *  镜像里记下 `layer`：与 `phantomSeatFor` 的入参不一致时按空集处理
 *  （宁可幻影重叠，也不把过期的 items 当真占用去压真实卡）。 */
export function publishSeatItems(layer: string, items: readonly LayerItem[]): void;
```

```ts
// phantom-seat.ts 模块态：当前层的 rows 镜像（由 publishSeatItems 写入）。
let seatLayer: string | undefined;
let seatItems: readonly LayerItem[] = [];

export function publishSeatItems(layer: string, items: readonly LayerItem[]): void {
  seatLayer = layer;
  seatItems = items;
}

export function phantomSeatFor(size, layer) {
  // 镜像归属核对：层不符 ⇒ 按空集（宁可重叠，不压真实卡）。
  const items = seatLayer === layer ? seatItems : [];
  const occupied: AutoLayoutRect[] = [
    ...items.map((it) => ({ id: it.path, x: it.x, y: it.y, w: it.w, h: it.h })),
    ...getPhantomsSnapshot()
      .filter((p) => ghostVisibleOn(p.layer, layer))
      .map((p) => ({ id: `phantom:${p.toolCallId}`, x: p.seat.x, y: p.seat.y, w: p.seat.w, h: p.seat.h })),
  ];
  const result = flowColumns(
    [{ id: `phantom:${layer}`, w: size.w, h: size.h }],
    occupied,
  );
  const placement = result.placements[0];
  if (!placement) throw new Error('flowColumns returned no phantom placement');
  const z = 1 + items.reduce((m, it) => Math.max(m, it.z), 0);
  return { seat: { x: placement.x, y: placement.y, w: size.w, h: size.h, z }, occupied };
}
```

> **为什么用镜像而非 `stateRef`**：`phantomSeatFor` 的签名冻结为 `(size, layer)`（契约 §5），而 `stateRef` 是 `useWorld` 钩子闭包内的 ref——模块导出的函数读不到它。故由 `useWorld` 在 `fetchLayer` 成功处 `publishSeatItems(layerRef.current, next.items)` 发布。`next.items` 已是**当前层的 rows**（一次 fetch 只装一层，`LayerItem` 无 `layer` 字段），无需逐项过滤；转换为 `AutoLayoutRect` 时使用世界坐标 left/top 与真实 `w/h`，不再经过 center-box。
> **幂等**：`register` 第二次调用（心跳帧）时 `phantom.ts` 忽略 `seat`（§2.5），所以即便本函数重算也无副作用。
> **座位同源边界**：服务端与幻影调用同一个 shared `flowColumns`，但输入集合仍不同（前端 = 当前层 items ∪ 全部同层幻影；服务器 = `/layer` 页面 items 对应 rows ∪ 本批 boxes）。因此算法同源不等于输出永远同座；`land` 不改 seat，不一致时 `file_changed` → `fetchLayer` 的真实坐标赢，幻影由 §3.3 退场。
