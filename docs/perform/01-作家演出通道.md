## 1. 一句话与定位

**作家车道的四条演出帧，把「笔尖落下 → 正文湿墨 → 洇干落定 → 收笔归位」这条时间轴接到前端；其中 `writer_delta` 的来源流是一次契约级修正：正文来自 `chalk` 工具调用的 `content` 参数增量，而不是助手的文本回复。**

四条帧全在**演出帧**通道（`docs/tools/00 §5.3`），**一条都不落事件**（§5）。世界事实（`entity_created` / `entity_edited`）由 chalk 动作自己落账，经尾部读表以 `world_event` 到前端——两条通道独立，这是 `doc-21 §1.1`「帧是动画，不是变化」的字面意思。

**为什么本篇最贵**：契约 §3 裁决 A。现状把 `writer_delta` 映射到 `text_delta`（`apps/server/src/engine/event-bridge.ts:66-71`），而 AIRP 的叙事正文**不在回复里**：`WRITER_INSTRUCTION`（`extensions/instructions.ts:74-79`）逐字写着「text that lives only in your reply never reaches the player, and the canvas stays empty」；正文的唯一入口是 `chalk` 的 `parameters.content`（`extensions/toolkit/chalk.ts:41-43`）。照现状接线，会把作家的**过程语言**当叙事湿墨演上画布，再被真正落地的 chalk 覆盖——比「零消费」更糟。

## 3. 行为契约逐步（每步写「漏了会怎样」）

### 3.1 判定机制：**延迟确认**（裁决 A 强制；契约 §3.2 已删「乐观前缀」）

**裁决 A（R2/F-13）已从契约正文删除「乐观前缀流」，强制延迟确认。** 机制：缓冲 `toolcall_delta` 到 `toolcall_end`，读 `toolCall.name === 'chalk'` 后**才**产出 `writer_delta`；并追加**强制**：`appendInk` 对未知 `toolCallId` MUST 建 pending 缓冲（裁决 B，§6.3）。判定条件写成唯一一个等式：

```ts
const isChalkDelta = source === 'writer' && assistantEvent.type === 'toolcall_end'
                  && assistantEvent.toolCall?.name === 'chalk';
```

**为什么拒绝前缀判定**（论证）：

- 前缀 `{"content":` 只能证明「第一个键叫 content」，**不能证明工具是 chalk**。`R2/F-13` 实测：**带 `path` 的 chalk，其参数 JSON 以 `{"path":` 开头**（LLM 生成顺序不遵循 schema 声明序），与 `write`（`{path,content}`）**逐字不可区分**；故乐观判定**根本不成立**。裁决 A 已把「乐观前缀流」从契约删除，本篇不实现它。
- **延迟确认带来的时序反转已兜住**（裁决 B）：`writer_delta` 先于 `chalk_writing` 到达是**常态**，由 `appendInk` 的 pending 缓冲兜（§6.3、§7）。这是「延迟确认不损失观感」的另一半依据。
- 契约 §3.2 原则 4 是硬取向：「宁可延迟到 `toolcall_end` 再追字播放……也绝不在 delta 期间显示未确认内容——**显示错了再撤回，比晚几百毫秒更伤**」。乐观流一旦误判，必须在前端撤回已渗出的墨，这是本批明令禁止的画面（§9 反模式 4 的直接反面）。
- 延迟的代价只是「帧到达时刻」，而那个时刻**前端从来没消费**：逐字节奏由前端计时器给（§6.3）。故延迟不损失观感。

**漏了会怎样**：用前缀判定且误判 → 非 chalk 工具的参数字符串被当正文渗上画布，落地后与真实卡片对不上，玩家看到「凭空出现又消失的字」。延迟确认则**结构上不可能**发生。

### 3.2 服务端逐步（`mapEngineEvent` 的 `message_update` 分支改造）

```
on message_update(source, assistantMessageEvent = ev):
│
├─ ev.type === 'text_delta'
│   ├─ source === 'character' → push { type:'character_delta', source, delta }   // 不变（§3.4）
│   └─ source === 'writer'    → 不产任何帧                                      // 契约 §3 裁决 A
│
├─ ev.type === 'toolcall_delta' && source === 'writer'
│   └─ toolcallBuf.get(ev.contentIndex).push(ev.delta)     // 只缓冲，不产帧
│
├─ ev.type === 'toolcall_end' && source === 'writer'
│   ├─ frags = toolcallBuf.get(ev.contentIndex) ?? [] ; toolcallBuf.delete(ev.contentIndex)
│   ├─ tc = ev.toolCall
│   ├─ if (tc?.name !== 'chalk') → 丢弃 frags，不产帧（`write` 也走这条）
│   └─ else:
│        authoritative = tc.arguments?.content            // 已解析的对象属性（§2.2 item 3）
│        if (typeof authoritative !== 'string' || !authoritative) → 不产帧（§7）
│        else → replayFragments(frags, tc.id, authoritative)   // §3.2.1
│
├─ ev.type === 'message_end' || event.type === 'agent_settled' → toolcallBuf.clear()
└─ 其余 → 不变
```

`toolcallBuf` 与既有的 `toolArgsByCallId`（`EventBridge` 实例字段）一样挂在 `EventBridge` 实例上，`mapEngineEvent` 通过参数拿到；**纯函数性质保持**（探针可直接调用，`event-bridge.ts` 顶部注释的设计意图）。

#### 3.2.1 按分片重放（`chalk-delta.ts` 的用武之地）

```
prev = '' ; acc = ''
for frag in frags:
    acc += frag
    got = extractContentPrefix(acc)             // §3.3，返回「已确定的解码前缀」
    delta = got.text.slice(prev.length)
    if (delta !== '') push({ type:'writer_delta', source, delta, toolCallId: tc.id })
    prev = got.text

if (prev !== authoritative)                     // 一致性兜底（P1-1：替换语义，绝不累积）
    push({ type:'writer_delta', source, delta: authoritative, toolCallId: tc.id, mode: 'replace' })
```

- **不让任何一条 `writer_delta` 以半截转义结尾**：`got.text` 永远停在**已解码的完整字符**上；`\"`、`\uXXXX` 跨分片时整段计入下一片。
- **兜底语义 = 替换，不是追加**（R3/P1-1 实锤）：兜底帧 MUST 带 `mode:'replace'`，前端 `case 'writer_delta'` 见 `mode:'replace'` 时调 `setInk(toolCallId, delta)`（**整体覆盖** `entry.text`），而**不是** `appendInk`。若照初稿「补一条整段 `writer_delta`」，它会拼在已渗出的湿墨尾部 → 正文**翻倍**（`authoritative` 出现两次）。
- **为什么宁要替换也不要分片节奏**：正文绝不可能少字，也绝不可能翻倍；宁可与权威正文逐字一致。
- **漏了会怎样**：不做兜底，提取器一旦漏了某个转义形态，玩家看到**比真实正文短**的湿墨，落定后卡片又是完整正文 → 玩家理解成「作家改稿了」；用追加语义兜底则玩家看到**写重了一截**。

#### 3.2.2 `writer_delta` 的重放是「一次性多条」

`toolcall_end` 到达时循环 push 多条 `writer_delta`（每片一条），`EventBridge.broadcast` 逐条发出（`event-bridge.ts:240-251`）。前端把它们**并入同一个 `toolCallId` 的湿墨缓冲**（§6.3），节奏由前端计时器接管。

### 3.3 `chalk-delta.ts`：完整签名与算法（NEW，纯函数）

```ts
// apps/server/src/engine/chalk-delta.ts  —— 纯函数，无 I/O，单测必备（契约 §8 冻结路径）

export interface ContentPrefix {
  /** 已确定的**解码后**前缀。永不以半截转义结尾（`\` 或 `\uXX` 不完整时整段不输出）。 */
  text: string;
  /** true = 已读到 content 字符串的收尾引号；text 即完整值。 */
  complete: boolean;
}

/**
 * 从一份**正在累积**的参数 JSON 前缀里，抽出 `content` 字段已到达的、已解码的取值前缀。
 * 处理转义 `\" \\ \/ \b \f \n \r \t \uXXXX`、`content` 非首字段、未闭合字符串。
 * 找不到 `content`（未到达 / 非字符串 / JSON 未闭合） → { text: '', complete: false }。
 */
export function extractContentPrefix(json: string): ContentPrefix;
```

**算法（两趟扫描，逐字符）**：

**第 1 趟 — 定位顶层 `"content"` 的值起点**

```
i = 0 ; skipWs ; if json[0] !== '{' → none
i = 1
loop:
  skipWs ; if i >= n || json[i] === '}' → none
  if json[i] !== '"' → none
  (key, i) = readJsonString(i)          // 复用第 2 趟的解码器（键也要正确解码）
  skipWs ; if json[i] !== ':' → none ; i++ ; skipWs
  if key === 'content':
      if json[i] === '"' → valueStart = i+1 ; break
      else               → none          // content 非字符串
  else:
      i = skipValue(i)                   // 字符串→扫未转义收尾引号（未收尾则 none）；
                                         // 对象/数组→计数配平；字面量→扫到分隔符
  skipWs ; if json[i] === ',' → i++ ; continue ; else → none
```

**第 2 趟 — 解码字符串体（从 `valueStart`）**

```
out = '' ; j = valueStart
while j < n:
  c = json[j]
  if c === '"'  → return { text: out, complete: true }
  if c !== '\\' → out += c ; j++ ; continue
  if j+1 >= n   → break                       // ← 未闭合反斜杠：**不输出这个 `\`**（非空性用例）
  switch json[j+1]:
    '"'→'"' ; '\\'→'\\' ; '/'→'/' ; 'n'→'\n' ; 't'→'\t' ; 'r'→'\r' ; 'b'→'\b' ; 'f'→'\f'   ; j+=2
    'u' → if j+6 > n || !/^[0-9a-fA-F]{4}$/.test(json.slice(j+2,j+6)) → break  // 未闭合/非法 \uXXXX：整段不输出
          out += String.fromCharCode(parseInt(json.slice(j+2,j+6),16)) ; j += 6
    default → out += json[j+1] ; j += 2        // 宽容：非法转义按字面字符处理
return { text: out, complete: false }
```

- **代理对（surrogate pair）**：`\uD83D\uDE00` 会以两个 UTF-16 码元追加。前端拼出的是同一串码元，**视觉与正文一致**；`[推断]`：无需合并（`MarkdownText` 不按码点切分，`apps/web/src/lib/md.ts`）。
- **`skipValue` 的字符串分支也复用同一解码器**：`{"path":"a\"b","content":"y"}` 里的 `\"` 不能当 `path` 的收尾引号——否则 `content` 定位错位（契约 §3 item 2 点名的失败）。

### 3.4 两个车道的来源流为什么不同（契约 §3 item 4）

| 车道 | 叙事载体 | 正确来源 | 依据 |
|---|---|---|---|
| writer | `chalk` 工具调用的 `content` 参数 | `toolcall_delta`（缓冲后 `toolcall_end` 确认） | `instructions.ts:74-79`、`chalk.ts:41-43` |
| character | 助手**直接说的话**（角色被要求直接开口，没有 chalk 工具） | `text_delta` | `instructions.ts:168`（`CHARACTER_INSTRUCTION`）、`:174`（「your words ARE the scene」） |

**刻意不同，不是疏忽**：角色遮罩的台词就是助手的文本回复流（`apps/web/src/components/overlay/CharacterModal.tsx` 的 `Phase` 机与帧消费已按 `character_delta` 落地，行号待复核）。若把角色改成工具参数，等于要求角色走 chalk——而 `CHARACTER_INSTRUCTION` 明说「That is not your job」。

**思考指示（保留并写明）**：作家在 `chalk` 工具调用**之前**说的过程语言（`text_delta`）**不产任何帧**——它既不上画布的湿墨（否则会把 "let me think" 渗到画布，§1），也不进 `writer_delta`。**这是刻意的**：画布上的「笔尖在场」由 `chalk_writing`（+ `ChalkMark` 的笔尖指示）承担，不由作家的思考文本承担。**唯一例外**：作家在 `chalk` 参数流之外的**最终**文本回复仍走 `writer_message`（`message_end`，门禁已豁免为 `INTENTIONALLY_UNCONSUMED`，§12.3）——本批不动它。

**漏了会怎样**：把 writer 的 `text_delta` 也映射成帧（现状）→ 过程语言上画布（§1）；把 character 的 `text_delta` 也掐掉 → 遮罩哑掉（A3 刚接上的流被拆）。

## 5. 落账（演出帧一律不落事件——说清为什么）

**四条帧全不落事件**。理由三层：

1. **通道定义**（`docs/tools/00 §5.3` / `docs/tools/12 §6.1`）：演出帧是「世界变化的动画」，事件是「世界怎么变成现在这样的」。四条帧都是**动画的中间态**，没有一条回答「世界变成了什么」。
2. **事件已由动作自己落**：`chalk` 动作落 `entity_created`（append 时 `entity_edited`），经 `store.appendEvent` → `history.db` → 尾部读表 → `broadcast({type:'world_event'})`（`event-bridge.ts` 的 `drainWorldEvents`）。这里再落一条，同一事实会有两份账。
3. **落账会污染 `seq`**：`event.seq` 是前端唯一排序游标与去重键（`docs/tools/12 §6.4`）。逐字湿墨写进事件表会让 `events` 表按字符数膨胀，且每条都会触发一次整层重取（`case 'world_event'` → `fetchLayer`）——**写一个字重取一次层**。

**机械判据（R3/P2-3 更正）**：`apps/server/src/engine/event-bridge.ts` grep `appendEvent` **命中 1 次**——且仅在 `drainWorldEvents` 的**注释**里（`event-bridge.ts:265` 的 doc-comment 词），**代码路径零调用**（它只调 `getEventsSince`/`getMaxSeq`）。**不是「零命中」**：初稿写「零命中」是错的，评审点出后改正。判据应写「`appendEvent` 仅出现在注释（1 处），无代码调用」。

**与现有实现的差异**：现状本来就没落（`case 'chalk_writing'`、`case 'chalk_landed'`、`case 'writer_idle'` 三个发射点均不落账）[行号待复核]，本批**不引入落账**——这点必须写明，因为「给 `writer_delta` 接消费方」很容易顺手补一条事件。

### 6.1 `chalk_writing` —— 笔尖落下 + 幻影壳（**不依赖 `items`**）

契约 §6b-1 是硬约束：`chalk_writing` **不带 `path`**，此刻文件未落盘，**目标卡在 `items` 里还不存在**。故 `case 'chalk_writing'` 只做三件事：进 writing 态、登记幻影（座位由 `03` 的 helper 算）、起蓄势音。

```ts
case 'chalk_writing':
  if (msg.source !== 'writer' || typeof msg.toolCallId !== 'string') break;
  writerState.beginTurn('chalk', msg.toolCallId);      // §6.4，UI 进 writing
  phantoms.register(msg.toolCallId, {                  // §6.2，独立浮层
    kind: 'chalk', source: 'writer',
    seat: phantomSeatFor({ w: CARD_FORMS.chalk.w, h: CARD_FORMS.chalk.h },   // 03 §8.5：座位属 03
                          layerRef.current).seat,
    layer: layerRef.current,
  });
  playCharge(0);                                       // §6.0b：笔尖蓄势（逐帧续推 progress 归 ChalkMark）
  break;
```

- **MUST NOT `items.find(path)`**（契约 §6b-1，反模式 5）。**座位由 `03` 的 `phantomSeatFor(size, layer)` 算**（`03 §8.5`：内部对 `items ∪ 同层幻影` 求空位，复用 `lib/seat.ts` 的 `seatSpiral` + `lib/collide.ts` 的 `makeBox`）——**`01` 不再拥有座位算法，禁自造 `nextInkSeat`**（裁决 D/R1-03/R2/F-3）。chalk size 取 `CARD_FORMS.chalk`（`packages/shared/src/schemas/forms.ts` 的 `{ w: 460, h: 190 }`，**实读**；`useWorld.ts` 需 import `CARD_FORMS` 或本地常量）。与 T3.5「幻影座位=成品座位」的**期望**一致；实际以真实重取为准（§6.6）。
- **`register` MUST 带 `layer`**（R1-05/契约 §8.1）：两条帧都不带 `layer`，由调用方在 `register` 时补当前层（`layerRef.current`；否则换层后幻影悬空、`PhantomLayer` 的 `entry.layer === currentLayer` 过滤失效）。
- **笔尖 / 幻影壳**由 `ChalkMark` 渲染（`performance/WriterInkLayer.tsx`，挂载在 `PhantomLayer` 下，§6.6）：`.chalk--ghost` 壳 = shimmer 骨架条 + 笔尖指示；**无正文**（正文走 `writer_delta`）。

**漏了会怎样**：把幻影挂到 `items` 上 → `items` 里没有该 path → 什么都不出现，「笔尖落下」这一拍整个丢失（玩家只看到几秒空屏后正文突然出现）。

### 6.2 `lib/phantom.ts` —— 幻影注册表（**本批冻结签名**）

契约 §8.1（**主 agent 亲自冻结**，裁决 C）给了完整字段集与 API 面：`register` / `appendInk` / `setInk` / `land` / `reconcileLanded` / `evict` / `subscribePhantoms` / `getPhantomsSnapshot` / `usePhantoms`。**本篇逐字采用，不再单方面扩字段**（`label?`/`elapsedMs?`/`layer?`/`reused?` 已由裁决 C 并入契约；`PhantomLandPayload.seat?` 已删）。两点语义（`register` 幂等合并、`layer` 过滤）见下。`03` 逐字复用；座位 helper `phantomSeatFor(size, layer)` 属 `03`（`03 §8.5`，本篇 §6.1 调用它）；已 IRC 对齐 `Rewrite03Image`。

```ts

/** 座位坐标（世界坐标的 left/top + w/h/z），由 `03` 的 `phantomSeatFor` 产出。 */

/** 幻影条目（**字段集 = 契约 §8.1 逐字**）。 */

  toolCallId: string;
  kind: PhantomKind;
  source: 'writer' | 'character';
  /** chalk_landed / image_landed 前未知（此前 undefined：卡还不存在）。 */
  path?: string;
  /** 幻影座位 = 成品座位；`land` **不改**它（契约 §5 座位过户）。 */
  seat: PhantomSeat;
  /** chalk 车道的湿墨累积正文（写时半透明）。 */
  text?: string;
  /** image 车道的落定资源（`/api/asset?path=<asset>` 用）。 */
  asset?: string;
  /** image 落定是否命中缓存（`land` 时从 payload 写入；`GhostCard` 读它贴封条）。 */
  reused?: boolean;
  /** 壳内一行标签（`register` 从 `PhantomInit.label` 存下；chalk 车道不读）。 */
  label?: string;
  /** 进度心跳的已用毫秒（`03` 幂等合并时更新）。 */
  elapsedMs?: number;
  /** 幻影所属层（`register` 时传当前层）；缺省 = 不过滤。 */

/** `register` 的初始化载荷（**字段集 = 契约 §8.1 逐字**）。 */

  kind: PhantomKind;
  source: 'writer' | 'character';
  path?: string;
  seat: PhantomSeat;
  label?: string;
  elapsedMs?: number;
  layer?: string;
}

/** `land` 的附加载荷；两个车道共用。**无 `seat?`**（契约 §8.1：`land` 语义＝座位不变）。 */
export interface PhantomLandPayload {
  path?: string;
  asset?: string;
  mimeType?: string;
  width?: number;
  height?: number;
  reused?: boolean;
}

/** 新增/合并一个幻影（**幂等**）。 */
export function register(toolCallId: string, init: PhantomInit): void;

/** 幻影 → 落地：置 phase='landed'，记录 payload；**座位不变**（契约 §5 座位过户）。 */

/** 追加湿墨片段（`writer_delta` 用）。**未知 `toolCallId` → 建 pending 缓冲**，`register` 时灌入（§6.3 / P0 时序）。 */

// --- 订阅（React 侧）---
export function subscribePhantoms(cb: () => void): () => void;
```

**订阅机制**：本模块提供现成 hook：

```ts

}
```

- `getPhantomsSnapshot` MUST 返回**稳定引用**（缓存数组，仅 `register`/`land`/`appendInk`/`setInk`/`evict`/`reconcileLanded` 时重建）——否则 `useSyncExternalStore` 的 `Object.is` 检查会无限重渲染。
- `subscribePhantoms` 返回退订函数；与 `lib/parallax.ts:38-44` 同形，但**不做**「订阅即回调一次」（初值由 `getSnapshot` 给）。

**`register` 的幂等合并语义（与 `03` 对齐，冻结）**：

- 首次调用：建 entry，`createdAt = now`，`phase='pending'`（尚无湿墨/未确认为 writing），`seat` 取自 `init`。
- 同 `toolCallId` 二次调用（`03` 的 `resolving` + N 帧 `generating` 心跳走这条）：**只更新 `init` 本次给了值的字段**（`label` / `elapsedMs` / `layer` / `path`），**不重算 `seat`、不重置 `createdAt`、不改 `phase`**（`phase` 只在 `appendInk`/`land`/`evict` 变）。
- **pending 缓冲灌入**（P0 时序，契约 §5/§8 强制项）：`register` 时若该 id 已有 `appendInk` 建立的 pending 缓冲，**把缓冲灌进 `entry.text`**（湿墨不丢），随后清缓冲。首次 `appendInk` 到 `register` 之间 `phase` 可为 `'pending'`。
- 判据单测：同 id 二次 `register` → 快照引用变、`createdAt`/`seat` 不变、`label` 与 `elapsedMs` 更新；`appendInk('t1','x')` 先于 `register('t1',…)` → `entry.text === 'x'`。

**`layer` 过滤**：`PhantomLayer`（`03`）按 `entry.layer === currentLayer` 过滤；`entry.layer === undefined`（老帧 / 调用方未传）**不过滤**（容错，遵循既有「前端 MUST 容忍缺失」纪律）。**`03` 不另建 toolCallId→layer 旁表**（第二注册表违契约 §5）。

**谁调谁**：

| 调用方 | 调用 |
|---|---|
| `useWorld` `case 'chalk_writing'` | `register(toolCallId, {kind:'chalk', source:'writer', seat: phantomSeatFor({w,h}, layerRef.current).seat, layer: layerRef.current})` |
| `useWorld` `case 'writer_delta'` | `appendInk(toolCallId, delta)`（未知 id → pending 缓冲） |
| 服务端兜底（§3.2.1） | 前端 `case 'writer_delta'` 带 `mode:'replace'` 时 → `setInk(toolCallId, delta)`（替换语义） |
| `useWorld` `case 'chalk_landed'` | 用 `msg.toolCallId`（**已加**，§2.1）→ `land(toolCallId, {path})` |
| `useWorld` `case 'tool_end'`（writer + isError） | `evict(toolCallId, {reason})` |
| `useWorld` `fetchLayer` 成功后 | 对每个 `path` 命中的 chalk 幻影调 `reconcileLanded(entry.toolCallId)`（§6.5） |
| `03` 的 `image_generation_progress` | `register(toolCallId, {kind:'image', source:'writer', seat: phantomSeatFor(size, layer).seat, layer, label: stage, elapsedMs})`（幂等心跳，见上） |
| `03` 的 `image_landed` | `land(toolCallId, {asset, mimeType, width, height, reused})` |
| `PhantomLayer`（`03`） | `usePhantoms()` → 按 `entry.layer === currentLayer` 过滤 → 分派 |

**座位 helper 属 `03`**：`phantomSeatFor(size, layer): { seat: PhantomSeat; occupied: Box[] }`（`03 §8.5`，实现复用 `lib/seat.ts` 的 `seatSpiral` + `lib/collide.ts` 的 `makeBox`，occupied = `items ∪ 同层 image 幻影`）。**`01` MUST 调用它，禁止自造 `nextInkSeat` 或第二份排座**（裁决 D / 契约 §5）。chalk 的 size 用 `CARD_FORMS.chalk`（`packages/shared/src/schemas/forms.ts` 的 `{ w: 460, h: 190 }`）。

**`chalk_landed` 的定位键（已定案，R5/B6）**：`toolCallId` **是过户键**（`land`/`reconcileLanded` 直接按 id 匹配，无歧义）；`path` **是对齐键**（`reconcileLanded` 用「真实卡是否已含此 path」判定幂等撤销）。同 turn 多篇 chalk 场景下二者都由服务端帧携带（`toolArgsByCallId` 已有 id），**不再需要「最早未落定」启发式**。

### 6.3 `writer_delta` —— 湿墨累积渲染挂点

```ts
case 'writer_delta':
  if (msg.source !== 'writer' || typeof msg.toolCallId !== 'string' || typeof msg.delta !== 'string') break;
  if (msg.mode === 'replace') phantoms.setInk(msg.toolCallId, msg.delta);   // 兜底替换（§3.2.1）
  else                        phantoms.appendInk(msg.toolCallId, msg.delta); // 正常累积（未知 id → pending）
  break;
```

- **挂点 = `phantom.ts` 注册表，不是卡片**（契约 §6b-1：卡还不存在）。
- **累积而非替换**（契约 §3 item 3）：正常帧走 `appendInk` 拼在 `entry.text` 尾部；**唯一例外**是服务端兜底帧（`mode:'replace'`，§3.2.1）走 `setInk` 的**替换语义**。
- **P0 时序（契约 §5，R3/P0-1）**：`writer_delta` 源自 `toolcall_end`，**常态先于** `chalk_writing`（源自 `tool_execution_start`）到达。故第一条 `writer_delta` 到达时幻影**尚未 register**——`appendInk` MUST 对未知 id 建 **pending 缓冲**，`register` 时灌入 `entry.text`。**没有这条，湿墨被静默丢弃（零报错）**，玩家只看到一张白壳（§7 该行）。
- **渲染 = `ChalkMark`**（`performance/WriterInkLayer.tsx`；由 `PhantomLayer` 按 `kind` 分派，§6.6）：每条 `kind:'chalk'` 幻影渲染成 `.chalk--bare .chalk--ghost` 节点，`text` 交给 `MarkdownText`（`apps/web/src/lib/md.ts`）。
- **逐字节奏**：服务端在 `toolcall_end` 一次性推多条 `writer_delta`，前端可能一帧内收完——**逐字由 `ChalkMark` 的本地计时器实现**（每 ~24ms 把 `shownChars` 前进一格，追到 `entry.text.length` 为止）。计时器**独立于帧到达时刻**，这是「延迟确认不损失观感」的实现依据（§3.1）。
- **`text_delta` 不进这里**：反模式 4；服务端已不产（§3.2），前端也**不加**这个来源。

### 6.4 `writer_idle` + `lib/writer-state.ts` —— `idle ⇄ writing` 状态机（**本批冻结**）

`docs/前端改造计划.md:347` 要求：「writing 中再按 Enter → placeholder 变『作家正在写……』，输入无效（诚实，不排队不打断）」；`doc-06 §2.3:73-84` 给出状态机与打断语义。

```ts
export function endTurn(): void;                     // ← `writer_idle` 调它
```

**状态迁移**：

```
idle ──tool_start(source==='writer') / chalk_writing──▶ writing
writing ──writer_idle（agent_settled）──▶ idle（endTurn()；§6.0b：endCharge() + 停 writing 态环境音）
```

**重连归位（R3/P1-2）**：`phase:'writing'` 的唯一正常出口是 `writer_idle`（`agent_settled` 只在 turn 的 finally 发）。若 WS 在 writing 期间断开（热重载 / 网络抖动 / 休眠），`writer_idle` 落在断线窗口 → **phase 永久停在 writing、输入条永久禁用、玩家输入静默丢失**。既有代码对同类问题已有防线：`useWorld.ts` 的 `ws.onopen`（现重置 `writerToolsInFlight.current = 0` 的那段）[行号待复核]。**本批 MUST 在该 `onopen` 里同时调 `writerState.reset()`**，与既有重连守卫同处。判据进单测（§10.3）。

**消费点**：

- `WriterBar`（`apps/web/src/components/chrome/WriterBar.tsx`，组件体 [行号待复核]）：`const writing = useWriterPhase() === 'writing'`；`disabled={disabled || writing}`；`placeholder` 在 `writing` 时换成「作家正在写……」文案（i18n +1 key；`lib/i18n.ts`）。
- `App.tsx`（`WriterBar` 挂载处 [行号待复核]）：把新文案传给 `WriterBar`。

### 6.5 `chalk_landed` —— 座位过户（**幂等**）

```
case 'chalk_landed':
  if (msg.source !== 'writer' || typeof msg.toolCallId !== 'string') break;
```

- **过户幂等**（契约 §6b-5）：`file_changed` 仍整层重取（A 档定案），真实卡随后进 `items`；`fetchLayer` 成功后**对每个 `entry.path` 命中真实卡的 chalk 幻影**调 `reconcileLanded(entry.toolCallId)`（内部 `evict`）。
- **不重排真实卡**（契约 §5）：真实坐标以重取为准；幻影期间不写 `card_position`，避免与服务器排座打架（反模式 5）。
- **`chalk_landed` 不触发 `fetchLayer`**：重取由 `file_changed` 负责（`useWorld.ts` 的 `case 'file_changed'`）[行号待复核]，本 case 只做过户——**在 `chalk_landed` 里 `fetchLayer` 会与 `file_changed` 撞车、白白重取两次**。

**漏了会怎样**：不幂等 → 重取后幻影卡与真实卡**同时在画布上**，玩家看到两张一样的板书（重影）。不做 `reconcileLanded` → 重进层时幻影壳永久残留（encore 事故变体，`doc-06 §2.2:69`）。

### 6.7 `writer_idle` 与 `writerToolsInFlight` 的关系（**契约 §6b-6 要求说清**）

`writerToolsInFlight`（`useWorld.ts` 的既有 ref，`tool_start`/`tool_end` 仅 writer 加减）喂 footprint 调度器的 `isBusy`（`footprint.ts` 的 gate）[行号待复核]。本批新增的 `writer-state.ts` 是**第二个 writer 忙闲源**。**必须语义一致，不许各说各话。**

**定案：同一批 `case` 驱动，「一次帧、两个消费方」**——

- `writerToolsInFlight` **保持**为 footprint 的忙闲源（`useWorld.ts` 的 `isBusy` 不改）。
- `writer-state.ts` 的 `beginTurn/endTurn` **由同一批 `case` 驱动**：`case 'tool_start'`（writer）→ `beginTurn('turn')`；`case 'chalk_writing'` → `beginTurn('chalk', toolCallId)`；`case 'writer_idle'` → `endTurn()`；`ws.onopen`（重连）→ `reset()`。
- **职责划分（不重叠）**：

| 源 | 语义 | 消费方 | 位置 |
|---|---|---|---|
| `writerToolsInFlight` | **有工具在飞** → 文件窗口未稳，别测量 | footprint 调度器（`footprint.ts` 的 gate） | `useWorld.ts` 的 `isBusy` |
| `writer-state.phase` | **作家在写** → 输入禁用、笔尖在场 | `WriterBar` / `ChalkMark` | 本批新增 |

- **一致性判据（可核验）**：`phase === 'idle'` ⇒ `writerToolsInFlight.current === 0`。反向**不成立**：`tool_end` 之后、`writer_idle` 之前允许 `phase==='writing' && inFlight===0`（chalk 落定到收笔之间的湿墨洇干期，正是 §6.6 需要的）。这条**单向蕴含**进单测（§10.3）。
- **为什么两个源不能合并成一个**：`writer_idle` 是 `agent_settled` 的唯一归位信号（`event-bridge.ts` 的 `agent_settled` 分支）；`tool_end` 只能减计数，**不能**判「作家空闲」——一个 turn 里可有多个工具，减到 0 不代表轮结束。若用 `tool_end` 归位 UI，玩家会在「第一个工具回、第二个还没发」的空档看到输入条解禁 → 玩家的输入静默丢失（**违反 §7「失败必须可见」**）。


**读者注意**：`writer-state` 的 `phase` 是**写作输入面**的忙闲；它不参与 footprint 调度（那是 `isBusy` 的事），两者只在「同一批帧驱动」上耦合，不共享状态对象——避免一处改了字段另一处读不到。

## 7. 错误与边界（失败必须可见，不静默）

| 情形 | 现象 | 处理（**可见**，不静默） |
|---|---|---|
| `tool_end{isError:true}`（chalk 写盘失败 / 参数非法） | 幻影壳留在画布半成品 | `evict(toolCallId, {reason})` → `.chalk--ghost` 加 `.ghost--evicting`，~320ms 淡出+轻微右移后移除；**不 `console.warn` 当可见**（反模式 3） |
| `tool_end{isError:true}` 但 `toolCallId` 无对应幻影（帧乱序 / 未 `chalk_writing`） | `evict` 空操作 | `phantom.ts` 内部守卫：未知 id → 记入模块内一个**非导出**孤儿计数（供 `phantom.test.mjs` 经测试钩子断言），**不抛错**（前端永不因演出帧崩）。**不新造导出 API** |
| **P0 时序：`writer_delta` 先于 `chalk_writing` 到达（常态，非异常）** | 第一条湿墨到达时幻影尚未 `register` → **静默丢字** | `phantom.ts::appendInk` MUST 对未知 `toolCallId` 建 **pending 缓冲**，`register` 时灌入 `entry.text`（§6.2/§6.3）。**这是常态路径**（`toolcall_end` 先于 `tool_execution_start`，契约 §5）；判据：先 `appendInk('t1','x')` 再 `register('t1',…)` → `text==='x'`（§10.3） |
| `chalk_landed` 到达但无任何 chalk 幻影（例如刷新后重连） | 无壳可过户 | `land(toolCallId, …)` 空操作（无该 id）；真实卡由 `file_changed` 重取带入——**这是正路，不是错误** |
| `toolcall_end` 的 `arguments.content` 非字符串 / 空 | 无正文，湿墨不能出现 | 服务端**不产帧**（§3.2）；前端 `register` 仍发生（`chalk_writing` 已到），幻影壳呈「白纸+笔尖」到 `chalk_landed` 过户——**空正文是合法叙事（"世界的沉默"），不是失败** |
| `writer_idle` 在 `chalk_writing` 之前到（异常时序） | `endTurn` 把还没开始的写作关了 | `endTurn` 幂等；`writer-state` 不校验顺序（避免误判卡死）—— `[推断]`：实际不会（`agent_settled` 总在 turn 末） |
| **WS 在 `writing` 期间断开**（热重载 / 抖动 / 休眠） | `writer_idle` 落在断线窗口 → `phase` 永久停在 `writing`、输入条永久禁用、玩家输入**静默丢失** | `useWorld.ts` 的 `ws.onopen`（已有重连守卫：重置 `writerToolsInFlight`）**同时调 `writerState.reset()`**（§6.4 重连归位）。判据：`reset()` 后 `phase==='idle'`（§10.3） |
| `getPhantomsSnapshot` 引用不稳定 | React 无限重渲染 | 单测断言「无变更时 `getPhantomsSnapshot() === getPhantomsSnapshot()`」（§10.3） |
| 提取器遇到未覆盖的转义 | 湿墨短于正文，或兜底把正文写重 | §3.2.1 一致性兜底：`prev !== authoritative` → 推一条 **`mode:'replace'`** 的 `writer_delta`，前端走 `setInk`（**替换**，绝不累积）——正文既不少字也不翻倍 |
| `chalk_landed` 的 `path` 缺失 | 无法按 path 对齐真实卡 | **`toolCallId` 是过户键**（已加，§2.1）→ `land(toolCallId, {path?})` 无歧义；若该 id 无幻影 → 忽略（真实卡仍由重取带入）。**不再用「最早未落定」启发式** |

**失败撤离的可见性判据**（可浏览器验）：令 `chalk` 失败（如临时把 chalk 工具改抛 `invalid_argument`，或让 writer 写一个非法 path），幻影壳必须在 ~320ms 内**可见地**淡出+撤离，画布上**不留半成品**（`doc-10 E3` 的 `cancelPerformance` 纪律，`docs/前端改造计划.md:356`）。

### 10.2 浏览器实测判据（**门禁假绿的解毒剂**，契约 §10）

在浏览器打开画布，向 `WriterBar` 发一句会触发 chalk 的输入（如 `templates/whitechapel` 的任一开局 prompt），逐条断言：

1. **顺序断言（P0 时序，第一优先）**：一次 chalk 演出里，**湿墨首字 MUST 晚于幻影壳入 DOM**。DevTools 打时间戳：`ChalkMark` 的 `.ink-tip` 节点出现早于正文首字；若湿墨先出现，说明 `appendInk` 的 pending 缓冲没兜住（§6.2、§7）——此条立刻红。
2. **`chalk_writing`**：输入回车后**几秒内**画布上出现**半透明 shimmer 壳 + 笔尖指示**（`.chalk--ghost` + `.ink-tip`），**且此刻卡片 `[data-path]` 上还没有该文件**（DevTools 断言：壳的 DOM 节点**不在** `.object[data-path]` 内）——证明「独立于 `items` 的浮层」成立（§6.1）。
3. **`writer_delta`**：壳内正文**逐字增长**（每 ~24ms 一字，可肉眼/截图比对两帧）；**正文内容 = chalk 文件的 body**（落定后与文件逐字比对），**不是**作家的过程语言（如 "let me think"）——后者若出现即裁决 A 未落地（反模式 4）。
4. **`chalk_landed`**：壳转为 `.ink-spread` 洇干；`file_changed` 重取后真实 `ChalkCard` 出现，**幻影节点消失**（`reconcileLanded` 生效，无重影）——证明过户幂等。**座位断言**：`doc-06` 期望同座，但真实坐标**以重取为准**（契约 §5：前端 `items ∪ 幻影` 与服务器 `seatUnplaced` 的 occupied 集合可能不同）。故断言写成「真实卡出现在**服务器排座给定的**位置、且幻影不再残留」，**不是**「差 ≤1px」（与 `03 §8.5` 同口径，见 §6.6）。
5. **`writer_idle`**：`agent_settled` 后 `WriterBar` 解禁（placeholder 从「作家正在写……」变回 `copy.writerPlaceholder`）；**在 writing 期间按 Enter 输入无效且不排队**（`doc-06 §2.3:81`）。
6. **失败可见**：令 chalk 抛错（见 §7 判据），幻影壳 ~320ms 可见撤离，输入条**也解禁**（不能卡在 writing）。
7. **声音**（裁决 J）：`chalk_writing` 后能听到蓄势音起（`playCharge` 的低频正弦），`chalk_landed` 时 `endCharge()` + 一记 `paper-slide`；`writer_idle` 后蓄势音归零（§6.0b）。
