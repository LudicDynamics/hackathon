## ① 一句话定位

**把「玩家双击一张 stub 卡」变成一次真正的初始化，并把生成过程与结果演出来。** 具体三件事：

1. **服务端触发（R2）**：新增一条浏览器 → 服务端的 WS 入站消息 `airp_init`，服务端**不 await** 地把 `/airp-init <json>` 送进作家进程（`RpcClient.prompt`），结果由既有事件表回流（契约 §2.1 / §8 反模式 2）。
2. **`first` 信号的消费**：`POST /api/enter-layer` 今天就返回 `first`（`apps/server/src/routes/world.ts:784` → `packages/shared/src/actions/layer.ts:85`），前端在 `handleEnterGate`（`apps/web/src/App.tsx:253-269`）把它**丢掉了**——本档定义怎么用。
3. **呈现**：stub 层的「这里是……」一行输入（可留空/跳过）+ 生成中的**幻影占位**（doc-11 §3.4）+ 事件回流后的**座位过户**与布局刷新。

**本档不改任何代码**，也不碰 `useWorld.ts` 的 switch（A 档已合，通用 `case 'world_event'` 已覆盖 `layer_*`）——只写设计、落点与冲突。

### 3.2 `first` 信号的消费（核心改造）

现状（逐字）：

```ts
// apps/web/src/App.tsx:253-269（现行；HEAD 版同构）
const handleEnterGate = async (target: string) => {
  try {
    const res = await fetch('/api/enter-layer', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ layer: target }),
    });
    const data = await res.json();
    if (!res.ok) {
      showToast(data.error || 'This scene is still locked.');
      return;
    }
    enterLayer(target);            // ← data.first 到此丢弃
  } catch (err) {
    showToast(err instanceof Error ? err.message : String(err));
  }
};
```

**`first` 的语义链（已全链路存在，逐字核实）**：

| 环 | 位置 | 事实 |
|---|---|---|
| 计算 | `packages/shared/src/actions/layer.ts:66-68` | `dir = layer === 'map' ? 'world' : layer`；`readme = await statKind(dir + '/README.md')`；`first = readme === 'missing'` |
| `statKind` | `packages/shared/src/store/world-store.ts:130` | 返回 `'file' \| 'dir' \| 'missing'`；路径不存在 → `'missing'` |
| 进 details | `actions/layer.ts:85` | `details: { layer, name, first, event }` |
| 出 HTTP | `apps/server/src/routes/world.ts:784` + `reply`（`:44-58`） | `res.json({ ok: true, ...details })` → 响应体含 `first` |
| stub 不拦 | `apps/server/src/routes/world.ts:741-781` | 门卡校验只在 README 存在（`statKind === 'file'`）时跑；stub 直接落到 `:784` |

即 **`first === true` ⟺ 目标层没有 README ⟺ 契约 §3.1 判定的 stub 层**——判据与 `isLayerEmpty`（`packages/shared/src/rules/emptiness.ts:37`）同源。

**改造后的 `handleEnterGate`（目标形态）**：

```ts
const handleEnterGate = async (target: string) => {
  try {
    const res = await fetch('/api/enter-layer', { /* 同上，不变 */ });
    const data = await res.json();
    if (!res.ok) { showToast(data.error || 'This scene is still locked.'); return; }
    enterLayer(target);                                  // ① 先让玩家进去（doc-11 §3.4「玩家已经在场」）
    if (data.first === true) {                           // ② 只有 stub 才触发（幂等由判空短路兜底）
      setPendingStub({ layer: target, kind: 'scene' });  // ③ 弹「这里是……」（§3.3）
    }
  } catch (err) { showToast(err instanceof Error ? err.message : String(err)); }
};
```

- **顺序不可颠倒**：先 `enterLayer` 再弹问，玩家立刻身处 stub（可走动、可发话，doc-06 §2.4 的留言条），doc-11 §3.4-1「进入瞬间 stub 卡按 material: stub 渲染」成立。
- **`data.first` 严格判 `=== true`**：旧服务端/异常响应可能缺字段，缺字段 = 不触发（**保守**：宁可不初始化，也不误触发）。
- **漏了会怎样**：stub 层进入后**永远不初始化**；`first` 继续作为死字段留在响应体里（`04-验收与回归.md` 的判据 `(b) events 表新增 layer_initialized` 必红）。

### 3.3 「这里是……」需求输入（可留空/跳过 → 默认 brief）

**呈现**（doc-11 §3.2「穿越动画里给一行输入机会」）：本仓库**没有穿越动画组件**（无 `LayerTransition`/`Transition` 模块；全仓只有 Tailwind 的 `transition-*` 工具类，`App.tsx:491,515`）。故：

> **新设计（最小实现）**：不造动画层，落一条**贴画布底部的输入条**，视觉复用既有 `.writer-bar`（`apps/web/src/components/chrome/WriterBar.tsx`）——但它**不是** `WriterBar` 实例：`WriterBar` 的 `onSend` 只接非空文本（`WriterBar.tsx:30` `if (!trimmed || disabled) return;`），而这里**空提交是合法语义**（= 默认 brief）。故新增一个极薄的兄弟组件 `StubPrompt`（NEW）。

```tsx
// NEW —— apps/web/src/components/chrome/StubPrompt.tsx
export interface StubPromptProps {
  kind: 'scene' | 'nook';
  copy: { label: string; placeholder: string; skip: string };
  /** 提交（含空串 = 留空）与跳过走同一出口：'' 表示留空。 */
  onResolve: (request: string) => void;
}
```

- 提交（Enter）与「跳过」都调 `onResolve(text)`，`text` 未 trim 前可为 `''`；**留空与跳过等价**（doc-11 §3.2「可跳过→默认 brief」）。
- Escape 也视同跳过（与 `App.tsx:282-290` 的 Esc→返回上级**冲突**，见 §⑪-9）。
- **MUST NOT 全屏**：不得引入全屏动画/遮罩重绘（`AGENTS.md §7.6` 第 1 条：全屏 canvas 每帧重绘 = 一帧预算的一半）。输入条是普通 DOM，`pointer-events` 只覆盖自身。

**解析后**（App 侧）：


**漏了会怎样**：`request` 恒为 `undefined` → `buildSceneInitBrief` 的 `if (ctx.userPrompt)`（`packages/shared/src/render/brief.ts:44`）恒假 → brief 永不输出 `[Player Request]` 行 → `03` 篇初始化器正文承诺的「玩家诉求」永远是空（doc-11 §2.2 的 brief 协议缺一行）。

### 3.4 发触发：服务端如何「先返回、后异步」（契约 §8.2）

**服务端分支（NEW，`apps/server/src/index.ts`，插在 `:113` 与 `:114` 之间）**：

```ts
} else if (data.type === 'airp_init') {
  const writer = lifecycle.getWriter();
  if (!writer) {
    ws.send(JSON.stringify({ type: 'error', source: 'writer', message: 'Writer agent is not running' }));
    return;
  }
  const kind = data.kind === 'nook' ? 'nook' : 'scene';
  const target = typeof data.target === 'string' ? data.target : '';
  if (target === '') {
    ws.send(JSON.stringify({ type: 'error', source: 'writer', message: 'airp_init: target is required' }));
    return;
  }
  const args = JSON.stringify({
    kind,
    target,
    ...(typeof data.request === 'string' && data.request.trim() !== '' ? { request: data.request } : {}),
    by: 'player',
  });
  // FIRE-AND-FORGET（契约 §8.2）：绝不 await。
  // 理由是硬事实，不是偏好：pi-rp 的 RpcClient.send 对每个请求有 **30s 硬超时**
  // （vendor/pi-rp/packages/coding-agent/dist/modes/rpc/rpc-client.js:671 `}, 30000);`），
  // 而扩展命令的 RPC 应答要等 handler 返回才发出
  // （.../modes/rpc/rpc-mode.js:434-442 的 preflightResult → output(success(id,'prompt'))），
  // handler 内 `ctx.spawnAgent({timeoutMs: 60_000})`（契约 §2.3 第 5 步）会跑满 45–60s。
  // 于是 await 它 = 30s 后必然 reject，且这期间服务端被吊住。
  // 不 await：命令照常跑完、照常经 recordLayer* 落账、照常由尾部读表回流
  // world_event（event-bridge.ts:278-289）——前端拿结果走事件，不靠这条 RPC 应答。
  void writer.prompt(`/airp-init ${args}`).catch((err) => {
    console.warn('[AIRP WS] airp-init RPC response lost (init keeps running):', err);
  });
}
```

**四条设计判据**：

1. **不入 HTTP**。契约 §8 反模式 2 点名「不许在 `/api/enter-layer` 里同步跑初始化」。也不新开 HTTP 端点：那会多一条要冻结的请求体（`tools/check-request-bodies.mjs` 的 `BODIES` 表 `:28-37` 要登记）、多一处「200 到底代表 accepted 还是 done」的歧义；WS 把 accepted 做成隐式的，且与既有 `writer_prompt`（`index.ts:96-113`）同形。
2. **不 await**（上文的 30s 硬事实）。这是本档**最重要的工程约束**，比「要不要 await」的直觉更重要。
3. **`request` 空则整键省略**：命令的 `parseInitArgs` 校验 `request` 存在时必须是 string（契约 §2.3 第 1 步 / `02` 篇 §3.1），传 `undefined` 即「没有这一行」。
4. **`by: 'player'` 恒填**：`by` 只进 `detail.by`，动作层 actor 恒 `engine`（`actions/layer.ts:118-125`，契约 §2.2 末段）。

**漏了会怎样**：
- 不写这个分支 → 前端发 `airp_init` 石沉大海（`index.ts` 的 message 分支无匹配 → 静默丢弃，`:92-209` 无 default 报错）。
- 若改成 `await writer.prompt(...)`（尤其放在 HTTP 里）→ 契约 §8 反模式 2 + §⑪-1 的 30s reject，且请求吊 30–60s。

### 3.5 幻影占位（doc-11 §3.4）

**关键洞察（决定最小实现）**：`GET /api/layer` **今天就已经为 stub 子层合成了一张可渲染的 stub 门卡，并给它落了持久座位**。

| 事实 | 位置 | 后果 |
|---|---|---|
| stub 门卡合成 | `apps/server/src/routes/world.ts:388-401` | 子层无 README → `{ path: '<id>/README.md', filename:'README.md', frontmatter:{type:'readme',stub:true,name:…}, body:'This scene has not been written yet.' }` |
| 合成卡也排座 | `world.ts:410-417` | `unseated` 含该 path → `store.seatUnplaced(layer, unseated)` |

→ **父层页面上的那张虚线 stub 门卡，本身就是「幻影」的父层视图**（`CardRenderer.tsx:140-141` `isStub` + `:174` `gate--stub` + `apps/web/src/index.css:1018` 虚线框）。doc-11 §3.4-1 已经由既有代码满足。

**座位规则（「不重排」的机理性保证）**：幻影是**纯客户端、不持久化**的：它不进 `worldState.items`，不进 `POST /api/card/footprint`，不进 `card_position`。它渲染在 `Canvas` 的 `items.map`（`Canvas.tsx:471-478`）**之外**的独立一层。
- **「不重排」的含义有二**：
  1. 幻影出现**不推开**任何既有卡（它不参与 `relaxAll`/`pushFrom`，`apps/web/src/lib/collide.ts:44,71`——那些只在拖拽路径调用，本档不新增调用点）。
  2. 幻影消失后，真实产物首次落座时，**既有卡一个都不动**；`/layer` 把完整 page items 传给 `seatUnplaced`，store 只过滤无 row files，已存在 rows 作为 occupied（`docs/layout/00 §3.1`）。
- **「座位过户」的视觉实现**：初始化 phantom 不自行写坐标，也不特判旧 anchor；它调用 `phantomSeatFor(size, layer)`，由 shared `flowColumns` 在当前层真实 items + 同层全部 phantom 的 occupied 上计算临时座位。空层首个合法 placement 是冻结 config 的 `origin = {x:360,y:96}`，真实产物落地时仍只过户、不重排。
- 同批产物的顺序由 `/layer` canonical stage-major order 决定（Chalk → 注册 component kind → 其它），不是 README/path 的偶然字典序；真实 `/layer` 返回的坐标优先于任何 phantom 预测。

**「不进 footprint」为何成立（逐层核实，非推断）**：`CanvasObject` 会给每个壳写 `data-path`（`CanvasObject.tsx:125`），而 footprint 的两条读路径都吃这个属性——但**两条都恰好过滤掉幻影**：
1. **ResizeObserver**（`useWorld.ts:278-283`）：`document.querySelectorAll('.object[data-path]')` 会观察到幻影壳 → 触发 `notify()`。**无泄漏**（只是 arm 一次）。
2. **测量**（`lib/footprint.ts:73-85`）：`measureHeights` 会读到幻影的 path。
3. **但 flush 的宽度门**（`lib/footprint.ts:170-174`）：`const w = widths.get(path); if (typeof w !== 'number' || …) continue;` —— `widths` 来自 `stateRef.current.items`（`useWorld.ts:240`），**幻影不在 items 里**，故 `w` 为 undefined → **盒被丢弃**（`continue`）。`boxes.length === 0` 时直接 `return`（`:175`）。
→ **幻影的任何测量都不会落库**。这一条是本档「幻影零持久化」的**机械证明**，也是 `ghost` 用 `CanvasObject` 渲染（而非自造壳）**仍然安全**的理由。

> **但仍建议给幻影壳一个额外保险（`[推断]`）**：让 `ghostItemFor` 产出的 item 的 `w` 与幻影的 `path` **不同域**（上方 `ghostItemFor` 的 `path` 建议 `__ghost__/<layer>`），以免将来有人把 `ghost` 也塞进 `items` 或给 `stateRef` 加默认宽度时，上面这条门被绕过。**待拍板 §⑫-1 附带**。

**漏了会怎样**：doc-11 §3.4-2 落空——玩家进入 stub 层看到一块空白画布与一个输入条，没有任何「正在这里生成」的信号；45–60s 的等待没有任何反馈（doc-11 §6.2「不中断，让它写完」的前提下，玩家会以为卡住了）。

## ⑪ 发现的冲突

> 与冻结契约/并行批次冲突的，**只写不改**（契约 §4 纪律）。

### 冲突 1 — RpcClient 的 30s 硬超时 vs 45–60s 初始化（**契约未覆盖，本档最重要的发现**）

**事实**：`RpcClient.send` 对每个请求设 `setTimeout(…, 30000)`（`vendor/pi-rp/packages/coding-agent/dist/modes/rpc/rpc-client.js:671`），超时即 `reject`。而扩展命令的 RPC 应答要等 handler 返回（`.../modes/rpc/rpc-mode.js:434-442`：`preflightResult((didSucceed)=>{…output(success(id,'prompt'))})` 由 `_tryExecuteExtensionCommand` 完成后回调，`.../core/agent-session.js:1524-1527`）。handler 内 `spawnAgent({timeoutMs: 60_000})`（契约 §2.3 第 5 步）会跑满 45–60s。

**推论**：`await writer.prompt('/airp-init …')` 在 **30s 必然 reject**（不是初始化失败，是 RPC 应答超时），且这期间服务端被吊住。

**契约现状**：契约 §2.1 说「服务端经 `RpcClient.prompt('/airp-init <json>')` 把初始化请求送进 agent 进程」，**未说明是否 await、也未提 30s**。契约 §8 反模式 2 只禁止「在 `/api/enter-layer` 里同步跑」。

**本档做法**：**fire-and-forget**（不 await，`.catch` 记一句 warn）。**报主 agent 裁决**——若要在契约里补一条「R2 的 RPC 必须 fire-and-forget（30s 硬超时）」，落点在契约 §2.3 执行序。

### 冲突 2 — 旧 `lib/seat.ts` 与服务端（已裁决）

旧版 `lib/seat.ts` 的 `seatSpiral`、`SEAT_ANCHOR` 与服务端 `spiralCells` 存在候选数和溢出语义差异；这正是本批要消除的第二套几何，不再通过“空层恰好等价”来规避。初始化 phantom 统一调用 `phantomSeatFor` → shared `flowColumns`，服务端 `seatUnplaced/reseatLayer` 也调用同一纯函数。

`seatPresence` 等非卡片点位若仍保留独立几何，不属于本批自动排版范围；验收只检查卡片/phantom 排座面，不要求全仓删除所有 `spiralCells` 字符串。

### 冲突 4 — `writer` 车道的 error 帧前端**不可见**（`airp_init` 失败会静默）

### ⑫-1 幻影的最小实现路线（**已裁决**）

- 初始化幻影不复用 `lib/seat.ts`，也不直接坐 `SEAT_ANCHOR`；`ghostItemFor` 只构造临时状态，座位统一走 `phantomSeatFor(size, layer)` → shared `flowColumns`。

### ⑫-2 命令「不落账」路径的前端回执（冲突 5）

玩家连点两次门卡 → `enterLayer` 的 `next === layerRef.current` 分支（`useWorld.ts:152-156`）仍会 re-fetch，`data.first` **仍为 true**（README 还没写出来）→ **弹两次 `StubPrompt` / 发两条 `airp_init`**。

**裁决（契约 §2.3.1）**：命令内持**进程内 in-flight `Set`**（键 = `kind + ':' + target`），命中即 `sendMessage('initialization already in flight')` 并 return——这是**并发**的防线（pi-rp 扩展命令在 streaming 中立即执行、`prompt()` 不排队，判空短路只挡顺序进入）。前端触发侧**配合**：`requestInit` 前判 `initializingLayer === target` 则不重复发（本地最小去重），与服务端 in-flight 锁形成两道防线。
