## 2. 关键架构决定（本批的支点）

### 2.1 为什么是「扩展命令」，不是「服务端直接 spawn」

pi-rp 的 subagent 是 **in-process**（同进程、`SessionManager.inMemory`，`vendor/pi-rp/packages/coding-agent/src/core/subagent/run.ts`），**不发新进程、不拼 CLI args**。它的执行器 `spawnAgent(options)` 只存在于 **agent 进程的扩展上下文**（`ExtensionContext.spawnAgent`，`src/core/extensions/types.ts:383`；经 `runner.ts:891` 暴露给 `pi` API）。**服务端 `AgentLifecycleManager` 只有 RpcClient，够不着 `spawnAgent`。**

→ **建一个 `initLaunch`/服务端直 spawn 的方案是错的**（会让子代理脱离世界进程的扩展与技能环境）。正确接缝是 **RPC 的扩展命令**：

> pi-rp RPC 文档逐字：*"Extension commands: If the message is an extension command (e.g., `/mycommand`), it executes immediately even during streaming. Extension commands manage their own LLM interaction via `pi.sendMessage()`."*（`docs/rpc.md:41` 段）

所以：**服务端经 `RpcClient.prompt('/airp-init <json>')` 把初始化请求送进 agent 进程，命令 handler 在进程内用 `ctx.spawnAgent` 执行。** 这条路径天然复用 `--extension`（`extensions/tools.ts` 已加载）与 `--skill`，与 R1 的环境**逐字一致**（doc-11 §2.4 要求的「两入口工具集一致」由此自动成立）。

### 2.2 冻结：初始化命令 `airp-init`

| 项 | 冻结值 |
|---|---|
| 命令名 | **`airp-init`**（注册为 `pi.registerCommand('airp-init', …)`，调用为 `/airp-init`） |
| 注册位置 | `extensions/toolkit/init-command.ts`（NEW）；由 `extensions/tools.ts` 的 `initialize` 里 `pi.registerCommand` 注册（与 `registerTool` 同一入口文件） |
| 参数 | 单个位置参数 `args: string`，内容是一段 JSON |
| 参数形状 | `{ kind: 'scene' \| 'nook', target: string, request?: string, by: 'player' \| 'engine' }` |
| 返回值 | handler `await` 完成后，命令结果经 `pi.sendMessage` 回一条**人话**给会话（不影响玩家 UI，仅供作家/日志感知） |
| 谁调用 | 服务端（R2）；R1 不用命令（作家直接用 `subagent` 工具） |

**`target` 口径（冻结）**：
- `kind: 'scene'` → `target` = **层 id**（如 `baker-street/crime-scene`）或世界根相对目录（`world/baker-street/crime-scene`）；命令内部用 `dirOfLayer` / `layerOfDir` 归一（**不得**另写一份 map↔world 映射）。
- `kind: 'nook'` → `target` = **角色 id**（如 `watson`）；命令内部经 `nookIdOf(id)` 得 `characters/watson`（**唯一** `nookIdOf`）。

**`by` 决定事件 actor 与文件归属语义**：`'player'`（玩家直唤）/ `'engine'`（引擎）。注意 `recordLayerInitialized` 的动作层**恒写 actor = `engine`**（`actions/layer.ts:120`）——`by` 只进 `detail.by`，不改 actor。这是既有裁决，本批遵守。

### 2.3 冻结：`airp-init` 的执行序（唯一内核，R1 不经过它但共享同一 preset）

```
1. 解析 args → 校验 kind/target（非法 → sendMessage 报错，不落事件）
2. 判空短路：isLayerEmpty / isNookEmpty（见 §3.1）→ 已有内容则不初始化，直接返回
3. 解析上下文：manifest（store.getManifest）+ parentLayer + knownClues（本批可为空数组，登记）
4. 拼 brief：
   - scene → buildSceneInitBrief({ targetPath, manifest, parentLayerName, parentLayerId, parentLayerPath, userPrompt: request })
   - nook  → buildNookInitBrief(characterName, roleDesc, manifest, { missingFiles })
5. ctx.spawnAgent({ profileId: 'scene-init' | 'nook-init', task: brief, customTools: AIRP_TOOLS.map(t=>t.tool), timeoutMs })
6. 结果分流：
   - status === 'completed' → 校验产物非空（见 §3.2）→ recordLayerInitialized({ layer, by, files })
   - status !== 'completed' → W2 兜底落盘（见 §3.3）→ recordLayerInitFailed({ layer, reason, fallback:'template' })
7. sendMessage 三行摘要（复用初始化器的 [Report] 三行；失败时说明降级）
```

**超时（冻结）**：场景 `60000ms`、小天地 `45000ms`（doc-11 §6.2）。**从命令参数读，不从常量读死**——`spawnAgent` 的 `timeoutMs` 即 pi-rp 的 `timed-out` 机制（`SpawnAgentResult.status: 'timed-out'`，`subagent/spawn.ts` `SpawnAgentResult`）。本批作为命令内部默认值，登记为「配置项待外提」。

### 2.4 R1 / R2 / W2 的关系（冻结）

| 路径 | 触发 | 执行体 | 本批做什么 |
|---|---|---|---|
| **R1 委托** | 作家 `subagent` 工具 | pi-rp 的 subagent | **只需**把两个 init preset `installPreset` 进世界（让 `subagent_profiles` 看得到）。作家提示词已指路（`extensions/instructions.ts:144`）。 |
| **R2 直唤** | 服务端 → `/airp-init` | 本批的 `airp-init` 命令 | 本批主体。 |
| **W2 兜底** | 引擎，零 AI | 纯常量写盘 | 本批实现（§3.3）。 |

**R1 与 R2 共用 preset**（doc-11 §2.1 的支点）：preset 静态、brief 动态。R1 的 brief 由作家在 `task` 里写，**不经过 `build*Brief`**——作家不是代码，它读的是 `03` 篇正文。故 `build*Brief` 只服务 R2/W2；R1 靠 preset 正文 + 作家提示词的委托纪律。（这一点**必须**在两篇文档里一致陈述，否则会出现「R1 也应该调 buildSceneInitBrief」的错误实现。）

## 3. 冻结：三个纯函数 + 一个常量

### 3.1 空判定（纯函数，`packages/shared/src/rules/emptiness.ts`，NEW）

> **与 `docs/nook/00` 的边界**：`isNookEmpty` / `isLayerEmpty` 归本批（doc-11 §9.1 第 3 项）；`nook/00` 的 `04` 篇只**引用**，不实现。

```ts
/** doc-11 §3.1: 层是 stub ⟺ 目录里没有 README.md。吃 worldRoot 相对文件清单，不碰 store（可单测）。 */
export function isLayerEmpty(files: readonly string[], dir: string): boolean;

/** doc-11 §4.1: 小天地为空 ⟺ 除 preset.json / *.json 外无任何 md/文件（直接子级）。 */
export function isNookEmpty(files: readonly string[], dir: string): boolean;
```

**判据口径（冻结，勿混）**：
- `isLayerEmpty`：`dir` 的**直接子级**里没有 `README.md`（大小写敏感，逐字 `README.md`）。doc-11 §3.1 明确「判据是目录有没有 README.md」。
- `isNookEmpty`：`dir` 的**直接子级**中，除 `preset.json` 与任意 `*.json` 外，没有任何文件 → 空。**必须只看直接子级**（`characters/<id>/sub/file.md` 不算填满父目录）；但 doc-11 §4.1 的产出（README.md + identity.md + 内容文件）本就落在直接子级，故直接子级判定与产出规范自洽。
- 「取直接子级」需要一个 `dirOf`：`packages/shared/src/store/layers.ts:42` 的 `dirOf` **是私有未导出**。**本批 MUST 导出一个共用的路径工具**（见 §3.4），**禁止**在 emptiness.ts 里重写第三份。

> **`files` 的语义**：调用方传 `store.listFiles(dir)` 的结果。已知三条语义（`local-store.ts:210-233`）：**跳过 dotfile 与 `node_modules`**、返回**相 worldRoot 相对**路径、**不返回目录本身**。因此「直接子级」= `files` 里去掉 `dir + '/'` 前缀后**不含 `/`** 的项。

### 3.2 产物非空校验（纯函数，同文件）

`status === 'completed'` **不等于**产物合格（模型可能什么都没写）。故：

```ts
/** 初始化产物是否已落盘：dir 直接子级存在 README.md（场景）或存在任一非 json 内容文件（小天地）。 */
export function hasInitProduct(files: readonly string[], dir: string, kind: 'scene' | 'nook'): boolean;
```

- `scene`：直接子级存在 `README.md` → 合格（doc-11 §3.3 要求 README 覆盖 stub 占位）。
- `nook`：直接子级存在任一非 `*.json` 文件 → 合格（`README.md` / `identity.md` / 内容文件都算）。
- **不合格视同 `failed`**，走 W2（§2.3 第 6 步）。理由：doc-11 §3.1「目录里已有 README.md 就不再初始化」——若 README 没写成，层仍是 stub，下次进入会再触发，形成死循环；必须兜底落一个。

### 3.3 W2 兜底常量（纯常量，`packages/shared/src/rules/init-fallback.ts`，NEW）

doc-11 §5 的模板，逐字：

```ts
/** doc-11 §5：零 AI 兜底。占位 README + 空 chalk。 */
export function w2SceneTemplate(dirName: string): { readme: string; chalk: string };
```

- `readme` = `---\ntype: readme\nname: <dirName>\nmaterial: stub\n---\n\n# <dirName>\n\n(This place has not taken shape yet.)`
- `chalk` = `---\ntype: chalk\n---\n\n(You stand here. Nothing is clear yet.)`
- **文件名（冻结）**：`README.md` 与 `opening.md`（chalk 落 `opening.md`，与 `03` 篇正文一致；**不得**用 `evening.md`——那是 holmes 世界的手写内容）。
- **`material: stub` 是合法的**（`MATERIAL_SKINS` 含 `stub`，`schemas/forms.ts:193-198`）——这是 W2 占位的**正解**（"这里还没长出来"的皮肤），与 doc-11 §3.3 那句「README 的 material 取 brief 给的默认材质」**不冲突**：§3.3 说的是**初始化器成功产出**的 README 用世界默认材质，W2 兜底用 `stub`。

### 3.4 路径工具（导出，冻结）

`layers.ts` 的 `dirOf` **私有**（`layers.ts:42`），而本批的 `emptiness.ts`、`routes` 的校验都要用「取直接父目录 / 取相某前缀的直接子级」。**冻结**：在 `packages/shared/src/store/layers.ts` **导出**：

```ts
/** 'a/b/c.md' → 'a/b'; 'a' → ''; 无 '/' → ''。逐字移植现有私有实现，勿另写。 */
export function dirOf(p: string): string;
```

**MUST NOT** 在别处重写第四份（现有重复：`layers.ts:42` 私有 + `actions/layer.ts:23` 的 `layerIdOf` 是同类映射）——本批只**导出现有的那一份**。

### 3.5 角色 id 校验（`packages/shared/src/rules/characters.ts`，NEW）

> **`docs/nook/00 §5.2` 冻结的唯一实现处**（N1 批三处调用它）。本批提供，落地后广播。

```ts
/** ^[a-z0-9][a-z0-9-]*$ */
export function isValidCharacterId(id: string): boolean;
/** 合法 → `characters/${id}`，否则 null。 */
export function nookIdOf(id: string): string | null;
/** `characters/<id>/…` → id；不匹配或 id 非法 → null。 */
export function characterIdOfPath(path: string): string | null;
/** docs/nook/01 §2.4：小天地页面成员 = 直接子级 .md − README.md。 */

```

- `characterIdOfPath` 的匹配是 `path === 'characters/<id>'` 或 `path.startsWith('characters/<id>/')`，其中 `<id>` 必须**不含 `/`**（正则天然挡住穿越），且 `isValidCharacterId(id)` 为真。它回答「归属哪个角色」，**不**回答「是不是直接子级」——`characters/ryo/letters/unsent.md` 仍属 `ryo`（docs/nook/01 §2.2）。

- **`index.ts` 必须手工补三行导出**（`'./rules/characters.js'` / `'./rules/emptiness.js'` / `'./rules/init-fallback.js'`）——`packages/shared/src/index.ts` **无 glob**，漏行即「静默不可达」（`index.ts:44-46` 注释逐字警告）。

## 5. 冻结：世界侧 preset 安装（R1 的前提）

**`installPreset` 只有两个调用点**（`launch.ts:106` writer、`launch.ts:149` character）。本批**新增**把两个 init preset 装进世界的调用点。

**冻结落点**：在 `writerLaunch`（`launch.ts:105`）里、`installPreset(writer)` 之后**追加两行**：

```ts
installPreset(worldRoot, path.join(repoRoot, 'presets', 'scene-init.json'));
installPreset(worldRoot, path.join(repoRoot, 'presets', 'nook-init.json'));
```

理由：init profile 是**作家进程**里 `subagent_profiles` 枚举的对象（`getDelegatablePresets` 读当前 session 的 config dir），而作家进程 `PI_PROJECT_CONFIG_DIR=.airpworld` 指向的就是 `<worldRoot>/.airpworld/prompt-presets/`。装一次即可，角色进程不需要（角色**永不**初始化，doc-11 §1.3）。
