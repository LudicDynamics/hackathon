## 2. 关键架构决定（本批的支点）

### 2.1 为什么是「扩展命令」，不是「服务端直接 spawn」

pi-rp 的 subagent 是 **in-process**（同进程、`SessionManager.inMemory`，`vendor/pi-rp/packages/coding-agent/src/core/subagent/run.ts`），**不发新进程、不拼 CLI args**。它的执行器 `spawnAgent(options)` 只存在于 **agent 进程的扩展上下文**（`ExtensionContext.spawnAgent`，`src/core/extensions/types.ts:383`；经 `runner.ts:891` 暴露给 `pi` API）。**服务端 `AgentLifecycleManager` 只有 RpcClient，够不着 `spawnAgent`。**

→ **建一个 `initLaunch`/服务端直 spawn 的方案是错的**（会让子代理脱离世界进程的扩展与技能环境）。正确接缝是 **RPC 的扩展命令**：

> pi-rp RPC 文档逐字：*"Extension commands: If the message is an extension command (e.g., `/mycommand`), it executes immediately even during streaming. Extension commands manage their own LLM interaction via `pi.sendMessage()`."*（`docs/rpc.md:41` 段）

所以：**服务端经 `RpcClient.prompt('/airp-init <json>')` 把初始化请求送进 agent 进程，命令 handler 在进程内用 `ctx.spawnAgent` 执行。** 这条路径天然复用 `--extension`（`extensions/tools.ts` 已加载）与 `--skill`，与 R1 的环境**逐字一致**（doc-11 §2.4 要求的「两入口工具集一致」由此自动成立）。

### 2.2 冻结：初始化命令 `airp-init`

| 项 | 冻结值 |
|---|---|
| 命令名 | **`airp-init`**（注册为 `pi.registerCommand('airp-init', …)`，调用为 `/airp-init`） |
| 注册位置 | `extensions/toolkit/init-command.ts`（NEW）；由 `extensions/tools.ts` 的 `initialize` 里 `pi.registerCommand` 注册（与 `registerTool` 同一入口文件） |
| 参数 | 单个位置参数 `args: string`，内容是一段 JSON |
| 参数形状 | `{ kind: 'scene' \| 'nook', target: string, request?: string, by: 'player' \| 'engine', template?: boolean }` |
| 返回值 | handler `await` 完成后，命令结果经 `pi.sendMessage` 回一条**人话**给会话（不影响玩家 UI，仅供作家/日志感知） |
| 谁调用 | 服务端（R2）；R1 不用命令（作家直接用 `subagent` 工具） |

**`target` 口径（冻结）**：
- `kind: 'scene'` → `target` = **层 id，带 `world/` 前缀**（如 `world/baker-street/crime-scene`；根层 id 是 `map` 而非 `world`）。**这是 `/api/enter-layer` 实际收到的形状**（`routes/world.ts:738` 直接 `${layer}/README.md`，`CardRenderer.tsx:165` 的 `layerOfDir` 同源）。命令内部用 `dirOfLayer(id)` 得目录、`layerOfDir(dir)` 回 id（**不得**另写一份 map↔world 映射）。**MUST NOT** 用无前缀的 `baker-street/crime-scene` 当层 id——它会被当成字面目录名而产生 `baker-street/crime-scene/README.md`（不存在），归一分支静默错过。
- `kind: 'nook'` → `target` = **角色 id**（如 `watson`，不含 `characters/` 前缀）；命令内部经 `nookIdOf(id)` 得 `characters/watson`（**唯一** `nookIdOf`）。

**`by` 决定事件 actor 与文件归属语义**：`'player'`（玩家直唤）/ `'engine'`（引擎）。注意 `recordLayerInitialized` 的动作层**恒写 actor = `engine`**（`actions/layer.ts:120`）——`by` 只进 `detail.by`，不改 actor。这是既有裁决，本批遵守。

### 2.3 冻结：`airp-init` 的执行序（唯一内核，R1 不经过它但共享同一 preset）

```
1. 解析 args → 校验 kind/target（非法 → sendMessage 报错，不落事件）
2. 判空短路：isLayerEmpty / isNookEmpty（见 §3.1）→ 已有内容则不初始化，直接返回
   - **顺序路径的幂等**由此成立；但**并发双击**不由此挡住（见 §2.3.1），需叠加在飞锁。
3. 解析上下文：manifest（store.getManifest）+ parentLayer + knownClues（本批可为空数组，登记）
4. 拼 brief：
   - scene → buildSceneInitBrief({ layerId: layer, targetPath: dir, manifest, parentLayerName, parentLayerPath, userPrompt: request })
   - nook  → buildNookInitBrief({ characterId: target, displayName, roleDesc, home, role, manifest, missingFiles })
5. ctx.spawnAgent({ profileId: 'scene-init' | 'nook-init', task: brief, customTools: AIRP_TOOLS.map(t=>t.tool), timeoutMs })
6. 结果分流：
   - status === 'completed' 且 hasInitProduct（§3.2）→ recordLayerInitialized({ layer, by, files })
   - 否则（failed/cancelled/timed-out，或 completed 但产物为空）→ scene 走 W2 兜底落盘（§3.3）/ nook 不落盘（§4.3）→ recordLayerInitFailed({ layer, reason, fallback })
7. sendMessage 三行摘要（复用初始化器的 [Report] 三行；失败时说明降级）
```

**超时（冻结）**：场景 `60000ms`、小天地 `45000ms`（doc-11 §6.2）。作为命令内常量，登记「配置项待外提」。`spawnAgent` 的 `timeoutMs` 即 pi-rp 的 `timed-out` 机制（`SpawnAgentResult.status`）。

> **RPC 超时陷阱（已在上游修根因，2026-09-13）**：原先服务端 `RpcClient` 的 send 超时约 30s，而扩展命令的 ack 要等 handler 跑完（45–60s）才发——**命令还在跑，服务端已经判超时**，成功被误报为失败。I1 落地时以「fire-and-forget + 事件回报」绕开（见 `03` 篇），**这个选择不变**（请求本就不该阻塞在一段 45–60s 的生成上）。根因已在 pi-rp 修掉：`prompt()` 现在**识别到命令即回 ack**，不再等 handler（`vendor/pi-rp` 提交 `fix(rpc): ack extension commands on recognition`，`docs/rpc.md` 的 Prompting 段已同步）。因此「ack 超时」不再是这条路径的风险；但 `success:true` 的语义是**「命令已被受理」而非「命令已完成」**——`nook-init` 及任何后续扩展命令仍 MUST 走事件回报，**MUST NOT** 把 ack 当完成信号。

#### 2.3.1 并发防线（裁决，语义评审 M2）

pi-rp 的扩展命令**在 streaming 中也会立即执行**，且两次 `prompt()` 之间**没有串行化锁**（`agent-session.ts:1991-1996` 起 `_tryExecuteExtensionCommand` 直接 `await command.handler(...)`，`prompt()` 不排队）。因此「判空短路」只挡**顺序**的二次进入，**挡不住并发**：玩家双击 stub 卡 → 两条 `/airp-init` 同时在飞 → 两条都过判空 → 各自 `spawnAgent` → 两套陈设。

**冻结修法**：命令内持一个**进程内 in-flight 集合**（`Set<string>`，键 = `kind + ':' + target`）。命中则 `sendMessage('initialization already in flight')` 并 return。扩展进程是单例，模块级 `Set` 足够，不需要跨进程锁。**这条是幂等性的第二道防线**；第一道仍是判空短路。**MUST NOT** 依赖「命令会自动排队」——实测不会。

#### 2.3.2 上帝模式「建目录」= 零 AI 路径（裁决，语义评审 M3）

`doc-11 §5` 第三行明确：**「上帝模式新建空目录（玩家没写诉求）→ 直接落最小模板，不惊动 AI」**。**保留这条零 AI 路径**：`airp_init` 带 `template: true`（或 `request` 为空且 `by` 非 `player`）时，**不 `spawnAgent`**，直接 `w2SceneTemplate(dirName)` 写盘 + `recordLayerInitialized({ by: 'engine' })`。理由：上帝模式建目录是**地图编辑**语义（先占个位，内容后补），起一次 45–60s 的 AI 生成既慢又可能不合玩家的空白意图。

> **`by` 值域修正（重要，勿照抄前稿的 `'god'`）**：事件的 `layer_initialized.by` 是**封闭枚举** `z.enum(['writer','player','engine'])`（`schemas/events.ts:99`，且 `：109` 有 `satisfies` 穷尽约束），**不能加 `'god'`**。所以：
> - 命令参数里的 `by` **直接取该枚举**：玩家双击 stub → `'player'`；引擎/其它 → `'engine'`。**无 `'god'`**。
> - 「是否走零 AI 模板」由**独立布尔参数 `template`** 表达，**不进事件**（事件只记「谁触发的」，不记「怎么产出的」）。
> - 上帝模式建目录 → `{ kind:'scene', target, by:'engine', template:true }`。
>
> **无需独立 mkdir 能力**：`LocalWorldStore.writeFile` 自带 `mkdir -p`（`local-store.ts:165`），写 `README.md` 即建目录。
> **待 `03` 篇落实**：上帝模式的建目录入口今天直接写 README（`App.tsx:398-400`），与 stub 判据互斥（03 §⑪-8）；本裁决要求它改走 `airp_init`（`template:true`）或至少不加 README。

## 3. 冻结：三个纯函数 + 一个常量

### 3.1 空判定（纯函数，`packages/shared/src/rules/emptiness.ts`，NEW）

> **与 `docs/nook/00` 的边界**：`isNookEmpty` / `isLayerEmpty` 归本批（doc-11 §9.1 第 3 项）；`nook/00` 的 `04` 篇只**引用**，不实现。

```ts
/** doc-11 §3.1: 层是 stub ⟺ 目录里没有 README.md。吃 worldRoot 相对文件清单，不碰 store（可单测）。 */
export function isLayerEmpty(files: readonly string[], dir: string): boolean;

/** doc-11 §4.1: 小天地为空 ⟺ 除 preset.json / *.json 外无任何 md/文件（直接子级）。 */
export function isNookEmpty(files: readonly string[], dir: string): boolean;
```

**判据口径（冻结，勿混）**：
- `isLayerEmpty`：`dir` 的**直接子级**里没有 `README.md`（大小写敏感，逐字 `README.md`）。doc-11 §3.1 明确「判据是目录有没有 README.md」。
- `isNookEmpty`：`dir` 的**直接子级**中，除 `preset.json` 与任意 `*.json` 外，没有任何文件 → 空。**必须只看直接子级**（`characters/<id>/sub/file.md` 不算填满父目录）；但 doc-11 §4.1 的产出（README.md + identity.md + 内容文件）本就落在直接子级，故直接子级判定与产出规范自洽。
- 「取直接子级」需要一个 `dirOf`：`packages/shared/src/store/layers.ts:42` 的 `dirOf` **是私有未导出**。**本批 MUST 导出一个共用的路径工具**（见 §3.4），**禁止**在 emptiness.ts 里重写第三份。

> **`files` 的语义**：调用方传 `store.listFiles(dir)` 的结果。已知三条语义（`local-store.ts:210-233`）：**跳过 dotfile 与 `node_modules`**、返回**相 worldRoot 相对**路径、**不返回目录本身**。因此「直接子级」= `files` 里去掉 `dir + '/'` 前缀后**不含 `/`** 的项。

### 3.2 产物非空校验（纯函数，同文件）

`status === 'completed'` **不等于**产物合格（模型可能什么都没写）。故：

```ts
/** 初始化产物是否已落盘：dir 直接子级存在 README.md（场景）或存在任一非 json 内容文件（小天地）。 */
export function hasInitProduct(files: readonly string[], dir: string, kind: 'scene' | 'nook'): boolean;
```

- `scene`：直接子级存在 `README.md` → 合格（doc-11 §3.3 要求 README 覆盖 stub 占位）。
- `nook`：直接子级存在任一非 `*.json` 文件 → 合格（`README.md` / `identity.md` / 内容文件都算）。
- **不合格视同 `failed`**，走 W2（§2.3 第 6 步）。理由：doc-11 §3.1「目录里已有 README.md 就不再初始化」——若 README 没写成，层仍是 stub，下次进入会再触发，形成死循环；必须兜底落一个。

### 3.3 W2 兜底常量（纯常量，`packages/shared/src/rules/init-fallback.ts`，NEW）

doc-11 §5 的模板，逐字：

```ts
/** doc-11 §5：零 AI 兜底。文件名即键——写入侧零映射。 */
export interface W2SceneFiles { 'README.md': string; 'opening.md': string }
export function w2SceneTemplate(dirName: string): W2SceneFiles;
```

- `'README.md'` = `---\ntype: readme\nname: <dirName>\nmaterial: stub\n---\n\n# <dirName>\n\n(This place has not taken shape yet.)`
- `'opening.md'` = `---\ntype: chalk\n---\n\n(You stand here. Nothing is clear yet.)`
- **返回形状（冻结，已按实现）**：`{ 'README.md', 'opening.md' }` —— 以**文件名**为键，写入侧 `for (const [name, body] of Object.entries(files)) write(...)` 直接用，不必维护第二张「字段名→文件名」映射。`01` 篇初稿写的 `{readme, chalk}` 作废（多一次映射、更容易漂）。
- **文件名（冻结）**：`README.md` 与 `opening.md`（chalk 落 `opening.md`，与 `03` 篇正文一致；**不得**用 `evening.md`——那是 holmes 世界的手写内容）。
- **正文语言（冻结为英文）**：按 `AGENTS.md §1.1`「世界素材 → 英文」。**`doc-11 §5` 那两行中文是文档语言，不是产品文案**——已列入 `04` 篇的 doc-11 回写清单。已知粗糙边缘：`firstsnow`（日文世界）的 W2 占位会是英文；W2 是罕见失败路径，不为它引入 locale 机制（过度设计），登记待拍板。
- **`material: stub` 是合法的**（`MATERIAL_SKINS` 含 `stub`，`schemas/forms.ts:193-198`）——这是 W2 占位的**正解**（"这里还没长出来"的皮肤），与 doc-11 §3.3 那句「README 的 material 取 brief 给的默认材质」**不冲突**：§3.3 说的是**初始化器成功产出**的 README 用世界默认材质，W2 兜底用 `stub`。

### 3.5 角色 id 校验（`packages/shared/src/rules/characters.ts`，NEW）

> **`docs/nook/00 §5.2` 冻结的唯一实现处**（N1 批三处调用它）。本批提供，落地后广播。

```ts
/** ^[a-z0-9][a-z0-9-]*$ */
export function isValidCharacterId(id: string): boolean;
/** 合法 → `characters/${id}`，否则 null。 */
export function nookIdOf(id: string): string | null;
/** `characters/<id>/…` → id；不匹配或 id 非法 → null。 */
export function characterIdOfPath(path: string): string | null;
/** docs/nook/01 §2.4：小天地页面成员 = 直接子级 .md − README.md。 */

```

## 4. 冻结：brief 的字段与来源

**落点（裁决，2026-09-13）**：`buildSceneInitBrief` / `buildNookInitBrief` **从 `apps/server/src/engine/brief-builder.ts` 下沉到 `packages/shared/src/render/brief.ts`**（NEW；原文件删除——零调用点，不留 shim）。理由（02 §⑪-6）：`airp-init` 命令在 `extensions/`（jiti 直跑），现存纪律是**只 import `packages/shared/dist`**；若不改落点，命令要么跨包 import `apps/server/src/**`（全新方向、与既有纪律相反），要么在命令里内联一份 brief 模板（两个入口必然分叉）。下沉后命令与 server 同源 import，与本批 `rules/*` 同一模式。`render/` 是既有「把结构化数据渲染成文本」归属地（`state.ts` 注入块装配同族）；brief 正是「给初始化器的任务书文本」。

### 4.2 `buildNookInitBrief`（`render/brief.ts`）—— 签名拆分（裁决，02 §⑪-7）

```
