### 2.3 层语法：choice 只有两个合法落点（**本批最易写错**，见 §11 冲突 C4）

**层的自身 README 不是画布实体。** 它由 `/api/layer` 作为 `scene` 单独返回、**从 `items` 里剔除**（`apps/server/src/routes/world.ts:955-959`、`:867`；`packages/shared/src/store/layers.ts:98-114` 的 `cardsOfLayer` 注释原文「MINUS its own README」），前端 `App.tsx:778` 的 `canvasItems` 也过滤掉它；它的 `body` 只在左侧 journal 渲染（`App.tsx:1178`），**widget 一个都不渲染**。

| 落点 | 谁渲染 | 语义 |
|---|---|---|
| **门卡** | `EntityInteractions.tsx:302` 对 gate 卡同样调 `renderFrontmatterWidgets` | 层 L 的 README 是**父层页面**上的一扇门；选项只在玩家站在父层、hover 门卡时可点 |
| **场内实体** | `CanvasObject.tsx:373` 挂 `EntityInteractions`；`:207` 的 `readable` 让 note/component 点开即读 | 写在 `world/<layer>/*.md` 的 chalk/note/component 上，**进门后看得见** |

**设计规则（本文件全程遵守）**：
1. 层 README **只写「这是哪、门卡上给人看什么」+ 出口类选项**（Main 2026-09-15 实测口径：「回园区」「退回电梯厅」这类属于门卡自我介绍，允许留 README）；
2. **「在此处做什么」类选项 MUST NOT 只留在 README 上**——必须有场内实体承接；
3. 每个新场景自检：**玩家走进来之后，眼前有什么可点的？** 答案为空 = 设计未完成。

### 3.6 明月的出场设计（第一句台词）

**第一句要同时立住三件事**：**她是行政**、**她记人**、**她爱讲故事**。

> **【台词·写进 `09-03-first-day.md` 正文】**
>
> 「你是新来的吧。支持组，周——」她低头看了一眼手里那本摊开的硬皮笔记，指尖在某一页上压住，「……不用说了，你名字我昨天就抄在本子上了。」
>
> 「走，我带你把手续办了。这个楼里认路不难，认人难。」
>
> 她合上本子，封面什么都没写。

**为什么这样写**：`我昨天就抄在本子上了` 一句完成三件事——**行政**（她提前拿到名册）、**记人**（抄的是人名不是工号）、**叙事自觉**（把「记住一个人」当成值得写下来的事）。且**不点破任何东西**：她不知道埃利亚斯为什么收白兰花。

**必须避免**：不得说「这是游戏 / 帮你通关 / 你可以选 A 或 B」。可说的是 00 §3.2 允许的叙事自觉（「这段我记下了」「你俩刚才那段对话，比我在追的连载好看」），不是攻略。

### 12.1 `autoWrite` 的确定口径（2026-09-15 主 agent 裁决，**本批设计的硬前提**）

**对 04 设计的四条直接约束**（已体现在 §3–§4）：

1. **声明动作不起作家轮** —— 本批所有「看笔记 / 看台账 / 回走廊 / 找明月」都是 `read`/`enter`/`character`，**都不会额外烧一轮作家**。这是本批设计上的便宜，不是遗漏。

4. **本批不写 `.airpworld/settings.json`** —— fpal 走 schema 默认即可，无需在模板里加字段（模板本来也不该加）。
