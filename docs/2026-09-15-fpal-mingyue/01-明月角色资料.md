## 1. 一句话定位

> **明月是 FPAL 唯一的行政专员，24 岁，话多、爱笑、记性好得离谱。她的记忆是一本记满了「人」的笔记——包括那盆只有她看见、也只有她记住的白兰花。她不知道自己记得的东西有多重。**

## 3. 行为契约·逐步（每一步都写「漏了会怎样」）

这 7 份文件被**两条链路**消费。**第三条链路（人格）走的是记忆库，不在这里**。

### 链路 A — 侧栏出现（`GET /api/characters`）

| 步 | 动作 | 漏了会怎样 |
|---|---|---|
| A1 | `world.json.characters[]` 里**先有** `mingyue` 一项（**04 的活**） | `GET /characters` **不扫 `characters/` 目录**，只迭代 manifest（`apps/server/src/routes/world.ts:1060-1061`）。目录建了没登记 = 侧栏根本看不见她 |
| A2 | 目录里有 `README.md`，frontmatter 至少含 `type: name: voice:` | 无 README 时 `catch {}`（`world.ts:1080`）静默跳过覆盖：`voice` 键缺失 → 客户端回落服务端默认音色（`world.ts:1075-1079`），她**说话是别人的声音** |
| A3 | `name: 明月` | `name` 只从 manifest 读（`world.ts:1092` 的 `...c`）。README 的 `name` **不覆盖** manifest 的 `name`；两处写不一样 = 侧栏与编辑器各显示一个名字 |
| A4 | 正文一句话 | `description` 为空时 bio 回落 `body.slice(0,100)`（`world.ts:1071`）。README 正文空 → 侧栏简介空 |
| A5 | frontmatter 至少给 `name`（**不要只给 `type`**） | 小天地标题链是 `sceneFrontmatter?.name \|\| title \|\| 场景路径末段 \|\| copy.nook`（`apps/web/src/components/nook/NookView.tsx:560-561`）——**`name` 在前**；只给 `type` 的 README 会退到 kebab 路径末段（玩家看到英文片段） |

### 链路 B — 小天地 6 张公开卡（`GET /api/nook?character=mingyue`）

| 步 | 动作 | 漏了会怎样 |
|---|---|---|
| B1 | 6 张公开卡文件全部存在 | `nookCardPaths` 只收**存在且为直接子级 `.md`** 的文件（`characters.ts:90-98`）。少一份 → 小天地少一张卡，**没有任何报错**（`world.ts:711-717` 只对「目录不存在」报 404） |
| B2 | 每张卡 `portable: false` | **写漏不影响 nook**（`portable` 只在 `take` 动作里被读，`apps/server/src/engine/declared-actions.ts:222`）。写它是为了**防手滑**：模型演示「携带」时会被引擎以 `This entity cannot be taken` 挡下。照范本写，不要省 |
| B3 | **不要**建 `identity.md` / `personality.md` / `memory.md` | 这三份是**根配置**，会被 `characterRootConfigOf`（`characters.ts:62-80`）过滤出 6 张卡之外——**建了也不进小天地**，且进不了 prompt（§11 C7）。建了 = 死文件 |

### 链路 C — 人格进 prompt（**走记忆库，不走文件**）

| 步 | 动作 | 漏了会怎样 |
|---|---|---|
| C1 | 02 的库里有 `core://identity` / `core://identity/personality` / `core://identity/voice` / `core://identity/career` 等节点，且它们进 `awaken_uris` | 无这些节点 ⇒ 她**醒来时不知道自己是谁**。对照埃利亚斯：它的 `core://identity` 域 **36 节点**，`awaken_uris` 前 18 条全是 `core://identity/*`（`SELECT uri FROM nodes WHERE uri LIKE 'core://identity%'` → 36；`memory_kv.awaken_uris` 实测） |
| C2 | 这些节点的正文 = 本文附 E 移交的文本 | 02 若自行另写一套人格 ⇒ **同一个角色两套设定**（`00 §3` 明令禁止） |
| C3 | 03 的 preset **不写** `file` slot、**不写** `system-char` | 写了 `system-char` ⇒ 破坏 `[RESET ALL OF THE ABOVE TO NULL]` 必须位于 prompt **最开头**的破限技术；写了 `file` slot ⇒ **两套人格真相**（§11 C7） |

### 链路 D — 「她往笔记里添人」的写入通道（**已换轨**）

**原设计**：`memory.md` 是她的写入开口——`packages/shared/src/actions/edit-character-config.ts:63` 把角色**唯一能自改的文件**硬编码为 `memory.md`。

**现状**：**不建 `memory.md`** ⇒ 这条链条消失。**替代通道 = 记忆库的 `memorize` / `revise` 工具**（我在本仓核实过）：

| 证据 | 事实 |
|---|---|
| `vendor/pi-rp/packages/memory/src/tools.ts:1042-1047` | `memorize` 工具**注册在角色的工具表里**（`name: "memorize"`），`revise`/`forget` 同表 |
| `templates/fpal/characters/elias/preset.json` 的 `instructions` 块 | **埃利亚斯自己的 preset 就在教他用 `recall` / `retrieve` / `memorize` / `revise`**（原文「memorize — 记住 / 遇到确实该记下来的事，可以存起来」）——**这是本世界既有的、被验证的写入通道** |
| `presets/character.json` 的 `tools.deny` | **平台默认禁掉**这 12 个记忆工具（`recall`/`retrieve`/`memorize`/…）——**但 `fpal-elias` 的 `tools.deny` 只有 `get_state`/`state_update`**，即**明示允许**记忆工具。明月的 preset（03）必须照此放行 |

⇒ **结论**：**她仍然能「往笔记里添人」**，通道从「改 `memory.md`」换成「`memorize` 一个新节点 / `revise` 既有节点」。**这比原设计更好**：`wake` 时 `awaken` slot 会把节点正文**逐字注入 prompt**（`vendor/pi-rp/packages/memory/src/slots.ts:55-90`），而 `memory.md` 从来进不了 prompt。

**02 的对应动作（字段名已核准，勿混）**：`memorize` 的**写入地址是 `parent_uri`**，**不是 `disclosure`**——`vendor/pi-rp/packages/memory/src/tools.ts:424-431` 的工具入参为 `uri`（必填）/ `content`（必填）/ `parent_uri?` / `importance?` / `when?` / `time?`；其中 **`when` 映射到节点的 `disclosure`**（`tools.ts:445`：`disclosure: params.when ?? null`），**它只是「想起条件」，不是地址**。

- **地址（她要往哪儿写）**：`parent_uri: "core://identity/notebook"`；
- **`core://identity/notebook` 自己的 `disclosure`**（= 蓝图的 disclosure 列）保持 02 §4.1 现写的「当我翻开那本笔记、或想起某个人时」——它决定**这个节点何时被想起**；02 **无需改**。
