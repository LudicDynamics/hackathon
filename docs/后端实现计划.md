## 0. 现状体检（都是实测，不是推断）

### 0.1 致命项：我们说的话 pi-rp 听不懂

`apps/server/src/engine/rpc-client.ts` 发的是 JSON-RPC 风格的 `{ id, method, params }`；pi-rp 的 RPC 模式收的是**带 `type` 的 JSONL 命令**（`src/modes/rpc/rpc-types.ts` 的 `RpcCommand`）。实测：

```
→ {"id":1,"method":"prompt","params":{"message":"ping"}}
← {"id":1,"type":"response","success":false,"error":"Unknown command: undefined"}

→ {"id":"a","type":"get_session_stats"}
← {"id":"a","type":"response","command":"get_session_stats","success":true,"data":{...}}
```

**所以 `writer.prompt(...)` 这一年都在空转**——玩家说话、骰子回执、上帝动作通知作家，全部落在地上。连带三处协议不兼容：

| # | 问题 | 证据 |
|---|---|---|
| 1 | 命令用 `method`/`params`，pi-rp 认 `type` | 上面的实测回包 |
| 2 | 请求 id 用数字，pi-rp 的 `id` 是 `string`；回包形状是 `{type:"response",command,success,data}`，我们的 `handleMessage` 按 `msg.id` + `msg.error` 匹配 | `rpc-types.ts:21-330` |
| 3 | 用 `node:readline` 读 stdout | pi-rp `docs/rpc.md`「Framing」明确写：**readline 不合规**——它会在 `U+2028`/`U+2029` 上断行，而这两个字符在 JSON 字符串里合法 |

**为什么探针没抓到**：`tools/probe-writer.mjs` 只 spawn + 等 1.5 秒 + 查 stderr 有没有 `not found`，**从来没发过一轮 prompt**。地基探针只探到了地基的一半。

**修法不是修我们的 client，是删掉它**：pi-rp 自带完整的 `RpcClient`（`vendor/pi-rp/packages/coding-agent/dist/modes/rpc/rpc-client.js`），协议正确、JSONL 框正确，且已经有 `prompt` / `steer` / `followUp` / `abort` / `waitForIdle` / `onEvent` / `getEntries` / `appendMessage` / `switchSession` 全套。它不在 `package.json` 的 `exports` 里，但我们是 vendored，深路径 import 即可（或给 pi-rp 补一个 `./rpc` 导出，见 §11 取舍登记 #5）。

### 0.2 第二致命项：AIRP 一个工具都没注册

doc-05 §9 的作家工具面——`chalk` / `read_canvas` / `link` / `arrange` / `delete` / `get_component` / `show` / `generate_image`——**`extensions/` 里一个 `registerTool` 都没有**。`extensions/instructions.ts` 只注册了 4 个 instruction slot。

后果分两层：

- **作家层**：提示词里写着"用 chalk 落板书"，而 chalk 不存在。作家只能拿内建 `write` 硬写 md——frontmatter 格式、`append_to`、`link_to`、落盘路径约定全靠它自觉，doc-07 风险表里"LLM 把 chalk 写成小说段落"这一条**没有任何工程兜底**。
- **子代理层**：初始化器要落盘，能不能落取决于子代理的默认工具集。**这条我一开始照抄了 doc-11 §2.3 C1 的旧结论（"不含 write/edit"），是错的**——见 §0.4。


### 0.4 复核 pi-rp 源码后的更正：四条旧约束已被上游修掉

doc-11 §2.3 那张「pi-rp 源码级约束」表写于 2026-09-11 白天，当晚复核源码时发现**同一位作者当天已经把其中四条修掉了**：

| 约束 | 旧结论 | 现在 | 提交 |
|---|---|---|---|
| **C1** 子代理默认工具集 | `["read","grep","find","ls","bash"]`，不含 write/edit | `["read","bash","edit","write","grep","find","ls"]` | `402ccc59b` |
| **C3** slot `options` 宏 | 不展开，`path:"{{x}}.md"` 原样传入 | 字符串叶子走宏展开 | `05893618c` |
| **C5** 子会话 cwd | prepare 用父 cwd、run 用 `process.cwd()`，可能不一致 | 统一用 prepare 记录的 cwd | `ea310c9fc` |
| **C7** preset 目录 | 只读顶层，不递归 | `collectPresetFiles` 深度优先递归 | `6c693a7f3` |

上游甚至补了 `3ca27f746 test(subagent): airp-style world-init e2e covering C1/C2/C3/C5/C7`——**就是照着 AIRP 的用法写的 e2e**。

仍然成立的是 **C2**（`tools.allow` 是过滤器，加不出工具）、**C4**（`onMissing:"error"` 致命）、**C6**（`spawnAgent` 不校验 `delegatable`）、**C8**（子会话无扩展运行时，事件 handler 不触发）、**C9**（回报被 `truncateTail` 截断）。

**但这里有一个更阴的坑**：`vendor/pi-rp/packages/*/dist/` 被 pi-rp 的 `.gitignore` 排除，**是每台机器本地构建的产物，不随 submodule 指针走**。实测本仓库的 dist 停在 **9/8**，比源码落后四天：

```
src/core/subagent/prepare.ts   9/11  DEFAULT_SUBAGENT_TOOLS = ["read","bash","edit","write",...]
dist/core/subagent/prepare.js  9/8   [...["read","grep","find","ls","bash"], ...]
```

我们的服务端与探针跑的都是 `dist/cli.js`——**所以运行时行为一直是旧的，源码修没修都白搭**。已重建，dist 现在与源码一致。为了不再靠记性，子模块工作流收进了 `tools/pi-rp.mjs`（`pnpm pi status|build|update|commit`，移植自 worldlines-rivet）——`status` 直接报 dist 新鲜度，凡是动 HEAD 的路径都自动重建。纪律见 AGENTS.md §6.5 / §7.2 与 doc-11 §2.3.1。

**对本计划的影响**：B1 不再需要为"让初始化器能写盘"造 `write_world_file` 之类的替身工具——扩展该注册的是引擎独有能力（`chalk` / `read_canvas` / `link` / `arrange`），不是内建工具的同义词。

**`INIT_TOOLS` 也不需要了**（中途我一度写成"仍然必需"，那是在上游修掉之前）：`spawnAgent` 原本把 `tools` 预填成只有内建集，显式传进去的 `customTools` 因名字不在白名单里被静默滤掉；这违背 pi 自己的 `tools` 语义（收窄白名单，省略即全开），已由 pi-rp `dfebadcd3` 修正。现在 R2 只要 `spawnAgent({ profileId, task, customTools })`，与 R1 等价。详见 doc-11 §2.4。

## 2. 参考实现：worldlines-rivet（抄什么 / 不抄什么）

`~/projects/worldlines-rivet` 是同一套底座的成熟形态——**世界包 + 多 agent + pi-rp 引擎**，且已经跑过生产。它的会话域被抽成三个模块，正好对应我们缺的那一整块：

| 文件 | 行数 | 职责 |
|---|---|---|
| `services/gateway/wl-protocol.mjs` | 229 | **协议单一事实源**：命令集 / 事件目录 / 关闭码 / 回放魔法 id / 文本提取。**不含 I/O、不含状态、不认识 WebSocket** |
| `services/gateway/ws.mjs` | 315 | WS 外壳：路由 + 版本协商 + 鉴权 + 心跳 + 命令分发。**只把 sink 接到 ws 上**，回放与扇出全在会话域里 |
| `services/gateway/session-host.mjs` | 977 | **会话域**：spawn / stdout 行解析 / seq 盖章 / 回放缓冲 / pending 结算 / 两套 kill / 空闲回收 / 单回合护栏 |
| `launch.mjs` | — | **pi 启动参数与环境的单一来源**（writer / character / creator 三个入口共享） |

架构文档在 `docs/ARCHITECTURE.md`（§1 进程模型、§3 叙事循环、§7 存档、§9.1 web 壳）。

### 2.1 必抄（低成本、高收益，且我们一定会踩的坑）

| # | 机制 | 为什么我们需要 |
|---|---|---|
| 1 | **协议单一事实源模块** | 形状与词汇集中一处，**不掺 I/O**；并置一份 `.d.mts` 类型镜像，用测试锁死两者逐项一致，防手抄漂移。我们的落点是 `packages/shared/src/protocol/ws.ts`——AGENTS.md §6.3 要求"协议变更必须同步 schema"，这个模块就是那个锚点 |
| 2 | **事件目录分两类** | `EVENT_TYPES`（引擎透传）与 `GATEWAY_EVENTS`（网关合成）显式分开。我们的 `chalk_landed` / `layer_initializing` / `world_frozen` 是合成事件，`message_update` 是透传——混在一起迟早分不清谁该保证顺序 |
| 3 | **seq 盖章 + 回放缓冲 + `replay_done`** | 事件行前缀注入会话内单调 seq（**字符串手术，不 JSON.parse**：一次 slice 一次拼接）；buffer 有上界（4000 条）；回放按 `agent_end` 切轮次，回放最近 5 个**完整**轮次，最旧一轮不截断；回放帧与实时帧走**同一个 sink**、同一同步 tick 交付，所以交集只可能是逐字节相同的重复帧（客户端按内容去重），**不会丢事件**。我们现在刷新一下页面就丢一整段叙事 |
| 4 | **一码一义的关闭码** | `4400 协议不匹配 / 4401 仅鉴权 / 4404 会话不存在 / 1001 服务关闭`，配一个 `closeKind()` 做唯一分类实现，**禁止前端嗅探 reason 字符串**。他们踩过 4400/4401 共用一码逼得前端猜字符串的坑 |
| 5 | **`send` 即发即忘永不抛错 / `request` 永不 reject** | 超时以 `Result` 结算而不是抛异常，调用方不需要层层 try/catch，也不会吊死。我们现在 `PiRpcClient.send()` 的 pending 在进程死时靠 `cleanup()` 逐个 reject——形状对了一半，缺的是超时与"永不 reject" |
| 6 | **pending 唯一结算点** | 只在 `request` 创建、只经 `settle` 移除，同 id 多等待者 FIFO。这是并发下最容易写出幽灵 pending 的地方 |
| 7 | **两套 kill 策略** | `graceful`（SIGTERM → 共享宽限窗口 → SIGKILL）与 `immediate`（SIGKILL）。`stop()` **同步部分先完成**（删条目 / 发信号 / 关 watcher / 通知 sink）并返回一个 `done` Promise 等收割——删世界这种"要等进程真死"的动作才有得等 |
| 8 | **复用 + 收尸原子** | 同 (world, save) 已有存活会话直接**复用**，不 spawn 第二个。他们写明了理由：**重复 spawn 会往会话文件追加一轮 `preset_change`/`schema_change` 条目——这是正确性问题，不是优化**。顺手清掉同键的僵尸条目并关掉它的 state watcher（否则 inotify 一直盯着已删目录） |
| 9 | **⚠️ warmup 补历史（pi-rp 特有坑）** | rpc-mode **只在 `rebindSession()` 里订阅会话事件，而它跑在 `session_start` hook 之后**——开场白 / 既往剧情的 message 事件因此被丢掉。他们的解法：启动后延时补发一帧 `get_messages`（id=`init-history`）＋一帧 `get_entries`（id=`init-entries`，回收 choice 等 custom entry）。**我们的 opening 播种正好挂在 `session_start`，百分之百会踩这一条** |
| 10 | **单回合护栏 ≠ 空闲回收** | `turnTimeoutMs`（墙钟）与 `turnTokenBudget`（累计 token）任一触发就 **abort 本回合**，会话与存档保留，玩家能接着玩；空闲回收才是杀会话。他们实测过一次失控回合烧掉 294k 输入 / 13k 输出、撞满 150s 仍不收敛。**演示当场卡死是黑客松最贵的失败**，这道闸值钱 |
| 11 | **零回合会话的硬超时** | pi 在首个 assistant `message_end` 之前**根本不建会话 jsonl**，此时按常规空闲回收 = 开场白永久丢失。他们对"完成回合数 = 0"的会话用 4 倍硬超时兜底 |
| 12 | **sink 抛错即注销该 sink** | 一个死连接不能拖垮其余客户端的推送 |
| 13 | **应用层 ping/pong + 服务端 30s 心跳** | 浏览器发不了协议层 ping；服务端一轮没收到 pong 就 terminate（移动网络 NAT 兜底） |
| 14 | **启动参数单一来源** | 他们的 `launch.mjs` 头注释写着血泪："三份复制（run.sh / gateway / handoff.ts）曾互相漂移，gateway 漏了 `_` 前缀过滤、缺 opening 挂载与 `WL_OPENING`"。**我们已经在漂移边缘**：`lifecycle.startWriter` 给 skills、`startCharacter` 不给，`probe-writer.mjs` 又自己拼第三份还多一个 `--offline`。收成 `writerLaunch()` / `characterLaunch()` / `initLaunch()` 三个函数，探针与服务端共用 |

### 2.2 抄形状不抄实现

- **gateway / runtime 服务边界**：`runtime-client.mjs` 与进程内 `createSessionHost` **完全同形状**（六入口 + 两个配置读数），靠 `WL_RUNTIME_URL` 一个环境变量切换，调用点一律 `await`（对同步返回值 await 无害）。我们不做远程 runtime，但**保持 host 的形状**——doc-05 §6 的云端托管版将来只换实现不换接口，正对上 doc-07 护城河 2「砍范围不砍形状」。零成本。
- **`admit` 准入钩子 + `maxSessions`**：多租户配额我们不需要，但留个钩子位几乎不花钱，且能顺手防"前端疯狂重连 spawn 出 30 个 pi 进程"。
- **`recorder` 四钩子**（session start/exit、turn start/end，含 token 累计）：他们用来做账本，我们用来做**演示后的成本复盘与卡点定位**，同一个接口。

### 2.4 顺手带回来的一条：他们的角色上下文构造

`docs/ARCHITECTURE.md` §3.3 是我们 §6（B3 角色上下文）问题的成熟答案，形状可以直接搬（内容要换成 AIRP 的词汇）：

- **L1 保底旁白（自动）**：递话筒前最近一条有正文的旁白，**永远**以 `<narration>` 发给角色，作家不填任何字段。→ 我们对应：**永远给本层最近一条 chalk**，不需要任何人记得传。
- **L2 扩展层（范围可控）**：档位 `brief`（无扩展层）/ `since-last`（该角色上次真实回复之后）/ `all`（会话起点），外加 `since` 锚点（子串匹配、命中整条、优先于档位、找不到**报错标红**不静默）。→ 我们对应：`character_cursor` 游标 = 他们的 since-last 下界。
- **防重叠**：扩展层的上界 = 保底旁白的起点之前——**旁白只在时间序里出现一次**。这是一个不写下来就一定会重复注入的细节。
- **⭐ 不连贯提示**：`brief` 档位下若确实有被省略的经过，自动附一句 `[期间发生了一些其他的事……]`——**告诉角色"中间有缺失，而且缺失是正常的"**，避免它把场景跳变当 bug 去追问。这条极聪明，我们照抄。
- **组装序固定**：`<state>` → `<scene_brief>` → `<knowledge>` → [不连贯提示] → 扩展层 → `<narration>`（**保底旁白放最末，紧邻角色的回复**）。
- **跨会话协调三概念**：锚点（角色在主线里"最后一次出现"的位置）、**显式关联**（回复条目里存对方会话的 entry id，别拿 entry id 当关联键去"种植"——他们种植过，碰撞时关联直接崩）、会话投影（把分支按策略转成消息的纯函数模块，transport 可换）。

我们比他们多一样、也少一样：**多**的是磁盘上的世界（所以我们能给"指路文件清单"，他们只能给 state 快照）；**少**的是作家对范围的逐拍控制（我们没有 handoff 工具，档位由引擎按游标定）。

## 5. B2 Hook 注入（P0 · 4h）

doc-05 §5 的管线第一步叫「Hook 上下文注入」，doc-12 #1 把它列为赛时最小子集之一。**pi-rp 的 `before_agent_start` 就是这个 Hook**：它在玩家提交 prompt 之后、agent loop 之前触发，可以返回 `{ message: { customType, content, display } }` 注入一条持久化消息，也可以改这一轮的 system prompt。

新建 `extensions/context.ts`：

```
before_agent_start →
  [视点] 玩家在「Baker Street」层，正看着柜台附近。背包里有：铜钥匙。
  [本层现有] README.md / 01-雨夜.md / 柜台.md / 铜钥匙.md（4 个物件，2 篇板书）
  [世界动态]
  - 玩家把「铜钥匙.md」从柜台拿到了自己的背包里。
  - 玩家掷骰：检定「推理检定」掷出 62（>50 通过）。
  - 「Abandoned Orchard」第一次被走出来了。
```

三段各自的来源与纪律：

| 段 | 来源 | 纪律 |
|---|---|---|
| **视点上报表** | 前端上报（当前层 / 相机中心 / 选中项 / 背包清单）→ server 写 `canvas.db` → 扩展读 | doc-05 §10「这个/这里」的消解靠它；**不给坐标数字**，给人话方位 |
| **本层现有** | `read_canvas` 同款逻辑，只列文件名 + 一行摘要 | **只列不塞全文**——doc-08 定案 4「防回潮」的同一条原则 |
| **世界动态** | `history.db` 取「自作家上次发言以来」的增量 | **人话陈述句、合并去重、N 轮未提及自然过期**（doc-05 §5.1）。不给 diff、不给路径清单噪音 |

**关键工程细节**：扩展跑在 agent 进程内，`cwd` 就是世界根目录，所以它可以**直接用 `node:sqlite` 只读打开 `.airpworld/history.db`**——不需要 sidecar HTTP，不需要 server 拼字符串塞进 prompt。server 与扩展共享同一个文件，注意开 WAL、扩展侧只读连接。

**为什么不用 `--append-system-prompt` 或每轮 prompt 前置拼字符串**：前者不随轮变化，后者把系统噪音混进玩家的话里，作家会把它当玩家说的（doc-03 人话协议里最容易破功的地方）。`before_agent_start` 的注入是**独立的 customType 条目**，身份清清楚楚。

## 6. B3 角色上下文（P0 · 4h）——你点出的那个隐藏问题

### 5.1 问题复述

玩家推了几轮剧情，作家落了几篇板书 md、演化了几个物件。这时玩家去找角色。角色进程是**刚 spawn 的**，它的上下文只有 preset 引的几个身份文件 + 一句"最近场景情况"。**它不知道刚才发生了什么**，于是要么装傻，要么胡编——遮罩对话的质量当场塌掉（doc-07 风险表已登记这条，标注的应对是"最近场景情况注入 + opening 播种双重保障"，但**两条都还没实现**：`startCharacter` 的 `recentContext` 由前端传，而前端从来不传）。

### 5.2 设计：三条来源 + 一条新的

| # | 来源 | 状态 | 说明 |
|---|---|---|---|
| 1 | **opening 播种**（pi-rp 内建） | 资产缺 | `<world>/.airpworld/openings/<角色id>.json`。角色的**出生记忆**，跨续档持久。`airpEnv()` 已经会在文件存在时设 `PI_OPENING`，**但一个 opening 文件都还没写** |
| 2 | **preset file slot** | 半通 | identity/appearance/personality —— doc-11 §4.3 已指出 holmes 的 watson 引了两个**不存在的文件** |
| 3 | **角色自己 `read_canvas`** | 缺工具 | 见 B1 |
| 4 | **⭐ 场景近况简报**（新） | **全缺** | 本节主体 |

> **形状直接取自 worldlines-rivet §3.3**（见本文 §2.4）：保底旁白 L1 + 范围可控的扩展层 L2 + 防重叠 + 不连贯提示 + 固定组装序。下面是换成 AIRP 词汇后的版本。

### 5.3 简报的五段（`buildCharacterBrief`）

与作家那份 Hook **刻意不同**——作家要的是"世界怎么变了"，角色要的是"我该知道的那部分"：

```
[Where you are] The counter of the Baker Street inn. Evening, after the rain.
[What has happened here] （本层最近 3 篇 chalk 的标题 + 首句，不是全文）
  · 01-雨夜：The door slammed open, and rain came in with him.
  · 02-柜台：He asked about the woman who stayed in room four.
[Since you last spoke with the player]（事件增量，人话，只留与本角色/本层相关的）
  · The player took the copper key from your counter.
  · A check was rolled and passed.
[If you need detail, read these]（⭐ 指路，不是灌注）
  · world/baker-street/02-counter.md — what the player just did here
  · player/copper-key.md — the item they are carrying
[Note] Some other things happened in between. That is normal.   ← 仅当确有省略时
```

**组装序是固定的**（rivet §3.3 的教训）：处境 → 近况 → 增量 → 指路 → [不连贯提示] → **最后一段永远是本层最近一条 chalk 的正文**，紧邻角色要说的话。最近那条正文放最末，角色接话时接的就是它。

**防重叠**：第二段（近况）的上界 = 最末那条 chalk 之前——**同一段正文只在简报里出现一次**。这个细节不写下来必然重复注入。

**不连贯提示**照抄 rivet：只在确有被省略的经过时附一句，告诉角色"中间有缺失，而且缺失是正常的"——否则角色会把场景跳变当 bug，反过来追问玩家"刚才怎么了"，当场出戏。

**第四段是关键**，也是你说的"引导角色去读"。它把**文件路径 + 一行这是什么**交给角色，让角色**自己决定读不读**。

为什么是指路而不是全量注入：

- **token**：全量注入等于每次点开角色都把本层全文吞一遍，第 20 轮时角色的开场上下文比作家还长；
- **哲学一致**：这就是 pi-rp Agent Skills 的 progressive disclosure（system prompt 只带 description，正文按需 `read`），也是 doc-05 §1 懒加载的同一条；
- **人设一致**：doc-05 §4.1 定案「**角色知道什么 = 没人告诉它什么，不是规则防出来的**」。指路清单是"桌上摊着这些东西"，读不读是角色的自由——**不是信息门禁**。这条边界要守住：一旦开始设计"哪些不能让角色看到"，就会滑向作家防玩家那种脏设计。

### 5.4 "上次说话是什么时候"——游标

需要一个 `character_cursor` 表（`canvas.db`，因为是**代码消费的架构状态**，符合 doc-05 §8.5 判据）：

```sql
CREATE TABLE IF NOT EXISTS character_cursor (
  character_id TEXT PRIMARY KEY,
  last_event_id TEXT,           -- history.db events.id，增量的起点
  last_seen_at  TEXT NOT NULL
);
```

配套 `store.getEventsSince(eventId)`（现在只有 `getEvents(limit)`）。角色遮罩关闭时推进游标——**不是打开时**，否则中途 Esc 会吞掉一段（doc-13 #2 的中断语义）。

### 5.5 注入方式

用 `RpcClient.appendMessage({ role: 'user', content: brief })` 或扩展侧 `before_agent_start`，**不要用 `prompt()`**——现在 `startCharacter` 里是：

```ts
setTimeout(() => client.prompt(`[System note: the player is standing in front of you ...]`), 500);
```

这有三个毛病：① 占掉一个真实对话回合，角色会**对着系统提示回话**（玩家还没说话就先收到一句"嗯，我在"）；② 500ms 是猜的，spawn 慢一点就打在初始化中间；③ 每次点开都重复注入，多轮后上下文里全是系统旁白。改成 `appendMessage` 落成一条不触发 turn 的会话条目，或走扩展 hook 每轮新鲜生成。

### 5.6 顺带把 `character_prompt` 接上

`index.ts` 里 `character_prompt` 分支**是空的**（只有一行注释）。前端 `CharacterModal` 因此用本地假回复顶着。接上之后连带要做：`[emo: <tag>]` 标签从流里解析出来（提示词已经要求角色输出了）→ 走 WS 推给前端切表情 → 对应 `docs/前端改造计划.md` T3.2 的精灵表。

## 9. B6 网关与会话域（P1 · 5h）——按 worldlines-rivet 的三层切

不要在 `index.ts` 里继续堆 `if`。照 §2 的切法分三个模块，**边界就是"谁认识什么"**：

```
packages/shared/src/protocol/ws.ts   ← 只有形状与词汇：命令集 / 事件目录 / 关闭码 / 回放 id
                                        不含 I/O、不含状态、不认识 WebSocket
apps/server/src/gateway/ws.ts        ← WS 外壳：路由 + 版本协商 + 心跳 + 命令分发
                                        只把 sink 接到 ws 上，回放与扇出不归它
apps/server/src/engine/session-host.ts ← 会话域：spawn / 事件解析 / seq / 回放缓冲 /
                                        pending / 两套 kill / 空闲回收 / 回合护栏
```

`lifecycle.ts` 被 `session-host.ts` 吸收（它现在做的三件事——单例、spawn、回收——正好是会话域的子集）。

### T6.1 协议模块（1h）

`packages/shared/src/protocol/ws.ts`，照抄 `wl-protocol.mjs` 的组织方式：

| 导出 | 内容 |
|---|---|
| `PROTOCOL_VERSION` | `"1"`，WS 查询参数 `?v=1` 协商，不匹配就响亮关连接 |
| `WS_COMMANDS` | 客户端 → 服务端：`input` / `choice` / `abort` / `character_open` / `character_input` / `character_close` / `viewpoint` / `ping` |
| `WS_CLOSE` + `closeKind()` | `4400 协议 / 4401 鉴权（占位） / 4404 会话不存在 / 1001 关闭`。**唯一分类实现**，前端不许嗅探 reason |
| `EVENT_TYPES` | 引擎透传（`message_update` / `message_end` / `tool_execution_*` / `agent_settled` / `response`）+ 网关合成（`chalk_landed` / `canvas_patched` / `file_changed` / `world_frozen` / `layer_initializing` / `layer_init_failed` / `turn_aborted` / `process_exit` / `replay_done`） |
| `GATEWAY_EVENTS` | 上面后半截的清单，显式标出"这些不是引擎发的" |
| `REPLAY_ID` | `init-history` / `init-entries` / `rollback-history` 三个魔法 id 收成常量 |

配 zod（我们已经用 zod）而不是他们的手写 `.d.mts` 镜像——**同一份 schema 既校验又产类型**，比他们那套"两份镜像 + 一致性测试"更省。这是我们能做得比参考实现更好的一处。

### T6.2 会话域（2.5h）

按 §2.1 的 1/3/5/6/7/8/10/11/12 逐条落。最小形状：

```ts
createSessionHost({ spawn, log, timings, maxSessions, idleTimeoutMs, turnTimeoutMs })
  → { start(spec), send(id,msg), request(id,msg,{timeoutMs}), subscribe(id,sink),
      stop(selector,{policy,reason}), list(), info(id) }
```

**赛时可以砍的**：多租户归属、配额 `admit`、`recorder` 账本、远程 runtime。**不能砍的**：复用+收尸、seq+回放、pending 结算、两套 kill、回合护栏——这五条每一条都对应一个演示当场翻车的场景。

### T6.3 WS 外壳（1h）

- 路由 `/ws?v=1`（或 `/api/sessions/:id/events?v=1`，若走多世界）；
- 命令分发：每条带 `id` 的命令**必有 response**；pi 的 `response` 行经广播自然到达发起者（**无需按来源分发**），只有"pi 不回执"的命令（如 `extension_ui_response`）才由网关合成回执；
- 未知/非法消息：单发 `{type:"response", success:false, error}`，**不关连接**；
- 心跳：服务端 30s ping + 应用层 `ping`/`pong`。

### T6.4 世界切换与并发（0.5h）

- `/api/worlds/load` 现在只 `store.close()`：不停旧作家进程、`worldFrozen` 是 router 闭包里的模块级变量、切世界不重置 → 全部收进会话域的 `stop({world})`；
- `history.db` 被 server 与 agent 扩展同时打开：**开 WAL，扩展侧只读连接**；
- fail-loud（doc-07 §3 禁令）：模型不可用明确报错，不静默回退。

## 11. 取舍登记

| # | 事 | 结论 |
|---|---|---|
| 1 | 自研 RpcClient vs 用 pi-rp 的 | **用 pi-rp 的**。协议是人家定的，自研只会一路追着抄 |
| 2 | 上下文注入走 server 拼字符串 vs 扩展 hook | **扩展 hook**。它在 agent 进程内，cwd 就是世界根，能直读两个 db；且 `before_agent_start` 每轮新鲜，spawn 时注入只新鲜一次 |
| 3 | 角色上下文：全量灌 vs 指路 | **指路**。token、懒加载哲学、人设三条都指向同一边 |
| 4 | `use_item_on` 是否即时打断作家 | **待拍板**。它是 doc-19 的 money shot（拖钥匙开锁要立刻有回应），"不打断"的定案在这里可能需要一个明写的例外。倾向：`use_item_on` 走 `followUp`（等作家当前轮结束再接），既不打断也不用等玩家再打一次字 |
| 5 | pi-rp 深路径 import vs 给它补 export | 先深路径（vendored，零风险）；若要上游化再补 `"./rpc"` 导出（AGENTS.md §7.2：改 pi-rp 在 vendored 副本里改，指针同步提交） |
| 6 | 协议类型：zod 单份 vs rivet 的「模块 + `.d.mts` 镜像 + 一致性测试」 | **zod 单份**。他们用手写镜像是因为纯 JS 无类型；我们有 zod，同一份 schema 既校验又产类型——这是少数我们能做得比参考实现更简的地方 |
| 7 | 抄不抄 rivet 的 handoff / pass_mic 递话筒 | **不抄**。doc-05 §4 明文砍掉世界内角色编排；我们的角色由玩家点开唤起，不由作家调度。抄了等于把砍掉的东西装回来（§2.3） |
| 8 | 远程 runtime 服务边界 | **只留形状不做实现**。host 六入口保持同形、调用点一律 `await`，将来云端版换实现不换接口（doc-07 护城河 2） |
