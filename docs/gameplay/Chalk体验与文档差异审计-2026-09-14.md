# Chalk 体验与文档差异审计（2026-09-14）

本次是当前工作区源码与文档的静态对照，不是只审骰子，也不是浏览器全流程验收。未修改玩法代码或把旧设计直接覆盖为当前实现。模板搜索范围为 `templates/**/*.md`；未据此断言玩家存档没有新声明。

## 当前实际体验

Chalk 在画布上默认是无底色的叙事文字。悬停或键盘聚焦，旁边出现独立行动区；点击正文或 Enter，原位置展开阅读纸片，侧边行动区暂时卸载。阅读纸片自己重新渲染 status、choice、roll_dice。普通侧栏选项先填入作家栏，玩家 Send 才向作家发送；阅读页选项则直接请求 `/api/choice`。带 `choice_actions` 的侧栏选项还可直接阅读、收取、挑选材料、进入地点或打开人物。

这个体验已经超出早期“旁白正文下挂三种 widget”的描述，但三个入口还没有共享完整的执行行为。

## 六组主要差异

### 1. 同一个选项在侧栏与阅读页行为不同（实装一致性问题）

- 文档：《Chalk执行验收》把玩家 choice 描述为服务端验证并记 `choice_selected`；AGENTS 则规定“点击先填入作家栏，Send 才执行”。
- 侧栏普通 choice：`EntityInteractions` → `App.prepareChoice` → 填入作家栏；Send 直接发 writer prompt，前端这条路径不调用 `/api/choice`。是否由后续 Agent 记选择事件另取决于工具执行，不能当成点击时已落账。
- 阅读页：`BagItemDialog` 直接 `airpGateway.choose`，立即请求服务端。普通 choice 在 autoWrite=off 时只记事件，可能没有即时叙事；打开自动续写时可能直接起作家。
- 对已声明动作，阅读页未消费返回的 `action`，因此不会像侧栏一样打开材料/阅读弹窗、跳场景或打开人物。服务端执行型动作仍可能已经发生。
- 证据：`apps/web/src/App.tsx` 的 prepareChoice/submitWriter；`components/BagItemDialog.tsx` 的 renderFrontmatterWidgets；`components/narrative/EntityInteractions.tsx` 的 choose；`apps/server/src/routes/world.ts` 的 /choice。

### 2. 声明式动作与部分材料面板已写入代码，但文档和模板未接齐（代码领先、交付未完成）

- 《Chalk玩法形态与判定约定》仍以单项 use_item_on/choice 为当前能力，多槽提交待实现；《Chalk执行验收》也将结构化动作列为未完成。
- 当前新增 `choice_actions`：read / take / stage / enter / character / reply / writer。stage 有材料复选框、缺件提示和“用选中的材料向作家提问”。
- 这还不是完整的多槽 Hybrid：没有“证物/证言/方法”槽位类型、必填约束或原子结算；提交只是构造作家草稿，仍需 Send。
- 声明式 read/stage 使用居中的带背景遮罩弹窗；普通 Chalk 正文阅读则是原位纸片。阅读设计文档没有解释这两个视觉分支。
- 本次在 docs 中未找到 choice_actions/dice_outcomes 的专门协议记录；在 templates 的 Markdown 中未找到实际声明。不可把“代码存在”报成六世界已上线。
- 证据：`apps/server/src/engine/declared-actions.ts`；`apps/web/src/components/narrative/DeclaredActionDialog.tsx` 与 declared-actions.css。

### 3. 骰后后果已出现有限自动回写，旧“只落点数”说明不完整（条件能力）

- 玩法文档写 HTTP 掷骰目前只落骰点，后果在后续 Writer 行动中处理。
- 当前 `/api/dice` 已走 runDeclaredRoll：有 dice_outcomes 时，只支持固定 `2d6 >=7` 与 2–3/4–6/7–10/11–12 四档，自动向原 Chalk 追加对应文本，并替换 choice 与 choice_actions，保存复用回执。
- 普通未声明检定仍只落骰点。声明路径也没有自动扣物、发奖或生成完整新场景。
- 模板尚未找到 dice_outcomes；“掷完马上有短后果”不能当成默认体验。
- 这也不是 D10 演出的改动：分档后果与动画是两个独立层面。
- 证据：declared-actions.ts 的 runDeclaredRoll；routes/world.ts 的 /dice。

### 4. 逐字湿墨已不按文档描述播放（明确文档漂移）

- 《perform/01-作家演出通道》§6.3 与验收要求 ChalkMark 每约 24ms 显示一个字。
- 当前 ChalkMark 直接以 MarkdownText 渲染收到的整份 entry.text，没有 shownChars、逐字计时器或调用 chalk-reveal。chalk-reveal.ts 的纯函数仍在，但生产渲染没有引用。
- 仍有空白时笔尖、落定 ink-spread 和失败退场；不能把整条演出称为未实现，也不能继续声称逐字节奏已经验证。
- 证据：`apps/web/src/components/performance/WriterInkLayer.tsx`；`apps/web/src/lib/chalk-reveal.ts`。

### 5. 阅读形态已分成两层，旧“正文下方交互”的主说明过时（新文档仅部分追上）

- 工具文档 02-chalk 与 fm.tsx 的注释仍描述互动在正文下方。
- 实际画布 ChalkCard 默认不渲染 widgets；由 CanvasObject 的 EntityInteractions 放在右/左/下的浮动行动区。展开阅读后才由 BagItemDialog 放在正文下方。
- 《阅读与音效优化》与 doc-06 尾部已记录原位展开、纸外/Escape 收起，不应把这部分判成未实现；但主 Chalk 说明和旧验收没有给出“浏览/悬停/展开”的完整状态图。
- Chalk 已有点数时，画布正文下另有常驻结果。阅读页则使用骰子 widget 展示，形式也不同。
- 证据：ChalkCard.tsx、CanvasObject.tsx、BagItemDialog.tsx、scene-shell.css。

### 6. “轻微旋转/年龄风化/Anchor 贴靠”不能按旧文档报为完整体验（混合漂移与未完成）

- 《Chalk执行验收》勾选“数字 size 与轻微旋转不再被全局样式覆盖”；当前 shellStyle 对 chalk 明确强制 0deg。数字 size 仍可用，但倾角已被新实现取消。
- 工具文档把风化解释为年龄驱动；当前 chalkStyleOf 读取显式 collapsed/aged 字段，未在本次检查的呈现链找到按 mtime 自动风化逻辑。
- anchor 当前可做 hover 连线与目标高亮；未见由它驱动贴靠排座或位置移动后的持续跟随。它不是完整的空间附着功能。《Chalk执行验收》已将完整 Anchor 列为待做，这一部分不是新回归。
- 证据：CanvasObject.tsx 的 shellStyle；packages/shared/src/schemas/forms.ts 的 chalkStyleOf；apps/web/src/lib/chalk-anchor.ts。

## 仍是内容约定，不能算完成的运行时保障

四形态（骰子/新地点/提交/Hybrid）没有变成四种完整独立 UI。成功后“先待揭示、点击再发奖/生成”、材料语义核验、先公开风险再确认、奖励与消耗最多一次，仍主要依赖世界文案、Writer 工具执行与后续验收。玩法文档本身已经写明这些限制；它们应列作交付缺口，不应全算文档写错。

## 建议处理顺序

1. 先统一同一 Chalk 的侧栏与阅读页动作分发，明确何时只填草稿、何时记事件、何时执行直接动作。这会直接影响玩家是否认为“点了没反应”或“还没确认就执行”。
2. 再决定是否把 choice_actions/dice_outcomes 正式接入世界模板；若接入，补协议和逐入口验收，尤其 read/enter/stage/writer 在阅读页的行为。
3. 重写 Chalk 的用户体验主文档：浏览 → 展开 → 准备行动 → 明确提交 → 等待 → 看见后果；分别标出普通动作、已声明动作与需 Writer 的动作。
4. 更新落墨、旋转、风化的验收状态，保留“部分实现”和“尚待实测”的区别。不要仅在旧长文顶部加一条更新提示。
