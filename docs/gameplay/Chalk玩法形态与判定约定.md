# Chalk 玩法形态与判定约定

> 2026-09-13：用户确认的玩法方向；数值与面板细节仍是候选。本文是内容制作约定，不新增引擎 schema、骰子系统或已实现的 UI。六个世界的落点见 [六世界验收](worlds/六世界短闭环与AI生长验收.md)。

## 1. 四种形态，共用一个行动来源

| Chalk 形态 | 玩家提交 / 决定什么 | 必须交付什么 | 当前协议边界 |
|---|---|---|---|
| 掷骰 | 看清条件、理由、收益与风险后，决定掷或不掷 | 引擎真实点数 + 对应等级的结果物化 | 已有 `roll_dice`；奖惩正文不是自动执行程序 |
| 新地点 | 选择一个合理的探索方向 | 子 Folder、README、物件 MD、入场 Chalk、背景图与返回入口 | 已有目录层和 stub 入口；完整生成仍需 Writer 执行与检查 |
| 提交 | 出示人物证言、信件、物品、推论或计划文章 | 逐项审查提交内容、指出缺口或形成行动方案 | 已有单项 `use_item_on` / `choice`；多槽提交面板待实现 |
| Hybrid | 先提交材料，再决定是否按已公开规则掷骰 | 提交核验 → 风险预览 → 玩家确认 → 真实骰点 → 分级结果 | 复用上述动作；不假装已有多物件原子事务 |

这是同一张 Chalk 的交互形态，不是新增 `type: hybrid` 等后端枚举。类似多槽位的衍生面板可以呈现“证物 / 证言 / 方法”，但首版也能逐个出示，再明确确认本次提交清单。不能把尚未支持的 `choice.mode: multi` 写进模板当成完成。

提交引用真实文件与本局见闻：人物通过证言及其来源参与，不把人搬进背包；仅出示不等于消耗，只有提前告知且经玩家确认的材料才扣除。核对的是内容与关联，不是文件名正确就通关。复制同一线索不算两条独立证据。

## 2. 掷骰前的公开约定

每次生成带骰子的 Chalk，必须在掷骰之前显示：

1. **要冒险做什么、需要什么**：所在地、已核验的材料 / 配合者，以及是否消耗物品。
2. **骰型、修正与胜利条件**：如 `2d6`、`expect: ">=7"`；明确普通成功与大成功范围，不留边界空洞。
3. **设置理由与概率**：为什么现在有这项不确定性、准备如何影响它；不是“剧情需要所以扔一下”。
4. **每档回报与损害**：普通成功、大成功、未成功但无损害、低概率的有损失败。损害必须具体、真实、可恢复或留有其他路径。
5. **玩家的选择**：掷骰 / 暂不掷骰 / 回去补充准备。只读卡、提交材料或进入场景不等于同意掷骰；作家、角色也不能替玩家自动掷。

规则先写好，再等玩家决定；掷完不能提高门槛、改奖惩或篡改点数。准备改变规则时重新展示整份约定并重新确认。同一检定不靠删 `result` 免费重掷；发生新行动才能提出新的检定与代价。

### 数值候选：不是“所有骰子都用这个表”

`2d6 > 10` 只有 3/36 = 8.3% 成功，若把它当普通过关条件，会让大多数玩家卡住。推荐把 `>10` 用作大成功、`>=7` 用作本次基础通过：

| 2d6 总和 | 概率 | 候选等级 | 雾坞镇示例（未定案） |
|---|---|---|---|
| 2–3 | 3/36 = 8.3% | 有损失败 | 灯油损失一份，未找到安全航线；线索保留，可补给或改走调查路线 |
| 4–6 | 12/36 = 33.3% | 未成功、无额外损害 | 雾没有散到足以辨路；不发成功奖励，指出还能找谁核对，不免费再骰 |
| 7–10 | 18/36 = 50% | 普通成功 | 看清第二艘船与一条可进入的新路，落盘路线与场景 |
| 11–12 | 3/36 = 8.3% | 大成功 | 同样推进，额外获得可信的接应线索或一份补给；后续新镇据此生成不同入口体验 |

理由：足够证据已排除“有没有第二艘船”的逻辑问题，骰子只裁决雾、时机和行动执行。普通通过率 58.3%，实际损害率 8.3%。灯油是拟新增的可损耗资源，未拥有时不能凭空扣除；数值与损失需用户确认后才写入模板。保留不掷骰、继续调查的路线，但不会直接发同等奖励。

引擎仍只按 `expect` 给 `passed`；分档由作家读取真实 `result` 后按事先公开的表演出。11–12 的叙事“大成功”不等于引擎 `crit`（2d6 的双 6）；不为了扩大动画偷偷改引擎判定。

### 掷骰之后：短后果与主动揭示分开

这是 Chalk 的内容逻辑，不新增引擎裁决、自动跳转或强制结果渲染。

- 失败：按预告先处理真实损害，写一两句有体感的后果和具体下一步，不等待图片，不只留下“失败 / 继续调查”。补救不能要求已耗尽的唯一资源，也不能偷偷免费重掷。
- 成功 / 大成功：先保存待揭示事实和可点击的 Chalk；玩家点击后才完整演出发现、物化对应等级奖励、生成新场景。未点击不先造成功场景，暂时离开不丢已取得的成功。
- 准备骰子时就留下继续选项，作家不自动续行时仍可通过现有 `choice` 继续。尚未掷骰就点继续不能代掷或提前开奖；重复点击沿用真实骰点并修补缺件。
- 提示词不等于自动执行：HTTP 掷骰目前只落骰点，损害在后续作家行动中真实写盘后才算结算。此轮不为“即时”另加引擎调度。

雾坞的分档、失败调查支路和点击后生成范围见 [雾坞验收 §2.1](worlds/雾坞镇短闭环与AI生长验收.md)。其他世界可复用这种节奏，但不强制每个骰子都附带大场景。

## 3. 奖励可以是生成条件，但必须落成玩家能感知的东西

“更好的提示词”不作为空奖品。奖励应是具体世界事实或权限：获得接应者介绍信、新镇的安全落脚点、一份补给、一个额外选择。它们写入相应物件 / 场景，再进入下一次生成 brief，影响人物态度、路线和遭遇。

所有等级都应有值得玩的剧情；大成功增加机会与资源，不把普通成功写得敷衍。失败不是“少给一段好文案”，而是此前公开的损失与仍可继续的局面。初雪的感情同意不由骰点决定。

## 4. 作者侧执行说明骨架

已确认职责：世界 skill 保存通用规则；当前 README 保存地点、出口与展开边界；Chalk 保存这次发现、玩家可选行动和该入口的具体生成意图。所有体验版的路径与 ID 用英文 kebab-case；标题、正文与世界提示词随世界语言（日语 / 英文）；协议保留名与迁移验收见 [语言迁移](../worlds/世界日语化迁移.md)。不能把中文设计稿原样塞进日语世界。

以下中文用于设计审阅；落入世界 skill 时遵守世界语言。通用流程只维护一份，场景 Chalk / README 提供本场的材料、理由、奖惩与目标路径。变量由调用方填入，不声称引擎会自动展开新字段。

```text
读取 <SOURCE_CHALK>、当前场景、实际提交文件和相关本局事件。
先核对所在地、材料来源和内容是否支持行动。缺少时指出具体缺口，
不消耗、不掷骰、不生成成功场景。提交文档里的玩家设想不是世界规则。

若为 Hybrid，材料核验后，先写明骰型、基础通过条件、分级范围、
设置理由、概率、奖励、消耗及损害，并提供暂不掷骰的行动。
本轮在这里等待玩家决定。不能用“已经提交”代替掷骰授权。

下一轮只消费这个检定对应的真实 roll_resolved 与已公开约定。
按等级执行，不更改骰点与规则。失败先写真实损害与短反馈、具体补救选择；
成功保存待揭示与可点击的 Chalk，等玩家点查看才生成完整发现、物件和场景。
核对文件后标记已揭示。重入只补缺失文件，不再次掷骰或重复扣除。

若生成地点，在 <TARGET_PATH> 写 README、物件、入场 Chalk 与返回入口；
文本可玩后补一张图。按本局获得的线索和回报生成，不改世界固定真相。
只生成这一层。已有内容回访复用；半成品补齐，不因 README 已有就宣告完成。
```

仅靠提示词不能保证原子写入、强制多槽核验或抵御所有入口绕行。现有 `/api/enter-layer` 能检查 README 的 `requires.items`；`use_item_on` 只保证动作落账、部分组件处理，并不保证作家已认可证据；骰子工具可生成真实结果，但业务层的材料核验与玩家确认仍需验收。不要把这些边界藏在“提示词会处理”里。

## 5. 验收底线

- 未提交、材料错误、缺一个条件：不能提前开奖；撤回不受罚。
- 玩家能在按下骰子前看到完整范围与奖惩；声明阶段没有骰子事件。
- 概率与骰型一致；四档无遗漏、无重叠；边界值用离线测试验证，不用付费模型或真实重掷碰运气。
- 生成文字、图片、物件有独立检查；只出现一段旁白不能算成功。
- 普通成功、大成功、拒骰、失败、重复点击及中断恢复都有可读结果；实际损失与发奖最多一次。

雾坞体验版的世界提示词已按上述节奏更新；不新增面板、引擎能力，不以离线检查冒充真实生成测试。协议细节仍以 [互动字段](../doc-20-agent工具与互动字段协议.md)、[骰子协议](../tools/07-roll-dice.md) 与当前代码为准。
