# 六世界选项解耦与骰子解谜

> 2026-09-14。适用六个 `*-playtest` 体验版。模板和生成源码同步修改，不迁移正在游玩的存档。

## 1. 玩家不必替角色考推理题

雾坞与福尔摩斯保留手动调查，同时允许玩家把观察、线索关联与推理交给角色掷骰完成。玩家仍决定要不要冒险、是否相信判断，以及要怎样行动；不是骰子随机改变真相。

地图直接提供“ダイスで手掛かりを見つける”（用骰子找到线索）。不必先按顺序跑完所有地点，也不必先提交正确答案或两篇文章。

## 2. 按钮与作家分开

| 声明 | 点击后的确定行为 | 何时需要作家 |
|---|---|---|
| `read` | 打开已有文件正文 | 不需要 |
| `take` | 通过既有 move 动作放入背包，展示物品 | 不需要；重复点击不重复拿取 |
| `enter` | 走现有进层入口，仍检查门禁 | 已写场景不需要；未写场景仍遵守 I1 设置 |
| `character` | 打开对应角色对话 | 不自动发问；玩家发送后由角色回应 |
| `stage` | 展示多槽材料、候选、缺件；可查看、替换、清空 | 核对文件版本后准备审核草稿；仍需 Send，不执行计划。详见 [多槽材料协议](多槽材料与统一行动入口.md) |
| `reply` | 展示已写好的短反馈 | 不需要 |
| `writer` | 把明确的 RP／生成请求填入输入框 | 玩家 Send 后才执行 |

`stage` 不等于提交，更不等于执行传真、施法或设局。生成场景、自由 RP、未定约定与现场结局保留作家介入。

声明放在原实体 frontmatter，由 `choice.options[].id` 关联；不是根据运行时按钮文字猜行为：

```yaml
choice:
  options:
    - id: read-letter
      label: 手紙を読む
choice_actions:
  read-letter:
    kind: read
    paths: [world/watson-letter.md]
```

服务端只识别上述有限动作、校验路径并组合既有 `chooseOption` / `moveEntity`，不执行模板脚本。读取范围为 `world/`、`player/` 的 Markdown，不开放角色私密目录。提交的材料仍是文件路径，不是显示标题。

## 3. 骰子结果先确定，生成另行确认

本批调查卡统一 `2d10`，普通成功 `>=11`。两骰的集中分布表示多数调查能获得方向；极端损害与额外奖励较少。

| 点数 | 概率 | 当下反馈 | 下一步 |
|---|---|---|---|
| 2–4 | 6% | 获得线索，但调查声响暴露动静，失去隐秘调查的机会 | 仍能继续，作家后续必须承接代价 |
| 5–10 | 39% | 没有立即看透，获得明确的复查方向 | 换一种方法继续，不额外扣资源 |
| 11–17 | 49% | 得到角色的解释与下一步 | 玩家选择是否推进 |
| 18–20 | 6% | 得到解释，以及额外观察机会 | 后续场景体现这份优势 |

条件、理由、四档后果在掷骰前可读，玩家可以不掷。低点数不封主线，也不靠免费反复掷骰刷成功。这里的代价是写进原卡正文的剧情事实，**不是已实现的资源扣除系统**。

`dice_outcomes` 定义四个连续区间，每项含 `min/max/text/options`；结果选项内是 `id/label/action`。HTTP `/dice` 调用原裁决动作，再用原 `editEntity` 把短反馈与下一组选项写回同一张 Chalk。`dice_receipt` 仅保留本实体的投掷回执以支持重试；无第二份世界状态。原始点数优先，不能伪造单颗骰面来恢复回执。

结果即时落盘，不要求先生成完整场景。新地图、图片、角色、README 和 Chalk 仍在下一次明确生成请求后产出。没有改动 pi-rp、Agent 原生 roll 工具或骰子动画；本批确定性结果投影的接入点是玩家 HTTP `/dice`。

## 4. 六世界的具体落点

| 世界 | 直接操作 | 保留作家介入 |
|---|---|---|
| 雾坞 | 接委托与徽章；读三处证物；人物对话入口；材料预览；四张调查骰子卡 | 雾外道路／城镇生成、自由调查 |
| 福尔摩斯 | 读信与证据；拿信物；五位 NPC 对话入口；材料预览；八张调查骰子卡 | 试行安全计划、人物反应与结局 |
| 分支线 | 读信／拿蛙拆开；事故与传真机说明；草稿预览；返回时间地图 | 写／发送实际传真、改写未来 |
| 初雪 | 拿点歌纸；人物对话入口；读旧约定；返回关系画布 | 新约定、赴约与现场结局、后日谈 |
| 魔法学院 | 拿名札；读已有魔法材料；草稿预览；人物对话入口 | 组合魔法、同意代价后施法、结果生成 |
| 未写之门 | 已写好的信封外观即时反馈 | 打开未知内容、电话与门外世界的生成 |

雾坞四张：第七码头、工坊、旧灯塔、港城总图。总图失败可请求生成潮痕调查的小场景，成功可请求生成雾外岸道；均可继续探索，不再强求两份正确材料和照明方案。

福尔摩斯八张：第三案现场、停尸间、印刷所、编辑室、画室、Edith 房间、无名街、伦敦总图。总图给出 Holmes 的怀疑与可试行的安全方案：重点调查 Wayne，请编辑协助核对地址，在实际中庭验证，Edith 留在 221B，Watson 负责配合。它不是无需证明就定罪；低点数可以进入短失败／部分成果，不再索要两篇作文。

## 5. 边界与验收

- 六个模板的既有选项均已声明路由；生成源码经 `choice-bindings.mjs` 同步编译，重装不丢失。世界 skill 要求新生成选项也声明路由。
- 未声明的旧存档／动态内容仍走旧流程，**不能声称所有未来生成按钮都已强制保证解耦**。本轮不覆盖用户存档。
- 声明动作即使 `autoWrite=scenes-and-choices` 也不自动起作家；无声明的旧选项保留原设置语义。`chooseOption` 本身仍只校验、记录选择；复合动作由 HTTP 外层编排。
- 测试：`node --test tools/direct-world-actions.test.mjs`，覆盖六世界实际临时安装、HTTP 不启动作家、拿取重试、门禁、材料缺失，以及四档边界与骰子幂等。
- 本批未调用收费模型或生图服务；确定性分流通过不等于已验证所有 AI 生成结局。

## 6. 文案通俗化与 D10 限定

玩家可读文案遵循“发生了什么 → 说明什么 → 下一步去哪”。`plain-language.mjs` 管理这层内容，覆盖六世界引导，并重点重写雾坞与福尔摩斯的地点、证物和推理提示。目录 ID、门禁、人物关系、图片引用与固定真相不变。世界 skill 同步要求实时生成也用简单说法，不靠隐喻隐藏操作。

例：福尔摩斯的记录直接列出“昨日18时收到絵、今早6时发生案件”，再解释“絵在案件之前，所以要查提前看过原稿的人”。雾坞的船伤直接解释“水碰不到这个高度，可能是另一艘船撞到的”，再指向灯台调查。

新生成骰子只允许当前有演出的 `1d10`、`2d10`、`1d100`。本批十二张调查卡统一 `2d10`，合计至少11成功，四档覆盖全部100种等概率组合（6、39、49、6种）；模板与作家提示词不再含2d6。

本次定向回归：`node --test tools/plain-language-worlds.test.mjs tools/direct-world-actions.test.mjs tools/holmes-playtest.test.mjs`，12/12 通过。包括模板与生成源码正文一致、骰子范围与概率、真实隔离 HTTP 操作、Holmes 人物与线索分布。前后端构建通过。隔离浏览器组件页确认读信即时展示且零作家输入；生成按钮只填一次输入，未发送。测试页已移除，未切换或修改玩家存档。没有把这项组件检查等同于六世界逐个完整通关。
