# 作家局部上下文实验

2026-09-14。仅作家，实验草案；不改变角色、初始化器、全局提示词与现有存档。先测行为约束，再决定是否改注入结构。

## 为什么测

当前 `extensions/instructions.ts` 的作家步骤 2 要求叙事涉及的每条路径都先打开；`packages/shared/src/render/sections.ts` 的场景/背包以清单摘要为主，最近板书还会跨场景收集。两者叠加可能造成连续补读。减少工具轮次可能加快响应，但还受模型、历史长度、输出长度、生图等因素影响，未实测不能承诺倍数。

本实验的“自己的物品”指玩家背包 `player/`，不是新增一个 writer 私有背包。

## 范围

- 当前场景自己的 README、直接实体与本轮实际涉及的背包材料可读；子场景门牌可见不等于可以递归读子场景正文。
- 已完整提供且本轮未变的内容不重复读；修改文件前仍需足够的当前版本信息，避免覆盖其他更新。
- 场景外只使用玩家提交的材料快照、已经发生且可见的互动事实、已有对话里的确证内容；不根据路径名补写秘密，不递归搜索世界。
- Skill 负责生成手艺和文风，按任务需要加载；不作为每轮重读全世界剧情的导航。世界必要的既定约束不能仅因优化而丢弃。
- 缺失关键事实时停下来说明缺什么，不为赶速度伪造证据。一次行动默认只落一段 Chalk，不自行扩展成长回合。

## 现在可手动测试的文本

在世界选择中点“新的开始”创建专用测试存档，不使用上帝之手。选择已有场景、不需要生图或新地点的简单行动。将下段与真实行动一起粘贴到作家栏：

```text
For this turn, test a local-context writing workflow. Apply this only to the Writer.
Use the current scene and the player-provided materials as your working context.
Read the current scene README and only the directly relevant scene entities or player inventory files if their full current content is missing. Do not reread content already available and unchanged in this turn.
Do not search other scenes, recursively list the world, or read unrelated character files. Use outside-scene facts only when established by an interaction, supplied material, or existing confirmed conversation context. A filename or a short index entry is not evidence of its contents.
Read a generation skill only when needed for this action; do not survey plot skills to discover extra tasks. Keep applicable world constraints. If a necessary fact is unavailable within this scope, report the missing fact and stop rather than inventing it.
Complete exactly this one action. Normally land one concise final narrative paragraph with chalk, reuse the current beat where appropriate, then stop. Do not generate images, new scenes, or extra dialogue for this test.

Player action: [replace with the actual action]
```

这只是低优先级的行为试验，**不是已经生效的路径权限或上下文隔离**。当前常驻提示词仍要求先读涉及文件；当前注入、历史、Skill 列表仍保留原状。若效果不稳定，不能据此否定局部上下文方案，下一阶段才在作家专用实验开关内替换该条规则。

## 对照与验收

1. 同模板建立两个新存档，使用同一个模型和 thinking 档位，走到相同场景、持有相同材料。
2. A 只输入真实行动；B 输入上述限制加同一个行动。不能在 A 写完后的同一个存档测 B。
3. 先各测一次验证玩法，再分别重复至少 3 次；首次启动与热启动分开记录。不要用需要生图的动作比较文本延迟。
4. 记录首次可见反馈、Chalk 落成、整轮结束的耗时；统计 read/look_at/ls/find/grep、总工具次数、失败与重复读取。记录模型输入/输出 token（可获取时）。
5. 同时检查：材料事实正确、骰点没改写、承诺没遗漏、没有场外剧透、只响应一次、文件真落盘。速度快但丢剧情不算通过。

## 若实测有效，再做的工程改动

只给 writer 增加可回退的局部模式；在轮边界组装有字数预算的当前场景与相关材料快照，替换“每条路径先打开”的重复读取要求。不要无限灌入整个场景，也不要同时保留同一内容的多份拷贝。

场景外互动要区分持久事实与短期消息：承诺、证据、骰点继续落实体文件/既有事件表，下一轮按相关性派生上下文。仅放入临时注入块会在下一轮或压缩后失去依据；不建立第二套可独立修改的剧情状态文件。

需同步修订 `docs/hooks/00` 的清单不含全文、跨层最近板书规则，以及 `docs/prompts/01` 的先读要求。当前文档只登记实验，不宣布这些冻结契约已经改变。不修改 character 分节、角色提示词或 pi-rp。
