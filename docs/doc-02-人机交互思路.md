## ⚠️ AIRP 批注（2026-08-30 带着产品上下文回看）

**三大命题对 AIRP 依然成立，但玩家身份变了**——Nodesign 的用户是"操作者/上帝"，AIRP 的玩家是"角色 + 上帝双模"。所以命题的落点不同：

| 命题 | Nodesign 落点 | AIRP 落点 |
|---|---|---|
| A 空间指向 → Agent 上下文 | 用户圈选/评论 → 元素语义上下文 | **上帝模式**：圈选/编辑 → world 落地；**角色模式**：玩家视点 → 作家感知（视点上报表直接继承，是作家懒加载的输入） |
| B Agent 动作可见 | 舞台演出/精灵/反向操作 | **作家可见**（红杆铅笔 liveness：悬停=在想，按压=在写，收笔=退场）+ **世界响应**（叙事落板、组件落地）；~~角色精灵活动~~ → 角色只是**类光标+圆形头像**，不做动画演出（2026-09-10） |
| C 用户修改与 Agent 衔接 | pending-changes 缓冲 | **事件表 + 黑板**：一切行动（玩家/作家）产事件，作家读增量（见 doc-05 §5） |

**章节级对照**：
- §1 空间交互层：**整个画布底座直接搬**（单 transform/相机/手势仲裁/拖拽/小地图）——但 AIRP 是**层级画布**（doc-05 §3.2：每一层都是一块平等的无限画布，切换=换画布）；§1.5 小地图"导航控件不是第二种视图"直接继承为层级导航（大地图→城市）；
- §2 圈选/锚定：上帝模式直接继承；"锚点三层递降"在 AIRP 里用于世界内容引用（角色卡引用地点、物件引用组件）；
- §3 上下文打包：**视点上报表直接继承**（作家懒加载核心输入）；"人话/机器双视图"继承（世界物件的 agent 视图）；
- §4 Agent 可见性：**作家可见性继承**（§4.2 板书直播 = AIRP 的 chalk 流式落板；§4.5 liveness 光点 → 红杆铅笔呼吸）；~~角色/子代理精灵~~不做（2026-09-10 角色砍精灵）；§4.6 低阈值不渲染 → **AIRP 不做状态栏**（状态 = 叙事 frontmatter 快照）；
- §5 pending-changes 缓冲：演化为事件表+黑板；"手势产载荷、消息产指令"→"行动产事件、作家读增量"；
- §6 玩法层：板书/关系线/黑板选项板（choice frontmatter）直接继承；**角色扮演/精灵在场收窄**（2026-09-10：不做角色精灵动画，角色=遮罩+小天地）；
- §7 可借鉴清单：**15 条交互模式几乎全部继承**——其中 #1 手势即意图、#5 视点上报表、#9 合成在场、#14 显式打断权是 AIRP 直接依赖的；#2 攒批、#6 落点提示、#7 冻结渲染、#8 双缓冲 iframe 是画布基建。


## 0. 总纲：AI 协作界面的三个核心命题

把 NoDesign 的上千个交互细节向上抽象，人机交互的设计其实在回答三个问题：

**命题 A：用户模糊的空间指向，如何变成 Agent 精确的上下文？**
用户在画布上"圈一下/指一下/看一眼"，背后是坐标、元素、视野——Agent 需要的是"框住了谁、这块在页面哪儿、用户在看哪"。答案是一套**语义化管道**（见 §3）。

**命题 B：Agent 的动作，如何在界面上可见？**
Agent 是异步的、看不见摸不着的。NoDesign 把它物化成"舞台演出 + 在场感 + 反向操作"——让用户永远知道 Agent 在干什么、在动哪个文件、接下来要干嘛（见 §4）。

**命题 C：用户主导的修改，如何与 Agent 的工作流衔接？**
用户直接改的东西（拖、圈、写、删）和 Agent 正在写的源码是两套真相。答案是一个**持久化的缓冲层**：手势产结构化载荷，消息只产指令（见 §5）。

三个命题共用同一条底层哲学——**"文件即真相，画布即投影"**：所有交互最终都收敛到磁盘上的真实文件，用户改的是"目标态"，Agent 改的是"源码"，两者在缓冲层汇合，绝不各自为政。

## 1. 空间交互层：无限画布的底座

### 1.1 坐标与相机（数学层与交互层分离）

- 坐标约定 `屏幕 = (世界 + 相机偏移) × 缩放`：相机是加在世界坐标上的偏移而非镜头位置，缩放公式没有减法嵌套；拖拽位移必须除以缩放转回世界单位，否则缩放后"跟手"是错的。
- **离散缩放档**（0.1~3 共 8 档）+ 滚轮指数映射：档位保证工具栏 +/- 有确定语义，指数映射保证 0.2→0.3 与 2→3 手感一致。
- **焦点保持**：缩放被边界夹住时保持光标底下的世界点不动，避免画面朝视口中心跳。
- **相机动画三种**：飞行补间（跟随 Agent 产物）、适配矩形（整块入镜，限最大缩放防贴脸）、立即跳转（小地图拖拽专用，1:1 跟手不拽橡皮筋）。

**可借鉴**：相机是纯数学模块（几十条单元测试），交互是另一层——"复杂交互先建模，模型可单测"是无限画布类产品的第一课。

### 1.2 渲染：一个 transform 扛所有

整个世界层只有一个 `transform: scale + translate`，浏览器合成器把全部内容当一张位图平移缩放——**这是"大量对象不卡"的根基**。逐帧相机移动不触发任何布局重排；无限点阵纸背景画在视口上（backgroundSize 随缩放、position 随相机），零 DOM 成本。

其余性能手段全是"别让重活发生在相机帧上"：
- 关键渲染 memo 化（相机平移时 200 张板书不重跑 markdown 解析——曾有 17fps 事故）；
- iframe 重活按需挂载：进视口才挂、缩放小于阈值不挂、每卡活预览有预算上限；
- **冻结渲染循环**（frame-freeze）：把 iframe 的 rAF 换成"只排队不执行"，动画停在最后一帧但画面保留、CPU 归零；悬停解冻、产物窗开着时卡片立刻定格（避免窗里窗外双实例抢核）。

**可借鉴**："定格是常态、想看动的悬停上去"——用冻结渲染循环而非停帧截图解决预览性能，画面永远是最新一帧。

### 1.3 命中与手势仲裁（交互不打架的关键）

- **两层命中表**：工具栏/卡上小按钮（相机也要躲）vs 卡片/工作区（只有相机要躲，工具可以落在卡上画圈写批注）——"相机躲物件、工具不躲"这种不对称需求一张表装不下。
- **点选用几何命中不用 DOM target**：画布指针事件在捕获下会被重定向（pointer capture 后 click 落到公共祖先），拿世界坐标对矩形算，**白送"叠堆下翻"**（一摞卡片点第一下命中最上面，再点循环翻到底下）。
- **长按框选 vs 拖拽平移的仲裁**：空白处拖拽已归相机平移（最常用动作不能抢），所以按住 220ms 不动才转框选；期间手一动（>4px）就当平移、定时器作废；转框选那一瞬必须撤销已武装的平移，否则一次手势同时拉框和推镜头。判据是**时延 + 位移阈值双闸，谁先触发谁接管，且接管要"反悔"另一方**。
- **让既有路让路，不给新路铺路**：触屏改造只做一件事——手指落下即置"抓手态"，拖卡/相机/手势三方都在问同一个开关，相机接管，一行新平移代码都不用写；双指捏合时给已在进行的单指手势补一个合成的 pointercancel，复用现成收尾接口。

**可借鉴**：交互模式冲突时，"优先级链（工具→框选→相机）+ 共享开关"比"给每种手势单独铺路"干净得多。

### 1.4 拖拽体验：跟手优先于对齐

- **世界坐标抓点**：抓点存世界坐标，拖拽位移 = 当前光标下世界点 − 抓点，公式里相机项自然消掉——**拖着卡滚滚轮也跟手**（老算法少相机项，滚一格轮目标就丢了）。
- **相机补帧**：拖拽中相机被滚轮移动时不产生 pointermove，用最后一次已知光标位置补一帧——卡钉在光标下，世界在它下面滑。
- **落点只提示归属，不预告坐标**：实时高亮"会搬进哪个文件夹/会跟哪件成组"，但**永不画 ghost 预告坐标**（逐帧预告坐标 + 松手吸附 = "拖动往鼠标反方向跑"的全部原因）。
- **避让系统**：交互中的卡有路权，别人让——谁层级高谁不动，其余按最小位移让位，且让位方向单调必收敛。
- **边缘跟车**：拖到视口边 60px 带内自动推相机（只推相机不碰物件坐标，物件靠补帧自动跟手），掉帧封顶限速。

**可借鉴**：拖拽的反馈是多层语言——ghost（我在哪）+ 插入 caret（插到哪）+ 对齐引导线（对齐谁）+ 距离数字（差多少）+ 等距标签（排整齐），一个手势五种即时信息。

### 1.5 小地图：导航控件，不是第二种视图

- 总览**不再是一种视图模式**，而是一个导航控件：全貌用它看，干活始终在当前这一层——消除模式切换的认知成本。
- 投影范围取"内容 ∪ 视口"：相机是自由的，跑再远小地图上也看得见自己和内容各在哪边，点一下就能回去——这正是撤掉硬边界的兜底。
- 两种手势按按下位置区分（按在视窗框里=抓框走，框外=跳点），共享一个函数只差一个偏移；**不做缩放**（不是第二套镜头控制）。
- 内容一件一个小方块，不画标题不画图标——这个尺寸下任何字都是噪点。

## 2. 反馈语义层：圈选、锚定、评论

### 2.1 圈选：把"框住谁"变成可测的语义（最精华的一段）

用户拖一个框，背后是三条规则链：

1. **三套坐标系**（浮层系/iframe 内部视口系/页面系）各司其职：画框用浮层系、算相交用内部系、截图用页面系（服务端得知道滚到哪）。坐标换算单点实现，所有浮层共用。
2. **框住谁 = 四条筛选规则**：不相交出局；自身面积大于圈面积 3 倍的视为容器排除（画小框在页面正中，body 和每层 wrapper 都不是用户的意思）；祖先让位给后代（A 包含 B 只留 B）；全筛空时兜底取面积最小的相交元素（"你圈的地方在它里面"是唯一说得出口的话）。上限 12 个元素（再多 Agent 也读不完，token 照烧）。
3. **两个正交问题分开答**：`圈里有什么`（元素清单，按被圈比例排序）+ `这块地方是页面的哪儿`（完整包住圈的最内层容器）——光有一串 div Agent 分不清页头页脚，光有 section 不知道用户嫌的是哪几个。

视觉上，画框时整层压薄暗、框外压深、框内透亮——"现在在圈"一眼可辨；手抖点一下当没画（面积判据）。

**可借鉴**："用户意图显式建模成可测的纯函数"——圈选的语义有专门测试，兜底规则保证永不出现"圈了半天没圈到"。

### 2.2 锚定：让引用活过 DOM 变动

评论/选中/直接编辑都要引用"某个元素"，但 DOM 会被 Agent 反复改写。锚点三层递降：

1. `data-anchor`（Agent 生成时埋的稳定 id）——最可靠；
2. DOM 路径（tag:nth-of-type 链）——位置式，DOM 一动就指到邻居，所以**命中也要对文本提示双保险**；
3. 文本模糊找回（前 50 字 + 包围盒）——前两层失效时兜底，取命中里最短的（避免祖先容器抢坑）。

**可借鉴**：跨重渲染/拖拽的稳定引用是 AI 协作工具的通用刚需——"先盖稳定 id 再序列化"应成为默认动作。

### 2.3 评论系统：从一句话到 Agent 上下文

- 评论浮卡贴元素右上角、钳在视口内（修过坐标系混用导致"评论卡飘到别处"的 bug）；头徽标显示 `<h1> 第 2 页 · 主视觉区`（人话角色）+ 离屏时 MapPin 跳转；
- 提交评论时自动附带元素的**机器视图**（结构 + 锚点 + 计算样式 + 兄弟节点），隐私模式下自动剥文本留结构（Agent 修版式要的是锚点和结构，不需要页面台词）；
- 视觉反馈：已评论元素橙框 + "已评论"标签，按锚点去重（同元素多条合并计数）；Agent 处理完清缓冲，前端按 id 移除标记——闭环无需轮询；
- **评论可以"攒着"**：走查画布的真实节奏是"这张不对、那张也不对、还有那个"，逐条起轮=三轮并发抢同一批文件；右下角"发给 agent（N 条标注）"浮钮攒够一次发。

## 3. 上下文打包层：画布动作 → Agent 可读上下文

### 3.1 元素语义双视图（人话 + 机器）

选中一个元素，同时产出两种视图：
- **人话视图**（给用户确认"我说的是这个"）：标签→人话词典（H1=一级标题、DIV 按 className 细化 card/item/col/row/grid/hero/toolbar）+ 当前样式按设计师关心的维度分组翻译（"深棕 #3a2a18"）+ 可调维度按元素角色过滤（文本类全部维度，容器类只给背景/边距/圆角，图片只给边距圆角）；
- **机器视图**（给 Agent 干活）：结构 + 锚点 + 页码版式 + 截断的 outerHTML + 关键计算样式 + 兄弟节点索引。

### 3.2 视点上报表：Agent 每回合都知道"用户在看哪"

- 前端节流上报"相机世界矩形 + 缩放 + 当前文件夹层 + 开着的窗 + 选中集"，**只在语义级变化时报**（相机挪超过 1/8 视口、缩放变、窗/选中变，最快 1.2s 一次）；
- 服务端每项目只存**最近一份**（TTL 10 分钟）——"它是此刻"，不是历史；
- 每回合在用户消息前注入一行人话：`用户此刻在画布上：视口 (1234,567) 1920×1080 缩放 1.00；视口里有 5 件：a、b、c…；开着窗：站点首页；选中：note/批注/x.md。他说"这个/这里/这张"多半指 选中的 > 开着的窗 > 视口里的东西。`
- **一句话里直接给消解优先级**，而不是把原始坐标丢给 Agent 自己悟。

**可借鉴**：指代消解（"这个/这里/那张"）是 AI 画布类产品的核心难点——用"视点上报表 + 显式优先级"把模糊指代变成可消解的问题。

### 3.3 眼睛模式：Agent 的视觉回路

Agent 也需要"看"画布：`look_at_board` 工具让常驻浏览器打开**用户看的同一张画布页**（不另写渲染器——"同一件东西多个实例"是最贵的一课），URL 参数指路（?eye=1 带视野矩形/带 tag/全景），页面摆好相机后打 `data-eye-ready` 标记回传真实视野矩形，工具等这个标记再按快门截图。

**可借鉴**：复用同一页面实例做 Agent 的视觉，前后端共享同一份渲染真相——服务端零渲染器。

## 4. Agent 可见性层：让 Agent 的存在可感知

### 4.1 事件三管线：一个事件驱动两个 UI 面

WS 事件进前端后走三条管线：**舞台旁路**（画布上的演出，旁路不短路，可继续走后面）→ **聊天流折叠**（时间线 reducer，消费即止）→ **控制帧与生命周期**。`run.tool_use.started` 等事件既要演在画布上（精灵/卡片），又要折进聊天时间轴——两条管线有交集是刻意的。

### 4.2 舞台演出：Agent 干活是画布上的一场戏

- 工具调用逐块流式演在画布上：工具卡落在"目标物件旁（贴它正在改的东西）→ 没上墙贴它归属的工作区 → 认不出掉屏幕底部 dock"三级兜底；
- Agent 每写一个文件，物件亮"已更新"角标淡出 + 镜头跟过去（**只平移不缩放**，不打断"我正在看细节"；8 秒用户接管期让路；多子代理只跟主 Agent，避免镜头抽搐）；
- 生图等待是**幻影物件**：占位卡按正常入座算法排座、渲染在纸面层，真图落地时座位直接过户——占位在哪成品就在哪，不跳位；用户可以直接拖幻影=指定这张图落哪；
- 板书直播（ChalkLiveInk）：Agent 写字直接上画布、带光标、写完淡出，真板书经落盘事件上墙接棒。

### 4.3 在场感：Agent 是画布上另一个"人"

数据模型抄 tldraw 的多人协作在场表（光标/选中/镜头/名字/颜色）——**抄模型不抄代码**：
- 从既有事件流归约出在场表：`run.start`（上场）、`run.tool_input`/`file_changed`（**开写就位，不等写完**——只听 file_changed 的话大文件写十几秒精灵全程站旧目标）、`run.done/error/cancelled`（下场，三种都不能漏——漏了 cancelled 用户取消后精灵永远转圈）；
- 子代理事件一律忽略（算错主精灵就在子代理动的文件之间瞬移）；
- **跟人不是跟事件**：有明确目标才跟随，不做"跟最近动的那个"——那正是镜头横跳的原因；
- 精灵摆位两条决策链：工作时贴目标（头顶→右→左→脚下避让，压最小遮挡），闲时找空位（**宁可不显示、不压别人的作品**）；但输出框（正在写的代码）规矩相反——**宁可压也不消失**：闲话可以不说，正在写的代码必须看得见。

### 4.4 Agent 的反向操作：高亮、跳页、开窗

- `highlight`：Agent 在改某个元素时，前端脉冲高亮该元素（1.5s 黄色描边）——用户视觉锚定；
- `navigate_to_page` / 改了第 N 页：自动跳页 + 高亮 anchor，用户对"Agent 在动哪一页"毫无感知是设计缺陷；
- `preview_deck`：Agent 显式请求预览=等价于用户双击那张卡；产物列表滞后于文件系统时**挂起-补开**（路径跟着 id 一起挂，避免"看起来成功了"的假成功）；而 `file_changed` 事件**不**映射成自动开窗（每写一个文件就来一发=每次存盘拍一扇模态窗在用户脸上）——**Agent 控制"打断用户"的时机**。

### 4.5 聊天里的过程可见性（分级供给）

- **thinking 折叠**：双阈值——流式超 1000 字自动收起留 500 字预览（防 thinking 无限增长刷屏），非流式超 320 字显 220 字 + "Show more"；流式短内容一直显示全文（用户要看打字效果）；
- **工具调用摘要优先**：Edit/Write 显示"文件名 + +N/−M 行数 + 可展开真 diff"（diff 前端本地自算，不依赖模型输出）；子代理收进**时间轴抽屉**（状态行一句话 + 可展开 BRIEF/摘要流水/结果）——过程噪音与可追溯的平衡点；
- **时间线组**：thinking+tool 包成可折叠的"思考片段"，标题本地启发式生成（工具调用说话 > thinking 首句剥开场白截断）——不调 LLM 就给出人话标题；最终回复剥出时间线用正常大字号显示（"真正的最终回复"不该被塞进时间线）；
- **liveness 光点**：流式且 2 秒内有事件→绿点 pulse（Agent 在产 output）；无事件→灰点（深度思考/长工具调用）——"图标在动=OK，不动=待审视"，替代"已 30s 无输出"文字；状态长在正文将要出现的位置（"思考中 · ~N tok"占位行），正文一到就被顶掉。

### 4.6 上下文用量：低于阈值不渲染

上下文用量条只有两档：60% 以下**什么都不画**（零像素——有自动压缩兜底时这个信息行动价值为零）；60-85% 一条 hairline（宽度即用量、颜色即紧迫度）；85% 以上加"87% · 压缩"入口。点开明细：已用/上限、**这段上下文实际跑在谁身上**（模型）、token 构成、Top 工具 token 排行（哪几个工具在烧钱）、会话常量。

**可借鉴**："不是所有指标都值得常驻像素"——把"到点提醒"和"随时查看"拆成两个入口，共享一份数据组件。

## 5. 协作缓冲层：pending changes 全链路

### 5.1 缓冲是什么

用户的一切画布动作（圈选/评论/改字/拖拽/复制/删除/标注）在**发生瞬间**写入项目级持久化缓冲（pending-changes.json），每条带：锚点（元素身份）+ 机器上下文（给 Agent 的结构视图）+ 动作类型 + 可选的区域截图。用户下次发消息时，服务端在消息前注入系统提示：`用户在过去时段做了 1 编辑、2 评论、1 圈选。可调 get_pending_changes 查看详情；处理完调 clear_pending_changes 清缓冲。`——Agent **主动拉取**而非被动塞入。

### 5.2 攒批的去重合并

同锚点 + 同类型的反复调整只留最后一条（Agent 看最终态），但撤销继承首次的还原函数（能整体退回最初态）——"去重给 Agent 看，保留给用户撤"。

### 5.3 应用的两种语义

- 用户改站点 = **前端直接写盘**：磁盘干净源码 + 按锚点重放操作（text/move/duplicate/style），锚点找不到就整体回退整页序列化（宁可带污染别丢改动）——防页面脚本污染进源文件；
- 用户改幻灯 = **等 Agent 应用**：底部浮条"N 拖动 · M 复制 待应用"，点"应用"在聊天框塞预设消息让 Agent 拉详情处理；
- 拖拽落地分**暂存→确认→落盘**：拖完先进暂存栈（"N 处调整未保存"条），确认前可撤销一步/全部放弃；换页/关窗/Agent 开跑前自动保存（运行时 DOM 即将销毁，不救就丢）；
- 协作 lock：Agent run 期间强制退出用户拖拽模式（避免双方并行写同一份文件）。

### 5.4 闭环

Agent 调 clear_pending_changes → 服务端广播 → 前端按 clearedIds 移除橙色标记 + 清本地 state（不调用还原函数——Agent 已把改动落到源码，reload 后视觉跟代码一致）。

**一句话**：画布↔Agent 之间隔着一层持久化的"黑板"，手势产结构化载荷、消息产指令，两件事各司其职——**用户不需要会描述**。

## 6. 玩法层交互：板书、关系、角色（思路速览）

| 玩法 | 交互思路 | 可借鉴点 |
|---|---|---|
| **板书** | Agent 的思考物化成画布上的手写字；草稿态（半透明）→ 落定（实）；双击就地改原文（frontmatter 保留）；右键整组"落定/擦除/导出连接图" | "过程可见"：用户能看到 Agent 正在打草稿，误触代价低 |
| **黑板选项板** | Agent 在板书 markdown 里写可点按钮（`[A] 跟上去`），点=回复；`until` 指令让旧按钮过期失效（陈年选项不许再进待发队列） | 交互物与内容物同构：控件就是内容的一部分，就地可改 |
| **关系线** | 六种语义用线型+端头区分（颜色留给状态）；每条线可写 label 给 Agent 读；悬停"关系一瞥"；材质轴（墨线/手绘/丝线）与语义正交 | 语义双通道编码（形状表语义、颜色表状态），色弱用户也读得出 |
| **谱系收叠** | 改自链旧版叠在现役版身后（像一沓纸露出边角）；**恰好一个链尾才折叠**——环/分叉都原样铺开 | 拿不准就铺开，绝不猜错藏谁 |
| **角色扮演** | 常驻角色（rp- 子代理）在画布上写字、有精灵+名字书签；用户在角色字上回话直达角色；投递结果如实分三种（已送达/已排队/已召回） | 状态语义分离（一个布尔绝不背两件事）；送达语义诚实，宁可啰嗦不让用户对着没人听的板子说话 |
| **精灵在场** | 铅笔精灵有工作目标贴目标、没目标蹲槽位；身份随模型换（星芒/鲸/方块）；点精灵=对话通道 | Agent 的存在感 = 位置 + 正在做什么 + 可对话性；确定性伪随机抖动让动画"活"但不"吵" |
| **自动排座** | 只给没有坐标的新物件排落脚点；**已摆放的永不重排**；关系边决定先后；幻影过户；批注跟着目标走 | 自动与手动的边界划在"有没有坐标"上——算法从不跟你抢已摆好的位置 |
| **右键菜单** | 四张数据表（批量/物件/文件夹/空白）；每个菜单项可见性都过"删了有没有反应"审计（浏览器卡不给删除钮——会静默 404） | 不给用户必然失败的选项 |

## 7. 可借鉴清单（模式 × 适用场景）

按"我们要做类似产品时能用上什么"整理，每条都标注了出处场景。

### 7.1 交互模式

| # | 模式 | 一句话 | 适用场景 |
|---|---|---|---|
| 1 | **手势即意图，消息即指路牌** | 画布动作产结构化载荷进缓冲，聊天只发指路语 | 任何"用户指 + AI 改"的协作界面 |
| 2 | **攒批再发** | 反馈先攒着，一次任务批量处理 | 用户走查节奏与任务粒度对齐（逐条起轮会并发抢文件） |
| 3 | **锚点三层递降** | 稳定 id → DOM 路径（+文本双保险）→ 模糊找回 | 引用要活过 AI 反复改写 DOM 的场景 |
| 4 | **圈选语义纯函数** | 框住谁 = 可测的四条规则 + 兜底；容器与元素分开答 | 把模糊空间指向变成精确上下文 |
| 5 | **视点上报表 + 消解优先级** | 每回合注入"用户在看哪"，显式给出"这个/这里"的优先级 | 指代消解是 AI 画布类产品的通用难题 |
| 6 | **落点只提示归属，不预告坐标** | 拖拽实时高亮去向，永不画 ghost 预告坐标 | 拖拽"跟手优先于对齐" |
| 7 | **冻结渲染循环** | iframe 预览 rAF 排队不执行，定格是常态、悬停解冻 | 大量实时预览的性能（画面永远最新一帧） |
| 8 | **双缓冲 iframe** | src 变化时旧画面不动、隐藏实例加载完再提升 | "Agent 边写用户边看"的刷新不闪白不丢滚动 |
| 9 | **合成在场 + 指纹 + 看门狗** | 本地乐观合成一条在场，真事件回来接管，看门狗防钉死 | 乐观 UI 与远端真相的衔接 |
| 10 | **幻影物件** | 异步结果（生图）先在空间占位、座位过户、可拖指定落点 | 异步产物与同步空间语义统一 |
| 11 | **一个布尔不背两件事** | 状态语义严格分离（isStreaming vs 舞台表） | 状态建模的第一原则（有真实事故背书） |
| 12 | **低阈值不渲染** | 60% 以下不画仪表；"到点提醒"与"随时查看"两个入口 | 克制：不是所有指标都值得常驻像素 |
| 13 | **外部动作双确认** | 发布/外发两击确认；批量删除加确认 | 不可逆/有外部影响的动作 |
| 14 | **显式打断权** | Agent 控制"打断用户"的时机（显式 preview 开窗，file_changed 只更新缩略图） | 后台 Agent 与前台用户共存 |
| 15 | **预览按真实设备宽** | 站点多尺寸不做 transform 缩放，"缩小的桌面版"骗不了人 | 响应式产物检查 |

### 7.2 工程纪律（间接影响交互质量）

| # | 纪律 | 作用 |
|---|---|---|
| 1 | **文件即真相，画布即投影** | 卡片 id 就是磁盘路径，改名/移动/删除都有对账机制 |
| 2 | **用户改动与 Agent 生成在磁盘同一份源上收敛** | 锚点重放（防脚本污染）/ pending 缓冲 / 协作 lock 三件套 |
| 3 | **能力顺着媒介走** | 活页面→DOM 编辑；页图→圈选；无文件→接管；不硬套同一套交互 |
| 4 | **消灭一切"看起来成功了"的假成功** | 静默 404、收不到的导出、开不存在的页，全部显式报错 |
| 5 | **不给用户必然失败的交互** | React mount 区不挂可编辑（会被覆盖）；浏览器卡不给删除钮 |
| 6 | **坐标/锚点/词汇表单点实现** | 浮层坐标、锚点序列化、形态词汇表各只一份，全部有测试 |
| 7 | **parity 断言钉住双份表** | 前端视觉表 ↔ 服务端校验表逐项对账，加语义忘了给视觉测试直接红 |
| 8 | **fail-open / fail-closed 双态** | 判据异常放行（薄壳再兜 try/catch），拿不到信息绝不落宽松档——按风险方向选边 |
| 9 | **纯派生零数据** | 关系线、tag 包络、卷卡都是派生视图不落盘；"顺序是权威、坐标是算的" |
| 10 | **交互事故沉淀为注释规则** | 每个踩过的坑（坐标系混用、pointer capture 重定向、bwrap symlink）都变成注释里的设计规则 |

### 7.3 给明月的一句话总结

> NoDesign 的交互设计可以浓缩成三句话：**画布是全空间（一切都在上面发生），缓冲是黑板（一切动作都沉淀成给 Agent 的结构化上下文），消息是指路牌（聊天只说"看黑板"）**。它的每个亮点几乎都遵循同一模式：把模糊的用户意图显式建模、把异步的 Agent 过程物化可见、把用户与 Agent 的修改收敛到同一份真相——然后，删掉一切"看起来成功了但实际没成功"的路径。
