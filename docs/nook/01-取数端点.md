## ① 一句话定位

**给小天地开一条与「层」平行、但只在少数几个点上必须分叉的通道**：`GET /api/nook?character=<id>` 复用 `/api/layer` 的 `LayerState` 形状与坐席逻辑，却**不经过** `resolveLayer` 门禁（`local-store.ts:550-556` 对 `characters/**` 逐字返回 null）；同理，拖卡在 `arrangeCards` 里加一个与之同型的 nook 分支（§3.7）。

**`characterIdOfPath` 的形状要求（**实测**，`rules/characters.ts:46-53`；也是 `05` 的断言依据）**：

- `characterIdOfPath('characters/ryo/diary.md')` → `'ryo'`。
- `characterIdOfPath('characters/ryo/letters/unsent.md')` → 仍应返回 `'ryo'`（**它只回答「归属哪个角色」**，不回答「是不是直接子目录」）。**这不是漏洞**：`arrangeCards` 的 nook 分支允许拖子目录卡（`assertCardExists` 保证文件存在），而 `GET /api/nook` 的页面成员由 `nookCardPaths`（§2.4）单独收口——**两者是不同的问题，不应由同一个函数回答**。
  > 与 §⑪ 一致：§⑪ 裁决的是**画布显示什么**（只收直接子目录），不是**哪些路径属于这个角色**（子目录也算）。前一版草稿把两件事压进一个「段数必须 = 3」的函数里，那是**过度约束**——它会让 `characters/ryo/letters/unsent.md` 在拖动时 404，而那张卡只是**不显示**，不是**不属于** ryo。改用契约的拆分后，这个过度约束自然消失。
- `characterIdOfPath('world/inn/a.md')` → `null`（前缀不是 `characters/`）。
- `characterIdOfPath('characters/ryo')` → `'ryo'`（**裸目录也算**：实现里「没有第三段」时直接取整段作 id）。**这让 §6.3.1 不必补尾斜杠**——layout 的 `layer` 实参本就是 `characters/<id>`，**可直接喂进去**。
- `characterIdOfPath('characters/README.md')` → `null`（`README.md` 不是合法 id）。
- `characterIdOfPath('characters/ryo/../../secret')` → `'ryo'`（**实测**）：穿越被 id 正则挡在「取第一段」这一步，**不是** strip 路径——所以它永远产不出越界的 id。

- **落点为什么是 `rules/`（B 档已落地，非本片提议）**：`rules/` 是「零依赖纯规则」的既有归属地（`rules/dice.ts` / `rules/interactive.ts`），而这些函数不碰 store、不碰文件系统。更硬的约束是**依赖方向**：契约 §3.7/§3.7.1 冻结 `arrangeCards`（`packages/shared/src/actions/canvas.ts`）也调用它们，而 shared **不能** import `apps/server`。调用点四个（nook 路由 / footprint 分支 / arrangeCards 两条分支），其中三个在 shared 内，所以唯一实现处**只能**是 shared。
- **桶导出已补**：`packages/shared/src/index.ts:15` 已有 `export * from './rules/characters.js';`（B 档）。**本片不需要再动**。该文件有一条注释逐字警告 *"TS `export *` has no glob, so every new module MUST be added here by hand — a missing line is a SILENT unreachable module"*——**这是对「将来再加模块」的纪律，不是本片的动作项**。（按 nook 00 §5.6，此处**不写行号**，改引符号。）
- **消费方 import**：`routes/world.ts` 写 `import { isValidCharacterId, nookIdOf, nookCardPaths } from '@airp/shared'`；`actions/canvas.ts` 写 `import { characterIdOfPath, nookIdOf } from '@airp/shared'`（两文件头部已有大量同类 import：`world.ts:7-22`）。
- **`isValidCharacterId` 语义边界（文档与测试 MUST 说清）**：
  - 只判**形状**，不判**存在**。`isValidCharacterId('does-not-exist') === true`。
  - 空串 `''` → `false`（正则要求首字符 `[a-z0-9]`），**不需要**额外的空串分支。
  - 大写 / `_` / `.` / `/` / `..` / 非 ASCII（含中文目录名）→ `false`。
  - 长度**不设上限**（正则无界）。id 由世界作者命名，目录名本身受文件系统限制；不引入本文档无权发明的上限。

```ts
// packages/shared/src/rules/characters.ts:65   —— ALREADY EXISTS (B 档 99ae55d)。MUST import, MUST NOT rewrite
```

- **签名是 `readonly string[]`**（不是 `string[]`）。传 `string[]` 可以（协变），但**别在调用处再包一层**。
- **它是 `characterIdOfPath` 的互补函数，MUST NOT 合并**（`rules/characters.ts:61-63` 逐字写了这条）：`nookCardPaths` 答「页面显示什么」（只收直接子级），`characterIdOfPath` 答「这条路径属于谁」（子目录也算）。
- **实现（照抄，别重写）**：委托 `directChildrenOf(files, dir)`（`rules/emptiness.ts:19`，全项目「直接子级」的唯一实现），再滤掉非 `.md` 与 `README.md`，拼回 `nookId` 前缀。**实测**：`nookCardPaths(['characters/ryo/README.md','characters/ryo/desk.md','characters/ryo/sub/deep.md','characters/ryo/preset.json','characters/ryo/base.png'], 'characters/ryo')` → `['characters/ryo/desk.md']`。
- `readLayerItems` 是 world.ts 私有的：`Promise.all` 读 + `parseFrontmatter`，与 `/api/layer` 的 `cardFiles.map` 分支（`routes/world.ts:383-387`）**逐字同形**。抽出来是为了让「一个 md 怎么变成 `LayerItem`」在 `02`/`04` 的文档里能引用同一个定义，且实现时不必在 `Promise.all` 里再抄一遍。

> **不抽的**：坐席组装（`enriched`）**不抽成共享 helper**。`/api/layer` 的 `enriched`（`:429-446`）与 nook 的 `enriched` 共享**算法**但必须分叉**两个入参**（§⑥.1）。强行抽一个带 5 个参数的函数，会让 `/api/layer` 的既有行为进入本批的改动面（违背 nook 00 §3.1「不动 layer 地基」）。**复制 18 行 + 改两处入参，比抽一个跨批次 helper 安全。**

## ③ 行为契约逐步（每步写「漏了会怎样」）

### 步骤 1：取活跃世界

```ts
const store = getActiveStore();
if (!store) return res.status(400).json({ error: 'No active world' });
```

- 与 `/api/layer` 逐字同款（`routes/world.ts:375-376`）；错误体是**裸 `{error}`**，不是 `{ok:false,code}`——既有约定，不要「顺手统一」。
- **漏了会怎样**：`store` 为 null 时后续调用直接 TypeError → **500**，前端拿到 500 而非「未加载世界」的明确信号（`02` 的空态分支判不出来）。

### 步骤 2：校验角色 id

```ts
const id = typeof req.query.character === 'string' ? req.query.character : '';
if (!isValidCharacterId(id)) {
  return res.status(400).json({ ok: false, code: 'invalid_argument', error: 'character must be a lower-kebab-case id' });
}
```

- **漏了会怎样**：`?character=../../../etc` 直达步骤 3。虽然 `store.statKind` → `resolvePath` 会拦（`local-store.ts:119-137` 拦绝对路径与 `..`），但那是**抛 `ActionError`** → 落到 catch → 500；且「靠下层偶然拦截」不是安全边界。契约要求这里是 400。

### 步骤 3：目录存在判定

```ts
const nookId = `characters/${id}`;              // nook 00 §3.2：nookId 的形状
if ((await store.statKind(nookId)) !== 'dir') {
  return res.status(404).json({ ok: false, code: 'not_found', error: `No such character: "${id}"` });
}
```

- `statKind`（`local-store.ts:196-203`）三态 `'file' | 'dir' | 'missing'`，**不抛**（catch 返 `'missing'`），是这里唯一正确的原语：`readFile` 会抛、`listFiles` 对不存在路径静默返 `[]`（`:226-228` 的空 catch）。
- 判据是 **`!== 'dir'`**，不是 `=== 'missing'`：`characters/<id>` 若是个**文件**（畸形世界），也应 404。
- **漏了会怎样**：把「文件」当空目录 → 200 + `items: []`，「角色不存在」被伪装成「小天地是空的」，前端永远进不去空态（`02` 的空态文案是给**存在但空**的目录的）。
- **为什么不用 `listFiles(nookId).length === 0`**：那是步骤 4 的原语，但 `listFiles` 对**不存在**的目录也返 `[]`（`:226-228`），无法区分「不存在」与「空」。复用成存在性判据会让 404 永远发不出来。

### 步骤 4：组装 `items`（**核心裁决见 §⑪**）

```ts
// `listFiles(prefix)` walks RECURSIVELY (local-store.ts:214-231), so the
// "direct children only" cut is ours to make — the same call `GET /api/nook`
// and `arrangeCards`' layout branch share (§6.3.1).
// TWO args: (files, nookId). A one-arg call compiles but SILENTLY returns [].
const mdFiles = nookCardPaths(await store.listFiles(nookId), nookId);   // @airp/shared (landed)
const items = await readLayerItems(store, mdFiles);
```

- **不用 `pageOfLayer`**：它内部调 `listFiles()`（**全树**，无 prefix，`local-store.ts:1498`）再 `cardsOfLayer`——为一个小天地扫整个世界。用带 prefix 的 `listFiles(nookId)` 只扫该角色目录，再用 `nookCardPaths` 收成页面成员。
- `nookCardPaths` 里那三个条件**必须齐全**，因为 `listFiles(prefix)` 的 `walk` 是**递归**的（`:220-221`），子目录的 md 也会带出来。
- 排除 README 的理由与 `cardsOfLayer`（`layers.ts:94-110`）**同源**：README 是「配置/门面」，本路由已把它放进 `scene`（步骤 5）。同一 path 同时出现在 `scene` 与 `items` 会造出「一个 path 两个位置」——`/api/layer` 注释（`routes/world.ts:448-451`）明写要避免这个。
- **漏了会怎样**（三个过滤各自漏的后果）：
  - 漏 `.md` → `preset.json` 进 `items`，`cardKindOf` 解析不出 kind，前端渲染一张无形态废卡。
  - 漏「直接子目录」→ 子目录陈设**同时**出现在父级小天地页面上（§⑪），违反「目录即嵌套」的既有语义（`layers.ts:19-22`）。
  - 漏 README 排除 → 门面出现两次，其中一次会被 `seatUnplaced` 排座、写一行 `cards`，与 `scene` 的展示位置冲突。

### 步骤 5：`scene` = 该角色 README（缺则 `null`）

```ts
let scene: SceneReadme | null = null;
let bg: { src: string | null; tone: string; grain: string } = { src: null, tone: 'warm', grain: 'parchment' };
let audio: { ambient: string | null; bgm: string | null } = { ambient: null, bgm: null };
try {
  const readmePath = `${nookId}/README.md`;
  const raw = await store.readFile(readmePath);
  const parsed = parseFrontmatter(raw);
  scene = { path: readmePath, filename: 'README.md', frontmatter: parsed.frontmatter, body: parsed.body, kind: 'scene' };
  bg = readLayerBg(raw);                                          // routes/world.ts:190
  audio = readLayerAudio(parsed.frontmatter, store, AUDIO_ROOT);  // routes/world.ts:274
} catch {
  // README missing -> scene stays null; bg/audio stay their defaults (nook 00 §3.1)
}
```

- **MUST NOT 合成 stub**（nook 00 §3.1）。`/api/layer` 会为无 README 的**层**合成 stub 门牌（`routes/world.ts:393-400`），但那个 stub 是**门的视觉**（门存在、场景未写）。小天地没有「门牌」这个产品概念，缺 README 就是「这间屋子还没写过门面」，交 `02` 走空态。
- `bg` / `audio` 从**同一个 README**读，`own`-only，**无 map 继承**（nook 00 §3.1）。`/api/layer` 的继承块（`routes/world.ts:475-490`）整段**不复制**——它读的是 `world/README.md`，对小天地是**错的源**。
- **漏了会怎样**：
  - 漏 `try/catch` → 无 README 的角色目录（`templates/cthulhu/characters/old-sailor/` **实测只有 `preset.json`**）整个请求 500，「有角色、没写过门面」这个**正常状态**变成故障。
  - 复制了继承块 → 小天地顶部出现 map 的 ambient/bgm；`audio` 的「声明即覆盖」三态语义（`routes/world.ts:472-485` 注释）在小天地没有对应物，是凭空多出来的行为。

### 步骤 6：坐席（seat + reseat + enriched）

```ts
const rowByPath = new Map(store.getLayerCards(items.map((it) => it.path)).map((r) => [r.id, r]));

const unseated = items
  .filter((it) => !rowByPath.has(it.path))
  .map((it) => ({ path: it.path, ...storedSizeOf(it, rowByPath.get(it.path)) }));
if (unseated.length > 0) {
  for (const row of await store.seatUnplaced(nookId, unseated)) rowByPath.set(row.id, row);
}

for (const row of await store.reseatLayer(nookId, items.map((it) => ({ path: it.path, ...declaredSizeOf(it) })))) {
  rowByPath.set(row.id, row);
}

const enriched = items.map((it) => {
  const row = rowByPath.get(it.path);
  const { kind, w, h } = storedSizeOf(it, row);
  return { ...it, kind, x: row ? row.x : SEAT_ANCHOR.x, y: row ? row.y : SEAT_ANCHOR.y, w, h, z: row ? row.z : 1, rot: rotOf(it.path) };
});
```

逐行对照 `/api/layer`（`routes/world.ts:407-446`）。**唯一必须分叉的两处入参**：

| 传给 store 的 `layerId` | `/api/layer` | `/api/nook` |
|---|---|---|
| `seatUnplaced(layerId, …)`（`:414`） | `layer`（如 `world/baker-street`） | **`characters/<id>`** |
| `reseatLayer(layerId, …)`（`:422`） | 同上 | **`characters/<id>`** |

其余（`storedSizeOf` / `declaredSizeOf` / `SEAT_ANCHOR` / `rotOf` / `getLayerCards` 按 `id=path` 匹配）**逐字相同**。

- **为什么 `layerId` 必须是 nookId**（主 agent 2026-09-13 实测确认）：`seatUnplaced` 用 `WHERE layer = ?` 算 `cards.layer` 的 `MAX(z_index)`（`local-store.ts:591-596`），并把 `layerId` 写进新行的 `cards.layer`（`:644-645`）。传 `'map'` 会让 nook 的卡**抢占 map 层的 z 序号**并把自己的行标成 map 层。
  - **漏了会怎样**：z 与 map 层耦合（map 层重排后小天地卡 z 跳变），且 `cards.layer` 撒谎——`04` 的 footprint 回写与后续任何按 layer 的查询都被误导。nook 00 §3.3 已冻结 `cards.layer = characters/<id>`。
- **`getLayerCards` 按 `id = path` ONLY**（`local-store.ts:565-578` 的 `WHERE id IN (...)`，SQL 里**没有** layer 条件）：坐席的行匹配与「这张卡属于哪层」无关，与 footprint BLOCKER-2 裁决同源（`docs/footprint/00` §3.3）。nook 与 layer 抢同一 path 行是**不可能**的——path 是世界根相对、全局唯一。
- **`reseatLayer` 必须调用，不能只靠 `seatUnplaced`**：
  - `seatUnplaced` **只给无行的卡**排座（`local-store.ts:586-589`），已排过的卡永远不动。
  - F1 的核心链路是「实测占位变大 → 座位让开」，**唯一**发生在 `reseatLayer` 的漂移源 4（`local-store.ts:734-750`）。漏掉它 → 小天地里被测量过的卡永远按旧尺寸排 → 长卡重叠，正是 F1 要治的病。
  - **顺序不能颠倒**：先 `seatUnplaced` 建行，再 `reseatLayer` 补 `formVersion`/判漂移。与 `/api/layer` 同序，别自创。

### 9.2 `GET /api/nook` 伪码

```ts
// Get a character's nook (docs/nook/01). Same `LayerState` shape as /api/layer,
// but `characters/**` is NOT a layer (local-store.ts:550-556), so those gates
// cannot be borrowed: the id regex + `statKind` are this route's own gate.
router.get('/nook', async (req, res) => {
  const store = getActiveStore();
  if (!store) return res.status(400).json({ error: 'No active world' });        // 1

  const id = typeof req.query.character === 'string' ? req.query.character : '';
  if (!isValidCharacterId(id)) {                                               // 2  (@airp/shared)
    return res.status(400).json({ ok: false, code: 'invalid_argument', error: 'character must be a lower-kebab-case id' });
  }
  const nookId = `characters/${id}`;
  if ((await store.statKind(nookId)) !== 'dir') {                              // 3
    return res.status(404).json({ ok: false, code: 'not_found', error: `No such character: "${id}"` });
  }

  try {
    const mdFiles = nookCardPaths(await store.listFiles(nookId), nookId);      // 4
    const items = await readLayerItems(store, mdFiles);

    let scene: SceneReadme | null = null;                                      // 5
    let bg: { src: string | null; tone: string; grain: string } = { src: null, tone: 'warm', grain: 'parchment' };
    let audio: { ambient: string | null; bgm: string | null } = { ambient: null, bgm: null };
    try {
      const readmePath = `${nookId}/README.md`;
      const raw = await store.readFile(readmePath);
      const parsed = parseFrontmatter(raw);
      scene = { path: readmePath, filename: 'README.md', frontmatter: parsed.frontmatter, body: parsed.body, kind: 'scene' };
      bg = readLayerBg(raw);
      audio = readLayerAudio(parsed.frontmatter, store, AUDIO_ROOT);           // own only — NO map inheritance
    } catch { /* no README -> scene null, bg/audio defaults (nook 00 §3.1) */ }

    const rowByPath = new Map(store.getLayerCards(items.map((it) => it.path)).map((r) => [r.id, r]));   // 6
    const unseated = items
      .filter((it) => !rowByPath.has(it.path))
      .map((it) => ({ path: it.path, ...storedSizeOf(it, rowByPath.get(it.path)) }));
    if (unseated.length > 0) {
      for (const row of await store.seatUnplaced(nookId, unseated)) rowByPath.set(row.id, row);
    }
    for (const row of await store.reseatLayer(nookId, items.map((it) => ({ path: it.path, ...declaredSizeOf(it) })))) {
      rowByPath.set(row.id, row);
    }
    const enriched = items.map((it) => {
      const row = rowByPath.get(it.path);
      const { kind, w, h } = storedSizeOf(it, row);
      return { ...it, kind, x: row ? row.x : SEAT_ANCHOR.x, y: row ? row.y : SEAT_ANCHOR.y, w, h, z: row ? row.z : 1, rot: rotOf(it.path) };
    });

    res.json({                                                                // 7/8
      layer: nookId, scene, bg, audio, items: enriched,
      links: [], presence: [], worldFrozen,
    });
  } catch (err) {
    res.status(500).json({ error: err instanceof Error ? err.message : String(err) });
  }
});
```

## ⑪ 硬问题裁决：`items` 要不要包含子目录？

### 问题

`listFiles(prefix)` 递归（`local-store.ts:214-231` 的 `walk` 对 `entry.isDirectory()` 继续下钻），会把 `characters/ryo/works/draft.md` 也带出来。nook 的 `items` 该不该收它？

### 裁决：**不收。`items` = `characters/<id>/` 的「直接子目录的 md」（除 `README.md`）**，与 nook 00 §3.1 的措辞逐字一致。

### 理由（四条，按权重）

1. **与「页面成员」的唯一既有定义对齐。** `cardsOfLayer(layerId, allFiles)`（`layers.ts:102-110`）用 `dirOf(f) === dir` 做**精确目录**匹配——只收直接子目录。`pageOfLayer`（`local-store.ts:1497-1503`）与 `GET /api/layer`（`routes/world.ts:379`）都走这个函数。小天地是**同一张画布**（`02` 复用 `Canvas`），页面成员的定义若与层不同，同一份 md 在两种画布上的「算不算一张卡」会分叉——这是 nook 00 §3.1「复用 `LayerState` 形状」精神下最不该出现的事。
2. **嵌套 = 目录，这是本仓库的架构公理。** `layers.ts:19-22` 逐字写着 *"It never reaches into a child layer's contents — the tree decides nesting, so a sub-scene's cards stay on the sub-scene's page."* 小天地里出现子目录（如 `characters/ryo/letters/`）时，若把子目录的 md 拉进父层，就**推翻**这条公理，且没有替换语义（小天地没有「子层门牌」这个概念可承接它）。
3. **它会让「空目录判定」撒谎。** `04` 要识别 `nook-init` 的触发点（`doc-11 §4.1`：根目录为空 = 只含 `preset.json`）。若 `items` 递归，一个**根目录空、只有子目录有内容**的小天地会渲染出非空画布 → 前端判「不空」→ 初始化永不触发。反过来，若 `items` 只收直接子目录，「画布是否为空」与「目录是否为空」就是**同一个事实**。**判据与呈现必须同源**——这正是 `look-at.ts:9-11` 对 `pageOfLayer` 的论证方式（「agent 的文本视图与玩家的画布不可能分叉」）。
4. **nook 00 §3.1 的措辞本身就是「直接子目录」。** 契约原文：「`items` 为 `characters/<id>/` **直接子目录的全部 md**（除 README.md 自身）」。我不改契约，只按它实现——但**必须解释为什么这是对的**：否则下一个实现者会「顺手」直接用 `listFiles` 的递归结果，因为那是最省事的写法。**这就是 `nookCardPaths`（§2.4）必须存在、且`GET /api/nook` 与 layout 分支都必须调用它的理由**（§③ 步骤 4、§6.3.1），也是 §2.2 把「页面成员」与「路径归属」拆成两个函数（`nookCardPaths` vs `characterIdOfPath`）的同一条理由。

### 验收这条裁决（`05` 可引用）

- fixture：`characters/ryo/{README.md, diary.md, letters/unsent.md}`。
- 断言：`GET /api/nook?character=ryo` 的 `items.map(i => i.path)` **不含** `characters/ryo/letters/unsent.md`，且**含** `characters/ryo/diary.md`。
- 反例：若实现用了未过滤的 `listFiles`，该断言必须失败。
