# 06 — 角色自身媒体投影（Nook）

> 状态：设计稿，2026-09-14。本文只描述角色自身媒体在 Nook 中的投影，不实施代码、模板或素材迁移。
>
> 共同契约：必须服从 `docs/nook/00-共同上下文.md` 与 `docs/presence/00-共同上下文.md` 的 `LayerState`、`presence`、nook id、单一 WebSocket、资产 URL 和错误可见性语义。本文发现的冲突只列在第 11 节，不回改冻结文档。
>
> 事实引用均带 `file:line`；没有被源码直接证明的判断标为 `[推断]`。

## ① 一句话定位

**角色是 world.json 的 manifest 身份与 `presence` 行，不是 `world/**` 下可拖动的角色卡；Nook 在保留 `LayerState` 画布陈设的同时，从 `/api/characters` 取得该角色自己的 `avatarVideo/avatar`，在 Canvas 外投影一份最多一个视频的媒体 DOM。**

这条边界解决两个容易混淆的问题：

- 「角色此刻在哪」继续由 `presence` 表决定，`home` 只用于首次落场；不可因为展示头像而新建/修改 presence。
- 「Nook 里看到谁」不再依赖 `characters/<id>/portrait.md` 或 `world/**` 的 `type: character` 卡；角色自己的媒体是角色 metadata 的投影，不是 `LayerItem`。

Nook 仍然可以显示角色 README 门面和其它生活陈设。`GET /api/nook` 的 `scene/items/links/presence` 形状不改，媒体仅作为前端投影附加在其上。

## ② Props 与数据来源

### 2.1 数据源的权威顺序

1. **发现/身份**：App 已通过 `airpGateway.characters()` 请求 `/api/characters`，请求封装在 `apps/web/src/lib/airp-gateway.ts:84-102`；`App` 在 `loadChromeData` 的并行请求与提交处取得并保存 characters，见 `apps/web/src/App.tsx:402-415`。
2. **字段形状**：`CharacterView` 已包含 `id/name/home/role/avatar/avatarVideo`，以及 presence，见 `apps/web/src/App.tsx:91-114`。本媒体投影只消费 `id/name/avatar/avatarVideo`，**不把 `home` 当当前位置，也不消费/改写 presence**。
3. **服务端合并**：`/api/characters` 先枚举 `manifest.characters`，再用角色 README 覆盖 `avatar/avatarVideo/bio/voice`，见 `apps/server/src/routes/world.ts:1022-1042`；返回时保留 manifest 字段并加上 `avatar/avatarVideo`，见 `apps/server/src/routes/world.ts:1052-1064`。因此 App 传给 Nook 的 metadata 已经是服务端合并后的值。
4. **Nook 空间数据**：Nook 仍从 `/api/nook?character=<id>` 取得 `LayerState`，`NookView` 当前取数与逐字段组装在 `apps/web/src/components/nook/NookView.tsx:105-135`；服务端仍把角色 README 作为 `scene`、将直接子级 md 作为 `items`，见 `apps/server/src/routes/world.ts:685-757`。该 README 可以继续提供 Nook 门面和状态文字，但不再作为角色媒体的主要来源。

### 2.2 NookView 的新 props

在 `apps/web/src/components/nook/NookView.tsx:33-58` 的 `NookViewProps` 中新增一个**必需**的角色媒体快照和一个效果开关：

```ts
// NEW，建议放在 NookView 文件旁或共享 web 类型文件中；不是世界文件 schema
export interface CharacterMediaSnapshot {
  id: string;
  name?: string;
  avatar?: string;
  avatarVideo?: string;
}

// NookViewProps 新增
character: CharacterMediaSnapshot;
effectsEnabled: boolean;
```

- `character.id` 必须等于当前 `characterId`；App 通过 `characters.find(c => c.id === nookChar)` 组装，找不到时仍传 `{ id: nookChar }`，保证 Nook 可以诚实显示初始字母而不是等待一个不存在的卡片。
- `avatar`、`avatarVideo` 是世界根相对路径或已经存在的历史 `/api/asset` 值；组件不得复制路径校验或自己猜文件名。
- `effectsEnabled` 由 App 现有效果开关传入，与 CharacterModal 现在把 `effectsEnabled` 传给动媒体的做法一致（`apps/web/src/App.tsx:1235-1253`；modal 使用处 `apps/web/src/components/overlay/CharacterModal.tsx:811-817`）。关闭效果只把动态媒体降为静态身份图，不影响 Nook 的文字、卡片或 presence。
- `NookView` 继续保留现有 `characterId`, `onClose` 及动作回调；不把 `LayerState`、camera、WebSocket 或 presence 真相提升到 media props。

### 2.3 媒体组件的共享接口

现有 `MotionPortrait` 是一个对话立绘组件，但它已经包含可复用的媒体状态机：视频/静态图分支、`prefers-reduced-motion`、`document.hidden`、可播放状态与错误降级，见 `apps/web/src/components/overlay/MotionPortrait.tsx:4-67`。为避免 Nook 重抄第二套状态机，建议将该实现提取为一个共享 `CharacterMedia`（NEW），由 CharacterModal 与 Nook 共同消费：

```ts
import type { ReactElement, ReactNode } from 'react';

// NEW apps/web/src/components/media/CharacterMedia.tsx
export interface CharacterMediaProps {
  video?: string;
  poster?: string;
  enabled: boolean;
  name: string;
  className?: string;
  fallback: ReactNode;
}

export function CharacterMedia(props: CharacterMediaProps): ReactElement;
```

这是组件重用，不是新的世界状态或数据源。若实现者决定保留 `MotionPortrait.tsx` 文件，则只能让它调用同一个 `CharacterMedia` 实现；不得同时复制一份隐藏/404/reduced-motion 逻辑。当前 `MotionPortrait` 的 `onPosterError` 回调应收敛成组件内部可见 fallback，不让 Nook 依赖「海报失败后再由父组件猜测视频是否失败」。

## ③ 行为契约（逐步；每步写漏了会怎样）

### 3.1 进入 Nook 与 metadata 对齐

1. App 仍以 `nookChar: string | null` 保存投影选择，并由 `openPrivateSpace` 完成相机事务和切换，见 `apps/web/src/App.tsx:287-306`；Nook 入口继续由角色 rail 的 `onOpenNook` 提供，见 `apps/web/src/components/sidebar/CharacterRail.tsx:156-165`。
2. App 渲染 Nook 时，同时传 `characterId={nookChar}`、`character={...}` 和 `effectsEnabled`，现有渲染落点为 `apps/web/src/App.tsx:940-965`。
3. `NookView` 只把 `character.avatarVideo` 和 `character.avatar` 交给 `CharacterMedia`，不从 `state.scene.frontmatter.avatar/avatarVideo` 覆盖它们。README `scene` 仍可用于状态行；媒体身份以 `/api/characters` 合并结果为准。

**漏了会怎样**：Nook 仍从角色卡/README 的偶然内容取媒体；角色卡被删除后出现空白，或 README 与 manifest 媒体不一致时出现「画布显示一个人、角色 rail 显示另一个人」的双真相。

### 3.2 视频优先、avatar 静态回退

媒体回退链固定为：

1. `avatarVideo` 非空且可加载、当前允许动态 → 挂载**唯一** `<video>`。
2. 视频尚未可播放时，`avatar` 作为 `poster` 或同槽静态图；视频失败（404、错误 MIME、解码失败）→ 卸载/停用视频，显示 `avatar` `<img>`。
3. `avatarVideo` 缺失 → 不创建 video，直接显示 `avatar` `<img>`。
4. `avatar` 缺失或静态图也失败 → 显示可读的初始字母/名字 fallback（`role="img"` + `aria-label`），不显示黑框或空占位。

`/api/asset` 的客户端构造必须复用 `airpGateway.assetUrl(path, undefined, kind)`（`apps/web/src/lib/airp-gateway.ts:142-147`），图片传 `image`、视频传 `video`。服务端 `/api/asset` 明确要求 `kind` 为 `image/video/audio` 并调用 `assertAssetReference`，见 `apps/server/src/routes/world.ts:1484-1502`；因此 Nook 不得只拼 `/api/asset?path=` 而遗漏 media lane。

**漏了会怎样**：视频 404 后留下黑色 `<video>`，或者 avatar 失败后落入通用图标，玩家无法知道「角色身份媒体缺失」；遗漏 `kind` 还会得到 400，误被前端当作 Nook 数据失败。

### 3.3 Reduced motion、效果开关与 document.hidden

- `prefers-reduced-motion: reduce`：复用 `useStill()`，现有读取与订阅位于 `apps/web/src/lib/motion.ts:24-58`；`enabled` 为 false 时**不挂载 video**，显示 avatar 静态图或 fallback。
- `effectsEnabled === false`：与 CharacterModal 语义一致，媒体静止但角色身份仍在；文字、状态、陈设和可操作性不消失。
- `document.hidden === true`：遵守 Nook 冻结契约的「暂停而非替换」口径，保留同一个媒体槽并暂停 video；返回前台后在 `visibilitychange` 中恢复尝试播放。现有 `MotionPortrait` 已监听 visibility 并对隐藏元素调用 `pause()`，见 `apps/web/src/components/overlay/MotionPortrait.tsx:16-42`。
- `play()` 被浏览器自动播放策略拒绝：这不是资产 404；保持静态 poster/avatar，并继续显示角色身份，不把策略拒绝伪报为资源损坏。

**漏了会怎样**：减少动态偏好仍加载视频会违反无障碍；后台 tab 持续解码会浪费合成预算；把 autoplay 拒绝误判为 404 会让可用角色显示成失败。

### 3.4 最多一个 video，与 Canvas 卡片解耦

Nook 直接媒体是该投影的唯一动态角色媒体。Nook 里的 `Canvas` 必须传 `stillPortraits={true}`，让任何历史/用户自建 `portrait` 卡保持静态；`CanvasProps.stillPortraits` 和其 `playingPortrait` 计算已经存在于 `apps/web/src/components/canvas/Canvas.tsx:50-61,192-195`，但当前 Nook 有内容分支 `apps/web/src/components/nook/NookView.tsx:530-549` 尚未传该 prop。

在所有条件下，Nook 投影的断言是：

```text
video 元素总数 ≤ 1
```

角色自身 video 在 `data-nook-zone="character-media"` 下，**不是** `.object`、没有 `data-path`，不进入 `items`、卡片拖拽、碰撞、footprint 或相机 bounds。画布卡片仍由既有 Canvas 处理。

**漏了会怎样**：直接媒体 + 一张旧 portrait 卡同时播放时会变成两路 VP9 解码，违反 `docs/nook/00 §6` 与 `AGENTS.md:104-109` 的性能红线；把媒体包进 `.object` 则会伪造角色卡、写入 cards 行并干扰排座。

### 3.5 退出、重取与重挂

1. 关闭 Nook 仍走 `onClose`，App 恢复 caller projection；媒体组件卸载并在 cleanup 中暂停 video。
2. 角色 metadata 因既有 `airp:world-event` 重取而更新时，App 更新 `characters`，Nook 用新的 `character` 快照重新解析 URL；`avatar/avatarVideo` 变更必须清掉旧 src 的失败状态。
3. Nook `/api/nook` 失败时沿现有 `NookError` 可见错误，不因为媒体失败而丢掉成功的 Nook `LayerState`。当前 Nook 已保留旧 payload、只设置错误，见 `apps/web/src/components/nook/NookView.tsx:217-236`。

**漏了会怎样**：关闭后旧 video 继续播放；素材换成新 URL 仍沿用旧的 failed boolean；Nook 数据失败被媒体错误覆盖，玩家误以为角色的陈设也不存在。

## ⑤ 落账与世界真相

- 角色自身媒体加载是纯读和浏览器本地状态：**不追加事件、不调用 action、不改变 `presence`、不创建 cards 行**。
- `/api/nook` 仍返回 `LayerState`，包括冻结的 `presence: []`；这是「Nook 不属于场景、Nook 内没有在场角色」的投影语义，不得把角色自身媒体误写成 Nook presence。冻结语义见 `docs/presence/00-共同上下文.md:161-168` 与 `docs/nook/00-共同上下文.md:113-121`。
- 首次加载世界时，manifest 中没有 presence 行的角色由初始化代理处理：一次性读取 `store.getPresence()`，对缺失行用 `characters[].home` 经 `resolveHome` 得到 destination，再以固定 `{ type: 'engine' }` 调用既有 `moveCharacter({ character, destination })`；坐标由 `moveCharacter` 内部唯一调用 `store.seatPresence` 产生，初始化接缝不得预先 `seatPresence` 或直接 `upsertPresence`。`resolveHome` 当前只从 manifest 读取 home 并对非法值退回 map，见 `packages/shared/src/actions/presence.ts:192-216`；`moveCharacter` 现有 seat、upsert 与 `character_moved` 事件链见 `packages/shared/src/actions/move-to.ts:45-123,131-154`。
- 该初始化链的硬约束是：有 presence 行时不得覆盖 `layer/x/y/following`；媒体投影不得成为绕过该约束的「隐式入场」。默认世界启动与 `POST /api/worlds/load` 都必须接线，且初始化在 `eventBridge.startTailReader` 之前完成；加载失败要清理未激活的新 store。以上形状以 `docs/presence/00-共同上下文.md:171-189` 为准。
- 视频生产仍由 `tools/motion-clip.mjs` 负责，不能在 NookView 或媒体组件里手写 ffmpeg；路径和 VP9 alpha 口径由 `docs/nook/00-共同上下文.md:334-338` 冻结。

## ⑥ WS 与前端刷新

1. **不新增 WebSocket**：Nook 当前明确不调用 `useWorld()` 以避免第二 socket，见 `apps/web/src/components/nook/NookView.tsx:22-31`；该原则继续有效。
2. **不新增帧名**：媒体没有独立帧；`world_event` 继续是既有变化通道。`docs/presence/00-共同上下文.md:23-24` 明确本批不新增 WS 帧名。
3. 角色 README/manifest/资产声明变化通过现有 App 的 `airp:world-event` 监听重新执行 `loadChromeData`，见 `apps/web/src/App.tsx:523-531`；Nook 持有的 `character` props 更新后重置媒体失败状态。
4. 卡片变化仍由 Nook 现有 `airp:world-event` 监听触发 `load(characterId)`，见 `apps/web/src/components/nook/NookView.tsx:308-345`；媒体加载失败不触发卡片重取，也不伪造 `file_changed`。
5. 页面 hidden 只影响本地 video 播放；不暂停世界状态、presence、Nook card 请求或 action。媒体投影必须能在 effects off/hidden 时保留名字、fallback、陈设和回到页面后的继续路径。

**漏了会怎样**：再开一个媒体 socket会和 `useWorld` 形成重复订阅；新增 `character_media_failed` 帧会扩张冻结枚举；将媒体 404 当 world event 会反复重取 Nook，却无法修复坏资源。

## ⑦ 错误边界与可见恢复

| 情形 | UI 结果 | 不允许的处理 |
|---|---|---|
| `/api/characters` 未就绪，但已有 `nookChar` | 显示角色 id 初始字母/名字；metadata 到达后自动替换 | 不从 scene card 猜 avatarVideo |
| `avatarVideo` 404/403/错误 MIME | 同一媒体槽显示 `avatar` 静态图；可在可展开 details 中给出失败资源 | 保留黑色 video、静默 `console.warn`、创建备用 md |
| `avatar` 缺失或 404 | 显示初始字母/角色名，并保留 Nook 文本/陈设 | 复用无关角色的默认图并宣称是该角色 |
| `prefers-reduced-motion` | 0 个 video，显示 avatar 或 fallback | 挂载 video 后仅靠 CSS 隐藏 |
| `document.hidden` | video 暂停；回前台恢复尝试；无错误 toast | 把后台状态误报为资源失败或清空 Nook |
| 自动播放策略拒绝 | 静态画面仍可见；下一次可见/用户手势再尝试 | 把拒绝归类为 404 |
| `/api/nook` 400/404/5xx | 沿现有 Nook 错误面板显示状态、code、message、可重试条件；成功旧 state 不闪回空白，见 `NookView.tsx:564-589` | 用空房间吞掉取数错误 |
| 当前世界不存在 | 沿 `no_active_world` 既有世界选择流程，不能把它当角色没头像 | 媒体组件自行启动世界加载 |

失败状态按 src 字符串而不是单一 boolean 记录；换角色或换 URL 时必须允许新资源重新尝试。现有 `MotionPortrait` 已以 `failed`/`ready` 及 `sourceRef` 组织这类生命周期，见 `apps/web/src/components/overlay/MotionPortrait.tsx:9-14,44-66`。

## ⑧ 精确代码落点与实现顺序

### 8.1 初始化代理与 shared seam（由 PresenceInitDesign/主代理负责）

- `apps/server/src/routes/world.ts:568-626` 的 `POST /api/worlds/load` 是当前加载世界、建立 `LocalWorldStore`、启动 event bridge 的入口；默认世界启动入口在 `apps/server/src/index.ts:120-125`，也必须复用同一初始化接缝。当前代码在 `new LocalWorldStore` 后直接 `clientManifest`/watch/start writer，尚未调用角色初始 presence 结算。
- 在新 store 对外激活前、`eventBridge.startTailReader` 之前，调用共享 `initializeMissingCharacterPresence(store, { turn })`（NEW，唯一 seam）：一次性读取 presence，对缺失行按 `resolveHome` 得到 destination，再以 `{ type: 'engine' }` 调用既有 `moveCharacter({ character, destination })`；坐标只由 `moveCharacter` 内部唯一 `store.seatPresence` 产生。不能在路由内直接 `upsertPresence`，不能预先 seat，也不能把已存在行重排。

## ⑩ 测试与浏览器验收

实现后由主代理运行具体测试；本文设计阶段按用户要求不运行项目级测试、构建或 lint。

### 10.1 组件/浏览器测试（每条都必须能在错误实现下失败）

1. **metadata 来源非空性**：fixture 中让 `world.json`/`/api/characters` 的 avatar 与 `characters/<id>/README.md` 的旧 avatar 不同，打开 Nook；断言 `data-nook-character-media` 使用 `/api/asset` 的 manifest/API avatarVideo/avatar，而不是 `state.scene.frontmatter` 的旧值。没有本修复时该断言失败。
2. **视频优先**：合法 avatarVideo + avatar，断言 `.nook-character-media video` 恰好 1 个、`muted/loop/playsInline` 为真，且 avatar 是 poster/still，不额外渲染第二个 video。
3. **视频 404 回退**：拦截 video URL 返回 404；断言 video 被停止/移除、avatar `<img>` 可见；若 avatar 也失败，断言 `role="img"` fallback 有角色名。不能只断言 console 输出。
4. **无视频/无头像**：分别验证仅 avatar、两者均缺失；第一档 0 video + 1 img，第二档 0 video + 可读 monogram/name，不允许空白槽。
5. **Reduced motion**：模拟 `matchMedia('(prefers-reduced-motion: reduce)').matches=true`，断言 direct media 的 video 数为 0、静态 avatar/fallback 可见；切换 MediaQueryList 后状态更新，不需要 remount。
6. **后台可见性**：video 已可播放后设置 `document.hidden` 并派发 `visibilitychange`，断言同一 video `paused === true`；恢复可见后只尝试恢复该 video，不创建第二个元素。
7. **Nook 全局上限**：fixture 同时放一张历史 `portrait` card 和角色自身 avatarVideo；断言整个 Nook projection 的 `video` 总数 `<= 1`，并断言 Canvas card 没有夺走角色自身媒体的播放名额。
8. **边界隔离**：断言角色媒体节点没有 `.object`、`data-path`，不出现在 `items`；拖动/footprint 测量只见卡片，媒体不产生 `/api/card/footprint` body。
9. **LayerState/presence 不变**：打开/关闭 Nook 前后，当前 layer 的 `presence` 行 `layer/x/y/following` 不变；Nook response 仍是 `presence: []`，不得由媒体展示创建 row。
10. **世界重取**：发送既有 `airp:world-event` 后 `/api/characters` 返回新 avatarVideo，断言 direct media 换 src 并清除旧失败状态；不新增 WS 帧和媒体专用 HTTP API。

### 10.2 初始化契约的联验

这是 Presence 初始化代理的验收，但必须在整体浏览器/服务端验收中联看：

1. 首次加载真实 world，manifest 有角色且 `canvas.db` 无对应 presence 行；断言默认启动与 `/api/worlds/load` 均调用 `initializeMissingCharacterPresence`，每个角色按 `home → resolveHome → moveCharacter(engine)` 获得唯一坐标（座位由 `moveCharacter` 内部唯一调用 `store.seatPresence` 产生），并落一条 `character_moved`。
2. 预置一条角色 presence（故意使用不同 layer/x/y/following），重新加载世界；断言四个值逐字保留，没有被 home 覆盖。
3. 打开 Nook 不会改变上述行；回到主 Canvas 后头像仍由 presence projection 按当前 layer 判定，而不是由 Nook media 的 DOM 存活时间决定。

### 10.3 浏览器视觉验收

- **桌面宽屏**：Nook 背景/Canvas 继续占满世界 stage；角色透明媒体在右侧偏下成为唯一主焦点，header、左侧 call/error lane、右下 note composer 不重叠；角色名/status 仍一眼可读。
- **窄屏/触屏**：媒体缩放且不遮挡返回按钮、状态文字、输入或卡片操作；没有依赖 hover 才能看到身份或错误。
- **效果关闭/减少动态**：静态 avatar 与文字层位置稳定，去掉 video 不改变 Nook 的空间坐标或卡片排座。
- **切 tab 再回来**：视频暂停并恢复，不出现重新叠一层 video、黑帧、持续后台播放。
- **失败可见**：video/avatar 404 都能在媒体槽与读屏树中识别角色及 fallback；不是静默空白。
