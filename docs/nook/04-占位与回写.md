## ③ 行为契约逐步（每步写「漏了会怎样」）

> 视角：`NookView` 渲染完成后前端测高 → `POST /api/card/footprint {layer: nookId, boxes}`。

**步骤 1 —— 路由拿 `layer` 字符串并粗校验。**
沿用 `:642-644`（非空字符串）。**漏了**：`layer` 为 `undefined`/`''` 时后续 `characters/` 前缀判断要么误命、要么落到层门禁 → 语义混乱的 404，看不出是调用方 bug。

**步骤 2 —— 分流：`layer` 是否以 `characters/` 开头。**
- **是** → 提取 `characterId = layer.slice('characters/'.length)`，走步骤 3。
- **否** → 走原有层门禁 `resolveLayer(dirOfLayer(layer)) === layer`（`:648-650`），语义与今天逐字一致。

**为什么是前缀分流而不是正则匹配 `^characters/[^/]+$`**：前缀分流把 `characters/ryo/../..`、`characters/ryo/letters` 这类**畸形/嵌套**值全部收进 id 校验 → 统一 400。若用严格正则，畸形值会漏到层门禁 → 得到 404 `layer must be an existing layer id`，把「你传了个畸形的 nook 路径」误报成「这个层不存在」。
**漏了分流**（即不写这一支）：`characters/**` 走 `resolveLayer`，而 `resolveLayer('characters/ryo')` 逐字返回 `null`（`local-store.ts:552-555`：非 `world/` 子树直接 `null`）→ `null !== 'characters/ryo'` → **恒 404**。后果不是「报错」而是**静默失效**：前端 `createFootprintScheduler` 的 `post` 回调（`useWorld.ts`，定位见下）把非 2xx 当异常抛、`console.warn`、本地不动，于是**实测尺寸永远写不回 → `cards.height` 永远是声明值 → 长卡片按声明高排座 → 长卡片重叠**（`AGENTS §7.5` 老 bug 原样复现）。
> 行号有保质期：撰写时该 `post` 在 `useWorld.ts:243-250`（`fetch('/api/card/footprint')` `:243`；`throw` `:249`）；早先稿引的 `:198-200` 已随 wiring A 档漂移。**以符号名 `createFootprintScheduler` 的 `post` 参数为准**。

**步骤 3 —— id 形状校验。** `if (!isValidCharacterId(characterId)) → 400 invalid_argument`。
**漏了**：`characters/ryo%2f..`、`characters/Ryo`、`characters/ryo/../ryo` 之类进入路径拼接（`characters/${characterId}`）→ 路径穿越面 / 大小写不一致导致同一角色两套行。契约 §3.2 明写「校验闸在 id 正则，不在路径 normalize」。

**步骤 4 —— 目录存在性校验。** `if ((await store.statKind('characters/'+characterId)) !== 'dir') → 404 not_found`。
**漏了**：对一个不存在的角色目录收下 footprint，`writeFootprints` 因 `SELECT ... WHERE id = ?` 找不到行 → **跳过 + warn + 计入 `unchanged`，HTTP 200**（`local-store.ts:875-881`）。于是「角色目录打错字」被伪装成「值已对」，正是 footprint §3.3 BLOCKER-1 明令要 fail-loud 的那类。`statKind` 返回 `'missing'` 或 `'file'` 都算不存在。

**步骤 5 —— `boxes` 数组与逐盒校验。** 沿用 `:651-671`（非数组→400；空数组→`{ok:true,updated:0,unchanged:0}`；逐盒全字段校验、整批 400）。**漏了**：坏盒子只跳不报，把自家前端的 bug 藏起来（`:657-658` 注释已定「whole-request 400」）。
**不改这条。** `layer` 的取值语义只影响门禁，**不参与行匹配**（见 §⑨.2）。

**步骤 6 —— 交给 `store.writeFootprints(layerId, boxes)`。** `layerId` 只用于**路由层门禁**与 warn 文案（`:849-850` 逐字注释）。

**步骤 7 —— 行必须先由 `seatUnplaced` 建立（跨文档闭环，见 §⑨/附 B）。**
`GET /api/nook`（`01`）在组装 items 时**必须先** `seatUnplaced`（建行，layer = nookId）**再** `reseatLayer`，顺序照抄 `routes/world.ts:409-427`。
**漏了建行**：footprint POST 走到 `:875` 找不到行 → 全部 `unchanged`、HTTP 200、**没有一行被写**。这是 `04`（写侧）与 `01`（读侧）唯一的强耦合点。

**步骤 8 —— 落账：不落、不广播。** 继承 footprint §3.6 与 nook §3.6。**漏了**（私下加事件）：`doc-21` 封闭枚举被破，Hook 每轮多一段「卡片尺寸变了」噪声。

### 9.4 `reseatLayer` 对 nook 的行为分析（读 `cards.metadata.formVersion`，会不会误判）

**判定链**（`local-store.ts:711-761`，逐条）：

| 分支 | 条件 | 对 nook 的行为 |
|---|---|---|

| `:734` `measuredAt != null && (row.h !== row.seatH \|\| row.w !== row.seatW)` | **实测占位变了** | 用**行值**重排 ← F1 核心 |

**关键：`reseatLayer` 内部没有任何 `resolveLayer` / layer 形状门禁。** 它只做两件「层相关」的事：
1. `layerId` 落进 INSERT/UPDATE 的 `layer` 列（`:805`/`:823`）；
2. `WHERE layer = ?` 取 max z（`:779-782`）。

**结论**：只要 `01` 的 `/api/nook` 传 `layerId = characters/<id>`，且 items 的 `SeatFile` 带 `kind + w + h`（照抄 `world.ts:424` 的 `declaredSizeOf(it)` 形态），`reseatLayer` **不会因路径不是层而误判**——它的判据全部是行内 `metadata` 与 declared 的比对，与路径前缀无关。**与 §3.7 的 `arrangeCards` 形成对比**：后者在动作层**显式**调了 `resolveLayer`（`canvas.ts:458`），必须加 nook 分支；而 `reseatLayer` 从不需要它。

# 附 B：必须回答的两个问题（直接答案）

**Q1：nook 的卡片首次进入时（此刻）有没有 `cards` 行？**

**按「无行」假设设计。** 实测其余五个 `templates/**/.airpworld/canvas.db` 与 `worlds/test-school` 的 `SELECT id … WHERE id LIKE 'characters/%'` 均为 **0 行**。

> ⚠️ **证据撤回（2026-09-13，契约 §3.7.1 末同步）**：本文初稿曾把 `templates/holmes-world/.airpworld/canvas.db` 里那一行 `characters/watson/README.md`（`layer=characters/watson`，`x=5 y=6`，`w=280 h=180`，无 `metadata`）当作「既有通路先例」。**该证据不洁**——`NookView02` 主动报告：那行是它**本次实测探针**（`store.placeCard('characters/watson', …)`，x=5/y=6 是探针实参）**直接写在真实模板目录上**产生的，不是历史遗留；该 db 已删除。**故「首次进入是否有行」按「无行」假设。**

**撤回后仍成立的结论**（由该探针反向坐实，且已实测复核）：

1. **存储层可写**：`applyPlaceCard`（`local-store.ts:1011-1038`，**直呼、不反查 layer**）确实能把 `cards.layer` 写成 `characters/<id>` → 契约 §3.3「`cards.layer` 存完整 nookId」在存储层自洽（不是空想）。

3. **已存在行是正常情形、且被正确保留**：`seatUnplaced` 的 `ON CONFLICT(id) DO NOTHING`（`:642`）**不会覆盖**已有行；其 w/h 若是 DEFAULT/漂移，由 `reseatLayer` 的 legacy 分支（`:753`，`row.w/h !== declared` → 用 declared 重排）收敛。

**结论**：**「实测的既有世界均无 nook 行；holmes-world 那一行是探针产物、已删。」** Q2 的答案仍是「第一次由 `GET /api/nook` 的坐席调用建行」，并附一条：**已有行会被 `seatUnplaced` 的 `ON CONFLICT(id) DO NOTHING` 正确保留，尺寸修正是 `reseatLayer` 的职责。**

原因（为何历史上无行）：`characters/**` 从不进层树（`layers.ts:57-59` 只收 `world/`），`/api/layer` 永不列它；而**任何带门禁的放置路径都会拒绝 nook**（§3.7 place / §3.7.1 layout 两处 `resolveLayer` + 本批的 footprint 门禁）。故除直接调 `placeCard` 外，历史上没有路径为它建行。

**Q2：谁给它建行？`/api/nook` 的坐席调用会不会建？**

**会——如果 `01` 照 `/api/layer` 的顺序调用 `seatUnplaced`。** `seatUnplaced` 对无行的路径执行 `INSERT INTO cards (…) VALUES (…) ON CONFLICT(id) DO NOTHING`（`local-store.ts:639-653`），`layer` 列填传入的 `layerId`。`/api/nook` 在组装 items 时**必须先** `seatUnplaced(nookId, items.map(it => ({path: it.path, ...storedSizeOf(it, rowByPath.get(it.path))})))`、**再** `reseatLayer(nookId, items.map(it => ({path: it.path, ...declaredSizeOf(it)})))`，与 `routes/world.ts:409-427` 逐字同形。

**若省略这一步**（或顺序颠倒 / 传错 layerId）：footprint POST 会走到 `local-store.ts:875-881` 的「no row → skip + warn + `unchanged`，HTTP 200」，**不留任何一行**，且不报错——静默失效。这是 `04`（写侧）与 `01`（读侧）之间唯一的强耦合点，**必须两侧同时落地**。

**补充**：建行时 `layer` 必须填 `characters/<id>`（完整 nookId），因为 `seatUnplaced` 的 z 取自 `WHERE layer = ?`（`:591-594`）；填别的值会导致 z 序与占用集不一致。而 footprint 的**行匹配**不受 `layer` 影响（`WHERE id = ?`，`:872`）——两者解耦，正是 nook §3.3 冻结的形状。
