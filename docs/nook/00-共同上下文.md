### 2.7 ⚠️ BLOCKER-N1：`seatUnplaced` 的占位集在批内不更新，多张新卡全部叠在同一坐标（2026-09-13 实测发现，独立于本批的既有 bug）

**实测复现（真实世界数据，非推断）**：

```bash

#   world/baker-street/raindrops.md   820,450
```

**根因**：`local-store.ts:599` 建 `occupied` 时只放**已存在的行**：

```ts

```

**裁决（主 agent，2026-09-13；用户当日明确拍板：随 N1 一起修。修法经子代理 NookRoute01 实测补全为两行）**：
1. **本批 MUST 修**（不是"登记为后续"）——它落在 `01-取数端点`（nook 取数走的就是 `seatUnplaced`）的验收范围里，是"能看见小天地"的前置。
2. **修法 = 两行，必须同时补**（**2026-09-13 修正**：初稿只提了第 1 行，子代理实测发现第 2 行同样缺）：
   - **(a) 位置去冲突**：循环内 `INSERT` 之后补 `occupied.push({ cx: placedX + w / 2, cy: placedY + h / 2, w, h })`，与 `reseatLayer:807/826` **逐字同形**。
     - 漏了 → 同一批 N 张无行卡全部落在同一坐标（实测 4 张同尺寸卡 `distinct (x,y) = 1/4`）。
   - **(b) z 序自增**：`nextZ` 在函数内**只算一次、循环里从不自增**（`local-store.ts:596` `let nextZ = …`，循环体 `:640-655` 用它但无 `nextZ++`）→ 同一批 N 张新卡的 `z_index` **全部相等**。
     - 实测：4 张同尺寸卡 `z values = [1,1,1,1]`，`distinct z = 1/4`。**只补 (a) 会让座位分散而 z 序全等**——叠放次序未定义，且与 `seatNear`（`:1191` 每次新算 nextZ）语义不一致。
     - 补法：循环内 `INSERT` 之后加 `nextZ++`（与 `seats.push(... nextZ)` 的消费顺序一致）。
3. **归属**：`01-取数端点` 的 owner 实现（同文件同函数）。**`05-验收与回归` MUST 给两条修复前失败的断言**：`distinct (x,y) === N` **且** `distinct z === N`（修复前均为 1）。fixture 见 §3.7.1 末（**不得用 watson**）。
4. **回写**：`docs/footprint/00-共同上下文.md` §2.1/§2.4 的"`seatUnplaced` 只对无行卡排座"断言**不含本 bug**，本批修完需在 footprint 契约登记一条勘误（由主 agent 在验收阶段统一回写）。
5. **与 F1 的关系**：F1 治的是"声明尺寸 ≠ 实测尺寸导致的重叠"；本 bug 是"批内座位互不知情（位置 + z 序双双不更新）"，**两者独立、都要修**。
6. **边界（实测已确认，勿扩大）**：`seatNear`（`:1157`）一次只排**一张**卡、且每次新算 nextZ（`:1191`），**不中招**；`reseatLayer` 有 push（`:807/:826`），**不中招**。本 bug **只在 `seatUnplaced` 的批量路径**。验收断言只针对该函数，不要顺手改另两处。

## 3. 冻结决定

### 3.1 端点形态：独立 `/api/nook`，复用 `LayerState` 形状（B 方案，用户 2026-09-13 拍板）

**新增 `GET /api/nook?character=<id>`**，返回体**与 `/api/layer` 的 `LayerState` 逐字段同形**（`layer, scene, bg, audio, items, links, presence, worldFrozen`），其中：

- `layer` 字段填 **nook id**（本批冻结为 `characters/<id>`，见 §3.2）；
- `scene` 为**该角色 README**（nook 门面）；若缺 README，返回 `null`（不合成 stub，交由前端走空态）；
- `items` 为 `characters/<id>/` **直接子目录的全部 md**（除 README.md 自身）；
- `bg` / `audio` 从该角色 README 的 frontmatter 读（复用 `readLayerBg` / `readLayerAudio`，**`characters/` 不继承 map 的三态语义**——本批直接取 own，无 inheritance）；
- `links` / `presence`：**本批返回空数组**（小天地本批不做关系线与在场，登记为后续）。

**为什么不动 layer 地基（否决 A 方案）**：`layers.ts` 是前后端共用的纯函数，把 `characters/**` 塞进 `deriveLayers` 会同时改变 `cardsOfLayer`/`childLayers`/`layerOfPath` 与所有既有世界的层树——影响面远超本批价值，且与「层 = 场景」的产品语义冲突（小天地不是场景）。

**为什么不是 C 方案（`/api/layer?layer=characters/ryo`）**：`POST /api/card/footprint` 有 `resolveLayer` 门禁（`routes/world.ts:648`，要求 `resolveLayer(dirOfLayer(layer)) === layer`），对 `characters/**` 必 404 → 实测占位永远写不回 → 长卡片重叠。**复用 C 等于把 AGENTS §7.5 的老 bug 再犯一遍。**

### 3.2 nook id 的形状（冻结）

**`nookId = "characters/<id>"`**（相世界根相对路径，无前导 `/`，无尾随 `/`）。

- 路由入参用 `?character=<id>`（**只传角色 id，不传路径**，避免路径穿越；服务端拼 `characters/${id}`）。
- `<id>` MUST 通过 `^[a-z0-9][a-z0-9-]*$` 校验（ASCII kebab-case，见 `AGENTS.md §1.1`）；失败 → **400 `invalid_argument`**。
- `<id>` 对应的目录 MUST 存在于世界根下（`characters/<id>/` 是目录）；不存在 → **404 `not_found`**。
- **MUST NOT** 接受 `characters/<id>/../..` 之类的相对路径（校验闸在 id 正则，不在路径 normalize）。

### 3.3 占位尺寸的复用（**关键**）

小天地的卡片**同样要写 `cards` 行、同样要回写实测尺寸**。两条路径：

1. **读**：`GET /api/nook` 在组装 `items` 时，**完全复用** `/api/layer` 的坐席逻辑（`seatUnplaced` + `reseatLayer` + `storedSizeOf`/`declaredSizeOf`），row 匹配同样是 `cards.id = path` ONLY。
2. **写**：`POST /api/card/footprint` **新增一条 layer 门禁分支** —— 当 `layer` 形如 `characters/<id>` 时，用与 `/api/nook` 相同的 id 校验；**MUST NOT** 走 `resolveLayer`（它必然返回 null）。

> ⚠️ **这是本批唯一需要触碰 footprint 契约的地方，且只加分支、不改形状。** owner = `04-占位与回写`。若实现中发现必须改 `docs/footprint/00` 的既有条文，MUST 报主 agent。

**`layer` 列的取值（冻结）**：小天地的 `cards.layer` 存 **`characters/<id>`**（完整 nookId），与 `id = path` 的行匹配键解耦。理由同 footprint §3.3 BLOCKER-2：跨层门牌 README 已在证明「`cards.layer` 不必等于展示它的层」。

### 3.4 入口（冻结）

**角色 tab 每行新增第 4 个按钮「Nook」**（`RightSidebar.tsx` 现有 3 按钮之后）：

- 文案键 `copy.nook`（en/ja 两套；i18n 目前无此键，需新增）。
- 点击 → `onOpenNook?.(char.id)` ——**与 `onChatWithCharacter` 对称的新 callback**，由 `App.tsx` 提供。
- **MUST NOT** 复用「聊」或「导航」按钮的语义（doc-06 §5.4：导航=切层、聊=遮罩、跟=在场、nook=进私人空间，四者互斥）。

`App.tsx` 的新状态 **`nookChar: string | null`**：非空即渲染 `NookView`，`null` 渲染既有 `Canvas`。**不引入路由库、不改 `currentLayer` 语义。**

### 3.5 微动立绘组件（`portrait` kind）

**新增一个 kind `portrait`**，落在 `room` pack（该 pack 注释已写「room — a character's private nook」，语义正对）。

| 项 | 冻结值 |
|---|---|
| kind 名 | `portrait`（单数，kebab-safe） |
| pack | `room` |
| 声明尺寸 | `CARD_FORMS.portrait = { label: 'Portrait', w: 288, h: 384, chrome: 'bare' }`（**2026-09-13 裁决，采纳 03 篇的数**：3:4 = 现有立绘 1080×1440 的实测比例；288 = 同 `room` pack 的 `board.w`，与周围卡（`diary` 208 / `thread` 300）同量级。初稿 360×480 是主 agent 的 `[推断]`，已被 03 的实测依据取代。** 02/03/05 一律按 288×384） |

| 渲染 | `<video autoPlay loop muted playsInline preload="metadata">`，`poster` 或静态 `<img>` 为回退 |

### 3.7 拖卡通路：`arrangeCards` 的 nook 分支（**2026-09-13 实测修正，主 agent 此前判断有误**）

**撤回一条先前的错误广播**：主 agent 曾广播「`/api/card/position` 无 layer 门禁，小天地拖卡天然可用，无需新增路由」。**这条是错的**——只读了路由层（`routes/world.ts:609-618`，确实不做 layer 校验），漏读了动作层内部。子代理 `NookView02` 实测反驳并经主 agent 复核确认：

`packages/shared/src/actions/canvas.ts:457-464`（`hasPlace` 分支）：

```ts
await assertCardExists(store, place.path);
const layer = await store.resolveLayer(place.path);
if (layer === null) {
  fail('not_found', `"${place.path}" is not on a canvas layer; arrange can only place cards shown on a layer page.`);

```

`resolveLayer`（`local-store.ts:550-556`）对 `characters/**` **逐字返回 null** → nook 路径拖卡**必 404**。

**影响（2026-09-13 实测更正）**：nook 路径拖卡时 `arrangeCards` 抛 `not_found` → 路由 catch 直接返回 404，**`card_position` 帧不会广播**（广播在 `await arrangeCards` **成功之后**，`routes/world.ts:610-611`）。表现为「拖了又弹回去」的成因是**前端乐观更新回滚**（`useWorld.moveCard` 失败分支，`useWorld.ts:161-164`），**不是**"帧先到、HTTP 后 404"——初稿此描述有误，由子代理 `NookRoute01` 实测更正。

**裁决（冻结）：走 `arrangeCards` 的 nook 分支**（否决另两条）：

| 方案 | 裁决 | 理由 |
|---|---|---|
| **(a) `arrangeCards` 加 nook 分支** | ✅ **采用** | 与 §3.3 footprint 门禁分支**同型**；`arrangeCards` 是玩家 UI（`routes/world.ts:610`）与 Agent 工具（`extensions/toolkit/arrange.ts:86`）的**唯一共同入口**，一处改动双端共享；保留 `seatDeclaredRows`（row-creating path，契约 §5.5 要求新行不得是 schema DEFAULT）与动作层 details/事件归属 |
| (b) 路由层绕开 `arrangeCards` 直呼 `store.placeCard` | ❌ 否决 | 丢掉动作层语义（`arrange` 的 details/落账/工具面一致性），制造第二条摆放通路 |
