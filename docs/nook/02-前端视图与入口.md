## ① 一句话定位

**给角色 tab 加第 4 个按钮（Nook），点击后 `App` 把主工作区从「层画布」切成「某个角色的私人空间画布」——同一个 `Canvas` 组件、同一条拖卡通路、同一套实测回写，只有取数端点和空态不同。**

本批判据（00 §4）：玩家能从角色 tab 走进一个角色的私人空间，看见那里的陈设（含一件会动的立绘），并能在里面正常看卡/拖卡。

## ③ 行为契约逐步（每步写「漏了会怎样」）

### 3.1 进入（`RightSidebar` 第 4 按钮 → `App`）

1. 玩家点角色行第 4 按钮 → `onOpenNook?.(char.id)`。
2. `App` 侧：`handleOpenNook(charId)`：
   - `camera.save(currentLayer)`——把层相机存进 `CAM_MEMORY[currentLayer]`（`useCamera.ts:150-152`）。
   - `setNookChar(charId)`。
   - **不** `sendMessage({type:'character_start'})`（那是「聊」的语义，doc-06 §5.4；四按钮互斥，00 §3.4）。
3. `nookChar` 非空 → 主工作区渲染 `NookView` 取代 `Canvas`（渲染落点见 §⑧）。

**漏了会怎样**：不 `camera.save` → 关掉小天地后层画布回到上次记住的相机或 `DEFAULT_VIEW`（`useCamera.ts:35`），玩家在层里的位置丢失。

### 3.2 取数

4. `NookView` mount / `characterId` 变化 → `fetchNook(characterId)`。
5. 成功：把响应喂进 `state`。**响应里 `layer` 字段是 nookId**（`characters/<id>`，00 §5.1）——组件用它做 footprint 的 layer 实参（§3.6），**不要**自己拼 nookId。
6. 失败：`error` 置位，渲染错误态（§⑦），**不清空** `state`（避免从「有内容」闪回空白）。

**漏了会怎样**：把 `layer` 拼成 `nook/${characterId}` 之类的自造形状 → `POST /api/card/footprint` 的 nook 门禁（00 §3.3）判 404，实测高度永不回写。

### 3.3 渲染（复用 `Canvas`，见 §⑧ 与 §⑫-1）

7. `state.items` → `<Canvas items={state.items} …/>`；`state.scene`（角色 README 或 `null`）→ `scene`；`state.bg` → `bg`。
8. `currentLayer={state.layer}`（= nookId）——`Canvas` 只用它做相机记忆 key（`Canvas.tsx:117-125`），对 nook 是**恰好正确**的语义：进出小天地各记一次相机。
9. `links={[]}`、`presence` 不进 `Canvas`（`Canvas` 不吃 presence）：本批 00 §3.1 冻结 `links/presence` 为空数组。

**漏了会怎样**：`currentLayer` 传 `currentLayer`（层 id）→ 小天地和层共用相机记忆，进出时相机会互相覆盖。

### 3.4 关掉（返回）

10. 返回按钮 / `Escape` → `onClose()`。
11. `App` 侧 `handleCloseNook`：
    - `setNookChar(null)`；
    - `camera.restore(currentLayer)`——层请求发出去**之前**同步（乐观重取），避免 `Canvas` 用错的相机画一帧（对照 `enterLayer` 的既有约定，`useWorld.ts:enterLayer`）；
    - `void refresh()`——`useWorld` 的 `refresh()`（`useWorld.ts:refresh`，`return` 块 `:400-411` 导出），层数据是**读时求值**的，可能已过期。

**漏了会怎样**：不 `refresh` → 若 `NookView` 的 `airp:world-event` 监听尚未首触发（或事件在 WS 断线期丢了），层画布显示陈旧内容。**注意**：`useWorld` 在 nook 期间**照常**收到 `file_changed` 并重取层（§⑥，`useWorld` 零改动），所以这条 `refresh` 是**兜底而非唯一来源**——不存在"层数据一定陈旧"的情形。

`Escape` 的**互斥**：`App.tsx` 现有 Esc → `handleReturnToParent`（`useCallback` 在 `:275-279`，**监听 effect 在 `:281-290`**）。Esc 分支改写为：`nookChar !== null` 时调 `handleCloseNook()` 并 `return`（**复用同一个**函数，不要在 Esc handler 里重抄 save/restore/refresh——三处状态改动必须只有一处实现）。`NookView` **不自挂**第二个 `keydown` 监听。

**漏了会怎样**：在小天地里按 Esc → 层悄悄切到父层，关掉小天地后玩家落到别处。

### 3.6 实测回写（footprint）

15. `NookView` **自建**一个 footprint 调度器实例：

```ts
const fpRef = useRef<FootprintScheduler | null>(null);
useEffect(() => {
  const scheduler = createFootprintScheduler({
    layer: () => nookIdRef.current,                                   // = state.layer
    widths: () => new Map((stateRef.current?.items ?? []).map(it => [it.path, it.w])),
    measure: () => measureHeights(),
    post: async (l, boxes) => { /* POST /api/card/footprint { layer: l, boxes } */ },
    isBusy: () => false,          // nook 本批不消费 writer 的 tool_start/tool_end
    isDragging: () => document.querySelector('.object.dragging-item') !== null,
  });
  fpRef.current = scheduler;
  return () => { scheduler.dispose(); fpRef.current = null; };
}, []);
```

**为什么必须自建**（不是可选用法）：调度器目前**只存在于 `useWorld` 内**（`useWorld.ts:235-267`，`createFootprintScheduler` 调用在 `:238`），且 `widths` 读的是**层**的 items、`layer` 读的是层的游标；而 `measureHeights()`（`lib/footprint.ts:73`）扫的是 `document` 全局的 `.object[data-path]`。进小天地后 nook 卡也在 DOM 里，但其 path 不在层 widths map 中 → `footprint.ts` 的 flush 循环（`for (const [path,h] of heights)`，`const w = widths.get(path)` 取不到即 `continue`）直接跳过 → **nook 卡实测高度永不回写**，`cards.width/height` 停在声明值 → 长 chalk 卡（实测 578px vs 声明 190px）与邻居重叠，正是 `AGENTS §7.5` 的病灶。

**漏了会怎样**：看卡正常，但拖卡时碰撞盒用的是声明尺寸 → 卡片视觉重叠、链线错位；且服务端排座（下次进小天地）也用声明尺寸。

`createFootprintScheduler` 是导出的纯工厂（`lib/footprint.ts:93`，时间与副作用全注入），第二实例不与 `useWorld` 的实例冲突：两者的 `measureHeights()` 都扫全局，但各自只提交**自己 widths map 里的 path**（`footprint.ts:170-173`）——天然互斥。

**三个必须照抄的条件（漏一个就等于没做）**：

1. **必须在 `fontsSettled` 之后 arm 第一次测量**。`useWorld` 的做法见 `useWorld.ts:272-303`：`whenFontsSettled()`（`lib/fonts.ts`）未落定前不 `notify()`——字体度量决定换行（355px → 291px，footprint 契约 §3.5）。**漏了会怎样**：首进小天地实测高度偏小 → 写回一个错的 `cards.height` → 下次排座按错值。
2. **必须给每个 `.object` 挂 `ResizeObserver`**（`useWorld.ts:278-283`），payload 变化时重挂。**漏了会怎样**：卡片内容变化（如 `portrait` 视频加载后尺寸变化）不触发重测，行值永久停在首测值。
3. **`document.hidden` 时 `notify()` 被调度器自行阻断**（`footprint.ts:100,142` `isHidden()`），无需自己处理——但**不要在 hidden 时 `dispose()`**，否则切回前台不再测。

**重取机制：复用既有的 `airp:world-event`，不新造事件名。**

`useWorld.ts:318-321`（switch **之前**，wiring A 档已落地）无条件转发：

```ts
if (msg.type === 'file_changed' || msg.type === 'card_position') {
  // App listens for this to keep its backpack/character views in sync.
  window.dispatchEvent(new CustomEvent('airp:world-event', { detail: msg }));

```

（另有一处 `world_event` → `entity_*` 的转发走 `forwardWorldEvent`，`useWorld.ts:224-233`。）

该事件名是**既有契约**（`docs/wiring/00 §5` 冻结其转发集合，含 `file_changed`；`App.tsx` 已是消费者，`airp:world-event` 监听在 `App.tsx` 的 `useEffect` 内）。故 `NookView` 只需：

```ts
useEffect(() => {
  const onWorldEvent = (e: Event) => {
    const msg = (e as CustomEvent).detail;
    if (msg?.type === 'file_changed') void fetchNook(characterId);
  };
  window.addEventListener('airp:world-event', onWorldEvent);
  return () => window.removeEventListener('airp:world-event', onWorldEvent);
}, [characterId]);
```

**为什么这样比"改 `useWorld` 的 switch"好**：
- **零新契约**：不引入 `airp:nook-changed`（原稿的方案，已废弃）；
- **零改动 `useWorld`**：仍在 nook 里跑的那次 `fetchLayer(layerRef.current)`（`useWorld.ts:323-324`）取的是**层**的数据——**无害且有益**：玩家退出小天地时层数据已是热的（`handleCloseNook` 的 `refresh()` 仍在，作兜底双保险）；且 `Canvas` 未渲染 → 无孤儿 DOM、无 footprint 串扰（`measureHeights()` 扫不到任何 `.object`）。
- **不碰 `layerRef`**：nook 不进入层游标（00 §3.4）。

**漏了会怎样**：作家在小天地里写了新陈设 → `file_changed` 到了但无人重取，小天地永远看不到新文件（玩家得退出再进）。

**已知取舍（登记）**：重取粒度为**整个 nook**（不做增量合并）——与 `wiring/00 §4` 对 `world_event` 的"本批最小实现：整层重取"同口径。

## ⑦ 错误边界

| 情况 | 服务端 | `NookView` 呈现 |
|---|---|---|
| 角色 id 非法（不匹配 `/^[a-z0-9][a-z0-9-]*$/`） | 400 `{ok:false,code:'invalid_argument'}` | 错误态 + `nookError`；**不重试**（id 是编辑器/后端给错，重试无用） |
| 角色目录不存在 | 404 `{ok:false,code:'not_found'}` | 同上 |
| 未加载世界 | 400 `{error:'No active world'}`（**无 `code`**） | 错误态；文案按 `error` 原样（这条与 `/api/layer` 同款，见 §⑪-4） |
| 网络/解析失败 | — | 错误态 + `nookRetry` 按钮 |
| `scene === null` 且 `items` 空 | 200 | **不是错误**，是空态（§3.8） |
| `scene === null` 但 `items` 非空 | 200 | 正常画布，无 `SceneChalk`（`SceneChalk.tsx:31` `if (!scene) return null`） |

**错误态的三种可读骨架**（实现要求具体，不能只写"错误态"）：

1. **错误横幅**：`role="alert"` + `nookError` 文案 + HTTP 状态与 `code`（如有）+ 原始 `error` 字符串。**不用 toast**——`App` 的 toast（`:133-137`）3.5s 自灭，而取数失败是**持续状态**，不是瞬时事件。
2. **`<details>` 展开原始响应体**：`docs/tools/00` 硬约束 4 要求失败在 UI 可见；`console.warn` 不算可见。
3. **`nookRetry` 按钮**：重发 `fetchNook(characterId)`。**仅非 4xx** 显示——4xx 是确定性问题（id 非法 / 目录不存在），重试不会变。**漏了会怎样**：所有错误都给重试按钮 → 玩家对着必 404 的按钮反复点，以为是自己网不好。

**挂载期的错误必须有唯一的"最后一次请求胜出"守卫**：`fetchNook` 用 `useRef` 存 `reqSeq`（照 `useWorld.ts:92-102` 的既有做法），`characterId` 快速切换时丢弃陈旧响应。**漏了会怎样**：先点 A 角色再点 B 角色，A 的慢响应后到 → 画布显示 A 的陈设而标题是 B。

**不许 `console.warn` 当失败可见**（00 §6 反模式 4）：`useWorld.fetchLayer` 现在这么做（`useWorld.ts:97-99`），**`NookView` 不得照抄**。

`error` 态下**保留** `state` 的旧值（§3.2 步 6）——玩家在小天地里时世界被换掉（`POST /api/worlds/load`）会在错误态里保留旧画布，比闪白好。

## ⑪ 发现的冲突
