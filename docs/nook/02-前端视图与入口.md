## ① 一句话定位

**给角色 tab 加第 4 个按钮（Nook），点击后 `App` 把主工作区从「层画布」切成「某个角色的私人空间画布」——同一个 `Canvas` 组件、同一条拖卡通路、同一套实测回写，只有取数端点和空态不同。**

本批判据（00 §4）：玩家能从角色 tab 走进一个角色的私人空间，看见那里的陈设（含一件会动的立绘），并能在里面正常看卡/拖卡。

## ③ 行为契约逐步（每步写「漏了会怎样」）

### 3.1 进入（App inline character rail 私密空间按钮 → App）

1. 玩家点角色行的私密空间按钮 → `onOpenNook(char.id)`（required，不能 optional-chain）。
2. `App` 侧：`handleOpenNook(charId)`：
   - `CameraMemoryStack.pushTransition(current → {projection:'nook', identity: charId, slot: 'nook:'+charId})`——caller snapshot 由 UX05 stack 保存；不直接调用 `camera.save(currentLayer)`。
   - `setNookChar(charId)`，并让 Nook 成为唯一 active projection；底层 layer Canvas inert/unmounted。
   - **不** `sendMessage({type:'character_start'})`（那是「聊」的语义，doc-06 §5.4；按钮互斥，00 §3.4）。
3. `nookChar` 非空 → 主工作区渲染 `NookView` 取代 `Canvas`（渲染落点见 §⑧）。

**漏了会怎样**：不 push caller snapshot → 关掉小天地后层画布回到错误相机；保留底层 Canvas → 两个 projection 继续响应全局测量/拖拽。

### 3.2 取数

4. `NookView` mount / `characterId` 变化 → `fetchNook(characterId)`。
5. 成功：把响应喂进 `state`。**响应里 `layer` 字段是 nookId**（`characters/<id>`，00 §5.1）——组件用它做 footprint 的 layer 实参（§3.6），**不要**自己拼 nookId。
5a. `fetchNook` 成功后，Nook active projection 才执行 `CameraMemoryStack.restoreTarget({projection:'nook', identity: characterId, slot:'nook:'+characterId})`；有保存 target 则恢复，无保存则用 Nook default framing。空 Nook 也必须执行该步骤，不能沿用 caller layer camera。
6. 失败：`error` 置位，渲染错误态（§⑦），**不清空** `state`（避免从「有内容」闪回空白）。

**漏了会怎样**：把 `layer` 拼成 `nook/${characterId}` 之类的自造形状 → `POST /api/card/footprint` 的 nook 门禁（00 §3.3）判 404，实测高度永不回写。

### 3.3 渲染（复用 `Canvas`，见 §⑧ 与 §⑫-1）

7. `state.items` → `<Canvas items={state.items} …/>`；`state.scene`（角色 README 或 `null`）→ `scene`；`state.bg` → `bg`。
8. `currentLayer={state.layer}`（= nookId）——`Canvas` 只用它做相机记忆 key（`Canvas.tsx:117-125`），对 nook 是**恰好正确**的语义：进出小天地各记一次相机。
9. `links={[]}`、`presence` 不进 `Canvas`（`Canvas` 不吃 presence）：本批 00 §3.1 冻结 `links/presence` 为空数组。

**漏了会怎样**：`currentLayer` 传 `currentLayer`（层 id）→ 小天地和层共用相机记忆，进出时相机会互相覆盖。

### 3.4 关掉（返回）

10. 返回按钮 / `Escape` → `onClose()`。
11. `App` 侧 `handleCloseNook`：
    - `CameraMemoryStack.popTransition({projection:'layer', identity: currentLayer})` 并 `restoreProjection(frame)`；不调用 `camera.restore(currentLayer)` 固定槽；
    - `setNookChar(null)`；
    - `void refresh()`——`useWorld` 的读侧重取是回到 layer projection 的兜底，不替代 stack restore。

**漏了会怎样**：不 `refresh` → 若 `NookView` 的 `airp:world-event` 监听尚未首触发（或事件在 WS 断线期丢了），层画布显示陈旧内容。**注意**：`useWorld` 在 nook 期间**照常**收到 `file_changed` 并重取层（§⑥，`useWorld` 零改动），所以这条 `refresh` 是**兜底而非唯一来源**——不存在"层数据一定陈旧"的情形。

`Escape` 的**互斥**：`App.tsx` 现有 Esc → `handleReturnToParent`（`useCallback` 在 `:275-279`，**监听 effect 在 `:281-290`**）。Esc 分支改写为：`nookChar !== null` 时调 `handleCloseNook()` 并 `return`（**复用同一个**函数，不要在 Esc handler 里重抄 save/restore/refresh——三处状态改动必须只有一处实现）。`NookView` **不自挂**第二个 `keydown` 监听。

**漏了会怎样**：在小天地里按 Esc → 层悄悄切到父层，关掉小天地后玩家落到别处。

### 3.5 拖卡 / 看卡（**本节的确定答案**）

12. 拖卡走 `Canvas.onMoveCard` → `moveCard`（`useWorld.ts:moveCard`，失败回滚在 **`:184-188`**）→ `POST /api/card/position`。
13. **`POST /api/card/position` 无 layer 门禁**（`routes/world.ts:596-620` 只校验 `path/x/y`），但它内部转 `arrangeCards`，而 `arrangeCards` 的 place 分支**有** `resolveLayer(path)===null → 404`（`packages/shared/src/actions/canvas.ts:457-464`；`resolveLayer` 对 `characters/**` 返回 null，`local-store.ts:550-556`）。实测：

FAIL arrangeCards | not_found | 404 | "characters/watson/README.md" is not on a canvas layer;

→ **小天地拖卡当前不通**，必须按 **00 §3.7** 给 `arrangeCards` 加 nook 分支后**才**可用。`NookView` 侧就是原样把 `moveCard` 交给 `Canvas`，**不新增端点、不绕开动作层**。

### 3.6 实测回写（footprint）

15. `NookView` **自建**一个 footprint 调度器实例：
`writerPublicState` 由 App/UX03 注入的同一 public projection；Nook 不建立 writer busy ref，也不使用 `writerToolsInFlight`。
```ts
const fpRef = useRef<FootprintScheduler | null>(null);
useEffect(() => {
  const scheduler = createFootprintScheduler({
    layer: () => nookIdRef.current,                                   // = state.layer
    widths: () => new Map((stateRef.current?.items ?? []).map(it => [it.path, it.w])),
    measure: () => measureHeights(),
    post: async (l, boxes) => { /* POST /api/card/footprint { layer: l, boxes } */ },
    isBusy: () => writerPublicState.phase === 'writing' || writerPublicState.toolCount > 0,
    isDragging: () => document.querySelector('.object.dragging-item') !== null,
  });
  fpRef.current = scheduler;
  return () => { scheduler.dispose(); fpRef.current = null; };
}, []);
```

**为什么必须自建**（不是可选用法）：调度器目前**只存在于 `useWorld` 内**（`useWorld.ts:235-267`，`createFootprintScheduler` 调用在 `:238`），且 `widths` 读的是**层**的 items、`layer` 读的是层的游标；而 `measureHeights()`（`lib/footprint.ts:73`）扫的是 `document` 全局的 `.object[data-path]`。进小天地后 nook 卡也在 DOM 里，但其 path 不在层 widths map 中 → `footprint.ts` 的 flush 循环（`for (const [path,h] of heights)`，`const w = widths.get(path)` 取不到即 `continue`）直接跳过 → **nook 卡实测高度永不回写**，`cards.width/height` 停在声明值 → 长 chalk 卡（实测 578px vs 声明 190px）与邻居重叠，正是 `AGENTS §7.5` 的病灶。

**漏了会怎样**：看卡正常，但拖卡时碰撞盒用的是声明尺寸 → 卡片视觉重叠、链线错位；且服务端排座（下次进小天地）也用声明尺寸。

`createFootprintScheduler` 是导出的纯工厂（`lib/footprint.ts:93`，时间与副作用全注入），第二实例不与 `useWorld` 的实例冲突：两者的 `measureHeights()` 都扫全局，但各自只提交**自己 widths map 里的 path**（`footprint.ts:170-173`）——天然互斥。

**三个必须照抄的条件（漏一个就等于没做）**：

1. **必须在 `fontsSettled` 之后 arm 第一次测量**。`useWorld` 的做法见 `useWorld.ts:272-303`：`whenFontsSettled()`（`lib/fonts.ts`）未落定前不 `notify()`——字体度量决定换行（355px → 291px，footprint 契约 §3.5）。**漏了会怎样**：首进小天地实测高度偏小 → 写回一个错的 `cards.height` → 下次排座按错值。
2. **必须给每个 `.object` 挂 `ResizeObserver`**（`useWorld.ts:278-283`），payload 变化时重挂。**漏了会怎样**：卡片内容变化（如 `portrait` 视频加载后尺寸变化）不触发重测，行值永久停在首测值。
3. **`document.hidden` 时 `notify()` 被调度器自行阻断**（`footprint.ts:100,142` `isHidden()`），无需自己处理——但**不要在 hidden 时 `dispose()`**，否则切回前台不再测。

## ⑦ 错误边界

| 情况 | 服务端 | `NookView` 呈现 |
|---|---|---|
| 角色 id 非法（不匹配 `/^[a-z0-9][a-z0-9-]*$/`） | 400 `{ok:false,code:'invalid_argument'}` | 错误态 + `nookError`；**不重试**（id 是编辑器/后端给错，重试无用） |
| 角色目录不存在 | 404 `{ok:false,code:'not_found'}` | 同上 |
| 未加载世界 | 400 `{error:'No active world'}`（**无 `code`**） | 错误态；文案按 `error` 原样（这条与 `/api/layer` 同款，见 §⑪-4） |
| 网络/解析失败 | — | 错误态 + `nookRetry` 按钮 |
| `scene === null` 且 `items` 空 | 200 | **不是错误**，是空态（§3.8） |
| `scene === null` 但 `items` 非空 | 200 | 正常画布，无 `SceneChalk`（`SceneChalk.tsx:31` `if (!scene) return null`） |

**错误态的三种可读骨架**（实现要求具体，不能只写"错误态"）：

1. **错误横幅**：`role="alert"` + `nookError` 文案 + HTTP 状态与 `code`（如有）+ 原始 `error` 字符串。**不用 toast**——`App` 的 toast（`:133-137`）3.5s 自灭，而取数失败是**持续状态**，不是瞬时事件。
2. **`<details>` 展开原始响应体**：`docs/tools/00` 硬约束 4 要求失败在 UI 可见；`console.warn` 不算可见。
3. **`nookRetry` 按钮**：重发 `fetchNook(characterId)`。**仅非 4xx** 显示——4xx 是确定性问题（id 非法 / 目录不存在），重试不会变。**漏了会怎样**：所有错误都给重试按钮 → 玩家对着必 404 的按钮反复点，以为是自己网不好。

**挂载期的错误必须有唯一的"最后一次请求胜出"守卫**：`fetchNook` 用 `useRef` 存 `reqSeq`（照 `useWorld.ts:92-102` 的既有做法），`characterId` 快速切换时丢弃陈旧响应。**漏了会怎样**：先点 A 角色再点 B 角色，A 的慢响应后到 → 画布显示 A 的陈设而标题是 B。

**不许 `console.warn` 当失败可见**（00 §6 反模式 4）：`useWorld.fetchLayer` 现在这么做（`useWorld.ts:97-99`），**`NookView` 不得照抄**。

`error` 态下**保留** `state` 的旧值（§3.2 步 6）——玩家在小天地里时世界被换掉（`POST /api/worlds/load`）会在错误态里保留旧画布，比闪白好。

## ⑪ 发现的冲突

1. **footprint 调度器只服务层**（严重，跨 02/04 边界）。`useWorld.ts:235-267` 的调度器 `widths` 读层 items；`lib/footprint.ts:73` 的 `measureHeights()` 扫全局 `.object[data-path]`。→ nook 卡在 DOM 里却进不了 boxes。**02 的解法**：`NookView` 自建第二实例（§3.6）。已按边界协调发消息给 `Footprint04`：**前端测量归 02**（组件内部），04 只 own 服务端 footprint 的 nook 门禁分支 + `cards.layer` 取值。若 04 已在自己文档里写了 nook 测量通道，以 04 为准并删本节（待其回复确认）。

2. **`RightSidebar.tsx:122` 的头像 fallback 是裸绝对路径**：`char.avatar || '/assets/characters/portraits/lady_1.png'`。与 `/api/asset?path=` 口径（00 §5.4；主 agent 实测：`path=` 相对**世界根**解析，L476 实测 `templates/firstsnow/characters/nanami/README.md` 的 `avatar: /api/asset?path=assets/characters/nanami.webp` → 真实文件 `templates/firstsnow/assets/characters/nanami.webp`；现有立绘 1080×1440）**不一致**。`/api/characters` 自己也内置了另一个 fallback（`routes/world.ts:553`：`'/assets/characters/portraits/fella_1.png'`）——**两处 fallback 且都不是 `/api/asset` 形状**。本批**不改**（不在 02 范围），登记为回写项；**`NookView` 的存在核心条（§3.8 步 16）MUST NOT 沿用这两个常量**，必须走 `/api/asset?path=`。

3. **`gate` 卡在小天地里无意义**：`CardRenderer.tsx:165-166` 的单击目标是 `frontmatter.target || path.replace('/README.md','')`，喂给 `onEnterGate` → `POST /api/enter-layer`，而层 id 的取值域是 `world/**`。若角色目录里出现 `type: gate` 的 md，`NookView` **不给 `onEnterGate`**（§⑫-1）→ 点它静默无反应。这是**有意的静默**（比跳去错误的层好），但要在 03/05 里确认 `portrait`/`room` pack 不产出 gate 卡。

4. **`No active world` 响应无 `code` 字段**（`routes/world.ts:376`：`{ error: 'No active world' }`），而 nook 的 400/404 有 `code`（00 §5.1）。`NookView` 的错误态必须容忍 `code` 缺失。00 §5.1 已列出这条，但两种错误体形状不同——**写实现时别假设 `code` 恒存在**。

5. **`arrangeCards` 的 nook 分支归属 — 已解决（2026-09-13）**：原 00 §3.7 要点 4 把它署名给 02，落在 02 的「不改服务端」边界之外。02 发消息与 `NookRoute01` 对齐，01 **接**该分支（同侧文件），02 只 own 前端通路。**已写进 §8.4：02 消费、01 实现**。附带更正：校验函数落点从 `routes/world.ts` → `packages/shared/src/store/characters.ts` → **最终冻结为 `packages/shared/src/rules/characters.ts`**（契约 §5.2；shared 不能 import `apps/server`）。

6. **00 §3.5 的 `CARD_FORMS.portrait` 声明尺寸最终冻结为 `288×384`**（2026-09-13 裁决，采纳 03 篇实测：3:4 = 现有立绘 1080×1440 的实测比例；288 = 同 `room` pack 的 `board.w`）。**本文按 288×384 引用**；`02` 的代码**不依赖具体数值**（`NookView` 只用行值）。尺寸演进：`320×480`（初稿推断）→ `360×480`（主 agent 推断）→ **`288×384`（定稿）**。

## ⑫ UX batch implementation contract（supersedes N1 baseline）

1. `NookViewProps` 必须传入 N1 的 move/choice/full-details dice/take callbacks，以及 UX batch 的 `onOpenCharacterModal`、`onEntityAction`、`onItemDropOnTarget`、`onDropItemToScene`；这些动作缺失属于组装错误，不能 optional-chain 成 no-op。
2. `onActionResult` 由 NookView 自身的 action Adapter 消费并投影到 `ActionFeedbackStore`，不传给 Canvas（CanvasProps 没有该字段）；`onOpenRadialMenu` 与 `onEnterGate` 明确不传，Nook 不提供 Radial creator 或跨层 enter。
3. `onDiceRolled` 必须保留完整 `RollDiceDetails`，不能退化成 `(result, passed)`；详情进入 `DiceCeremonyInput` 的唯一 source owner。
4. Nook 成为唯一 active projection 时可以拥有一个 projection-scoped footprint scheduler；禁止第二 `useWorld`、第二 WS、第二 camera singleton 与两个 scheduler 同时扫描全局 `.object`。`isBusy` 读取 UX03 canonical `WriterPublicState.phase/toolCount`。
5. 进入/退出使用 UX05 `CameraMemoryStack` 的 caller snapshot + `restoreTarget`；空 Nook 也必须恢复 Nook default target，再回到 caller layer。
6. 这些条目取代本篇早期 §⑫-1/⑫-2 的 N1 baseline 省略/可选说明；旧内容只用于解释历史实现，不得作为 production implementation 依据。

3. `airp:world-event` listener 必须同时消费 `file_changed` 与 `world_event`；两者都触发 `/api/nook` 重取，必要时按 nook path 过滤。只监听 `file_changed` 会让玩家 note/角色批注在当前 projection 静默不出现。
4. `old-sailor` 等缺 README 的角色继续按 `scene:null/items:[]` 空态处理，不合成 stub；存在核心条只显示真实角色名，不造状态文案。
5. `stillPortraits` 由 motion owner 提供；Nook 只传入 Canvas，不在 NookView 自判 reduced motion 或另建 media scheduler。
6. Nook 初始化 `nook-init`、关系线/presence、背景视频与新建/删除卡片仍不在 N1/UX batch；若以后启用，另开契约与验收。
