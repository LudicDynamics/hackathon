## 2. 视觉语法总则

### 2.1 结论先行

1. **一张暖墨画布。** 画布、Nook 和阅读层共享同一组暖纸/暖墨 token；材质变化只能是 Adapter 的受控变化，不能变成第二套主题。
2. **内容比家具更响。** v2 的圆角、低饱和三色、漫射软影和留白替代旧手账路线的贴纸、钉子、红笔划痕；这不是取消层次，而是把层次交给表面、明度和空间关系。
3. **身份靠字形。** LXGW WenKai 表达人写的正文，Caveat 表达画布手写，Manrope 表达拉丁 UI，DM Mono 表达机器元数据。字体不因 appearance 任意改变语义身份。
4. **一个对象一个表面身份。** shell 不给 Chalk 兜底纸面；读取、Shelf、Nook、dialogue 只在各自语义上引入纸面，不把它们伪装成卡片。
5. **动效是连续的，不是装饰噪声。** 成形、洇墨、轻呼吸和软影只服务状态；关闭 Effects 或 reduced motion 后保留信息、焦点与错误文案，不保留无必要循环。

### 2.2 四层职责图

```text
World context (material / bg / audio)
        ↓ 只决定舞台背景 Adapter
Global shell (viewport / stage / chrome / overlay frame)
        ↓ 只提供全局 semantic tokens
Entity view + AppearanceResolution
        ↓ 唯一 appearanceViewOf → 受信 appearance token
Surface content (Chalk / gate / note / letter / portrait / reading)
```

- **Module：shell**：管理 viewport、场景背景、全局 Chrome 的连续边界；不读取实体 `appearance` 来判断内容。
- **Module：surface**：声明一个平面的材质身份（transparent ink、paper、cream、dialogue paper）；不拥有动作结果、座位、Depth 数字。
- **Module：appearance**：仅管理单实体的五轴已验证值；由 `components` 的 registry/resolver 所有，UX 只定义其与 shell 的接缝。
- **Interface：Adapter**：`material/bgStyle` → stage surface；`AppearanceResolution` → `appearanceViewOf` → entity-local token；两者不能互相写入。
- **Seam：实体外壳**：`CanvasObject` 只注入位置、尺寸、旋转、实体 appearance 视图；shell 的视觉 token 可被实体内部消费，但不得被实体替换。
- **Leverage：统一 fallback**：resolution 缺失时沿旧 kind 默认；token 或装饰缺失时保持正文与互动，输出既有 diagnostics。
- **Locality：局部失败**：坏 appearance 只能影响单实体表面；不得让整层、Shelf、Nook 或 dialogue 白屏。

## 3. Global token contract

### 3.1 Token namespace 与来源

本篇建议新增 **NEW `--ux-*` 语义 token namespace**，只放在全局 token source（`apps/web/src/index.css :root` 的迁移终点）。它不是 appearance ID，也不登记到 `APPEARANCE_REGISTRY`。实现时可以把现有 canonical v2 值迁移为 `--ux-*`，但不得在 `prototype.css`、`scene-shell.css`、Tailwind、组件 JSX 再开同名 literal 来源。

`--appearance-*` 仍由 `docs/components/04-前端渲染与交互呈现.md:19-42` 的 `appearanceViewOf` 产生；它们是实体局部适配值。`--ux-*` 是 shell/默认 surface 的值。两者的 fallback 可以通过 CSS 变量引用连接，但不能复制 appearance registry 或凭 ID 在 React 中自行映射。

### 3.2 Color 与 surface

| 语义 token（NEW） | v2 基准 | 职责 | 禁止 |
|---|---|---|---|
| `--ux-color-wall` | `#d9d0bf` | viewport / stage 的暖墙底色 | 不能被单个实体改写 |
| `--ux-color-paper` | `#f4f0e8` | reading、dialogue、paper form 的纸面 | 不能作为 Chalk 默认背景 |
| `--ux-color-cream` | `#fbf8f1` | 轻亮实体、控件内面、焦点纸面 | 不能和 dark purple 形成第二主题 |
| `--ux-color-ink` | `#292820` | 主正文、标题、图标 | 不使用纯黑 |
| `--ux-color-muted` | `#777468` | 次要说明、时间印章、回执辅助文字 | 不放在低对比纸面上而不测量 |
| `--ux-color-line` | `rgba(41,40,32,.15)` | hairline、网格与静态分隔 | 不用中性黑 rgba 描边 |
| `--ux-color-rust` | `#c96f4c` | 作家/焦点/错误或结果强调 | 不恢复旧路线“所有强调都红” |
| `--ux-color-sage` | `#899b87` | 世界门卡、平静状态 | 不用作通用 success 文案 |
| `--ux-color-blue` | `#7893a2` | note/连接线/辅助信息 | 不改变动作成功含义 |
| `--ux-surface-stage` | `wall + radial gradient + 80px grid` | 场景空间底座；由 `SceneBackdrop`/`CanvasGrid` 消费 | 不在实体里重新绘制整屏背景 |
| `--ux-surface-transparent-ink` | `transparent` | Chalk bare surface | 不由 `.object` 或 `ink-form` 补 paper |
| `--ux-surface-paper` | `paper` /受控材质 | reading、dialogue、Shelf 目录的语义纸面 | 不把 overlay 变成一张普通 card |

值的基准来自 `docs/doc-04-视觉设计风格.md:182-192`；现有 `index.css:5-20` 已有同值 v2 根变量，但 legacy alias 与组件 literal 尚未清理。

**Surface 规则：**

- `stage` 是连续空间，不是卡片；其背景由世界/层 context Adapter 提供。
- `paper` 是可阅读的承载面；只有阅读、dialogue、Shelf 等明确语义才能使用。
- `transparent-ink` 是合法 surface，不是缺省错误；Chalk `.chalk--bare` 必须保持 transparent、无 border、无 shadow（现状证据：`apps/web/src/index.css:892-907`）。
- `ink-surface` 不是 v2 全局默认。现有背包等暗色面需要按组件语义决定是否保留为局部控件 surface，并登记迁移理由；不得扩散为 shell 背景。

| 语义 token（NEW） | 字体职责 | 允许消费面 | 现状证据/迁移 |

### 3.5 Responsive scale

响应式是 token 刻度与布局约束，不是把 `CARD_FORMS` 或 `item.w` 缩放成另一套尺寸：

| Band | 条件（语义断点） | Shell | Surface/阅读 | Typography/spacing |
|---|---|---|---|---|
| `desktop` | `min-width:1181px` | Header、journal、world meta、Writer 可同时存在；stage 保持呼吸 | reading inline 最大宽度沿原位展开；Shelf 不遮住主要入口 | 4/8 基础间距，正文使用 human step，machine 保持 9–12px |
| `narrow-desktop` | `701–1180px` | 收掉低优先级 status，保留主入口、返回、effects、language；不得挤压 World canvas | panel 以可滚动纸面承载，互动区必要时改 left/below，但不测量反馈循环 | spacing 降一档；标题只缩到下一 type step，不裁正文 |
| `phone` | `max-width:700px` | Header 横向可滚动；journal/hand tray/dock 进入明确车道，安全区参与计算 | reading/Shelf/Dialog 不超出安全边界；Nook 使用整屏 active projection 而不是内嵌第二 Canvas | 触控目标 ≥44px；正文最小可读字号不因宽度被压扁；长文只在内容区滚动 |
| `390×844` fixture | exact viewport | 验证 safe-area、键盘前后、Shelf/reading/dialogue 关闭路径 | 不允许 horizontal overflow；Chalk bare 不因壳宽度变纸卡 | 验证 title、状态、错误、焦点 ring 均可见 |

现状断点分裂在 `prototype.css:703-707,709-786`、`scene-shell.css:149-171`、`prop-card.css:28-29`，分别使用 1180/700、600/700、600；这不是设计上的三套 band。迁移时保留断点语义而非复制 media block，所有新 token 只能从上述 band 消费。

## 4. AppearanceResolution 的消费与分层

### 4.1 唯一数据路径

1. 服务端在 `/api/layer` 与 `/api/nook` 的 `items[]` 上附带可选已验证 `appearance: AppearanceResolution`；形状由 `docs/components/00:87-89` 与 `docs/components/01:94-103` 冻结。
2. `useWorld.LayerItem` 目前只有 `path/filename/kind/frontmatter/body/x/y/w/h/z/rot`（`apps/web/src/state/useWorld.ts:24-36`）；实现接线只增加可选 resolution，不让 `useWorld` 重算或从 raw frontmatter 取主题。
3. 前端唯一 Adapter 是 `apps/web/src/lib/appearance-view.ts`（NEW，归 `components/04`）：`appearanceViewOf(resolution)` 将已验证值转成受信 `data-appearance-*` 与 `--appearance-*`。A01 只规定它必须挂在 entity seam，不复制实现。
4. `CanvasObject` 的 `.object` 根节点一次消费该 view，`CardRenderer`、`ChalkCard`、`EntityInteractions` 和阅读层继承或显式传入同一 view；现有 shell position/width/rotation 仍归 `shellStyle`（`CanvasObject.tsx:151-170`）。
5. 缺 resolution 时按 kind 旧默认；有 warnings/fallback 时允许开发/测试看到稳定 code，但不能向玩家泄露 YAML、CSS、内部路径，也不能产生 appearance 事件。

**漏接后果：**如果任一 view 分支重新解析 raw `frontmatter.appearance`，卡面、阅读层和实体互动会各自选皮肤；未知值可能静默变成 CSS class，造成注入、跨端漂移和无法复现的主题。

### 4.2 registry 与 shell 的硬隔离

- `APPEARANCE_REGISTRY` 唯一登记 appearance ID、kind 能力、preset 与安全 token（`docs/components/01:113-168`）；A01 不声明 `ThemeRegistry`、`ShellAppearanceRegistry` 或第二张颜色表。
- `material`、`bgStyle`、`audio.theme` 是 world/layer context；`appearance` 是 entity input。`docs/components/02-主题包与渲染解析.md:15-21,27-43` 已明确二者隔离。
- shell 只能消费全局 `--ux-*` 与 stage Adapter；appearance 只能影响 entity-local `--appearance-*` 及固定 view 分支。appearance 禁止写 `left/top/width/height/transform/z-index`，也不能改变 `CARD_FORMS`、rotation、interaction 和 Depth。
- appearance ID 不得复用为 shell 状态名；例如 `parchment` 是受控 appearance/material 语义，不得把 `.shell--parchment` 当成第二套外壳 API。
- `AppearanceResolution.warnings/details` 是诊断，不是 shell 状态；其 shape 与来源必须回指 `components/01`，不得在本篇重述字段。

**漏接后果：**把实体 preset 当 shell class 会让切层、Shelf、Nook、dialogue 产生视觉跳变；把 shell token 写进 registry 会把全局换肤错误地绑定到某个 kind，破坏旧内容回退。

### 4.3 适配错误边界

| 故障 | 处理 | 必须保持 |
|---|---|---|
| item 缺 resolution（旧响应） | kind 旧默认，记录缺失仅供开发/测试 | 正文、互动、尺寸、位置、旋转、事件 |
| unknown preset/axis | 接受服务端 fallback resolution；不在 React 猜新值 | 内容可读，fallback diagnostics 可观察 |
| token metadata 缺失 | `token-missing` 后回 kind 安全 token（遵守 `components/04:42`） | 不白屏、不改变 action |
| view 缺失 | 使用 `GenericComponentView` 语义静态面（`components/04:69-73`） | `EntityInteractions` 仍负责 choice/status/dice/item |
| raw CSS/class/URL 进入 frontmatter | 写入拒绝；读取保留原文并诊断（`components/00:82-91`） | 不执行、不注入、不发伪造成功 |
| shell token 未加载 | 使用静态安全 fallback，显示内容优先 | 不等待 token 而隐藏实体 |

## 5. 行为顺序与漏接后果

这是实现应遵守的时序，不是新增事件或数据源：

1. **确定 world/layer context。** `SceneBackdrop` 从既有 bg/material 读取 stage surface；实体不参与 stage 决策。**漏接：**每张卡以自己的 preset 重画画布，切层时出现多套背景。
2. **确认 active projection。** Layer、reading、Nook、dialogue 只能有一个可交互投影；Nook 按 `docs/nook/00:121-126` 复用层语义而不是开第二 `useWorld`。**漏接：**两个 Canvas 同时响应 pointer/WS，焦点和相机记忆互相覆盖。
3. **接收 resolution。** 服务端唯一 resolver 已完成验证；React 只接收可选结果。**漏接：**前端与服务端默认值不同，刷新换皮或 warnings 消失。
4. **安装 shell token。** root stage、Chrome、overlay frame 使用 `--ux-*`，建立基础字体/颜色/影子/spacing。**漏接：**Chrome 继续从旧暗紫或旧直角 literal 读取，出现外壳断层。
5. **在 entity seam 一次安装 appearance view。** `.object` 继承局部 token，内部 view 消费；shellStyle 仍只写几何。**漏接：**同一实体卡面、互动区、reading panel 的色面不一致，或 appearance 改变碰撞。
6. **按 kind 保持现有 view 分支。** `CardRenderer` 的 visual→chalk→gate→letter→registry→note 顺序与 `CanvasObject` 的 portrait/sprite 分支按 `components/04:77-85` 执行。**漏接：**Chalk 被 generic paper 包裹，letter/portrait 被错误当 note。
7. **绘制 surface 与内容。** Chalk bare 透明；paper form 只由 kind/阅读/dialogue 语义引入；正文、互动控件和状态文本共用字体职责。**漏接：**舞台纸面盖住 Chalk，或者对话与实体正文像两种产品。
8. **安装反馈态。** hover/focus/drag/drop 只改颜色、outline、shadow 与有限过渡，不改动作后果；phantom 继续 `pointer-events:none`。**漏接：**视觉 hover 被误认成功，ghost 抢走 pointer，失败后残留半成品。
9. **应用 responsive band。** 先收低优先级 Chrome，再调整 panel 车道，最后调整 type/spacing；不改 `item.w/h` 和座位。**漏接：**窄屏 overflow、读层遮挡输入、测量和排版产生反馈循环。
10. **应用 Effects/reduced-motion/visibility 优先级。** 关闭非必要循环、视频和装饰，保留状态文字、颜色、outline、aria 和可操作性。**漏接：**用户关闭动效仍被呼吸/抖动打扰，或 reduced motion 后看不到“正在写/失败”。

## 6. 四种视觉连续性

### 6.1 Chalk：surface:none 是第一等公民

- Chalk 的语义是“写在画布上的字”，不是一张最小卡；`.chalk--bare` 必须 `background: transparent`、无 border、无 shadow，正文直接落在 stage 上（`index.css:892-907`）。
- `.object` 只负责定位、声明宽度、旋转与 session lift；`CanvasObject.shellStyle` 当前明确写入 `left/top/width/zIndex/--target-rot`（`CanvasObject.tsx:160-170`），不得借 appearance 追加 surface。
- `.chalk--card` 是受控的 Chalk 特例（`index.css:938-946`），不得被当成全局 Chalk 默认；其纸面应由 kind/legacy bridge 明确产生，不能由 `.object` 广撒网。
- 湿墨 phantom 是 performance projection，不是实体纸面；`.chalk--ghost` 透明度/blur 与失败撤离沿 `perform`/`layout` 契约，`.object--ghost` 永远 `pointer-events:none`（现状 `.chalk--ghost` 证据：`index.css:276-291`；ghost shell 证据：`index.css:1792-1804`）。

**漏接后果：**全局 `.object { background: ... }` 会令 Chalk 失去“写在世界上”的身份，且把正文 footprint 与纸壳高度混在一起。

### 6.2 阅读层：放大原位，不另造产品

- 产品要求阅读细化为“画布原位放大约 500px、不用全屏遮罩/背景模糊”（`docs/doc-04-视觉设计风格.md:1-3`）；因此 inline reading 仍是实体的第二层表达，不是新 shell。
- 当前 `BagItemDialog` 既有 inline/carried 两种形态，使用 `data-reading`、`paper-reading--inline/carried`，并保留 Escape、outside close、互动 fieldset（`BagItemDialog.tsx:9-46`）。
- 当前 reading CSS 已规定 inline 最大 500px、carried fixed paper 与 phone max-height（`apps/web/src/components/canvas/prop-card.css:15-29`）。迁移只换到 `--ux-*`/已验证 appearance token，不改变关闭、滚动、action 或 footprint。
- 阅读层消费同一 entity resolution；若没有 resolution，沿旧 form 默认。阅读纸面的 text color/background 不能反向写回 stage 或 appearance registry。

**漏接后果：**reading 若使用固定 cream 或重新 resolver，会出现“卡面一套皮、正文另一套皮”；若改为全屏遮罩，会违反 doc-04 的原位阅读与 active projection 语义。

### 6.3 World shelf：保留世界背景的侧边目录

- `WorldShelf` 是 `role="dialog"` 的世界/存档选择面，现状挂在 App 的 `WorldShelfDialog`（`apps/web/src/App.tsx:723-726`），内部包含 world list、save、删除确认、关闭与状态反馈（`apps/web/src/components/WorldShelf.tsx:33-58`）。
- 视觉上 Shelf 是从 stage 侧边抽出的同材质目录：保留当前世界背景的连续性，使用 paper surface、human/machine typography 和 soft/halo shadow；不使用独立 dark purple app theme。
- Shelf 的 action 状态（loading、删除确认、message）仍是 Chrome/动作文档所有；A01 只规定其 surface token lineage。
- 窄屏 Shelf 必须落在 `16px` 安全边距内并可滚动；不能压住整个场景后让“继续此故事”失去焦点路径。现有 `scene-shell.css:135-149` 的 world-directory literal 与 max-width 规则是迁移对象。

**漏接后果：**Shelf 的 dark-purple/直角 literal 会让用户误以为离开世界；若覆盖 stage 且没有焦点恢复，关闭后会丢失场景上下文。

### 6.4 Nook：同一舞台的 active projection

- `NookView` 的契约是“复用 layer `<Canvas>` wholesale，只改变 `/api/nook` 取数与空态”，且不调用 `useWorld`（`apps/web/src/components/nook/NookView.tsx:18-27`）；这也是 `docs/nook/00:113-126` 的冻结形状。
- Nook 的 stage、CanvasObject、appearance adapter、Chalk bare、reading 与拖卡视觉必须和 layer 同源；角色 README 的 `scene/bg/audio` 只是 Nook context，不得再开一套组件皮肤。
- 当前 App 将 Nook 包在 `.prototype-nook`（`apps/web/src/App.tsx:758`），而 `scene-shell.css:179` 仍将其画成 dark purple fixed panel。这是明确迁移冲突：最终 Nook shell 应是同一暖墨 stage 的 active projection，容器只负责边界/返回/加载/错误，不负责第二材质。
- Nook 返回时恢复原层相机与 refresh（`apps/web/src/App.tsx:753-758`）；A01 的视觉要求是背景、字体、实体 appearance 和阅读层在进入/返回之间连续，不要求也不允许新增相机或 Depth 机制。

**漏接后果：**Nook 若维持暗紫内嵌 panel，会把“角色私人空间”做成另一个应用；若再挂一份 global Canvas，拖拽、WS、footprint 与 active projection 会竞争。

### 6.5 Dialogue：特写焦点，不吞掉世界身份

- 角色画布上仍是头像/在场标记，进入角色对话才使用大特写；产品分工见 `docs/doc-04-视觉设计风格.md:24-30` 与 `docs/doc-06-演出与交互设计.md:37-40`。
- 现有 `CharacterModal` 由 App 在 `activeCharacter` 下挂载（`apps/web/src/App.tsx:732-755`）；`index.css:329-340` 规定背景是暖墨 dim/blur tint，`index.css:464-477` 的 `.speech-paper` 是 dialogue paper surface。
- Dialogue 可以比普通实体更高注意力，但仍沿 `--ux-color-paper/ink/muted/rust`、human typography、soft/deep shadow lineage；角色 emotion/演出由 `perform`/`agent`/`tts` 文档负责，本篇不定义帧、z 或音频。
- Close、Escape、streaming line、输入与 reduced motion 保持现有语义；对话结束后 stage 必须可恢复，不能把 modal token 泄露成全局 shell。

**漏接后果：**dialogue 若使用冷黑 backdrop 或独立字体，会从暖墨世界跳出；若把遮罩视觉状态写回实体 appearance，关闭对话后卡面会被污染。

### 10.2 静态 token 机械检查

以下断言由统一 `tools/check-ux-contract.mjs` 的 `visual` registry 执行，不另建 `check-ux-visual-tokens.mjs`：

1. **单一来源：**在 `index.css :root` 之外，禁止新增 `--ux-*` 定义；`prototype.css`、`scene-shell.css`、Tailwind 不得定义同名 token。
2. **literal 扫描：**目标 CSS 与 Tailwind 中的 hex、`rgb[a]`、颜色关键字、shadow/radius/font-family literal 必须命中登记的 global source、`transparent/currentColor`、或经评审批准的 asset/gradient exception；未登记值返回 file:line。
3. **appearance 隔离：**目标文件中不得出现 `APPEARANCE_REGISTRY`、preset ID allowlist 或 resolver 逻辑；React 不得从 `frontmatter.appearance` 拼 class/style；只有 `appearanceViewOf` 接缝可产生 `--appearance-*`。
4. **surface:none：**静态断言 `.chalk--bare` 显式保持 `background: transparent`、`border: none`、`box-shadow: none`；禁止全局 `.object`/`.ink-form` 给 `kind=chalk` 追加背景。
5. **phantom safety：**`.object--ghost` 与 ghost root 必须保持 `pointer-events: none`；禁止在 God Hand、hover 或 show 状态覆盖。
6. **geometry safety：**appearance token 映射不得声明/写入 `left/top/width/height/transform/z-index`；`shellStyle` 的几何字段仍只来自 item/reading 状态。
7. **responsive source：**断点只允许 desktop `1181`、narrow `701–1180`、phone `≤700` 的语义集合；`600/640` 旧规则必须被迁移或显式标为待清理，不得新建第三 band。
8. **font/shadow/radius source：**Tailwind 颜色、fontFamily、boxShadow、radius 必须与 global token source 对齐；检测 literal 值与 `index.css :root` 的 diff。
9. **legacy gate：**`--canvas-bg`、`--card-cream`、`--ink-secondary` 只允许出现在兼容声明与迁移测试；新增消费命中即失败。
10. **非空性：**门禁 fixture 必须包含 Chalk bare、旧 legacy Chalk、appearance resolution、reading、Nook、dialogue；若删除 canonical token 或 resolver 消费接线，至少一条断言必须失败，防止“正文能显示”假绿。
