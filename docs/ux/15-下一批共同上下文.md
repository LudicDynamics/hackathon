# UX 下一批共同上下文

> 状态：设计阶段冻结（2026-09-15）
>
> 本文是 UX 下一批实现的共享地基。模块设计文档可以提出实现方案，但不得自行改变本文规定的权威层级、事件边界、状态语义和验收底线。若设计中发现本文与代码或上位文档冲突，必须先列入「发现的冲突 / 需要修订的上位文档」，不能静默绕开。

## 1. 本批目标

把上一批已经落地的 UX 基础能力从“局部可用”收口为一条真实、可验收的跨模块链路：

1. App 与 Nook 的动作入口共享同一套事实反馈和权威结果语义；
2. Nook 拥有与普通 layer 等价的演出生命周期，但不产生第二套 WS、show listener 或 camera 真相；
3. Dialog、Photo、Gate、Nook、CharacterModal 的关闭和焦点恢复遵循同一个 topmost 事务；
4. active projection、媒体 readiness、hidden、Effects off、reduced motion 和 stale epoch 可以在运行时被证明；
5. 契约测试、浏览器回放、静态门禁和设计文档互相对齐。

本批不新增第二套世界状态、第二套动作层、第二套事件类型或第二套前端 WS。

## 2. 当前事实（实现前必须复核）

- `tools/check-ux-contract.mjs` 当前能通过现有 UX 规则，但尚未等价实现所有 UX 文档中声明的 visual token/literal 和 runtime marker 检查。

## 3. 权威层级

发生冲突时按以下顺序裁决：

1. 世界文件、实体 frontmatter 和动作层权威结果；
2. 共享协议与冻结契约（本文件及对应领域的既有 `docs/*/00-共同上下文.md`）；
3. 服务端 HTTP/WS 接线；
4. 前端 store、reconcile 和公开状态；
5. 演出层、音频、动画和装饰性反馈。

演出层永远不能反过来制造事实，也不能把“文件存在”“请求返回 200”或“组件已经挂载”当成叙事成功。

## 4. 动作反馈共同约束

### 4.1 唯一入口

App、Nook 和未来新增的 UI 动作都必须经过同一个前端动作反馈适配层；适配层内部可以调用既有 gateway，但不得让不同组件各自解释结果。

### 4.2 权威结果

动作至少需要区分：

- intent/pending：玩家已经表达意图；
- accepted：动作层确认发生；
- rejected/conflict：动作层拒绝或世界条件不满足；
- failed：通信、解析或其他技术失败；
- reconciled：前端已经根据权威结果更新公开视图。

具体 TypeScript 字段名由动作反馈设计文档提出并经评审冻结；禁止在组件中用 HTTP status、`handled` 单字段或本地 optimistic 状态替代完整结果。

### 4.3 演出门禁

只有 accepted 且完成必要 reconcile 后，才允许播放成功专属演出、奖励提示、镜头跳转或成功音效。rejected/conflict/failed 必须给出可见且可恢复的反馈，不能静默吞掉。

同一动作的 dedup key、并发动作、取消、超时和重试必须有单一解释，App 与 Nook 不得各自生成不同 key。

## 5. 演出与投影共同约束

- `airp:show-frame` 保持唯一事件语义；新增 Nook 消费不得增加第二个全局 listener。
- PerformanceLayer 的资源和 listener 必须绑定可见 surface 的生命周期；layer、Nook、dialogue 切换后不得继续向旧 root 写入。
- 同一时刻只能有一个 active projection/stage root；modal 是覆盖层，不得偷偷产生第二个舞台真相。若 dialogue 需要成为 projection，必须在设计文档中明确 marker、`aria-hidden` 和 `inert` 的关系并加入运行时断言。
- 所有 renderer 都必须明确处理 `document.hidden`、Effects off、reduced motion、取消/替换和 stale epoch；不可用“某个 renderer 已处理”推导其他 renderer 也安全。
- camera 的移动只能改变相机，不得回写首帧排版坐标；Nook 卸载必须释放 camera/show 资源。

## 6. Focus 与 Escape 共同约束

- Escape 只关闭当前 topmost 可关闭 owner，一次按键最多完成一次关闭事务。
- 局部组件不得绕过 coordinator 制造第二个全局关闭真相；focus trap、return-focus、composition 和 input/contenteditable 保护必须保留。
- 不为方便接线而扩张既有 FocusOwner 集合；若确需新增 owner，必须在评审中证明现有 owner 无法表达，并同步所有消费方和契约文档。
- 关闭顺序、事件阶段（capture/bubble）、stopPropagation、portal 边界和卸载时注销必须有可断言测试。

## 7. 资源与偏好共同约束

- hidden、Effects off、reduced motion 是独立维度，不能把其中一个当成另外两个的别名。
- voice、foley、stinger、ambient、BGM、theme 和视觉 show 各自声明 owner、启动条件、停止条件和 stale epoch 行为。
- 未满足 readiness 时只能使用明确允许的静态/无声 fallback；不得因为资源文件存在就宣称媒体已就绪。
- 浏览器媒体偏好变化使用真实 `matchMedia` / visibility 事件；测试必须证明 listener 会更新，而不是只读取初始值。

## 8. 模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| 动作反馈 | App/Nook 入口、权威结果、dedup、reconcile、反馈公开状态 | 改写世界事实、定义第二套动作 API |
| Nook 演出 | Nook 的 PerformanceLayer、show/camera 生命周期、projection marker | 新增 WS、复制全局 action truth |
| Focus/Escape | owner 注册、topmost、关闭事务、焦点恢复 | 解释动作成功与否、播放演出 |
| 声画与门禁 | renderer/音频 readiness、hidden/effects/reduced/stale 保护、静态规则 | 重新定义动作权威结果 |
| 验收收口 | 契约测试、浏览器回放、checker、文档回写 | 以测试放宽实现语义 |

模块设计文档不得跨越表中的“负责”边界；共享接口变更必须在评审报告中集中登记。

## 9. 最低验收门槛

实现不得以单文件类型检查作为完成证明，至少需要：

1. App/Nook 动作 parity、authority gating、dedup、enter outcome 的行为测试；
2. Focus/Escape topmost、一次关闭、focus return、组件卸载清理测试；
3. Nook/layer/dialogue 的 active projection 浏览器回放；
4. hidden、Effects off、reduced motion、媒体 readiness 和 stale replacement 的运行时验证；
5. `pnpm check:ux`、`pnpm check:ws`、`pnpm check:bodies`、`pnpm check:docs`、`pnpm build`、`pnpm test`；
6. 文档中的文件路径、状态和测试名称与最终代码一致。

每个新增测试都必须包含一条“没有该修复会失败”的非空性断言，不能用永久 `skip` 或接受未实现状态来制造假绿。

## 10. 评审裁决（2026-09-15）

以下决定由主代理依据 `docs/ux/review-20-下一批设计评审.md` 冻结，模块设计和实现必须遵守；若实现证明它们与上位协议冲突，必须先暂停并回写契约。

1. **ActionFeedback**：采用 App 按 active world 创建的一份 coordinator/store，通过 context 供 Canvas、Nook 和局部动作组件使用；不使用 module-global singleton，不允许 Nook 或局部组件另建 store。保留现有 `phase` 作为迁移兼容字段，但玩家可见结果以 `outcome + reconcile` 为唯一解释，成功专属演出必须等待 reconcile。
2. **choice 语义**：遵守 `docs/protocols/doc-20-工具与互动字段协议.md:262,277` 和 `docs/ui/doc-06-演出与交互设计.md:6` 的既有上位契约——点击选项先填入 writer，发送才执行 choice。任何直接 `/api/choice` 的 UI 入口必须先确认它属于已冻结的 declared-action 例外，并在 UX04、UX16 和 doc-20 同批回写；不得让实现代理自行兼容两种语义。
3. **PerformanceLayer**：App `.prototype-world` 内保持一个 stable sibling 挂载；layer 与 Nook 共享同一 `airp:show-frame` listener、live context、admission 和 camera owner，不创建第二个 PerformanceLayer、WS 或全局 show store。
4. **CharacterModal**：采用 overlay-only，不是 active stage projection；active marker 只属于 layer/Nook stage。对话期间底层 stage 保留 marker 但设置 `aria-hidden`/`inert`，modal 自己保持 dialog 可访问性，不增加第三个 projection marker。
5. **Focus/Escape**：保持现有八个 FocusOwner；在同一个 coordinator 内增加 surface lease registry。Escape 遵循 `dialogue → workspace surface（含 belongings 内容）→ Nook → shell → parent` 的 topmost 顺序，一次事件只关闭一个 surface。局部组件不得保留 document/window Escape 真相。
6. **主轨 hidden**：ambient、BGM、theme 保留当前声明 ref，页面 hidden 时暂停，重新可见后仅恢复当前 ref；one-shot 在 hidden/stale 时丢弃且不补播。该规则需要同步回写 `docs/audio/00-共同上下文.md` 和 UX07。
7. **readiness**：新增 readiness 能力优先作为 `audio.ts`/媒体 adapter 内部可测 seam，不扩张已冻结的 audio public API；若确需 public export，先回写 audio/00 并重新评审。
8. **visual checker**：canonical visual token source 冻结为现有 `apps/web/src/index.css:6-28` 的 `:root`；在既有 `tools/check-ux-contract.mjs` 中增加 `visual-literal`，例外使用精确、可过期、可验证的 registry，不另造第二 checker。
9. **targetless show**：在不改变 `ShowFrame`/WS 形状的前提下，targetless show 作用于当前唯一 active stage；target 不在当前 stage 则 no-op。若未来需要跨 stage 归属，必须走 perform/protocol 设计，不得前端私加 `layer` 字段。

## 11. 未决但不阻塞本批首轮实现

以下事项必须在对应模块落地前由 owner 记录最终值，但不得重新打开已冻结的上位方向：

1. `ActionFeedback` 的最终字段是公开扩展现有 shape，还是对外保留兼容 view、内部使用 stage receipt；两者必须只有一个玩家可见解释。
2. `ACTION_FEEDBACK_TIMEOUT_MS` 的具体数值和各动作 deadline；15 秒只能作为待测提案，不能写成现状事实。
3. video readiness 采用 `loadedmetadata`、`canplay` 或更强证据的跨浏览器最小条件。
4. reduced motion 下是否保留静态 spotlight/veil；在没有 static adapter 前，非事实装饰统一 skip。
5. 合法材质/插画 literal 的逐项清单与 provenance；例外不能覆盖 shell/state/focus 视觉。
