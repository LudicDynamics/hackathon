# 音频独立音量设置设计

> 状态：已实现（2026-09-14）
>
> 日期：2026-09-14
>
> Module owner：UX / Settings（实现由 `TtsSettings.tsx` owner 协调 `audio.ts` owner；本文不改音频引擎、TTS provider 或服务端语义）
>
> 范围：在现有 Voice & connections 入口中加入 `music` 与 `voice` 两个独立滑块；明确 0–100 的显示值、0–1 的引擎值、浏览器持久化、master mute、TTS/音频不可用及无障碍降级。

## 1. 一句话定位

让玩家在不离开当前世界、不改变任何世界事实的前提下，用一个现有设置弹窗分别调低背景音乐与角色语音；最小 UI 是复用 `TtsSettings` 的入口和设置面板，再保留 `MuteButton` 作为一键 master mute，不新增音频页、音量事件或服务端设置。

玩家目的不是理解 Web Audio 总线，而是回答两个问题：“我想保留多少音乐？”和“我想听清多少角色语音？”因此首层只显示两个带百分比的原生滑块；TTS 配置、浏览器音频能力和诊断信息留在已有状态说明之后。

**已落地事实与设计边界：**音量改变是本地偏好，不是世界动作；它不写文件、不追加 `history.db.events`、不发送 WS，也不等同于音频资源已经可播放。音频/视觉装饰关闭时，文本、动作和世界事实仍保留。

## 2. 签名、参数与类型

### 2.1 不改变的引擎 API

`apps/web/src/lib/audio.ts` 已提供以下签名（现状见 `apps/web/src/lib/audio.ts:71-103`）：

```ts
export type VolumeChannel = 'music' | 'voice';
export function getChannelVolume(channel: VolumeChannel): number; // [0, 1]
export function setChannelVolume(channel: VolumeChannel, value: number): void;
```

设置 UI **只能**调用这两个 channel preference API。不得新增 `setMusicVolume`、`setVoiceVolume`、`setMasterVolume`，不得改动 `setMuted`、TTS provider、服务端 TTS 合成或网络 payload。

### 2.2 UI 显示值与内部值

对每个 slider 使用同一线性映射：

```ts
// UI → engine
channelValue = clamp(percent, 0, 100) / 100;

// engine → UI
percent = Math.round(clamp(channelValue, 0, 1) * 100);
```

输入属性冻结为：

```text
role="slider"（原生 <input type="range">）
min="0"
max="100"
step="1"
value={percent}
```

- `0` 显示 `0%`，内部值为 `0`，不可把它当作“未设置”或自动回到默认值。
- `100` 显示 `100%`，内部值为 `1`。
- 任何从 getter 读到的越界或非有限值都在显示前 clamp；正常情况下底层 getter 已按 `audio.ts:72-79` 回退/限制。
- 百分比是玩家可理解的线性偏好显示，不承诺分贝（dB）或等响度曲线；本批不引入非线性映射。

### 2.3 组件输入与可测 DOM 契约

`TtsSettings` 不新增必需 props，继续由 `App` 无参挂载。两个控件必须有稳定的人类可读名称，建议结构如下（名称可经 i18n 翻译，不依赖 CSS selector）：

```text
<fieldset aria-labelledby="audio-levels-heading">
  <legend>Audio levels</legend>
  <label for="music-volume">Music volume</label>
  <input id="music-volume" type="range" ... aria-describedby="music-volume-value" />
  <output id="music-volume-value" for="music-volume">{percent}%</output>

  <label for="voice-volume">Voice volume</label>
  <input id="voice-volume" type="range" ... aria-describedby="voice-volume-value" />
  <output id="voice-volume-value" for="voice-volume">{percent}%</output>
</fieldset>
```

实现可以调整 DOM 包装，但必须保留：两个 `role=slider`、`aria-valuemin=0`、`aria-valuemax=100`、`aria-valuenow` 与可读百分比同步。

### 2.4 本地持久化键

持久化由现有 `audio.ts` 完成，不在 React 组件中另写一套 storage：

```text
music → localStorage key `airp-volume-music`
voice → localStorage key `airp-volume-voice`
```

现状证据：`audio.ts:72-81` 在模块初始化时读取这两个键，`audio.ts:87-95` 在 setter 中写回。UI 首次渲染从 `getChannelVolume` 读取；每次合法 slider 改变先换算成 0–1，再调用 setter，并用同一个百分比更新 `output`。

## 3. 行为契约（逐步与漏接后果）

### 3.1 打开设置

1. 玩家激活现有 `Voice & connections` 按钮。
   - **漏接后果：**若另加一个“Audio settings”入口，会产生两个设置发现路径和重复的弹窗状态。
2. 弹窗打开后分别从 `getChannelVolume('music')`、`getChannelVolume('voice')` 读取当前值，转换为 0–100；同时沿用当前 TTS 配置刷新。
   - **漏接后果：**只从初始默认值渲染会覆盖/伪造玩家上次选择；只读 React 旧状态会让多处使用引擎 API 时显示过期数字。
3. `Audio levels` 放在已有语音开关与连接配置之前；两个 slider 同时可见，不要求玩家先配置 TTS 才能调整偏好。
   - **漏接后果：**把滑块藏在 TTS provider 成功回调之后，会把“偏好设置”和“服务配置”错误绑定。

### 3.2 调整滑块

1. 玩家拖动、点击轨道或使用键盘改变某一原生 range。
2. 读取 0–100 整数，clamp 后除以 100，调用对应的 `setChannelVolume`。
3. 立即更新该 slider 的 `value`、`aria-valuenow` 和 `output`（如 `42%`）；不等待音频加载、TTS 请求或世界状态。
4. 不调用另一个 channel 的 setter；不调用 `setMuted`；不重启、暂停或重新请求当前播放片段。底层 API 已声明 volume change 是 post-envelope channel gain，见 `audio.ts:86-102`。
   - **漏接后果：**共用 state 或 master gain 会让音乐滑块改变语音，或拖动音量产生断音/重播。
5. setter 对合法值在有无 AudioContext 时都完成偏好更新；若当前无 Web Audio，UI 仍保持新的显示值。
   - **漏接后果：**把浏览器解码能力当作控件前置条件，会使玩家无法先保存偏好，也会在文本模式下产生不必要的阻断。

### 3.3 静音关系

1. `MuteButton` 仍是 header 中的一键总静音，继续调用 `useAudio().toggleMuted`，不被两个 slider 替代。
2. master mute 为上层增益开关：静音时两个 slider 的数值仍可修改并持久化，但当前扬声器保持静音；slider 不被禁用、不被改写为 `0%`。
3. 取消 master mute 后，音频恢复到两个已保存的 channel 值；UI 不把“取消静音”描述为“恢复到 100%”。`setMuted` 只改变 master ramp，现状见 `audio.ts:1038-1049`。
4. 本批只持久化两个 channel 值。`mutedState` 当前为模块内运行时状态（`audio.ts:65-69`），不新增 master mute 的 localStorage 记忆。
   - **漏接后果：**把 mute 写入同一偏好键会让刷新后的行为与现有 API 语义不一致，也会把一键临时操作误当长期音量偏好。

### 3.4 TTS 未配置或被关闭

1. `readTtsConfig(true)` 返回 `configured: false` 时，沿用当前“未配置，文字对白仍可用”的状态说明；这不是音量控件错误。
2. voice slider 仍可读、可调、可保存。说明应明确“当前没有可播放的角色语音”，而不是把 `voice=0` 或“未配置”显示成失败的音频设置。
3. 当前 TTS checkbox 关闭时，voice slider 仍代表未来/其他语音播放的本地 channel 偏好；切换 checkbox 不重置 voice 百分比。
4. 不因为 TTS 未配置而禁用 music slider，也不从 TTS 配置接口推导音乐状态。
   - **漏接后果：**把 voice preference 和 TTS enable 合并会丢失玩家选择，并让未配置状态阻断文字对白。

### 3.5 音频不可用与自动播放限制

1. `initAudio()` 返回 `null` 时，设置 UI 仍可打开和修改；现有实现已在 `audio.ts:107-130` 对 Web Audio 不可用做安全返回。
2. 界面不得显示“已播放测试音”或声称数值已经作用于扬声器；状态文案只说明“偏好已应用到当前页面”，并在能力已被可靠探测时补充“浏览器当前无法输出音频”。若实现没有能力区分能力状态，则使用条件式帮助文案，不伪造实时诊断或跨刷新持久化保证。
3. 音频上下文 suspended 或尚未收到用户手势时，slider 仍写入 preference；unlock 规则继续由现有引擎处理。一次性声音、TTS 的 drop/不补播语义不由本 UI 改写。
   - **漏接后果：**为了“确认滑块有效”而强行解锁、播放测试声或排队旧语音，会越过 autoplay 和一次性音效契约。
4. TTS 网络/配置失败继续由 `TtsSettings` 的 status/error 路径反馈；音量设置不重试 provider，不改变服务端语义。当前刷新 catch 及文字降级见 `TtsSettings.tsx:12-15,33-37`。
   - **漏接后果：**把 provider error 当作 channel setter error 会给玩家错误的修复动作。

### 3.6 关闭、重复打开与刷新

1. 点击 Close、遮罩、Escape 时关闭弹窗，已提交的 slider 值保留；不触发任何世界动作。
2. 重复打开时重新读取 getter，显示引擎当前值；不得累加 listener 或建立第二个 storage 同步循环。
3. 刷新浏览器后，`audio.ts` 从两个键恢复值；storage 不可用时以当前引擎的默认回退为准，并保持本次会话可操作。
   - **漏接后果：**只把值保存在组件 state 会造成刷新丢失；组件自行读取 storage 又会与引擎的 clamp/default 产生双真相。

## 5. 落账与 WS / 前端联动

**世界落账：无。WS 联动：无。**

音量偏好不属于文件真相、`world_event`、`agent_activity` 或 writer state。一次 slider input 的链路只有：

```text
玩家输入
→ TtsSettings 百分比换算
→ setChannelVolume(channel, value)
→ audio.ts channelVolumes + localStorage + 已存在的 GainNode ramp
→ UI output 更新
```

不得从 `useWorld.ts` 消费或新增帧；不得向 `history.db.events` 写入 `volume_changed`；不得把 TTS 配置状态广播成世界事件。`useWorld.ts` 是唯一 WS 消费入口的共同契约仍有效，但本功能没有 WS 输入，故无需添加任何消费分支。

页面切换世界/层时，两个 channel 偏好继续由当前浏览器全局持有；世界声明的 theme/BGM/ambient 仍由既有 App/audio 接线驱动，不因打开设置或拖动 slider 重新解析 README，也不因音量变化制造“世界改变”的 Toast。

## 6. 错误边界与失败/降级路径

| 情况 | 必须行为 | 玩家可核验结果 | 不得发生 |
|---|---|---|---|
| `localStorage.getItem` 抛错或值不是数字 | `audio.ts` getter 初始化回退 `1`；UI 显示 `100%`，继续可调 | slider 可操作；没有崩溃 | NaN、空白 output、把异常显示成世界错误 |
| setter 收到 NaN/Infinity | 由 `audio.ts:87-89` 忽略；UI 只产生合法整数，因此正常路径不会发生 | 既有合法值保持 | 写入字符串 `NaN` 或强制归零 |
| setter 收到越界 | 引擎 clamp 到 `[0,1]`（`audio.ts:89-90`）；UI 输入本身已限制 0–100 | getter 可重新读到 0 或 1 边界 | 越界传播到 GainNode |
| `localStorage.setItem` 抛错（私密模式/quota） | 引擎 catch；保留运行时值，继续显示当前百分比 | 本次页面仍可用；刷新后是否保留由浏览器能力决定 | 弹窗抛异常、伪报“世界保存失败” |
| `initAudio()` 返回 `null` | setter 仍记录 channel preference；不播放、不测试音 | 文本与动作继续可用；slider 可保存至可用范围 | 禁用整个设置页或声称音频已改变 |
| AudioContext suspended/autoplay blocked | 不由 slider 强制 unlock；遵循现有主轨/一次性声音 drop 规则 | 设置值可见；首次合法用户手势后由既有引擎处理 | 补播过期 voice/foley/stinger |
| master mute 为 true | slider 值照常改变并保存；master 仍是 0 | MuteButton 的 label/icon 仍表示 muted；取消 mute 后使用新值 | 把 slider 显示成 0、调用 setter 时自动 unmute |
| TTS 未配置 | 保留文字对白；voice slider 可调；状态说明指出未配置 | 可读文字、可继续操作 | 把“未配置”说成 slider 失败或阻断 music |
| TTS checkbox off | 不播放角色语音；保留 voice preference | 开关状态与百分比互不覆盖 | 关闭时删除 voice key |
| TTS refresh/network 失败 | 沿用 `TtsSettings` error/status；音量 setter 不重试网络 | 错误原因与文字降级可见 | 暗示重新拖 slider 能修复 provider |
| 弹窗关闭/层切换/重复打开 | 仅结束 UI 焦点；channel preference 已提交 | 下次打开从 getter 读回 | 写事件、触发 Writer 或重播音频 |

“音量数值已写入内存/storage”与“某个音频资源已经成功 fetch/decode”是两件事。资源失败应遵守 `docs/audio/00-共同上下文.md §7` 的轨道降级；本设置 UI 不把资源存在、文件存在或播放请求当作成功事实。

## 7. 代码落点

### 7.1 `TtsSettings.tsx`

- 在 `TtsSettings` 组件内增加 channel slider 的本地百分比 state（初始化调用 getter）。
- 用小型纯换算 helper（可留在组件文件，或由设置 owner 放入同一 settings utility）保证 `clamp → /100` 与 `clamp → round(*100)` 单一实现。
- 用一个 `onVolumeInput(channel, percent)` 处理两个控件，映射后分别调用 `setChannelVolume`；不得将 channel 写成动态未校验字符串。
- 保持现有弹窗 `role="dialog"`、`aria-modal`、Escape 关闭与 focus 起点，补充 `fieldset/legend/label/output` 语义。
- TTS refresh 的 `error`、`configured` 状态继续由现有逻辑负责；新增帮助文案只描述 audio preference 与 capability，不扩张 TTS provider 责任。

### 7.2 `audio.ts` 与 `useAudio.ts`

- `audio.ts`：实现阶段只复用 `getChannelVolume/setChannelVolume`，不得编辑签名、storage key、clamp、ramp 或 master mute 语义。
- `useAudio.ts`：优先由设置组件直接 import getter/setter，避免为了两个数值复制 store；若现有 React 绑定需要统一 notify，新增 API 也只能是同一底层 getter/setter 的薄转发，须在实现评审中证明无第二真相。
- `MuteButton.tsx`：保持 `muted`、`toggleMuted`、`aria-label` 的现有职责，不把它改成 slider 容器。

### 7.3 CSS 与消息

- `apps/web/src/decoration.css:129-132` 已有 `.settings-volume` 的 label/value/range/focus 形状，优先复用；需要把当前 TTS 弹窗迁入设置样式时，必须保留 `prototype-dialog-backdrop` 的 modal stacking 与窄屏约束，不新增同义 token。
- `apps/web/src/lib/messages.json` 增加本节定义的 key，并由 `useLocale().t` 读取；英文 key 本身是 fallback（`i18n.ts:10-13`），zh-CN/ja 必须同时提供。
本批新增 key 的英文基准值固定如下（`translate()` 对英文直接返回 key；zh-CN/ja 由消息 owner 补译）：

| key（English） | 用途 |
|---|---|
| `Audio levels` | 音量 fieldset 标题 |
| `Music volume` | music slider label |
| `Voice volume` | voice slider label |
| `{value}%` | `output` 与 `aria-valuetext` 的百分比值 |
| `Audio preferences are saved in this browser.` | 可用 storage 时的帮助说明 |
| `Voice playback is off; text dialogue remains available.` | voice checkbox 关闭时的说明 |
| `TTS is not configured. Text dialogue remains available.` | TTS 未配置状态 |
| `Audio output is unavailable. Volume preferences will still be saved.` | 仅在能力可靠探测为不可用时显示；不能用于 storage 写入失败的断言 |
- CSS owner 统一为 `decoration.css` 的 settings surface；TtsSettings 不写 slider 的 inline style，不用颜色/动画单独表达可用性。

## 9. 验收测试与浏览器验收矩阵

### 9.1 可测接口与专项测试断言

不新增生产 API；使用现有导出、fake Web Audio、fake `localStorage` 和可访问 DOM 验收：

1. **映射边界（纯 helper 或 DOM 事件）**
   - 0 → `0`、0.5 → `50`、1 → `100`；负数/大于 1 显示边界；`42` → `0.42`。
   - output、`aria-valuenow` 与 range value 始终一致。
2. **独立性**
   - fake engine 初始 music=0.3、voice=0.8；打开弹窗显示 30%/80%。
   - 输入 music=0 后只调用 `setChannelVolume('music', 0)`；voice 仍为 80%。
   - 输入 voice=40 后只调用 `setChannelVolume('voice', 0.4)`；music 仍为 0%。
3. **持久化**
   - fake `localStorage` 预置两个键，模块初始化 getter 恢复它们；setter 写入精确的 0–1 字符串（例如 `0.4`）。
   - 0 值必须保留为 `0`，不可因 falsy 检查回到 1；对应底层已有非空行为测试 `apps/web/test/audio-volume.test.mjs:6-60`。
4. **master mute 关系**
   - `muted=true` 时 slider 仍可改值；不得调用 toggle/unmute。
   - fake master gain 保持 0；取消 mute 后 bus 使用最后的 channel 值。底层独立 bus 与 master 断言见 `apps/web/test/audio-volume.test.mjs:36-56`。
5. **无音频能力**
   - `initAudio() === null` 时打开、拖动、关闭不抛；getter 返回当前内存值；文本状态仍可见。底层安全断言已有 `apps/web/test/audio-volume.test.mjs:70-77`。
6. **TTS 状态**
   - `configured=false`、checkbox off、refresh reject 三种 fixture 都保持两个 slider 可见且不重置 voice；状态说明明确文字可用。
7. **无世界副作用**
   - 调整任一 slider 时，world event、WS send、Writer prompt、TTS fetch 次数均为 0；这是 UI 集成测试的负向断言。
8. **键盘/屏幕阅读器**
   - Tab 可聚焦两个 range；ArrowLeft/Right 改变 1 个百分点；Home/End 到 0/100；Space 不提交任何世界动作；Escape 关闭 dialog。
   - accessible tree 能读出 label、当前百分比与“已保存/当前不可用”说明；装饰性图标不进入焦点。

## 10. 发现的冲突 / 需修订的上位文档

1. **`docs/ux/08-niko功能迁移契约.md:78-89` 与 `docs/audio/00-共同上下文.md:270-293` 只冻结了 `music`/`voice` API 及 0–1 范围，没有冻结“music channel 覆盖哪些具体轨道”。**当前实现证据显示 `audio.ts:665-683` 对 ambient sample 选择 `master`，而 BGM/theme 走 `musicBus`；`audio.ts:767-773` 的合成 ambient 与 `audio.ts:880-912` 的 foley 也有独立 destination。建议 audio 上位文档补一张“轨道→channel”的冻结表；在该表裁决前，本设计不把 Music 文案扩张为“所有非语音声音”，也不新增 effects slider。

2. **`docs/audio/00-共同上下文.md:322-330` 定义了 theme/bgm/ambient/stinger 的轨道音量语义，但没有将它们映射到本批 UI channel。**建议补充：UI 只能控制既有 `get/set ChannelVolume` 所代表的底层 channel；若产品要求 ambient/foley 也受 Music slider 控制，应由 audio owner 单独提出路由变更并更新专项测试，不能由 `TtsSettings` 绕过 API 改 destination。

3. **现有 `TtsSettings.tsx:21-39` 与 `apps/web/src/decoration.css:79-142` 使用两套设置外壳：前者实际使用 `prototype-dialog-backdrop/prototype-world-picker`，后者已有 `.settings-panel/.settings-volume`。**本设计选择保留现有 modal shell、复用 settings volume 语法；若实现要把整个 TTS 弹窗迁入 `.settings-panel`，需由 CSS owner 评审 stacking、focus trap 和窄屏回归，不得在两个文件各维护一套同义组件样式。

4. **现有 `TtsSettings` 的可见文案多数是硬编码英文（`TtsSettings.tsx:22-37`），而 `i18n.ts:10-13` 已提供 message-key fallback。**本批新增文案必须补齐三语言；是否同时把本次触碰到的旧 TTS 文案全部迁移到 key，应由 i18n owner 在实现评审裁决。无论裁决如何，不能新增另一批硬编码音量文案。

## 11. 仍未知待拍板

1. `music` channel 最终是否必须包含 ambient、foley、stinger，或只包含 `musicBus` 上的 BGM/theme：当前 API 名称和实现路径不足以独立证明产品语义。本文暂定 UI 只承诺底层 channel，不新增“effects”文字；由 audio owner 依据第 10 节补充映射表。
2. 音频不可用是否要显示一个实时能力 badge：现有 `initAudio(): AudioContext | null` 能判断创建结果，但 `useAudio` 当前公开返回值没有 `audioAvailable`（`useAudio.ts:27-34`），且在 render 时主动 probe 可能改变 autoplay 生命周期。本文采用不伪造实时状态的静态降级文案；若要动态 badge，需单独冻结 binding 形状与生命周期。
3. 是否要对“storage 写入失败”显示短暂 status：当前 `setChannelVolume` catch 不向 UI 返回错误（`audio.ts:91-95`），不能在 UI 声称已持久化。默认不新增错误提示；若需要，必须新增不改变底层 setter 签名的可观测诊断 seam，并给出私密模式测试。
4. `TtsSettings` 的焦点 trap、点击遮罩关闭和 `autoFocus` 的完整行为目前只在组件行内定义（`TtsSettings.tsx:28-30`），本设计只要求保留 Escape/键盘路径；是否引入通用 dialog primitive 不属于本批，需避免借音量功能扩大范围。
5. “线性百分比”是否需要产品改为感知等响度曲线：本批冻结为线性 0–1 映射，因底层 API 只接受 0–1 且用户明确要求 0–100 显示。若改曲线，必须更新映射测试和文案，不能在 CSS 或组件中偷偷转换。
