# UX19 声画门禁与静态检查设计

> 状态：设计稿，未实现（2026-09-15）
>
> 模块 owner：PerformanceLayer renderer gates、audio visibility/readiness、visual token checker。
>
> 本文只设计门禁、资源就绪和静态视觉检查；不改动作权威结果、WS/HTTP payload、`appearance` schema、音频素材生产或第二套 projection。

## 一句话定位

把同一个“当前可演出、当前可播放、当前可见”的判定收敛到 `PerformanceLayer`、音频 owner 和一个 checker：用户关闭 Effects、启用 reduced motion、切后台、替换 layer 或遇到媒体失败时，事实仍可读，旧 epoch 的 renderer/audio 永不落地，所有合法材质/插画例外都必须有可审计登记。

## 用户预期

1. 玩家已得到权威结果后，成功专属的 show、foley 或 stinger 才出现；show 不是动作事实来源。
2. `Effects off` 关闭视觉装饰，但不把音频静音开关、结果文案、焦点和可操作性一并关闭。
3. `prefers-reduced-motion` 运行中变化立即生效；位移、循环和高刺激演出停止或降为静态表达。
4. 页面隐藏、切层、冻结、关闭对话或新语音替换时，旧一次性声音不在稍后补播；重新可见只恢复当前有效主轨/媒体，不复活旧 show。
5. 图片、视频、音频未 ready 时，先看到静态纸面、poster、文字或既有 fallback；“请求已发出”不等于“媒体已播放”。
6. 视觉 token 迁移不会被一个随意的 allowlist 绕过：shell/状态视觉必须消费 `--ux-*`，仅材质和插画的、局部且无状态含义的 literal 可以逐项登记。

### 3.2 NEW：统一 gate/readiness 内部契约

以下是设计阶段新增的内部类型，必须标 `NEW`，不是 HTTP/WS payload，也不允许 renderer 自行发明同义字段。

```ts
// NEW, internal only; source owner: apps/web/src/lib/media-readiness.ts
export type MediaOwner =
  | 'background' | 'portrait'
  | 'ambient' | 'bgm' | 'theme'
  | 'foley' | 'stinger' | 'voice' | 'show';

export type ReadinessState = 'unrequested' | 'loading' | 'ready' | 'failed';

export interface ReadinessSnapshot {
  owner: MediaOwner;
  key: string;
  state: ReadinessState;
  epoch: number;
  errorCode?: 'fetch' | 'decode' | 'media-error' | 'stale';
}

export interface MediaReadinessAdapter {
  request(owner: MediaOwner, key: string, epoch: number): Promise<ReadinessSnapshot>;
  snapshot(owner: MediaOwner, key: string): ReadinessSnapshot;
  invalidate(epoch: number): void;
  cancel(owner: MediaOwner, key: string, epoch: number): void;
}
```

`request` 的完成回调只有在 `key` 和 `epoch` 都仍然匹配时才能把状态推进到 `ready`；旧 URL 即使 decode 成功也只成为 cache，不得改变当前 projection。`failed` 不自动 visibility retry；显式新 URL、用户重试或新 layer epoch 才能重新 request。

```ts
// NEW, PerformanceLayer internal admission; source owner: PerformanceLayer.tsx
export interface ShowGateContext {
  epoch: number;
  hidden: boolean;
  effectsEnabled: boolean;
  reducedMotion: boolean;
  resourceKey: string;
  readiness: ReadinessSnapshot[];
}

export interface ShowGateDecision {
  accepted: boolean;
  mode: 'full' | 'static' | 'skip';
  reason?: 'effects-off' | 'reduced-motion' | 'hidden' | 'not-ready' | 'failed' | 'stale' | 'target-missing' | 'admission-rejected';
}
```

这是编排内部结果，不新增 `ShowFrame` 字段，不让 `show_frame` 传入 `epoch` 或直接传 gate。

## 4. PerformanceLayer：统一门禁顺序与 renderer 规则

### 4.1 所有 show 的固定顺序

`performShowFrame` 必须按下列顺序执行；任何一步失败都不能调用该 renderer 的 DOM、camera、audio 或 admission 副作用：

1. 校验 `type === 'show_frame'`、`resolveShowKind` 和当前 `liveCtx`。失败返回 `false`，不播放任何声音。
2. 读取当前 `ShowGateContext`，捕获当前 layer/projection epoch；`document.hidden` 仅由宿主转换为 `hidden`，renderer 不自己读取偏好。若 `liveCtx` 已卸载或 epoch 变化，返回 `stale`。
3. 先确认 target/links/geometry/admission 等纯查询条件；target 不在当前 layer 时返回 `target-missing`，不拆旧 show、不播音效。
4. 计算 `Effects off → reduced motion → hidden → required readiness`。这些维度独立；优先级表示选择更保守的投影，不表示把 Effects off 当 mute。
5. 依 renderer 得出 `full/static/skip`。`skip` 不产生 DOM、camera、timer、`playFoley`/`setAmbient`/admission token；`static` 只能产生无位移、一次性、可清理的静态视觉，且不得把事实留在 `aria-hidden` 的 show root。
6. 只有 `accepted` 的 frame 才创建 renderer；同 `resourceKey` 的旧 show 在新 renderer 已完成无副作用 admission 后清理，避免一个坏 frame 拆掉有效 show。新 show 保存 `epoch`、`resourceKey`、cleanup；异步 readiness 完成再次比较二者。
7. 任何 timer、camera subscription、Particle burst、ambient 临时 cut、admission token 都必须挂在该 show 的 cleanup 上；`cancelShow`、replace、layer/frozen/unmount 都调用同一 cleanup。
8. `durationMs` 到期只 cleanup，不补播声音、不重新进入 show；旧 timeout 即使继续回调，也必须因 `activeShow().find(id)` 不存在而 no-op。

**漏了第 2 步**会让切层前的旧 frame 在新 root 落地；漏了第 3 步会让 target-specific 声音先响后发现 target 不存在；漏了第 4 步会造成各 renderer 门禁漂移；漏了第 6/7 步会留下旧 caption、rAF、camera 或临时 ambient。

### 4.3 replace/cancel/stale epoch

- **replace**：同 `ruleKeyOf(kind)` 的新 frame 先完成纯 admission；成功后旧 show cleanup，再登记新 `ActiveShow`。不同 resource key 并行，但每个 show 独立 epoch、timer 和 cleanup。
- **cancel**：`cancelShow(reason?)` 只做 cleanup 和 active 清空；不触发成功、失败或“恢复”声音。`lights_out` 的 ambient 恢复属于可逆资源 cleanup，不是动作结果。
- **stale epoch**：layer、world freeze、active projection、root、hidden→visible 边界或 readiness owner 变化时生成新 epoch（具体何时递增由实现按上述边界统一）。Promise、camera lease、caption timer、audio one-shot callback 均比较 `epoch` 与 key；不匹配直接 drop。
- **hidden 往返**：进入 hidden 使 transient show 失效；重见不重播旧 frame。若业务仍需演出，必须由新的权威 frame/新的 `requestKey` 重新进入 dispatcher。
- **renderer 不能自行 gate**：renderer 只消费 `ShowGateContext`；不得分别读取 `document.hidden`、`matchMedia`、`localStorage`，否则同一 frame 会出现 `PerformanceLayer` 认为 skip 而 renderer 仍有副作用。

## 5. Audio owner：六类通道的明确规则

### 5.1 共同音频门禁

音频一次性请求必须同时通过：当前页 visible、`mutedState=false`、AudioContext running、owner key 未被 replace、`visibilityEpoch`/show epoch 未变化、素材 readiness 为 `ready`。任一失败都 drop，不排队，不在重见或 unlock 时补播。

主轨请求则保留服务端声明 ref，即使 context 未解锁或 hidden；ready/visible/unlock 后只按当前 ref 重建/继续，绝不从意图或默认值猜音轨。`null` 仍是声明静音，不能回退合成。

### 5.2 Audio × gate 矩阵

| owner | 权威来源/现有符号 | Effects off | reduced motion | hidden | readiness / fallback | replace/cancel/stale |
|---|---|---|---|---|---|---|
| **foley** | `playFoley(FoleyName)`（`:913-943`）；结果/触觉 owner | 不因 Effects off 自动 mute；但若它是被跳过的纯装饰 show（如当前 `ink_burst` 的 `pen-scratch`、fireworks 的 `crit-chime`），必须随 show `skip` 为 0。动作 intent/result Foley 可保留。 | 声音本身不因 reduced 自动 mute；与被跳过的纯装饰绑定时为 0。 | 当前实现 hidden/epoch drop；不得补播。 | decode ready 播 sample；失败按 `audio.ts` 既有合成 foley fallback；声明不存在的 key 不假装 ready。 | 同名 busy window、show token 和 epoch 均可取消；失败不 visibility retry。 |

### 5.3 `lights_out` 的音频特殊边界

当前 `showLightsOut` 在创建 veil 后立即保存 `audioDebugState().ambient`、调用 `setAmbient(null)`，cleanup 再恢复（`PerformanceLayer.tsx:213-222`）。设计修复为：

1. 先通过 gate 和 epoch admission，再保存当前 track ref 和 track token。
2. 调用 NEW 内部 `beginTransientAmbientCut(ref: string | null, epoch: number): { release(): void }`；它只属于 `ambient` owner，不能改 BGM/theme。
3. `release()` 仅在 owner ref/token 仍是原 show 所有时恢复；若用户已经切层/显式换 ambient，则 no-op。
4. hidden、Effects off、reduced 选择 `skip` 时不调用 cut；否则“视觉未演出而环境声被静音”。

该 helper 若新增，必须标 `NEW`，并由 `audio.ts` 定义；不能继续让 `PerformanceLayer` 直接凭 debug snapshot 写主轨。

### 5.4 音频请求逐步行为（每一步的漏接后果）

1. **声明 owner 与当前 key。** App 只把服务端最终 URL/null 交给 `setAmbient`/`setBGM`/`setTheme`；dialogue/show 只把当前页或已准入 frame 交给 one-shot owner。**漏接：**前端重新解析 README、从 `[emo:]` 猜 BGM，形成第二真相源。
2. **记录 ref/token/visibility epoch。** 主轨保留声明 ref；foley/stinger/voice 捕获 request token 和当前 epoch。**漏接：**旧 decode 会覆盖新 layer，或 hidden 前发出的声音在重见后落地。
3. **先判断 gate，再开始 decode/play。** 检查 visible、mute、context、replace/cancel 和 readiness；one-shot 任一失败直接 drop，主轨只进入 loading。**漏接：**后台耗电、未解锁声音排队、文件存在被误报成已播放。
4. **确认 decode/media ready。** ready 才创建 `AudioBufferSourceNode`；failed 按 owner fallback，不能把失败当 declared silence。**漏接：**音频与画面错拍，或 theme 被错误替换为 ambient 合成音。
5. **在完成回调再次核对 key/epoch/owner。** 只允许当前请求 play；voice 还必须确认 `voiceToken` 未变。**漏接：**A 页语音、旧 stinger 或旧层主轨覆盖当前页。
6. **登记可停止句柄与诊断状态。** one-shot 归 owner，主轨归 track；cleanup/stop/release 必须幂等；`audioDebugState()` 记录 ref 与成功 loaded。**漏接：**取消只删 DOM 不停声，或测试只能看到“请求过”而无法区分 ready。
7. **visible/unlock 只恢复当前主轨。** 不恢复过期 one-shot；若 ref 已变则旧恢复 no-op。**漏接：**回来时补播错过的高潮，或旧 URL 重新夺回新层。

## 6. 资源 readiness adapter

### 6.1 统一状态和 owner

`unrequested → loading → ready | failed` 是唯一状态机；`static/paper` 是视觉层在 `failed` 或未声明动态资源时的呈现，不是 readiness 状态。每个请求以 `{owner,key,epoch}` 为身份：

- image：`onLoad` 才 ready，`onError` failed；先显示已有 paper/静态 fallback。
- video：至少 `loadedmetadata` 和 `canplay` 中规定的 ready 事件（实现需在未知项中拍板）；ready 前不调用 `play()`。`preload="metadata"` 只代表请求提示。
- audio：`loadSample` decode 成功才 ready；`audioDebugState().loaded` 只表示成功 cache，失败 URL 不在其中，不能把“未列入 loaded”直接当 failed，必须由 audio readiness adapter 返回最终状态。
- show/DOM：没有外部媒体的 renderer 以 geometry/admission ready；CSS 动画本身不是资源 ready 证据。

### 6.2 代码接线

1. NEW `apps/web/src/lib/media-readiness.ts` 定义 `MediaOwner`、`ReadinessSnapshot`、`MediaReadinessAdapter`；不读 README、不写世界。
2. `SceneBackdrop` 把现有 `failedSrc/failedVideo/readySrc`（`SceneBackdrop.tsx:37-64`）接到 adapter，保留 `data-media-state`、poster/paper fallback 和 source URL guard；删除 App 用 `Image` probe 作为“背景 ready”真相（旧落点 `App.tsx:553-564`）。
3. `CharacterMedia` 把 `ready/failedVideo/failedPoster`（`CharacterMedia.tsx:31-40,72-115`）接到相同 adapter；IntersectionObserver 仍只决定可见播放，不改变 readiness。
4. audio owner 在 `audio.ts` 内提供 adapter bridge；readiness 必须是内部可测 seam，不扩张 `docs/audio/00` 已冻结的 public API。`preloadAudio`/`audioDebugState` 仍是既有外部 surface；若内部需要新 helper，标为 `NEW` 但不 export。不能用 `audioDebugState().loaded` 猜 loading/failed。
5. `PerformanceLayer` 在 renderer admission 使用 show/particle readiness snapshot；不等待事实 UI，缺 readiness 时只 skip 装饰；`reducedMotion=true` 在 static adapter 冻结前也统一 skip，不转 static。
6. 所有 Promise completion 先做 `sourceRef === key`、`epoch === currentEpoch`、当前 owner 未 cancel 三重检查；旧 layer 的 ready 只能进入 cache，不能更新当前 DOM/音轨。

### 6.3 错误、取消和重试

- `failed`：背景回 poster/paper、立绘回 poster/fallback、ambient/BGM 依 audio contract fallback、theme/stinger/voice 静音；保留诊断状态，不宣称媒体已播放。
- `cancel`：取消请求的消费，不要求底层 fetch 可中断；late completion 必须因 epoch/key 检查而 no-op。
- `retry`：只允许新 URL、新 layer epoch 或明确用户 retry；`visibilitychange`、`unlock`、re-render 不得隐式无限重试。
- `HTTP 200`、文件存在、`<video>` 已挂载、`audioDebugState().ref` 已写入均不是 ready。

## 7. 静态 visual token checker 设计

### 7.1 继续使用唯一 checker

`tools/check-ux-contract.mjs` 当前 schema 在 `:15-29,48-106` 关闭 KINDS/字段，`tools/ux-contract.json` 的 `visual` 规则在 `:37-157`；本设计扩展同一个 checker，不创建第二个视觉 checker。

新增 `visual-literal` rule kind（NEW），并在 `validateContract`/`validateExpect` 中注册；推荐形状如下：

```jsonc
{
  "id": "visual.global-token-and-literal-policy",
  "kind": "visual-literal",
  "doc": { "path": "docs/ux/01-全局视觉语法.md", "anchor": "§10.2" },
  "owner": "UXVisualGrammar01",
  "scope": "global visual grammar and bounded material/illustration exceptions",
  "target": ["apps/web/src/**/*.css", "apps/web/src/**/*.{ts,tsx}", "apps/web/tailwind.config.js"],
  "expect": {
    "canonicalTokenFile": "apps/web/src/index.css",
    "tokenPrefix": "--ux-",
    "appearancePrefix": "--appearance-",
    "legacyAliases": ["--canvas-bg", "--card-cream", "--ink-secondary"],
    "literalKinds": ["color", "gradient", "shadow", "radius", "font", "motion"],
    "exceptionRegistry": "visualExceptions"
  },
  "allow": ["transparent", "currentColor"],
  "forbid": ["new global literal source", "legacy consumer"],
  "reason": "UI/state literals must consume the canonical token source; only bounded material/illustration paint may be registered."
}
```

`visualExceptions` 同在 `tools/ux-contract.json`（NEW）登记，逐项包含：`id`、`target`、`selectorOrSymbol`、`kind: material|illustration|asset`、`literals`/`assetUrls`、`properties`、`owner`、`reason`、`expiresAfter`。例外必须是精确 selector/symbol，不允许 `apps/web/src/**` 这种整目录 allowlist。

### 7.2 checker 机械算法

1. **canonical source**：解析 `canonicalTokenFile` 的 `:root`，收集所有 `--ux-*` 定义；除 canonical 文件外出现同名定义即失败。`--appearance-*` 只允许在 `appearanceViewOf`/其明确消费接缝，不能借它替代 shell token。
2. **definition/use**：扫描 target glob 的 CSS、TS、TSX、Tailwind；发现 color hex、`rgb[a]/hsl[a]`、颜色关键字、gradient、`box-shadow`、`border-radius`、`font-family`、motion duration/easing literal 时，要求：
   - 是 `var(--ux-*)`、`var(--appearance-*)`、`transparent/currentColor`；或
   - 完全命中 `visualExceptions` 的文件、selector/symbol、property 和 literal。
3. **legacy**：legacy alias 可以只出现在 canonical 兼容声明和迁移测试；任何新消费（CSS `var(--canvas-bg)`、TSX style、Tailwind value）失败并报 file:line。
4. **例外收窄**：`material` 只允许 `background/background-image/border-color/box-shadow` 中表达材质；`illustration` 只允许该具体图形的 paint，不得放宽 `font-family`、focus、error、success、state、shell、Depth、geometry；`asset` 只登记 URL/纹理，不准借 asset 例外放宽旁边的状态色。
5. **appearance 隔离**：继续执行现有 appearance unique-call/forbidden-source；literal checker 不得把 raw frontmatter、preset ID 或 arbitrary style 视为合法例外。
6. **异常输出**：每个 finding 包含 `id/file:line/kind/property/literal/fix/doc`；fix 必须指出迁移到哪个 canonical token 或补齐哪一条精确例外。单纯把值复制进 allowlist 不能通过 reason 校验。
7. **非空执行**：`scanRepo` 必须至少扫到一个 CSS、一个 TSX、`tailwind.config.js`；target glob 为空、例外 target 不存在、例外 literal 未在 source 出现均 fail-closed。

## 11. 错误、取消、重试边界

1. **畸形/未知 show**：`performShowFrame` 返回 `false`，不抛异常、不播音、不拆已有有效 show；现有 unknown component warning 保持开发诊断。
2. **target/geometry 缺失**：renderer 不创建 DOM、camera、audio；已有 show 继续，除非新 frame admission 成功。
3. **authority 失败/conflict/failed**：不触发成功专属 renderer/audio；可见失败文案由动作反馈层承载。
4. **layer/freeze/projection cancel**：统一 `cancelShow`、停止 voice、使 transient foley/stinger/readiness epoch 失效；主轨仅按当前 audio owner 策略停/保留 ref。
5. **decode/fetch 失败**：背景/立绘回静态，ambient/BGM 合成 fallback，theme/stinger/voice 静音；不反复 fetch，不把 failure 改为 success。
6. **autoplay/context suspended**：foley/stinger/voice 直接 drop；主轨 ref 可记录，unlock 后只恢复当前声明主轨。
7. **replace race**：新 URL/token 取代旧 URL；旧 Promise、旧 `onCanPlay`、旧 `loadSample` 完成均 no-op；旧音频不能覆盖新 layer。
8. **hidden race**：visible 发起、hidden 完成的 one-shot 一律 stale；visible 后不补播；主轨按上文提案恢复当前声明 ref。
9. **用户显式 retry**：只能生成新的 request key/epoch；checker 例外变更也必须改 registry 与 failure fixture，不能仅扩 allowlist。

## 12. 验收测试设计

实现后至少形成以下测试；每条都必须有真实行为或可观测状态，不能以静态 marker 代替。

### 12.1 Renderer gate/runtime

- **G1 非空失败断言（修复前必须失败）**：同一 fixture 发送 `spotlight`、`lights_out`、`evidence_burst`、`ink_burst`、`roll_ceremony`，设置 `effectsEnabled=false`、`hidden=true`、`reducedMotion=true` 三组；修复前至少可观察到 veil/ambient cut/ink foley/roll DOM 之一，修复后每个 renderer 的副作用计数为 0。
- **G2 reduced live change**：不 remount，`matchMedia('(prefers-reduced-motion: reduce)')` 的 `change` 从 false→true；下一 frame 的 camera/fireworks/burst 为 0，事实结果仍在公开状态。
- **G3 hidden stale**：visible 发起 `fireworks`/`ink` 后切 hidden，再回 visible；`activeShow` 不复活，`crit-chime`/`pen-scratch`/caption 不增加。
- **G4 replace/cancel**：同 `resourceKey` 新 frame 成功接管，旧 DOM、camera subscription、ambient lease、admission token 全清；坏 target 的新 frame 不拆旧有效 frame。
- **G5 target/authority**：target 不在 layer 时 `performShowFrame=false` 且所有一次性声音为 0；动作 rejected/failed fixture 不能出现 success-only sound/show。
- **G6 active projection**：layer↔Nook↔dialogue 浏览器回放中只有一个 active root 可交互，唯一 `airp:show-frame` listener 无增量；`aria-hidden` show root 不承载唯一事实文案。

### 12.2 Audio/readiness

- **A1 one-shot epoch**：foley/stinger/voice 在 decode pending 时切 hidden→visible；修复前若无 epoch guard会补播，修复后计数不增。
- **A2 voice replace**：voice A pending 后立即 `playVoice(B)`；A 永不播放，B 最多一条，`stopVoice` 先于 B。
- **A3 主轨三态**：`null` 不启 synth；URL failed 允许 ambient/BGM synth fallback；theme failed 静音；声明 ref 与 `loaded` 集合可区分。
- **A4 主轨 hidden（待 audio owner 冻结）**：hidden 时 ambient/BGM/theme 不改变声明 ref；按最终裁决的 pause/continue 行为断言，visible 不重复触发 one-shot。
- **A5 media readiness**：video 仅 `loadedmetadata/canplay` 后允许 `play`；image `onLoad` 后才 ready；旧 URL 的 late event 不改变当前 `data-media-state`。修复前直接以 mount/HTTP 200 视 ready 的 fixture 必须失败。
- **A6 failed retry**：失败资源只 fallback 一次；visibility 往返不重复 fetch；新 key/显式 retry 才重新请求。

### 12.3 Checker 静态门禁

- **C1 非空失败断言（修复前必须失败）**：在 fixture CSS/TSX 增加 `color:#123456`、`box-shadow:...` 或 `PerformanceLayer` 内新 literal；旧 checker 会 clean，新增 `visual-literal` 必须报告精确 file:line/property。移除 canonical `--ux-color-rust` 定义或把消费改回 `--rust` 时也必须失败。
- **C2 合法例外**：`.cabin-prop--door .cabin-prop__shape` 登记的 paint literal clean；把同 literal 移到 `.prototype-worldtop` 或用于 `:focus` 必须 failure。
- **C3 未登记例外**：例外 literal 未出现在 source、target 不存在、`expiresAfter` 过期、例外 selector 命中多个不相关 selector，均 fail-closed。
- **C4 legacy**：`var(--canvas-bg)` 兼容声明 clean；任意新组件消费 failure。
- **C5 source diff**：Tailwind 增加与 root 不同的 hex/font/shadow/radius failure；全局 `--ux-*` 定义移出 canonical root failure。
- **C6 contract schema**：未知 `visual-literal` 字段、相对路径越界、空 target/空 exception registry failure；已有 visual/depth/projection 规则仍 clean。

### 12.4 浏览器证据矩阵

至少复用 `docs/ux/07:223-244` 的 E/R/H/A 组合：默认 ready、failed、hidden、reduced、Effects off 以及四者组合；每组记录 `activeShow`、rAF/draw、video `paused/currentTime`、audio owner ref/loaded、one-shot 调用计数和事实文案。截图只证明视觉，Media/Performance trace 才证明 ready、暂停和没有补播。
