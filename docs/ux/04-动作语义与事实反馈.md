## 0. 范围、权威与术语
本篇负责 `inspect / act / enter / choice / dice / present / cancel` 的前端交互语义、结果反馈节拍和重复入口收敛；不重写动作层领域协议，不新增事件 type、WS frame、HTTP 请求体或 `WorldStore` 字段。

必须服从：

- `docs/ux/00-共同上下文.md §2、§3.3、§4.2、§4.3、§4.4、§4.6.2、§4.6.3、§4.7、§7`：唯一 active projection、Depth、动作词、事实先于反馈、DiceCeremony 唯一归一化、ActionFeedback 终结一次性、Effects/Reduced motion 优先级和机械核验。
- `docs/doc-06-演出与交互设计.md §1.5、§2.6、§3.1、§3.5、§5.1、§5.4、§6、§7`：门双击、角色单击、查看与行动分离、背包落点分流和 `choice / roll_dice` 呈现。
- `docs/tools/00-共同上下文.md §4、§5、§6` 与 `docs/tools/01-动作内核与事件落账.md`：`packages/shared/src/actions/` 是校验 → 落盘 → 落账 → 返回的唯一动作实现处；路由和工具不得自建第二套规则。
- `docs/perform/00-共同上下文.md §4、§5、§6b、§8b`：幻影是临时投影，`chalk_landed/image_landed` 只是座位过户，`tool_end` 失败要 evict；音效只能跟随权威演出阶段。
- `docs/layout/00-共同上下文.md §5、§6`：普通玩家可阅读/互动 Chalk，不可拖 Chalk；幻影永远不可拖，真实重取坐标优先。
- `docs/nook/00-共同上下文.md §3.4、§5`：Nook 与 layer 复用 `LayerState` 形状和动作语义；Nook 是另一个 active projection，不是第二套动作层。

本篇使用以下术语：

| 术语 | 本篇冻结含义 |
|---|---|
| `inspect` | 只读查看外观、摘要或正文；不写文件、不追加事件、不发 `writer_prompt`，也不自动选 `choice`/掷骰。 |
| `act` | 对实体声明的互动执行选择、掷骰、拿取/移动等世界动作；必须经过动作层。 |
| `enter` | 穿越场景门（`layer_entered`）；角色对话是注意力/对话 projection 的进入，不把它伪装成门动作。 |
| `present` | 背包物品指向目标的出示/以物解谜；请求形状固定为 `use_item_on { item, target }`，不是 `move`。 |
| `cancel` | 取消尚未发出的本地预览/手势，或请求停止正在进行的演出；不能把“请求已发出但响应未到”伪装成撤销世界事实。 |
| authoritative result | HTTP 2xx `ActionResult.details`（含事件/裁决字段）或明确的 `ActionError`；WS 演出帧不能反过来替代动作结果。 |
| `conflict` | 请求合法到达权威层，但当前世界拒绝其语义效果（如门禁未满足、物品不匹配、选项已过期、骰子已落定）；有时仍有拒绝事件。 |

| 动作 | 触发与对象 | 请求/事实 | 成功后允许的呈现 | 失败/冲突后 | 明确不做 |
|---|---|---|---|---|---|
| `inspect` | 卡片单击、普通卡键盘 Enter、letter/PropCard 打开 | 无请求、无事件；读取现有 `LayerItem` 投影 | 在 `entity`/`dialogue` Depth 展开摘要/正文；可显示 choice/dice/status 控件但不执行 | 只显示本地缺失/不可读态，保留关闭路径 | 不发 writer、不选 choice、不掷骰、不切层、不播放成功拟音 |

### 2.2 门单击/双击/Enter 的明确规则

1. **单击 gate 或 visual door = inspect**：保留卡面摘要、hover detail 或门的视觉 pressed/focus；不调用 `onEnterGate`。
2. **双击 gate 或 visual door = enter**：在同一 `CanvasObject`/门 adapter 内做双击判定，调用一次 `enterLayer`。双击的第二次 click 不得再触发 inspect 或第二次请求。
双击窗口固定为 **500ms inclusive**；第一击立即完成 local inspect 并记录 pending click，第二击在 `≤500ms` 内取消 inspect projection、只提交一次 enter；超时则保留 inspect，不等待第二击。移动端使用显式 Enter，不依赖双击精度。
3. **键盘 Enter = enter（focused gate）**：gate 必须可 focus；在 `CanvasObject` 的键盘接缝调用同一个 enter adapter。普通 readable 卡键盘 Enter 仍是 inspect；不能以 `readable = kind !== 'gate'` 让门失去键盘入口。
4. **显式 `→ Enter scene` = enter**：它是可达性/移动端补偿入口，必须与双击共用同一个去重的 pending key。
5. **面包屑/返回 = navigation enter adapter**：不伪装成 gate 双击，但同样必须等待 `/api/enter-layer` 成功和目标 layer 重取后再做空间过渡。
6. `next === current layer` 的重进只做同步读取；不追加 `layer_entered`，不播放进入成功演出。
7. `requirements_not_met` 是 domain conflict，不是 network failure：只走本地 GateThreshold；不发作家、不自动 dice、不自动 move。

### 2.3 角色单击与查看外观分离

- sprite 单击唯一语义是进入对话 projection（对话本身是 `dialogue` Depth 的聚焦，不是 `inspect`，也不是 layer enter）；其相机和遮罩按 `doc-06 §3.1、§3.4` 记忆/恢复。
- 角色外观查看由画布本体 hover/focus 或角色资料/小天地投影承担；不得在单击角色后先弹一个“查看外观”再等第二次单击聊天。若产品需要只读详情，必须另有明确的资料控件，不能挪用单击语义。
- `EntityInteractions` 的 Talk 按钮、encountered/resident orb、角色 tab Chat 必须调用相同的 dialogue adapter；任何来源缺 `characterId` 都是 failed，不进入遮罩。
- Nook 中不出现 gate enter；Nook 与 layer 必须共享同一 `ActionFeedbackStore`、present 结果和 dialogue adapter，`characters/<id>` 不是 `enterLayer` 目标。NookView 的 present/dialogue parity 是本批启用契约，不得以“当前 projection 缺 callback”为 conditional fallback；实现接缝由 `docs/nook` owner 回写。

## 3. 事实反馈状态机与节拍

### 3.1 前端本地状态形状（NEW）

不新增服务端协议；建议建立一个仅存于前端的反馈 adapter：

```ts
// NEW — internal local seam; no server/WS payload.
type ActionFeedbackPhase = 'pending' | 'succeeded' | 'failed' | 'conflict' | 'cancelled';
type ActionVerb = 'inspect' | 'act' | 'enter' | 'choice' | 'dice' | 'present' | 'cancel';
type PresentationIntent =
  | { kind: 'none' }
  | { kind: 'use-item'; foley: UseItemOnPresentation['foley']; burst: UseItemOnPresentation['burst'] }
  | { kind: 'gate'; key: string }
  | { kind: 'dice'; key: string; verdict: DiceCeremonyInput }
  | { kind: 'page'; key: string };
interface ActionFeedback {
  key: string;
  verb: ActionVerb;
  target?: string;
  phase: ActionFeedbackPhase;
  message?: string;
  code?: string;
  presentation: PresentationIntent;
}
interface ActionFeedbackStore {
  begin(input: { key: string; verb: ActionVerb; target?: string }): ActionFeedback;
  settle(key: string, result: ActionResultDetails): ActionFeedback;
  cancel(key: string): ActionFeedback;
  get(key: string): ActionFeedback | null;
}
type ActionResultDetails =
  | { verb: 'enter'; layer: string; name: string; first: boolean; event: WorldEvent }
  | { verb: 'choice'; details: ChooseOptionDetails }
  | { verb: 'dice'; details: RollDiceDetails }
  | { verb: 'present'; details: UseItemOnDetails }
  | { verb: 'move' | 'take' | 'drop'; details: MoveEntityDetails }
  | { verb: 'inspect'; details: { path: string } }
  | { verb: 'act'; details: WriterPromptAcceptance }
  | { verb: 'error'; code: string; message: string };

function classifyActionResult(
  verb: ActionVerb,
  result: { ok: true; details: ActionResultDetails } | { ok: false; error: unknown } | { cancelled: true },
): ActionFeedbackPhase;
```

`RollDiceDetails`、`UseItemOnDetails`、`UseItemOnPresentation`、`WorldEvent` 必须直接引用真实类型（实现时补真实 import）；不得复制一份近似字段。`classifyActionResult` 必须按 `verb` 与结构化 details 判定，不能只按 HTTP 2xx 或人类文案：`present.details.handled:false` 即使 HTTP 2xx 也必须是 `conflict`；`dice.details.passed:false` 是成功落账后的检定事实，不是 action conflict。只有 `settle` 完成并经过数据投影/重取，才允许把 typed `PresentationIntent` 交给声画 Seam。

`ActionFeedbackStore` 是本地投影，不是第二个世界状态源；pending key、终态一次性与 details 判定必须可独立测试。Dice 的 HTTP `RollDiceDetails` 与 writer `dice_result` 必须先归一到 `docs/ux/00 §4.6.2` 的 `DiceCeremonyInput`，再由同一 `DiceCeremony` 消费。

### 3.2 固定时序

```text
用户手势
→ 建立 pending（只显示等待/可取消，不显示成功含义）
→ 发既有 HTTP/WS action
→ 权威结果：2xx details 或 ActionError
→ 持久事实/事件重取或既有 WS world_event/file_changed
→ 视觉 / 音频 / Chalk / camera / performance
→ succeeded / failed / conflict / cancelled 终态保留到本地反馈节拍结束
```

逐步漏接后果：

1. **pending 漏掉** → 重复 click/drop 可产生两次 `choice`、两次 `use_item_on` 或重复进入；UI 会先显示成功再被回滚。
2. **权威结果漏掉** → 前端只能猜 HTTP 文本或碰撞结果，`handled:false`、gate 409 和骰子拒绝会被误报成功。
3. **持久事实/事件重取漏掉** → 成功视觉与真实 `/layer`/`player` 文件脱节，重进场景后“演出成功、世界没变”。
4. **终态与演出顺序漏掉** → 解锁音、骰子音、Chalk 或 camera 在失败前已发生，玩家无法相信文件真相。
5. **失败/冲突可见性漏掉** → 玩家只能看到“拖回去/按钮没反应”，无法判断是缺物、错物、网络故障还是事件落账失败。

节拍规则：

- **pending**：按钮 `aria-busy`/disabled、drop target 可高亮、门卡可显示“准备进入”的非成功 pressed 状态；不得播放 `unlock`、`gate-open`、`dice-roll`、成功 stinger，不得写 Chalk，不得 fly camera，不得改变持久实体。普通 drag preview 不是成功。
- **succeeded**：仅在 2xx/权威帧确认后进入；对会改世界的 `present`/`move`，必须再完成对应 `world_event`/`refresh` 的真值接管，才演成功效果。音效来自动作结果提供的现有 `presentation` 或既有演出帧，不从视觉分支推断。
- **failed**：`ActionError`、非 2xx、解析失败、网络错误或内部错误。显示 role alert/Chrome notice；保留原实体、背包和可重试入口。不能调用成功专属 `playFoley`、stinger、Chalk、camera 或 `PerformanceLayer`。
- **conflict**：动作层明确拒绝世界效果但请求本身已被理解（gate requirements、wrong item、already rolled、choice stale、name collision）。显示本地化、可行动的原因；可以有低刺激“拒绝/碰壁”反馈，但不得使用成功的 unlock/落定语义；`use_item_on` 的 `presentation` 是唯一可用的结果提示。
- **cancelled**：未发请求的 gesture/inspect close 立即结束；已发请求不允许本地改成 cancelled。`writer_abort` 只表示 stop requested，必须等 `turn_aborted`/`error`；不能提前把 WriterBar 变 idle 或把半截 Chalk 当失败落板。Writer 对外仍只有 `idle/writing`，`stopRequested` 与 `error/retryable` 是附加维度（`docs/ux/03 §3、§5、§7`），EntityInteractions 的 HTTP busy 不得写 writer-state。

### 3.3 Depth、声画与 Chalk 的门槛

- `pending` 属于 `entity/chrome` 低动量提示；目标描边可以存在，但不进入 `performance` Depth。
- `succeeded` 的 `unlock`、`gate-open`、`paper-slide`、`dice` 仪式、camera fly 进入既有 `performance/stage` Depth（具体投影者依 `docs/ux/00 §4.2`），且必须晚于 §3.2 的 authority + reconcile。
- 任何 `chalk_writing/writer_delta/chalk_landed` 只能由既有 WS/真实文件链驱动：玩家点击 choice/use item 的成功响应不能自行造 Chalk。`choice` 自动作家轮只有 `/api/choice` 的 autoWrite 逻辑与后续 writer 帧可以触发（`world.ts:1039-1046`）。
- `chalk_landed/image_landed` 只表示座位过户；不得把它们当 item drop/进入/解谜成功。失败 `tool_end` 必须复用 `evictPhantom`，不留半成品。
- 允许的拟音取自现有 `apps/web/src/lib/audio.ts`/`docs/perform/00 §8b`：`unlock`、`paper-slide`、`dice-roll`、`gate-open`、`crit-chime` 等。对于 `use_item_on`，前端只消费 `details.presentation`；`handled:false` 的 character-like present 可用 `paper-slide/present` 表达“出示被看见但未生效”，不能播 `unlock`。
- Effects off、`prefers-reduced-motion`、页面隐藏的降级必须遵守 `docs/ux/00 §4.7` 和 `docs/components/00 §4.2` 更保守者：保留必要的文字/状态，卸载非必要循环和成功装饰；不绕过用户设置。

## 4. 各动作的错误矩阵

### 4.1 Gate / visual door

| 权威结果 | phase | 玩家可见反馈 | 不得发生 |
|---|---|---|---|
| 2xx `enterLayer.details` | succeeded | 先重取目标 layer，再 camera/门面展开；`first:true` 显示“场景正在成形” pending，不宣称初始化完成 | HTTP 前换层、播放成功门音；`first` 直接当 `layer_initialized` |
| 409 `requirements_not_met` + `missing[]` | conflict | `gateFeedback` → `GateThreshold`：显示 gate 的 `blocked` 文案、缺失物本地化标题/描边；Return to scene/Escape/重试 | 显示 409/JSON/path；调用 writer、dice、move；播放 unlock/gate-open |
| 409 `invalid_gate` | failed（配置错误） | 诚实技术/配置 alert，保留当前场景；建议提供“门配置无效”而非虚构缺物 | 当作 requirements_not_met；显示作者 blocked 文案 |
| 400 invalid argument/path、404 not_found | failed | chrome alert，保留当前 layer，允许重试/返回 | 改写 layer、空目标 camera、成功演出 |
| 409 no active world、5xx/network | failed | 打开世界选择或显示连接/服务错误，按既有 `airp:world-unavailable` 行为处理 | 把连接失败写成剧情门禁 |
| 同层重进 | succeeded（read sync） | `fetchLayer` 同步数据；不新增事件、不做穿越演出 | 重复 `layer_entered`、camera 跳动 |

### 4.3 Item drop 与 `use_item_on`

|---|---|---|---|

## 5. Module / Interface / Implementation / Depth / Seam / Adapter / Leverage / Locality

### 5.1 Module 归属

- **Action semantics Module**：本篇冻结动作词与入口矩阵；不拥有动作领域写入。
- **Action result Adapter（NEW）**：`apps/web/src/lib/action-feedback.ts`；把 `AirpRequestError`、HTTP details 和既有 WS result 映射为 `ActionFeedback`，供 App、Canvas、BagItemDialog、Nook 使用。它是唯一决定 pending/终态的前端接缝。
- **World authority Module**：`packages/shared/src/actions/*.ts` + `WorldStore`；继续拥有校验、落盘、事件、`details`。本篇只消费，不重写。
- **Projection Module**：`CardRenderer`/`PropCard`/`CanvasObject`/`EntityInteractions`/`BagItemDialog`/`GateThreshold`；只把 Adapter 的 phase 映射到 `entity/chrome/performance/dialogue` Depth。
- **Performance Module**：`useWorld` 既有 WS case、`phantom.ts`、`PerformanceLayer`、`DiceRoller`；只有 authority/reconcile 后才能演。

### 5.2 Interface 与契约接缝

- `CardRendererProps.onEnterGate`、`onItemDropOnTarget` 和 `CanvasObjectProps` 现有回调保留名字，调用必须通过共享 Adapter；不新增平行 `onUnlock`/`onUseSuccess`。
- `UseItemOnDetails.presentation` 是 present 反馈唯一来源；前端不得依据 `targetKind`、CSS class 或 visual 值猜音效。
- `EnterLayerDetails.first` 只驱动 initializer pending；`layer_initialized/layer_init_failed` 仍走唯一 `world_event` case 和 `airp:layer-init`。
- `ChooseOptionDetails.index/count` 是 stale detection 接缝；不在前端复制 `visibleChoiceOptions` 解析规则。
- `RollDiceDetails` 的 `crit/fumble/forged` 是结果事实；不在 UI 重新按 95/5 阈值猜（仅兼容旧数据时由现有组件降级）。
- `NookView` 的 action surface（NEW）必须转发与 layer 相同的 `onItemDropOnTarget(item,target)`、`onOpenCharacterModal(characterId)`、`onEntityAction(prompt)` 结果接缝；它们直接消费父级 `ActionFeedbackStore` 与同一 details/presentation。Nook 不得 conditional 地隐藏 present/dialogue parity；仅 gate enter 被禁止。

### 5.3 Implementation 与 Locality

1. **Action result Adapter（NEW）** 的实现落点建议为 `apps/web/src/lib/action-feedback.ts`；其中 `ActionFeedbackStore` 维护当前 feedback snapshot，子组件通过回调读取/提交，不各自捕获 `fetch`/`String(error)`。
2. **App action coordinator（NEW）**：`apps/web/src/App.tsx` 的 `handleItemDrop`、`handleReturnItem`、`handleTakeItem`、choice/dice/enter 回调统一通过 Adapter；不得让组件直接调用 gateway 后再向 App 报一个已丢失 details 的 `(result, passed)`。
3. **Enter outcome seam（NEW）**：`useWorld.enterLayer(next: string): Promise<EnterLayerOutcome>`；`type EnterLayerOutcome = { phase: 'succeeded'; details: EnterLayerDetails } | { phase: 'conflict' | 'failed'; error: AirpRequestError }`。`enterLayer` 不得再以 `Promise<void>` 吞掉 `AirpRequestError`；它必须把显式 outcome 交给 `enterGate(target, source)`，由 adapter 决定 GateThreshold/technical alert，且成功 outcome 仍须等待其内部 `fetchLayer` 完成后才允许 camera。
4. **Gate adapter（NEW）**：`enterGate(target: string, source: 'double-click'|'keyboard'|'button'|'breadcrumb'): Promise<ActionFeedback>`，唯一去重的空间接缝；不新增 endpoint。
5. **Present adapter（NEW）**：`presentItem(item: string, target: string): Promise<UseItemOnDetails>`；消费 `handled/reason/presentation`，成功 2xx 后必须再等待 `world_event`/`refresh` 的 target 真值接管，然后才显示成功 `PresentationIntent`；`handled:false` 只显示 conflict。
6. `CardRenderer`/`PropCard` 只负责 view/inspect 和把真实 `path` 传入 adapter；移除 visual door 单击直接 onEnter 的语义（实现阶段依据此设计改接线）。
7. `EntityInteractions` 的 `choose`、Take、Enter、Talk 与 `BagItemDialog` 的 widgets 不得持有第二套 action busy/error 判定；`run()` 仅可变成 Adapter 的薄 UI seam。
8. `DiceRoller` 的动作实现仍可在本组件内作为显示 Module，但必须把“请求结果已到达”作为开启动画的 gate；其 `onRollComplete` 只能在 settled succeeded 后触发。
9. `useWorld.enterLayer` 当前在失败时 dispatch `gate-feedback`/`airp:notice`（`:186-211`）；实现阶段必须把 dispatch 与显式 `EnterLayerOutcome` 对齐，不能一边 dispatch 一边对调用方返回 void。
10. 所有成功空间移动必须在真实目标 payload 接管后执行；与 `Canvas.tsx` 的 framing effect、`useCamera` module state 和 Nook active projection 的相机记忆对齐，不在 pointer handler 内 fly。

### 5.4 Leverage 与跨模块复用

- 复用 `gateFeedback`/`GateThreshold` 的“场景内拒绝”机制，不把 HTTP/JSON 暴露给玩家。
- 复用 `airpGateway` 的 `AirpRequestError` status/payload；不重新定义错误字符串协议。
- 复用 `useWorld` 唯一 WS、`mergeItemPatch`/`fetchLayer` 和 `reconcileLanded`；不得为动作 feedback 新建 WS。
- 复用 `playFoley`/`playStinger` 枚举，且由 `UseItemOnPresentation`/权威帧选择时机。
- 复用 `BagItemDialog` 的 Escape/纸外关闭、`EntityInteractions` 的 `data-no-drag`，但关闭只影响 inspect projection，不写 world。

#### 7.2.1 `doc-06` 首拍五层反馈 fixture（F0）

### 7.3 机械负断言（必须有一条修复前失败的非空性用例）

1. `CardRenderer`/`PropCard` 的 gate 单击不得调用 `onEnterGate`；**修复前现有 `onClick` 会使断言失败**，双击/Enter/显式 button 只能调用一次。
2. target drop 的 pending 阶段调用记录中不得有 `playFoley('unlock')` 或 `puzzle-unlock-burst`；**修复前 `CardRenderer.tsx:99-102` 与 `CanvasObject.tsx:223-225` 会失败**。
3. Dice HTTP 未返回 2xx 前，`dice-roll`、tumble、crit/fumble、`onRollComplete` 调用次数必须为 0；**修复前 `DiceRoller.tsx:161-170` 会失败**。
4. inspect 单击/打开/关闭时，`/api/choice`、`/api/dice`、`/api/use-item`、`writer_prompt` 请求次数必须为 0；**修复前 `EntityInteractions.tsx:91` 的 Look closer 会失败**。
5. `handled:false` 的 `use_item_on` 不得出现 unlock 成功专属效果；**修复前 App 固定成功 toast + drop burst 会失败**。
6. action rejection 不得修改 `LayerState.layer`、camera focus、物品路径或 Chalk phantom；只有 authority + reconcile 后才允许相应变更。
7. `world_event` 只在 `useWorld.ts` 唯一消费点去重/转发；动作反馈 adapter 不得创建第二 WebSocket 或第二事件去重集合。
8. `.object--ghost` 在任何 `pending/succeeded/failed/conflict/cancelled` 均 `pointer-events:none`；God Hand 不得成为例外。
9. reduced-motion / Effects off / `document.hidden` 下，失败/冲突文字和状态保留，循环装饰、视频和非必要 burst 停止；不能因“反馈”重新启用。
10. 矩阵中每个 `succeeded` 都必须有一个失败对照：无权威结果时截图/断言不会出现其成功专属音画；否则验收是假绿。
