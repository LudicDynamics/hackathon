# UX 舞台统一与交互连续性：共同上下文

> 状态：设计阶段冻结草案，尚未进入实现  
> 日期：2026-09-13  
> 范围：全局视觉语法、舞台 Depth、Chrome 状态、动作语义、Nook 投影、公开演出状态  
> 关联：`docs/components/00-共同上下文.md`、`docs/layout/00-共同上下文.md`、`docs/perform/00-共同上下文.md`、`docs/nook/00-共同上下文.md`

## 1. 目标

把当前前端从“多套视觉与交互 Module 叠加”收敛为一个连续的纸雕舞台：

1. 场景、实体、背包、阅读层、角色遮罩、Nook 与世界选择共享同一视觉语法，但允许题材 Adapter 改变材质细节；
2. 背景、画布、实体、演出、Chrome、遮罩拥有稳定且可测试的 Depth 语义；
3. 玩家只需要学习一套查看、行动、进入、出示、取消和失败回退的动作语法；
4. Nook 是与层并列的舞台投影，不是另一个拥有半套交互的 Canvas；
5. 浏览器截图、动作回放和状态转移测试能够共同证明美学与交互闭环。

## 2. 权威层级

发生冲突时按以下顺序裁决：

1. 稳定系统原则：文件即真相、事件是唯一变更来源、一个 active projection、动作结果先于成功演出；
2. 本文的跨 Module 契约；
3. 专题冻结契约：components / layout / perform / nook / settings / wiring；
4. `docs/doc-04`、`doc-06`、`doc-19` 的产品与演出要求；
5. 现有源码实现；
6. 浏览器当前表现只能作为证据，不自动成为设计真相。

本批次不得悄悄修改专题冻结契约。若实现需要改变字段、事件、权限或路径，必须在设计文档中列出冲突，并先回写权威文档。

## 3. 与 components / layout 的职责分离

### 3.1 components 拥有

- 实体 `appearance` 命名空间；
- appearance registry / resolver；
- verified token 与 `AppearanceResolution`；
- 世界/层 material、bgStyle 与实体外观的隔离；
- 实体 view registry、Chalk `surface:none`、旧 Chalk / letter 迁移。

本批次不得重新定义 `appearance` 字段、`CARD_FORMS` 尺寸、旋转、互动字段或实例 token。

### 3.2 layout 拥有

- `flowColumns` 与自动座位几何；
- `cards.width/height`、footprint、occupied 与 reseat；
- phantom 与真实卡片座位过户；
- Chalk 拖拽锁与 God Hand 权限的几何接缝；
- 生成批次与初始化时的落位顺序。

本批次不得把 `flowColumns` 扩展成视觉 Depth、相机管理、Chrome 排布或动作语义 Module。

### 3.3 本批次拥有

- 全局 visual grammar：shell、surface、字体、颜色、纸面、shadow、响应式尺度；
- Theatre Depth：背景、世界舞台、实体、show、Chrome、dialogue 的覆盖语义；
- Chrome / attention / writer public state 的归属；
- inspect / act / enter / present 的动作语义与结果反馈节拍；
- Nook 与层的 active projection、相机记忆和完整互动接缝；
- 公开 Agent frame、writer busy、dialogue phase 的单一消费路径；
- 音频、动效、Reduced motion 与 Effects 的全局优先级。

## 4. 跨 Module 契约

### 4.1 Visual grammar 与 appearance 的关系

- visual grammar 决定“舞台是什么材质”；
- appearance 决定“某个实体在该舞台上是什么外观”；
- appearance 不得通过 literal CSS 改写 shell 的身份；
- shell 不得覆盖实体声明的 verified token；
- `surface:none` 的 Chalk 不得被全局 `.object` 纸壳重新包裹。

### 4.2 Theatre Depth

Depth 是语义名，不是任意数字。至少需要表达：

- `background`：背景图、动态画卷、环境粒子；
- `stage`：画布纸面、连接线与空间底座；
- `entity`：卡片、头像、道具与 Chalk；
- `performance`：幻影、骰子、追光、Money Shot、writer 演出；
- `chrome`：Header、行动台、侧栏、状态回执；
- `dialogue`：角色特写与阅读焦点。

具体 stacking 实现属于 Implementation；任何 Module 不得自行发明同义 Depth 或通过无穷增大 z-index 解决覆盖问题。
在 `layout` 契约中，phantom 是临时投影：它可以位于 `performance`，但 phantom 的 seat/z 不能被解释为真实卡片的 z；`.object--ghost` 必须保持 `pointer-events:none`，不因 God Hand 或演出模式获得例外。`flowColumns` 只产生 x/y/w/h，不参与 PerformanceLayer、spotlight 或 Chrome stacking。

### 4.2.1 座位过户不是动作成功

`chalk_landed`、`image_landed` 只表示座位过户 / reconcile，不表示动作成功，也不触发通用成功音效或成功剧情演出。真实 `/layer` 坐标接管最终投影；`tool_end` 失败必须让所有相关 phantom/source evict，并显示玩家可见文案，不能只写 `console.warn`。

### 4.2.2 全局动效取更保守者

实体 appearance 的 motion 规则来自 `components/00 §5` 与 verified token；本批次的全局 Effects / Reduced motion 规则不能放宽它。两者冲突时取更保守者：不位移、不循环、不持续合成；关键反馈只能降级为低动量、低刺激版本。

### 4.3 动作语义

所有可操作实体至少区分：

- `inspect`：查看外观或正文，不改变世界事实；
- `act`：选择、掷骰、使用、移动等改变世界的动作；
- `enter`：穿越门或场景；
- `present`：将背包物品交给目标；
- `cancel`：取消当前演出或关闭当前焦点。

门卡必须遵守 `doc-06` 的双击进入语义；角色头像遵守单击进入对话语义。查看外观与选择行动不能因为存在 `onEnter` 就合并。

### 4.4 事实与反馈

动作的反馈顺序固定为：

```text
用户动作
→ 动作层请求
→ 权威结果（成功 / 失败 / 冲突 / 取消）
→ 持久事实与事件
→ 视觉 / 音频 / Chalk / 空间演出
```

未获得权威成功结果时，不得播放会被玩家理解为成功的 unlock、落定或剧情推进演出。失败必须有可见的本地反馈，并保持重试或返回现场的路径。

### 4.5 Active projection 与 Nook

- 同一时刻只允许一个舞台投影拥有 Canvas 交互焦点；
- Nook 不拥有第二份 `useWorld`、WS 消费、相机 singleton 或全局 DOM 测量；
- 层与 Nook 可以使用不同的空间数据 Adapter，但必须消费同一套动作语义、Depth 和 footprint 输入；
- 进入 dialogue、Nook、layer 的相机记忆必须是可嵌套、可恢复的，而不是连续 `save/restore` 覆盖。
### 4.5.1 Player Nook note seam

doc-06 §4.2–§4.3 的“玩家留便签 → 角色批注”在本批次不是静态 mock。实现必须新增一个 player-authorized action seam（NEW），不允许让前端直接写文件或复用 god-only `writeChalk` 路由：

```ts
interface NookNoteInput {
  characterId: string;  // MUST pass isValidCharacterId + nookIdOf
  title: string;
  body: string;
  clientRef?: string;
}
interface NookNoteOutcome {
  path: string;          // server-generated direct child under characters/<id>
  eventSeq: number;
  actor: { type: 'player' };
  created: true;
}
```

推荐 transport：`POST /api/nook-note`（NEW），server 先用 shared `isValidCharacterId(characterId)` / `nookIdOf(characterId)` 验证，失败返回 `invalid_argument`，再以固定 `actor: { type: 'player' }` 调用共享 `writeChalk` action。客户端不能提交 actor；服务端生成 `characters/<id>/NN-<slug>.md`，不接受任意 path/frontmatter/link。失败返回可区分的 `invalid_character` / `invalid_note` / `conflict`，不返回成功假象。回放必须断言落账事件的 actor 精确等于 `{type:'player'}`。world_event 重取后，角色批注必须作为真实文件或事件投影持久存在，重新进入 Nook 仍可见。
### 4.6 公开 Agent 状态
- WS 入站只经过一个归属与去重路径；
- writer、character、show、error 的公开状态由单一投影提供；
- CharacterModal、Writer dock、Chrome 不得各自监听同一帧并自行判断 phase；
- `characterId` 缺失或不匹配的帧必须显式丢弃并记录可见错误，不得进入当前角色遮罩。
### 4.6.1 Writer state 唯一形状

`docs/ux/03` 是 writer public state 的唯一 owner；`docs/ux/06` 只引用它，不得再定义第二个 `WriterState`。实现阶段采用同一投影字段：`phase`、`reason`、`stopRequested`、`stage`、`startedAt`、`toolCount`、`error`、`lastPrompt`、`lastMessage`、`completionSeq`。`WriterResult` 从 `lastMessage + completionSeq` 投影，不另存 `result`。`acceptWriterFrame` 是唯一 writer 帧入口；`beginWriterPrompt` 是被接受的 prompt 唯一开始点。

### 4.6.2 Dice ceremony 唯一归一化

玩家 HTTP `RollDiceDetails` 与现有 writer `dice_result` 是两个输入 Adapter，不是两套 ceremony。它们必须先归一化为同一内部 `DiceCeremonyInput`（NEW，非 WS/HTTP payload），再由 `DiceCeremony` 消费。HTTP 详情中的 `result/passed` 是权威结果；writer 帧经过现有 `dice_result` 过滤。不得要求玩家 HTTP 路径伪造 WS 帧，也不得让两条路径各自播放一套仪式。
```ts
// NEW internal normalization; extends the real RollDiceDetails type from
// packages/shared/src/actions/roll-dice.ts; no network payload.
export interface DiceCeremonyInput extends RollDiceDetails {
  source: 'player-http' | 'writer-frame' | 'character-frame';
  sourceId: string;
  requestKey: string;
  sourceSeq: number; // allocated by the canonical dice ingress, never copied from timestamp
}
```

字段映射必须逐字保留 `RollDiceDetails` 的 `path/name/dice/desc/expect/result/passed/rolls/crit/fumble/forged/layer`；`dice-ceremony.ts` 先用 source-specific fingerprint 去重，再给每个新输入分配单调 `sourceSeq`。`player-http` 直接 spread `POST /api/dice` 的 details，`sourceId`/`requestKey` 使用 ActionFeedback 的本地 key；`writer-frame` 与 `character-frame` 直接 spread已归属的 `dice_result` / `DiceFrameVerdict`，`sourceId = source + ':' + characterId + ':' + path + ':' + sourceSeq`。WS timestamp 只参与 fingerprint，不直接转换为 number。缺少任一权威字段或角色 ID 的输入进入可见错误，不得创建半截骰子演出。
**Source owner：**实现时由 `apps/web/src/lib/dice-ceremony.ts`（NEW）导出 `DiceCeremonyInput`；本文冻结字段与映射，不提供可 import 的 TypeScript module。`perform/02`、`ux/04` 和 `DiceCeremony.tsx` 都必须从该 source owner 引用，不能从 Markdown 导入。
`apps/web/src/lib/dice-ceremony.ts` 同时导出以下内部 allocator（NEW），消除 listener 自己拼接 `sourceSeq` 的歧义：

```ts
interface DiceIngressAllocator {
  fingerprint(raw: RollDiceDetails | DiceFrameVerdict, source: DiceCeremonyInput['source']): string;
  allocate(fingerprint: string): { requestKey: string; sourceSeq: number; isDuplicate: boolean };
}
```

`fingerprint` 使用完整权威字段、source、characterId（若有）和 WS timestamp；`allocate` 只在 fingerprint 未见过时递增 `sourceSeq`。HTTP ActionFeedback key 可作为 fingerprint 的稳定前缀，但不能让任意客户端直接提交 sourceSeq。


### 4.6.3 Action feedback 的终结一次性

`ActionFeedback` 必须有以 `key` 为索引的本地 pending store：同一 key 只能 begin 一次，终态只能由一次权威结果或明确本地 cancel 写入；`handled:false`、HTTP 2xx 但 domain conflict、409 门禁都不能被粗略归类为 succeeded。所有动作 Adapter 必须返回可区分的成功、冲突、失败和取消结果；`Promise<void>` 且吞掉错误的旧接缝不能直接作为成功依据。

### 4.7 动效、音频与用户偏好

优先级从高到低：

1. 用户明确关闭 Effects；
2. `prefers-reduced-motion`；
3. 页面不可见或资源未就绪；
4. 默认演出偏好。

关键事实反馈可以保留低动量、低刺激版本，但不得绕过用户关闭设置。音频与视觉演出消费同一演出阶段，不从各自局部点击推断时机。

## 7. 必须机械核验的结果

### 7.1 统一机械门禁 owner

本批次只允许一个机械门禁 Module：`tools/check-ux-contract.mjs`（NEW）。机器可读登记文件为 `tools/ux-contract.json`（NEW），包含三组互相关联的登记：

- `visual`: `--ux-*` canonical token、legacy alias、允许的 literal/gradient exception、appearance namespace 只读接缝；
- `depth`: 六类 Depth、根 stacking context、surface owner、允许的局部偏移和数据排序例外；
- `projection`: active marker、Canvas root、ghost pointer、camera/footprint scope 与 owner。

扫描范围、失败输出与非空 fixture 统一由该门禁声明；不得再分别创建只扫视觉或只扫 Depth、却互不求 diff 的两个 checker。`tools/check-ux-contract.mjs` 不替代浏览器截图、动作回放、性能 trace 或现有 components/layout 门禁；它只证明静态登记与源码消费没有漂移。
设计完成后至少需要形成以下可执行检查：

- visual grammar token 来源不存在未登记的第三套 literal 覆盖；
- appearance 不改变 footprint、rotation、interaction 和 shell Depth；
- Depth 名称与投影者一一对应，不出现未登记 z-index；
- Nook 与 layer 的动作矩阵一致，且只有一个 active projection；
- gate 单击 / 双击 / Enter、inspect / enter 分离有行为测试；
- 失败动作不会出现成功专属音效或成功空间演出；
- 公开 Agent frame 只有一个归属消费路径；
- Reduced motion、Effects off、页面隐藏均停止非必要装饰循环；
- 桌面 1440×960、桌面窄屏、390×844 至少各有截图验收。

## 8. 设计冲突记录规则

任何子文档发现以下情况，必须单列“发现的冲突 / 需要修订的上位文档”：

- 与 `components/00` 或 `layout/00` 的字段、权限、路径冲突；
- 与 `doc-06` 的门卡、角色、反馈或退场语义冲突；
- 与 `perform/00`、`nook/00` 的帧、相机、投影形状冲突；

- 现状源码与文档断言不一致。

主代理确认后，必须在同一回合广播契约变更，并把变更回写到所有受影响文档。
