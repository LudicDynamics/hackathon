# 物品行动草稿设计

> 状态：已实现（2026-09-14）
> 日期：2026-09-14
> 目标：把“选择一个背包物品”变成可编辑的本地 Writer 草稿；只有玩家明确点击／键盘触发 `Send`，请求才进入现有 Writer prompt 接缝。
> 依据：`docs/ux/08-niko功能迁移契约.md`、`docs/ux/00-共同上下文.md`、`docs/agent-awareness/00-共同上下文.md`、`docs/tools/00-共同上下文.md`，以及 `[origin/niko@8a2df60]` 的 `apps/web/src/lib/item-action-draft.ts`。

## 1. 一句话定位与边界

**物品行动草稿是背包到 Writer 输入框的可撤销本地编辑辅助，不是物品动作，也不是新的动作层。**

玩家从背包选择物品后，界面只把一个带精确世界相对路径的 Markdown 引用追加到 Writer 草稿；玩家可以编辑、删除或继续追加引用。选择、重复选择、取消、关闭和重新打开弹窗均不得发送请求、写文件、写事件、消耗物品、移动物品或启动 Writer。只有明确的 `Send`（发送按钮或 Writer 输入框的 `Enter`）才把最终编辑文本交给现有 `sendToWriter`／`beginWriterPrompt` 接缝。物品是否可用、是否消耗、是否移动、是否需要骰子或场景条件，仍由现有 Writer 与动作工具／事件链决定。

“Place in current scene”、拖放、frontmatter choice 等已有入口不被这个草稿功能改写：它们继续走自己的现有动作语义。

## 2. 共享契约引用与不变量

本设计服从以下冻结口径：

- `docs/ux/08-niko功能迁移契约.md:72-76`：物品草稿只改本地输入草稿；只有明确 Send 才进入 Writer；选择和关闭不能改变世界。
- `docs/ux/08-niko功能迁移契约.md:10-17`、`docs/ux/00-共同上下文.md:107-119`：文件和 `world_event` 才是世界真相；动作结果先于演出；组件不得另造 WS 消费路径。
- `docs/tools/00-共同上下文.md:48-56`：引用使用世界根相对、POSIX、无前导 `./`、无绝对路径的路径；显示标题不能替代稳定路径。
- `docs/agent-awareness/00-共同上下文.md:254-260`：作家正文仍由 Chalk 落点产生；活动提示不是正文或世界事实。草稿中的路径指导只作为 Writer prompt 的输入，不创建 `agent_activity`。
- `useWorld.ts` 是唯一 WebSocket 消费入口。草稿模块不监听 `window` 原始帧、不发 WS 帧，也不读取事件表。

因此，`item-action-draft.ts` 是无副作用纯函数模块；它不 import `airpGateway`、WebSocket、`ActionFeedbackStore` 或动作服务。草稿内的 Markdown 链接是给玩家和 Writer 的可编辑文本，不是隐藏的第二份状态、权限凭证或自动执行指令。

## 3. 输入、签名与精确路径表示

实现落点为 `apps/web/src/lib/item-action-draft.ts`，沿用 niko 的纯函数形状：

```ts
type DraftItem = {
  path: string;
  filename: string;
  frontmatter: Record<string, unknown> | null;
};

type Translate = (
  key: string,
  values?: Record<string, string | number>,
) => string;

export function itemDraftReference(item: DraftItem): string;
export function referencedItemPaths(text: string, items: DraftItem[]): string[];
export function appendItemAction(
  text: string,
  item: DraftItem,
  t: Translate,
): string;
export function buildItemActionPrompt(
  text: string,
  items: DraftItem[],
): string;
```

行为约束：

1. `itemDraftReference` 的显示部分取 `frontmatter.title || filename`，清理 `[`、`]`、换行；链接目标保留 `item.path`，用 URI 编码处理空格和圆括号。路径不会被标题重写。
2. `referencedItemPaths` 只接受文本中能解析的 Markdown 链接，并只返回当前 `items` 中路径逐字相等的项；按文本首次出现顺序去重。解码失败或未闭合的编辑不产生引用。
3. `appendItemAction` 若同一精确路径已在文本中，原文逐字返回；同标题但不同路径仍追加第二项。未引用时追加本地化的 `Use {item}.` 句子，空草稿直接生成该句子，非空文本保留原文并以一个空格分隔。
4. `buildItemActionPrompt` 在没有当前背包引用时逐字返回文本；有引用时在最终文本后追加 exact paths 指令，要求 Writer 读取每个物品和当前场景 README（含 frontmatter/intent），并声明引用不等于自动消费、组合、移动或绕过场景门槛。目标不明确时要求 Writer 在 Chalk 中询问；合法动作仍使用既有动作工具并落账。

路径示例：

```text
玩家可见／可编辑：把它交给 Ryo。[ぜんまいの蛙](player/clockwork-frog.md)を使う。
发送给 Writer 的附加引用："player/clockwork-frog.md"
```

不允许把原始绝对路径、`../`、客户端提交的 actor 或任意“已使用”标志放进该接口。`buildItemActionPrompt` 不替 Writer 判断权限，也不直接调用 `use_item_on`。

## 4. 状态模型与不变量

状态 owner 是 `App.tsx`，不是 `BagItemDialog`、`WriterBar` 或新的 store：

```ts
// App-local UI state; never a world fact.
writerDraft: string;
selectedBagPath: string | null;
```

`writerDraft` 是当前 Writer 输入的唯一草稿；`selectedBagPath` 只控制背包阅读弹窗。`preparedAction`（若保留）只能是通知用的截断文本，不能作为发送依据。引用集合在 Send 时从“当前草稿文本 + 当前 `backpack` 快照”重新计算，不能另存隐藏 attachments：玩家删掉 Markdown 链接，发送时就不再带该路径；物品在刷新后不再属于背包，也不能被隐藏引用继续附着。

不变量：

- 选择物品只调用 `appendItemAction` 并更新 `writerDraft`，不产生 `ActionFeedback`、`world_event` 或 Writer turn。
- 同一 `path` 至多有一个由选择产生的引用；两个不同 `path` 即使标题相同也必须保留两个引用。
- `writerLocked = writerState.phase === 'writing' || writerSubmitPending || state?.worldFrozen === true`（当前派生见 `apps/web/src/App.tsx:187-195`）。锁定时不能接受新的物品草稿选择，也不能发送；不排队、不打断。
- `sendToWriter` 接受后才清空草稿；被拒绝时保留完整文本，供玩家修正或重试。世界切换时清空 `writerDraft` 与 `selectedBagPath`，避免把旧世界路径带入新世界。
- 草稿永远不被解释为物品已经使用。真正的消耗／移动／执行只能发生在 Writer 调用既有动作工具并收到权威结果之后。

## 5. 逐步行为与漏接后果

1. **打开物品。** 背包按钮只设置 `selectedBagPath`，从当前 `backpack` 找出物品后显示 `BagItemDialog`。没有 Writer 调用。若把打开误接成动作，会在玩家尚未确认意图时改变世界。
2. **选择“使用这个物品”。** `BagItemDialog` 调用 `onUse(item.path)`；App 校验 `writerLocked`、按路径取得当前物品并调用 `appendItemAction(writerDraft, item, t)`。成功后关闭该阅读弹窗、打开／显出 Writer 区并聚焦输入框，通知“已选中，请检查后发送”。若这里直接调用 `sendToWriter`，会绕过玩家编辑和明确 Send 门槛；若调用 `airpGateway.useItem`，会违反不自动消费约束。
3. **再次选择。** 玩家重新打开同一物品并选择时，`appendItemAction` 原样返回草稿，不重复句子或路径。选择同标题的另一物品时因路径不同而追加第二引用；按标题去重会把两个可区分实体错误合并。
4. **编辑。** Writer 输入为普通可编辑文本。玩家可改写句子、移动或删除链接、加入目标和条件，也可删成空白。实现不维护不可见的“已选物品列表”；否则删掉引用后仍发送隐藏物品，造成意图欺骗。
5. **取消／关闭。** 点击关闭、遮罩外、标题关闭按钮或 `Escape` 只关闭弹窗；它不清空 `writerDraft`，因为草稿已经属于 Writer 输入。若玩家希望取消该物品，只需在 Writer 输入中删除引用或整段文字。关闭后不产生本地动作终态，不调用 `ActionFeedbackStore.cancel`。
6. **明确发送。** Writer 的 `Send` 按钮或输入框 `Enter` 调用 App 的 `submitWriterText`；先 trim 判空，再运行 `buildItemActionPrompt(text, backpack)`，最后调用现有 `sendToWriter(prompt, activeLayer)`。只要该调用未返回 `accepted: true`，输入仍保留，便于恢复。
7. **Writer 工作期间。** 发送被 transport 接受后 Writer state 进入 writing，输入、Send 和物品 Use 均锁定。玩家点击被锁控件不会排队，不产生额外请求；Busy 文案解释“作家正在写”。若漏接这一锁，重复点击会产生多个并发 turn。
8. **结束、失败或停止。** Writer 的 `writer_idle`、error、aborted 继续由 `writer-state.ts` 处理；本功能不伪造完成事件。成功后的世界变化只由真实文件／`world_event` 反映。可重试错误使用现有 `retryWriterPrompt()`，不能因为草稿曾选过物品就自动再次发送。

## 6. 交互矩阵：重复、取消、空文本、窄屏与键盘

| 情境 | 可见行为 | 请求／世界副作用 |
|---|---|---|
| 单击背包物品 | 打开阅读弹窗 | 无 |
| 在弹窗点“使用这个物品” | 追加一次带 exact path 的本地句子，关闭弹窗并聚焦 Writer | 无网络、无事件、无消费／移动 |
| 再次选择同一物品 | 草稿不变，仍只有一个引用 | 无 |
| 选择同标题不同路径物品 | 两个 Markdown 链接都保留 | 无 |
| 手动删除链接 | UI 草稿同步删除；Send 时不再带该路径 | 无 |
| 关闭／遮罩外／`Escape` | 只关闭弹窗；Writer 草稿保留 | 无 |
| Writer busy／世界 frozen 时选择 | Use 按钮 disabled 或保持可见并通知等待；不改变草稿 | 无 |
| 草稿空白时点 Send／按 Enter | 保留输入，显示“请输入行动后再发送”状态；不清空、不调用 prompt seam | 无 |
| 非空时明确 Send | 发送最终编辑文本；接受后清空输入并进入 writing | 仅现有 Writer 请求；没有新增事件 |
| transport closed／busy 拒绝 | 保留文本和引用，显示现有失败原因，可再次 Send | 无世界变化 |
| 桌面窄屏 | Writer 行不溢出；Send 可点击，弹窗内容可滚动，关闭控件保持可见 | 语义不变 |
| 390×844 | 弹窗与 Writer 不互相遮挡；聚焦后软键盘不隐藏 Send；必要时页面可滚到输入框 | 语义不变 |

键盘细则：

- 背包物品按钮支持 `Tab` 聚焦、`Enter`／`Space` 打开；弹窗打开后关闭按钮和 Use 按钮进入合理 Tab 顺序。
- 弹窗 `Escape` 关闭；输入框内的 `Escape` 也关闭弹窗，但不得提交。遮罩监听必须继续遵守现有事件清理，不能新增原始 WS listener。
- Writer 输入框 `Enter` 等同点击 Send；输入法组合期间（`event.nativeEvent.isComposing`，并沿用 `apps/web/src/lib/ime.js` 的 `guardImeKey` 规则）不得误提交。单行输入不新增 Shift+Enter 换行语义。
- Writer 历史的 `ArrowUp`／`ArrowDown` 继续由 App 的已有历史逻辑处理（当前 `apps/web/src/App.tsx:814-821`）；历史切换不能覆盖 App 未发送的当前 draft，回到末尾时恢复它。
- 聚焦、禁用、错误和 Busy 状态必须可由 `aria-label`、`aria-busy`、`role=status`／`role=alert` 读取；不能仅靠颜色或 Toast 传达。

## 7. 前端／后端接线与文件级 owner

数据流固定为：

```text
inventory click
  → App.selectedBagPath
  → BagItemDialog.onUse(path)
  → App.prepareItemUse(path)
  → item-action-draft.appendItemAction
  → App.writerDraft
  → WriterBar controlled input
  → App.submitWriterText
  → item-action-draft.buildItemActionPrompt
  → useWorld.sendToWriter(prompt, layer)
  → writer_prompt + beginWriterPrompt
  → 既有 Writer／动作工具／文件与 world_event 链
```

文件职责：

- `apps/web/src/components/BagItemDialog.tsx`：保留阅读、关闭、Place 与现有 frontmatter choice；新增可选 `onUse?: (path: string) => void` 和 `useDisabled?: boolean`。只在 `onUse` 存在时显示独立 Use 按钮；该按钮仅回调路径，不调用 gateway。`inline` 阅读投影不传 `onUse`，因此 Canvas 阅读不会意外获得 Writer 草稿入口。
- `apps/web/src/App.tsx`：持有 `writerDraft`、`selectedBagPath`、busy/frozen 门禁、历史和 `prepareItemUse`；负责将草稿提交到 `buildItemActionPrompt`，调用 `sendToWriter`，并只在 accepted 后清空。现有 `onPlace={handleReturnItem}` 保持独立。
- `apps/web/src/components/chrome/WriterBar.tsx`：继续负责输入展示、非空 trim、Enter／Send、Writer busy 锁。为支持 App 预填，采用可选 controlled props（例如 `value`／`onChange`）与可转发的 `inputRef`；未提供时保留当前 Nook 的非受控用法。WriterBar 不知道物品路径、不调用 draft helper、不写世界。
- `apps/web/src/lib/item-action-draft.ts`：唯一引用解析和 prompt 附加纯函数 owner；不产生副作用。
- `apps/web/src/lib/action-feedback.ts`：不扩展动作种类；只继续服务真实 choice／Place 等动作的本地回执。
- `apps/web/src/state/useWorld.ts`：保持唯一 WS／Writer 入口；现有 `sendToWriter`（`apps/web/src/state/useWorld.ts:262-287`）继续负责 trim、busy、transport closed、`writer_prompt` 和 `beginWriterPrompt`。
- `apps/web/src/lib/messages.json`：补齐 `Use {item}.`、选择后检查并发送、空输入和等待文案的英文／日文／简中翻译；不把 prompt 指令正文做成可见文案。
- `apps/web/test/item-action-draft.test.mjs`：纯函数和源接线的非空测试 owner；必要的 UI 行为测试继续放在 `apps/web/test`，不写第二套状态源。

后端不新增 route、payload、事件或动作工具。Writer 收到的是普通 `writer_prompt.message`，其中的 exact paths 是 prompt 文本的一部分；作家继续通过既有读取和动作工具决定是否使用物品。`useWorld.ts` 不因本功能增加任何 `window` 监听。

## 8. ActionFeedback、Writer seam 与副作用隔离

`ActionFeedbackStore` 的语义是“一次真实动作尝试的本地回执”，不是所有按钮点击的通用状态。当前 `BagItemDialog` 的 frontmatter choice 从 `apps/web/src/components/BagItemDialog.tsx:42-54` 调用 `runAction`，Place 从 `apps/web/src/components/BagItemDialog.tsx:87-90` 走移动回调；这两条保持原状。

物品 Use 草稿明确**不得**调用 `runAction`、`actionKey`、`airpGateway.choose`、`airpGateway.useItem` 或 `ActionFeedbackStore.cancel`。选择草稿没有 pending／accepted／failed action，因此不应显示“行动成功”回执；可以显示本地“已选中，请检查并发送”提示，但该提示不代表世界事实。

明确 Send 也不是一个新的世界动作反馈：

1. App 先执行空文本和 `writerLocked` 门禁。
2. `buildItemActionPrompt` 只构造最终 Writer 文本。
3. App 调用 `sendToWriter`；其现有返回值区分 `invalid`、`busy`、`transport-closed` 和 accepted（`apps/web/src/state/useWorld.ts:262-287`）。
4. accepted 后 Writer state 才由 `beginWriterPrompt` 进入 writing；随后真实 Writer 工具／动作层负责文件、事件和结果反馈。

因此，Toast、ActivityRail、`agent_activity`、`world_event` 都不从“选择物品”推测成功；也不为草稿添加新事件类型。

## 9. 错误边界与失败恢复

- **物品已消失或路径不在当前背包：** `prepareItemUse` 不修改草稿、不关闭正在看的弹窗，显示“物品已不可用，请刷新”类可见错误。绝不只用标题猜路径，也不把过期路径附在 prompt 中。
- **路径含空格、Unicode、圆括号或标题括号：** `itemDraftReference` 编码链接目标并清理显示标题；解析失败的半成品链接被忽略，保留玩家原文，不抛异常、不发送隐含引用。
- **草稿被玩家改为空或只有空格：** Send 保持输入，`role=status` 提示下一步；不得清空、调用 `sendToWriter` 或制造 Writer busy。
- **Writer busy、world frozen 或重复点击：** Use／Send 门禁在 UI 和 handler 两层都检查；handler 再次检查是必要的竞态保护。返回现有 busy 文案，保留草稿，不排队。
- **发送时连接关闭：** `sendToWriter` 返回 `transport-closed`，保留最终文本和引用，提示“连接已断开，请重试”；不显示 Writer 已开始，不产生世界变化。
- **发送被 invalid 拒绝：** 保留文本；显示现有 invalid message，玩家可以编辑后重试。
- **Writer 进入 error／aborted：** 使用现有 `writer-state.ts` 的 retryable error 与 `retryWriterPrompt()`（`apps/web/src/lib/writer-state.ts:84-91`、`:124-127`）。不得因错误自动重新消费物品或自动再发一轮；Retry 仍需玩家明确触发。
- **世界切换或刷新：** 关闭 selected item 并清空 writerDraft，取消旧世界引用；既有 `resetForReconnect('world_change')` 继续负责 Writer state。失败加载时保留世界选择恢复路径，不把旧草稿发送到新世界。
- **组件卸载／弹窗关闭：** 清理 Escape／pointer listener；本地 draft 是否保留只由 App 控制，不留 promise 回调写入已卸载弹窗。

### 11.2 浏览器冒烟

使用实际应用和真实或受控的现有世界数据，至少验证：

- **桌面 1440×960：** 打开背包物品，点 Use，看到带标题的引用和 exact path；重新打开选择同物品不重复；选另一条同标题不同路径后两条都显示；编辑删除一条；点击 Send 后输入清空、Writer 显示 writing，最终世界变化只在真实 Writer／`world_event` 出现。
- **桌面窄屏：** Writer 行、Send、弹窗关闭控件不溢出；弹窗正文滚动不触发遮罩关闭；Busy 时重复点 Use／Send 不增加 prompt 请求。
- **390×844：** 用触摸打开／关闭弹窗；软键盘出现后可编辑和点击 Send；旋转或滚动不丢草稿；Escape（支持的键盘设备）只关闭弹窗。
- **失败恢复：** 空 Send 显示可读 status 且不发送；断开连接后文本仍在；恢复连接后玩家再次明确 Send 才重试；Writer 错误可走现有 Retry，不自动再发。
- **事实隔离：** 浏览器网络／WS 面板确认选择、取消、关闭和编辑阶段没有新 `/api` 请求、`writer_prompt`、`world_event` 或物品移动请求；只在明确 Send 后观察到一个 Writer prompt。

## 12. 发现的冲突／需要修订的上位文档与未知项

### 发现的冲突／需要修订

1. `[origin/niko@8a2df60]` 的 `BagItemDialog` 同时引入 `EntityInteractions` 与 `onUse`，而当前主线的 `BagItemDialog` 直接渲染 frontmatter widgets 并通过 `runAction` 处理 choice（`apps/web/src/components/BagItemDialog.tsx:42-54`）。本设计只迁移 `onUse` 的本地草稿回调，不迁移 niko 的内容编译器或新动作层；若需要改变 choice 归属，必须另行回写工具／动作契约，当前不做。
2. 当前主 Writer dock 是 `App.tsx:805-825` 的内联输入，`WriterBar.tsx:26-73` 是另一套带本地 state 的输入，形成两个输入实现。本设计冻结采用 controlled `WriterBar` 承载主 dock 输入，由 App 持有唯一 `writerDraft`；`docs/ux/08-niko功能迁移契约.md:131` 要求该 App 接线由同一实现者协调。实现不得保留第三套草稿状态。
3. 当前主线的 `writer-state.ts` 把 Writer busy 定义为从 `beginWriterPrompt` 到 `writer_idle`（`apps/web/src/lib/writer-state.ts:3-8,84-91`），而 niko 的旧接线在发送前使用本地 working 标志。本设计以当前 `writer-state` 和 `useWorld.sendToWriter` 为准，不回写上位契约。

### 仍未知（不得伪装成已定）

- 最终产品采用 `WriterBar` controlled props 的具体 prop 命名（`value`／`onChange`／`inputRef`）仍需在 App 与 WriterBar 实现评审时冻结；本设计冻结的是“App 唯一持有 draft、WriterBar 只呈现和提交”的职责，而非 React API 拼写。
- 各 locale 的最终产品文案仍由 `messages.json` 的既有翻译流程确认；行为测试必须使用 key 或受控 translator，不以某个语言的句号作为语义判断。
- 浏览器验收所用世界、当前层和可重复的物品路径由测试夹具确定；不得把某个模板标题当作路径契约。
- 弹窗在窄屏的具体 CSS 断点和滚动容器属于实现／视觉评审；必须满足第 6 节的可见控件和键盘／触摸语义，不能改变草稿闭环。

本设计没有提出新的动作层、事件类型、WS 入口、物品事实状态或自动执行机制；若实现需要其中任一项，必须先回写 `docs/ux/08-niko功能迁移契约.md` 及对应上位文档，由主代理评审后再做。
