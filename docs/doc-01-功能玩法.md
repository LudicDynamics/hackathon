> - 云端托管版保持接口一致，只是存储实现不同（S3 + PostgreSQL vs 本地文件 + SQLite）
> - 社区生态（UGC 分享/世界模板/扩展）在本地开源自部署下是核心驱动力，不是增值服务

## ⚠️ AIRP 批注（2026-08-30 带着产品上下文回看）

> 本文是对 Nodesign 自身的分析，原样保留。以下是站在 **AIRP（AI 互动叙事游戏：agent + 无限画布 + 层级世界）** 视角的对照——哪些继承、哪些改造、哪些不用。

**一句话对照**：Nodesign 是"工作台"——画布上的东西是**交付物**（站点/幻灯/文档），用户在上面干活；AIRP 是"世界"——画布上的东西是**世界本身**（地点/角色/物件/内容），玩家在里面生活。同一个画布底座，两种产品灵魂。

| 章节 | AIRP 视角 |
|---|---|
| §2.1 圈选闭环 | **上帝模式直接继承**（玩家捏世界=圈选/评论/直接改）；**角色模式没有**——玩家是角色不是上帝，不圈改世界只生活其中 |
| §2.2 多产物 | **不适用**——AIRP 不产 ppt/docx/site；产物系统换成**世界内容系统**（地点/角色/物件/文档/互动组件）。但"能力顺着媒介走"哲学保留 |
| §2.3 Agent 自检 | 演化为**摘要验收**（子代理生成→作家过目，见 doc-05 §4.3）；多尺寸截图等创作向自检不适用 |
| §2.4 板书 | **继承并演化为核心**：作家的叙事正文=板书（chalk），**叙事文本是唯一主角**；"交互物与内容物同构"（可点按钮写在 markdown 里）→ AIRP 的 **choice frontmatter**（选项就是叙事文本的一部分，见 doc-05 §3.1） |
| §2.5 Agent 浏览器 | **基本不用**——AIRP 没有"让 agent 上网调研做产物"的创作流 |
| §2.6 画布即工作桌 | **核心继承**："卡片=文件投影、路径即 id、真实文件双向同步"是 AIRP 世界存储的基石（本地文件+SQLite，见 doc-05 §8） |
| §2.7 关系网络 | **改造继承**：地点道路/人物关系/物品来龙去脉；语义线型 + label 给 agent 读直接可用；**线条归 canvas.db 画布状态，作家用 `link` 工具统一管理，不从 md link 派生**（doc-10 E13 推翻"md 自动连线"） |
| §2.8 Tweaks | 演化为 **status frontmatter**：Tweaks 调参数 vs 状态快照（status.data 绑在 chalk 上），前端渲染折叠表格 |
| §2.9 角色扮演 | **批注更新（2026-09-10）**：Nodesign 把 RP 当彩蛋，AIRP 曾经把它当核心——**现在收窄**。AIRP 砍掉世界内角色编排（不做直聊/角色间直连/精灵），角色退化为**对话遮罩 + 小天地**：被点开才 spawn 独立进程，玩家在小天地与角色对话、角色实时可见可评论（见 doc-05 §4.1，doc-06 §3/§4） |
| §2.10 时间线回滚 | 演化为**快照+事件回滚**（AIRP 不用 git：世界快照打点+事件表回溯，见 doc-05 §8.6） |


## 1. 产品是什么

### 1.1 一句话定位

**"哪里错了圈哪里。生成、检查、反馈和修改，全程不离开同一张无限画布。"**

NoDesign 是一张**以真实文件为底座**的 Agent Native 创作工作台：告诉 Agent 你想做什么，它会在画布上创建网站、演示稿、Word 文档、图片和视频；你留在同一张画布上检查结果，发现不满意的地方直接圈选、评论，或者双击就地改——Agent 理解你说的"这里"到底是哪里，修改背后的真实文件，再回到画布继续检查。

核心创作循环：**提出需求 → Agent 生成 → 画布检查 → 圈选反馈 → 修改真实文件 → Agent 自检 → 原地继续**。

### 1.2 三个核心理念

| 理念 | 含义 |
|---|---|
| **真实文件底座** | 画布上的每张卡片都对应磁盘上的真实文件/目录。打开、改名、归类、移动都会同步到工作区；产物可下载、可拿其他软件继续编辑，不被锁在私有格式里。 |
| **无限画布** | 网站、幻灯、文档、图片、视频、参考资料可以同时摊在一张画布上，由同一个 Agent 连续处理，不换工具、不重新解释背景。 |
| **Agent 协作闭环** | 用户的"当前视野 + 选中对象 + 组件信息"会随消息一起交给 Agent；Agent 的动作（写板书、改文件、跳页高亮）也在画布上实时可见。双方在同一空间里协作。 |

### 1.3 演进史（理解设计的钥匙）

- **2026-04-29**：对标 Anthropic Claude Design 做产品拆解（`Claude_design.md`），从"生成漂亮页面"的形态拆出 inline comments / direct edits / custom sliders / inspector 等交互原子。
- **2026-04-30 战略转向**：弃自写 agent-loop，改为"**Claude Code 之上的画布编辑层**"——agent 能力（LLM / loop / 工具 / session / hooks / MCP / subagent）全部来自现成 SDK，自己只做薄壳后端 + 画布层 + 业务桥接 + 一份教 Agent 写 HTML 的 SKILL.md。
- **2026-08-27 引擎迁移**：把 SDK 子进程整个摘掉，agent loop 交给 pi-rp（`pi --mode rpc` 的 RPC 模式），工具经 pi 扩展 `registerTool` 直挂；提示词从"隐形注入"变成**能读的文件**（preset 体系），安全闸变成显式 hook 代码。

**这条演进史的启示**：产品内核不是"自己造一个 Agent 系统"，而是"把 Agent 能力当基础设施，把所有精力花在画布层的人机交互上"。

## 2. 核心玩法拆解

### 2.1 主循环：圈哪里改哪里

这是整个产品最核心的玩法闭环，四个入口对应四种用户习惯：

| 入口 | 用户操作 | 怎么变成 Agent 的上下文 |
|---|---|---|
| **圈选** | 在产物上拖一个框，框住不满意的区域 | 系统自动筛出"框住了谁"（元素语义清单）+ "这块在页面哪儿"（容器），服务端按当时的视口**真截一张区域图**，连同用户的一句话（可以留空——框本身就是话）一起发给 Agent |
| **评论** | 单击元素，在浮卡里写一句 | 评论自动锚定到该元素的稳定引用（不随 DOM 变动丢失），附带元素的结构/样式/兄弟节点机器视图 |
| **直接改** | 双击文字原地改 / 拖移工具拖到想要的位置 | 改完的"目标状态"进缓冲，Agent 负责把它翻译回源码（站点场景由前端直接写盘，幻灯场景由 Agent 应用） |
| **标注** | 右键"标注给 agent" | 发送即处理；也可以"攒着"，多张卡片标完一次性发 |

关键设计：**手势即意图，消息即指路牌**。用户在画布上的每个动作（不用会描述、不用会打字）都变成结构化指令进一个共享缓冲；聊天消息只写一句"我在 X 上圈了一块（含三个元素）：这三张卡片对不齐"。Agent 主动拉取缓冲里的详情（含截图），处理完清空，画布上的橙色标记自动消失。

> 产品灵魂："很多时候，问题并不是模型不会修改，而是它不知道你说的'这里'究竟是哪里。"

### 2.2 多产物同一张画布

画布上能同时摊开这些物件，每种都有适配自己媒介的交互：

| 物件 | 本质 | 卡上预览 | 窗内玩法 | 用户编辑方式 |
|---|---|---|---|---|
| **幻灯 deck** | 单个 .html（16:9 设计稿坐标系） | iframe 跑真文件（固定画框等比缩） | 分页预览/翻页/多稿并排对比/源码直改 | 双击改字、拖拽、评论 → Agent 应用 |
| **网站 site** | 目录（多页）或单页 | iframe 按真实设备宽渲染取首屏 | 桌面/平板/手机三尺寸切换、站内导航、发布 | 双击改字/拖拽 → **前端直接写盘**（锚点重放，防脚本污染源文件） |
| **Word docx** | .docx（OOXML） | 服务端渲的页图 | 翻页、按需现渲 PDF、多版本切换 | 页图上圈一块说事（无 DOM，顺媒介而为） |
| **图片/视频** | 常见格式 | 缩略图 | 详情/原文件 | 素材处理（抠图等由 Agent 做） |
| **浏览器 browse** | Agent 的浏览器会话（无文件） | 服务端存的上一帧 | 实时画面流 + **用户可随时接手** | 直接接管鼠标键盘 |
| **便签 note** | notes/*.md | 纸片 | 阅读/编辑 | 给 Agent 看的留言 |
| **板书 chalk** | 手写字（md 渲染） | 板上的一笔墨 | 双击改字、整组落定/擦除 | 给 Agent 的思考留痕，也可手动改 |
| **涂鸦 scribble** | 画布原生笔画 | — | 旋转/缩放 | 纯给自己看的记号（Agent 读不到，要给它看就写便签） |

**"能力顺着媒介走"**是这套体系的统一思路：活页面（deck/site）有 DOM 级能力——点选元素评论、拖拽改位、读计算样式；页图（docx）没有 DOM，就退化成"圈一块 + 一句话"（人批注纸质文档本来就是圈一块说事）；浏览器背后没有文件，就只提供"看 + 接管"。

### 2.3 Agent 自检与第三方评审

Agent 不只负责生成，还能主动检查自己：

- **多尺寸截图**：获取桌面 / 平板 / 手机宽度下的页面截图，检查断点是否生效；
- **真实渲染信息**：读浏览器控制台错误、检查最终渲染样式、字体是否加载、滚动动效与关键动画帧；
- **第三方评审**：连续修改仍不满意时，Agent 可以邀请一个**只读评审子代理**，从第三方视角逐页找问题——评审角色只负责指出缺陷，不直接改文件。

### 2.4 思考可见：板书与黑板模式

Agent 不只把最终产物摆上画布，也把**中间思考过程**摆出来：画草图、写板书、在相关内容之间建立连接、说明计划、把复杂问题拆成可继续讨论的部分。

- 板书本身是真实文件（`notes/板书/`），草图节点、连接线、文字都可以手动调整；改完 Agent 会继续使用更新后的内容；
- 黑板模式把画布变成主窗口：Agent 每轮把想法画成草图（半透明"草稿态"→ 落定变实），镜头自动跟过去，聊天退居旁白；
- 板书里可以长**可点按钮**（Agent 直接写在 markdown 里的选项板），点一下就是给 Agent 的回复——交互物与内容物同构；
- 项目决策、风格记录、个人偏好不藏在聊天历史里，作为可见、可编辑的内容留在工作区，可进一步沉淀成可复用的 Skill。

### 2.5 Agent 拥有自己的浏览器

- 可以浏览、截图、分析页面布局配色字体、观察内容分区、检查滚动动效，把有用的截图和素材收进项目；
- 本地版浏览器**保留登录状态**；遇到验证码/登录确认需要人工时，Agent 暂停并请求用户接管，处理完继续原任务；
- 浏览器在画布上是一张常驻卡（不是 run 时才有），空闲回收、刷新后还能找回——"错过就没了"是 AI 协作工具的大忌。

### 2.6 画布即工作桌：真实文件双向同步

- 卡片 id 就是磁盘路径（`site:产物根` / `deck:文件.html`），改名、归类、移动都会同步到工作区；
- 用户手改与 Agent 生成在**同一份磁盘源**上收敛：站点场景前端直接把用户改动重放到磁盘干净源码（防页面脚本污染进文件），幻灯场景走 pending 缓冲等 Agent 应用；
- 导出体系："按引用收素材"——只打包这份产物真正引用到的文件，而不是整个项目；交付包带 README（你的后端要实现哪些接口）；
- 发布：一键发布到 Cloudflare Pages，外发动作双确认。

### 2.7 关系网络：卡片之间建立语义

六种关系线（改自 / 批注 / 接着做 / 取材 / 对照 / 关联），语义靠线型+端头区分（不靠颜色，色弱用户也读得出）；每条线可写一句 label——**Agent 会逐字读**。线的"材质"（墨线/手绘/丝线）是另一条正交轴，满足不同场景情绪（归档 vs 推理 vs 随手）。关系线还驱动自动排座（批注要贴着目标、对照要并排）。

### 2.8 参数化微调（Tweaks）

Agent 做完一稿后可以主动"暴露可调参数"（如主色、Hero 字号、排版密度、暗色模式），前端按 Agent 给的 schema 渲染出滑杆/色板/分段控件；用户拖一下，iframe 里的 CSS 变量实时变（轻预览不落盘），满意后点 Apply 让 Agent 把数值固化进源码。

### 2.9 角色扮演 / 互动演出（实验玩法）

- 常驻角色（带 `rp-` 前缀的子代理）可以在画布上写字、有精灵（铅笔小人/星芒/鲸，随模型换身份）、有名字书签；
- 用户在角色写的字上回话会**直达该角色**（绕开主 agent，省回合且主 agent 不会抢答）；投递结果如实区分"已当面送达 / 已排队等它醒来 / 已托主持人召回"；
- 多角色对话"输出面是画布不是聊天"：各自在板上写字，空间即对话；
- 配套玩法：舞台状态表、场务编排（编排.yaml 三区模型控制上下文预算）、掷骰子（服务端真随机）。

### 2.10 时间线：撤销与回滚

- 每条用户消息都是一个**可回滚的版本锚点**（"回到此处"）；每个思考轮次也可以"回滚到这轮之前"；
- 底层是文件版本双轨：会话内文件检查点 + 跨会话 git；
- 与 pending buffer 的"应用/撤销"构成两套互补的后悔药。

## 3. 典型创作旅程（用户视角走一遍）

```
1. 新建项目 → 画布空桌 + 悬浮聊天卡
2. 说一句"帮我做一份关于 XX 的作品集，参考这张图"（拖图进托盘）
   → Agent 生成站点 → 卡片出现在画布上（实时缩略图跟着文件版本走）
3. 双击卡片开窗 → 桌面/平板/手机三尺寸检查
   → 发现"第二屏右边那个蓝色的块位置不太对"
4. 拖一个框圈住那块 → 说"这里太挤了"（或什么都不说）
   → Agent 收到"框住了谁 + 当时长什么样 + 这句话" → 改源码 → 原地刷新
5. Agent 主动截图自检三个尺寸 → 仍不满意 → 邀请只读评审子代理找问题
6. 满意 → 右键"导出"选整站 zip / 一键发布到公网
```

跨媒体版本：调研 → 整理成 Word → 生成幻灯 → 提取宣传长图 → 做配套站点 → 圈改 → 交付。

## 4. 一句话总结每种"玩法"的设计价值

| 玩法 | 解决的是什么问题 | 可借鉴内核 |
|---|---|---|
| 圈选反馈 | "这里"说不清 | 空间指向 → 结构化上下文（框住谁+长什么样+一句话），且支持留空 |
| 攒批发送 | 走查节奏 vs 逐条起轮抢文件 | 动作进缓冲、消息是指路牌，一次任务处理一批反馈 |
| 双击改字 | 小改不想等 Agent | 直接改目标态，Agent 负责翻译回源码；能被覆盖的（React 区）不硬改 |
| 锚点评论 | 评论要跟元素走 | 三层稳定引用（稳定 id → DOM 路径 → 文本模糊找回） |
| 板书 | 思考过程也是产物 | 草稿态→落定、可编辑、内容物与交互物同构（按钮写在 markdown 里） |
| 关系线 | 素材之间"有渊源" | 语义线型化 + label 给 Agent 读 + 驱动自动排座 |
| Agent 眼睛 | Agent 看不到自己画的 | 复用同一画布页做截图渲染器（眼睛模式），"画一笔看一眼改一笔" |
| 接管浏览器 | 自动化卡在验证码 | 常驻工具卡 + 随时人工接手 + 身份保留 |
| 时间线回滚 | 改坏了要回去 | 聊天记录即版本历史，每条消息都是回滚锚点 |
| 多尺寸预览 | 响应式是否生效 | 真实设备宽渲染（不缩放），"缩小的桌面版"骗不了人 |
