# AIRP 无限画布与层级切换构思（讨论稿）

> 2026-09-08。回应明月的判断：**doc-04 批注里"结构层 / 场景层"两套视觉语言的划分思路错了**。
> 两层深度根本不够（大地图→城市→商店→抽屉→纸，随便就五层），正确模型是：
> **每一层都是一块平等的无限画布，切换层级 = 换一块画布。理论上不存在"双层"。**

---

## 0. 一句话模型

**一个目录 = 一块画布。同一时刻世界只有一块画布在场。进入子目录不是"钻进一个洞"，是"换了一块画布"——上一块画布退成历史，不常驻、不并排、不透视。**

推论（这条模型自动带来的三个简化）：

1. **没有"世界树管理器"**——想看世界全貌？大地图本身就是一块普通画布，切过去就是了。层级导航不需要独立 UI。
2. **没有"两套渲染管线"**——doc-04 设想的"结构层手账风 + 场景层 2D 场景渲染"合并成一种视图：**画布 + 材质皮肤 + 精灵**。房间看起来"像场景"，只是因为它的背景是一张图、物件摆得密、精灵在走动——底座和大地图完全同一套。
3. **深度免费**——目录能嵌多少层，画布就能换多少层。抽屉里的一张纸和整个世界用同一个渲染器。

## 1. 与 Nodesign 的同与不同（含一个重要教训）

底座几乎全抄：单 transform 世界层、相机纯函数模块（board-camera.js，几十条单测）、离散缩放档 0.1~3、手势仲裁（长按框选 vs 平移双闸）、两层命中表、冻结渲染循环、小地图=导航控件、板书/精灵/关系线/幻影物件。

但层级心智上，**Nodesign 走过弯路又折回来了**——FolderWindow.js 头注释原文：

> 「进文件夹 = 整块桌面换成它那一层」（cwd 模型）。用户拍板改成用统一那扇窗打开：
> 桌面不动，文件夹在窗里摊开，关掉就回来。差别在心智上：换层的时候你**离开了**
> 桌面，得记住自己在第几层、怎么退回去；开窗的时候桌面还在那儿，窗只是暂时盖住它。

这个折返对 Nodesign 是对的——它是**工具**，操作者的家永远是桌面。但 AIRP 是**游戏**，
"你现在身在何处"本身就是玩法：走进商店就该是离开大地图、身在商店，而不是在大地图上
开一扇"商店窗"。**Nodesign 刻意避开的心智，恰恰是 AIRP 刻意要的。** 所以我们反向选择：

| | Nodesign | AIRP |
|---|---|---|
| 层级 | 单画布 + 文件夹开窗（桌面永在，窗是覆盖） | 画布栈（换层=换画布，旧层退场） |
| 文件夹 | zone 卡，双击开窗，窗内是**算出来的网格** | 场景卡（门），双击换画布，**每层自由摆位** |
| 根 | 桌面永远是根 | 没有特权根；面包屑 + 历史栈定位"我在哪" |
| 窗内网格的理由 | 窗会随宽变，绝对坐标立不住 | 不成立——每层是"地方"不是"临时窗"，坐标存 canvas.db 站得住 |

## 2. 一块画布上有什么（统一物件系统）

| 物件 | 来源 | 呈现 |
|---|---|---|
| **场景卡（门）** | 子目录的 README.md | 封面图 + 标题 + 摘要，材质随本层；这就是"入口/门" |
| chalk 浮字 | `type: chalk` 的 md | 楷体墨字浮在画布上，无卡片壳 |
| 便签 / 文件卡 | md / txt 等 | 纸卡，双击阅读器 |
| 组件 | `type: component` | 信、谜题盒、棋盘……iframe/组件渲染 |
| 图片 / 背景 | `type: asset` | 图片是卡；`background` 特例铺满画布做底 |
| 关系线 | 目录间/物件间绑定 | 手绘线 / 丝线 / 墨线，大地图上=道路 |
| 精灵 | 独立角色进程 | 在场感：谁在哪儿、在干嘛，点精灵=对话 |

**材质身份**：每层 README 或 config.json 声明 `material`，决定这张"画布"长什么纸——
大地图=羊皮纸、城市=牛皮卷宗、商店=便签墙、抽屉=索引卡、题材包=终端墨版（科幻）。
场景层就是 `material: scene` + 背景图的特例。材质词汇表直接继承 doc-04 §6。

**每层记住自己的相机**：离开时什么缩放、看到哪儿，回来还是什么样。这是"每一层是一个
地方"的关键细节——房间不会因为你离开过就变样。

## 4.5 过场相机的四条纪律（2026-09-08 原型踩坑后定）

原型跑起来后暴露的缩放问题，根因不是某一行的 bug，而是四个叠加的设计错误。修正后沉淀成纪律：

| # | 纪律 | 反面教材（原型初版） |
|---|---|---|
| 1 | **锚点式插值**：推进段补间的不是 cam.x/y/z 三个量，而是“门中心在屏幕上的位置 p(t)”——任意时刻 `cam = 锚点 − p(t)/z(t)`。x/y/z 各自线性补间，门的屏幕轨迹是二次曲线：边漂移边放大 | 推进门画曲线、感觉“追不上” |
| 2 | **z 全程连续**：两段动画（推进 / 展开）必须共用同一个 z 交界值；换层只许发生在门面 overlay **完全不透明**之后（等待时长 > overlay transition）。缩放断崖被半透明的遮罩漏出来，就是“画面撕裂”的主观来源 | 推进终点 z≈5.9、展开起点 z≈1.0，中间靠 overlay 掩盖但只等了 220ms < 240ms |
| 3 | **缩放上限**：推进段 z 封顶（如 2.2），“溢满视口”的意象交给 overlay 门面表达，不把 DOM scale 到 6 倍——文字全糊，且与下一段无法衔接 | gz = cover 倍数 × 1.18 ≈ 5.9 |
| 4 | **房间记忆只在交互结束时机存**：拖拽抬手 / 滚轮停顿 500ms / 离开层之前；绝不能在动画帧或 ensureLayer 里顺手存——动画中间态（贴脸门框）会污染“这一层离开时的样子” | 相机只在 ensureLayer 存过一次，返回时回到几十秒前的位置 |

另：返回段的“缩进门卡”要用 **cover 式比例（max(w 比, h 比)）**——视口与门卡宽高比不同，按宽缩会留下“比门卡矮一截”的错位；且换层前必须让旧层 DOM 保持可见（inline display 抢回），否则缩小动画全程不可见，返回退化成“闪一下换层”。

## 3. 怎么切换（交互全集）

| 动作 | 模式 | 说明 |
|---|---|---|
| **点门 / 双击场景卡** | 主入口 | 角色模式：点门=走过去+进入（演出一步）；上帝模式：双击直进 |
| **面包屑** | 常驻 | 左上角，路径即 id 的可视化，书签绳造型，楷体；点任意祖先跳回 |
| **Alt+← / Esc** | 返回 | 回上一层（浏览器 back 语义） |
| **历史栈 前进/后退** | 导航 | 穿越过的层缓存着，秒回 |
| **小地图** | 空格/M | **只画当前层** + 视口框（继承 doc-02 §1.5："导航控件不是第二视图"） |

明确不做的：

- **滚轮缩放到阈值自动穿越**——缩放是相机不是门，误触代价太高。切换必须显式。
- **画布边缘拖拽切层**——同上，空间手势留给相机。
- **"世界全貌"悬浮视图**——想看全貌，切到"大地图"那块画布。它不比别的层高贵。

## 4. 切换效果：穿越（zoom-through）

空间语义要诚实：**下层=更近，上层=更远**。Google Earth 验证过的手感，两段式：

**进入（约 600ms）**
1. 相机向被点的门推进，门卡放大充满视口（~300ms）；
2. 门卡的面（封面图/材质）短暂成为全屏"底"；
3. 新画布在这张底后面准备好，然后从底里展开——zoom out 落到适配视口（~300ms）。

**退出（对称的逆过程）**
1. 当前画布 zoom out 整体缩小；
2. 收缩成上一层画布里对应门卡的尺寸和位置；
3. 门卡"接住"它，上一层浮现，落回你离开时的相机。

```mermaid
flowchart LR
    A[点击门卡] --> B[相机推进 门卡放大至满屏]
    B --> C[门面成为全屏底 新画布幕后就绪]
    C --> D[新画布自底展开 zoom out 落定]
    D --> E[恢复该层上次的相机状态]
```

实现落点：两次相机补间 + 一层过场底图，`fitBox` / 飞行补间都是现成的；新画布提前挂载
在底图后面，过场结束接管——没有空白帧。过场期间旧画布冻结输入。

**降级版（MVP 第一天就能有）**：整屏纸色淡入淡出 + 新画布 zoom 1.15→1.0 落定。
先有"换了"的手感，穿越后补。

**题材可选件**：翻页（返回像翻回一页日记）/ 卷轴展开——留给题材包，不做默认默认。

## 5. 画布的生老病死（性能与状态）

- **懒加载天然成立**：进哪层挂哪层，"第一眼才存在"在渲染层零成本。
- **离开的层**：LRU 缓存最近 ~3 层，DOM 冻结（frame-freeze，CPU 归零、画面保留）；
  更早的直接卸载，只留 canvas.db 里的坐标和相机状态。
- **布局对账**：每层坐标存 canvas.db（按目录路径键），文件即真相、画布即投影的纪律不变。
- **视点上报表带画布路径**：作家每回合知道玩家在哪层、看什么——"当前场景"上下文的直接来源。
