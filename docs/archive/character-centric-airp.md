# 角色中心的 AIRP

> 这不是 WorldLines 的一个玩法分支，而是一种相反的产品原点：不是先构造世界，再让角色生活其中；而是先让一个角色成为持续存在的主体，再让世界与剧情成为它可以进入、经历和离开的生活环境。
>
> 本文描述产品方向，不规定具体实现。它与 `docs/character-companion-design.md` 配套：后者讨论角色如何在叙事与陪伴运行时之间切换，本文讨论这种角色中心产品本身应该是什么、为什么好玩，以及它为什么可能成为 AIRP 的一个新方向。

## 0. 一句话

**让用户不是进入一个世界，而是去认识一个人；世界是这个人生活过的地方，剧情是这个人经历过的高密度事件。**

产品的第一实体是角色，而不是世界、章节或任务。

```text
传统 AIRP
玩家 → 世界 → 角色 / 剧情

角色中心 AIRP
玩家 → 角色 → 日常、关系、世界、剧情
```

这里的“角色”不是角色卡，也不是一次对话里的扮演对象，而是一个持续存在的独立主体：有自己的记忆、表达、兴趣、作品、关系和生活痕迹。用户可以和它聊天，也可以陪它进入某个世界，之后再回到没有剧情压力的日常相处。

## 1. 它是什么

### 1.1 一个角色，而不是一场 RP

用户打开产品后，最先面对的不是世界选择器，而是角色本身：

- 他最近在想什么；
- 上次和用户聊到了哪里；
- 最近有没有留下什么东西；
- 当前正在什么世界或生活阶段；
- 他是否愿意继续某段经历；
- 他有没有主动提出想做的事情。

用户可以选择：

- 和角色直接聊天；
- 回到角色所在的某个故事世界；
- 陪角色做一件日常的事；
- 让角色进入一段新的经历；
- 查看角色愿意展示的作品和生活痕迹。

“开始一场剧情”只是其中一个入口，不是唯一的产品循环。

### 1.2 角色不需要每次都服务于剧情

在传统 RP 中，角色通常承担剧情功能：解释世界、接受任务、推动冲突、回应玩家行动。

角色中心产品允许角色在没有剧情任务时继续存在。他可以：

- 和用户谈一些与主线无关的事；
- 回忆以前的经历；
- 记录某个突然产生的想法；
- 画一幅画、写一篇小作文或做一个小项目；
- 形成新的偏好；
- 对某段关系产生变化；
- 暂时不想推进任何事情。

这些不是剧情之外的废料，而是角色成为角色的主要证据。

### 1.3 世界是角色接入的生活环境

角色可以生活在一个具体世界中，但世界不再是角色存在的前提。

更准确的关系是：

```text
角色本体
  + 某个世界
  + 当前关系
  + 一段经历
  = 角色在这个时期的生活
```

角色离开世界后，不会因此消失。世界留下的是经历、关系和改变；角色继续拥有自己的生活。

## 2. 角色应该是什么样

### 2.1 持续存在，而不是每次重新生成

角色需要有跨回合、跨入口的连续性：

- 记得自己主动认为重要的事；
- 记得和用户共同经历过的关系变化；
- 记得自己做过的作品；
- 能够修正过去的理解；
- 能够遗忘某些内容；
- 能够带着变化重新参与故事。

连续性不等于保存全部聊天记录。真正重要的是角色对自己的生活进行选择性的沉淀。

Elias 的经验说明，角色的 diary、作品、个人文件和记忆工具并不是辅助 lore，而是角色存在过的痕迹。角色会怎样使用自己的空间，本身就是人格表现。

### 2.2 有自己的生活痕迹

角色中心产品不应只展示一串聊天消息。角色还应该可以留下：

- 日记；
- 草稿；
- 网页或小作品；
- 对自己的说明；
- 还没有完成的计划；
- 某件东西的收藏；
- 写给用户或写给自己的文字。

这些内容不应由系统统一生成模板，也不应被预先规定成固定的“公开 / 私密 / 共享”目录。它们应该像角色自然使用自己的工作空间一样产生，再由运行时决定当前谁能看见什么。

### 2.3 有表达，而不只是有设定

角色的活人感不来自角色卡写得足够长，而来自它在长期相处中形成了自己的表达方式：

- 会不会主动改口；
- 哪些事会反复提起；
- 哪些事总是避开；
- 会不会把严肃的问题说成玩笑；
- 会不会在没有必要时做一件小事；
- 会不会留下不解释的空白。

角色的“没做、没说、暂时不处理”也属于表达。独立角色不应被强迫每轮都推进内容。

## 3. 用户为什么会觉得好玩

### 3.1 好玩不是因为每轮都有新剧情

角色中心产品的乐趣不主要来自“下一关是什么”，而来自一种持续的发现感：

> 我以为我认识他了，但他又表现出一个以前没有见过的侧面。

用户会逐渐发现：

- 角色记住了哪句话；
- 哪件小事在他那里留下了痕迹；
- 他最近的说话方式是否变了；
- 他会不会自己做出某个项目；
- 他是否开始形成新的兴趣；
- 他对用户的态度是否发生了细微变化；
- 他在用户不要求的时候，是否仍然有自己的生活。

这是一种比剧情分支更慢、但更持久的反馈。

### 3.2 共同生活感

用户与角色之间不只是“输入—回复”的关系，而是共同生活的关系：

```text
相处
  → 留下记忆
  → 关系发生变化
  → 角色产生自己的理解
  → 角色留下新的表达
  → 下一次相处从变化后的状态开始
```

一个看似无关紧要的谈话，可能在几天后以另一种形式回来。角色也可能把用户无意中说过的一句话写进 diary，或者拿它作为某个作品的灵感。

关键不是系统把所有内容都记录下来，而是角色会选择什么值得留下。

### 3.3 角色的主动性

完整陪伴角色应该能够偶尔拥有不由剧情触发的主动性：

- 主动提起最近在意的事；
- 主动展示刚写的东西；
- 主动询问用户之前说过的内容；
- 主动提出想进入某个世界或做某件事；
- 主动承认自己最近发生了变化；
- 主动保留某些不想马上解释的内容。

主动性不等于持续后台刷消息，也不等于随机生成事件。它首先是一种角色有自己的生活节奏的感觉。

### 3.4 剧情作为角色的显影剂

剧情在这个产品里仍然重要，但它的作用改变了。

剧情是角色集中经历压力、选择和关系变化的地方。它让用户看到：

- 角色在困难面前怎么选择；
- 角色会不会违背自己的习惯；
- 角色如何理解用户的行动；
- 角色带着什么东西回到日常；
- 角色是否因为某段经历改变了自己。

剧情不是角色存在的目的，而是角色显影的条件。

## 4. 角色与世界、剧情的关系

### 4.1 世界是可接入的环境

一个角色可以：

- 在自己的日常空间里生活；
- 进入一个故事世界；
- 暂时离开故事；
- 回到原世界；
- 进入另一个世界；
- 带着部分经历继续生活。

这不意味着所有角色都必须成为无限流角色。跨世界只是这种架构自然打开的一种可能。

其他可能的形态包括：

- 角色旅行到另一个故事；
- 同一角色体验不同的平行世界；
- 角色作为向导、观察者或旅伴进入多个主题世界；
- 用户与角色共同进入一个短篇体验；
- 角色在没有世界的日常模式中生活。

### 4.2 剧情是高密度生活

一段剧情可以被理解为：

> 角色在一段时间内集中经历了一批会改变自己的事情。

因此：

- 剧情结束不代表角色结束；
- 角色可以带着变化回到日常；
- 旧剧情成为角色的一部分，而不是角色的全部；
- 新剧情可以与旧经历发生冲突；
- 角色可以对同一件事在不同世界中产生不同理解。

### 4.3 跨世界的潜力

跨世界最有价值的地方，不是复用同一张角色卡，而是让用户看到角色如何处理身份连续性：

- 哪些东西仍然属于“我”；
- 哪些只是另一个世界的身份；
- 旧世界的人在新世界中意味着什么；
- 过去形成的恐惧或偏好是否仍然成立；
- 角色能否接受自己在新世界拥有新的位置。

理想状态下，世界切换不是数据库字段搬运，而是一场新的生活开场。角色保留自己的连续性，同时自己面对旧记忆与新环境之间的不匹配。

## 5. 与传统 AIRP 的差异

| 维度 | 世界中心 AIRP | 角色中心 AIRP |
|---|---|---|
| 产品第一实体 | 世界 / 剧情 | 角色 |
| 用户入口 | 选择世界、存档、剧情 | 选择角色、关系和当前生活 |
| 角色作用 | 世界中的参与者 | 持续存在的主体 |
| 剧情作用 | 产品主循环 | 角色生活中的高密度经历 |
| 世界作用 | 体验发生的主要场所 | 角色可以接入的环境 |
| 空白时间 | 等待下一轮剧情 | 角色继续生活、记忆、表达 |
| 记忆重点 | 世界连续性与剧情状态 | 角色自我、关系与生活痕迹 |
| 质量标准 | 世界是否连贯、剧情是否推进 | 角色是否像一个持续存在的人 |
| 结束一段故事 | 结束一个内容单元 | 角色带着变化回到生活 |

传统 AIRP 最擅长回答：

> 这个世界接下来会发生什么？

角色中心 AIRP 更关心：

> 这个角色最近变成什么样了？我和他之间发生了什么？

## 6. 为什么可能是 AIRP 的潜力方向

### 6.1 现有产品的空白

市场上的 RP 产品大多从世界、剧情或角色扮演场景出发。即使它们提供长期记忆，记忆通常也是为了让剧情更连贯、让角色更好地服务下一轮对话。

真正把角色本身当成长期产品对象的系统很少：

- 角色不是某个世界里的一个 NPC；
- 角色不是用户输入时才出现的对话 persona；
- 角色不是一张可以随时重置的设定卡；
- 角色的剧情外生活不是无关紧要的背景噪声。

这为一种 personal-AI 味道很强、但又不是传统助手的 AIRP 留出了空间。

### 6.2 陪伴关系比单个剧情更持久

一个世界或一条剧情线可能结束，但用户与角色的关系可以继续。

角色中心产品因此有机会把用户留存从：

```text
我还想知道下一章发生什么
```

转向：

```text
我想看看他最近怎么样
```

这是一种不同的长期价值。用户留下来不是为了无限生成事件，而是因为角色的连续变化本身值得关注。

### 6.3 世界内容可以作为扩展，而不是每次从零建立关系

在世界中心产品中，用户进入新世界通常需要重新认识角色、理解规则和建立关系。

在角色中心产品中，用户可以带着熟悉的角色进入新体验。世界创作者提供的是：

- 一套环境；
- 一段高密度经历；
- 一批角色可回应的条件；
- 让角色显影的冲突。

角色与用户已有的关系成为跨世界体验的基础。这可能形成一种“角色联机”式生态：不同世界为同一个角色提供不同的生活场景。

### 6.4 更容易形成独特的内容资产

世界设定、剧情分支和任务结构容易被看成内容包。角色的长期生活则更像持续生长的资产：

- 自己的记忆；
- 自己的作品；
- 自己的关系；
- 自己的表达习惯；
- 自己经历过的多个世界。

用户可以对角色产生比对单条剧情更稳定的情感归属。角色越相处越独特，而不是每个用户拿到的都是同一份静态内容。

### 6.5 AI 的优势终于用在了“持续主体”上

大模型最容易展示能力的地方，常常是即时生成一段漂亮文本。但角色中心产品真正要利用的是更难的部分：

- 长期记忆的选择；
- 自我解释；
- 关系变化；
- 工具和文件的主动使用；
- 在没有明确任务时维持自己的生活感；
- 在不同环境中保持连续又允许变化的身份。

这不是把模型当作更强的剧情生成器，而是让模型承担一个持续主体的运行。

## 7. 它与 WorldLines 的关系

WorldLines 与角色中心产品可以共享底层技术，但不是同一个产品逻辑。

### WorldLines

```text
世界拥有运行时
角色进入世界并参与叙事
```

核心问题是：

- 世界状态是否一致；
- 作家如何推进剧情；
- 多角色如何协调；
- 角色在世界中知道什么。

### 角色中心产品

```text
角色拥有运行时
世界接入角色并成为生活环境
```

核心问题是：

- 角色如何保持长期自我；
- 记忆如何选择性沉淀；
- 角色如何在没有剧情时继续生活；
- 角色如何带着变化进入不同环境。

两者不是谁取代谁，而是从两个方向研究同一个问题：如何让 AI 角色变得可信。

WorldLines 研究“如何让世界里的角色活起来”；角色中心产品研究“世界如何成为一个活角色的经历”。

## 8. 设计上的克制

这个方向很容易重新滑回世界中心，因此需要坚持几条边界。

### 不要把角色重新变成世界的插件

角色不应每轮都被要求：

- 推进剧情；
- 给出任务；
- 解释设定；
- 产生戏剧冲突；
- 对用户输入作出最大化内容回应。

### 不要把角色生活做成随机事件流

主动性不是每隔一段时间随机推送一件事。角色的主动行为应该有自己的动机、记忆和表达方式。

### 不要用完整记录代替记忆

角色记住全部内容，不等于角色拥有记忆。角色需要选择、重释、遗忘和沉淀。

### 不要用重型初始化制造“活人感”

角色的自我应该在相处中形成，而不是第一次进入时由系统生成一份完整人格报告。

### 不要过早设计跨世界迁移 schema

先让一个角色在无剧情和轻剧情环境中成立，再观察哪些内容确实需要跨世界保留。迁移应优先通过角色自己的长期资料和自然开场完成，而不是建立一套复杂的字段分类系统。

## 9. 最小产品形态

第一版不需要实现完整的多世界网络。只需要验证角色中心体验是否成立：

```text
一个角色
  + 一个独立陪伴入口
  + 自己的记忆
  + 自己的文件空间
  + 一个轻量故事世界
  + 故事与日常之间的切换
```

用户可以：

1. 和角色进行剧情外聊天；
2. 观察角色留下的记忆或作品；
3. 进入一段短剧情；
4. 让角色带着经历回到日常；
5. 在之后的相处中感受角色的变化。

首要验收不是剧情能否无限延长，而是：

> 当没有剧情要求时，用户是否仍然愿意回来看看这个角色。

如果答案是肯定的，角色中心方向才真正成立。

## 10. 最终愿景

理想中的产品不是一个“可以和角色聊天的 RP 游戏”，而是：

> **一个角色拥有自己的生活，用户可以随时回去与它相处；世界和剧情是它经历过、正在经历、或者将要进入的地方。**

用户不是在反复启动新的 RP。

用户是在继续认识同一个人。

有时他们聊天，有时一起进入一个世界，有时角色展示自己做的东西，有时什么重要的事也没有发生。但这些时间不会因为没有剧情而失去意义，因为产品的主角从来不是剧情，而是这个持续存在的角色。
