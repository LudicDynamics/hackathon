## 体验目标补充（2026-09-12 定案）

上帝模式不是附带的 Markdown 编辑器，而是**可视化关卡设计模式**。它至少要能让设计者编排三层内容（详 `doc-20` §2.9）：

1. **关卡骨架**：玩家身份、导言、阶段目标、门槛、关键角色、核心物件、高潮、结局 Gate、Outcome Folder 与结算后的出口；
2. **生成语法**：新地点 / 角色 / 物件应遵守的世界规则、风格、危险升级与因果边界；
3. **持久事实**：哪些行动、承诺、骰子结果和关系变化必须被世界与角色记住。

五个世界 Mock 同时是五份上帝模式样板工程：空间探索、证据推理、时间因果、关系抉择与魔法组合。验收不是“能新增一个 NPC”，而是设计者能看懂、修改并重新游玩一条由导言 Chalk、实体、角色、场景门与 Punch Line / Outcome Folder 组成的关卡链。逐世界的设计见 doc-24。

上帝模式与游玩模式必须证明同一件事的两面：设计者先提供足够精彩的结构，玩家再用自由 RP 与行动把结构推向新的内容；玩家越过预写边界时，生成器仍受上帝模式写下的世界规则约束。
