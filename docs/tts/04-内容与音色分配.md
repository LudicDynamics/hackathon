> 子文档 `04`，owner 边界：**角色 `README.md` 的 `voice` 声明、音色清单、模板落地、世界 locale → 语言映射核对**（`docs/tts/00-共同上下文.md §14`）。
> 上游冻结契约：`docs/tts/00-共同上下文.md`（下称 `00`），厂商文档 `docs/tts/qwen3-tts-flash.md`（下称「厂商文档」）；主 agent 裁决见 `00 §15`。
> **本文不改任何代码、不写任何模板文件**；只给逐字可落地的分配与片段。冲突写本文「⑪ 发现的冲突」，不改 `00`。
> 冻结日期：2026-09-13（§15 裁决后修订）。

---

## 1. 一句话定位

**给每个角色的 `README.md` frontmatter 加一行 `voice: <DashScope 音色 ID>`，让「角色 = 一个固定的声音」成为文件事实。** 本批**不生产任何音频素材**——TTS 是实时合成，音色 ID 只是「用哪个嗓子念」的声明。

---

## 2. 签名与参数（本模块涉及的形状）

本模块**不新增任何函数**。它只写两类既有形状：

| 形状 | 位置 | 本模块负责 |
|---|---|---|
| `voice`（README frontmatter 顶层字段） | 冻结于 `00 §3.1` | **取值**（本文 §4） |
| `language`（`POST /api/tts` 请求体字段） | 冻结于 `00 §2.1` | **每世界该传什么**（本文 §5） |
| `voice`（`POST /api/tts` 请求体字段） | 冻结于 `00 §2.1` | 由 `/api/characters.voice` 下推（`00 §15.5`，服务端读 README） |

```ts
// 00 §3.1 冻结的 frontmatter 形状（本文只填值，不改形状）
voice: Sage        // 裸名，DashScope 音色 ID；非 URL、非路径；MUST 匹配 /^[A-Za-z0-9_-]+$/
```

**缺省语义（冻结）**：README 无 `voice` → 服务端回落 `AIRP_TTS_DEFAULT_VOICE`（`00 §4.3`，默认 `Cherry`）。所以**本文的分配不是「可选优化」，是「不让角色用错嗓子」的必需动作**：`Cherry` 是女声，若一个男角色不在 README 声明，他就会用女声说话。

## 3. 行为契约逐步（每步写「漏了会怎样」）

1. **角色目录存在** → 其 `README.md` 的 frontmatter 是音色唯一真相源（`00 §3.1`；`AGENTS.md §3.2`「文件即真相」）。
   - 漏了 → 没有声明点，只能吃服务端默认音色，角色性别/气质与声音错配。
2. **`voice` 的值是厂商真实音色 ID**（§3.1；**落地前 MUST curl 实测，§9.1**）。
   - 漏了（编造/拼接 ID）→ DashScope 400，`00 §8` 的 `tts_upstream` 分支：**该角色每一页都无声**，演出退化成纯文字。**这正是 §15.2 要求逐条实测的原因。**
3. **值必须是单 token 且匹配 `/^[A-Za-z0-9_-]+$/`**（`00 §4.2` 步骤 4，**§15.1 裁定不变**）。
   - 漏了 → 服务端把畸形值回落默认音色（fail-loud 落日志）。**厂商表里看似带空格的写法（如 `Eldric Sage`）不是单个音色**——`Eldric` 与 `Sage` 是两个独立 ID（`00 §15.1`）。**MUST NOT 用带空格的拼接值。**
4. **世界 `locale` 决定 `language`**（`00 §4.4`），`ja`→`Japanese`，`en`→`English`。
   - 漏了 → 日语角色用英语模型念日语，发音错误（本文 §5、`00 §15.4`）。
5. **一个角色跨世界时，声音应一致**（本文 §4 的 Watson 原则）。
   - 漏了 → 同一个人在两个世界换嗓子，角色身份感断裂。

## 4. 逐角色音色分配

### 4.0 分配原则

1. **优先从 §15.2 的 8 个「安全集合」里选**；集合外 ID 仅在气质明显更贴合时选用，且**必标「候选」并跑 §9.1 实测**。
2. **语言优先**：角色的文本语言 = 世界的 `locale`（§5）。日文角色必须选「支持 Japanese」的音色。
3. **性别与气质对齐**：按 README 正文 / `world.json` 的 `description` / `preset.json` 的 persona 判断。
4. **角色身份 ↔ 声音**：**同一个角色跨世界用同一个 `voice`**（Watson 在 `whitechapel` 与 `holmes-world` 是同一人 → 同一嗓子）。
5. **不双选**（除第 4 条的有意相同）：不同角色尽量不同 ID，让玩家听声辨人。
6. **避开方言音色**（§3.1）。

## 5. 语言正确性：世界 `locale` → `language`

`00 §4.4` 冻结服务端映射：`ja`→`Japanese`、`en`→`English`、其他/缺省→`Auto`。前端只传**世界 locale 短码**。

**逐世界核对（实测 `templates/*/world.json`，2026-09-13）**：

| 世界 | `world.json` 的 `locale` | 证据 | 建议请求 `language` | 服务端 `language_type` |
|---|---|---|---|---|
| `firstsnow` | **`"ja"`**（实测） | `templates/firstsnow/world.json` | `'ja'` | `Japanese` |
| `whitechapel` | **`"en"`**（实测） | `templates/whitechapel/world.json` | `'en'` | `English` |
| `holmes-world` | **缺失** | `templates/holmes-world/world.json` | `'en'`（§15.4 前端兜底） | `English` |
| `magic-academy` | **缺失** | `templates/magic-academy/world.json` | `'en'`（同上） | `English` |
| `school-romance` | **缺失** | `templates/school-romance/world.json` | `'en'`（同上） | `English` |
| `cthulhu` | **缺失** | `templates/cthulhu/world.json` | `'en'`（同上） | `English` |

**结论（含 `00 §15.4` 裁决）**：

- **只有 `firstsnow` 是 `ja`**（实测）；`whitechapel` 是 `en`；其余四个**未声明 locale**（内容皆英文）。
- 日语角色（`firstsnow` 的 `nanami`/`sumi`）→ 请求 `language:'ja'` → 服务端 `Japanese`。**这是本批语言正确性的核心一条**：漏了它，日语台词会被英语模型念。
- **四个缺 `locale` 的世界**：`00 §15.4` 裁决**本批不改 `world.json`**（超出 TTS 范围），改由 `05`/`03` 前端兜底——`language` 取值顺序 = `manifest.locale` → 世界内容语言的既有默认（这四个世界**传 `'en'`**）。**MUST NOT 用 `App.tsx:39` 的浏览器语言猜测做 TTS `language`**（日语浏览器会把英文台词念成日语）。登记为后续：给这四个世界补 `locale`。

## 8. 素材缺口：本批**无 assets 生产任务**（明确）

| 维度 | foley / stinger（`docs/audio/00`） | 角色语音（本批） |
|---|---|---|
| 素材形态 | **预制音频文件**（`.mp3`，31 条已产出） | **实时合成**（每次调 DashScope 现场生成 `.wav`） |
| 生产步骤 | 下载 / 转码 / 剪辑 / 落 `assets/audio/CREDITS.md` | **无**——无第三方素材，无需署名 |
| 存储 | 平台池 `assets/audio/`（进 git） | 每世界私有缓存 `<worldRoot>/.airpworld/tts-cache/`（见下） |
| 版本 | 素材换了要重录 | 换 `voice` 即换声；缓存 key 含 `voice`（`00 §3.2`）自动失效重合成 |

**结论**：

- **本批不产出任何 `assets/` 文件，不新增 `CREDITS.md` 条目，不走 `search_audio` 下载流程。**
- 音色 ID 是**声明**，不是素材——`04` 的交付物是「README 里的一行字符串」而非二进制。
- TTS 音频进 `<worldRoot>/.airpworld/tts-cache/`（`00 §2.3`）。

## 9. 验收测试（手工命令）

### 9.1 直连 DashScope：证明「这个音色真的存在且出声」（**§15.2 强制，逐 ID 必跑**）

```bash
# 需要真实 Key（新加坡地域）。未配置时返回 401 InvalidApiKey（本机实测）。
curl -sS -X POST 'https://dashscope-intl.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation' \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3-tts-flash-2025-11-27",
    "input": { "text": "The game is afoot, Watson.", "voice": "Eldric", "language_type": "English" }
  }' | jq -r '.output.audio.url'
```

- **通过判据**：返回 `https://…aliyuncs.com/...wav` URL；`curl -o /tmp/v.wav '<url>'` 后 `ffprobe /tmp/v.wav` 有音频流、时长 > 0。
- **失败判据**：`status_code != 200` / 数组错误 / 无 `output.audio.url` → **该 ID 不可用**，按 §4.1 回退。
- **必跑清单（§4.1 的 8 个不同 ID）**：`Serena`(ja)、`Cherry`(ja)、`Eldric`(en)、`Sage`(en)、`Momo`(en)、`Neil`/`Mia`/`Vincent`(各 en)。日语角色用日文文本验证：`voice:"Serena"` + `language_type:"Japanese"` + `text:"おはよう、今日もいい天気だね。"`。

### 9.2 走本仓端点：证明「角色的 `voice` 经服务端真出声」

```bash
# 前提：服务端已起（默认端口 3001，apps/server/src/index.ts:216），.env 有 DASHSCOPE_API_KEY，且已进入某世界。
curl -sS -X POST 'http://localhost:3001/api/tts' \
  -H 'Content-Type: application/json' \
  -d '{ "text": "The game is afoot, Watson.", "voice": "Eldric", "language": "en" }' \
  | tee /tmp/tts.json | jq .
```

- **通过判据**：`{ ok:true, url:"/api/tts/audio/<20 hex>.wav", cached:false, characters:27, truncated:false }`；再 `curl -sS -o /tmp/a.wav "http://localhost:3001$（jq -r .url /tmp/tts.json）"`，`ffprobe` 有音频流。
- **日语角色**：`{"text":"おはよう。","voice":"Serena","language":"ja"}` → 服务端应映射为 `Japanese`（`00 §4.4`）。
- **未配置 Key 的默认路径（本机当前即此）**：同命令应返回 **503 `{ok:false,code:"tts_unconfigured"}`**（`00 §4.5`），非 500/崩溃。
- **缓存命中**：第二次 → `cached:true`，不联网（`00 §4.2` 步骤 6）。

> 上述 `curl` 命令**本批未执行**（无 Key；按约束不跑项目级命令）。它们是**落地时的验收命令**，`06` 负责使其可断言。
