# 07 — 音色别名映射（voice palette）

> 本批（2026-09-13）新增。权威层级见 `00-共同上下文.md` §0：本文补充 `00`，与 `00` 冲突处以 `00` 为准（但 §6 已列出 `00 §15.1` 的被推翻条），与 `01`/`04` 冲突处以本文为准。

---

## 0. 为什么有这份文档

落地后第一件事是拿真 key 实测，结果抓到 **3 个已上线的静默 bug**，全部同一个根因：**音色靠人肉记 DashScope 的商品名**。

| # | 现象 | 根因 |
|---|---|---|
| B1 | `whitechapel/watson`、`holmes-world/watson` 每页无声 | 写 `voice: Eldric`，但 **`Eldric` 不是音色** |
| B2 | `magic-academy/archivist` 每页无声 | 写 `voice: Sage`，**`Sage` 也不是音色** |
| B3 | 正确写法 `Eldric Sage` 被**静默换成默认音色**（Cherry 的嗓子） | `VOICE_RE = /^[A-Za-z0-9_-]+$/` 不含空格 |

B1/B2 的错误源头是 `00 §15.1` 的一条**错误裁决**：它断言「音色是单个无空格 token」，并据此把真实音色 **`Eldric Sage`（沧明子，一个音色，名字里有空格）** 判成「两个音色被拼接、不合法」。官方音色表（`docs/tts/qwen3-tts-flash.md` 之外的 Qwen-TTS 音色列表）与实测都证明相反：`Eldric`、`Sage` 各自 **`InvalidParameter`**，`Eldric Sage` **正常出声**。

三条 bug 的共同教训不是「记错了名字」，而是：**让内容作者去写厂商商品名，本身就是设计缺陷**。所以本批不再要求作者记名字，改为**按效果命名**。

---

## 1. 目标

让写世界内容的人**不需要知道 DashScope 的任何音色名**，也能给角色配音，并且**写错时会被门禁拦下**而不是静默无声。

一句话形态：**世界内容写效果别名（`wise-elder`），服务端在唯一解析点把它翻成商品名（`Eldric Sage`）。**

---

## 2. 词汇表：两套词，一个权威

| 词汇 | 长相 | 谁写 | 例子 |
|---|---|---|---|
| **效果别名（alias）** | kebab-case | **世界内容作者**（`characters/<id>/README.md` 的 `voice:`） | `wise-elder`、`hoarse-weathered`、`news-anchor` |
| **商品名（id）** | DashScope 自己的大小写，**可含空格** | **无人手写**；只作为解析目标存在 | `Eldric Sage`、`Vincent`、`Radio Gol` |

作者**只该写别名**。裸商品名仍然**被接受**（向后兼容 + 渐进迁移），但：

- `check:voices` 会对「写了裸 id 而没写别名」打 **`~~` 警告**（不失败），推动内容收敛到别名；
- 新内容一律写别名。

> **为什么不是「两套词都鼓励」**：一旦允许写商品名，B1/B2 就会重演——别名存在的全部意义是**让正确写法比错误写法更好写**。

---

## 3. 解析链（唯一真相源）

```
characters/<id>/README.md   frontmatter: voice: wise-elder
        │
        │  /api/characters 原样透传（不解析，见 §4）
        ▼
前端  PUT /api/tts  { text, voice: "wise-elder", language }   （CharacterModal）
        │
        │  resolveVoice()  ← packages/shared/src/rules/voices.ts（唯一解析点）
        ▼
DashScope   input.voice = "Eldric Sage"
```

**解析恰好发生一次**，在 `POST /api/tts`（`apps/server/src/routes/tts.ts`）。理由与 `00 §15.5`「不在 world.json 加 voice」同构：**两处解析 = 两个真相源**。`/api/characters` 因此只透传原文，前端也不解析（它不拥有调色板）。

### 3.1 `resolveVoice` 的契约

```ts
resolveVoice(name: string): string | null
```

| 输入 | 返回 | 语义 |
|---|---|---|
| 调色板里的别名（`wise-elder`） | 对应 id（`Eldric Sage`） | 正常路径 |
| 调色板里的裸 id（`Eldric Sage`） | 原样（`Eldric Sage`） | 兼容路径，不重复解析 |
| **任何其他字符串**（`Eldric`、`Sage`、`cherry`、`nope`、`''`） | **`null`** | **近失不静默接受**——这正是 B1/B2 的护栏 |

`null` 是关键设计：**它不是错误码，是「不在调色板里」的事实**，服务端据此警告 + 回落默认（页面继续播），门禁据此让构建变红（typo 出不了门）。**宁可回落也不要 400**——一个角色的嗓子写错不该让整页演出挂掉（与 `00 §8` 降级矩阵同一条原则）。

### 3.2 服务端回落顺序

```
requested = body.voice?.trim() ?? ''
default   = resolveVoice(AIRP_TTS_DEFAULT_VOICE) ?? AIRP_TTS_DEFAULT_VOICE

requested === ''                    → default（文档化的「用默认」路径，不警告）
!VOICE_RE.test(requested)           → default + warn（结构性畸形，如 ../evil）
resolveVoice(requested) === null    → default + warn（不在调色板：typo）
否则                                 → resolveVoice(requested)
```

`VOICE_RE = /^[A-Za-z0-9][A-Za-z0-9 _-]*$/` —— **只做结构性体检**（允许空格，因为 `Eldric Sage` 合法），**决定权在 `resolveVoice`**。旧正则 `/^[A-Za-z0-9_-]+$/` 就是 B3 的成因。

## 4. 为什么不把别名表放进世界包

调色板（`packages/shared/src/rules/voices.ts`）是**平台级**的，不是世界级的。理由：

1. **商品名是引擎事实，不是世界内容**：`Eldric Sage` 能出声是 DashScope 的属性，与哪个世界无关。放进世界包 = 每个世界抄一份 = 必然漂移。
2. **门禁要跨世界统一判**：`check:voices` 走一次全仓 README，拿一份表就能判；分表就得先解决「哪个世界用哪张表」。
3. **零依赖**：与 `rules/characters.ts` 同款纪律——不 import zod / store / node builtin，服务端、门禁、未来音色选择器都能安全 import。

## 5. 验证方法（增删音色的**唯一**许可流程）

> **规矩：没有实测出声的音色，MUST NOT 进调色板。** 一份容纳未验证 id 的白名单，正是把 typo 变成无声的原因。**没有实测就加，等于把 B1/B2 请回来。**

实测命令（`$D` = `AIRP_TTS_BASE_URL`，key 见 `.env`）：

```bash
curl -s -X POST "$D/services/aigc/multimodal-generation/generation" \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"qwen3-tts-flash","input":{"text":"A voice speaks.","voice":"Eldric Sage","language_type":"English"}}' \
  | jq -r 'if .output.audio.url then "OK" else "FAIL "+(.code//"?") end'
```

## 8. 反模式（MUST NOT）

1. **在世界内容里手写商品名。** 写别名；门禁会对裸 id 打 `~~` 警告。
2. **在第二处解析别名。** 解析只在 `POST /api/tts`；`/api/characters` 透传、前端透传。
3. **把未实测的音色加进调色板**（§5）。
4. **把 typo 当合法输入静默接受。** `resolveVoice` 返回 `null` 就是护栏；不要为了「容错」加模糊匹配（`Eldric` → `Eldric Sage` 这种猜测会让 B1 变得不可检测）。
5. **按性别/语言建多套别名。** 调色板已含 `gender` 字段；TTS 音色本身多语，语言走 `language_type`，不是另一套名字。
6. **让「同世界两个角色撞声」通过。** 跨世界同声合法（同一演员/统一风格），同世界撞声会让两人说话时无法区分——`check:voices` V4 拦之。
