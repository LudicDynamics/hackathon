## ① 一句话定位

**新增 `apps/server/src/routes/tts.ts`，作为全批唯一合成点：`POST /api/tts` 收一页角色台词 → 查磁盘缓存 → 未命中则调 DashScope `qwen3-tts-flash` 拿 OSS 音频 URL → 下载 wav → 原子写盘 → 返回本地 URL；`GET /api/tts/audio/:file` 把该 wav 以内容寻址的长期缓存吐回。**

进程内不含任何 TTS 状态、不落 `events`、不发 WS 帧（契约 §1/§9）。前端只收到一个 URL，永不持有 key（契约 §9.1）。

## ② 签名与参数

### 2.1 对外函数（契约 §4.1 冻结）

```ts
// apps/server/src/routes/tts.ts — 全部 NEW
import { Router } from 'express';
import type { LocalWorldStore } from '@airp/shared';

/**
 * Assemble the TTS routes. Mounted alongside `createWorldRouter` on `/api`.
 * Nothing here is module-level state: every request re-reads env and the
 * active store, so tests may set env after import (hard requirement, see §10).
 */
export function createTtsRouter(
  repoRoot: string,
  getActiveStore: () => LocalWorldStore | null
): Router;

/** Synthesise one page of text via DashScope → download → return the wav bytes. */
export async function synthesise(opts: {
  text: string;
  voice: string;
  languageType: string;   // already mapped: 'Auto' | 'Chinese' | 'English' | 'Japanese' | … (never the short code)
  apiKey: string;
  baseUrl: string;        // e.g. https://dashscope-intl.aliyuncs.com/api/v1
  model: string;          // e.g. qwen3-tts-flash-2025-11-27
  timeoutMs: number;      // total budget incl. the OSS download
}): Promise<Buffer>;

/** sha256(`${model}|${voice}|${languageType}|${text}`).slice(0, 20) — 20 hex chars. */
export function hashOf(
  model: string,
  voice: string,
  languageType: string,
  text: string
): string;
```

> `createTtsRouter` 的**两参签名是契约冻结**（`00 §4.1`）；`repoRoot` 当前只用于日志/将来扩展，缓存根由 `store.worldRoot` 决定（§2.3）。**不要**为了可测性加第三参（注入 client），那会私改契约——测试靠 env 注入（见 §10，已与 `06` 对齐）。

## ③ 行为契约逐步

### 3.A `.env` 加载（`apps/server/src/index.ts`）

契约 §3.3 冻结：MUST 在**读取任何 `process.env.AIRP_*` 之前**执行：

```ts
try { process.loadEnvFile(path.join(REPO_ROOT, '.env')); } catch { /* no .env → ambient env */ }
```

**精确落点**：`apps/server/src/index.ts`，在 `REPO_ROOT` 定义（`:15`）之后、**第一处 env 读取之前**。当前唯一的启动期 env 读取是 `:216` 的 `process.env.PORT`，但 `:38-43` 构造 `AgentLifecycleManager` 时会经 `airpEnv()`（`presets.ts:76-80`）读 `process.env[key]`——那是**每次 spawn 时**读，不是启动时读。

**MUST 插在 `:17` 与 `:19` 之间**（`WEB_DIST` 定义之后、`const app = express()` 之前）：

```ts
const WEB_DIST = path.join(REPO_ROOT, 'apps/web/dist');           // :17 既有

// NEW — load .env before ANY AIRP_* / DASHSCOPE_* read. Node native, no dotenv
// dependency (docs/tts/00 §3.3). Missing file is normal (CI / first checkout).
try { process.loadEnvFile(path.join(REPO_ROOT, '.env')); } catch { /* ambient env */ }

const app = express();                                            // :19 既有
```

以及紧随其后、**也在 `:19` 之前**的启动期一次性 warn（契约 §4.5）：

```ts
if (!process.env.DASHSCOPE_API_KEY) {
  console.warn('[AIRP TTS] DASHSCOPE_API_KEY not set; /api/tts returns 503 (character voice disabled).');
}
```

- **为什么在 `:17` 而不是更靠下**：`REPO_ROOT` 必须先定义；而 `AgentLifecycleManager`（`:38`）与 `createWorldRouter`（`:64`）都在 `:19` 之后，全部晚于该点，顺序天然正确。
- **为什么在 `:38` 之前而不是紧贴 `:216`**：`createWorldRouter`（`:64`）内部会读 `manifest.audio` 等，将来 `createTtsRouter` 挂载点也在 `:73` 之后。把 `.env` 加载顶到最前，任何下游读取都已被覆盖。**这是「保险栓放最上游」的写法**。
- **漏了会怎样**：`.env` 里的 `DASHSCOPE_API_KEY` 不生效 → `/api/tts` 永远 503（§3.D 步骤 7），本机默认路径（`DASHSCOPE_API_KEY` 未设置，见广播）会直接暴露成「角色全程无声」。而且失败是**静默的**——只在启动时那条 warn。
- **`catch` 吞掉所有异常是否安全**：安全。`loadEnvFile` 抛的是「文件不存在」；存在但语法错也会抛，此时保留 ambient env 是正确降级（契约写的就是 `catch { /* no .env */ }`）。**不要**把错误 `console.error`+退出，那会让 CI 无 `.env` 直接起不来。
- **类型可用性**：`process.loadEnvFile` 已在 `@types/node` 声明（`node_modules/@types/node/process.d.ts:1472`），`tsc -b` 不需要 `as any`。实测 Node v26.8.1 `typeof process.loadEnvFile === 'function'`。

### 3.C 路由挂载（`apps/server/src/index.ts:64-73`）

`createWorldRouter` 挂在 `app.use('/api', createWorldRouter(...))`。TTS router **并列**挂同前缀：

```ts
// :63-73 既有 —— 保持原样
app.use(
  '/api',
  createWorldRouter(REPO_ROOT, lifecycle, eventBridge, () => activeStore, (s) => { activeStore = s; })
);

// NEW —— 紧接其后（:76 `app.use(express.static(WEB_DIST))` 之前）。Same prefix;
// Express matches in order, and the two routers own disjoint paths (/api/tts*
// vs /api/worlds…/api/asset…), so the second never shadows the first. Only
// getActiveStore is shared — no lifecycle, no eventBridge: TTS is HTTP-only and
// must never touch the WS fan-out (00 §10.1).
app.use('/api', createTtsRouter(REPO_ROOT, () => activeStore));
```

- **import 落点**：`apps/server/src/index.ts:11`（`import { createWorldRouter } from './routes/world.js';`）之后加一行
  `import { createTtsRouter } from './routes/tts.js';`。
- **为什么并列而不是塞进 `createWorldRouter`**：TTS 与世界的生命周期耦合极弱（只要 `getActiveStore`），且 `createWorldRouter` 已 900+ 行。单开一文件符合「一个模块一个 owner」（契约 §14）。
- **路由顺序安全性**：`createWorldRouter` 内部没有 `/tts*` 路径（实测 `grep router.get/post` 无 `tts`），所以谁先挂都不冲突。[推断] 依赖 Express 顺序匹配的默认行为，非本文件新增语义。
- **漏了会怎样**：`GET /api/tts/audio/:file` 落到 SPA fallback（`index.ts:79-84`，`app.get('*')`），返回 HTML，前端 `decodeAudioData` 失败；`POST /api/tts` 会 404（`app.get('*')` 只接 GET）。两者都坏，所以挂载是硬要求。

### 3.D `POST /api/tts` 八步（契约 §4.2 逐字）

每步写「漏了会怎样」。字段名/响应形状逐字遵守契约 §2.1。

**步骤 0 —— 每请求读配置**（本文件私有）：

```ts
interface TtsConfig { apiKey: string; baseUrl: string; model: string; timeoutMs: number; defaultVoice: string; }

/**
 * Re-read env on EVERY request (not at module load): the test harness sets
 * env after import and expects it to take effect (TtsVerify06). Also lets an
 * operator rotate the key without a server restart.
 */
function readTtsConfig(): TtsConfig {
  const timeoutRaw = Number(process.env.AIRP_TTS_TIMEOUT_MS);
  return {
    apiKey: process.env.DASHSCOPE_API_KEY ?? '',
    baseUrl: (process.env.AIRP_TTS_BASE_URL ?? DEFAULTS.baseUrl).replace(/\/+$/, ''),
    model: process.env.AIRP_TTS_MODEL ?? DEFAULTS.model,
    timeoutMs: Number.isFinite(timeoutRaw) && timeoutRaw > 0 ? timeoutRaw : DEFAULTS.timeoutMs,
    defaultVoice: process.env.AIRP_TTS_DEFAULT_VOICE ?? DEFAULTS.voice,
  };
}
```

漏了会怎样：若在模块加载时读一次，测试无法在 harness 里 set env 后生效（`06` 已明确要求）；运维改 key 必须重启。

**步骤 1 —— active store**：

```ts
const store = getActiveStore();
if (!store) return res.status(400).json({ ok: false, code: 'no_active_world', error: 'No active world' });
```

- 漏了 → 缓存根未知，`path.join(undefined, …)` 抛错或落到 CWD，写盘污染随机目录（契约 §4.2 步骤 1）。
- code 逐字 `no_active_world`（契约 §8）。

**步骤 2 —— 校验 `text`**：

```ts
const { text: rawText, voice: rawVoice, language: rawLanguage } = req.body as {
  text?: unknown; voice?: unknown; language?: unknown;
};
if (typeof rawText !== 'string' || rawText.trim() === '') {
  return res.status(400).json({ ok: false, code: 'invalid_argument', error: 'text must be a non-empty string' });
}
```

- 漏了 → 空文本合成出奇怪音频并污染缓存（契约 §4.2 步骤 2）。
- **只在 `trim()` 判空，不 `trim()` 后发送**：页文本原样送给 DashScope（前导空格可能是有意的停顿）[推断]。

**步骤 3 —— 截断**：

```ts
let text = rawText;
let truncated = false;
if (text.length > MAX_TEXT_CHARS) { text = text.slice(0, MAX_TEXT_CHARS); truncated = true; }
```

- 漏了 → 超长请求被 DashScope 拒，整页无声（契约 §4.2 步骤 3）。
- **截断是「保住演出」而非静默失败**：`truncated` 进响应体（步骤 8），前端可标记。
- **注意**：截断发生在 hash 之前——hash 用**截断后**的 `text`（与缓存写入的文本一致）。若先 hash 后截断，缓存 key 会对应一段从未发出的文本。

**步骤 4 —— 解析 `voice`**：

```ts
const requestedVoice = typeof rawVoice === 'string' ? rawVoice.trim() : '';
const voice = VOICE_RE.test(requestedVoice) ? requestedVoice : config.defaultVoice;
if (requestedVoice !== '' && !VOICE_RE.test(requestedVoice)) {
  console.warn(`[AIRP TTS] reject malformed voice "${requestedVoice}"; falling back to "${config.defaultVoice}"`);
}
```

- 漏了 → 畸形 voice 让 DashScope 400，前端整页无声（契约 §4.2 步骤 4）。fail-loud 落日志（沿用 `docs/audio/00 §3.1` 口径）。
- **响应形状不扩**：不把「voice 被回落」写进响应体（契约只冻结 `ok/url/cached/characters/truncated` 五字段）。日志是唯一出口。
- **不读 README**：voice 由 `/api/characters` 下发（§3.C′），前端填进请求体；服务端只校验形状，避免第二个解析点。
- **`VOICE_RE` 值域已由主 agent 裁決（§15.1，2026-09-13）**：`Eldric Sage` 不是厂商音色（`Eldric` 与 `Sage` 是两个独立 ID），故**不**放宽正则接受空格。含空格的 `voice` 会被判畸形 → 回落默认（fail-loud 落日志）。落地无需为空格特判。

**步骤 5 —— 语言映射（契约 §4.4）**：

```ts
const languageType = typeof rawLanguage === 'string' ? (LANGUAGE_MAP[rawLanguage] ?? 'Auto') : 'Auto';
```

- 漏了映射（直接透传短码）→ DashScope 收到 `ja` 非法枚举 → 400（契约 §4.4）。
- **`Auto` 兜底**而非 `Chinese`：多语言混输官方默认（`qwen3-tts-flash.md §2.2`）。
- **`language` 的来源（契约 §15.4，归 05/03）**：前端取值顺序 = `manifest.locale` → 缺 locale 的世界**传 `'en'`**（四个世界内容皆英文）；**MUST NOT** 用 `App.tsx:39` 的浏览器语言猜测。服务端只做 §4.4 映射，不猜测。
- **未知短码**（如 `zh`）：`LANGUAGE_MAP` 未列 → 落 `Auto`（§4.4 的「其他/缺省 → Auto」），不报错。

**步骤 6 —— 查缓存**：

```ts
const hash = hashOf(config.model, voice, languageType, text);
const cacheDir = path.join(store.worldRoot, '.airpworld', 'tts-cache');
const file = `${hash}.wav`;
const abs = path.join(cacheDir, file);
if (existsSync(abs)) {
  return res.json({ ok: true, url: `/api/tts/audio/${file}`, cached: true, characters: text.length, truncated });
}
```

- 漏了（不查缓存）→ 每次翻页重复合成，延迟与成本飙升（契约 §4.2 步骤 6）。
- `existsSync` 而非 `stat`：命中是快路径，且原子写保证「存在即完整」（步骤 7）。
- **`characters` 用截断后长度**（= 实际合成字符数，与 `qwen3-tts-flash.md §3` 的 `usage.characters` 同义）。[推断：契约 §4.2 步骤 8 只写 `characters: <text.length>`，取「发送给厂商的文本长度」最一致。]

**步骤 7 —— 合成 + 原子写**：

```ts
if (!config.apiKey) {
  return res.status(503).json({ ok: false, code: 'tts_unconfigured', error: 'DASHSCOPE_API_KEY is not set' });
}
let wav: Buffer;
try {
  wav = await synthesise({ text, voice, languageType, apiKey: config.apiKey, baseUrl: config.baseUrl, model: config.model, timeoutMs: config.timeoutMs });
} catch (err) {
  const mapped = mapSynthError(err);   // §7.A
  return res.status(mapped.status).json({ ok: false, code: mapped.code, error: mapped.error });
}
await writeAtomic(abs, wav);           // §7.C
```

- **key 检查放在缓存命中之后**（步骤 6 之后）：已缓存的页即使 key 被撤走也能播（缓存是内容寻址的既成音频）。这是刻意的顺序——**先给已付出的成本续命，再拒新合成**。
  - [推断] 契约 §4.5 只说「`POST /api/tts` → 503」，没说与缓存查询的先后。放这里更省事且不伤害「未配置=无语音」的语义（首次未缓存页仍 503）。
- 漏了原子写 → 并发/中断时缓存里是半截 wav，前端 `decodeAudioData` 失败且**永不重试**（`failCached`，契约 §4.2 步骤 7）。
- **写盘失败**：`writeAtomic` 抛 → 错误被 handler 兜住 → 500 `{ ok:false, code:'internal', error }`。合成已成功但没落盘，下次重合成——可接受（幂等）。

**步骤 8 —— 返回**：

```ts
return res.json({ ok: true, url: `/api/tts/audio/${file}`, cached: false, characters: text.length, truncated });
```

字段顺序无关；关键五字段逐字（契约 §2.1）。**不落账、不发 WS 帧、不写 `events`**（契约 §1/§9）。

## ⑦ 错误边界与实现细节

### 7.A `synthesise` 逐步（`qwen3-tts-flash.md` 逐字对齐）

**第 1 步 —— 构造请求**（逐字参照 `qwen3-tts-flash.md §1.1 / §1.2 / §2.1 / §2.2 / §4.3`）：

```ts
const endpoint = `${opts.baseUrl}/services/aigc/multimodal-generation/generation`;
// qwen3-tts-flash.md §1.1: HTTP Base URL = https://dashscope-intl.aliyuncs.com/api/v1
//                           TTS 端点 = {base}/services/aigc/multimodal-generation/generation
const payload = {
  model: opts.model,                    // §2.1 顶层 model = "qwen3-tts-flash-2025-11-27"
  input: {                              // §2.1 顶层 input 对象，必填
    text: opts.text,                    // §2.2 text  必填，最大 512 Token
    voice: opts.voice,                  // §2.2 voice 必填，如 "Cherry"
    language_type: opts.languageType,   // §2.2 language_type 可选，默认 "Auto"
  },
};
const headers = {
  Authorization: `Bearer ${opts.apiKey}`,   // §1.2
  'Content-Type': 'application/json',       // §1.2
};
```

- **`language_type` 的 key 是下划线**（`§2.2` 表逐字）。写成 `languageType` 会静默落到 `Auto`（DashScope 忽略未知 key）——不影响成败但丢自然度。
- **端点必须拼 `baseUrl`**，不能硬编码：`AIRP_TTS_BASE_URL` 是契约冻结的 env（§3.3 表），测试靠它指向 mock（`06` 的诉求）。

**第 2 步 —— 发起（含总超时）**：

```ts
const ac = new AbortController();
const timer = setTimeout(() => ac.abort(), opts.timeoutMs);
try {
  const res = await fetch(endpoint, { method: 'POST', headers, body: JSON.stringify(payload), signal: ac.signal });
  // … 第 3、4 步 …
} finally { clearTimeout(timer); }
```

- **单 `AbortController` 覆盖合成 + 下载两跳**（契约 §3.3：`AIRP_TTS_TIMEOUT_MS` = 「单次合成（含下载）总超时」）。两跳共用一个 signal，`clearTimeout` 放到最外层 `finally`。
- 漏了超时 → 上游 hang 时请求永远挂着，前端每页都等，演出彻底停摆。

**第 3 步 —— 解析 `output.audio.url`**（`§3` 响应形状）：

```ts
if (!res.ok) throw new TtsUpstreamError('upstream', `DashScope HTTP ${res.status}`);
const data = (await res.json()) as {
  status_code?: number; code?: string; message?: string;
  output?: { audio?: { url?: string } };
  usage?: { characters?: number };
};
const audioUrl = data.output?.audio?.url;
if (typeof audioUrl !== 'string' || audioUrl === '') {
  throw new TtsUpstreamError('upstream', `DashScope response has no output.audio.url: ${data.code ?? ''} ${data.message ?? ''}`);
}
```

- 响应形状逐字见 `qwen3-tts-flash.md §3`：`output.audio.url`、`output.audio.expires_at`、`usage.characters`。
- **必须立刻下载**：`§5.3` 明写 OSS 签名链接**有效期 24 小时**（`§3` 的 `expires_at`）。缓存命中后不再依赖它，所以「拿到就下载+落盘」是唯一正确姿势。
- **不用 `data.status_code` 判成败**：HTTP 200 时 `status_code` 也是 200（§3），但 4xx 时可能仍是 200 body 带 `code`——以 `res.ok` 为主判据，`code/message` 仅用于错误消息 [推断：厂商未在文档中明确非 2xx 的 body 形状]。

**第 4 步 —— 下载 wav**：

```ts
const audioRes = await fetch(audioUrl, { signal: ac.signal });
if (!audioRes.ok) throw new TtsUpstreamError('upstream', `OSS download HTTP ${audioRes.status}`);
const buf = Buffer.from(await audioRes.arrayBuffer());
return buf;
```

- 用 `fetch` + `arrayBuffer`（Node 26 原生全局 `fetch`），**不引 axios/node-fetch**。
- 漏了看 `audioRes.ok` → 把错误页 HTML 当 wav 落盘，前端 decode 失败且永不重试。
- **校验 magic bytes（契约 §15.21 MUST）**：下载后断言 `buf.length >= 12 && buf.toString('latin1',0,4)==='RIFF' && buf.toString('latin1',8,12)==='WAVE'`（`isWav` 私有函数，实现见 `tts.ts:97-101`）。非 wav → 抛 `TtsUpstreamError('upstream')` → 502 `tts_upstream`，**不写盘**。理由：污染内容寻址缓存是**永久**的（前端 `failCached` 不重试），4 字节比较的代价可忽略。

**超时/异常映射**（`mapSynthError`）：

```ts
class TtsUpstreamError extends Error {
  constructor(public kind: 'timeout' | 'upstream', message: string) { super(message); this.name = 'TtsUpstreamError'; }
}
function mapSynthError(err: unknown): { status: number; code: string; error: string } {
  if (err instanceof TtsUpstreamError && err.kind === 'timeout') {
    return { status: 504, code: 'tts_timeout', error: err.message };
  }
  if (err instanceof TtsUpstreamError) {
    return { status: 502, code: 'tts_upstream', error: err.message };
  }
  const aborted = err instanceof Error && (err.name === 'AbortError' || err.name === 'TimeoutError');
  if (aborted) return { status: 504, code: 'tts_timeout', error: 'TTS request timed out' };
  return { status: 502, code: 'tts_upstream', error: err instanceof Error ? err.message : String(err) };
}
```

- `fetch` 被 abort 抛 `AbortError`（DOMException，`name === 'AbortError'`）。映射到 504。
- 网络层异常（ECONNREFUSED 等）映射到 502 `tts_upstream`。
- **`kind` 显式标记而非抓 `AbortError` 全局**：更稳，且 `synthesise` 内可在超时点主动抛 `TtsUpstreamError('timeout')`。

### 7.B `hashOf`（契约 §3.2 逐字）

```ts
import { createHash } from 'node:crypto';

/**
 * docs/tts/00 §3.2: sha256(`${model}|${voice}|${language_type}|${text}`).slice(0,20).
 * The four fields are joined verbatim (including the RESOLVED language_type, not
 * the request's short code) — same voice/text/model MUST hit, different MUST miss.
 */
export function hashOf(model: string, voice: string, languageType: string, text: string): string {
  return createHash('sha256').update(`${model}|${voice}|${languageType}|${text}`).digest('hex').slice(0, 20);
}
```

- **`languageType` 是映射后的值**（`Japanese` 而非 `ja`），逐字按契约 §3.2。
- `digest('hex')` 得 40 字符，`slice(0,20)` 得 20 个 `[a-f0-9]`（契约 §2.2 的 `:file` 形状 `^[a-f0-9]{20}\.wav$` 依赖它）。
- `|` 是分隔符：四个字段位置固定，model/voice/language 无 `|`，故无歧义。
- **确定性**：同一世界内同输入必得同 hash（无 salt、无时间戳）。

### 7.C 原子写（§4.2 步骤 7 的并发语义）

```ts
import fs from 'node:fs/promises';
import { randomUUID } from 'node:crypto';

/**
 * Same-dir temp + rename, mirroring LocalWorldStore.writeFileAtomic
 * (local-store.ts:174-188). Same-dir is REQUIRED: rename is atomic only within
 * one filesystem. The temp name carries pid + random because two concurrent
 * requests (two pages prefetched at once) may synthesise the SAME hash and race.
 */
async function writeAtomic(abs: string, data: Buffer): Promise<void> {
  await fs.mkdir(path.dirname(abs), { recursive: true });
  const tmp = `${abs}.tmp-${process.pid}-${randomUUID().slice(0, 8)}`;
  try {
    await fs.writeFile(tmp, data);
    await fs.rename(tmp, abs);
  } catch (err) {
    await fs.rm(tmp, { force: true });
    throw err;
  }
}
```

**并发语义（关键）**：

- 两个并发请求合成**同一 hash** → 各自写**不同的 tmp 名**（pid+random）→ 各自 `rename` 到同一目标。`rename(2)` 在同一 fs 内原子；后到的 `rename` **覆盖**先到的（POSIX），最终文件是**其中一个完整副本**，绝不半截。
- **不查重写**：不做「先 stat 再写」。查了也有 TOCTOU 窗口；重复合成同一 hash 的代价（多写一次同内容字节）可忽略。**重合成 > 竞态**。
- **同目录**：`.tmp-…` 与目标同在 `<cacheDir>`，否则跨 fs 的 `rename` 会 `EXDEV`。
- **崩溃残留**：若进程在 `writeFile` 与 `rename` 之间崩溃，会留下 `.tmp-…` 垃圾。`GET /api/tts/audio/:file` 的 `FILE_RE` 不匹配 `.tmp-…`，所以垃圾**永不会被当成缓存命中**（这正是原子写的保护点）。
- **`?file` 形状**：`^[a-f0-9]{20}\.wav$` 不含 `.tmp-`，`.tmp-…` 天然被 GET 拒。

## ⑪ 发现的冲突

1. **角色 `voice` 的来源（已裁決 §15.5，归 01 落地）**。
   契约 §3.1 定 README `voice` 是唯一真相源，§2.1 定请求体带 `voice?`，但未写前端从哪拿。**裁決（契约 §15.5）**：`GET /api/characters` 每个角色对象 MUST 新增 `voice?: string`（读 `characters/<id>/README.md` frontmatter，与 `avatar` 同处 `world.ts:545-550`），形状冻结 `{ id, home, role, avatar, bio, voice? }`，缺省不下发；落点归 **01**（服务端路由，§3.C′），`05` 消费。`04` 只负责取值与清单。**此条已闭环。**

2. **`VOICE_RE` 与厂商音色 ID 值域（原裁决已由 `07 §0` 推翻并取代）**。
   `04` 曾主张放宽正则以容纳 `Eldric Sage`，`00 §15.1` 原判其「是两个 ID 拼接」并保持正则不收空格。**该判断为假**——2026-09-13 实测：`Eldric`/`Sage` 各自 `InvalidParameter`，`Eldric Sage` 正常出声。**现行口径见 `07`**：`VOICE_RE` 放宽为 `/^[A-Za-z0-9][A-Za-z0-9 _-]*$/`（只做结构体检），**决定权在 `resolveVoice` 调色板**；世界内容写效果别名。
   - **01 的实现**：步骤 4 先 `VOICE_RE` 体检，再 `resolveVoice()` 解析；未知 → warn + 回落默认（fail-loud）。**不再把含空格的值判为畸形**（那是 B3 静默改声 bug 的成因）。
   - **信任等级（`07 §5`）**：调色板全部条目已逐条实测出声；**服务端不校验 ID 是否存在**（上游 400 → `tts_upstream`），存在性由 `check:voices` 在构建期保证。

3. **TTS 的 `code` 不在封闭 `ActionErrorCode` 枚举里**。
   契约 §2.1 说失败响应「沿用 `ActionError.toHttp()` 形状」——形状是 `{ ok:false, code, error }`，但 `tts_unconfigured`/`tts_upstream`/`tts_timeout` **不在** `ActionErrorCode`（`errors.ts:3-20`），`HTTP_STATUS` 表（`:23-41`）也没有 503/502/504。
   - **01 的裁定（不私改契约，仅记录）**：TTS **不复用 `ActionError`**，直接 `res.status(n).json({ ok:false, code, error })` 手写（形状与 `toHttp()` 逐字同构，code 是自由字符串）。理由：`ActionError` 语义是「action layer 的唯一失败通道」（`errors.ts:44`），TTS 不是 action，硬塞会污染枚举与状态码表。`GET /api/tts/audio` 的 403 同理用 `not_found` 的 body 形状（契约未冻结 403 body）。
   - **风险**：若 `06` 对 code 做 `ActionErrorCode` 类型断言会失败——但 code 只在 HTTP body，无编译期约束。
   - **建议主 agent**：契约 §2.1 补一句「`code` 为 TTS 自有字符串，非 `ActionErrorCode`」。01 不擅自补。

4. **契约 §2.3「不进 git」原为假断言（已由广播 #2 修正，01 已落地 `.gitignore`）**。
   原写「`.airpworld/` 已被忽略」；实测只忽略 db 与 prompt-presets，`tts-cache/` 会进 `git status`。现已按契约 §2.3 修订版在 `.gitignore:23` 后追加 `**/.airpworld/tts-cache/`（§3.B′），并实测三条 `check-ignore` 通过。**此条已闭环，留下作记录**。

5. **契约 §4.2 步骤 3 的截断与「页文本」现实冲突（低风险，记录）**。
   广播明确「0 条真实模型多行输出」→ 未来真实模型可能输出**整段无换行的长回复**，此时前端（按契约 §6.2 警告 ②）**不截断**，整段发给 `POST /api/tts`，服务端步骤 3 截到 500 字符 → **该页后半句无声但文字照常**。契约允许（§4.2 步骤 3「保住演出」+ `truncated` 标记），01 遵守。
   - **提醒 `03`**：拿到 `truncated:true` 时应视为可接受降级，不做重试风暴 [推断]。
