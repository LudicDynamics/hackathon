# 初雪七海：本机 TTS 与线上兜底

2026-09-14 用户确认：first-snow 女主七海（nanami）优先使用本机角色 TTS，经 Tailscale 地址访问；失败警告并回落既有线上服务。本节作为对 00 / 01 / 09 旧单供应商契约的增补。

浏览器仍只调用 AIRP 的 `/api/tts`，请求扩为 `{ text, voice?, language?, characterId?, emotion? }`。`characterId` 来自当前角色，`emotion` 来自该页标签，不发送角色背景或私密设定。无新增字段的旧调用继续走线上。返回 JSON 形状不变；本机失败的响应附带 `X-AIRP-TTS-Fallback: local-to-online`，前端据此 `console.warn`，包括线上也失败的情况。

服务端依据活跃世界 manifest 的 ID 与角色表核实归属，仅 `first-snow`、`first-snow-jp`、带存档后缀的初雪世界及旧 `firstsnow-*` 的 nanami 使用本机；澄及其他世界继续使用既有线上音色。世界 README 的 `voice` 保留为线上兜底声明，不需要迁移旧存档。

部署配置（写入本机 `.env.local` 后重启后端）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `AIRP_TTS_LOCAL_BASE_URL` | 空，关闭 | 本机 Fish TTS 基址；本机部署为 `http://100.120.116.13:8090` |
| `AIRP_TTS_LOCAL_VOICE` | `setsuna` | 本机服务加载的声音 |
| `AIRP_TTS_LOCAL_TIMEOUT_MS` | `30000` | 包含读取音频的单次总预算 |
| `AIRP_TTS_LOCAL_API_KEY` | 空 | 服务启用鉴权时使用，仅服务端持有 |

调用 `POST <base>/v1/tts`，发送 `{ text, voice, language, emotion }`，接收 RIFF/WAVE 字节。`normal/shock/thinking` 映射 `neutral`，`smile` 映射 `happy`，`sad/angry` 原样；缺省或未知标签使用 `neutral`。线上仍遵守 09 的固定语气指令，不接收 emotion。

本机 HTTP 错误、断连、超时和非 WAV 均触发服务端警告，然后走原 DashScope 缓存与合成流程。两条链路各有独立超时预算。线上缺少密钥或请求失败仍返回原错误码并警告，不伪造音频。本机不需要 DashScope 密钥；`GET /api/tts/config` 的 configured 表示至少一个供应商已配置，不保证网络可用，model/defaultVoice 仍指线上兜底配置。

本机缓存使用 `sha256(JSON.stringify(['fish-tts-v1', baseUrl, voice, language, emotion, text])).slice(0,20)`，与原线上缓存键分开。本机缓存命中优先；否则先尝试本机，失败后才读线上缓存或合成。线上兜底音频不写入本机键，下次请求会重新尝试本机，服务恢复后不会永久留在兜底声音。缓存目录及音频 URL 仍沿用 00 的世界隔离和反穿越规则。更换同一服务地址背后的模型时，应同步修改本机 voice 标识或清理对应本机缓存。

验证：本机真实日语合成与 AIRP 音频下载；自动测试覆盖本机成功、角色/世界隔离、HTTP/超时/非 WAV 降级、情绪缓存及服务恢复。用户明确不测试线上真实调用，线上密钥未配置时不宣称线上已验证。
