# 08 — 音色技能与门禁（voice-casting）

> 本批（2026-09-13）新增。权威层级见 `00-共同上下文.md` §0：本文补充 `00` 与 `07`，与它们冲突处以 `00`/`07` 为准。
> 起因（用户 2026-09-13）：「这个音色哪怕是映射成别名，你也需要写一个平台级的 skill 来教作家和其他 agent 用」。

---

## 0. 要治的病

`07` 解决了**机器侧**的问题：别名 → 商品名的解析链、调色板、`check:voices` 门禁。但**写内容的人仍然不知道写哪个**。

`07 §7` 的分配表只覆盖现存 9 个角色——它是**结果**，不是**方法**。下一个写角色的人面对的是：

- 40 条别名，只有 `alias` + `gender` + `tone` 三个字段；
- 一条硬约束（同世界不许撞声）；
- 一条反模式（不许写商品名）却没说**为什么**；
- 一个门禁（`check:voices`）却没人告诉他什么时候跑。

**这些知识今天只存在于 `07`（一份中文设计文档）和 `voices.ts` 的注释里，而内容作者读的是英文 skill。** 本批把「怎么给角色选嗓子」写成平台级 skill，让作家与其余 agent 在按需加载时读到判据。

---

## 1. 落点与命名

| 项 | 值 | 依据 |
|---|---|---|
| tier | **平台级**（`<repo>/skills/`） | 音色是引擎事实，跨世界共享（`07 §4`）；世界级会 N 份漂移 |
| 目录 | `skills/voice-casting/` | ASCII kebab-case（`AGENTS.md §1.1`） |
| `name` | `voice-casting` | 与目录名逐字一致（`04` A11） |
| 正文语言 | 英文 | 平台级一律英文（`04` A2） |
| references | `references/voice-palette.md` | 40 行目录 = 长表，走渐进披露（`04 §2.5`） |

**为什么叫 `voice-casting`**：skill 名要说**手艺**（选角），不是**数据**（调色板）。`voice-casting` 与既有两份（`component-narration` / `tool-craft`）同构——都是「怎么做得好」，不是「有什么」。

## 2. 受众与触发

**受众 = 写角色的人**：世界作者（改 `templates/**`）、以及在运行时新增角色的作家（`chalk` 的 `WRITE_ROOTS` 含 `characters/`，故作家能手写 `characters/<id>/README.md`）。

**不给谁**：不写角色的角色 agent 读它没有意义——但机制上无法按 agent 裁剪（`04 §3.5` 的 `--skill` 传目录、靠 `description` 分流）。因此**分流靠 `description`**，与既有两份同一套办法。

`description` 的触发物（供 A7 机械核验）：`voice` / `README` / `palette` / `character`。

## 3. 正文放什么（判据，不放目录）

`SKILL.md` 正文（≤120 行，`04` A5）回答**怎么选**：

1. **这一行写在哪** —— `characters/<id>/README.md` 的 frontmatter `voice:`；
2. **按效果命名，不按商品名** —— 以及**为什么**（商品名不可拼、拼错静默无声）；
3. **怎么挑** —— 读 `tone` 列，问「这个人该是什么声音」（年龄 / 温度 / 语速 / 演给一屋子人还是对一个人说）；
4. **选错的代价（写成后果）** —— ① 不在调色板的名字 → 页面照播默认嗓子 + 服务端一条 warning + 门禁红；② 同世界撞声 → 玩家分不清谁在说；③ 性别不符；
5. **不是你这层的决定** —— 语言（一个嗓子说所有语言，世界 locale 定语言）、分行（行是写法决定的）；
6. **要加新音色怎么办** —— 「没实测出声 MUST NOT 进表」（`07 §5`），指向 `docs/tts/07`；
7. **写完跑什么** —— `pnpm check:voices`。

`references/voice-palette.md` 放**完整目录**：按 gender 分组的 `alias | tone` 表。

## 4. 关键裁决

### 4.0 V4 补洞：未声明的角色也算一份声音（2026-09-13，评审发现）

**旧 V4 有洞**：它把未声明 `voice:` 的角色 `.filter(v => v !== null)` 掉再做重声检查。但未声明的角色**不是没声音**——它回落服务端默认（`tts.ts:41` 的 `Cherry`）。于是：

- 同世界两个都不声明 → 播放时两把都是 `Cherry`（真碰撞），**门禁却是绿的**；
- 一个声明 `warm-cheerful`（其 id 就是 `Cherry`）与一个不声明 → 同样是真碰撞，门禁也看不见。

**修法**：未声明者按**默认音色**计入 `byWorld`（不再跳过），V4 比的是「角色实际发出的声音」。已在 `check-voices.mjs` 落地，并做过反向验证（同世界两角色都去掉 `voice:` → FAIL）。**skill 正文同步写明「不声明 = 默认音色，不是免责」。**

> 边界：V3 解析失败的声明仍只报一次（`if (resolved === null) continue`），避免「同世界两个 typo」被误读成碰撞。

### 4.1 目录表由 `tools/check-voices.mjs` 生成，不手写（V5）

`references/voice-palette.md` 是调色板的**第二份拷贝**。手维护必然漂移——skill 说 `wise-elder` 存在、而 `voices.ts` 已删掉它，正是本批要防的「正确写法与错误写法之间没有护栏」。

**裁决**：该文件是**生成物**（lockfile 模式），渲染函数住在 `tools/check-voices.mjs`（唯一实现），门禁 **V5** 逐字节比对；`node tools/check-voices.mjs --write-ref` 重新生成。**手改该文件 = 门禁红。**

> 为什么不放进 `SKILL.md` 正文：40 行 tone 表每次 `read` 都付全价，而大多数轮次不需要选角（`04 §2.5`）。

### 4.2 只暴露 `alias` 与 `tone`，不暴露商品名 id

`references/voice-palette.md` **不含** `id` 列。理由：作者**只需要**别名；把 `Eldric Sage` 摆在表里等于邀请人照抄（`07 §2` 的反模式）。id 映射的唯一真相源是 `voices.ts`，调试时去那里看。

### 4.3 门禁改动（三处，都是「新增 skill 后必须同步」的机械核验）

| 门 | 现状 | 本批 |
|---|---|---|
| `tools/check-skills.mjs` **A0** | `platformFiles.length === 2`（硬编码 2） | 改为**期望清单逐字比对**（`['component-narration','tool-craft','voice-casting']`）——新增 skill 忘了登记即红 |
| `tools/check-skills.mjs` **A7** | 一份共享的 8 词 `TRIGGER_NOUNS` 套在所有平台 skill 上 | 改为**按 skill 分表**（`TRIGGERS_BY_SKILL`）——音色 skill 不该靠 `roll_dice` 通过 |
| `tools/check-voices.mjs` **V4** | 未声明角色被跳过（见 §4.0 的洞） | 未声明者按默认音色计入重声比较 |
| `tools/check-voices.mjs` **V5** | 无 | **新增**：`references/voice-palette.md` 与调色板逐字节一致（§4.1） |

A7 的分表**不放松**既有两份：`component-narration` 与 `tool-craft` 的过滤词收窄为各自真正会说的工具名，两份仍分别命中 ≥2。

### 4.4 语言分层的边界（诚实登记）

`check:voices` 的 V3/V4 只走 `templates/*/characters/*/README.md`——**玩家世界（`worlds/`）与运行时新写的角色不在门禁内**。这是既有边界（`worlds/` 被 gitignore），本批不改；skill 正文如实写明门禁走的是 `templates/`，不假装覆盖全仓。

> **`pnpm check:voices` 不在 `pnpm build` 里**（`package.json`：build 只做 tsc + vite）。它是**人工收工自检**的一环（`AGENTS.md §6.4`）。skill 正文据此写明「门禁只在有人跑它时报」，不宣称 build 会拦——否则读者会以为 `pnpm build` 能救一个写错的音色。

## 6. 反模式

1. **手写 `references/voice-palette.md`** —— 它是生成物（§4.1），手改即门禁红。
2. **在 skill 里写商品名当推荐值** —— 正文举例一律用别名（§4.2）。
3. **把 40 行 tone 表塞进 `SKILL.md`** —— 违背渐进披露（A5 会红）。
4. **新增平台 skill 却不动 A0/A7** —— 门禁红；这正是 A0 改成清单比对的目的。
5. **在平台 skill 里写 CJK** —— A2 红（`docs/tts/07-音色别名映射.md` 这类中文路径必须写成 `docs/tts/07`）。
