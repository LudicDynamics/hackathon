## 3. 行为契约逐步（每条测试「漏了会怎样」）

### 3.1 测试 (a)：三条读取路径对列值求 diff

**契约 §10.1 第 1 条**。断言 `cards.width/height`（列）与**三条读取路径**的 `w/h` 逐卡相等：

1. `GET /api/layer` 返回体的 `items[].w/h`（`routes/world.ts` 的 `enriched`：今天 `w: form.w, h: form.h`，注释在 `world.ts:342-344`）。
2. `canvas.ts:367-375` 的 `boxesOf`（`arrange` 布局输入；今天读 `form.w/h`）。
3. `look-at.ts:149-152` 的 `boxesOf`（`look_at`/`view_canvas` 输入；**今天读 `row.w/h`**）。

**关键障碍（已与 02 约定解法）**：两个 `boxesOf` **都是模块私有**（`canvas.ts`/`look-at.ts` 的 `grep "^export"` 里都没有）——测试**不能直接调用**。采用**经公开入口**（不动导出面，最小侵入；已回复 02 采用此案）：

- `canvas.ts boxesOf` → `service.arrangeCards({ layout: { mode: 'row', paths } })` 的落点（`:489` 是 `boxesOf` 的唯一调用点）。
- `look-at.ts boxesOf` → `service.viewCanvas({ layer })` 的 `details.items[].w/h`（`:385-393`）。

**数据准备（防假绿，02 提示 + 契约 A2 对照实验）**：测前先用 `store.execCanvas('UPDATE cards SET height=? WHERE id=?')` 把某卡 `height` 改成**异于 `form.h`** 的值（578 vs 190）。否则读 form 与读 row 结果相同，三条路径**假绿**。

**读取顺序必须锁定（评审 MAJOR-1，已实测）**：`GET /api/layer` 内部会触发 `reseatLayer`，而**今天的 `reseatLayer` 会把列值冲回 `form.h`**（契约 §7 A4）。于是存在一条**假绿路径**：若先调 `/api/layer`、再读列，列已被冲成 190；接着三条路径（今天）恰好都读 190 → **`A = B = C = row` 全相等 → 测试假绿**，今天也不会红。**唯一正确的顺序**：

```
① store.execCanvas('UPDATE cards SET height=? WHERE id=?', [578, path])   // 写列
② const row = store.getLayerCards([path])[0];                            // 立即读回参考列值
   assert.equal(row.h, 578);                                             // 参考值锁定 = 578
③ 再调三条读取路径（此步可能触发 reseatLayer 冲列——无所谓，参考值已在 ② 固定）
④ 逐条与 row.h 比，全部相等才 PASS
```

> **为什么不能先调路径后读列**：参考值会被路径的副作用污染，得到「三条路径互相相等」的无意义绿。锁定顺序后，参考值恒为「写进去的 578」，才能区分「真读列」与「读表后正好回落成同值」。

**今天的实测（2026-09-12，`node /tmp/fp-a.test.mjs` 复现；参考列值在路径调用前读取）**：

```

/api/layer (form.h)        = 190      <- 读表（且它触发的 reseatLayer 会把列冲回 190）
canvas.ts boxesOf (form.h) = 190      <- 读表
look-at.ts boxesOf (row.h) = 578      <- 读列
=> three paths equal to row.h today? NO (/api/layer & canvas.ts=190 vs row=578)
```

**为什么今天必红**：同一张卡列被实测值覆盖后，`look-at` 读列看到 578，`/api/layer` 与 `canvas.ts` 读表仍看 190——**三条路径对同一张卡给出两个答案**（契约 §7 A2 的现成物证）。

**漏了会怎样**：若只测 `/api/layer`（旧口径），会漏掉 `canvas.ts` 与 `look-at.ts` 两个纯服务端消费者——修复只改 `routes/world.ts` 也会「测试全绿而 `arrange` 仍按 190 排版」（I1 破）。

> **I1 范围限定（02 登记，2026-09-12）**：本条只对**已排座卡**求 diff。**新卡初值**走 declared 是正当的，**MUST NOT** 把 `delete.ts:205` 的 `seatFileOf()`（`move.ts:172-183` 用它喂 `seatNear`/`seatUnplaced`，目的地层已确认为无行）当「第三处现算 `cardFormOf` 的碰撞点」判 I1 违例（契约 §3.2 MINOR-11 / §4.1）。同理 `routes/world.ts:85-86` 的 `cardSize()` 在新卡路径上也是正当初值。

### 3.3 测试 (b2)：层排座路径产出不重叠的绘制盒（**核心回归**）

**输入 = 真实时序**（契约 §10.1 第 2 条，已实测校准；这是唯一正确的形式）：

```
② 模拟 footprint 回写：store.execCanvas(
     'UPDATE cards SET width=?, height=?, metadata=? WHERE id=?',
     [realW, realH, JSON.stringify({ measuredAt: '2026-09-12T…' }), path])   // 只改 width/height/measuredAt

③ 重走层排座路径：store.reseatLayer('baker-street', files)          // files 仍是 declared（routes/world.ts:327-329 传的 cardSize()）
④ 用真实绘制高（BROWSER_MEASURED）计算 seats 两两是否重叠
```

- **断言**：`overlappingPairs.length === 0`。

> **为什么不能只调 `seatUnplaced`、也不能「把真实高喂给 `seatUnplaced`」**（假绿陷阱，契约 §10.1 第 2 条逐字警告）：`seatUnplaced` 忠实使用传入的 `w/h`。若把真实高直接喂给它，它输出**不重叠**、测试**假绿**（实测 `overlappingPairs = 0 PASS`）。**bug 不在 `seatUnplaced` 内部**——`seatUnplaced` 只给**无行的卡**排座（`local-store.ts:524-528`：`missing = files.filter(f => !existingIds.has(f.path))`，无缺失即 `return []`）。一旦卡已有行，**没有任何路径会在实测占位变化后重排**——这才是 bug。

**今天的实测（2026-09-12，`node /tmp/fp-ab.test.mjs`：declared 首排 → 回写实测列 + `measuredAt` → `reseatLayer`(declared) → 按真实高判重叠）**：

### 3.4 测试 (c)：实测值不被冲掉 + 稳态幂等（守 I2）

**契约 §10.1 第 3 条 / 不变量 I2 —— 稳态幂等形式**：

1. `seatUnplaced` 排一次（列初值 = declared；此时 `metadata.seatH` = declared 值）。
2. `store.execCanvas('UPDATE cards SET width=?, height=?, metadata=? WHERE id=?')` 写入实测值 + `metadata.measuredAt`（**不动 `seatW/seatH`**，模拟 footprint POST 的效果，契约 §5.2）。
3. 跑 `reseatLayer('baker-street', files)` **两次**，`files` 的 `w/h` = **declared**（模拟 `routes/world.ts:327-329` 传给它的 `cardSize()`）。
4. 断言：
   - **第一次**：第 3 条漂移信号命中（`row.h !== meta.seatH`）→ **允许重排**：`x/y` **可以变**（这就是「座位让开」，与测试 (b2) 同一机制），`seatH` 更新为行值，而 `w/h` **仍 == 实测值**（未被冲回 declared）。
   - **第二次**：稳态 → **no-op**：`w/h == 实测值`（**I2 的本体**）、`x/y` 不变、`seatH` 不变、`metadata.measuredAt` 仍在。

> ⚠️ **MUST NOT 断言「第一次 reseat 后 x/y 不变」**——那会与测试 (b2) 直接矛盾：实测占位**变大**时座位**必须**让开才算修好（契约 §10.1 第 3 条末、§3.2 I2 注）。
> **为什么仍断言 `metadata.measuredAt` 与 `seatH`**：`measuredAt` 存在证明实测值语义未被抹掉；`seatH` 在第二次不变是「稳态」的直接证据——若实现者每次都把 `seatH` 重置，第二次就会再次重排（`x/y` 抖动），断言即刻暴露。

**今天的实测（2026-09-12，`node /tmp/fp-b.test.mjs` v3）**：

```

[c] after  reseat: h = 190 (CLOBBERED back to form.h=190)
```

**为什么今天必红**：`reseatLayer:599-604` 把「`row.h !== form.h`」判成漂移 → `:635` `UPDATE ... width=?, height=?` 写回 form 值。实测值（999）与 form 值（190）不等 → 判漂移 → **无声冲回**（契约 §7 A4 配置矩阵）。第一次就冲回，第二次无从谈幂等。

### 3.5 测试 (d)：kind 改尺寸仍重排（守 §5.1 第 4 条）

**契约 §10.1 第 4 条 / §5.1 第 4 条（MAJOR-2）**——「kind 在代码里被改尺寸」这条 `reseatLayer` 的**原始正当用途**不能被实测补链静默移除：

1. 行带实测值（`metadata.measuredAt` 非空，`width/height` = 实测值）= 模拟一张已测量过的卡。
2. `metadata.formVersion` **存在且失配**当前 kind 算出的 declared version（如代码里把 `CARD_FORMS.chalk.h` 从 190 改成 210）。**`formVersion` = `cardFormVersionOf(kind, w, h)`，hash 输入是 `${kind}:${w}x${h}`（契约 §9 第 8 条 / MINOR-10）**——只按 `(w,h)` 会漏判 `map` 300×200 与 `thread` 300×200 这类**同尺寸异 chrome**。
3. 跑 `reseatLayer('baker-street', files)`，`files` 的 `w/h` = **declared**，且 **`files[].kind` 必须存在**（`cardFormVersionOf` 的输入之一；见下方硬约束）。
4. **断言**：该行**被重排**（`x/y` 变化或按 declared 落点；用 **declared** `form.w/h` 排，而不是行值——实测值按旧宽折的行已失效，契约 §5.1 SPLIT 语义），且 **`metadata.measuredAt` 被清空**（等下次测量重写）。
