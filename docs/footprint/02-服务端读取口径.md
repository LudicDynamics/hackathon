## 1. 一句话定位

**服务端有四条读取「卡片占位尺寸」的路径，今天口径不一致——`canvas.ts` 的 `boxesOf` 读 form 表、`look-at.ts` 的 `boxesOf` 读行列、`routes/world.ts` 的 `enriched` 读 form 表、`routes/world.ts` 的 `cardSize`（喂排座）读 form 表。本文把前三条统一到 00 §3.4 的口径（行列是唯一真相，form 表只是「行缺失/退化时」的初值回落），并把第四条 `cardSize` 按契约 §3.4 BLOCKER-3 拆成 `declaredSizeOf`/`storedSizeOf`（§2.2b）。**

边界：本文只改**读**。行列由谁写（01）、实测值由谁回传（03）、前端怎么测（04）、怎么证明（05）都不在本文范围（00 §4 owner 表）。本文**不引入第三次现算 `cardFormOf` 的碰撞点**（00 §3.2 I1）——恰恰相反，目标是把今天已存在的两种口径收成一种。

### 2.2 改造后的读接口（三个读点签名不变；新增共享 `boxSizeOf` + `world.ts` 两个 size helper）

三条读径最终都满足同一优先级：**行列 `w/h`（> 0）优先；否则回落该 kind 的 `form.w/h`**（00 §3.4 表）。

### 2.2a 读径的唯一 precedence（`boxSizeOf`，NEW）

为让「回落」只有**一个实现**（否则就是 I1 要消灭的多点真相）：

```ts
// NEW — packages/shared/src/actions/canvas.ts（index.ts:19 `export * from './actions/canvas.js'` 出 barrel）
import type { CardRecord } from '../store/world-store.js';   // 已存在：world-store.ts:13
import type { CardForm } from '../schemas/forms.js';          // 已存在：forms.ts:49

/** The ONE row-vs-form precedence (00 §3.4). A row that is missing OR degenerate
 *  (`w/h <= 0`) falls back to the kind's declared form — the first-paint default. */
export function boxSizeOf(
  row: Pick<CardRecord, 'w' | 'h'> | undefined,
  form: Pick<CardForm, 'w' | 'h'>
): { w: number; h: number } {
  return row && row.w > 0 && row.h > 0 ? { w: row.w, h: row.h } : { w: form.w, h: form.h };
}
```

放置理由：放 `actions/canvas.ts`（**02 的 owner 文件**）而非 `schemas/forms.ts`（01 的 owner），避免越界；出 barrel 后 `routes/world.ts` 与 `actions/look-at.ts` 都能 import，读径共用**同一段判定**。这是 I1 在读路径上的落点：**不是「三处都记得写 form 回落」，而是「三处都调同一个函数」。**

### 2.2b `cardSize` 拆成两个 helper（NEW，owner 02；契约 §3.4 BLOCKER-3）

`routes/world.ts:82-88` 的 `cardSize(item)` 今天**同时**喂两个调用点，而两者需要的值**相反**——这是契约上一版的表述漏洞。契约裁决**必须拆成两个 helper**：

| NEW helper | 用途 | 值 |
|---|---|---|
| `declaredSizeOf(item)` | 喂 `reseatLayer`（`world.ts:329`） | `{ kind, w, h }` ← `cardFormOf`（**declared**；kind 判定用） |
| `storedSizeOf(item, row)` | 喂 `seatUnplaced`（`world.ts:318`） | `{ kind, w, h }` ← `row.w/h ?? form.w/h`（**行值**，首次无行回落 declared） |

```ts
// NEW — apps/server/src/routes/world.ts（同文件局部函数，不导出）
import type { CardRecord } from '@airp/shared';   // 已存在：index.ts:6 → store/world-store.ts:13
// cardFormOf / cardKindOf 已存在：world.ts:13-14 已 import（forms.ts:123 / :108）；二者均返回 string kind

/** Declared footprint of a kind — reseatLayer judges "was this kind resized in code?".
 *  `kind` is part of the payload: contract §9 第 8 条 hashes `formVersion` over
 *  `kind + w + h` (map 300×200 and thread 300×200 share a size but differ in chrome). */
function declaredSizeOf(item: LayerItem): { kind: string; w: number; h: number } {
  const form = cardFormOf(item.frontmatter, item.filename);
  return { kind: cardKindOf(item.frontmatter, item.filename), w: form.w, h: form.h };
}

/** Stored footprint — the row is the truth; declared only when there is no row yet. */
function storedSizeOf(
  item: LayerItem,
  row: CardRecord | undefined
): { kind: string; w: number; h: number } {
  const declared = declaredSizeOf(item);
  const { w, h } = boxSizeOf(row, declared);   // ONE row-vs-form precedence body (§2.2a)
  return { kind: declared.kind, w, h };
}
```

> **`kind` 是必需的（与 01 的接口约定，2026-09-12 经 IRC 确认）**：01 的 `reseatLayer` 入参是 `SeatFile[]`（`world-store.ts:24-28` 今天只有 `path?/w?/h?`）。契约 §9 第 8 条把 `formVersion` 的 hash 输入定为 `kind + w + h`，故 **`SeatFile` 须新增可选 `kind?: string`**（01 owner），且 `world.ts:329` 构造的 SeatFile 必须带上它——否则 `declaredVersionOf` 返回 null，`reseatLayer` 跳过该 path（**静默降级**，功能不生效）。`:318` 的 `storedSizeOf` 也**一并带回 kind**，01 的 `seatUnplaced`/`seatNear` 才能在首次排座时写 `formVersion`（不带也能跑，靠同一 pass 的 `reseatLayer` backfill）。

**两者为何必须分开**（契约 §3.4 判据）：

- `reseatLayer` 的漂移判定第 4 条靠 **declared** 算出的 `declaredVersion`（由 01 在 `reseatLayer` 内用 `files[].kind + w + h` 现算；`metadata.formVersion` 是它上次的快照）判断「**kind 是否在代码里被改尺寸**」→ 必须拿 declared。若拿行值，每次实测回写都会被误判成 kind 变更、把实测值冲回 declared（**I2 破**）。
- `seatUnplaced` 的职责是**给一张全新（无行）的卡找不重叠的座位**→ 必须拿该卡**真实**占位；有行时即行值，无行时 declared 就是正确初值。
- **两者混用会让 b2 绿而服务端仍按 190 排座**（05 §3.3 已点名）。

`storedSizeOf` 委托 `boxSizeOf`（§2.2a），使「行 vs form 的回落」**仍然只有一处函数体**；`declaredSizeOf` 是**唯一的 declared 来源**（也服务 §3.2 的 `enriched` 无行回落，经 `storedSizeOf`）。

> **与 01 的边界（2026-09-12 经 IRC 确认）**：01 的 `reseatLayer` **不复用** `declaredSizeOf`——它在 `shared/store/local-store.ts` 内，入参是 `SeatFile[]`（无 `frontmatter`、不做文件 IO），自持 `declaredOf(f)`/`declaredVersionOf(f)`。`declaredSizeOf` 只是 **02 侧「从 `LayerItem` 取 declared（含 kind）」** 的逻辑，专服务 `world.ts` 的两个调用点。`kind` 是两边唯一必须对齐的字段。

## 3. 行为契约逐步（每一步写「漏了会怎样」）

### 3.1 `actions/canvas.ts` 的 `boxesOf`（layout 用，`:366-374`）

1. 取该批 path 的**全部行**：`store.getLayerCards(paths)`（`local-store.ts:504-517`；同步方法；`CardRecord[]`，`w/h` 来自 `toCardRecord:1160-1170` → `row.width/height`）。
   - **漏了会怎样**：继续现算 `cardFormOf` → `arrange` 的 grid/circle/row 仍按 chalk 的 `190` 排座，`arrange` 把长 chalk 叠在一起（00 §1 的 bug 原样保留）。
2. 建 `Map<path, CardRecord>`。
   - **漏了会怎样**：`getLayerCards` 的顺序由 SQL `IN (…)` 决定、且**会静默丢掉无行的 path**（3.1.4）；不建 Map 只按下标对齐，一旦有 path 无行，后续全部错位。
3. 逐 path 求 box：`row = map.get(path)`；`boxSizeOf(row, form)`。`form` 仍由 `parseFrontmatter(await store.readFile(path))` + `cardFormOf(frontmatter, basename)` 得到（`canvas.ts:20`/`:19` 已 import）；**行有值时短路，不读文件**。
   - **漏了会怎样**：把 form 值写回 `LayoutBox` 就退回第 1 步。
4. **缺失/退化行**：返回里没有该 path ⇒ 尚无行（首次未排座）⇒ 回落 `form.w/h`。行存在但 `w <= 0 || h <= 0` ⇒ 退化行 ⇒ 回落 `form` 并 `console.warn`（**不静默**）。
   - **漏了会怎样**：`arrange` 对从未上屏的卡拿到 `w=0,h=0`，`computeRow:353` 的 `pitch` 塌成 `SEAT_STEP`、所有卡叠在锚点——比今天更糟。
5. 返回 `LayoutBox[]`（顺序 = 传入 `paths`；`computeGrid` 内部另有 `bySortedPath`（`canvas.ts:313`）保证确定性）。
   - **漏了会怎样**：顺序漂移 → `arrange` 落点不确定，`canvas.test.mjs:397`（确定性断言）会红。

**A4 交互（00 §7 A4）**：`arrangeCards` **不经过** `/api/layer`，所以 `boxesOf` 读到的行**不会被 `reseatLayer` 冲回**；`placeCards`（`local-store.ts:711-730`）经 `applyPlaceCard`（`:741-770`，逐字注释 "w/h are never written"）**只写 x/y**，实测 w/h 在 `arrange` 前后**保持不变**。即：`arrange` 读实测值、**不破坏**实测值。§10.1(a) 顺带覆盖这一点。

### 3.3 `actions/look-at.ts` 的 `boxesOf`（`:149-152`）—— 不改函数体，改的是「它读到的列变真了」

今天它已读行列（`:150` `ctx.store.getLayerCards(paths)`），**代码无需改**。但 00 §3.4 表对 `spatial.ts`/`layer-page.ts` 写的「不变（入参来源在 §3.4 修正）」——那个「入参来源」就是本函数。

**设计判定（本文冻结）**：`look-at.ts boxesOf` **不加 form 回落**。

- 理由：`layer-page.ts:131` 的 `box?: Box` 契约逐字写「**Present only when a `cards` row exists**」；`look_at`/`view_canvas` 的分支语义是「无行 = 还没排座」（`renderLayerBlock:221-228`、`renderCanvasBlock:264/296-298` 的 "Not yet placed"）。给一个 form 回落的假 box，会让**从未上过屏的卡**在 `look_at` 里谎报几何与方位。
- 与 `canvas.ts boxesOf` 的**刻意不对称**：`arrange` 必须给每张卡一个落点（缺尺寸就排不了座）→ 回落；感知工具必须诚实报告「未排座」→ 不回落。两条语义都在 00 §3.4 口径之下（回落是「为算出一个数」，不是「为报告一个数」）。
- **漏了会怎样（若误加回落）**：`view_canvas` 的 `details.overlaps`（`look-at.ts:370-377`）会把「未排座卡按 form 摆出的假盒」算进重叠对，玩家明明没看到这些卡却报告重叠——比不报告更坏。

### 9.1 任务点名核实：`look_at` 输出的「卡片尺寸 a×b」会变——对 Agent 感知有无副作用？

**先纠正一处任务表述（发现）：`layer-page.ts:284` 的「a×b」不在 `look_at` 里，在 `view_canvas` 里。**

- `layer-page.ts:284` 位于 `renderCanvasBlock`（`:260-319`）；其**唯一调用者**是 `look-at.ts:380` 的 `viewCanvas`。`look_at` 的目录块走 `renderLayerBlock`（`:172-231`），**不印尺寸**。
- 所以「a×b 变化」影响的是 **`view_canvas` 的 text**；`look_at` 受影响的是它的 "Layout (nearest neighbour)" 与 "Overlapping pairs" 行（D5）。两者都变，但**变的位置不同**。

**会变，且是设计目标。** 逐条评估副作用：

1. **对 Agent 的世界感知：变准，不是变坏。** `view_canvas` 的尺寸与「重叠对」今天**是错的**（D7 漏报 2 组真实重叠，00 §2.3）。改造后 agent 读到的 `460×578` 与 "Overlapping pairs" 才是玩家所见。agent 据此决定「这两张卡叠着，我该挪一张」——这是**修好后才有**的能力。
2. **会不会「尺寸跳变」让作家困惑？** 分三档：
   - **不同次调用之间**（writer 又写一段 → chalk 真变高 → 下次测量回传 → `view_canvas` 印新值）：**如实反映现实**，不是噪声。00 §3.3 的 200ms 尾防抖 + 幂等（同值不写）保证只有**真实变化**才产生新值。
   - **同一世界、无浏览器会话时**：行列停在首次排座的 `form` 值 → `view_canvas` 印的就是今天的样子（`460×190`）。即**降级为今天的输出，不会更坏**（§12 未知 1）。
   - **一次调用内**：`view_canvas` 是快照读（一次 `getLayerCards`），**不会**在同一份输出里出现两个尺寸，不存在「跳变」。
3. **格式不变**：`sizeWordOf`（`layer-page.ts:123-124`）只看 `w`（`w >= 420 ? 'wide' : w <= 210 ? 'small'`），与 `h` 无关；`w` 本就不变 → **`wide/small` 分类不抖动**。`dirPhrase` 的阈值是**相对量**（`avgW`/`avgH` 归一，`spatial.ts:45-50`），盒变大不会让 "next to" 突变，除非真实几何变了。
4. **一句话结论**：`view_canvas`/`look_at` 的尺寸输出**会变、必须变**；这是 00 §1「认知与观感一致」的直接兑现。它**不产生伪抖动**（值只在 DOM 真变时才变），**最坏情形退化为现状**（无浏览器测量时）。
