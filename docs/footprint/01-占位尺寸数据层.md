## 1. 一句话定位

**把 `cards.width/height` 从「kind 常量的缓存」升格为「该卡的真实占位尺寸」，并重写 `reseatLayer` 的漂移判定——让它只在五个正当漂移源（行缺失 / 列值非法 / **实测占位已变** / kind 改尺寸 / legacy 迁移）时重排，绝不用 `form.h` 冲掉实测值。**

反面对照：今天 `reseatLayer` 用 `row.h !== form.h` 当漂移信号（`local-store.ts:599-604`），实测 A4 证明它**挂在每次 `/api/layer` 上**（`routes/world.ts:325-332`）——任何与 form 表不符的列值，下一次请求就被无声冲回。**本模块是本批次的前置：不先改它，03 的回写全被按回原状**（契约 §7 A4）。

```ts
/**
 * NEW. Short, deterministic hash of a DECLARED footprint. Changes IFF the
 * declared (kind, w, h) triple changes, so it is the ONLY thing `reseatLayer`
 * compares to decide "the kind was resized in code" (contract §5.1 第 4 条 /
 * §9 第 8 条). Pure FNV-1a on `${kind}:${w}x${h}` — dependency-free on purpose:
 * forms.ts is imported by the web bundle (cardFormOf), and node:crypto there
 * would break it.
 *

 * `thread` (300x200, chrome paper) share a box but paint at different heights, so
 * hashing `(w,h)` alone would miss a resize. Consequence accepted by the contract:
 * renaming a kind re-seats its cards once (the alternative — silent non-reseat —
 * is worse).
 */
export function cardFormVersionOf(kind: string, w: number, h: number): string;
// impl: let hash = 0x811c9dc5;
//       for (const ch of `${kind}:${w}x${h}`) { hash ^= ch.charCodeAt(0); hash = Math.imul(hash, 0x01000193) >>> 0; }
//       return hash.toString(16).padStart(8, '0');
```

```ts
/** NEW. Declared footprint carried by a SeatFile, or null when untrustworthy. */
function declaredOf(f: SeatFile): { w: number; h: number } | null {

function declaredVersionOf(f: SeatFile, d: { w: number; h: number }): string | null {
```

## 3. 行为契约逐步（每步写「漏了会怎样」）

> 本节是整个批次风险最高的一处（契约 §5.1：改错会触发全层重排、玩家自己拖过的位置全丢）。每一步都给出可机械核验的判据。

### 3.0 术语（先把话说死）

- **declared（声明尺寸）**：`cardFormOf(frontmatter, filename).w/h`，来自 `CARD_FORMS`（`forms.ts:64-96`）。`world.ts:82-88` 的 `cardSize()` 产出的就是它；**kind 名**（`cardKindOf`）与它同时进入 hash（§2.1）。
- **stored（列值）**：`cards.width/height`。**本批次后它等于真实占位尺寸**（初值 = declared，被实测回写覆盖）。
- **declaredVersion**：`cardFormVersionOf(kind, declared.w, declared.h)`。
- **rowVersion**：`cards.metadata.formVersion`（解析后）。
- **实测标记**：`cards.metadata.measuredAt` 非空 ⇒ 该行 w/h 是回写的实测值。
- **seatW/seatH**：`cards.metadata.seatW`/`seatH`（解析后）＝该行**上次排座时实际使用**的 w/h，即排座那一刻写进 `width`/`height` 列的值。**每一次 SEAT 与 `width`/`height` 一起写**；`writeFootprints` **绝不改它们**（契约 §5.2）。`row.h !== seatH` 就是「这行被重测过、真实占位变了」的唯一信号。

### 3.1 `reseatLayer(layerId, files)` 的漂移判定（重写，核心）

输入约定（**MUST，见 §11 冲突 1**）：`files[].w/h` 必须是**该文件当前 kind 的 declared 尺寸**，不是行值；`files[].kind` 是**当前 kind 名**（两者共同算出 `declaredVersion`）。今天 `routes/world.ts:329` 传的 `cardSize(it)` 满足尺寸部分，**需在 02 的 `declaredSizeOf` 里补 `kind`**（见 §11 冲突 1）。**此约定 MUST 保持**，因为 `declaredVersion` 必须由 declared 算出（`reseatLayer` 因此仍是 O(n) 无文件 IO）。

逐步行为（**五个漂移源，按顺序短路**；契约 §5.1）：

| # | 条件 | 动作（用哪个尺寸） | 漏了会怎样 |
|---|---|---|---|
| 1 | `files.length === 0` | return `[]` | 空层也走一遍螺旋，白烧 CPU（保留今天行为，`local-store.ts:596`） |
| 2 | **行缺失**（`byId` 无此 path） | **SEAT**，用 **declared**：插入 `(id, layer, x, y, width=declared.w, height=declared.h, z, metadata={formVersion: dv, seatW: declared.w, seatH: declared.h})` | 新卡无行 → `enriched` 落回 `SEAT_ANCHOR`（`world.ts:340`），多张新卡叠在锚点 |
| 3 | **`row.w <= 0 \|\| row.h <= 0`** | **SEAT**，用 **declared**（覆盖脏列值，同样写 `seatW`/`seatH`=declared） | 脏行永远参与碰撞且 `overlapsOccupied` 判它不占位（负值/NaN 都判否），别的卡压上去 |
| 4 | **`row.measuredAt` 非空 且 (`row.h !== row.seatH \|\| row.w !== row.seatW`)**（含 `seatH`/`seatW` 缺失＝视为不等） | **SEAT，用行值 `row.w/h`**：按实测占位重排；写回时 `width/height = row.w/h`，`metadata = {formVersion: dv, measuredAt: 旧值保留, seatW: row.w, seatH: row.h}` | ⚠️ **本批次的灵魂**：这是**唯一**能让「卡长高了 → 座位让开」发生的路径。`seatUnplaced` 只给无行的卡排座（`local-store.ts:525-528`），实测回写绝不写 x/y（契约 §8.6）——没有这条，列高变 578 而座位仍是按 190 算的，**永久重叠，F1 目标不达成** |
| 5 | **`rowVersion` 存在 且 `!== declaredVersion`** | **SEAT，用 declared**（`reseatLayer` 的原始正当用途，`local-store.ts:587-593`）；并**清空 `measuredAt`**（旧实测值按旧宽折的行，已失效，等下次测量重写）、写 `seatW`/`seatH`=declared | kind 在代码里被改尺寸后旧座位重叠；且若不清 `measuredAt`，第 5 条写回的 declared 会在下一次被第 4 条当成「实测占位已变」→ 反复重排（链路自锁） |
| 6 | **`rowVersion === declaredVersion`** | **不动**（no-op） | 稳态每张 chalk 每次 `/api/layer` 都被判漂移冲回 declared（**这就是今天的 bug**，实测 A4） |
| 7 | **legacy**（**无 `formVersion` 且无 `measuredAt`**）且 `row.w !== declared.w \|\| row.h !== declared.h` | **SEAT**，用 declared（一次性迁移：老数据的列值对应已变形的 kind） | 老世界升级后 kind 尺寸早已变，卡面重叠且永不修正 |
| 8 | **legacy** 且 `row.w === declared.w && row.h === declared.h` | **BACKFILL**：只 `UPDATE metadata = {formVersion: dv, seatW: row.w, seatH: row.h}`（x/y/w/h 全不动） | 老行永远停留 legacy，每次 `/api/layer` 重走判定；且下一条尺寸改动永远追不上它 |
| 9 | 兜底（`measuredAt` 非空、`seatH/seatW` 与行值相等、但 `rowVersion` 缺失） | **不动**（竞态保护，见下） | 03 的 `writeFootprints` 可能先落 `measuredAt`、后才有 `formVersion`；若把它当 legacy 走第 7 条，会**按行值重排并冲掉刚测到的高度** |

> **编号对照（本文九行表 ↔ 契约 §5.1 五源）**：本文按「先短路」的机器顺序编号（表头行占 1），契约按漂移源编号。对应关系：本文第 2 行 = 契约源①（行缺失）、第 3 行 = 源②（`w/h<=0`）、**第 4 行 = 契约源③（`measuredAt` 非空 且 `row.h !== seatH` → 用行值）**、**第 5 行 = 契约源④（`rowVersion` 存在且失配 → 用 declared + 清 `measuredAt`）**、第 7/8 行 = 源⑤（legacy 两子分支）。契约 §10.1/§5.2 说的「第 3 条」即本文第 4 行，「第 4 条」即本文第 5 行——**语义一致，只是编号错位**。

**第 4 行与第 5 行为什么必须 SPLIT（契约 §5.1「第 3 条 / 第 4 条」）**：

- **本文第 4 行 / 契约第 3 条（实测变化）用行值 `row.w/h`**——那才是这张卡**当下**的真实占位；重排后必须把 `seatW`/`seatH` 更新为行值，否则「实测变了」的信号不会消失，下一次请求又重排。**这是 F1 的唯一实现路径**。
- **本文第 5 行 / 契约第 4 条（kind 改尺寸）用 declared `form.w/h`**——实测值是按**旧宽**折的行，宽变了即失效；同时**清空 `measuredAt`**，让下一次测量重写。**为什么不能只补版本号**：`reseatLayer` 的原始正当用途就是「kind 在代码里改尺寸后旧座位会重叠」（`local-store.ts:587-593` 注释）；若实测行永不重排，则**每张被测量过的卡**（也就是所有卡）都逃过这次重排——该能力被静默移除（MAJOR-2）。
- **与 I2 的关系**：I2 守「**同版本**下实测值不被 declared 冲掉」；第 5 行处理「**跨版本**（kind 真被改尺寸）」，两者不冲突。

**为什么第 5 行的判据是「`rowVersion` 存在且失配」而非「`!== declaredVersion`」**：`rowVersion` **缺失不算失配**（契约 §5.1 第 4 条）。`writeFootprints` 刚落 `measuredAt` 但该层还没写过 `formVersion` 的行，若按「不等即失配」判，会被误判重排、冲掉刚测到的高度；这就是第 9 行兜底存在的理由。用「实测标记」`measuredAt` 而不是 `formVersion` 认「实测行」的同一条竞态推理，见下。

**为什么 legacy 判定要求「无 `formVersion` **且** 无 `measuredAt`」**：`metadata` 缺失、或只有 `measuredAt`（竞态行），都不是「从未升级过的老行」。只有两键都无才是第 7/8 行意义上的 legacy；只缺 `formVersion` 的行走第 9 行（不动），只缺 `measuredAt` 的行走第 5/6 行（按版本号判定）。

**为什么第 8 行不重排（对契约 §5.2 的定向收紧，见 §11 冲突 2）**：legacy 行存的**只可能是 declared 值**（本批次之前从未写过实测值）。`row.w/h === declared.w/h` 等价于「这个 kind 的尺寸从未变过」——重排只会把玩家拖过的 x/y 重置成螺旋位，零收益、纯损失。契约 §5.2「走一次重排后补 `formVersion`」的意图是「kind 定义可能已变」，而「变没变」有比无脑重排更便宜也更准的判据：列值 vs 声明值。

**重排的几何部分完全沿用今天**：`occupied` = 未漂移的兄弟（按**行值**算中心，`local-store.ts:610-617`）；螺旋 `spiralCells()` + `SEAT_STEP` + `overlapsOccupied()`（含 `SEAT_PAD`）；失败回落**最后一个候选格而非锚点**（`local-store.ts:623-633`，`seatUnplaced` 的逐字理由见 `:558-560`）。这部分**一行不改**；变的只有「谁会进 `seated`、用的是哪个 w/h」。

### 3.2 `writeFootprints(layerId, boxes)`（NEW，03 的入口）

1. **行匹配用 `id = path` ONLY，不匹配 `layer`**（契约 §3.3，BLOCKER-2 裁决）。理由：嵌套层的 README（如 `world/baker-street/README.md`）的 `cards.layer = 'world/baker-street'`，但它同时出现在 `map` 层的门牌列表里（契约 §2.2 的「跨层门牌」正是 A4 实测的第二类；`world.ts:290-303` 合成门牌 path）。若按 `layer = layerId` 匹配，`map` 层页发的 footprint 会全部跳过这张卡。*漏了（按 layer 匹配）会怎样*：地图层测到的门牌高度永不入库，03 每次 POST 都收到 `updated:0` 却不知是跳过——静默错误。**`layerId` 参数因此只服务路由层的 `resolveLayer` 校验（契约 §3.3：`resolveLayer` 是层校验器，入参 relPath，`local-store.ts:489`），不参与行匹配。**
2. `boxes.length === 0` → return `{ updated: 0, unchanged: 0 }`。
3. 单事务：`BEGIN IMMEDIATE` … `COMMIT`，异常 `ROLLBACK` 后 rethrow（照抄 `placeCards:717-728` 体例）。*漏了事务*：半层实测值入库、半层没入，前端下次拉到「一半新一半旧」的碰撞盒。
4. 逐 box：`SELECT width, height, metadata FROM cards WHERE id = ?`。
   - 无行 / 该 path 不属于本层 → **跳过**，`console.warn('[footprint] no row for "<path>" on layer "<layerId>"; skipped')`，计入 `unchanged`（契约 §3.3 BLOCKER-1：**HTTP 200，不是 404、不整批不做**；§7 不许静默）。*漏了（改报 404 / 整批失败）会怎样*：跨层门牌这类「非本层行」在批量里是**正常情形**，把正常的跳过报成错误会让 03 的调用方误以为整层失败。
   - `w`/`h` 非有限正数 → 同样跳过 + warn，计入 `unchanged`（路由层另做 400 `invalid_argument` 双保险）。
   - 行存在且 `row.width === w && row.height === h` → `unchanged += 1`，**不写 DB**（幂等）。
   - 否则 → `UPDATE cards SET width = ?, height = ?, metadata = ? WHERE id = ?`，`metadata = { formVersion: 原值 **保留**（可能缺失）, measuredAt: <now ISO>, seatW: 原值 **保留**, seatH: 原值 **保留** }`；`updated += 1`。
5. **只写 `width`/`height`/`measuredAt`**：`formVersion`/`seatW`/`seatH` **一律读-改-写合并保留**（契约 §5.2 / §8 反模式 9）。*漏了会怎样*：`seatH` 一旦被这里顺手写成新的实测高，「实测占位已变」的信号就永远不会出现（表第 4 行不再命中），**F1 的核心目标（卡长高 → 座位让开）消失**；`formVersion` 被清则会触发一次多余的全层重排。
6. **绝不写 x/y/z**（契约 §8.6）；**绝不写 `layer`**（嵌套 README 归自己的层）。*漏了会怎样*：玩家/作家的摆位被测量路径顺手改掉，比本 bug 更严重的静默篡改。

### 3.3 `seatUnplaced` / `seatNear` 的尺寸口径（每次 SEAT 与 `seatW`/`seatH` 一起写）

- 二者写入**初值**：`file.w/h` 若为正用传入值，否则回落 `280/180`（`local-store.ts:547-548`、`:899-900`，**保留**）。今天的调用方 `world.ts:318` 传 `cardSize(it)` = declared，所以初值 = declared，与契约 §3.1「初值仍是 form.w/h」逐字一致。**02 改喂 `storedSizeOf` 后，初值改为 `row.w/h ?? form.w/h`**（首次无行仍落 declared，契约 §3.4）。
- **SEAT 时 MUST 同时写 `seatW`/`seatH`**（契约 §5.2：「该行上次排座时实际使用」的 w/h，即此刻写进 `width`/`height` 的那个值）。三处 SEAT 写点——`seatUnplaced:575`（INSERT）、`reseatLayer`（UPDATE，§3.1）、`seatNear:939`（UPSERT）——**都要写**：`metadata = { ...原 meta, seatW: <写入的 w>, seatH: <写入的 h> }`，`formVersion` 若有则一并写。*漏了会怎样*：新排的行 `seatH` 为空，表第 4 行的比较恒不等（把「缺失视为不等」），下一次请求会**无谓重排一次**；虽然收敛，但违背了「缺 `seatH` = 该行尚未有过 SEAT 基准」的语义。
- `seatUnplaced` **仍不写 `formVersion`**（它拿不到 kind——`SeatFile` 的 `kind` 今天为空、`world.ts` 的 `cardSize` 也还没带）。新行以 `metadata = {seatW, seatH}` 落地，**同一次 `/api/layer` 里紧随其后的 `reseatLayer`（`world.ts:327`）会走表第 8 行给它 BACKFILL `formVersion`**（新行 `row.w === declared.w` 恒成立；注意表第 8 行的 legacy 判据是「无 `formVersion` 且无 `measuredAt`」，`{seatW,seatH}` 落地不破坏它）。*漏了（不加这次 backfill）会怎样*：新行永远无版本号，每次请求重走判定；但**不会**重排（表第 8/9 行兜住），所以是性能而非正确性问题。
- `seatNear`：`SeatFile` 可带 `kind`/`formVersion`（§2.1），带了就写 `formVersion`，不带就等下一次 `/api/layer` 的 backfill。行为一致。
- `seatPresence`（`local-store.ts:1001-1049`，`:1005` 读 `CARD_FORMS.sprite`）：**本批次不动**——presence 是点不是卡（`world-store.ts:30-33`），无内容撑高，声明值即真值。契约 §3.4 表也未列它。

### 3.4 「实测值驱动重排」与「I2」的端到端路径

**路径 A（实测变高 → 座位让开；第 4 条命中，F1 目标）**：

```text
POST /api/card/footprint {layer, boxes:[{path:"world/baker-street/evening.md", w:460, h:578}]}
  → writeFootprints → cards: width=460 height=578 metadata={seatH:190(旧), seatW:460, measuredAt:"…"}
                      —— seatH/seatW 是上次 SEAT 写的 190/460，这里**原样保留**
下一次 GET /api/layer?layer=world/baker-street
  → reseatLayer(files=[{path, kind:"chalk", w:460, h:190(declared)}, ...])
  → row.measuredAt 非空 ✓ 且 row.h(578) !== row.seatH(190) ✓ → 第 4 条 → **用行值 460×578 重排**，
    并写 seatH=578（信号消失，下一次不再重排）✓
```

**路径 B（同版本、实测值稳定 → 不被冲掉；第 6/第 4 条不命中，I2）**：

```text
紧接路径 A 的第二次请求（row.h 已 578 且 row.seatH 已 578）
  → reseatLayer(...)
  → measuredAt 非空，但 row.h === row.seatH → 第 4 条不命中
  → rowVersion === declaredVersion → 第 6 条 → **no-op** → 列值仍 460×578 ✓（这是 I2 的本体）
```

**⚠️ 关键区分**：I2 禁止的是「用 declared **冲掉**实测列值」——路径 B 证明它没发生。它**不**禁止路径 A 的重排（x/y 允许变）：实测占位变大时座位**必须**让开（契约 §3.2 I2 注）。**这是 §10 单测要钉死的两个行为。**

## 7. 错误边界（含「不静默降级」）

| 情形 | 行为 | 为什么不能静默 |
|---|---|---|
| `writeFootprints` 的 path 在 `cards` 无行 | 跳过 + `console.warn('[footprint] no row for "<path>" …; skipped')`，计入 `unchanged` | 若静默，前端测了却不入库，服务端排座永远用旧值；服务端日志是唯一可见面（契约 §3.3 失败语义「MUST NOT 静默」） |
| `writeFootprints` 的 `w`/`h` 非有限正数 | 跳过 + warn；路由层另做 400 `invalid_argument`（03 负责） | 写进 `NaN`/负值会污染 `overlapsOccupied`（负值、NaN 都判不重叠），无声错误 |
| `metadata` 是损坏 JSON | `parseCardMetadata` 返回 `{}` → 视作 legacy（无 `formVersion` 且无 `measuredAt`，第 7/8 条） | **不抛**：一行脏 metadata 不能炸掉整个 `/api/layer`。代价 = 该行按 legacy 走一次判定（可能重排），可接受的保守行为 |
| `reseatLayer` 收到的 `SeatFile` 缺 `w/h`（`declaredOf` 返回 null），或缺 `kind`/`formVersion`（`declaredVersionOf` 返回 null） | 跳过该 path（不重排、不回填） | 没有 declared 就算不出 `declaredVersion`；**猜一个值重排 = 用错误尺寸覆盖真值**。宁可不动 |
| 螺旋 600 候选耗尽 | 沿用今天：落到最后尝试的格子 + `console.warn('[seat] no free cell …')`（`local-store.ts:568-572`） | 已有既定语义，不改 |
| 事务中途失败 | `ROLLBACK` 后 rethrow（`writeFootprints`） | 静默吞异常会让前端拿到半更新的层 |

**不引入新异常类型**：`writeFootprints` 的输入非法由路由层用 `ActionError('invalid_argument')` 挡（03）；store 层只跳过 + warn（store 不负责 HTTP 语义）。

### 9.1 `arrange` 不能改尺寸、实测可以回写 —— 这条刻意不对称的论证（契约 §5.3）

1. **手改尺寸 = 第二套真相；实测尺寸 = 唯一的绘制真相**。`AGENTS §7.5` 第 2 条把「可见框 = 声明框」定为契约，但把「高度」从声明框摘出去（内容撑高）。手改 `w/h` 会让「作家写的数」与「DOM 的画」竞争同一个语义槽——下一帧就该被推翻，所以 `actions/canvas.ts:385-390` 选择**响亮拒绝**而不是「接收后悄悄撤销」（`docs/tools/09 §11 冲突 1` 原话：不是没做，是做了也会被下一帧撤销）。
2. **实测没有第二套真相可言**：`offsetHeight` 就是那张纸当前的高度，没有「另一份更真的高度」供它冲突。`cards.width/height` 升格后它**就是**碰撞唯一真相（契约 I1）。
3. **方向单调**：`arrange` 改尺寸是「人类意图 → 世界」（可能撒谎），实测回写是「渲染事实 → 世界」（不可能撒谎）。系统只信任后者。

**因此 `placeCard`/`applyPlaceCard` 继续不写 w/h（`local-store.ts:741-770`），而 `writeFootprints` 写——二者不是同一个「写尺寸」动作，是「意图」与「事实」的区别。** 这条不对称必须写进实现者注释，否则未来会有人「顺手给 arrange 开个后门」。

### 10.1 I2 独立单测（契约 §10.1 第 3 条，本文 owner，必写）

契约 §10.1 第 3 条明确「第一次 reseat 允许改 x/y（那是座位让开），第二次必须 no-op」，所以本测试分两段断言，**MUST NOT 断言第一次 reseat 后 x/y 不变**（那会与契约 §10.1 第 2 条直接矛盾）。

```js
test('01 §5.1(a): measured drift re-seats once, then is stable (I2 + seatH chain)', async () => {
  const { store, root } = await tempStore();
  try {
    // declared: chalk = 460x190（forms.ts:66）
    await store.seatUnplaced('world/inn', [{ path: 'world/inn/a.md', w: 460, h: 190 }]);
    // 首次 /api/layer 的迁移路径：declared 随 files 传入（kind 供 hash）
    await store.reseatLayer('world/inn', [{ path: 'world/inn/a.md', kind: 'chalk', w: 460, h: 190 }]);
    const seated = store.getLayerCards(['world/inn/a.md'])[0];
    assert.equal(seated.seatH, 190, 'SEAT baseline recorded (contract §5.2)');
    assert.ok(seated.formVersion, 'legacy row backfilled with formVersion (第 8 条)');

    // 前端实测回写：列高 578，seatH/seatW 保持不变（契约 §5.2 / §8 反模式 9）
    await store.writeFootprints('world/inn', [{ path: 'world/inn/a.md', w: 460, h: 578 }]);
    const measured = store.getLayerCards(['world/inn/a.md'])[0];
    assert.equal(measured.h, 578);
    assert.equal(measured.seatH, 190, 'seatH is NOT touched by writeFootprints');
    assert.ok(measured.measuredAt, 'measuredAt marker is written');

    // 第一次 reseat：第 4 条命中（row.h 578 !== seatH 190）→ 按【行值】重排（座位让开）
```
