## 1. 一句话定位

**定义前端"一张卡的真实占位"是什么**——`CanvasObject` 外壳的 `offsetHeight`（未旋转、未被相机缩放的布局盒）——并逐 kind 给出「契约声明 `h` vs 实测绘制高」的真实对照，回答"测什么元素 / 用什么 API / 什么时机"三问，供 03（回传通道）与 05（验收）直接消费。

## 2. 签名 / 参数 / 接口

本模块新增一个纯前端工具模块（字体就绪判定，04 owner），**对外口径是 `whenFontsSettled`**。DOM 批测本身归 03（`useWorld`），本文只冻结其口径。

### 2.1 新符号（04 拥有）

```ts
// NEW apps/web/src/lib/fonts.ts
/**
 * Resolve when web fonts are usable for layout. Never rejects: a font-load
 * failure must not block measurement (the fallback metrics are still measurable).
 */
export function whenFontsReady(): Promise<void>;

// NEW apps/web/src/lib/fonts.ts
/**
 * `whenFontsReady()` + one animation frame. Returns 'ready' on the happy path,
 * 'timeout' when the budget elapses first (never throws, never hangs).
 * The extra frame matters: `document.fonts.ready` can resolve in the same task
 * that triggers the reflow, so a synchronous `offsetHeight` read a microtask
 * later may still see pre-layout geometry.
 */
export function whenFontsSettled(timeoutMs = 1500): Promise<'ready' | 'timeout'>;
```

已与 03（`FootprintChannel`）在 IRC 上确认：**由 04 导出，03 await 之**（03 把它当黑盒）。实现要点：`document.fonts?.ready ?? Promise.resolve()`，整体 `try/catch`，`timeoutMs` 用 `Promise.race` 兜底。
**对外口径 = `whenFontsSettled`（契约 §3.5 冻结，2026-09-12）**：`whenFontsReady` 只是它的**内部步骤**，03 MUST await `whenFontsSettled`，MUST NOT 只 await `whenFontsReady`。`apps/web/src/lib/fonts.ts` 是 NEW 文件，**两个符号都从此文件导出**，签名如上（`whenFontsReady(): Promise<void>`；`whenFontsSettled(timeoutMs = 1500): Promise<'ready' | 'timeout'>`）。

### 2.2 测量口径（冻结，03 执行，04 定义）

| 问题 | 答案 |
|---|---|
| **测什么元素** | `CanvasObject` 根节点，即 `.object[data-path]`（`CanvasObject.tsx:121-141`）。**不是**内层卡（`.chalk--bare`/`.gate`/…），也不是 `.object` 的任何子节点。 |
| **用什么 API** | `el.offsetHeight` / `el.offsetWidth`（`measure.ts:66-67` 同源口径）。**禁止** `getBoundingClientRect().height`（被相机 zoom 缩放，见 §3.1）。 |
| **什么时机** | `items` 已提交渲染 **之后**、`await whenFontsSettled()` **之后**、且**不在 hover/展开态**（见 §7 边界）。层切换 / `ResizeObserver` 触发后按 200ms 尾防抖重测（03 owner）。 |
| **产出形状** | `{ path, w, h }` 逐卡；`w` 恒等于 `item.w`（§4 已证），**只为列自洽随 `h` 一起刷新，不是独立测量结果**（契约 §9 第 3 条已裁定，2026-09-12 更新）。 |

### 2.3 期望的 DOM 不变量（本模块负责维持）

- `.object` 外壳**只写 `width`，不写 `height`**（`CanvasObject.tsx:131`，逐字注释 `:132-133`）——保证 `offsetHeight` = 内容撑开的真实盒。
- 旋转只作用在外壳的 `--target-rot`（`:137-138`），且 **chalk / sprite 恒为 `0deg`**；`offsetHeight` 是 `transform` 之前的布局盒，与旋转无关（`collide.ts:7` 契约）。

## 3. 行为契约逐步

### 3.1 步骤 1 — 为什么是 `offsetHeight`，为什么不是 `getBoundingClientRect`

**实测（`world/baker-street/evening.md`，相机 scale=0.95）**：

| API | 值 | 含义 |
|---|---|---|
| `el.offsetHeight` | **578** | 未旋转、未缩放的布局盒（世界坐标 px） |
| `el.getBoundingClientRect().height` | **548.8** | 578 × 0.95（相机缩放）→ 世界坐标错 |
| `el.offsetWidth` / `rect.width` | 460 / 437 | 同上，宽度也被缩放 |

`getBoundingClientRect` 还会叠加 `rotate(-x deg)` 的旋转外接盒（gate/note/letter 外壳带手绘倾斜），使同一张卡在相机不同 zoom 下量出不同高——**不能作占位高**（契约 §8 反模式 7）。`offsetHeight` 是 layout px，与相机无关，与 `collide.ts` 的"未旋转盒"契约一致。

**漏了会怎样**：若用 `rect.height`，同一张卡在高倍缩放下量到的值偏小、低倍偏大；回传后服务端排座按缩放后的假值排，重新渲染又撞——**bug 从"两侧尺寸口径不一致"变成"每次缩放都换一个错值"**，更难查。

### 3.2 步骤 2 — 测"外壳"而非"内层卡"

外壳无 padding/border（`index.css:116-122` 只有 `position/transform`），内层卡（`.note`/`.gate` 等）`width:100%` 填满外壳，其盒高即为外壳内容高。因此 `shell.offsetHeight === inner.offsetHeight`（实测：raindrops `.object` 107 == `.note` 107；gate `.object` 277 == `.gate` 277）。测外壳是唯一与"占位 = 外壳盒"语义对齐的选择，也天然覆盖内层卡尚无固定高度的情形。

**漏了会怎样**：测内层卡会漏掉未来可能加在外壳上的 padding/margin；测 `.whitespace-pre-wrap` 之类的正文节点会漏掉 chalk 的 frontmatter 部件（§3.4，实测占 chalk 总高的 ~50%）。

### 3.3 步骤 3 — 字体就绪后才测

**实测（cache-busted `@font-face` 探针，同一段拉丁文本，460px 宽 chalk）**：

| 状态 | 行数 | 高度 |
|---|---|---|
| 字体未加载（fallback：serif） | **11 行** | **355px** |
| `await document.fonts.load('600 19px CaveatProbe')` 之后 | **9 行** | **291px** |

**字体加载让同一段文字少折 2 行、矮 64px（−18%）。** 若在字体就绪前测量，回传的高会系统性偏大（此处 chalk 偏 +22%）。故 03 MUST `await whenFontsSettled()` 再测（契约 §3.5）。

**反向核实**：`document.fonts.status === 'loaded'`，`document.fonts.check("600 19px Caveat") === true`。**但 `LXGW WenKai` 实际未加载**——`apps/web/index.html:10` 向 Google Fonts 请求的 4 个族里根本没有 LXGW（实测：返回 CSS 只含 Caveat / DM Mono / Manrope 共 34 个 `@font-face`，`--kai` 的字符宽与 `serif` 逐字节相等：27.4375px）。即今天的 CJK "楷体"其实是 serif 回退。**这不改变"必须等字体"的结论**（Caveat 那条路已实测会变），但说明契约 §3.5 举例的 Caveat 是对的、`--kai` 的实际字体是回退（见 §11 冲突 C4）。

**漏了会怎样**：字体就绪前测量并回传，chalk 类卡的高度静默偏大约 20%，服务端按偏大的值排座 → 卡间距虚大；字体加载完成后本地实测变小，但服务端列还是旧的大值，直到下一次收敛——期间"排座不重叠"断言虽能过，但布局与实际观感不符。

### 3.4 步骤 4 — chalk 的高度 = 正文 + frontmatter 部件

**实测（`evening.md` 外壳 578px 拆解）**：

| 子块 | 来源 | 高 |
|---|---|---|
| `.whitespace-pre-wrap`（正文） | `ChalkCard.tsx:55` | **291** |
| 状态折叠头（World State Snapshot） | `fm.tsx:93-120` | 29 |
| 骰子卡 | `fm.tsx:122-132` | 94 |
| 选项组 | `fm.tsx:134-163` | 116 |
| 三个 `mt-4`(16px) 外边距 | `fm.tsx:95,110,135` | 48 |
| **合计** | | **578** |

**契约 §2.4 把 chalk 超声明值全归因于 `pre-wrap` 正文——只对一半。** 本例正文 291，部件 287，**部件占超声明值（578−190=388）的 74%**。故"真实占位"必须包含 frontmatter 部件（`renderFrontmatterWidgets`，`fm.tsx:23`），不能只量正文。同一 card 的 `late-night.md` 同理：正文 194 + 部件 287 = 481。

**漏了会怎样**：若实现者误以为只需量正文（或把部件当"浮层不计入"），chalk 的占位会系统性漏掉最多 287px；`evening∩late-night` 的竖向重叠（契约 §2.3）会被低估近一半。

### 3.5 步骤 5 — `w` 不需要实测（实测裁定，非推断）

在 5 档声明宽（460 / 300 / 200 / 176 / 120 / 80px）注入对照：`.object` 的 `offsetWidth` **逐档严格等于声明值，零溢出**（80px 极窄下 chalk/note 的 `scrollWidth === offsetWidth`）。三个真实 kind（chalk 460 / gate 288 / note 200）实测宽与声明宽逐卡相等。

**结论**：`w` 由外壳内联 `style.width`（`CanvasObject.tsx:131`）+ 内层各家 `width:100%`（`index.css:892,1033,1076`）决定，是确定值；`overflow-wrap:anywhere`（`index.css:828`）只折文字、撑不开确定宽的外壳。**回传的 `w` 只是随 `h` 刷新以保持列自洽，不是独立测量结果**（契约 §9 第 3 条 2026-09-12 更新）。

**边界（真实缺陷，非本批次修）**：非 chalk 的 kind（`.note` / `.gate__desc` / `.letter__preview` / `.sprite__name`）的 `overflow-wrap` 是 `normal`，遇不可断长 token（URL/slug）时**墨迹会画到盒外**——实测 note 容器 `offsetWidth=200` 不变，但文字墨迹右边界达 `+867px`（超出外壳右缘 867px）。这是 `overflow: visible` 的绘制溢出，**不改变布局盒**，故 `offsetWidth` 仍是正确的占位宽、`w` 仍不需实测；但它是独立的视觉缺陷，记入 §11/§12。

## 6. WS / 前端反应

- **04 不直接订阅 WS**。测量由 03 的 `useWorld` 调度：`/api/layer`（或 WS 触发 `refresh()`）→ 渲染 → `await whenFontsSettled()` → 测 → POST。层切换/卡集合变化时 03 调 `invalidateMeasures()`（`measure.ts:33`）后再测。
- **前端碰撞仍读本地实测**（契约 §5.4）：`Canvas.tsx:291-299` 的拖拽软碰撞经 `elementBox()`（`measure.ts:44`）读 `offsetHeight`；关系线 `LinkLayer.tsx:127-129` 同源。回写只影响服务端持久值，**不改变本地碰撞**——两条轨各自独立，下一次 POST 收敛。
- **04 的增量**：把 `document.fonts.ready` 从"隐式相信浏览器已加载"变成 03 可 await 的显式门（`whenFontsSettled`），并让测量避开 hover 展开态（§7）。

## 7. 错误边界（不静默降级）

1. **字体就绪超时**：`whenFontsSettled(1500)` 超时返回 `'timeout'`，03 **仍继续测量**（用 fallback 度量），但 MUST 在 `console.warn` / details 留痕——**不静默**。理由：字体加载失败不该让卡完全不可测量；但偏大的值是已知风险，必须可见。
2. **`.object` 不可见/`display:none`**：`offsetHeight === 0`。03 MUST 跳过 `h === 0` 的卡，**不发该盒**（否则会把 0 写进列，比不写更糟）。**不静默**：跳过要在 details 里计数。
3. **hover 展开态污染（本模块实测发现，已入契约 §3.5）**：chalk 的状态折叠头是**流内**元素，`pointerover` 命中时展开 → `offsetHeight` 实测 **578 → 664（+86px）**（`.gate__detail` 是 `position:absolute`，不改变 gate 布局盒，实测 277 不变）。若恰在 hover 中测量，回传值偏大 86px。**契约 §3.5 已冻结"测量时 MUST NOT 在被 hover 放大的卡上取样"（2026-09-12）**；**闸门实现归 03**（`FootprintChannel`/`useWorld`）：测量前把 `document.activeElement`/hover 归零不可靠，改为**只在层渲染后、用户未交互的窗口内测**，或对 hover 造成的 `ResizeObserver` 触发做**忽略**（非用户尺寸事件）。此条导入 03 的防抖实现。
4. **不存在 `getBoundingClientRect` 回退**：04 MUST NOT 提供"rect 兜底"，因为它在相机缩放下是错的（§3.1）。宁可跳过，不给错值。

| sprite | 176×196 | 合成，长名（2 行） | 176×**176** | 0.90× | 小于 |
| sprite | 176×196 | 合成，超长名（3 行，`max-width:140` 封顶） | 176×**195** | 0.99× | ≈声明值，**有界** |
| 其余 18 component kind | 各有声明 h | 今天无独立渲染，落到 `.note` 分支 | = note 的绘制高 | — | 声明 h 与绘制无关（见下） |

**三条可执行结论**：

1. **必须回传的只有 chalk / note**（高度随内容大幅漂移，且两个方向都漂）。gate 恒偏（+8%~15%），也建议回传以纠偏。
2. **letter / sprite 有界**：letter 由 3 行 clamp 封顶（≤152 < 176），sprite 由 `sprite__name` 的 `max-width:140`+换行封顶（≤195 ≈ 196）。二者**可回传亦可不回传**——回传无损，不回传的误差分别 ≤65px / ≤59px。
3. **其余 18 component kind 今天渲染成 `note`**（`CardRenderer.tsx` 无对应分支）。它们的声明 w/h 对渲染无意义；在实现 component 渲染前，回传值 = note 的实测高。**这是契约未预见的口径空洞，记入 §11 冲突 C6。**

**关于 `seatH` 的语境（契约 §5.2/§5.1 第 3 条）**：上表的"实测绘制高"回写后**会影响排座**——它写进 `cards.height`，而 `reseatLayer` 用它与该行 `metadata.seatH`（上次排座时用的高）比较；只要实测高变了，漂移信号即命中，座位**必须让开**（这正是 F1 的目标，不是违例）。故上表每个"远超"行（chalk 578、note 447…）都是"该卡下一次 SEAT 会按这个高重排"的预兆。

## 10. 验收测试（可机械核验）

### 10.1 三问的可执行答案（本模块交付的核心口径）

| 问 | 答 |
|---|---|
| **测什么元素** | `.object[data-path="<path>"]`（`CanvasObject.tsx:121`）；即"外壳，非内层卡、非正文节点" |
| **用什么 API** | `el.offsetHeight` / `el.offsetWidth`（**MUST NOT** `getBoundingClientRect`） |
| **什么时机** | `items` 渲染后 ∧ `await whenFontsSettled()` 后 ∧ 非 hover/展开态；层切换/`ResizeObserver` 后 200ms 尾防抖重测 |

### 10.2 机械断言（04 提供 fixture 与预期值，05 落测试）

1. **【骨架一致性】** 对任一渲染出的卡：`shell.offsetHeight === shell.firstElementChild.offsetHeight`（外壳无 padding/border）。今天成立（raindrops 107==107，gate 277==277）。**防的是**有人给 `.object` 加 padding 而忘记同步口径。
2. **【相机无关性】** 同一卡在 camera scale ∈ {0.5, 1, 2} 下 `offsetHeight` 恒等；而 `getBoundingClientRect().height` 随 scale 变化。**防的是**实现者改用 rect。
3. **【字体就绪差】** cache-busted `@font-face` 注入后：字体加载前测得高度 ≠ 加载后（实测 355 → 291）。断言"测量函数在 `whenFontsSettled()` 之前被调用时，其结果与之后就绪态不一致"——即**证明门是必需的**。
4. **【hover 污染】** 对含状态部件的 chalk：hover 前 578、`pointerover` 状态头后 664。断言"测量函数不得在展开态取值"（03 的忽略逻辑守此）。
5. **【逐 kind 声明/实测对照】** 用 §9.1 的表作 fixture 基线：注入 5 类合成卡，断言 `offsetHeight` 落在表中区间（chalk≥32 且随内容变、letter≤152、sprite≤195、gate≥258、note 可变）。**防的是** CSS 改动悄悄把某 kind 拉回"声明值附近"。
6. **【`w` 恒等声明】** 对 5 档宽度（460/300/200/176/80）断言 `offsetWidth === 声明值`、`scrollWidth === offsetWidth`（chalk），且 note 的 `offsetWidth` 不因不可断 token 变化（实测 200 恒定）。**防的是**给 `w` 做无意义的实测回传。

> 注：§10.2 全部是**前端 DOM 断言**（jsdom 不跑真实 layout，MUST 用真实浏览器/headless 跑，如仓库既有的 chrome-smoke 通路）。服务端侧的"排座不重叠 / 两侧 diff / I2"由 05 与 01 负责，本文件不重复。
