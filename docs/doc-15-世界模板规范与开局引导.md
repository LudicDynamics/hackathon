## 背景与现状（已定案，不重谈）

- **模板 = 预写骨架**（doc-05 §0）：世界设定/关键事件/结局条件预写，剧情细节/支线/NPC 反应由作家现编；
- 世界 = 一个目录 + world.json manifest（doc-05 §8.4，已定案合并为单一 manifest）；
- 拷贝目录即开世界（doc-07 §3 scaffold：从模板世界拷贝出玩家世界）；
- `.airpworld.zip` 打包/分发（holmes-world READMEWORLD 已示范：`zip -r xxx.airpworld.zip .`）；
- 开放性设计原则（doc-05 §1 + holmes）：不预设全部剧情，线索串联。

## 模板体验契约（2026-09-12 定案）

模板不是题材素材包，而是一份**能完整游玩、又能继续生长的世界种子**。五个世界都必须包含：

> **黑客松交付边界**：上述是模板的长期契约，不等于本轮要把每项做成完整产品。当前每个 Mock 只需一条 6–10 分钟短闭环，并在结尾解锁 / 生成一个后续钩子；不要求完整后日谈、全分支结局或下一章内容。详见 doc-24 §0–§1。

1. **0 级导入（世界内导言层）**：完成身份、地点、事件动机三种信息职责；载体可是一至多个 Markdown / letter / component，不固定为三张纸；
2. **入口 Chalk**：玩家通过点开、展开或回应 Chalk 跨过门槛；Chalk 可以引用信物或解锁 Gate，并立即给出视听、空间和持久状态反馈；
3. **第一幕关卡链**：从明确目标走到高潮与回报节点，包含角色、物件、风险判定和可见世界变化；
4. **回报拓扑**：声明本篇采用 Punch Line 还是 Outcome Folder；前者必须直接打开新边界，后者必须声明结算组合、最终承诺动作及继续 / 下一章 / 检查点出口；
5. **生成语法**：约束新地点、角色、物件、危险升级、文风和多模态风格，保证越过预写边界后仍属于同一个世界；
6. **持久事实起点**：玩家身份、初始关系、持有物、承诺与世界状态能够被 Writer / Character Agent 继续继承。

固定入口顺序是：**0 级导入 → 入口 Chalk / 信物动作 → Gate → 1 级世界主视图 → 更深的场景或操作面**。主视图用地点、时间、关系还是其他轴组织，由世界体验决定；但任何世界都不得绕过 0 级导入直接把玩家丢进全览图。

导言应复用现有 Folder / Layer、`type: chalk` 与实体类型，不新建 `type: prologue` 或 `type: chunk`。“0 级”是体验层级名，不是新的 schema 或渲染类型。导言对应的具体目录路径、作为目录派生 Layer 时如何显示、以及如何从 launcher 进入，仍属实现待办；未定案前不得让五个世界各自发明一套目录协议。

## 边界

- 模板不写死剧情——写死的骨架（关键节点）可以被玩家和作家改写，模板只是"第一张纸"；
- 模板不做离线剧本测试工具（那是赛后 hub 的事）。
