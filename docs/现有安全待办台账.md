## 洞 2：原生 `edit` 工具可以改写已结算事实与幂等回执

### 事实（逐字核实，2026-09-14）

```ts
// packages/shared/src/actions/delete.ts:188-201
const parsed = parseFrontmatter(raw);
// `eventKindOf` is computed BEFORE the merge so an edit can never reclassify
// the entity it edits (04 §3.3 step 1).
const eventKind = eventKindOf(parsed.frontmatter, path);

let merged = parsed.frontmatter ? { ...parsed.frontmatter } : {};
if (input.frontmatter) {
  for (const [key, value] of Object.entries(input.frontmatter)) {
    if (value === null) delete merged[key];
    else merged[key] = value;            // ← 整键替换，无保留键防护
  }
}
```

→ `editEntity({ path, frontmatter: { roll_dice: {...} } })` 能**改写 `result` / `passed`**；
→ `editEntity({ path, frontmatter: { command_log: [...] } })` 能**伪造幂等回执**（C1 落地后才有 `command_log`，但**机制今天就在**）；
→ `:191-193` 的 `eventKindOf` 只在**合并前**算 `kind`，**不拦内容**。

**这是共享入口**：玩家 UI、作家 Agent、角色 Agent、扩展工具都走 `editEntity`。

### 与 C1 的关系

C1 的 `edit` **效果**（`04 §4.4` + 契约 §R.2）MUST 声明**保留键拒绝列**：`roll_dice.result`、`roll_dice.passed`、`command_log`、`command_error`、`on`。命中 → 拒绝 + 可见错误。

**但那只保护"命令通过效果层发起的 edit"**。Agent 用**原生 `edit` 工具**（`vendor/pi-rp/.../tools/edit.ts:314-350`，无扩展名/键检查）**绕过整个动作层**，拒绝列管不到它。

→ **C1 落地后，这个洞仍然活着。**

### 为什么这条比"能改 `result`"更严重

C1 的幂等机制（`05`）的 `fact` 分量依赖一条前提：**"`roll_dice.result` 一生只有一个值"**（`05:142`）。若 `result` 可被改写：

```
同 (source, hook, command) + 被改写的 result  →  不同 fact  →  不同幂等 key  →  重复结算
```

即 **C1 花整节（`05 §3.5`）堵住的"重复结算"通道，从背后被打开了**。

### 待办（建议）

- [ ] **把"保留键"提到 `WorldStore` / `editEntity` 层**，使其对所有调用者生效，而不是只在命令效果层。这需要先确定**保留键集合**（常量单一来源）。
- [ ] 决定**原生 `edit` 工具的语义**：拒绝、还是允许但落一条审计事件（后者的代价是"世界史多了噪声"）。
- [ ] 评估对既有内容的破坏面：今天有没有世界内容**合法地**改写 `roll_dice` 的其它键（如 `expect` / `type`）？——**注意区分**：改 `expect` 是合法的（那是作品的设定），改 `result` 不是（那是已发生的事实）。
- [ ] 与洞 1 同批定"内容/工具不可信输入"的统一纪律。

## 洞 3：`layer === null` 时向玩家弹"the current scene"这句假话

### 事实（逐字核实，2026-09-15；由 `Recon060910` 在 B7 复核中报出，主 agent 复核）

```ts
// apps/web/src/lib/world-event-toast.ts:118 —— 先试 detail，再退到兜底串
return last || clean || 'the current scene';

// apps/web/src/lib/world-event-toast.ts:121-122 —— layer 为空时无条件说"当前场景"
function layerLabel(event: WorldEvent): string {
  return event.layer ? basename(event.layer) : 'the current scene';
}

// apps/web/src/lib/world-event-toast.ts:216 —— toast 文案把这个值直接塞给玩家
values = { name: String(detail.name), layer: layerLabel(event) };
```

**问题**：`event.layer === null` 有**两类完全不同的来源**，而这条渲染器把二者说成同一件事：

| 来源 | `layer` | 真相 | toast 说的是 |
|---|---|---|---|
| 事件发生在**当前场景** | `null` | 就是当前场景 | 「the current scene」✅ 正确 |
| 事件发生在**世界根 / 背包 `player/` / 小天地 `characters/<id>/`** | `null` | **不在任何"场景"里** | 「the current scene」❌ **假话** |

依据：`resolveLayer` 对 `world/**` 以外的路径一律返回 `null`（`packages/shared/src/store/local-store.ts:951-964`，旧标 `:859-873`）。`docs/command/00 §10.13` 已把这条定性为 **latent（潜在）而非现行丢数据**——因为今天的世界内容还很少在 `characters/` 下产生 `entity_created` 这类事件。

### 与 C1 的关系

**这是 C1 取证时顺带发现的既有缺陷，不是 C1 引入的**（`review-pending-C2C3.md:251` 已把它列为 `[推断]` 待核项，`06:679` 段有论述但**未登记台账**——本条即补齐登记）。

C1 的 `[C-2]` 裁定「方案 A 不落账」的**主因**正是这条：若让命令失败落 `entity_created`，toast 会在 `layer === null` 时向玩家弹「the current scene」而实际不在任何场景——**向玩家说假话**。所以 C1 绕开了它，但**绕开不等于修好**：既有通路依然会说这句假话。

### 待办（建议）

- [ ] 决定 `layerLabel` 的三态语义：**当前场景** / **世界根等无层位置**（建议措辞：「your pack」/「the world」/「<角色名>'s room」）/ **其它层**。`null` 不能既表示"当前场景"又表示"无层"。
- [ ] 核 `:118` 的兜底串 `'the current scene'` 是否与 `:122` 是同一条假话的两个来源（两处都要改，不能只改一处）。
- [ ] 评估是否需要把 `resolveLayer` 的 `null` 拆成两个值（`'current'` vs `'none'`）——若拆，属跨端契约变更，MUST 走 `docs/wiring/` 与 WS 契约门禁。

> **与洞 1/洞 2 的形态差异**：洞 1/洞 2 是**安全**洞（越权写入）；本条是**诚实性**洞（向玩家说假话）。同属「既有通路不受 C1 保护」，故同台账登记。
---

## 共同点

洞 1 与洞 2 同一形态：**某个既有入口没有参与 C1 设立的那道防线**。

- 洞 1：写 `choice_actions` 数据的通路（C1 只保证"命令不说话"，不保证"内容不说话"）
- 洞 2：原生 `edit` 工具（C1 只保证"命令效果的 edit 有拒绝列"）

**结论**：C1 的两道防线（效果集排除 `writer` / `edit` 的保留键拒绝列）是**效果层的**。**效果层之外的同名入口不受保护。** 任何"C1 保护了 X"的表述 MUST 限定为"**C1 的命令效果**保护了 X"。

**洞 3 是另一形态**：它不是"防线漏了一个入口"，而是**一条既有的渲染器在信息不足时编了一句兜底假话**（`layer === null` 的两种含义被合并成一种）。它与洞 1/洞 2 的共同点是**都不受 C1 保护**，差异是**性质**——前两者是越权写入（安全问题），后者是向玩家说假话（诚实性问题）。**没有洞 1/洞 2 时，洞 3 依然存在。**
