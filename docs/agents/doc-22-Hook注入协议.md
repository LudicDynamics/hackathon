# doc-22 Hook 注入协议：状态块与事件段

> 状态：**已被 `docs/hooks/` 修正（2026-09-12）**。本文是这块设计的**起点**（方向正确），但**两处关键机制已实测证伪**，冻结契约现为 **[`docs/hooks/00-共同上下文.md`](../hooks/00-共同上下文.md)**，逐篇细节在 `docs/hooks/01`–`06`。**实现以 `docs/hooks/` 为准**；本文保留动机与分节理由，被推翻的机制已就地改写。
> 证伪记录：**[`docs/hooks/AUDIT-doc-22体检.md`](../hooks/AUDIT-doc-22体检.md)**（哪些断言为假、怎么测出来的）。
> 起因：doc-21 把"事件只描述变化"钉死之后，"柜台上有铜钥匙 / 玩家在哪 / 角色各自在哪"这些**当前值**就没有归宿了——它们不是事件，但 agent 每轮都必须知道。本文定这一块。

---

## 0. 一句话

**每轮注入 = 状态块（当前值，每轮全量）+ 事件段（变化，游标增量）。两者机制不同，不能互相替代。**

> **改（实测）**：状态块**不做指纹 diff**——"本轮比上轮变了什么"这个问法在临时注入下**没有指代对象**（见 §1 裁决 2）。有界性改由**条目上限**保证。

---

## 1. 为什么两样都要

一个很自然的想法是"只留一样就够了"——两个方向都塌。

| 只留…… | 塌在哪 |
|---|---|
| **只留事件** | 事件重放不出"现在什么样"。角色刚 spawn，要知道"柜台上有铜钥匙"就得把创世至今的事件全读一遍再在脑子里做加减——这是把日志当数据库用，且随轮次线性变长 |
| **只留状态** | 状态只能说出"现在什么样"，说不出**谁干的、什么顺序、中间经过了什么**。而 AIRP 要的恰恰是因果：作家需要知道"玩家把钥匙**拿走了**"，不是"钥匙现在在背包里" |

Nodesign 只需要前半段（它是工具型产品，没人在乎谁动的），AIRP 两段都要。**这就是 AIRP 比 Nodesign 多一层的地方，不是抄漏了。**

| | 状态块 | 事件段 |
|---|---|---|
| 回答 | 世界现在什么样 | 世界怎么变成这样的 |
| 来源 | `canvas.db` + 目录扫描 | `history.db` 事件表 |
| 去重 | **每轮全量重算**（无 diff，见裁决 2） | **`seq` 游标** |
| 丢了会怎样 | agent 瞎猜"这个/这里" | agent 不知道刚发生了什么，装傻或胡编 |
| 落地 | `docs/hooks/01`/`02` | `docs/hooks/03` |

### 1.1 两处与初稿相反（**先看这里**）

| # | 初稿的说法 | 裁决 | 依据 |
|---|---|---|---|
| **1** | 注入挂 `before_agent_start` 返回的 `message` | **改挂 `context` 钩子** | 实测：`before_agent_start` 的 `message` 被持久化成 `custom_message` 会话条目，**第 N 轮上下文里有 N 个块**（累积）。`context` 返回替换数组**不落盘**，是引擎唯一的临时注入接缝 |
| **2** | 逐节指纹 diff，只报变化的节 | **放弃差分，每轮全量** | `context` 注入**无状态**：请求 N 的载荷里没有第 N-1 轮的块，差分**没有指代对象**。有界性改由**条目上限**保证 |

**目标不变**（每轮知道世界什么样、刚变了什么、且上下文不无界增长）——只是把手段换成能兑现的那个。

## 2. 从 Nodesign 抄什么

九条，逐条抄（解剖见 doc-18 §124/§125）。**第 2/3/4/5/6/7 条在 AIRP 已改写**，因为 AIRP 的注入是临时路径（裁决 1）：

| # | 机制 | AIRP 抄成什么 |
|---|---|---|
| 1 | **按节组织**：每节 `{ key, title, text, items? }` | 状态块是若干节的拼接，不是一段散文（**保留**） |
| 2 | ~~首轮全量，之后只报变化~~ | **改写：每轮全量**。指纹 diff 无指代对象（裁决 2）；有界靠条目上限 |
| 3 | ~~清单节报增删~~ | **改写：每轮列全（上限内）**。不报增删——"和上轮比"没有参考系 |
| 4 | ~~没变的节末尾点名~~ | **废弃**。每轮全量即"所有节都在"，没有"未变"可言 |
| 5 | ~~一节都没变 → 一句话~~ | **改写**：所有节都无内容时输出 `[World state: nothing to report yet]`（角色版另一措辞）。这是"世界是空的"，不是"与上轮相同" |
| 6 | ~~压缩后重置记忆~~ | **废弃**：本批不做压缩层（§8），且注入不落盘、无记忆可重置 |
| 7 | ~~量化再算指纹~~ | **改写**：量化**保留**（1/8 视口，前后端同一函数），但它服务的是**前端上报节流**，不再是"指纹"。人话方位是天然量化（§5） |
| 8 | **fail-soft 到节** | **保留**（三层兜底，`docs/hooks/00` §11） |
| 9 | **一份措辞，两处复用** | **保留**：状态块与 `look_at` 共用方位词器（`render/spatial.ts`） |

### 2.1 它的接线我们不抄

Nodesign 把状态块**拼进 prompt 文本**（`client.prompt` 前加 `<system>…</system>`）。AIRP 走 **`context` 钩子返回替换数组**（裁决 1），三点更好：

- **身份清楚**：是一条独立的 `custom` 消息（`customType: 'airp_world_state'`），不是混在玩家那句话里；
- **不炸缓存**：**不碰 `systemPrompt`**——system prompt 是每轮不变的冻结区，改一个字整段缓存作废。可变内容只能挂在尾部；
- **可声明策略**：`registerCustomType('airp_world_state', { compaction: 'exclude' })` + `display: false`，状态块不进画布（doc-05 §5）。

## 3. 分节表

> 逐字格式（标签、缩进、上限、空态）见 `docs/hooks/02-分节表与渲染.md` §3；本节只列 key 与来源。

### 3.1 作家（6 节）

| key | 标题 | 来源 | 节型 | 纪律 |
|---|---|---|---|---|
| `viewpoint` | 玩家视点 | `canvas.db` 视点表（前端上报） | 单行 | **不给坐标数字，给人话方位**。附一句指代消解优先级 |
| `layer_files` | 本层现有 | 目录扫描 | 清单 | 只列路径 + 一行这是什么，**不灌全文** |
| `cast` | 在场角色 | `canvas.db` `presence` | 清单 | 谁在这层、大致在哪、谁在跟随 |
| `bag` | 玩家背包 | `player/` 扫描 | 清单 | 同上，只列不灌 |
| `recent_chalk` | 最近板书 | 跨层按 mtime 取 8 | 清单 | 路径 + 首行，正文自己 `look_at` |
| `dynamics` | 世界动态 | `history.db` 事件表 | **游标** | doc-21 §5.1：游标增量、排除自己、合并、上限 12 |

### 3.2 角色（4 节）

| key | 标题 | 差异 |
|---|---|---|
| `standing` | 你在哪 | 换成角色自己的位置 +「玩家此刻在你面前」（**须比较两层**，`docs/hooks/02` §3.2），不报玩家的相机 |
| `layer_files` | 本层现有 | 同作家（共享同一个 SectionSpec） |
| `cast` | 还有谁在 | 排除自己 |
| `dynamics` | 最近发生了什么 | doc-21 §5.2：本层过滤、首次取最近 12 条、关遮罩推游标 |

**角色不注入 `bag`**：玩家的口袋不在角色的视野里。但这是**省 token 和合乎叙事，不是门禁**——角色真要 `look_at player/` 也拦不住，AIRP 不做权限防备（doc-05 §4.1）。

### 3.3 注状态，不注指令

"怎么用这些东西"住 preset（缓存的 system prompt），**每轮再说一遍就是上下文里的 N 倍重复**。状态块里只有两类句子例外，因为它们依附于当下的值：

- 指代消解那一句（"他说「这个」多半指选中的 > 视口里的"）；
- **"下一步"那一句**（§10，`docs/hooks/04`）。

除此之外状态块里不出现祈使句。

## 4. 装配规则

> **真源是 `docs/hooks/02` §7 的逐字样例**（作家块 / 角色块）。本节给结构骨架。

```
[World state]

<每节：可选 title 行 + 缩进两空的条列；空节整节缺席>

<最后：next_step 段（无 title）>
```

四条固定规则：

1. **首行恒为 `[World state]`**（方括号、无冒号）；
2. **每轮全量**：所有非空节都在，不报"增删"、不点名"未变"（裁决 2）；
3. **空节整节缺席**（不输出"（无）"）；一节都无且无"下一步" → `[World state: nothing to report yet]`；
4. **`next_step` 永远最后一节**，无 title，与前一节空一行（§10）。

**事件段（`dynamics`）独立成节**，不参与任何比对——它本来就是增量，游标已保证不重复（doc-21 §5.4）。**游标在轮边界、注入成功后推进**；`context` handler 只读缓存字符串（`docs/hooks/00` §6.2）。

**轮边界缓存存模块级**：扩展跑在 agent 进程内，进程 = 会话。**但注意模块级是 per-extension-file 的**（loader 对每个扩展文件各建 jiti），所以 `extensions/context.ts` 不能复用 `extensions/toolkit/*` 的模块状态（`docs/hooks/00` §9）。

## 5. 防抖：状态最怕"看起来一直在变"

相机每帧都在动。初稿靠指纹 diff 防抖；**改为全量后，防抖落在"上报节流 + 量化 + 人话化"三道闸**：

| 闸 | 位置 | 做法 |
|---|---|---|
| **上报节流** | 前端 | 只在变化时发，最快 1.2s 一次；变化判据用量化后的 key（`docs/hooks/05` §3） |
| **量化** | 前端与服务端**用同一个量化函数** | 相机位移不超过 1/8 视口就算没动 |
| **人话化** | 渲染 | AIRP 注入的本来就不是坐标而是方位词（"在柜台附近"）——**方位词的粒度就是天然的量化**。坐标只供引擎排座，不灌给 agent |

前两道的落点是 `render/viewpoint.ts` 的共享量化函数（`docs/hooks/05` §3）；**存的是编码几何，人话是渲染产物**。

另加一条 **TTL**：视点超过 10 分钟没上报就当玩家不在，`viewpoint` 节**缺席**（**并级联** `layer_files`/`cast`，`docs/hooks/00` §5.1.1）。

## 6. 状态存哪

| 状态 | 存哪 | 理由 |
|---|---|---|
| 当前层、卡片坐标、关系线、角色 presence、跟随 | `canvas.db`（已有表） | **属于世界**：进存档、跟着快照回滚 |
| 玩家视点（当前层/相机中心/选中） | `canvas.db` 新增 `viewpoint` 单行表 | 见下 |
| ~~每轮指纹记忆~~ | ~~agent 进程内存~~ | **废弃**：不做 diff（裁决 2） |

**视点为什么也进 `canvas.db`**：AIRP 的装配跑在**扩展里，也就是 agent 进程**，与 server 不是同一个进程。共享文件是唯一不需要 sidecar 的通道——server 写、扩展读。

**但它不属于世界**：单行、带 `at` 做 TTL、**快照不打包、回滚不还原**。单玩家世界（doc-05 §6）所以单行就够。

前端上报的值**一律 sanitize**——但**不止这一处**（更正）：注入块同时印世界文件内容（`entityName` 的 title、层 README 的 name），而 `POST /api/god-action` 无鉴权接受任意 frontmatter。所以消毒是**内容级的**（剥换行/引号、限长），覆盖**所有进注入块的动态文本**（`docs/hooks/00` §14）。

## 7. 两层：注入摘要，细节走工具

状态块给的是**一行摘要 + 一份清单**；要细节，agent 自己调工具（AIRP 是 `look_at`）。判据：注入负责让 agent **知道有这么个东西**，工具负责让它**看清楚**。

---

## 8. 明确不做

- **不注入全文**：任何节都只给路径 + 一行。
- **不做"哪些节该注入"的运行时配置**：分节表硬编码。
- **不在状态块里放规则和指令**（§3.3）。
- **不把状态写进事件表**：没有 `state_changed` 事件（doc-21 §8）。
- **不做 summary 压缩层**：初稿的理由是"注入块天生有界"——**实测为假**（初稿挂的 `before_agent_start` 会累积）。**结论保留，理由更正**：注入走**临时路径**（`context` 钩子），每轮恰好一份、不落盘，**所以没有压缩的对象**。真要压的两样东西各有归宿：画布上的叙事正文归 doc-08，会话 transcript 归 pi-rp 自己的 compaction。
- **不引入 `get_state`/`set_state`/`state_update`/`watch_state`**（doc-20 §2.3）。

## 9. 落地落点

> **真源在 `docs/hooks/` 各篇的「落地落点」节**。本表只列与本协议直接相关的入口。

| 位置 | 改动 |
|---|---|
| `packages/shared/src/db/schema.ts` | `canvas.db` 加 `viewpoint` 单行表（`layer / focus / focus_x..h / selected / bag_count / at`） |
| `apps/server/src/routes/world.ts` | `POST /api/viewpoint`：sanitize（内容级）→ 写 `viewpoint` 表 |
| `apps/web/` | `useViewpointReport` 上报（变化触发 + 1.2s 节流 + 慢心跳 + 量化 key） |
| `extensions/context.ts`（新建） | **`context` 钩子**装配（**不是 `before_agent_start`**）；`makeSectionDeps`/`collectSections`/`renderState`（纯函数，可单测）；按 `AIRP_AGENT_ROLE` 选分节表 |
| `extensions/context.ts` | `registerCustomType('airp_world_state', { compaction: 'exclude' })`，注入时 `display: false` |
| `packages/shared/src/render/` | 方位人话 formatter（与 `look_at` 共用）、分节表、事件渲染、下一步、视点量化、消毒 |
| `presets/writer.json`、`presets/character.json` | `hiddenOverrides.compaction`（**在 preset JSON 里，不在 `extensions/instructions.ts`**）：压缩摘要的提示词（持久事实该保住什么）。**引擎压缩唯一的调教入口，手动与自动都走它** |

**纯函数与 I/O 分开**：采集（有 I/O、逐节 fail-soft）、渲染（纯函数、可单测）。

## 10. 「下一步」段（原「留白」，**已定稿**）

注入块末尾的「下一步」段（初稿标为"优先级最高的待设计"）：祈使的、由事实推出来的"现在轮到你做什么"（未回应的玩家动作 / 刚生成尚未被看见的内容 / 明确的"什么都没发生，别为填空而写"）。

**已定案**：位置（永远最后）、性质（只由事实推出、不替 agent 决定）、三类情形与逐字措辞，全部在 **[`docs/hooks/04-下一步段与压缩覆盖.md`](../hooks/04-下一步段与压缩覆盖.md)**；doc-12 #6 是它的来源。

**其余留白**（仍在）：`bag`/`layer_files` 的条目上限（暂定各 12）、多玩家（云端版 doc-17 再议）。
