# 回执通道与双工角色链路

> 2026-09-15 · niko。上游 `docs/live-voice/00`（冻结契约）不变：三条语音通道、端点、消毒分块、不新增 WS 帧。本文补的是 00 §7 没列出的第 5 个未决：**通话是单向的**——语音前端把请求委托给角色 agent，agent 做完了事（拿了钥匙、写了场景、掷了骰子），却没有一条通道把「做完了」送回给正在通话的角色，用户问「你做了吗」得不到回答。

## 1. 决定

1. **角色链路抽成通用接口，不写死 GPT Live。** `apps/server/src/engine/character-duplex.ts` 的 `DuplexCharacterChannel` 只有三件事：`speak(delegationId, content)`（角色自己的话，语音前端复述）、`notice(delegationId | null, content)`（可见提示，不是角色台词）、`close()`。`LiveCallRegistry` 只对这个接口说话；GPT Live 的 sideband 是它的第一个实现（`createLiveSidebandChannel`，帧仍是 00 §2.7 冻结的 `session.commentary.append` / `session.instructions.append`）。以后自研的微调双工角色模型只需再给一个实现，委托流程一行不改。
2. **每次委托回两样东西：台词 + 回执。** `receiptOf(events)` 把这一轮角色 agent 的 `tool_execution_*` 事件投影成动作回执（只保留会改世界的工具：`chalk / write / move / move_to / use_item_on / link / arrange / roll_dice / choose / delete / set_following / generate_image / show / create_char`；`look_at`、`get_component` 之类只读工具不算），`receiptLine(receipt, language)` 再把它说成一句给语音复述的话：`(Done: moved old key to player.) (Could not: rolled the dice.)` / `（完了：…）（できなかったこと：…）`。失败的调用**点名**，让用户听到「没做成」。
3. **只做了事、没说话的一轮不再算失败。** 以前 `lastAssistantText` 为空就走「I could not put that into words」；现在只要回执非空就把回执当台词 `speak`，只有台词与回执都为空才走可见失败。

## 2. 接线

| 位置 | 改动 |
|---|---|
| `engine/character-duplex.ts`（新） | 接口、`receiptOf` / `receiptLine`（纯函数）、GPT Live 实现 |
| `engine/live-session.ts` | `ActiveCall` 持 `channel` 与 `language`；`open()` 建 channel；`runDelegation` 台词后追加回执；`appendCommentary` / `appendVisible` 改为转发 channel |
| `test/character-duplex.test.mjs` | 回执投影、两种语言的措辞、sideband 帧形状与失败不吞 |

不新增 WS 帧、不新增端点；`event_id` 仍以本次通话的输出转写长度做盐。

## 3. 还没做（登记）

- **回执只覆盖同一轮 agent 内完成的事。** 委托触发的后续效果（角色的 chalk 引起作家一轮、I1 场景初始化、生成图片的异步落地）在这一轮结束时还没发生，回执不会提到；要等它们完成再补一条 `speak`，需要 lifecycle 的 turn 完成事件订阅，本批未做。
- 自研双工模型的实现：接口已留，`kind` 标签给日志与连接自检用。
