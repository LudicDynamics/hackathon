## 1. 一句话定位

**在 `CharacterModal` 的 `.identity-status` 里加一行「文字 / 通话」模式切换；把 `.speech-paper` 的内容按 store 快照换装成通话版面（字幕 + 状态 + 挂断）；文字模式的七个行为点各自在通话模式下短路。**

三条不变量：

1. **对话框不持有「我是否在通话」的 state**（契约 `10` §4.1）——模式**完全由 store 快照推导**，于是 nook 与对话框天然一致。
2. **通话版面不开新层、不开新窗口**——它复用 `.speech-paper`（`index.css:564-583`），只换内部子节点，纸的基线 / 倾斜 / 升降动画全部沿用。
3. **后端与 store 零改动**；本文只碰 `CharacterModal.tsx`、`messages.json`、`index.css` 的追加段。

## 3. 行为契约逐步（每步写「漏了会怎样」）

### 3.1 模式：默认文字，切换是派生量

1. `callVisible = (callActive || call.phase === 'error') && call.characterId === characterId`。**没有 `mode` state**。
2. `.speech-paper` 上的 `data-dialogue-mode={callVisible ? 'call' : 'text'}` 是唯一模式标记（供 CSS 与测试用）。**注意取值来源是 `callVisible`**——§3.5 的版面二选一必须与它一致，否则错误态又会被文字版面吃掉。
3. 进入通话**只有一个入口**：「通话」按钮 → `startDialogueCall()`。

**漏了会怎样（1）**：把模式做成组件 `useState`，则 nook 已为该角色开通话时打开对话框，对话框显示「空闲」并允许再点「开始通话」——store 虽会先挂断旧的那条（`10` §2.2 冻结 1），但玩家看到的是自相矛盾的两份真相（`10` §4.1 明文禁止）。

**漏了会怎样（2）**：把 `start()` 挂在「切到通话模式」的副作用里，就是 `10` §8 反模式 6 的**自动开通话**——建会话预扣 15 秒（`00` §2.9），且 `getUserMedia` 不在用户动作栈里，浏览器会拒。

### 3.2 模式切换的 UI 落点（**必做 1**）

**位置**：`<aside className="identity-status">`（`:869`）内、`.identity-heading`（`:870-877`，含既有 `onOpenNook` 按钮 `:872-876`）**之后**、`.identity-bio`（`:878`）**之前**。

```tsx
{modeSwitchVisible && (
  <div className="dialogue-modes" role="group" aria-label={t('Dialogue mode')} data-dialogue-mode-switch="">
    <button type="button" className="dialogue-mode" aria-pressed={!callVisible} onClick={hangUp}>
      {t('Text')}
    </button>
    <button
      type="button"
      className="dialogue-mode"
      aria-pressed={callVisible}
      disabled={callActive && call.characterId === characterId}
      onClick={startDialogueCall}
    >
      {callActive ? t('On a call') : t('Start a call')}
    </button>
  </div>
)}
```

**为什么另起一行而不塞进 `.identity-heading`**：`.identity-heading` 是 `display:flex; justify-content:space-between`（`index.css:614-619`），它的子按钮样式来自 `.identity-heading > button`（`:628-642`）；移动端断点把 heading 改为纵向、按钮 `align-self:flex-start`（`:840-849`）。再塞一个按钮会让「标题 + 两个按钮」在窄屏挤成三行，也表达不了「二选一」。新开一行 `role="group"` 语义正确、窄屏自动占满。

**复用**：视觉词汇沿用 `.identity-heading > button`（`var(--cream)` 底、`var(--line)` 边、`'Manrope'` 0.76rem），选中态借用既有「强调 = `var(--rust)` 底 + `var(--paper)` 字」的配对（`:638-642` 的 hover 正是这一对）。不引新 token。

**`available:false`**：`modeSwitchVisible` 为 false → **整行不渲染**（不是渲染一个禁用的按钮；契约 `10` §3.1 冻结 1 / §7 第一行）。
**漏了会怎样**：`/api/live/*` 未配置的部署里，玩家点「开始通话」拿到 `unsupported` 错误——把「这个服务器没有这功能」呈现成一个「你的操作失败」，归因错误。

**`aria-pressed` 而不是 tablist**：这两个是动作开关，不是视图标签页。**「通话」格的 `disabled` 用 `callActive && call.characterId === characterId`（不是 `callVisible`，也不是裸的 `callActive`）**：错误态下必须允许再点一次以重试（`start()` 本身幂等且会先清掉旧会话，`11` §3.2），若用 `callVisible` 会让错误态**永远无法重试**；而**裸的 `callActive` 是全局的**，会让「另一个角色正在通话」时本角色的按钮也被禁用——那正是 `10` §4.1 明文禁止的（「显示空闲、点通话先挂断旧的」）。加 `characterId` 一致判定后两个意图同时满足。`aria-pressed` 则用 `callVisible`——错误态语义上仍在「通话这一格」。

> **L3 修正（2026-09-15，`30` §4.2 冻结 7）**：以上取值修正来自实测——`disabled={callActive}` 曾使「他角色持有通话 ⇒ 本角色按钮灰掉 ⇒ 永不触发先挂断再开」。

### 3.3 文字模式既有行为的保护（**必做 3**，逐点短路）

所有短路都读 `callActiveRef.current`。**门一律加在「动作点」而不是共享函数内部**（下有例外标注），这样文字模式的执行路径逐字节不变。

| # | 行为点 | 现状行号 | 通话模式下的短路条件 | 漏了会怎样 |
|---|---|---|---|---|
| G1 | `prefetchVoice` 调用点 ①：`syncPages` 新建页封口即预取 | `:388` | `if (fresh.sealed && !callActiveRef.current) void prefetchVoice(fresh, i)` | 通话中每页发一次 `/api/tts` → 页面朗读与通话双路音频叠加，且白付 TTS 费用（`10` §5.2） |

| G6 | mock 问候语播种（整段） | `:542-610` | 在 `:542` 的 effect 顶部加 `if (callActiveRef.current) return;`（**在 `mockSeededRef.current` 判定之前**） | 见 §3.4 |

**为什么要埋 `callActiveRef` 而不是把门塞进 `prefetchVoice`（`:275-323`）内部**：契约 `10` §5.2 明确「落点是调用点，不是 `fetch('/api/tts'` 那一行」；而塞进 `prefetchVoice` 函数体首行虽也满足「结构不动」，却会把**已经进入 `voiceState='pending'` 的页**留在 pending（该函数开头 `:277` 的 `if (page.voiceState !== 'idle') return;` 会先命中），切回文字模式后那页永远不再预取——一个只能靠刷新恢复的哑状态。**在调用点短路则 `voiceState` 保持 `'idle'`，切回文字模式后重新走 `enterPage` → 自然补课。**（`G2/:400` 的 `prev.voiceState = 'idle'` 复位在 `:398`，早于调用点，与本次短路不冲突。）

**`advance` / `settleIfDrained` / `beginStream` / 帧消费**在通话模式下**不额外短路**——理由必须写清：

- **`advance`（`:443-458`）**：`.line-stage` 在通话版面上**不渲染**（§3.5），所以 `advance` 的唯一调用点是 `:899` 的 `onClick` 与 `:900-904` 的 `onKeyDown`，二者随 DOM 一起消失。**加门是死代码**。唯一残留触达路径是：进入通话前聚焦的 `.line-stage` 是否还持有键盘焦点——不会，因为 `callVisible` 一变（§3.6）就 `focus()` 到 `.call-hangup`。
- **`settleIfDrained`（`:210-222`）/ `beginStream`（`:421-440`）/ `pump`（`:225-252`）**：三者都只被「帧消费」与 `enterPage` 调用。通话模式下角色真实台词**仍经 `airp:character-frame` 到达**（`useWorld.ts:786/801`），并**仍进 `frameQueue`**——它们是硬事实，不是「文字模式的演出」。但**逐字打字机不该在通话里跑**（字幕要瞬时、且要按 store 的既有次序渲染）。
- **因此帧消费的短路点是 `consumeCharacterFrameFromQueue`（`:614-708`）的单点入口**：`if (callActiveRef.current) return;`（加在 `:614` 函数首行）。**漏了会怎样**：通话中角色说话会同时驱动 `pump` 的逐字计时器与 store 字幕——两处对同一句话做呈现，且 `phase` 变 `streaming` 会让 `busy`（`:773`）为真。**注意不能靠 `frameQueue.clear`**：`clear` 会丢掉真实帧，而 store 的帧监听是**独立**的 `window` 监听（`10` §2.3），清队列只影响对话框、反而让「store 有、对话框没有」，制造第二处真相。
- **切回文字模式**：`callVisible` 变 false → `callActiveRef.current = false` → 帧消费与预取自动恢复；`frameQueue` 里 `characterId` 匹配的帧在下一个 `queueVersion` 变化时被 `drainUntil(characterId)`（`:761`）正常消费。**通话期间到达的帧**：`consumeCharacterFrameFromQueue` 直接 return，但 `drainUntil` **已经把它们从队列取走**（`:761-762`）→ 它们不会事后补播。这是有意的：**通话期间的台词所有权归 store 的字幕**（`10` §2.3「展示规则」，`NookView.tsx:754-795` 同形），切回文字后不重播历史台词。**错误态例外**：`callVisible` 为 true 但 `callActiveRef` 为 false → 版面还是通话版面，但**帧消费与预取已经恢复**（帧会经 `drainUntil` 正常进 `syncPages`，只是被 §3.5 的版面判据挡在呈现之外）——这是正确的：错误态下 store 已无通话，角色确实可能因别的原因（如玩家又打字）产帧。

### 3.4 通话模式不播种 mock 问候语（契约 §3.3）

**落点**：`:542` 的 effect 首行 `if (callActiveRef.current) return;`。

三个要点：
1. **在 `mockSeededRef.current`（`:543`）判定之前**。否则 `mockSeededRef.current` 会被置 `true`（`:559`），切回文字模式后 `:543` 命中重入分支、`:547` 的 `if (!mockRef.current || pagesRef.current.length === 0) return;` 直接 return——**问候语永久不来**。
2. **同时不写 `localStorage`**：`:595-601` 的 `airp:greeted:v2:...` 写入在 return 之后，天然不会执行。**漏了会怎样**：玩家这次通话没看到问候语，下次打开对话框却被 `:588` 的 `if (greeted !== null) return;` 判定「已问候过」→ 问候语永远丢失（`airp:greeted` 是不可逆的一次性键）。
3. **`worldId === undefined` 时（`:579`）**：`key` 为 null，既读不到也写不了，纯降级——与通话无关，本次不改。

**切回文字模式后**：effect 依赖数组是 `[characterId, language, worldId, prefetchVoice, enterPage]`（`:610`），**不含 `callActive`**，所以它**不会重跑**。这是**正确的**：契约 §3.3 原话「切回文字模式时按文字模式既有逻辑处理（已播种过则不重复）」——本次会话未播种，切回后也不需要补播（玩家已经在通话里听过角色的真实开场）。

### 3.5 通话版面（**必做 2**）

**结构**：`.speech-paper`（`:891`）内二选一，判据是 **`callVisible`**（`callActive || phase === 'error'`，见 §2.2）。`data-dialogue-mode="call"` 时，`:892-921`（`.line-stage` 与 `.advance-indicator`）与 `:923-943`（`.speech-input-row`）**整块不渲染**，换成：
```tsx
<div className="call-stage">
  <ActivityRail surface="character-modal" agentId={`character:${characterId}`} />
  <div className="call-stage__transcript">
    {lines.lines.map((line, i) => <p key={i} className="call-line"><span className="call-speaker">{t('They say')}</span>{line}</p>)}
    {lines.streaming !== '' && <p className="call-line call-line--streaming"><span className="call-speaker">{t('They say')}</span>{lines.streaming}</p>}
    {lines.streaming === '' && call.outputText !== '' && <p className="call-line call-line--voice"><span className="call-speaker">{t('They say')}</span>{call.outputText}</p>}
    {call.inputText !== '' && <p className="call-line call-line--player"><span className="call-speaker">{t('You')}</span>{call.inputText}</p>}
    {lines.lines.length === 0 && lines.streaming === '' && call.outputText === '' && call.inputText === '' && (
      <p className="call-placeholder">{call.phase === 'connecting' ? t('Connecting…') : t('Listening…')}</p>
    )}
  </div>
  <div className="call-bar">
    <span className="call-status" role="status">{call.phase === 'connecting' ? t('Connecting…') : call.phase === 'live' ? t('On a call') : t('Could not connect')}</span>
    <button type="button" className="call-hangup" ref={hangUpRef} onClick={hangUp}>{call.phase === 'error' ? t('Close') : t('Hang up')}</button>
  </div>
  {callAlert !== '' && <p className="dialogue-call-alert" role="alert">{callAlert}</p>}
</div>
```

**⚠️ 两条「有符号无落点」修正（评审 E9/E10，主 agent 已核实并直接落文）**：

1. **`callAlert` MUST 派生自 `call.error`，MUST NOT 建本地 state（E9 修正 + 实现期更正）**：本文初版**全文 `setCallAlert(` 零命中**——若按初版实现，`role="alert"` 永不渲染。主 agent 初裁要求「加 `useEffect(() => setCallAlert(call.error ?? ''), [call.error])`」，**实现期实测证明该初裁是错的、已被推翻**，理由两条：① **`renderToStaticMarkup` 不跑 effect**——state 副本在渲染断言里恒 `''`，A3′/A5 **根本无法断言**（ModelImpl 实测）；② **state 副本会让挂断后告警残留**——`11 §3.3` 第 5 步的 `stop()` 会清 `call.error`，而本地 state 不会自动跟着清，玩家挂断后还会看到一条已经过期的错误。

### 3.7 §3.1.1 关对话框时序（**必做 4**）

**实测事实**（契约 §3.1.1）：`App.tsx:1116-1132` 的 `closeCharacter` 先 `sendMessage({ type: 'character_stop', characterId })`（`:1117`）**杀掉角色 agent**，再清 surface / 相机 / `setActiveCharacter(null)`。`stop(owner)` 只收 Live 会话与 sideband，**不碰 agent**（`live-session.ts:429-444`，`11` 已核）。所以时序要求是：**`stop(owner)` 必须早于 `onClose()`**。

**落点选定：`handleClose`（`:494-501`），而不是 `requestClose`（`:502-506`）。**

```tsx
const handleClose = useCallback(() => {
  if (closeTimer.current !== null) return;
  void stopOwnedCall();                 // ← 新增：早于 onClose()
  setClosing(true);
  closeTimer.current = window.setTimeout(() => { closeTimer.current = null; onClose(); }, 220);
}, [onClose, stopOwnedCall]);
```

**为什么 `requestClose` 不够**（三条，逐条可核验）：

1. **`requestClose` 有早退分支**（`:503-504`）：`if (lease && !lease.markClosing()) return;` —— `markClosing()`（`focus-coordinator.ts:180-186`）只在 `active.phase === 'open'` 时返回 true。**Console 的 Escape 路径**（`:528` `close: () => handleCloseRef.current()`）与**程序化关闭**（`App.tsx:353` 的 `closeCharacterRef.current()`，`openPrivateSpace` 里「打开小天地先关对话」）**都不经过 `requestClose`**，直接调 `handleClose`。挂 `requestClose` 会漏掉这两条主路径 —— 而 `openPrivateSpace` 正是「点『访问小天地』→ 角色 agent 被 `character_stop` 杀掉」的高频路径。
2. **`requestClose` 可能被跳过**：`markClosing()` 返回 false（例如同一帧内 Escape 与点击都到了）时 `requestClose` 直接 return，**不关也不挂**——通话留在原地，而 `handleClose` 也不会被调，于是这个对话框永远关不掉，通话永远不停（静默计费）。挂 `handleClose` 则只要关闭真的发生，一定先挂断。
3. **`handleClose` 是唯一收口**：所有关闭路径（`:835` 的 `×`、Escape、程序化）最终都落到 `handleClose`（`:505`、`:528`、`App.tsx:353`）。**一个门一处**，符合 `docs/tools/00` 的「一个真相源」。

**为什么不是卸载 effect**（`:766` 的 `useEffect(() => streamTurn, [streamTurn])` 旁边再加一个 `stopOwnedCall`）：契约 §3.1.1 明文「先关再挂断」是**竞态窗口**——卸载时 `character_stop` 已发出，若此刻恰有一条 delegation 在跑，`live-session.ts:626-633` 会走「角色 agent 不可用」并**在通话里说「我没能查证」**。失败可见但**归因错误**（玩家会以为角色本身有问题，而不是「我关了对话框」）。`handleClose` 里的调用**在同一 tick 内同步发起 `stop()`**，早于 220ms 后的 `onClose()`。

**卸载 effect 仍然要保留**（双保险）：`useEffect(() => () => { void stopOwnedCall(); }, [characterId, stopOwnedCall])`。**覆盖的是 `handleClose` 覆盖不到的路径**：`key={activeCharacter.id}`（`App.tsx:1501`）导致**直接换角色**时旧实例被 React 卸载，`handleClose` 不会被调。**漏了会怎样**：A 通话中直接切到 B 的对话框 → A 的实例被卸载、A 的通话续存且无任何 UI（静默计费，`10` §2.2 冻结 5）。
