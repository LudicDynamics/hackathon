## ② 不通过项清单

### F1（P1）§9-U2「`error` 帧镜像进 store」未落到 `11`

- 契约侧：`10:440`（§9 裁决「**进**。store 在 ingest 里对当前 `characterId` 的 `error` 帧置 `phase:'error'`」）。
- 设计侧：`11:355` 仍写「**store 本批不消费 error 帧**」；`11:161` 的过滤描述与 `11:287` 的示例代码 `else return;` 会把 `error` 帧直接丢弃；`11:535`（§13-U6）仍把该项列为**未拍板**。
- 影响：按 `11` 实现即漏掉契约裁决——`CharacterModal` 的 `callAlert` 拿不到 agent 死亡原因，`10 §7` 表末行的可见降级不成立。这是**消费侧分派点**（`useWorld.ts:790` 派发 `error` → `airp:character-frame`）在 store 的对应分支缺失。

### F2（P1）§9-U3「`errorText` 缺 `zh-CN`」未登记进 `13`

- 契约侧：`10:441`（「**本批不迁**，但**登记为已知缺口**交给 `13`……**MUST NOT** 在本批悄悄留着不记」）。
- 设计侧：`13:210-301` 的 W1–W20 回写清单**无任何 `errorText` / `zh-CN` 缺口条目**（grep `13` 无命中）。
- 影响：契约明文的 MUST 未兑现，`zh-CN` 界面下通话错误文案回落英文这条缺口在交接后即丢失。

### F3（P1）§4.3 守卫放宽**四份文档都没有落点**

- 契约侧：`10:212-217` 冻结 `NookView` 守卫 MUST 改为 `sameCharacterOnCall`（`call.characterId === id`）；`10:224` 声明「落在 `NookView.tsx`（11 号文档 §9.2 已含该文件的卸载 effect）」。
- 设计侧：`11:405-420`（§9.2 六条）**不含**守卫放宽项，全文无 `sameCharacterOnCall`；`12:308` 反向指认「§4.3 的守卫放宽也在**11 §9.2**」（指向不存在的条目）。
- 影响：`NookView.tsx:194-205` 的 `if (callInProgress)` 在 L2 单例下会**挡住所有角色**的对话框（`10 §4.3` 描述的误挡 + 归因错误），且没有任何子文档认领这次改动。

### F4（P2）`CONSUMERS` 范围与输出基准未同步（`13`/`11` 停留在旧口径）

- 契约侧：`10:272-303` 明列本批增列 **`live-call-store.ts` + `CharacterModal.tsx` + `dialogue-pages.ts` + `CanvasArrangeControl.tsx` + `writer-state.ts`**，并把基准改为 `clean (27 emitted, 25 consumed, 27 in contract)`（`10:298`）。
- 设计侧：`13:11`（「三处机械改动……增列**一行**」）、`13:19`/`13:64`/`13:251`/`13:267`（全部仍写 **24 consumed**、**4 条 → 5 条**）；`11:335`/`11:500`（只提 store、仍写 24）。
- 实测佐证：`CharacterModal.tsx`/`dialogue-pages.ts`/`CanvasArrangeControl.tsx`/`character-frame-queue.ts` 加入后均为 **24（0 新增）**，`writer-state.ts` 单独加入为 **25（净新增 `writer_message`）**。
- 影响：`13` 的 A1 判据（「与本次实测一字不差」）会与契约要求的基准冲突，验收时会被判未完成。

### F5（P2）`12 §6` 与自身表格自相矛盾

- `12:339`「**L2 只增列两个文件**——`CharacterModal.tsx` 与 `live-call-store.ts`」。
- `12:331-336` 同节表格：四处标**补**、`writer-state.ts` 标**增列**（共 5 个）；`12:325` 仍写「计数不变……`consumed` 仍为 **24**」。

### F7（P2）`11` 对契约 §2.3 节流措辞的描述已过期

## ③ 总判

**不通过**：符号/命名层全绿，但**契约 §9 的两条裁定（U2、U3）、§4.3 的守卫放宽在子文档中均无落点**，且门禁登记面（`CONSUMERS` 范围与基准、`BODIES.file`）在 `10`/`11`/`12`/`13` 之间尚未收敛为同一口径——按现文档实现会同时产生「漏改守卫」「漏消费 `error` 帧」「门禁基准对不上」三类偏差。
