## 0. 一句话

**玩家在角色对话框（`CharacterModal`）里把「文字」切成「通话」，就与同一角色进入 GPT-Live 全双工语音；后端与 nook 通话共用同一条 `/api/live/*` 通道，本批只新增前端落点、一个全局单例通话归属，以及对话框内的通话版面。**

三条不变量沿用 `00` §0，**一条都不新增**：

1. **角色 agent 仍是唯一的角色大脑**。语音前端只是嘴和耳朵。
2. **不引入第二份叙事状态**。通话不写世界正文、不写会话状态文件之外的真相。
3. **文件与事件仍是真相源**。通话产生的世界改动仍走动作层 + `world_event` / `file_changed`。

**为什么这件事本身很小**：后端 `/api/live/*` 只认 `characters/<id>/`（`routes/live.ts:76-115`），

**绑死在 nook 上的只有那个按钮。**

## 2. 通话归属：全局单例（本批冻结）

### 2.1 同一时刻至多一条通话

**冻结**：前端任一时刻**至多一条活跃通话**，跨角色。

理由（三条，缺一不可）：

1. **同一时刻只该有一路角色语音在播**。两条通话会让两路音频叠加，玩家无法分辨谁在说话。
2. **nook 与对话框可能同时对同一角色可见**：`App.tsx:1054` 的 `openCharacter` 允许在 nook 打开时叠加对话框（caller slot = nook）。归属若留在组件本地，两处 UI 会各说各话——nook 显示「通话中」而对话框同时显示「可以通话」。单例让它俩自动一致，**不需要新帧、不需要 App 中转**。
3. `00` §2.9 的按分钟计费下，同时两条通话就是双倍支出。

**与后端的关系**：后端仍是「每个角色至多一条」（`00` §2.4 冻结 1，`live-session.ts:382-386`）。前端比后端更严格，**不会冲突**——前端永远不会同时发出两条。

**MUST NOT**：把「哪条通话活跃」做成第二份全局真相、新 WS 帧，或写进世界文件。它是**本进程内的客户端运行态**，与 `agent-cursor.ts:409` / `overlay-admission.ts:26` 同级。

### 2.2 store 接口（`apps/web/src/lib/live-call-store.ts`，NEW）

Module-level 单例，持有全部 WebRTC 资源（`RTCPeerConnection` / data channel / `MediaStream` / `Audio` / 字幕段）。**组件不再持有资源**——否则「谁发起谁断开」无法在 nook 与对话框之间成立。

**落定（2026-09-15，11 号文档 §2.1 对齐）**：接口签名以 `docs/live-voice/11-通话归属单例store.md §2` 为**实现级唯一真相**；本文只冻结语义与不变量。11 号在此基础上新增了 4 个成员：`ensureConfig()`（惰性就绪探测）、`clearAll(reason)`（世界消失自清）、`tick(now)`（250ms 惰性时钟）、`createLiveCallStore(deps)` / `resetLiveCallForTest()`（测试缝）。**本批以 11 号 §2 为最终签名**，下方 `ts` 块保留为语义示意。

```ts
/** 全局快照。未通话时 characterId 为 null 且 phase 为 'idle'。 */
export interface LiveCallState {
  phase: 'idle' | 'connecting' | 'live' | 'error';
  error?: string;
  /** 正在通话的角色 id；无通话时为 null。 */
  characterId: string | null;
  /** 发起方入口的唯一标识（`"nook:<id>"` / `"dialogue:<id>"`），用于 owner 语义。 */
  owner: string | null;
  inputText: string;
  outputText: string;
}

/** 角色真实台词（既有帧的投影，§3）。 */
export interface LiveCallLines {
  streaming: string;
  lines: string[];
}

export interface StartCallOptions {
  characterId: string;
  locale: 'en' | 'ja';
  /** 发起方入口标识；`stop()` 只在 owner 匹配时挂断。 */
  owner: string;
}

export interface LiveCallStore {
  subscribe(listener: () => void): () => void;
  getSnapshot(): LiveCallState;
  getLines(): LiveCallLines;
  /** 服务端就绪门禁（`GET /api/live/config`）。订阅前可能尚未解析，默认 false。 */
  isAvailable(): boolean;
  /** 必须在用户动作里调用（getUserMedia）。已有通话先关闭再开新的。 */
  start(opts: StartCallOptions): Promise<void>;
  /**
   * 挂断。幂等。不传 `owner` 时关掉当前那条（无条件）；传了则**只在 owner 匹配时挂断**，
   * 否则不动也不报错（§5.1）。
   */
  stop(owner?: string): Promise<void>;
}

/** React 绑定：`useSyncExternalStore`，两个 hook 各读一份快照。 */
export function useLiveCallState(): LiveCallState;
export function useLiveCallLines(): LiveCallLines;
export function useLiveCallActions(): Pick<LiveCallStore, 'start' | 'stop'>;
/** 就绪门禁；false 时调用方 MUST NOT 渲染通话入口（`00` §2.9）。 */
export function useLiveCallAvailable(): boolean;
```

**冻结五条**：

1. **`start()` 换角色前 MUST 先 `stop()` 旧通话**，不叠加。这与后端 §2.4 冻结 1 同语义，只是提前到前端。
2. **`stop()` 幂等**，且**只有 store 发 `POST /api/live/close`**。组件 MUST NOT 直接发 close。
3. **store 无 React 依赖**：不 import React，不用 hook。`useSyncExternalStore` 的绑定是独立导出。
4. **`state.characterId` 只用于「归属」判定**，MUST NOT 被当作「角色 agent 正在运行」的证据。
5. **入口关闭 = 挂断，且只挂断本入口发起的那条**（owner 语义，见 §5.1）**。player 离开全屏投影后，画布与世界里没有任何可见的通话 UI 或挂断入口——续存就是静默计费，违反 `00` §2.9 的成本约束与「降级必须可见」。

   **守卫（2026-09-15 补，nook 侧）**：该不变量的 nook 执行者是 `NookView.tsx:201` 的卸载 cleanup
   `useEffect(() => () => void stopCall(\`nook:${characterId}\`), [characterId, stopCall])`。它**已有测试守卫**——`apps/web/test/live-call-store.test.mjs` 的 `leaving the nook hangs up the call this entry opened` 一条，断的是**行为**不是行存在，三条注入回归实测均变红（删整行 / 去 owner scoping / 依赖数组改 `[]`）。
   **背景**：该行曾被一次无关的行锚定编辑（空体 `PUT` 被解释为删除）吞掉，且**测试当时未变红在该处**，靠跨会话告警才发现；详细复盘见 `20-角色栏通话可行性调查.md §7`。

### 2.3 字幕来源：既有帧 + 语音前端转写（沿用 `00` §2.8）

**冻结**：store 自己监听 `window` 的 `airp:character-frame` DOM 事件（`useWorld.ts:786` 派发），按 `state.characterId` 过滤 `character_delta` / `character_message` / `character_idle`。**MUST NOT 新开 WS、MUST NOT 新增帧名。**

节流（**本批新增的实现约束**）：帧可能逐 token 到达，**MUST NOT 每个 delta 都通知订阅者**（会让两个 UI 每 token 重渲染）。**落定：照 `apps/web/src/lib/agent-activity-store.ts` 的「250ms 惰性 tick + 只在内容真变时换引用」体例**（该文件头注释原话：*"The list reference only changes when the list really changes, which is what useSyncExternalStore's Object.is check needs — and what keeps the 250ms tick from re-rendering an idle rail."*）。这同时满足 `useSyncExternalStore` 的引用稳定性要求与可测性（测试可直接调 `tick(now)`，无需真定时器）。**MUST NOT** 改成每 delta 通知；也不要用变量键式的后续优化替代 —— 体例以 `agent-activity-store.ts` 为唯一先例。

**展示规则**（沿用 `NookView.tsx:754-797` 的既有次序，本批不另立）：先角色真实台词（`lines` 已提交 + `streaming`），仅当 `streaming === ''` 时显示语音前端自己的 `outputText`，最后是玩家 `inputText`。**同一句话不得打印两次**。

## 3. 对话框落点（`CharacterModal`）

### 3.1 模式：默认文字，通话是可选第二条路

| 项 | 文字模式（现状，**不动**） | 通话模式（新增） |
|---|---|---|
| 输入 | 输入框 + STT 麦克风按钮 | 麦克风直连 GPT-Live（WebRTC） |
| 角色回复来源 | `character_message` → 逐页 | 同左（delegation 回灌后由语音前端说出） |
| 声音 | `/api/tts` 逐页朗读 | GPT-Live 语音；**逐页朗读关闭** |
| 纸面 | 分页逐字显示 | 通话版面（字幕 + 挂断） |
| 开场 mock 问候语 | 显示并朗读 | **不显示、不朗读** |

**冻结**：
1. **`available:false` 时 MUST NOT 渲染模式切换**（`00` §2.9），文字模式照常——不是渲染一个点了报错的按钮。
2. **进入通话 MUST 是显式动作**（点「开始通话」）。`00` §2.9：MUST NOT 自动开通话，建会话预扣 15 秒。
3. **通话中 MUST NOT 发 `/api/tts`**：`prefetchVoice` 的调用点需加通话门（§5.2）。
4. **通话中 MUST NOT 发 `character_prompt`**：文字输入区在通话模式下不渲染，键盘 Enter 不发送。
5. **退出通话**（点挂断 / 切回文字 / 关对话框 / 世界切换）**MUST 调 `stop(owner)`**。

### 3.1.1 ⚠️ 关对话框会杀角色 agent（实测核对，MUST 处理时序）

**实测事实**：`App.tsx:1116-1132` 的 `closeCharacter` 会 `sendMessage({ type: 'character_stop' })`，服务端 `index.ts:302` 收到后调 `lifecycle.stopCharacter`（`lifecycle.ts:239-249`）**杀掉该角色的 agent 进程**。而 `closeNook`（`App.tsx:386-400`）**不发** `character_stop`。

**这为什么是问题**：`00` §2.4 冻结 2 规定「挂断不杀角色 agent」，理由是下一通常紧接着来。但走对话框路径时，**关对话框这一步本身就会杀掉 agent**，与通话的时序叠加会出现两种坏情况：

1. **先挂断再关**（`stop(owner)` 在 `handleClose` 里）：安全。通话已收，agent 随后被杀，符合既有语义。
2. **先关再挂断**（卸载 effect 里才 `stop`）：通话仍在，agent 已被杀 → 若此刻正好有一条 delegation 在跑，`runDelegagation` 的 `client.promptAndWait` 会失败，走「角色 agent 不可用」路径（`live-session.ts:626-633`）并可见报错。**这是可接受的降级**（有可见错误、通话被收），但不应靠运气——**MUST 先挂断再关**。

**冻结**：`CharacterModal` 的关闭路径 MUST **在发起 `onClose()`（进而 `character_stop`）之前**调用 `stop(owner)`。落点：`handleClose`（`CharacterModal.tsx:494-501`）的 `setClosing(true)` 之后、`closeTimer` 回调之前，**或** `requestClose`（`:502-506`）内——子文档 `12` 必须选定一处并说明为何另一处不够。

**漏了会怎样**：竞态窗口内若在途 delegation 正好撞上 agent 被杀，玩家在通话里听到「我没能查证」的降级话术，且原因（关对话框）与表象（角色说查不到）无法对应——**失败可见但归因错误**。

**补充（不影响本批结论）**：`stop(owner)` 与 `character_stop` 是两条独立路径，前者只收 Live 会话与 sideband（`live-session.ts:429-444` 不动 agent），后者杀 agent。**本批 MUST NOT 改动 `closeCharacter`**——它是既有行为，本批只调整自己这一侧的时序。

### 3.2 与文字模式的互斥（同一对话框内）

同一对话框内文字与通话**互斥**：切到通话即停逐页朗读与输入；切回文字时若通话未挂断，**先挂断**。

### 3.3 开场问候语：通话模式下不播种

`CharacterModal.tsx:590-609` 的 mock 问候语在通话模式下 MUST NOT 播种（它会被 `/api/tts` 朗读，与通话冲突）。切回文字模式时按文字模式既有逻辑处理（已播种过则不重复）。

## 4. 跨入口互斥（nook ↔ 对话框）

### 4.1 归属单一，状态自动一致

- nook 通话中打开**另一个**角色的对话框 → 对话框显示「空闲」，且「开始通话」**MUST 可点**，点了会**先挂断 nook 那条**再开新的（§2.2 冻结 1）。

  > **L3 修正（2026-09-15，`30` §4.2 冻结 7）**：本行与 `12:77` 的 `disabled={callActive}` 曾互相矛盾——`callActive` 是**全局**的，会让「另一个角色」的按钮也被禁用，上面这条「可点 → 先挂断再开」**永远不会发生**。两份文档的**意图本不冲突**（`12:93` 要的是「错误态可重试」），是取值把两件事捆在了一起。**裁决**：`disabled` MUST 用 `callActive && call.characterId === characterId`——错误态下 `callActive` 为 false ⇒ 可点重试；他角色持有通话时 `characterId` 不匹配 ⇒ 不误禁。`aria-pressed` 继续用 `callVisible`（不变）。

- 某角色在 nook 通话中 → 对话框对同一角色显示「通话中」并可挂断；
- 某角色在对话框通话中 → nook 对同一角色显示「通话中」并可挂断；
- nook 通话中打开**另一个**角色的对话框 → 对话框显示「空闲」，点通话会**先挂断 nook 那条**再开新的（§2.2 冻结 1）。

**MUST NOT** 在两处各维护一份「本组件是否在通话」的 state。

### 4.2 与角色 agent 的双重驱动互斥（`00` §7.1 未决 1 的裁决）

**冻结为双向互斥**：同一角色**同一时刻只能有一条驱动路径**（文字对话框 / 通话）。

- 已有的单向守卫保留：`NookView.tsx:217-226` 在 nook 通话中阻止打开对话框（提示 `liveCallModalBlocked`）。
- **新增反向守卫**：对话框通话中，nook 的通话按钮对同一角色显示为「挂断」（同一条通话），而不是「开始通话」——由 §4.1 的单例自动成立，**无需新守卫**。

**为什么不需要「对话框通话中不许进 nook」的硬拦截**：nook 本身不驱动角色 agent（它只渲染画布 + 留便签），进入它不会造成双重驱动。真正要防的是**两条通话**与**通话中打字发 prompt**，两者分别由 §2.2 冻结 1 与 §3.1 冻结 4 覆盖。


### 4.3 ⚠️ nook 侧守卫必须从「全局在通话」放宽为「同一角色在通话」

**⚠️ 前提已被实测推翻（2026-09-15，评审 E8 抓出，主 agent 已亲自复核）**：本节初版写「**已有的**单向守卫保留」、并把下面的代码称作「现有守卫」——**两处都不成立，那个守卫是死代码。**

**实测**（`apps/web/src/components/nook/NookView.tsx`）：

- `:197` 定义的 `handleOpenCharacterModal`（含 `:199-202` 的 `if (callInProgress) { setNotice(liveCallModalBlocked); return; }` 拦截）**全文件唯一引用是 `:205` 它自己的依赖数组**；
- 真正传给画布的是 `:626` 的 **`onOpenCharacterModal={onOpenCharacterModal}`**——**原始 prop**（`:156` 解构的那个），**绕过了包装函数**；
- `App.tsx:1196`/`:1245` 也把 `openCharacter` 直连给 `Canvas`。

**后果**：`liveCallModalBlocked` 在**本批前后都不会触发**。§4.2 宣称的「双向互斥」第一支（nook 侧硬挡）**没有任何强制点**；本章整节以此为前提出，故必须连带修正。git 史：`2c1684b`（L 批）曾正确接线，`95f2b55` 断开——**既有缺陷，非本批引入**。

**冻结（两条，缺一不可）**：

1. **接线修复（MUST）**：`:626` 的 `<Canvas>` MUST 改传 **`handleOpenCharacterModal`**（包装后的函数），使守卫真正生效。**MUST NOT** 只改守卫逻辑而不接线——那会让 §4.3 成为「可实施但零行为」的空改动。
2. **放宽（MUST，原冻结沿用）**：守卫判据从「全局在通话」放宽为「同一角色在通话」：

```ts
const callInProgress = call.phase === 'connecting' || call.phase === 'live';
const sameCharacterOnCall = callInProgress && call.characterId === id;  // 放宽点
// 仅 sameCharacterOnCall 时 setNotice(liveCallModalBlocked) + return
```

## 5. 与既有实现的接缝（MUST 逐条兑现）

### 5.1 迁移 `useLiveCall` → store（**本批最重的改动**）

`apps/web/src/lib/live-call.ts` 的 `useLiveCall` 是**组件级**的：资源在 `useRef`、字幕段在 `useRef`、卸载时自动 `POST /api/live/close`（`live-call.ts:469-486`）。这套所有权**无法**支撑两个入口共享一条通话。

**冻结**：把状态机与全部资源搬进 `live-call-store.ts` 的 module-level 单例，`live-call.ts` 改为薄的 React 绑定（或直接删除，由 store 文件导出 hook）。

| 项 | 现状 | 本批 |
|---|---|---|
| 资源所有权 | 组件 `useRef` | store module 变量 |
| 卸载行为 | 自动 close（`live-call.ts:469-486`） | **按 owner 判定后 close**（§2.2 冻结 5） |
| `characterId` | hook 参数，绑定组件生命周期 | 快照字段，可跨组件存活 |
| 字幕 | 组件 state | store 快照（§2.3 节流） |

**MUST NOT**：让组件卸载关掉「不是它发起的那条通话」。判据是 `state.characterId === 本组件角色` **且** 本组件是发起方，不满足则不动。

**为什么卸载要 close（且只 close 自己的）**：nook 与对话框都是**全屏投影**，一次只有一个在前台（`App.tsx:1164-1207` 按 `nookChar` 二选一；对话框是 `dialogue` Depth 的 overlay）。玩家挂断的唯一可见入口就在当前投影里。一旦离开投影（关对话框、关 nook、切世界），画布与世界没有任何通话 UI，通话如果续存就是**静默计费**——这正是 `00` §2.9 与「降级必须可见」禁止的。

**owner 语义**：`start({owner})` 记录发起方；`stop()` 带 owner 时**只在 owner 匹配时挂断**。这样 nook 卸载不会误关对话框发起的通话，反之亦然。

**MUST NOT**：用「当前快照的 characterId === 本组件角色」当唯一判据——两个入口可以是同一角色（§4.1）。
