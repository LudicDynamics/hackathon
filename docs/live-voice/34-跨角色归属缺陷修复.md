## 1. 一句话定位

修复 L2 遗留的**两个同根缺陷**：三处通话 UI 把**全局快照**（`call.phase` / `call.phase === 'connecting' || 'live'`）当成了**本载体的归属**，因而（1）nook 的按钮会**挂断别人的通话**，（2）对话框的按钮会**被他角色的通话误禁**；并回答「还有没有第三个」——§7 的全局扫描给出**肯定答案，多出两个同型位点**。

## 2. 根因：一条判据被用在了两个问题上

`30` §2.2 冻结 1 逐字：

> **MUST NOT 用全局快照冒充「本载体的归属」**。判据：一个载体若要问「这条通话是不是我的」，MUST 比较 `call.characterId === <本载体的角色>`，MUST NOT 只看 `call.phase`。

`live-call-store.ts` 的 `LiveCallState` 是**一颗全局快照**（今日 `:30-40`，注释逐字「The global snapshot」）：

| 字段 | 今日行 | 含义 |
|---|---|---|
| `phase` | `:32` | **全局**：是否存在一条正在传输的通话 |
| `characterId` | `:36` | 该通话**属于哪个角色** |
| `owner` | `:53` | 该通话**由哪个入口发起** |

两个**不同**的问题被同一段代码回答：

- **Q1「有没有通话在跑？」** → 正确答案是 `phase !== 'idle'`，**载体无关**。用途：资源门、TTS 短路、并发去重。
- **Q2「这条通话是不是我的？」** → 正确答案是 `call.characterId === characterId`，**载体相关**。用途：按钮文案、按钮可点性、字幕归属、挂断对象。

**缺陷 1/2 都是「用 Q1 的答案去回答 Q2」**。这个字样贯穿全文：**下文把 Q1 的取值叫 `callTransporting`，Q2 的取值叫 `callMine`（或其合取 `callVisible`）**。

`store` 侧本来是对的：`stop(owner)` 有守卫（`live-call-store.ts` 的 `async function stop(owner?: string)`，今日 `:640`）：

```ts
// The lifecycle guard (§3.1-2): an entry only hangs up the call IT opened.
if (owner !== undefined && committed.owner !== owner) return;   // :642
```

⇒ **缺陷全在 UI 层**，`store` 不改形状（`30` §2.2 冻结 1）。

### 3.2 实测复现（`30` §4.1 的证据 + 本文的独立重放）

```

    closePosts=1 sessionPosts=1
    >>> DEFECT 1 REPRODUCED
```

**最后一段是「两处必须同批」的全部理由**（`30` §4.1 冻结 6 的补充，来自并行会话 `01a0a16c`）：`stop('nook:watson')` **静默 no-op**。若只把 `:696` 改成带 owner 而**不改判据**，按钮仍显示「Hang up」、仍走 `stop(\`nook:<自己>\`)` ⇒ **从「误挂别人的」变成「点了没反应」**——玩家看到挂断入口而它不作功，比原缺陷更坏（违反 `30` §5.2 的「挂断入口必须可达且作功」）。

## 6. 顺带：`phase: 'error'` 的 nook 缺口（`33` §13-V-1，本文一并收口）

`33` §5.3 发现 nook 在 `phase === 'error'` 时**没有挂断入口**，并把它归给本文裁决（`33` §14 未决 2）。**主 agent 已裁定「本批必修」，并冻结为 `30` §5.3 冻结 9**（该条同时采纳了本文 §3.3/§6.2 的修法）；本文 §6 即该冻结条款的实现说明，`30` §5.3 是权威出处。冻结 9 的三条 MUST：判据为 `callMine && (callInProgress || call.phase === 'error')`、error 时按钮显示挂断、`role="alert"` 保留在通话 lane 内——与本节 §6.2 逐条对应。**本文的裁定：本批必修，且它正是缺陷 1 的同型**。

### 6.1 事实（实测）

基线矩阵（§3.5 探针）：`X error` ⇒ 按钮显示 **Speak aloud**、字幕 lane **隐藏**、alert 显示。原因：`callInProgress`（`:183`）**不含 `error`** ⇒ `:744` 的门为假；`:690` 的 `if (call.phase === 'idle' || call.phase === 'error')` 落入 `startCall` 分支。而 **error 时资源可能仍活着**——store 的 `fail()`（`:416-418`）只 `commitState({ phase: 'error', … })`，**不 `releaseLocal()`**。实测（探针 §9.5）：

```
after live:                     {"phase":"live", tracksStopped:0, closedPeers:0}
after character error frame:    {"phase":"error","error":"sideband lost",
                                 tracksStopped:0, closedPeers:0, closePosts:0}   ← 麦克风与 peer 都还活着
after explicit stop:            {"phase":"idle", tracksStopped:1, closedPeers:1, closePosts:1}
```

⇒ **error 是「可能仍在计费」的相位**。它必须有一个**可点的挂断入口**，而现状没有（玩家只能点「Speak aloud」= 重新 `start`，那是**又开一条**）。

### 6.2 修法

即 §3.3 的 `callVisible = callMine && (callInProgress || call.phase === 'error')`——**与对话框 `:146` 的口径逐字同款**（`33` §5.3 明确把 `:146` 称作「正确范式」）。实测结果（§3.5 矩阵的 `X error` 行）：按钮变 **Hang up**、字幕 lane 出现、alert **保留在 lane 内**（`:731` 的 `callVisible && call.phase === 'error' && call.error` 仍渲染，因为 `callVisible` 为真）⇒ **`role="alert"` 不会随版面一起消失**，正是 `CharacterModal.tsx:143-144` 注释要求的性质。

**为什么这是「调判据」而不是「加功能」**：字典里 `error` 本来就在 `LiveCallState['phase']`（`:32`），`callVisible` 本来就在对话框里含它。nook 只是漏了同一处理。**O(1) 行、零新概念**。

### 6.3 为什么不改 store（把 `fail()` 改成 `releaseLocal()`）

**否决**。理由：`err` 的语义是「这条通话**失败了，但可能还能重试/还能挂断**」——`CharacterModal` 的 `Close`（`:1018`）与「错误态可重试」（冻结 7）都建立在「错误后本地方仍在」之上。若 `fail()` 直接释放资源，`:1018` 的 `Close` 就变成纯 UX 摆设，且**冻结 7 的 I-2 会被架空**。⇒ 资源释放的唯一责任点是 `stop()`（显式挂断），本设计保持它。
