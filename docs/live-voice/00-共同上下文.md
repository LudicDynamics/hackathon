## 0. 一句话

**玩家在 nook 里按下"开口说话"，浏览器与 `gpt-live-1` 建立 WebRTC 全双工语音；服务端用 sideband 挂在同一会话上，把每一次 delegate 转成一条现有 pi-rp 角色 agent 的回合，再把角色的真实台词回灌给语音前端说出来——角色人格、世界知识、动作工具一行都不重写。**

三条不变量（与根 `AGENTS.md` §2 对齐）：

1. **角色 agent 仍是唯一的"角色大脑"**。语音前端只是嘴和耳朵，不是第二个角色。角色说的话必须来自 `characters/<id>/` 那份 preset + 会话文件；GPT-Live 只负责把它说出来。
2. **不引入第二份叙事状态**。通话不写世界正文、不写会话状态文件之外的真相；角色在通话中调用的 `chalk`/`move_to`/… 仍走动作层并落事件（这一点由现有引擎免费兑现）。
3. **文件与事件仍是真相源**。通话产生的世界改动，全部通过现有 `world_event` / `file_changed` 被 nook 重取，不需要新机制。

## 1. 为什么是 GPT-Live + client delegation（本批的选型结论）

选型完成于 2026-09-14，实测证据见 §12。

| 方案 | 判定 | 理由 |
|---|---|---|
| **Realtime API**（`gpt-realtime-2`） | **否决** | 单模型：说话、推理、调工具在同一个模型里。工具执行期间语音停滞，做不出"一边做事一边回答"。要用它就得把角色人格/世界上下文/工具语义**整个搬进 Realtime session**——等于在 pi-rp 之外再造一个角色，违反不变量 1 |
| **链式管线**（浏览器 STT → 现有角色 → 现有 `qwen3-tts-flash`） | **备选，不采用** | 角色逻辑与音色零改动，但延迟高、无 barge-in、无 backchannel；"一边做事一边回答"直接没有 |
| **GPT-Live + client delegation** | **采用** | 前端模型只管对话节奏与 backchannel，后端异步干活；delegation 的目标就是"你自己的模型/agent/服务"——**形状与我们架构同构** |

**关键机制**：client delegation 下，`session.delegation.created` 只带 `delegation.id` 与元数据，**不带任务文本**（上游原文："The delegation object contains metadata, not task text"）。任务文本要我们从 transcript 事件自己攒。这正是我们要的——它把"听懂之后干什么"完全交给我们，也就是交给 pi-rp 角色。

## 2. 共享形状（本批冻结）

### 2.1 通道边界：三条语音通道互不重叠

| 通道 | 入口 | 归属批次 | 本批处置 |
|---|---|---|---|
| 遮罩内翻页朗读 | `CharacterModal` → `POST /api/tts` | `docs/tts/` | **不动**，不删不改 |
| nook 实时通话（**本批新增**） | nook 内通话按钮 → `POST /api/live/session` | 本批 | 新增 |
| 其它朗读位 | —— | —— | 不允许出现 |

**冻结**：`docs/tts/` 的端点、缓存、音色解析、`/api/tts/config` 就绪门禁**一律不改**。本批只**新增** `/api/live/*`，并且**共享**音色映射的唯一真相源（§2.6）。

**MUST NOT**：让通话复用 `POST /api/tts`（单向合成，做不出双向）；也**MUST NOT** 让 `POST /api/tts` 走 GPT-Live。

### 2.2 端点（本批新增，全部在 `/api` 下）

| 路由 | 请求体 | 200 响应 | 归属 |
|---|---|---|---|
| `POST /api/live/session` | `{ character: string, sdp: string, language?: 'en' \| 'ja' }` | `{ ok: true, sessionId: string, sdp: string, character: string, voice: string }` | 建会话 + 挂 sideband + 确保角色 agent 运行 |
| `POST /api/live/close` | `{ character: string }` | `{ ok: true }` | 收会话 + 摘 sideband（**不杀角色 agent**） |
| `GET /api/live/config` | ——（无 body） | `{ ok: true, available: boolean, reason?: string, model: string, voices: string[] }` | 就绪门禁，形状对齐 `/api/tts/config` |

**冻结四条**：

1. **`sdp` 是浏览器 SDP offer 的原文**（`RTCPeerConnection.localDescription.sdp`）。服务端**不解析 SDP**，原样转给 `POST /v1/live/sessions` 的 `transport.sdp`。
2. **`sessionId` 是不透明值**。服务端与前端都 MUST NOT 构造或解析它（上游原文："Treat the session ID as an opaque value"）。前端只在 `POST /api/live/close` 时不需要它（用 `character` 定位）。
3. **`voice` 是解析后的 GPT-Live 音色名**（§2.6），回显给前端做 UI/诊断。
4. **响应体走 `reply()` 约定**：成功 `{ ok:true, ...}`，失败 `{ ok:false, code, error }`（`docs/wiring/00 §6`）。

**为什么 close 用 `character` 而不是 `sessionId`**：会话是**每个角色至多一条**（§2.4），`character` 是稳定键；`sessionId` 由 OpenAI 生成、前端不该持有语义。

### 2.3 传输：WebRTC（媒体）+ sideband WebSocket（服务端）

| 角色 | 传输 | 拥有什么 |
|---|---|---|
| 浏览器 | WebRTC 对等连接：麦克风轨入、合成语音轨出，`oai-events` data channel | 麦克风采集、扬声器播放、**字幕与麦克风状态** |
| 服务端 | sideband：`wss://api.openai.com/v1/live/sessions/{session_id}/attach` | **delegation 执行**、transcript 累积、`session.*.append` |

**冻结**：

- **音频只走 WebRTC 媒体轨**。浏览器 MUST NOT 发 `session.input_audio.append`，也 MUST NOT 期望 data channel 上的 `session.output_audio.delta`（上游原文）。服务端 sideband **只能收**反射音频，**不能发**。
- **`session.start` 由 HTTP 请求隐式完成**。浏览器 MUST NOT 在 data channel 上发 `session.start`（上游原文："Do not send `session.start` on the data channel"）。
- **每个动作只有一个 owner**（上游原文："Assign one owner for each action"）：
  - **服务端 owner**：delegation 的接收与回灌（`session.commentary.append`）、`session.instructions.append`。
  - **浏览器 owner**：媒体轨、`session.close` 的发起、字幕 UI。
  - **两边都收得到**（data channel 与 sideband 各一份）不算重复，只要**执行**只发生一次。

**为什么不是"浏览器转发 delegation 给服务端"**：transcript 累积与角色回合必须成对发生在服务端；让浏览器做这段转发会把"哪些话进了角色"的真相切到前端。sideband 让服务端**从第一秒就观察会话**（上游原文："Attach early if the backend needs to observe the conversation from the start"）。

### 2.4 会话与角色 agent 的生命周期

```
玩家点「开口说话」
  → POST /api/live/session
      1. 校验 character 合法（isValidCharacterId）且 nook 存在（characterRootConfigOf / statKind）
      2. 确保角色 agent 在跑：lifecycle.getCharacter(id) 命中则复用，
         否则 lifecycle.startCharacter(id, worldRoot)          ← 懒加载，与遮罩同一条 spawn 路
      3. 解析音色：resolveLiveVoice(README.frontmatter.voice)  ← §2.6
      4. 拼 instructions（§2.5），POST /v1/live/sessions（delegation:{type:'client'}）
      5. 用返回的 session.id 开 sideband WS，挂三种 append 通道
      6. 回 { sessionId, sdp, character, voice }
  → 浏览器 setRemoteDescription(answer)，等 data channel 的 session.started
  → 期间/此后：sideband 收 delegation → 跑角色回合 → commentary.append

玩家点「挂断」
  → 浏览器发 session.close（等 session.closed）
  → POST /api/live/close → 服务端 session.close 兜底 + 摘 sideband
     **不调用 lifecycle.stopCharacter**：角色 agent 留着，下一通复用
```

**冻结三条**：

1. **每个角色至多一条活跃通话**。已有活跃会话时再次 `POST /api/live/session` → 先关旧会话再建新的（幂等重连），不叠加。
2. **挂断不杀角色 agent**。角色 agent 的回收仍由现有遮罩/换世界路径（`character_stop` / `stopCharacters`）负责。理由：通话结束常紧接着再来一通；spawn 是重量级动作（`lifecycle.ts:215-216` 无条件 stop-then-spawn）。
3. **世界切换 / 存档被删 → 必须收掉所有通话**。与 `docs/AGENTS.md §2` 的 `409 no_active_world` 同源：活跃世界消失时，通话会话与 sideband MUST 一并关闭，不得留下指向死世界的角色回合。

### 2.5 `instructions`（语音前端提示词）的内容边界

**冻结**：`instructions` 由服务端拼装，**MUST NOT** 由前端传入（前端传 `language` 即可）。

内容只允许这三块，合计 ≤ 16384 token（上游上限）：

1. **角色身份一句话**：从 `characters/<id>/README.md` 的 `name` + 一行 `description`（缺省则只用 name）。
2. **说话语言**：按 `language` 用该语言书写（上游："Write your prompt in the language you want the model to speak"）。
3. **delegation 策略三标签**（上游规定的结构，**标签名 MUST 保留**）：`Backend tools` / `Delegate to the backend when` / `Do not delegate to the backend when`。

**MUST NOT 进 `instructions`**：角色的完整人格文件、世界状态注入、工具 schema、`[emo: tag]` 输出格式约定。这些**全部留在角色 agent 的 preset 里**（不变量 1）——语音前端只需要"什么时候该叫人"。

> **`[emo: tag]` 不进语音前端**：情绪标签是角色对**画布**的输出格式，由角色 agent 的 preset 负责；语音前端收到的是 §2.7 已消毒的台词。

### 2.6 音色映射：扩展唯一真相源，不新建第二张表

**冻结**：音色别名的**唯一真相源仍是 `packages/shared/src/rules/voices.ts` + `docs/tts/07-音色别名映射.md`**。本批只在**同一模块家族**新增一个解析函数，**MUST NOT** 另建一张平行的别名表。

```ts
// packages/shared/src/rules/voices.ts（同文件新增，NEW）
/** 角色声明的 voice 别名（或原始 id）→ GPT-Live 音色名。未知输入返回 DEFAULT_LIVE_VOICE。 */
export function resolveLiveVoice(name: string | undefined): string;
/** 默认 GPT-Live 音色。 */
export const DEFAULT_LIVE_VOICE: string;
/** 本批允许的 GPT-Live 音色白名单（供 /api/live/config 回显与门禁断言）。 */
export const LIVE_VOICES: readonly string[];
```

映射规则（**确定性，无随机**）：按 `VoiceEntry.gender` 选同性别音色，再按 `tone` 的语义挑最接近的一条；表内逐别名显式写死，**不做字符串猜测**。

**为什么显式写死而不是"按 gender 二分"**：40 个别名若只分男女，同一世界两个同性角色会撞音色——与 `skills/voice-casting/SKILL.md` 的"同世界不撞音色"纪律冲突。逐别名写死才能保持区分度。

**回退**：`voice` 缺失（如 `templates/divergence/characters/young-ryo/README.md` 无该行）或别名未知 → `DEFAULT_LIVE_VOICE`，**并且 MUST 在 `/api/live/session` 响应里回显实际音色**（不静默）。

**硬约束（实测）**：非法音色名会被 `POST /v1/live/sessions` 拒为 **HTTP 403 `forbidden`**（实测 `girl-next-door` / `Cherry`）。因此 `resolveLiveVoice` 的返回值**必须在 `LIVE_VOICES` 白名单内**，且**门禁必须能机械核验**（§11）。

### 2.7 角色台词的消毒与分块（回灌前）

delegation 回灌用 `session.commentary.append`，其 `content` 是**纯字符串、≤ 500 token**（上游上限，硬约束）。

**冻结**：

1. **消毒**：角色 agent 的回复文本 MUST 先过 `sanitiseTtsText`（`packages/shared/src/rules/tts-text.ts`），剥掉 `[emo: …]` 标签与括号动作——与 TTS 通道同一条规则，不另写。
2. **分块**：超过 500 token 时按**句子边界**切块，顺序 append；**MUST NOT** 按字符硬切（会切断句子，语音前端念出半句）。
3. **`delegation_id` 必填**：回灌本任务结果用该次 `delegation.id`；会话级通用上下文用 `null`（上游："All appends … require `delegation_id`"）。
4. **回灌 ≠ 已播出**：`session.commentary.appended` 只证明"被接受"，**不证明**模型念了、玩家听到了（上游反复强调）。UI MUST NOT 用它会话状态当作"角色说完了"。

### 2.8 事件与帧：**本批不新增任何 WS 帧名**

**冻结**：通话中角色 agent 的回合产生的 `character_delta` / `character_message` / `character_idle` / `agent_activity` / `agent_progress` 帧，**由现有 `event-bridge.ts` + `lifecycle.ts` 自动发出**（`event-bridge.ts:152-153` / `:231` / `:373`；`lifecycle.ts:294`）。nook 通话 UI **直接消费这些既有帧**（按 `characterId` 过滤）。

**为什么不新增帧**：

- 通话 UI 的**状态**（连接中/已连接/已挂断）是**本组件局部状态**，广播给全局就是第二份真相（`AGENTS.md §2` 禁止）；
- 角色"在做事"的可视化已由 `agent_activity` / `agent_progress` 免费兑现；
- 角色的**真实台词是 `character_message` 的内容**，复用它是唯一正确的真相源。

**副作用（正面的）**：nook 通话 UI 消费 `character_delta` / `character_message` / `character_idle`（`NookView.tsx` 的 `frame.type ===` 分派），于是 `tools/check-ws-contract.mjs` 的 `CONSUMERS` 清单**新增两个文件**（`live-call.ts`、`NookView.tsx`），帧消费面从 2 个文件扩到 4 个。
  - ⚠️ **修正（2026-09-14，实现期实测）**：本节初稿写"`character_delta` 列为 KNOWN_DARK（已发未消费），消费它后该 finding 消失"——**这是错的**。实测：`character_delta`/`character_message`/`character_idle` 在 `useWorld.ts:559-561` **早已被消费**；`check-ws-contract.mjs` 的 `KNOWN_DARK` 是**修复提示的措辞表**（`compare()` 只在帧**确实未被消费**时才读它，`check-ws-contract.mjs:206-213`），不是断言、更不会因新增消费而"消失"。本批的真实门禁收益是**消费面登记**，不是 KNOWN_DARK 的增减。

**MUST NOT**：为通话新增 `live_*` 前缀帧名。若子设计认为非加不可，**先报冲突**（会同时触及 `docs/tools/12 §6.2`、`check-ws-contract.mjs` 的三张表、前端分派）。

### 2.9 配置与就绪门禁

**冻结**（对齐 `docs/AGENTS.md §2` 的 TTS 门禁与 `/api/tts/config` 的形状）：

- 凭据只用**服务端**的 `OPENAI_API_KEY`（`.env` / `.env.local`，`apps/server/src/index.ts:22-29` 已加载）。**MUST NOT** 下发到浏览器。
- `OPENAI_BASE_URL` 缺省 `https://api.openai.com/v1`（与 `connection-settings.ts:7-11` 同源）。
- **未配置时**：`GET /api/live/config` 回 `available:false` + `reason`；`POST /api/live/session` 回 `503 { ok:false, code:'unsupported', error }`。**MUST NOT** 发起任何 OpenAI 请求，也 **MUST NOT** 回落到 TTS 通道（回落会静默降级成"没有通话"）。
- **nook UI 在 `available:false` 时 MUST 不渲染通话按钮**（而不是渲染一个点了报错的按钮）。

**成本告知（设计约束，不是实现细节）**：

- GPT-Live 按**语音时长计费**（$0.05/分钟量级），**玩家沉默、后端干活时照收**。
- `POST /v1/live/sessions` 建 WebRTC 会话**预扣 15 秒**（起跑时抵扣，不是额外叠加）。
- 因此：**MUST NOT 自动开通话**；每次通话都必须由玩家显式动作发起。挂断是必须有的 UI。

### 2.10 语言

**冻结**：

- `language` 的取值域与 TTS 通道**同域**：`'en' | 'ja'`（`apps/web/src/App.tsx:942` 的世界语言口径）。
- **服务端不从 `world.json.locale` 读语言**。已实测：`locale` 不在 `WorldManifestSchema`（`packages/shared/src/schemas/world.ts:27-56`），服务端零读取；角色语言实际由角色 preset 的 `world-language` block 驱动。通话语言**由前端按世界语言显式传入**，与 TTS 完全同路。
- 缺省 `'en'`。**MUST NOT** 从角色名/角色 id 推断语言。

## 8. 错误边界（本批冻结的失败语义）

| 失败 | 判定 | 响应/行为 |
|---|---|---|
| 未配置 `OPENAI_API_KEY` | 服务端 | `GET /api/live/config` → `available:false`；`POST /api/live/session` → `503 unsupported`；nook **不渲染按钮** |
| `character` 非法 | `isValidCharacterId` 为假 | `400 invalid_argument` |
| nook 不存在 | `statKind` = missing | `404 not_found` |
| 无活跃世界 | 中间件 `needsWorld` | `409 no_active_world`（**已有中间件先拦**，与 `/api/nook` 同路） |
| OpenAI 建会话失败 | 非 2xx | 透传上游状态；`code` 取上游 `error.code`（如 `invalid_offer`），**不伪装成 500** |
| sideband 挂不上 | attach 失败 | 关闭已建的 Live 会话（不留半条），回 `502` + 可见 reason |
| 角色 agent spawn 失败 | `startCharacter` 抛错 | 同上：先关会话再回错 |
| delegation 后角色回合超时 | 等 `agent_settled` 超预算 | **`session.instructions.append` 告知语音前端"这次没查成"**（可见降级），并 `abort()` 该回合；**不静默** |
| 通话期间角色 agent 死亡 | 请求抛错 / 探测 | 同超时路径 + 通话 UI 显示可见错误（L-C2） |
| 挂断时会话已断开 | `session.close` 无响应 | 本地清理 + 摘 sideband；**不重试、不阻塞 UI** |

## 10. 验收（"功能上全面、效果上完整"的判据）

本批是实验性质，但**不许留下"看起来能跑"的半条链路**。以下每条都必须可观察：

1. 未配置 key → nook 里**没有**通话按钮（不是点了报错）。
2. 配置 key → nook 里出现通话按钮 → 点击 → **授予麦克风后能听见角色说话**（媒体轨通了）。
3. **玩家打断角色** → 角色停下听（barge-in 生效）。
4. **角色一边做事一边回答** → 玩家说一句需要动世界的话（如"把书桌收拾一下"），角色**先接话**，随后 `agent_activity`/`agent_progress` 帧出现（做事的可视化），世界文件**真的变了**（`file_changed` → nook 重取），最后角色**说出结果**。
5. **角色的台词是它自己写的** → `character_message` 的内容与说话内容一致（不是语音前端现编）；`.airpworld/sessions/char-<id>.jsonl` 里能看到这条回合。
6. 挂断 → 媒体停、会话收、角色 agent **仍在**（下一通复用不重新 spawn）。
7. 世界被外部删除 → 通话**自动收掉**，前端清画布（复用既有 409 路径）。
8. 音色：`voice: girl-next-door` 的角色与 `voice: wise-elder` 的角色，**通话音色不同**（映射生效）；未知/缺失 voice 的角色**照常能通话**（回退默认）。
9. 失败可见：拔掉 key 后重试通话 → UI 显示**具体原因**，不是静默无声。
