### 2.3 `check-i18n.mjs`：**新增 §3「动态键守卫」**（本批唯一新门禁；契约 `30` §3.3 的交付物）

#### 2.3.1 盲区的准确定性（主 agent 实测复核后的口径）

**不是 bug，是设计边界**：`check-i18n.mjs:47-49` 的注释逐字写着 —— *Dynamic keys (`t(someVariable)`) yield nothing and **intentionally not gated**.* 扫描器 `translationCalls`（`tools/lib/i18n-call-keys.mjs:16-22`）只认**标识符名为 `t`** 的调用，且只取**字面量**首参（`keys()` `:11-14`）。

**但后果真实**：`NookView.tsx` 的 `copy`（符号 `copy`，今日 `:174`）把 `UI_COPY.en` 的**值**当 key 查 `messages.json`：

```ts
const copy = Object.fromEntries(Object.entries(UI_COPY.en).map(([key, value]) =>
  [key, locale === 'ja' ? UI_COPY.ja[key] : translate(locale, value)])) as typeof UI_COPY.en;
```

- `locale === 'ja'` 支路走 `UI_COPY.ja`（有译文）⇒ **日文安全**；
- 其余（含 `zh-CN`）走 `translate(locale, value)` ⇒ **`messages.json` 里没有该 value 时 `entry?.[locale] ?? key` 回落成英文**（`i18n.ts:10-13`）。

**本次实测的盲区清单（8 个键；2 个动态读取点）**：

| 读取点（符号 + 今日行号） | 盲键 | `UI_COPY.en` 的值 | 后果 |
|---|---|---|---|
| `NookView.tsx` 的 `copy.liveCallStart` | `liveCallStart` | `Speak aloud` | **zh-CN 显示英文**（nook 通话启动按钮文案） |
| `NookView.tsx` 的 `copy.liveCallModalBlocked` | `liveCallModalBlocked` | `Finish the call before opening the dialogue.` | zh-CN 英文 |
| `NookView.tsx` 的 `copy.nookEmptyPrompt` | `nookEmptyPrompt` | `What should there be, here?` | zh-CN 英文（**非通话**，同一机制） |
| `NookView.tsx` 的 `copy.nookInitSkip` | `nookInitSkip` | `Skip` | zh-CN 英文（**非通话**） |
| `live-call-store.ts` 的 `copy.*`（`errorText`，`:263-278`） | `liveErrorUnconfigured` / `liveErrorMicUnsupported` / `liveErrorConnection` / `liveErrorGeneric` | 4 条错误文案 | **zh-CN 与 ja 都英文**（store 直接 `UI_COPY[locale]`，`:264`，绕开 `copy` 映射） |

> ⚠️ 上表第 5 行是**第二个读取点**：`DesignSharedComponent` 的组件只覆盖 nook **字幕段**；nook 的 **call lane**（`NookView.tsx` 的 `data-nook-zone="call"`，今日 `:686`）与 store 的错误文案**都还在盲区里**。⇒ 契约 `30 §3.3` 末句「是否顺手修由设计阶段评估」的答案是：**本批不迁这批文案**（迁它要动 `legacy-ui-copy.ts` 的 `Locale` 类型或新开 `messages.json` 键，属独立工作），**改为登记 + 门禁兜住不再扩大**。

**反向证据（门禁确实看不见）**：`node tools/check-i18n.mjs | grep -i "speak aloud\|voice calls\|finish the call"` → **零命中**（本次实测）。164 条 `warn` 是同一盲区的**镜像**（「有键、无字面调用点」，≡ 443 − 279），但 `warn` **不失败**（`check-i18n.mjs:78-82`）且**不含这 6 个键**（它们连 `messages.json` 条目都没有）。

#### 2.3.2 门禁设计（已用原型验证：今天绿、注入必红、修好后强制收缩）

**位置**：`tools/check-i18n.mjs` 的 `// 2. defined-but-unused`（`:77-82`）**之后**、失败判定（`:84-88`）**之前**，作为独立的 `// 3. dynamic-key reads`。

**形状（`shrink-only` 基线，与 `CONSUMERS` 同一条纪律）**：

```js

const DYNAMIC_KEY_CONSUMERS = [
```

| 全绿 | `ok` | `ok   i18n dynamic keys: 8 registered blind key(s), none new (baseline 8; shrink-only)` |

**非空性证明（本次实测，三次注入）**：

| 注入 | 结果 |
|---|---|
