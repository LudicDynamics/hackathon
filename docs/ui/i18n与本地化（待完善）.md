## 1. 机制现状（事实，非待办）

| 面 | 形态 | 位置 |
|---|---|---|
| UI 语言 | `en` / `zh-CN` / `ja`，存 `localStorage['airp-ui-locale']` | `apps/web/src/lib/i18n.ts` |
| 键表 | 英文原文**就是 key**；`translate()` 缺键**回落成 key 本身** | `apps/web/src/lib/messages.json`（**实测 2026-09-15：443 键**，zh-CN/ja 各 443；L2 批次新增 9 键见 `docs/live-voice/10 §5.4`；**L3 批次新增 0 键**——三载体文案复用既有 5 键，但 `check-i18n` 增了 **§3 动态键守卫**，登记 8 个 zh-CN 静默回落键，见 `docs/live-voice/35 §2.3`） |
| 世界正文 | **原文不译**（世界自己定语言，如 firstsnow 是日文） | 世界目录 |
| 门禁 | `pnpm check:i18n`：`t('…')` 字面量必须解析且 zh-CN/ja 齐全 | `tools/check-i18n.mjs` |
| 语言选择器 | 右上角 `<select>`（English / 简体中文 / 日本語） | `App.tsx` |

**关键陷阱**：`translate()` 的 `entry?.[locale] ?? key` —— **缺键不报错、显示英文**。这是「静默去本地化」的机制根源，门禁只为 `t()` 字面量挡住了它。

## 2. 待办台账

### T1 — 9 处内联 `locale === 'ja' ? … : …` 绕过 `t()`（**主要窟窿**）

**现象**：这些点**只区分 en/ja**，`zh-CN` 掉进 else 拿英文。也就是说**选了简体中文，这些文案仍是英文**。

| 文件 | 处数 | 例子 |
|---|---|---|
| `apps/web/src/components/overlay/CharacterModal.tsx` | 4 | `aria-label={locale==='ja' ? '続ける' : 'Continue'}`；`{locale==='ja' ? \`${id}は考えている…\` : \`${id} is thinking…\`}`；输入框 placeholder；对话 aria-label |
| `apps/web/src/components/canvas/CardRenderer.tsx` | 5 | `ja ? 'まだ白紙 · …' : 'UNWRITTEN · …'`；`'場面 · 入口':'SCENE · ENTRANCE'`；`'手紙':'Letter'`；`'開いて読む':'Click to open and read'`；`'たたんでしまう':'Fold & Put Away'`（经 `const ja = locale==='ja'`） |

**注意**：`App.tsx` 的 3 处 `locale === 'ja'` **不是文案**（是 locale 值传递：`setLocale`、TTS `language`、`NookView` 的 `locale` prop），**不在本项**。

**修法**：把每处文案提进 `messages.json`（英文原文作 key），调用点改 `t('…')`。注意 `CardRenderer` 的 `ja` 是个变量，5 处一并改。

**注意（重要）**：`CharacterModal` 的另 5 处三元在 **main 分叉点就存在**，`CardRenderer` 的是 niko 新写的——**都不是合并丢的**。所以这项**要问 kumo/niko**：zh-CN 是「正式要支持的第三语言」还是「先只在部分界面露头」？答案决定是「全铺」还是「把 zh-CN 从选择器撤下」。

### T2 — `NookView` 显式排除 zh-CN

`apps/web/src/components/nook/NookView.tsx:32`：`locale: Exclude<Locale, 'zh-CN'>`，`App.tsx:691` 传参 `locale === 'ja' ? 'ja' : 'en'`，`NookView:128` 用 `UI_COPY[locale]`（老 `legacy-ui-copy` 通道，只有 en/ja）。

**现象**：nook（角色小天地）视图**永远不进中文**。这看起来是**刻意的**（类型都排除了），但没写明原因。

**待办**：要么把 `UI_COPY` 补 zh-CN 并放开类型，要么在类型旁写清「为何 nook 不接中文」。**先问设计意图**——可能与 T1 同一答案。

### T3 — `legacy-ui-copy.ts` 与 `messages.json` 双轨未合并

`UI_COPY`（en/ja，`legacy-ui-copy.ts`）是 main 的老通道；`messages.json`（en/zh-CN/ja）是 niko 的新通道。**两套并存**：nook 走 `UI_COPY`，其余走 `t()`。合并时只把 main 的 4 个 perform 键并了进去。

**待办**：要么把 `UI_COPY` 补 zh-CN 并放开类型，要么在类型旁写清「为何 nook 不接中文」。**先问设计意图**——可能与 T1 同一答案。

> **L2 追加（2026-09-15）**：对话框通话文案走 `messages.json`（三语），nook 通话文案留 `UI_COPY`（en/ja）——**双轨并列是 L2 有意保留的现状，本批不合并**（理由：合并 `UI_COPY` 要动 `Locale` 类型与 `NookView` 全部取文案点，属独立工作；`docs/live-voice/10 §5.4` 已冻结「MUST NOT 复用 `legacy-ui-copy.ts` 的通话键给对话框」——那是 `en|ja` 两语言，`zh-CN` 会**静默回落英文**）。另：`live-call.ts` 的 `errorText`/`ERROR_COPY_KEYS` 仍只读 `UI_COPY`，故 **`zh-CN` 界面下通话错误回落英文**——已登记为独立待办（`docs/live-voice/13-门禁与回写.md` W24）。

### T4 — 世界 locale 与 UI locale 的关系未定

`App.tsx:100`：世界 `manifest.locale === 'ja'` 时**自动把 UI 切到 ja**。反向（玩家手动切 en 后世界是 ja 世界）行为未定：世界正文照旧日文，UI 语言是否该被世界覆盖/尊重玩家手选？**当前是「世界覆盖一次、之后玩家手选优先」**（`useEffect` 依赖 `manifest.id`）。
