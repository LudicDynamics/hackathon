# AIRP 前端重构共享契约

> 状态：2026-09-14 设计评审基线。本文冻结本轮 UI 重构的跨区信息层级、交互语义和布局安全区；实现代理不得自行改变这些形状。源码现状以各区域勘察报告为证据，未知以 `[推断]` 标注。

## 1. 产品答案

前端只保留三条清晰路径：**看见空间 → 直接点目标 → 在一个稳定的行动台继续**。画布永远是全屏空间；所有纸页、侧栏、活动和输入都是不改变画布坐标的覆盖层。任何 hover 只展示预览，不执行事实动作。

## 1.1 产品前端视觉规范（硬契约）

视觉质量不是实现偏好，而是用户能直接感知的产品契约：

- **材质与色彩**：以 `docs/ux/01-全局视觉语法.md §2–§3` 和 `docs/doc-04-视觉设计风格.md:170-194` 为唯一基准：暖纸/暖墨舞台、低饱和 rust/sage/blue、柔和阴影与清晰留白。不得在局部重新引入紫色渐变、纯黑、直角旧皮肤或第三套调色源。
- **字体职责**：人文正文/台词使用 `--ux-font-human`，UI 使用 `--ux-font-ui`，机器状态/路径使用 `--ux-font-machine`，画布手写使用 `--ux-font-hand`；字体失败时仍显示正文和操作。
- **表面职责**：stage 是连续空间；paper 只用于阅读、dialogue、Shelf 等明确语义；Chalk bare 必须透明、无纸壳、无 shadow。一个对象只拥有一个表面身份。
- **交互反馈**：每个控件只有一套稳定 hover/focus/pressed 反馈；优先颜色、hairline、soft shadow 和 outline，不用会改变布局的 translate/scale，也不混用多个高亮语法。focus 必须可见，触点至少 44px。
- **动效与降级**：动效只表达进入、焦点、处理中和落定，不用装饰循环掩盖状态；`prefers-reduced-motion`、Effects off、低性能、窄屏和媒体失败时，文字、状态、焦点、关闭和核心操作仍完整可用。
- **响应式**：统一 desktop `≥1181`、narrow desktop `701–1180`、phone `≤700`、验收 fixture `390×844`；先收低优先级 Chrome，再排安全车道，最后调整字号/间距，不改卡片 footprint、画布坐标或 active projection。
- **品质验收**：实现代理必须对 1568×744、1024×768、700px、390×844 检查无意外 overlap/overflow，检查 focus/hover/reduced-motion；“看起来更漂亮”不能替代几何、语义和可操作证据。

## 3. 跨区固定语义

### 3.1 一个意图一个主操作

| 意图 | 主操作 | 不允许 |
|---|---|---|
| 预览 | hover / focus | 请求、写世界、改变相机 |
| 阅读 | 点击卡片或明确的阅读区域 | 在卡片外再放一个“仔细观察”执行按钮 |
| 进入场景 | gate 双击（桌面加速）或聚焦后 Enter；触屏必须有显式入口 | 依赖触屏 double-click |
| 执行动作 | 组件内唯一 action 区 | 同一实体同时在卡面和外置面板渲染 Take |
| 对话推进 | 台词区点击/Enter/Space | Enter 既推进台词又发送输入 |
| 发送文本 | WriterBar/input 的 Enter 或发送键 | 复用台词推进事件 |
| 角色功能菜单 | 独立展开器 | hover 插入正常文档流 |
| 关闭/返回 | 当前 overlay 的 Close 或 Escape | 多个 surface 同时抢焦点 |
角色小天地是同一目标的等价路径而非两次动作：角色侧栏展开器中的 `Visit their ikigai` 是主入口；对话 identity/status 层的 `Visit private space` 允许作为同目标的次级入口。两者必须调用同一个 App-owned transition，不能各自管理 camera、focus 或 `/api/nook`；不得把按钮放回 speech paper。

### 3.2 事实与演出

- 文件与既有 action service 是世界真相；布局调整不得新增状态真相、WS 或坐标算法。
- `writer-state` 是作家生命周期唯一真相；`agent_activity` 是活动细节来源；`WorldToast` 只回执已落盘事实；WriterInk/phantom 只表现画布空间中的实时湿墨，不承担全局 busy。
- 状态表述按强度分层：实时主状态（一个位置）→ 可展开原始活动流（一个收纳处）→ 事件 toast（弱、短暂事实提示）。
- `agent_activity.phase` 仍只有 `started|completed|failed`；本地 UI 可以有 `accepted/processing/...`，但不得写回 wire phase。

## 4. 空间安全区

### 4.1 世界舞台

所有固定控件必须加入同一安全区计算，不以 z-index 解决 overlap：

- top lane：世界标题/返回/关闭；
- side lane：角色 rail、工具 rail；
- bottom action lane：writer dock、Stop、activity summary；
- notice lane：toast/错误，必须避开 bottom action lane。

覆盖层改变排列和滚动，不改变 `Canvas` 原点、camera memory 或卡片坐标。优先使用既有 `--depth-*` token，不新增深度值。实现前必须把现有 raw `z-index` 映射到既有 token：舞台内容 < chrome（writer/rail）< toast/notice < modal/dialogue；toast 不得越过 modal。`prototype-toast`、`.prototype-world-picker` 等现有逃逸值只能在本轮收口时被替换，不能继续新增同类数字。
### 4.1.1 顶栏（Header）职责与视觉质量

- 顶 lane 只承载世界身份/导航、低频全局设置与沉浸/关闭入口；作家、God Hand、Chalk、Stop、Activity details 不回顶栏，也不与 `world-meta` 重复声明同一身份状态。
- 身份层级固定为 `brand → world/layer breadcrumb → 当前层标题/状态 → 低频设置 → immersive/close`；状态文案只保留一个权威位置，长标题不可挤压或裁掉 close/返回。
- 桌面使用单行 toolbar；`701–1180px` 收起低优先级文字但保留 accessible name；`≤700px` 允许横向滚动或分组折叠，但 close、Worlds、language、返回和焦点路径必须可达，不得把最后一个控件藏在不可发现的滚动末端。
- 所有 header 触点至少 44px，沿 `--ux-*` 字体/颜色/圆角/软影；hover 不位移、不改变 header 高度；focus ring 与 reduced-motion 路径可见。
- Header、world-meta、edge controls 必须消费同一 top-lane 安全区；不能靠 z-index 把它们互相覆盖。进入 immersive 后必须保留可见 Stop 与触屏可发现的 chrome 唤回入口；Escape/关闭回焦到触发控件。

### 4.2 对话

单人物时不渲染空 portrait slot。人物媒体以底边基线锚定，并与 speech paper 共享可验证的底部安全区。speech paper 只承载当前台词、翻页提示和玩家输入；人物身份、bio、Visit nook、活动状态放入独立 identity/status 层。`CharacterModal` 必须继续复用 App 的 admission、frame queue、focus coordinator、camera restore。

### 4.3 角色 rail

单一 `CharacterPresenceView[]` 同时供 Canvas 与 rail；保留 views 原序。每行必须预留固定高度，expander/actions 只能 visibility/opacity 或 absolute overlay，不能 `display` 插入 flex 流。muted 状态 hover 仍保持可辨灰度；非同场景头像点击只给可见提示，不启动对话或导航。

### 4.4 Nook

Nook 保持唯一 active projection 与既有 camera stack/Canvas。其顶栏只有角色身份和返回；舞台只承载 Canvas；底部划分 live-call/notice、活动与 note composer 安全 lanes。composer 必须避开全局 Activity details、Bag、toast 和键盘安全区；不得以固定右下角覆盖解决。

### 4.5 Authoring

authoring surface 是 God Hand、freeze、Chalk editing、Writer input、Stop 和 Close 的唯一控制 owner。左侧 rail 只保留空间 Explore/Return；**Arrange 不在本轮假装已实现**：`docs/layout/06 §1.2/§4.3` 的 functional canvas-arranger 仍是独立待落地能力，若没有真实入口/状态/动作接线，必须不渲染该按钮，不得把现有 God Hand 或 Radial creator 冒充 Arrange。左侧不再提供第二个 God Hand 入口。God Hand 权限仍独立于 `attention`，离开 authoring 必须关闭。Enter/行动按钮唤起并聚焦 WriterBar，Escape 一层退出并恢复触发焦点。

## 5. 实现分工

- Dialogue：`CharacterModal.tsx` + `index.css`/modal styles；不得改 frame/voice 协议。
- Cards：`CanvasObject.tsx`、`CardRenderer.tsx`、`PropCard.tsx`、`EntityInteractions.tsx`；不得新增 action authority。
- Rail：`CharacterRail.tsx`、`character-rail.css`；不得重新派生 presence。
- Nook：`NookView.tsx`、`NookNoteComposer.tsx` 与 nook/scene shell styles；不得拥有 camera/WS。
- Writer chrome：`App.tsx` 编排、`WriterBar.tsx`/`GodModeToolbar.tsx`、prototype/scene shell styles；不得复制 writer-state。
- Activity：`App.tsx` projection、`ActivityRail`/`AgentActivityLog`/`WorldToast`/`WriterInkLayer`；不得新增 WS listener。

同一文件有重叠修改时，先按区域协调；不得覆盖其他会话未提交文件。实现完成后必须回写本文中被证据修订的语义。

## 6. 共同验收

至少覆盖 1568×744、1024×768、700px、390×844：

1. hover/focus/展开不改变相邻组件的 `getBoundingClientRect()`；
2. 画布坐标和相机记忆在打开/关闭 journal、nook、dialogue、authoring 后不变；
3. keyboard/触屏能完成与鼠标相同的目标路径；
4. 同一事实只出现一个主实时状态、一个原始活动收纳处、一个事实 toast；
5. `prefers-reduced-motion` 下仍可阅读、输入、关闭、拖拽和推进；
6. 世界内容/动作/WS 现有契约测试保持通过。

本轮实现代理必须跳过全量 build/test/lint；主代理统一启动应用、截图验收并运行构建与门禁。
