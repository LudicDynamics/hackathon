## 1. 一句话定位

**`04` 把契约 §2.2 的判定表落成一个唯一的纯投影 `projectPresence`，用 220ms 稳定窗口把「按层取回的离散
快照」磨成有阻尼的过渡，并给出「去 ta 那里」的单一导航入口 `navigateToCharacter`（`await enterLayer` →
等一次渲染提交 → `readLayerState` 取新层坐标 → `camera.flyTo`，全程不写相机记忆）；同时登记机械门禁与
验收矩阵，使「画布与侧栏读同一份派生结果」可被静态与浏览器双重核验。**

三个不可让步的点：

1. **唯一 owner**：全前端只允许一处调用 `projectPresence`（`state/usePresence.ts`，§8 落点）；画布与侧栏
   消费同一个 `CharacterPresenceView[]`，不得各自从 `state.presence` / `characters` 重推（契约 §4.1、
   `docs/ux/00 §4.6`）。
2. **纯**：投影不读 DOM、不发请求、不持 timer（契约 §4.1 末条）。所有时间从 `now` 参数进来，所有副作用
   （`enterLayer` / `flyTo` / `notify`）从参数注入。
3. **诚实**：不在场（`P(c) == null`，宽松相等，见 §3.1 步骤 2 的 P-12）就是不导航、就是灰、就是不能直聊；
   稳定窗口只压**投影输入**，绝不阻塞世界数据与交互（契约 §4.2）。

## 3. 行为契约逐步（每步写「漏了会怎样」）

### 3.1 `projectPresence` 的推导（契约 §2.2 判定表逐行实现）

输入约定：`L = input.layer`（玩家当前层）；`P(c) = input.characters[i].presence`；`S(c) = input.presence`
（`/api/layer` 的当前层 presence）里 `characterId === c.id` 的那一行，可能为 `undefined`。

| # | 步骤 | 判定 | 漏了会怎样 |
|---|---|---|---|
| 1 | 遍历 `input.characters`，逐角色建条；输出顺序 = 输入顺序 | `/api/characters` 与 `/api/layer` 都按 id 稳定（契约 §3.1 的 `ORDER BY`） | 顺序抖动 → z 序闪烁、侧栏列表跳动 |
| 2 | `P(c) == null`（**宽松相等**：同时命中 `null` 与 `undefined`）→ `state='absent'`、`layer=null`、`position=null`、`following=false` | §2.2 第 1 行 + P-12（§7 已承认 `presence` 可能整体缺失，`=== null` 会让步骤 3 在 `undefined` 上抛 TypeError） | 不在场角色被画上画布（无坐标可画）或侧栏误判为在别处；`=== null` 时 `P(c).layer` 对 `undefined` 抛 TypeError，整份投影崩掉 |
| 3 | `P(c).layer !== L` → `state='elsewhere'`、`layer=P(c).layer`、`position=null`、`following=P(c).following` | §2.2 第 2 行 | 跨层角色被当同场景渲染到错误的 `(x,y)` |
| 4 | `P(c).layer === L` **且** `S(c)` 存在 → `state='in-scene'`、`layer=L`、`following=P(c).following`、`position={x:S.x, y:S.y}` | §2.2 第 3 行 | **坐标来源必须是 `S`**：`P(c)` 只有层、没有坐标（契约 §3.2 / §4.1） |
| 5 | `P(c).layer === L` **但** `S(c)` 不存在（过渡中：`/api/characters` 已说在本层、`/api/layer` 还没回来）→ `state='elsewhere'`、`position=null` | 防御性收敛：宁可不画，不猜坐标 | 会拿上一层的坐标画，或画在 `(0,0)` 原点 |
| 6 | `following = P(c) == null ? false : P(c).following`（宽松相等，与步骤 2 同一守卫） | §2.2 「任意状态下 `following===true` → 附加跟随中」 | 跟随图标与开关真值分叉（契约 §2.4：前端不持有跟随真值）；`undefined` 未被步骤 2 拦下时此处再抛 |
| 7 | `arrivedByFollow = input.settled && following && state === 'in-scene'` | §4.2「切层：跟随带过来的角色」 | 见 §3.3 |

**关于 `position` 的唯一来源**：步骤 4 只读 `S(c).x / S(c).y`。**MUST NOT** 读 `P(c)` 上的任何坐标
（契约 §3.2 明写 `/api/characters` 的 presence 只有 `{layer, following}`）。这条必须有一个「把坐标从错来源
灌进来就会红」的用例（§10.1 用例 P3）。

### 3.2 `settled` 与「沿用上一帧投影」的落点

契约 §4.1 写 `settled: boolean; false = 用上一帧快照`。**纯函数不能持快照**，因此这条拆成两个协作者，
**不改任何冻结形状**：

- `projectPresence` 是**纯核**：永远从**它收到的输入**推导；`settled` 只用于步骤 7 的 `arrivedByFollow`
  门（`false` ⇒ 不武装「跟随入场」阻尼）。
- `createPresenceStabilizer` 是**唯一持有「上一帧」的地方**：缓存上一帧的**输入**
  （`{characters, layer, presence}`）与其投影结果，在静默期内**回放上一帧**，让消费者**字面地**看到
  「沿用上一帧投影」。

| 稳定窗口行为（契约 §4.2「侧栏成员状态翻转」行） | 漏了会怎样 |
|---|---|
| `layer` 变化，或 presence 的**身份集合**（同场景角色 id 集）变化时，记 `holdStart = now`，静默 `holdMs`（默认 `220`） | 切层瞬间整列灰一下再亮回来，玩家读成「他们掉队了」（契约 §4.2 原话） |
| 静默期内 `reduce` 返回**上一帧** `views`（`settled:false`），**丢弃**本帧新输入 | 硬切：头像瞬间跳变、侧栏成员翻转 |
| `now - holdStart >= holdMs` 后，用本帧输入算 `projectPresence({..., settled:true})`，返回 `settled:true` | 永不 settle → 投影冻结在旧世界 |
| 连续两帧输入一致时**不重置** `holdStart`（只由**内容变化**触发新一轮静默） | 每帧重置计时器 → 永远 settle 不了 |

> **稳定窗口只影响投影输入**：`usePresence` 不拦 `useWorld` 的 `world_event → fetchLayer`
> （`useWorld.ts:451`），不拦点击/拖拽，不 `await` 任何东西。它只在 `views` 这一路做 220ms 延迟。
> 漏掉这条纪律 = 用阻尼拖慢了世界（契约 §4.2 明确禁止）。

**为什么只比较「身份集合」而不是 `(x,y)`**：`move_to` / `carryFollowers` 造成的**同层坐标变化**由
`02` 的 `transform` 滑行（480ms）负责，**不应**触发 220ms 静默——否则坐标更新会被延迟一拍再滑。静默只
负责「成员状态翻转」（同场景 ⇄ 他处/不在场）这类硬切。

### 3.3 `arrivedByFollow` 的判定依据（含一处需主代理拍板的语义）

纯输入里**没有「上一帧在哪层」**：`characters[].presence` 只说「此刻在哪」，`/api/layer` 只说「当前层有谁」。
纯投影能给出的唯一诚实信号是：

```
arrivedByFollow = settled && following && state === 'in-scene'
```

即「**一个跟随者，且此刻与玩家同场景**」——`presence.following` 是唯一区分「被带过来」与「本来就住在这」的
持久位（契约 §2.1 表第 3 行）。它不是「本帧刚到」的严格跨帧判断，后者**只有阻尼消费者（`02`）持有
`prev` 数组时才做**（`02` 首次见到某 `id` 时才播入场，steady-state 的重复 `true` 无副作用）。

- 契约 §4.2 对这条的要求只是「视作入场，但**不做跨层滑行**，错峰排在最后」——`02` 用
  `arrivedByFollow` 选入场分支、跳过跨层 `transform` 滑行即可满足。
- **`settled=false` ⇒ `arrivedByFollow=false`**：过渡帧不武装新入场，避免一帧内既回放旧投影、又排队新动画。
- 若要「严格的本次到达」位，需给投影输入**增**一个跨帧字段——那是 §4.1 冻结形状的修改，**本文不擅自改**，
  登记为待拍板项 U-1（§12）。

### 3.4 导航与相机：三情形 + 竞态处理（契约 §3.4）★

`navigateToCharacter(view)` 是**唯一入口**（契约 §3.4「★ 跨层导航的相机竞态」要求封装成一个函数；
`03` 只调用它，相机时序不在 UI 组件里重写）。

| 情形 | 行为 | 漏了会怎样 |
|---|---|---|
| `view.state === 'absent'` | 立即 `notify('They are not here right now.')`，返回 `'absent'`，**不导航** | 硬造位置把玩家传送走（契约 §3.4：不在场就是不在场） |
| `view.state === 'in-scene'` | 直接 `camera.flyTo(view.position.x, view.position.y)`（`z` 省略 = `useCamera` 保持当前 `sharedTarget.z`，`useCamera.ts:159-165`） | 同场景也要等一帧，白白慢一拍（此情形无竞态） |
| `view.state === 'elsewhere'` | 见下方三步 | 相机被目标层记忆拉回旧位，玩家看到「点了没动」 |

**跨层三步（不可合并、不可换序）**：

```ts
// 1. 世界真的换了层（01 的 layer_entered + carryFollowers）
await enterLayer(view.layer);
// 2. ★ 等 React 提交这次的 currentLayer 重渲染
await nextFrame();
// 3. 同步读新层快照（stateRef，不触发渲染）
const s = readLayerState();
const row = s?.presence.find((p) => p.characterId === view.id);
if (!row) { notify('They moved before you arrived.'); return 'failed'; }
camera.flyTo(row.x, row.y);   // 只改 target，不写记忆
return 'navigated';
```

**为什么必须有第 2 步**：契约 §3.4 已核实——层变化时有两处 effect 会写相机，且顺序不由导航方控制：

1. `Canvas.tsx:144-152` 的 effect：层变化时 `camera.save(prev)` + `camera.restore(currentLayer)`
   （把相机拉回该层**记忆位置**）；
2. `App.tsx:187-191` 的 effect：`nookChar === null && !activeCharacter` 时
   `cameraStack.setCurrent(projectionTarget('layer', layer))`。

React effect 在渲染提交后执行。若 `restore(currentLayer)` 落在 `flyTo` **之后**，相机被拉回目标层旧记忆
——**看起来「没生效」**。`nextFrame()`（一次 `requestAnimationFrame`）保证 `flyTo` 排在这一次层切换的
提交之后。

**与 `createCameraMemoryStack` 的既有投影事务不冲突的论证**：

| 关注点 | 论证 |
|---|---|
| `Canvas.tsx:144-152` 的 `save(prev)`+`restore(currentLayer)` | 这是**层** slot 的常规换层行为（`cameraSlot('layer', id) === id`，`camera.ts:92-96`），每次换层本来就会发生。导航只是**在其之后**把 target 指到角色坐标；`save` 存的是**换层前**的 target，`restore` 读的是**目标层记忆**——两者都不依赖 `flyTo` 的值。 |
| 导航 MUST NOT 写记忆 | `save` 才写 `CAM_MEMORY`（`useCamera.ts:167-169`）；`flyTo` 只写 `sharedTarget`（`useCamera.ts:159-165`）。所以「用过一次导航 → 下次回这个场景丢失玩家自己的视点」不会发生（契约 §3.4 末段）。 |
| `App.tsx:187-191` 的 `setCurrent` | 该 effect **只在 `layer` 变化时**触发，且只改 `cameraStack` 的 current 指针，**不调用 `camera.restore`**（`camera.ts:203-206`）。它不会覆盖 `flyTo`。 |
| 与 `pushTransition`/`popTransition` 的关系 | 导航**不**入栈、**不**出栈（它不是投影切换）；玩家下一次进入 Nook/dialogue 仍走既有 `openCharacter`（`App.tsx:588-605`）/Nook 事务，与导航互不干扰。 |

**跨层导航后若目标角色恰好跟着来了**：`enterLayer` 的 `carryFollowers`（`01` 接线）会把跟随者的
`presence` 搬进新层（契约 §2.3），所以 `readLayerState()` 里**能**找到该角色；这正是 `04` 与 `01` 的
接线闭环（§10.3 用例 B2）。

### 3.5 `nextFrame` 的 production 实现（`usePresence` 内）

```ts
// usePresence.ts —— 两个 rAF：第一个让 React 的提交落地，第二个让 Canvas 的
// save/restore effect 之后的 target 写入稳定（契约 §3.4）。纯函数只吃注入的版本。
const nextFrame = useCallback(
  () => new Promise<void>((resolve) =>
    requestAnimationFrame(() => requestAnimationFrame(() => resolve()))),
  [],
);
```

单测注入一个 `nextFrame: async () => {}`（或手动 resolve 的假实现），使投影/导航测试**不需要 DOM 与
rAF**（§10.1 用例 N1–N4）。两次 rAF 的理由：`Canvas.tsx:144-152` 的 effect 与 `App.tsx:187-191` 的
effect 都注册在**同一提交**里，第二次 rAF 才保证它们的 target 写入已经发生、且 rAF 循环已把
`sharedCurrent` 推向该 target——此时 `flyTo` 覆盖它才是最后写入者。

### 8.1 `readLayerState` 的精确实现

```ts
// useWorld.ts —— 放在 refresh（:201-203）旁
const readLayerState = useCallback((): LayerState | null => stateRef.current, []);
// 返回对象（:728-743）追加：readLayerState,
```

- **为什么需要它**：`enterLayer` 内部 `await fetchLayer(next)`，而 `fetchLayer` 在 `setState` **之前**同步
  写 `stateRef.current = next`（`useWorld.ts:189-190`）。因此 `await enterLayer(...)` 解析时，`stateRef`
  已是新层，但 React 的 `state`（`useWorld.ts:132`）**未必已 flush** 到下一个渲染。导航需要**同步**读坐标。
- **纪律**：与既有 `stateRef` 纪律一致——`stateRef` 是 footprint/moveCard 的真相源
  （`useWorld.ts:141`、`:471`，注释「footprint/moveCard read stateRef as truth」）。`readLayerState` 只是把
  同一纪律开一个**只读**出口：不触发渲染、不写状态、不 `await`。

### 8.2 与既有 `stateRef` 消费点的同构性

| 既有消费点 | 为何同步 | `readLayerState` 的同构理由 |
|---|---|---|
| `createFootprintScheduler` 的 `widths: () => stateRef.current?.items`（`useWorld.ts:348`） | 调度器在 rAF/ResizeObserver 回调里跑，不能读 React state | 导航在 `await` 之后跑，同样不能读 React state |
| `moveCard` 的 `const prev = stateRef.current`（`useWorld.ts:247`） | 乐观回滚需要上一帧真值 | 导航需要跨层后的真值 |
