## 1. 总览：从哪两个轴看「上下文」

**轴一 · 谁在消费**：AIRP 有三个会「读东西进自己窗口」的执行者，外加一个引擎注入源：

| 消费主体 | 形态 | 出现的时机 |
|---|---|---|
| **作家** | 主 agent（常驻进程） | 每一轮玩家输入都吃整份上下文 |
| **角色** | 按需 spawn（懒灵魂） | 只在玩家点开遮罩时存在，吃自己的一小份 |
| **world subagent** | 作家 spawn 的委托进程 | 委托时临时存在，吃 brief + 自己的生成内容 |
| **扩展** | 引擎层插件 | 可向任意 agent 的提示词注入自定义数据（doc-05 §7.2） |

**轴二 · 何时进上下文**：同一份内容不是任何时刻都在上下文里，按生命周期分四档：

| 档位 | 内容 | 进上下文的方式 | Nodesign 对应 |
|---|---|---|---|
| **① 进程启动即载（静态脑）** | preset 引用的身份/规则/设定 | 编译进 system，整场不变 | prelude（system 区，整区冻结） |
| **② 每轮 Hook 动态注入** | 事件摘要、视点、当前场景变化、玩家输入 | 每轮拼进提示词 | turn-state 每轮状态块（指纹 diff） |
| **③ 叙事历史（滚动区）** | chat history、journal、旧 chalk | 按预算/轮数截断 + 摘要折叠 | 历史区（预算挤压 + 滚动前情提要） |
| **④ 按需懒加载** | 画布文件、截图、组件内容 | Agent 自己调 `look_at / read / view_canvas` 拉取 | 参考页/素材 Read、browse 截图 |

> ⚠️ doc-08 的问题就在 ② + ③ 的交汇处：**作家每轮默认吃进的东西**（当前场景目录全部文件 + journal）会随叙事文件增殖线性变长，而 ④（按需懒加载）本来是治这个的药，没被写进纪律。

## 3. Nodesign 对照：六件武器 + 一次解剖

### 3.1 Nodesign 实际做了什么（源码走读结论）

1. **三区模型 + 上下文预算**（`orchestrate.js`）：system（冻结，缓存本体）→ history（弹性，被预算从最旧挤压，切口永远落在 user 记录上）→ 尾部（唯一每轮可变的区，**触发词条只许住尾部**——结构性缓存保护）。默认预算 60000 token，历史保留 40 轮。
2. **滚动前情提要**（`summarize.js` / `chat-log.js`）：活历史攒到「触发 24 轮」就折叠一次，保留最近 12 轮，压缩成一篇「提要」（默认 ≤500 字）。压缩提示保留六要素：**人物与称呼、关系变化、承诺与约定、得到或失去的东西、时间地点推进、未解决的伏笔**。滞回区间（24>12）保证不会每轮都摘要；摘要失败不静默、边界不动、下一轮再试。全量记录留文件里（`至` 指针跳过折叠区），可随时重放导出。
3. **每轮状态块：首轮全量 + 之后指纹 diff**（`turn-state.js`）：8 节 = cwd / 素材清单 / 便利贴 / 视点 / 画布关系线 / 产物清单 / 最近板书 / 黑板模式。每节算指纹（djb2），没变的只在末尾一行点名「未变：…」，清单类只报新增/移除，全没变就一句话。**compaction 后重置记忆**（旧状态块被摘要吞了，「同上轮」没有所指）。采集纪律：扫不动就不说、单节异常跳过、不炸 turn。
4. **视点上报表**（`viewpoint-store.js`）：只存每个项目最近一份（TTL 10 分钟），一行人话注入："他在文件夹「X」里；视口 (x,y) w×h 缩放 z；视口里有 N 件：a、b、c；开着窗…；选中…"。视口矩形按 **1/8 视口量化**再进 hash（相机挪一像素不算"变了"）——与 AIRP doc-02 §3.2 继承的描述逐字同源。
5. **角色/演出系统**（`scene.js` / `role-card.js` / `cast.js`）：编排把「触发条目」锁在尾部；角色卡（`.claude/agents/rp-*.md`）是模型可写文件，但**工具白名单在派发时统一核**——上下文边界的收口靠"分发闸"而不是靠提示词自觉。
6. **上下文用量条**（ContextMeter）：60% 以下零像素 / 60-85% 一条 hairline / 85%+ 显示"87% · 压缩"入口；明细含已用/上限、跑在谁身上、token 构成、Top 工具排行。**不是所有指标都值得常驻像素**（doc-02 §4.6 已分析）。

### 3.2 逐条映射表（Nodesign → AIRP）

| Nodesign 机制 | AIRP 对应点 | 差距 |
|---|---|---|
| prelude 系统提示（身份/规则/回路） | 作家/角色 preset 的 system slot + S1/S4 | 基本同构，AIRP 更薄 |
| 三区模型 + 上下文预算 | ①预设 / ③历史(chat+journal) / ②Hook 尾部 | **AIRP 已有 doc-12 #2 讨论但无预算数值** |
| 滚动前情提要（触发 24 / 保留 12 / ≤500 字 / 六要素） | doc-08 候选方向 #4「上下文摘要宏」 | **提示词与参数可直接抄**（journal 版） |
| 每轮状态块指纹 diff（8 节 / 只报变化 / compaction 重置） | doc-08 候选方向 #2「历史手记折叠」；doc-12 #1 字段注入 | **"当前场景目录下有什么文件"不该每轮全量**——指纹 diff 是现成正解 |
| 视点上报表（已继承） | D2 | 无差距，已定案 |
| 最近板书 inject（limit 8，标题+一句） | 作家每轮该知道"最近落了几条板书"的模板 | 现成 |
| 摘要过目验收 | world subagent 回报（doc-05 §4.3） | 无差距 |
| 转录 + rewind（对话/文件双侧） | doc-16 快照回滚 | 技术同构，范围另议 |

### 3.3 对 doc-08 四个候选方向的直接回应（供后续定案参考，不定案）

| doc-08 方向 | Nodesign 给了什么证据 |
|---|---|
| **持续小段衔接（append_to）** | Nodesign 板书有 `reply_to` / `anchor` / near 语义：新板书接在相关旧板下面回。AIRP 的 `append_to` 是它的超集；**缺的是作家纪律**（doc-12 #4 把"同场景连续小段用 append_to 连成长文"写进 preset）——Nodesign 的写法是把它写进 prelude 当行为规则。 |
| **历史手记折叠** | 直接对应 turn-state 的「最近板书 limit 8 + 标题/一句」注入：前端折叠成历史手记后，**注入侧只喂最近 N 条 + 指纹 diff**，DB/文件全量保留。折叠阈值可抄「保留最近 8-12 条」。 |
| **journal 归档** | 对应 `摘要.json` 的语义：**全量不删、指针跳过、滚动覆盖**。归档不是搬文件，而是"边界前移 + 只留摘要进上下文"。触发者建议引擎化（阈值触发，Nodesign 是回复落盘后串行折叠，不阻塞回复）。 |
| **上下文摘要宏** | 直接抄滚动前情提要：触发轮数/保留轮数/长度/压缩六要素四参数 + 滞回防抖动 + 失败不静默。**摘要生成时机 = 归档/折叠动作本身，而不是每轮**。 |

### 3.4 给 AIRP 的最小可抄清单（赛时 MVP 到赛后扩展）

1. **journal 滚动摘要宏**（doc-12 #2 的最小实现）：参数照抄 `触发 N 篇 / 保留 M 篇 / 摘要 ≤X 字`，压缩六要素照抄，落成 `journal/.summary.md` 之类 + 边界指针——doc-08 待定问题 2（上下文预算模型）的最小正解。
2. **Hook 注入三段式**：`[世界动态]`（D1 事件摘要）→ `[玩家视点]`（D2）→ `[当前场景变化]`（D3 指纹 diff，未变就一句"同上一轮"）——对应 Nodesign 状态块，直接把"整批吞文件"改造成"只报变化"。
3. **最近板书注入**：每轮注入最近 3-5 条板书的「路径 + 首句」（limit 上限写死防膨胀），细节靠 `look_at` 拉——这是 D3 的降级替代，成本极低。
4. **compaction 后重置记忆**：作家上下文被摘要折叠或进程重启后，**必须重新全量注入**当前场景（否则"同上轮"没有所指），journal 摘要照旧。
5. **系统区冻结 / 尾部只放可变形**：同一结构的缓存保护——玩家输入每轮在变，所以事件/视点/变化段只能放尾部，设定/规则放 system 冻结区。

## 4. 待定问题（延续 doc-08，补 Nodesign 已给的证据）

1. **永久 chalk 生命周期**：Nodesign 证据 = 板书是"对话在板上的投影"，可被新板书接续（reply_to/append_to）但**从不主动消失**；折叠是前端呈现层的事（只读最近 N 条）。AIRP 若同此，则"历史手记折叠"只需解决**注入体积**，不需要解决"删叙事"。
2. **上下文预算模型**：Nodesign 给了默认值（60000 token / 保留 40 轮 / 摘要 24→12 / 500 字），但 AIRP 的"轮"比 Nodesign 的"轮"重（每轮写文件）。建议赛时按 **token 预算挤压旧轮 + journal 摘要宏**起步，数值按模型窗口再标定。
3. **摘要/归档触发者**：Nodesign 的答案是**引擎化 + 串行在回复落盘之后**（阈值触发、失败不静默、下一轮重试）。（2026-09-11 更新：AIRP 已定案为**软提醒混合制**——引擎阈值只给信号、作家决定折叠时机；详见 doc-08「方向定案记录」。本文原"作家自觉可出局"倾向作废。）
