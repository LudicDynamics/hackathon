# 05 — 迁移兼容与验收

> 状态：**已落地的实现与验收**（2026-09-14 回写校正）。已落地：resolver、前端 token、服务端写入门禁、作者工具接线；**未落地**：代表性模板声明（`templates/` 无 `appearance:` 声明）、§10 的 T-01..T-09 / R-01..R-07 测试矩阵（未创建）、迁移清理 CLI。Test matrix 与模板声明以「待办」保留，不得当作已完成。

## 1. 一句话定位

**让旧 Chalk、旧 letter、旧世界/层材质和没有 `appearance` 的旧存档先不变，再用可回滚、可观察、可逐步收紧的方式迁入唯一 `appearance` 入口；验收同时证明新组合确实生效，而不是只证明页面还能打开。**

兼容是读取/呈现兼容，不是永久保留第二套协议；清理只有在语义等价、备份可恢复、诊断已收集后才可删除旧键。`passthrough` 不等于迁移完成。

## 2. 签名 / 数据形状

`02-主题包与渲染解析.md` 负责唯一 resolver；05 只通过同一公开输入/输出黑盒验收，不另造类型：

```ts
import type {
  AppearanceResolveInput,
  AppearanceResolution,
} from './02-主题包与渲染解析.md'; // 文档引用；实现从 shared barrel 导入

resolveAppearance(input: AppearanceResolveInput): AppearanceResolution;
```

验收 fixture 必须构造完整 `AppearanceResolveInput`（`kind`、`entityPath`、`frontmatter` 与 `context.worldId/worldMaterial/layerId/layerMaterial`），并按 01 的 `AppearanceDiagnostic[]`、`details.preset` 对象和维度 source 断言。读取时未知 appearance 键保留在原文件并进入诊断；写入时由严格 `validateAppearanceInput(raw, kind)` 拒绝非法 namespace/未登记 ID，二者不是同一时机。

## 3. 行为契约（逐步；每步写漏了会怎样）

### 3.1 P0 盘点

1. 扫描模板、旧素材模板、玩家存档、角色小天地与 README，分类 appearance、Chalk 旧键、letter 内容键、material/bgStyle、未知键。
2. 记录路径、SHA-256、是否可一一等价映射；未知/冲突进入人工清单。
3. 盘点只产报告，不写 Markdown、SQLite、事件或 WS。

*漏了会怎样*：批量改写会把玩家进度、未知作者字段或正文变成不可逆差异，无法归因。

### 3.2 P1 兼容读取

1. 解析 appearance；缺失保持缺失语义。
2. 仅允许 kind 读取 legacy；复刻 Chalk 的 `color ?? tone`、`big/size`、`card/chrome`、`collapsed`、`aged`。
3. 统一用 `00` §4 的基础默认 → kind 默认 → preset → 显式维度；legacy 不另算优先级。
4. 未知 preset/维度逐项安全回退，`warnings`、`details.dimensions`、`fallbackCount` 可观察。
5. renderer 只接 verified `AppearanceResolution`，不接 raw YAML。

*漏了会怎样*：旧 Chalk 会变纸卡、旧 rust 变 ink，未知主题却被伪装为成功，违反零回归。

### 3.3 P2 服务端输出

1. `/api/layer` 与 `/api/nook` 的 `items[]` 一并返回 resolution；当前组装位置为 `apps/server/src/routes/world.ts:546-571`、`:661-726`，必须共用 resolver。
2. material/bgStyle 仍只进 bg/层上下文。
3. 兼容读取不落 `entity_edited`，不新增 appearance WS 帧；WS 仍由事件表尾读广播 `world_event`（`apps/server/src/engine/event-bridge.ts:355-356`）。
4. `look_at` 可展示已解析外观摘要，但仍为读操作，不写事件（`packages/shared/src/actions/look-at.ts:1-7`）。

*漏了会怎样*：服务端和前端/agent 得到不同主题，或页面加载产生事件噪声。

### 3.4 P3 模板迁移

1. 无 appearance 的模板保留为无 appearance 基线，不随机给所有卡片换肤。
2. 需题材外观的实体增加最小 appearance，ID 使用英文小写 kebab-case；正文、互动、路径、坐标、`CARD_FORMS` 不变。
3. 旧 Chalk 字段与 canonical appearance 双写一个发布周期，逐文件证明等价。
4. 下一发布周期才删除可等价的旧外观键；`big/size`、`collapsed/aged` 永不迁入 appearance，本批不清理。
5. 模板清单、提示词、示例 frontmatter、文档导航同批更新；模板发布不得覆盖 `worlds/<id>`（`docs/worlds/世界与存档.md:3-7`）。

*漏了会怎样*：新模板继续示范第二套协议，或过早清理改变六世界的阅读密度、年龄折叠和互动。

### 3.5 P4 旧存档

1. 打开旧存档只兼容读取；页面、`GET /api/layer` 和 scaffold 不偷偷改文件。
2. 显式迁移前复制整个存档目录或 `.airpworld.zip`，记录源/目标版本、哈希、报告、未知项。
3. 只迁移确定等价字段；正文、互动、路径、canvas.db 坐标、历史、会话、资产原样保留。
4. 未知字段、冲突、缺资源、解析失败时文件停在报告状态，不猜测；最终验收展示未迁移清单。
5. 写回原子化；运行时经 `editEntity`，它先写文件再落 `entity_edited`，事件失败明确报错（`packages/shared/src/actions/delete.ts:146-201`）。
6. 重启、重载、打开受影响层复查；复查通过前不删备份。

*漏了会怎样*：存档会无用户同意变脏，事件无法解释，半成功后无源文件恢复。

### 3.6 P5 清理与回滚

1. 只删除 resolver 证明等价的旧键；未知键、内容 extra、背景字段不删。
2. 前后保存 manifest/文件哈希；按文件幂等，第二次不重复变更或事件。
3. 出现渲染、互动、路径、事件差异就停止并恢复备份；“新样式更漂亮”不是豁免。
4. 回滚只恢复文件/快照，不删除 append-only 事件；遵守 `docs/doc-16-快照回滚与事件历史.md:6-20` 的换文件、事件不删、游标推新方向。
5. 回滚后重跑旧文件无 appearance 矩阵，避免前端继续缓存新 token。

*漏了会怎样*：迁移不可逆，回滚后作家重复旧事件或前端仍显示新主题。

### 3.7 P6 新组合必须与旧实现拉开差异

```yaml
# world/harbor-chart/appearance-combination.md
---
type: chalk
title: "Signal"
appearance:
  font: hand
  surface: none
  accent: rust
  ornament: underline
  motion: calm
---
A signal written directly on the fog.
```

新实现至少断言 `data-appearance-font="hand"`、`data-appearance-surface="none"`、rust token 和 `underline` 装饰钩子。旧 `ChalkCard` 只对顶层 frontmatter 调 `chalkStyleOf`（`apps/web/src/components/narrative/ChalkCard.tsx:27-63`），不会读 nested appearance；旧实现若也通过，说明测试只检查正文，非空性无效。

*漏了会怎样*：不读 appearance 的实现也能交卷，功能实际上没有生效。

## 7. 错误边界与回退链

1. frontmatter 解析失败：保持 `frontmatter:null` 与旧默认形态，记录诊断，不生成 appearance。
2. 无 appearance：kind 默认 + legacy adapter；Chalk `values.surface === 'none'`，不得由全局 paper 壳覆盖。
3. 未知 preset：安全 preset/kind 默认；warnings、details.preset/fallbackCount 可断言。
4. 未知维度：逐维回退，已知维度仍生效；不能整卡空白或拼 class/style。
5. 未知 key：读取时保留并诊断；作者/迁移写回时严格拒绝，不能清理器静默吞掉。
6. 世界背景越界仍由既有 `/api/asset` 拒绝；本批无 appearance 资源，正文/控件仍可用。
7. 缓存：按世界、路径、输入重新解析；切层/重载无主题泄漏。
8. 写入后落账失败：返回 `event_failed`，停止清理，不删原事件。
9. 尺寸/可读性不合格：阻断发布，不能用隐藏正文或溢出 CSS 放宽。
