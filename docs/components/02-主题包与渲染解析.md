# 02 主题包与渲染解析

## 一句话定位

本模块把受信任的内建/题材包 preset、世界与层的 `material` 上下文、组件 kind 默认和实体 `appearance` 声明汇合为一个可解释的 `AppearanceResolution`；服务端只把已验证结果交给前端，前端不从 raw frontmatter 猜主题，也不让主题改变组件语义、事件或 `CARD_FORMS` 足迹。

> 本文遵守 `docs/components/00-共同上下文.md` 的冻结形状与权威层级；`resolveAppearance` 已落在 `packages/shared/src/appearance/resolver.ts`，本文的唯一 resolver 约束继续适用于实现与后续扩展。

## 1. 边界：context 与组件实例 appearance

| 数据 | 所属 | 是否组件实例 `appearance` | 处理方式 |
|---|---|---:|---|
| `world.json.material` | 世界画布 context | 否 | 选择当前世界的题材默认 preset 候选 |
| 层 README 的 `material` | 层/场景 context | 否 | 覆盖世界 material，选择该层的题材默认 preset 候选 |
| 层 README 的 `bg` / `bgStyle.tone` / `bgStyle.grain` | 场景背景 context | 否 | 仍由背景读取链处理，**不**隐式覆盖组件维度 |
| `appearance.preset` | 组件实例声明 | 是 | 受 registry 校验的稳定英文 kebab-case ID |
| `appearance.font/surface/accent/ornament/motion` | 组件实例声明 | 是 | 受控维度 ID，逐维验证与降级 |
| `COMPONENT_REGISTRY[kind]` | 组件语义 registry | 否 | 只确定 kind、交互、字段、可移动性等 |
| `CARD_FORMS[kind]` | 足迹契约 | 否 | 仍是尺寸与 seating 唯一来源，preset 不能改 `w/h` |

现状证据：世界 manifest 的 `material` 默认是 `parchment`（`packages/shared/src/schemas/world.ts:27-45`）；层树从 README 派生 `material`（`packages/shared/src/store/layers.ts:51-95`）；层背景的 `bgStyle.tone/grain` 由服务端结构化读取（`apps/server/src/routes/world.ts:194-220`）。因此不能把 `material`、`bgStyle` 与实体 `appearance` 解释成同一个字段。

推荐口径：`material` 可以**间接**选择主题包的 context preset，但不能把自身字符串直接当成组件 `surface`/`accent`；`bgStyle` 只影响场景背景。如果评审要求 `bgStyle` 直接改变卡面，须先修订共享上下文并补组合矩阵，不能在 resolver 中偷偷加入隐式优先级。

## 2. 签名与跨端数据形状

### 2.1 唯一外观 registry（NEW）

`01-外观模型与schema.md` §2.4 的 `packages/shared/src/components/appearance-registry.ts` 是本批唯一 allowlist。它同时登记 kind 能力、preset、允许值、组合冲突与安全 token 元数据；本篇不再声明 `ThemeRegistry`、`ThemePackDef`、`ThemePresetDef` 或第二个 `AppearanceDimension`。

```ts
// 由 01 唯一声明并导出
import {
  APPEARANCE_REGISTRY,
  appearanceCapabilitiesOf,
  appearancePresetOf,
  componentAppearanceDocOf,
  type AppearanceKindCapabilities,
  type AppearancePresetDefinition,
} from '../components/appearance-registry.js';
```

题材包若在未来纳入，必须在构建/启动时把受信元数据编译进这一份 `APPEARANCE_REGISTRY`；不能运行时从 README/frontmatter 注册 ID、token、CSS 或 URL。本批不设计独立主题资产端点，preset 只引用 registry 中的受控 token/装饰 ID。`COMPONENT_REGISTRY` 继续回答“是什么/怎么互动”，`CARD_FORMS` 继续回答尺寸与排座；外观 registry 不得注册 kind、handler、accepts 或 form。

### 2.2 resolver 输入与唯一输出（NEW）

```ts
import type { AppearanceResolution } from '../schemas/appearance.js';

export interface AppearanceResolveInput {
  kind: string;
  entityPath: string;
  frontmatter: Record<string, unknown> | null;
  context: {
    worldId: string;
    layerId: string;
    worldMaterial: string | null | undefined;
    layerMaterial: string | null | undefined;
  };
}

export function resolveAppearance(input: AppearanceResolveInput): AppearanceResolution;
```

`AppearanceResolution`、`AppearanceDiagnostic`、`AppearanceValueSource` 和 `AppearanceDimension` 均从 01 的 schema/registry 导入，不能在本篇重写。`values` 五轴都是已验证 ID；`warnings` 是 `AppearanceDiagnostic[]`；`details.preset` 是对象，维度 source 必须保留 `context-preset` 与 `explicit-preset` 的区分。

`resolveAppearance` 是服务端唯一调用入口：它根据 `context.layerMaterial`（优先）或 `context.worldMaterial` 查 01 registry 的 `materialPresets`，不由 route 预先传入 `contextPreset`。它返回 `AppearanceResolution`，不读写文件、不发事件、不改 `CARD_FORMS`。前端只消费 resolution，不从 raw frontmatter 二次计算。
## 3. 来源与注册分层

### 3.1 内建 preset

`packages/shared/src/components/appearance-registry.ts`（由 01 唯一拥有）登记 base、kind defaults、允许值、组合冲突、官方 preset 和安全 token 元数据。内建 registry 随代码发布，ID 冲突、缺 kind、缺默认维度或 token 元数据非法时启动/构建失败；世界文件不能覆盖它。

### 3.2 未来题材包边界

本批不实现运行时题材包 loader 或主题资产端点。未来题材包只能在安装/构建时被验证并合入同一 `APPEARANCE_REGISTRY`，不能从 README/frontmatter 动态注册 kind、handler、accepts、CARD_FORMS、CSS、脚本或 URL。题材包的受信任来源、版本和签名另立市场/扩展设计，不在本批发明第二个 registry。

### 3.3 世界/层 context

`worldMaterial = world.json.material`，`layerMaterial = layer README.material`（有声明覆盖世界，无声明继承）。02 只把它们映射为**已登记的 context preset ID**；候选按 `[layerMaterial, worldMaterial]` 顺序取第一个已登记值，任一非空但未登记的 material 都产生 `unknown-material`，但不阻止继续尝试下一个候选。只有 frontmatter 明确存在 `appearance` namespace 时才把 context preset 叠加到组件上。缺失 `appearance` 的旧实体只使用 base/kind defaults，确保零视觉回归。`bg`、`bgStyle.tone`、`bgStyle.grain` 只进入场景背景输出，不隐式覆盖组件维度。

若两个 material 都无登记映射，跳过 context preset；显式 `appearance.preset` 仍按 01 的统一优先级覆盖 context preset。material 字符串不能直接变成 surface。

## 4. 唯一解析入口与完整流程

`resolveAppearance(input)` 是唯一入口。服务端在 `/api/layer` 与 `/api/nook` 的 item enriched 装配处分别调用同一函数（`apps/server/src/routes/world.ts` 当前 layer/nook 是两个独立分支），前端不实现 resolver。不得在 `CardRenderer`、`ChalkCard`、主题 loader 或 route 各自复制优先级。


### 4.1 逐步行为契约（每步均说明遗漏后果）

1. **规范化输入。** `frontmatter` 缺失/非对象按空声明处理；kind、路径和 layer/world context 使用服务端已解析值。漏了会让旧文件无法渲染，或诊断 key 不稳定。
2. **确认语义 kind。** 使用现有 `cardKindOf`/组件注册结果，不依据 appearance 猜 kind；检查 `COMPONENT_REGISTRY` 与 `CARD_FORMS` 一致。漏了会让 preset 把 note 伪装成 letter，或产生没有合法足迹的卡。
3. **建立 context 候选。** 只有 `frontmatter` 存在 `appearance` namespace 时，才按 layer material → world material 选择已登记 context preset；缺失 namespace 的旧实体跳过 context。`bgStyle` 只进入场景背景输出。漏了会让旧内容被悄悄改皮，或场景背景改变卡面语义。
4. **按冻结优先级叠加。** 严格为 `base default → kind default → context preset → explicit appearance.preset → explicit dimensions`；显式 `{}` 也可进入 context。漏了会让相同输入从不同路径得到不同皮肤。
5. **校验显式 preset。** 未知/不适用 preset 产生 01 的 `unknown-preset`/`unsupported-preset`，忽略该 preset，仍允许合法显式维度在 kind default 上生效。漏了会把拼写错误伪装成成功。
6. **逐维校验显式值。** 每个维度来自 01 kind allowlist；未知值只回该轴 kind default，其它合法维度保留。漏了会使一个错误字段污染整个主题或穿透 token 注入面。
7. **检查组合约束。** 通过 01 的 conflicts；冲突中的后轴回 kind default并产生 `conflicting-combination`，不改变 kind/`CARD_FORMS`。漏了会让透明叙事变纸卡、装饰挤正文或改变交互目标。
8. **输出 canonical 结果。** 返回 01 定义的 `AppearanceResolution`；同 world/layer/entity/input 得到稳定结果，不使用随机数。漏了会刷新换皮、端间漂移、诊断无法重现。

### 4.2 示例

```yaml
# kind: letter（仅作合法 letter fixture）
type: component
component: letter
appearance:
  preset: parchment-letter
  font: serif
  surface: parchment
  accent: rust
  ornament: seal
  motion: calm
```

若 `ornament: unknown-seal`，结果至少有 01 定义的 `unknown-dimension-value`，`path=appearance.ornament`，`fallback=kind-default`，且 `details.fallbackCount >= 1`；其它维度不受影响。

## 5. 主题 token 与安全边界

1. `appearance` 不接受 raw CSS、任意 class、HTML、脚本、data URI、外部 URL 或任意资源路径；实例只能写 01 registry 授权的 preset/dimension ID。
2. 01 registry 同时登记 ID 与安全 token 元数据；`resolveAppearance` 只返回已验证 ID，绝不把 CSS 字符串、style 对象或 URL 放入 `values`。
3. v1 不新增主题资产 endpoint，也不让 frontmatter 指向主题资源。背景图继续走既有 `/api/asset?path=<world-relative>`，由服务端保持 world root 越界防护（`apps/server/src/routes/world.ts:1147-1167`）。
4. token 元数据缺失时产生统一 `token-missing` 诊断并回 kind 安全默认；不阻断正文、互动、座位或 `CARD_FORMS`。

## 6. 文件与副作用

 - `packages/shared/src/components/appearance-registry.ts`（NEW）：01 的唯一 registry；本篇只消费其查询函数和 token 元数据。
 - `packages/shared/src/appearance/resolver.ts`（NEW）：只实现 `resolveAppearance(input: AppearanceResolveInput): AppearanceResolution`。
 - `packages/shared/src/index.ts`：导出 schema、registry 查询与 resolver；不导出运行时动态注册入口。
 - `apps/server/src/routes/world.ts` 的 layer 与 nook 两个 item enriched 分支：分别组装同一 `AppearanceResolveInput`，写入可选 `appearance` 派生字段。
 - `apps/web/src`：仅由 04 的 renderer 消费 `item.appearance.values`，不在本文件定义 DOM/CSS。

`resolveAppearance` 是纯函数：不读写文件/DB/canvas seat，不发事件，不修改世界。它不提供主题资产 URL，也不新增主题数据库。

## 7. 落账与事件

- 外观声明随实体原有 frontmatter 落盘，仍走现有写文件链；resolver 不建 appearance 表或主题数据库。
- `warnings/details` 必须随层响应可观察，可被服务端日志/测试采样，但不能只留 `console.warn`。
- resolver 不产生新领域事件；外观变化沿用现有实体/层刷新链路，不能伪造 `choice/status/roll_dice/look_at` 或互动事件。
- 包启用/禁用发生在世界加载/服务初始化边界；失败按矩阵回退，不发改变故事语义的事件。

## 8. WS 与前端边界

```ts
// /api/layer and /api/nook item payload (existing fields abbreviated)
{
  items: Array<{
    path: string;
    kind: string;
    frontmatter: Record<string, unknown> | null;
    // ... existing x/y/w/h/z/rot/body ...
    appearance?: AppearanceResolution; // optional for old server/old payload
  }>;
}
```

服务端在 layer 与 nook 两个 item enriched 分支都调用同一 resolver；缺失字段只表示兼容旧响应，不能触发前端 resolver。shared 定义并验证 `AppearanceResolution`；frontend 只消费 `values`，不解析 raw appearance。`COMPONENT_REGISTRY`/`CARD_FORMS` 继续提供语义 kind 与足迹，主题不能替换 `kind`、`w/h`、`z`、事件通道或互动字段。本批不新增 WS frame；现有层刷新重取 `/api/layer` 或 `/api/nook` 即可得到新 resolution。

## 9. 错误与回退矩阵

| 输入/故障 | 阻断层渲染 | 输出诊断 | 固定回退 |
|---|---:|---|---|
| 无 `appearance` | 否 | 无新增 warning | base → kind；Chalk `surface=none` |
| 显式 `{}` | 否 | warnings 按 context 结果 | base → kind → context preset |
| 未知 `preset` | 否 | `unknown-preset` | kind 安全默认 |
| preset 不适用当前 kind | 否 | `unsupported-preset` | kind 安全默认 |
| 单个未知维度 | 否 | `unknown-dimension-value` | 该维度 kind 默认，其它维度保留 |
| `material` 未注册 | 否 | `unknown-material` | 不应用 context preset，使用 kind/base |
| `bgStyle` 未知 | 否 | 不进入 appearance warnings | 背景沿既有默认，component values 不变 |
| 非法组合 | 否 | `conflicting-combination` | 冲突后轴回 kind default |
| registry 缺 kind / 非法 token 元数据 | **是** | `registry-invalid` | 修复 registry，不能回退 note |
| token 缺失 | 否 | `token-missing` | 该 token 的 kind 安全默认 |

“否”表示内容仍可读，不表示错误被吞掉；用户声明/包配置导致的降级必须出现在 `warnings/details`。

## 10. 精确代码落点

1. `packages/shared/src/appearance/resolver.ts` 实现且只导出 `resolveAppearance(input)`；不得让 web 按维度复制优先级。
2. `packages/shared/src/schemas/forms.ts:157-205` 的 `chalkStyleOf` 与 `MATERIAL_SKINS/materialSkinOf` 是当前旧实现；新 resolver 应由兼容适配器读取，不能再增加第三套 style table。
3. `apps/server/src/routes/world.ts:636-651` 已有 item kind/footprint 装配；在这里调用 resolver，尺寸仍来自 `storedSizeOf`/`CARD_FORMS`。
4. `apps/server/src/routes/world.ts:661-675` 已读取 layer README；context builder 送入 world/layer material，保持 `bg` 与组件 appearance 分离。
5. `apps/server/src/routes/world.ts:1147-1167` 的 `/api/asset` 继续服务世界 `bg`；v1 没有 appearance 主题资源路由。
6. `apps/web/src/components/canvas/CardRenderer.tsx:108-119,184-279` 当前按 visual/chalk/letter/note 分支；这是现状证据，不是本文件定义 DOM 的位置。04 接入 `item.appearance` 时保留语义分支和交互。
7. `packages/shared/src/components/types.ts:68-95` 的 `ComponentDef` 当前没有 appearance 字段；本设计保持独立 registry，避免组件 registry 同时承担语义和皮肤。

## 11. 与现状差异

| 现状 | 本设计差异 | 迁移边界 |
|---|---|---|
| frontmatter schema/parser `.passthrough()` 保留未知字段（`packages/shared/src/schemas/frontmatter.ts:117-154`） | `appearance` 可渐进保留，但 resolver 严格验证并输出 warning；passthrough 不算验收 | 05 负责旧字段兼容 |
| `ComponentDef` 只描述语义，无 appearance 字段（`packages/shared/src/components/types.ts:69-95`） | 独立 appearance registry，不重做组件 registry | 01 负责能力元数据 |
| `ChalkStyle` 读取顶层旧字段（`packages/shared/src/schemas/forms.ts:157-194`） | 新入口读 `appearance`，旧读取只作迁移适配 | 05 明确字段映射/冲突诊断 |
| 世界/层有 material，背景有 bgStyle，无组件 resolver | material 只作 context preset，bgStyle 不进 component values | 上位文档需写清两级皮肤 |
| `/api/layer` 与 `/api/nook` 返回 bg/raw item，未返回 resolution（`apps/server/src/routes/world.ts` 的两个 enriched 分支） | 每 item 增加可选 resolution | 04 只消费 verified result |

## 12. 验收测试

1. **非空性/唯一入口断言（没有 resolver 或显式覆盖优先级错误必失败）：** fixture 为 `kind=letter`、world material=`parchment`、layer material=`kraft`、显式 `appearance.preset=parchment-letter`、`accent=sage`。请求 `/api/layer`，断言 `items[0].appearance.values` 非空、`items[0].appearance.values.accent === 'sage'`、`items[0].appearance.details.dimensions.accent.value === 'sage'`。未接 resolver 时 `appearance` 缺失；丢掉显式维度阶段或顺序错误时 accent 断言失败。
2. 未知 preset 只回退 preset：`warnings` 含 `unknown-preset`，合法显式 font 保留，且不产生新事件/DB 行。
3. 未知维度逐维诊断：只设 `ornament=not-registered`，断言 warning `code=unknown-dimension-value`、`path=appearance.ornament`、fallback 非空/`fallbackCount > 0`，其它四维不变。
4. 世界/层 context：world=`parchment`、layer=`kraft` 时 layer 候选优先；移除 layer material 后回到 world；改变 `bgStyle.tone` 不改变 item values，只改变 `bg`。
5. 语义/足迹不漂移：不同 preset 下 `kind`、`w`、`h`、互动字段、事件字段不变，`CARD_FORMS` 仍是 seating 输入。
6. registry token 与尺寸元数据只允许受控 ID；本批不设计运行时主题资产和资产 404 回退。
7. registry fail loud：重复 preset ID、未知 kind、缺 `CARD_FORMS` 行的内建 registry 使启动检查失败，不能静默覆盖或回退 note。
8. 跨端单口径：服务端 `AppearanceResolution` 可被前端仅凭 `values` 消费；不得存在第二个 client-side resolver 优先级。

## 13. 发现的冲突 / 需要修订上位文档

1. `docs/doc-10-组件协议与官方组件清单.md:105-107,129-169` 说皮肤归题材包/doc-04，但仍把组件 schema/注册协议列为待设计；应补充独立 appearance registry，preset 不改变 kind/CARD_FORMS。
2. `packages/shared/src/components/types.ts:69-95` 无 appearance 能力字段；上位文档应明确外观 registry 与语义 registry 分层，题材包不能新增语义 kind。
3. `packages/shared/src/schemas/forms.ts:157-205` 同时承载 Chalk 旧 style 与 material skin；`appearance.surface`、`CARD_FORMS.chrome`、`materialSkinOf` 必须在兼容适配层区分。
4. `docs/doc-04-视觉设计风格.md:146,157-163,170-173` 要求 token 单一源；应明确 token ID 由 appearance registry 提供，CSS 只消费已验证 token，material/bgStyle 是场景级 token。
5. `apps/server/src/routes/world.ts` 的 layer 与 nook 是独立 enriched 分支；需在两个分支调用同一 resolver，不能只接 layer。

## 14. 当前批次外的后续范围

运行时题材包、世界自定义 preset 和主题资源市场不在 v1；未来另立扩展设计，构建时合入唯一 registry。
