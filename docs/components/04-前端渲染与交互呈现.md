# 04 前端渲染与交互呈现

## 一句话定位

本层把唯一的 `AppearanceResolution` 转为受信 CSS token，供 `CanvasObject`、`CardRenderer`、`ChalkCard`、letter/note、第二层阅读和未来 component view 共同消费；只改变“怎么画”，不改变 `CARD_FORMS`、尺寸、点击后果、互动字段或 WS 帧。

外观 schema、优先级、允许值以 `docs/components/00-共同上下文.md:63-94` 及 01/02 为准。前端不重新解析 `frontmatter.appearance`；缺失 resolution 才走旧默认。

## 签名 / 数据形状

01 §2.3 定义的唯一 `AppearanceResolution`（此处只引用，不复制 shape）：

```ts
import type { AppearanceResolution } from '@airp/shared';
```

前端只接收完整 resolution；`values` 五轴均为已验证 ID，`warnings` 是统一 `AppearanceDiagnostic[]`，`details` 使用 01 的 `preset` 对象与 `context-preset` / `explicit-preset` source。

### 前端适配 API（NEW）

`apps/web/src/lib/appearance-view.ts`（NEW）提供唯一前端适配：

```ts
export interface AppearanceView {
  resolution: AppearanceResolution;
  attrs: {
    'data-appearance-preset'?: string;
    'data-appearance-font': string; 'data-appearance-surface': string;
    'data-appearance-accent': string; 'data-appearance-ornament': string;
    'data-appearance-motion': string; 'data-appearance-warning'?: string;
    'data-appearance-fallback-count'?: string;
  };
  style: React.CSSProperties & Record<
    '--appearance-font-family'|'--appearance-ink'|'--appearance-muted'|
    '--appearance-surface'|'--appearance-border'|'--appearance-shadow'|
    '--appearance-radius'|'--appearance-ornament'|'--appearance-motion-duration'|
    '--appearance-contrast-on', string
  >;
}
export function appearanceViewOf(resolution: AppearanceResolution): AppearanceView;
```

`appearanceViewOf` 只把 01 registry 的已验证 ID 映射为前端受信 token；`04` 是唯一 ID→CSS token 的消费适配，不维护第二张 token 表。token 缺失使用 kind 安全 token 并记录统一 `token-missing`；未知值不可拼任意 class、属性名、URL 或 style。装饰由固定 JSX/伪元素分支绘制，默认 `none`。

| 输入 | DOM/CSS 映射 | 不能做什么 |
|---|---|---|
| `values.font` | `--appearance-font-family`，供 `.chalk`、正文、title、preview、阅读层使用；仅允许字体表 | 不改外壳宽高/旋转，不注入 `@font-face` |
| `values.surface` | `--appearance-surface`；`none` 为 transparent。Chalk 默认 bare 必须透明 | 不把世界 `material`/层 `bgStyle`混作组件背景，不由 `.object` 补纸面 |
| `values.accent` + registry `contrastOn` | `--appearance-ink`/border 与 `--appearance-contrast-on`，供 seal、标题线、focus/drag cue；注册表保证前景/表面组合对比度 | 不改变 choice/status/dice 语义色或控件行为 |
| `values.ornament` | `--appearance-ornament`，固定装饰；不挤正文盒 | 不放 raw CSS/HTML/SVG/data URI/任意 URL |
| `values.motion` | `--appearance-motion-duration`，仅有限成形/过渡 | 不做布局动画、无穷动画或拖拽外壳 transform |
| warnings/details | `data-appearance-warning`（稳定 code）和 fallback count，供开发/测试/可选诊断面板 | 不向玩家显示原始 YAML/内部路径 |

`apps/web/src/state/useWorld.ts:24-36` 的 `LayerItem` 增加 `appearance?: AppearanceResolution`（NEW，缺失=旧默认）；服务端在 `/api/layer` 与 `/api/nook` 的 item enriched 分支统一下发，前端不得调用 resolver。`useWorld.ts:154-174` 不得自行读 raw。`card_position`（`:390-405`）及 `canvas_patched`（`:502-528`）仍只合并既有位置/z。

## 行为契约（逐步；每步写“漏了会怎样”）

1. **唯一解析：** resolver 按 kind/context/preset/显式维度输出 resolution；React 只消费 values 与受信映射。**漏了会怎样：** 分支各算一次，卡面/阅读层不一致，未知值静默成功。
2. **外壳一次注入：** `CanvasObject.tsx:231-249` 的 `.object` 挂 attrs/style，使兄弟 `EntityInteractions` 继承；`shellStyle`（`:160-170`）继续独占 left/top/width/zIndex/`--target-rot`。**漏了会怎样：** 互动区回到错误皮肤或每个分支重复注入。
3. **保持分支顺序：** `CardRenderer.tsx:108-119` visual 先于 chalk；gate `:122-181`，letter `:184-247`，registry kind，最后 note `:250-278`；portrait/sprite 仍在 `CanvasObject.tsx:250-276`。**漏了会怎样：** visual 被 registry 吞掉，chalk 变纸卡，角色误进组件卡。
4. **静态根节点：** 只挂既有 class、受验证 `data-appearance-*` 和 CSS vars。**漏了会怎样：** frontmatter 变成 CSS 注入面。
5. **不碰 footprint：** `item.w`、坐标、外壳旋转、`CARD_FORMS` 座位/测高不变；appearance 禁止写 width/height/left/top/transform。**漏了会怎样：** 换字体/装饰改变碰撞、排座、命中。
6. **卡面摘要：** gate title/excerpt/detail、letter title/preview/meta、note title/body、PropCard label 按现状；hover detail 仍是预览，不自动打开。**漏了会怎样：** 源 markdown/frontmatter 泄漏，第二层职责混乱。
7. **互动单一所有者：** `EntityInteractions.tsx:15-16,83-97` 继续负责通用字段；`ChalkCard.tsx:35-41` 仅在 standalone handler 存在时渲染 widgets。**漏了会怎样：** choice/dice 重复或 appearance 改变 payload。
8. **点击/键盘不变：** `CanvasObject.tsx:235-245` 的 pointer threshold、readable、Enter、drag 排除不改；gate 进层、letter open、portable note Take、PropCard inspect/enter 的 callbacks 不变。**漏了会怎样：** 拖拽触发阅读、Enter 失效或焦点不可见。
9. **第二层共用 resolution：** `CanvasObject.tsx:250` 的 `BagItemDialog`（`BagItemDialog.tsx:31-45`）从 `.object` 继承 token；PropCard inspect 与 letter overlay 显式传同一 resolution。**漏了会怎样：** 展开层跳回固定 cream或重复解析。
10. **hover/drag/drop 只反馈：** 既有 `puzzleClasses`（`CardRenderer.tsx:94-106`、`CanvasObject.tsx:218-229`）、Canvas `.dragging-item`（`Canvas.tsx:270-273`）和 drop callback（`CardRenderer.tsx:94-104`）不改；appearance 只改色/影/过渡。**漏了会怎样：** 主题阻断 drop、覆盖 z-index 或制造额外动作。
11. **响应式不扩 footprint：** 卡片宽仍 `item.w`；阅读 max-width/max-height 及互动 right/left/below 算法（`prop-card.css:16-28`、`EntityInteractions.tsx:24-66`）保留，不观察浮层自身尺寸换边。**漏了会怎样：** 窄屏溢出或 ResizeObserver 反馈循环。
12. **动效降级：** `prefers-reduced-motion: reduce` 与 `motion: still` 关闭成形、装饰、hover 位移、puzzle pulse/burst，保留颜色、outline、aria、状态文字与操作性；portrait still 机制（`CanvasObject.tsx:69-72,92-129`、`index.css:1342-1347`）不变。**漏了会怎样：** 减少动效用户仍被抖动，或目标提示随动画一起消失。
13. **诊断可见但不落账：** warnings/fallbackCount 仅开发 DOM、测试和可选只读面板；不写 `status.data`、不发 appearance 事件。**漏了会怎样：** 无法区分未声明和未知值，视觉刷新被误记世界事件。
14. **错误隔离：** resolution/token/装饰 token 失败只回 kind 默认，语义 DOM、正文、互动、阅读、导航、拖拽继续。**漏了会怎样：** 坏主题使整层白屏。

## WS 与前端边界

## 无障碍、响应式与性能细节

`.object` 的 `tabIndex=0`、Enter、focus-visible 与 button/a/input 排除继续（`CanvasObject.tsx:235-245`）。letter overlay 补 `role="dialog"`、`aria-modal`、标题关联和可聚焦关闭按钮，不改变 open/close 语义；ornament `aria-hidden`。背景/正文/控件组合须满足注册表对比度，drag target 同时有 outline，不能只靠颜色。

外壳永远使用 `item.w`；阅读层遵守 `prop-card.css:16-28` 的 viewport 限制，互动区沿既有 right/left/below 算法。resolver/token 映射按 `path + resolution` memo，不为每卡发请求、不插入运行时 stylesheet，不触发 WS 重连或额外测量；变化不改 footprint scheduler 的 kind/w/h。

## 与现状差异

现状 `CardRenderer` 未消费 appearance、直接按 visual/type 分支（`CardRenderer.tsx:72-119`）；本设计统一接入 resolution 但保留顺序。现状 Chalk 使用专用 `chalkStyleOf`（`ChalkCard.tsx:32-55`），05 负责旧字段唯一兼容入口。现状 `ComponentDef` 无 React renderer（`types.ts:68-95`），本设计增前端 view registry但不改共享 registry。现状 letter 使用 cream/阴影/旋转内联值（`CardRenderer.tsx:212-245`），改为同 resolution token并补 dialog a11y；所有动作、尺寸、WS、CARD_FORMS 保留。
