# 03｜作者声明与内容生产

> 状态：实现已落地（2026-09-13）。本篇规定的 Writer / character 使用边界已接入 `extensions/toolkit/component.ts` 与 `extensions/instructions.ts`；不新增工具权限、不新增组件 kind、不定义第二套 frontmatter schema。外观共享形状、优先级、注册表和 resolver 以 `docs/components/00-共同上下文.md` 及 `01` / `02` 为准。

## 一句话定位

作者把“这是信 / 锁 / 板书以及它如何互动”写进现有语义字段，把“它怎么被画”写进唯一的 `appearance` 命名空间；先通过 `get_component` 或已加载的世界外观 skill 查合法英文 ID，再由 `write` / `edit` 落盘，绝不把 CSS、视觉指令或主题冒充成正文、`title`、`status`、`choice` 或 `roll_dice`。

## 签名 / 数据形状

作者继续使用既有工具：

```ts
// packages/shared/src/actions/component.ts:12-15
interface GetComponentInput { component?: string | string[]; }
// packages/shared/src/actions/create.ts:24-32
interface CreateEntityInput { path: string; body?: string; frontmatter?: Record<string, unknown>; content?: string; }
// packages/shared/src/actions/delete.ts:150-180
interface EditEntityInput { path: string; frontmatter?: Record<string, unknown>; body?: string; }
```

`get_component` 当前是只读 registry 门面，无文件、画布或事件副作用（`packages/shared/src/actions/component.ts:89-97`）；省略 `component` 列出已登记 kind，传入 kind 返回该 kind 的字段、用法和示例（`:100-147`）。作者不得因当前返回文本未含 appearance 段落就自行猜词表。

唯一外观输入仍是共享的 `appearance` object（不是第二套 schema）：

```yaml
appearance:
  preset: parchment-letter # 可选，稳定英文 kebab-case ID
  font: serif              # 可选，受控维度 ID
  surface: parchment       # 可选；none 表示无表面/无背景
  accent: rust             # 可选，受控色调 ID
  ornament: seal           # 可选，受控装饰 ID
  motion: calm             # 可选，受控动效档位
```

作者只能填写查询结果允许的 ID。`01` 唯一提供 `AppearanceInputSchema`、`AppearanceKindCapabilities`、`AppearancePresetDefinition` 与 `componentAppearanceDocOf(kind: string)`；本篇只消费其受控 ID、label、description，不定义这些形状，也不扩展 `ComponentDoc`。世界 style / appearance skill 可给题材推荐和世界语言显示名，但推荐不是授权；每个值仍须命中同一 registry / resolver。resolver 的最终值及 `warnings` / `details` 是唯一诊断来源。

## 行为契约（逐步；每步写漏了会怎样）

### 1. 先确定语义 kind

Writer / character 先读目标文件，确认 `chalk`、`letter`、`lock` 或其他 kind；新组件先 `get_component({ component: KIND })`，既有实体先 `look_at`，需要精确修改才 `read`。`look_at` 隐藏原始 YAML、保留正文与互动块（`docs/doc-20-agent工具与互动字段协议.md:151-164`）。外观不能反向改 kind。

**漏了会怎样：** 作者会使用错误字段或把信伪装成锁，导致点击、`use_item_on`、路径和互动语义漂移。

### 2. 取得合法选项

调用 `get_component`（或 01 的 `componentAppearanceDocOf(kind: string)` 经既有查询闭环）取目标 kind 的允许 preset、维度和组合；读取世界 skill 只为获得推荐与本地化说明。既有 `appearance` 默认保持，除非 brief / 玩家 / 迁移明确要求改。没有选项时用 kind 默认，不造 ID。

**漏了会怎样：** `gothic-night` 等自然语言会被误当主题；解析器只能回退，作者却会误报成功且无法定位原因。

### 3. 选择 preset 或显式维度

- 有已确认的整套题材组合时写 `appearance.preset`。
- 只需一处差异时只写显式维度，省略项由 resolver 补默认。
- `preset` + 显式维度只在查询确认组合可用时使用；显式维度覆盖 preset。
- 不需要主题时省略 `appearance`；旧文件缺失它仍是旧默认，Chalk 默认必须透明 / bare ink。

**漏了会怎样：** 每个文件都重复满配会扩大无效值面；强套不适用 preset 会引入装饰冲突、可读性问题或安全回退。

### 4. 严格分离正文与语义字段

`appearance` 只放受控 ID。`body` / `preview` / `title` / `sign` 只写玩家读到的事实、语气、线索，不写 CSS 或主题指令；`choice` 只列语义动作，`roll_dice` 只声明真实检定，`status.data` 只保存状态。正文可以说“蜡封裂开”，但不能用它代替 `ornament: seal`；也不能把 appearance 塞入 `status.data.appearance`。

**漏了会怎样：** 前端无法区分叙事和渲染，模型会把 CSS 展示给玩家，或用伪状态改变互动。

### 5. 先落语义，再落外观

`chalk` 先写正文（工具负责 `type: chalk`、命名和事件，`packages/shared/src/actions/chalk.ts:4-7,48-79`），再用现有 `edit` 第二阶段补 `appearance` 和互动字段；遵守 Writer 提示中互动字段第二阶段规则（`extensions/instructions.ts:101-107`）。letter / lock 先按 `get_component` 建立 kind，再用 `write` / `edit` 写 appearance。编辑后重新 `look_at`，诊断读 resolver，不把原始 YAML当玩家体验。

**漏了会怎样：** 视觉声明会混进正文或形成 stray YAML，字段被 parser 丢弃，且未产生正确事件。

### 6. 可执行 Writer / character 闭环

```text
1. 读世界状态；对将触碰的路径先 look_at，必要时 read。
2. 新建或改 component kind：get_component({ component: KIND })。
3. 只从查询结果 / 世界 skill 的已登记推荐选择 appearance ID；未确认就不用。
4. 先写语义正文和 kind；chalk 先由 chalk 工具落正文。
5. 用 write / edit 写 appearance object，保持 choice/status/roll_dice/accepts，除非语义确实改变。
6. 重新 look_at；读取 resolver warnings/details，修正或报告安全默认，不宣称未知主题成功。
7. 用 choose / roll_dice / use_item_on 处理动作；appearance 永不作为动作参数。
```

Character 的身份和记忆仍来自自身文件（`extensions/instructions.ts:168-176`），只在有真实理由时用工具，并先对新对象 `look_at`（`:190-198`）。角色若获既有编辑权限，重复同一闭环；若仅能写 chalk，则只在第二阶段补 appearance，不能以台词假装改文件。

**漏了会怎样：** 只把外观写在回复里会在刷新后消失；角色越权会使台词、文件真相和事件日志分裂。

### 7. 复制与派生

同 kind、同用途复制可保留 appearance，但须在目标世界重新确认 preset；同 kind、不同语境须按 brief / skill 重新选择；跨 kind 先清除不适用 appearance，再用目标 kind 查询重选。`choice`、`status`、`roll_dice`、`accepts` 仍按原 kind 验证，appearance 不是隐藏动作。

**漏了会怎样：** 原样复制会把旧世界专属主题带入新世界并静默降级；跨 kind 会造成“看起来像信、实际是锁”或错误状态。

### 8. 旧 Chalk 迁移

旧 Chalk 顶层 `font`、`color` / `tone`、`card` / `chrome` 只作兼容输入；`big` / `size`、`collapsed`、`aged` 永远不迁入 appearance，分别保留字号、折叠/摘要和做旧行为。迁移完成后 appearance 是唯一新的外观声明，旧字段仅在兼容窗口读取，不得两套各算一次。

**漏了会怎样：** 全局卡片壳会吞掉 Chalk 透明默认，新旧字段会一次显示 hand、另一次显示 serif。

### 9. 世界语言显示名

协议 ID、kind、工具名、路径和外观值永远是稳定英文 kebab-case；世界 skill 可将 `parchment-letter` 显示为本地语言，但不写回 ID。`title`、`preview`、正文、`choice`、`sign` 和作者报告遵守世界语言；日语世界已要求叙事用日语、协议 key / 值 / 工具名保持不变（`templates/first-snow-jp/language.md:1-8`）。诊断可保留英文 ID 并附本地说明，不把技术值塞进玩家正文。

**漏了会怎样：** 翻译协议 ID 会 registry miss、路径断裂；把英文诊断写进日语信件会污染世界语言。

### 10. 错误必须模型可见

未知 preset / 维度、禁用组合、失效资源或动效不支持时，接受安全默认只能算渲染降级，不能宣称主题成功；读取 `warnings` / `details`，将请求值、回退维度和最终值反馈给模型。能修正就重新查询并 edit，不能修正就保留语义并报告。raw CSS、任意 class、HTML、脚本、data URI、未经校验 URL 一律拒绝，不清洗后继续写。unknown kind 按现有错误先无参数列出注册 kind（`packages/shared/src/actions/component.ts:130-142`）。

**漏了会怎样：** 模型会把 fallback 当成功并在后续正文引用伪主题；问题只在前端出现时无法定位。

## 文件与副作用

| 动作 | 既有落点 | 允许副作用 | 禁止副作用 |
|---|---|---|---|
| 查询 | registry / skill / resolver | `get_component` 只读（`packages/shared/src/actions/component.ts:89-92`） | 不写主题文件、CSS 或事件 |
| 新建 Chalk | 目标 `.md`，先 `chalk` | 既有命名、落盘和一个世界事件 | 不用 bash 绕过引擎，不把 CSS 放正文 |
| 新建 / 编辑 letter、lock | 目标 `.md` 的 frontmatter + body | 既有 `write` / `edit` 事件、fs.watch | 不改 kind、路径、CARD_FORMS 或互动协议 |
| 复制 / 迁移 | 既有写文件路径 | 既有创建 / 编辑事件 | 不产生主题专属事件或隐式动作 |

`appearance` 属于实体编辑，不新增数据库、独立状态文件或主题市场。`editEntity` 读取、浅合并 frontmatter、保留 body 后写回（`packages/shared/src/actions/delete.ts:147-180`），不得用整文件替换抹掉未涉及互动字段。

## 落账与事件

1. `get_component` / 选项查询不落账、不写文件、画布或事件。
2. `write` / `edit` 沿用实体创建 / `entity_edited` 事件，不新增 `appearance_selected` 或 `theme_applied`。
3. 复制 / 迁移使用既有创建 / 编辑事件；诊断进统一 resolver details，不造作者日志表。
4. `choice_selected`、骰子、`use_item_on` 仍只记录互动事实；锁开关仍由 `status.data.locked` 与 handler 处理（`packages/shared/src/components/core.ts:39-53`），不由 appearance 推断。
5. 作者报告可引用 warnings 供下一轮模型修正；报告不是玩家正文或持久协议。

## WS 与前端边界

- 不新增 WS 消息、权限或作者通道；Writer / character 沿用现有 agent 工具事件。
- 前端只消费 `02` resolver 的验证结果和 `04` token，不直接解析 raw frontmatter，不执行 appearance 字符串。
- 不把 appearance 摘要塞进 `choice`、`status.data`、`[emo:]` 或 Chalk 正文通知前端。
- warnings / details 可返回模型；玩家是否看本地化外观名由 `04` / `05` 决定。
- 外观不改变 `CARD_FORMS`、尺寸、路径、收藏、点击、`choose`、`roll_dice`、`use_item_on` 或 `look_at` 语义。

## 错误边界

| 状态 | 模型可见反馈 | 正确动作 | 不得做 |
|---|---|---|---|
| 未知 preset / 维度 | warning + 安全回退 | 重新查询修正或明确接受默认 | 宣称成功、改正文掩盖 |
| 禁用组合 | details 指出冲突 | 删除不适用维度，保留 kind 默认 | 强行拼装或改 kind |
| skill 过期 ID | registry / resolver unknown | 以 registry 为准并报告 | 把 skill 当授权 |
| raw CSS / class / HTML / script / data URI / 未校验 URL | 参数错误 | 拒绝外观编辑，语义可继续 | 清洗后写入、执行或展示 |
| 跨 kind / 世界复制 | 目标查询不允许 | 清除并重选或默认 | 原样复制后静默降级 |
| 旧字段冲突 | 迁移诊断列字段 | 按 05 规则处理 | 两套解析器各取一个值 |
| 资源字段 / 动效不支持 | v1 appearance 不接受资源 URL；motion 只在 `still`/`calm` | 保持正文和互动可读并报告 | 伪造资源或改变语义 |
| 查询无 appearance 选项 | registry 未给该 kind 能力 | 使用默认并登记 01/02 缺口 | 03 自扩展 ComponentDoc / 词表 |

## 示例：Chalk、letter、lock

> 以下是设计验收 fixture：只有 registry / resolver 返回允许集合后才能写；示例文本不是作者自由词表。

### Chalk

```markdown
---
type: chalk
title: The Lamp Goes Out
choice:
  - Check the desk
appearance:
  font: serif
  surface: none
  accent: ink
  motion: calm
---

The lamp gutters once, then leaves the desk in darkness.
```

`surface: none` 保持 Chalk 默认无背景；`choice` 仍是玩家动作入口，appearance 不增删选项。正文是“灯灭了”的世界事实，不能写 `background: transparent` 或 `.chalk { ... }`。

### letter

```markdown
---
type: component
component: letter
title: A Letter from Watson
preview: The envelope is damp; the ink has run at one corner.
sign: J.W.
seal: wax-red
choice:
  - Open the letter
appearance:
  preset: parchment-letter
  font: serif
  surface: parchment
  accent: rust
  ornament: seal
  motion: calm
---

I would not trouble you if I could see another way.
```

`component`、标题、预览、落款、正文决定信的语义；`seal: wax-red` 是现有 letter 字段（`packages/shared/src/components/core.ts:108-135`），不是 `ornament` 的替代。choice 仍由 choose 执行，换 surface 不改变阅读层或 `use_item_on` 资格。

### lock

```markdown
---
type: component
component: lock
title: The Cellar Door
preview: A padlock newer than the door it guards.
accepts:
  itemKinds: [note]
  itemTags: [key]
status:
  data:
    locked: true
appearance:
  surface: iron
  accent: rust
  ornament: etched
  motion: calm
---

The padlock is bright and oiled. Someone has been keeping this shut.
```

`accepts` 与 `status.data.locked` 仍由 lock handler 负责；钥匙通过 `use_item_on` 把 locked 改为 false，appearance 不参与判定（`packages/shared/src/components/packs/adventure.ts:13-44`、`packages/shared/src/components/core.ts:39-53`）。`iron` / `etched` 是 lock registry 的受控值；若将来删去它们，示例必须同步改为当前 allowlist，不能因正文写“铁锁”就伪造主题。

## 验收测试

1. **查询闭环：** Writer 对 letter / lock / chalk 先查询；写入的每个 preset / 维度都命中同一查询 / resolver 允许集合，查询无文件、画布或事件副作用。
2. **skill 非授权：** skill 推荐未登记 ornament 时流程拒绝或删除该值并留模型诊断，不能凭 skill 写入。
3. **缺选项默认：** 查询不提供某 kind 选项时仍可生成语义文件，但不得臆造 ID。
4. **Chalk 默认无背景：** 无 appearance 的旧 Chalk 与 `surface: none` 新 Chalk 都是透明 / bare ink，不能被全局卡片壳补成纸面。
5. **互动不变：** 只改 letter / lock appearance，choice、status、roll_dice、accepts、动作路径、事件类型和 CARD_FORMS 不变；合法 key 仍能使 lock 的 locked 从 true 变 false。
6. **正文隔离：** body / title / preview / sign 不出现自动插入的 CSS、class、HTML 或主题指令；视觉声明只在 appearance。
7. **两阶段：** chalk 先写正文再 edit appearance，正文和互动保留，resolver 能读到合法外观。
8. **复制 / 迁移：** 同 kind 复制保留合法 appearance；跨世界旧 preset 给 warning 并回退；letter → lock 不自动搬 seal；旧 `font: hand` / `tone: rust` / `card: true` 按 05 映射且透明默认不变。
9. **世界语言：** 日语世界 appearance ID 仍英文 kebab-case，标题、正文、choice、显示名为日语；翻译不改变命中。
10. 模型反馈：unknown、禁用组合或严格写入拒绝都进入工具 / resolver `warnings` / `details`，不能只写 console。
11. **Character 边界：** 无实体编辑权限的 character 台词不会改变 appearance 文件；有权限也必须查询并用同一验证入口。
12. **必须失败的非空性断言：** 对以下输入，未实现验证闸门的对照测试必须至少失败一条；实现后必须拒绝写入且不产生 `entity_edited`，不能仅接受后回退（否则非法 raw CSS / 伪造主题已落盘）：
