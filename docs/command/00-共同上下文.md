## 1. 这个模块解决什么（产品答案）

### 1.1 一句话

> 玩家用**掷骰**在**一张事先公开了四档后果的调查 Chalk** 上追求**让角色替自己把线索连起来**，收到**毫秒级落盘、可复访的真实结果**（一份笔记出现在桌上／一份灯油从背包消失），并有理由去尝试**这个结果解锁或关闭的下一条路**。

### 1.2 真正的理由不是"快"，是"可靠"

"对抗作家 Agent 的 5 秒 loop"是这个模块最容易说出口的理由，但它不是最根本的。**更根本的是：Agent 执行确定性规则是不可靠的。**

同一个世界规则「61–95 不发成功线索」，作家 Agent 可能这一轮执行、下一轮忘记；可能重复发一次奖；可能把 `result: 62` 读成"接近成功"就网开一面。这些都不是提示词能根治的失败——它们是把**确定性裁决**交给**概率性生成器**的结构性后果。

因此本模块的分工原则是：

> **确定性的后果由代码执行，不确定性的意义由 Agent 叙述。**

代码负责"灯油少了一份、笔记出现在 `world/london-map/investigation-success.md`"；Agent 负责"雾散开一线，你看清了第二艘船的舷号"。两者都不可替代，也都不该越界。

"毫秒级"是这条分工的**副产品**，不是它的目的。

### 1.3 需求不是想象出来的，是内容层已经长出来的

**这是本批次最重要的一条证据。**

`dice_outcomes` 这个字段已经存在于工作树中的**大量文件**里。**定稿快照 `9af9c9b` 的实测（主 agent）**：`git grep -l dice_outcomes` = **44**。**准确分解**：**36 个 `04-investigation-dice.md`**（`templates/**/world/**` 24 个 + `archive/templates/pre-bilingual-2026-09-14/**` 12 个）+ **6 个 `SKILL.md`** + `tools/localize-world-editions.mjs` 1 个 + `docs/` 1 个。

## 2. 命名与边界（冻结）

### 2.1 `command` 这个词已经被占用一次，必须消歧

- **pi slash command**：`/airp-init`，注册于 `extensions/toolkit/init-command.ts:173-182`，是 **agent 会话内的斜杠命令**。
- **AIRP world command（本模块）**：世界目录下的玩法脚本，由**动作层**执行，与 agent 会话无关。

**冻结口径**：

- 文档中一律称**「世界命令」/ world command**，不得简写成"command"而不加限定，除非上下文是本批次文档内部。
- 代码中的类型、函数、文件名一律带 `WorldCommand` / `worldCommand` 前缀（`WorldCommandSpec`、`runWorldCommand`、`world-command.ts`），**禁止**出现裸 `Command` 类型名。
- 世界目录下的目录名仍为 `command/`（用户指定，且与 MC 命令方块的类比一致）。

### 2.2 世界命令 ≠ 扩展（mod），这是两层东西

| | 扩展（pi extension） | 世界命令（本模块） |
|---|---|---|
| 类比 | MC 的 mod | MC 的命令方块 |
| 运行位置 | **agent 进程内**（`extensions/*.ts`，jiti 直跑 TS） | **动作层**（`packages/shared`），玩家 HTTP 路径与 agent 工具路径共用 |
| 权限 | **完整 Node 权限**（`docs/doc-05:440-442`），可开文件、开网络、注册工具与 hook | **仅能编排动作层白名单能力**，无 fs / net / 任意代码 |
| 何时跑 | agent 生命周期钩子（`agent_start` / `context` / `tool_call` / `tool_result`，见 `extensions/context.ts:153-190`（旧标 `:128-164`，**快照已漂移**）、`world-context.ts:50-103`） | 玩家或 agent 触发一次动作时，同步执行 |
| 谁写 | 开发者 / 社区，需要懂 TypeScript 与 pi API | **作家 Agent 当场写**，或内容作者手写 |
| 能否在"玩家点击→HTTP"这条不经过 agent 的路径上执行 | **不能**（扩展只挂 agent 钩子；玩家路由 `apps/server/src/routes/world.ts:1187-1225`（旧标 `:1100-1138`，**快照已漂移**） 直接调 `serviceFor` 动作层，完全不经过 agent 进程） | **能，且这正是它存在的理由** |

> 上表最后一行是本模块**不可被扩展替代**的硬证据：`POST /api/dice` 与 `POST /api/use-item` 走 `world.ts:1187-1225`（旧标 `:1100-1138`，**快照已漂移**） 直接进动作层，agent 进程此刻根本没有被唤醒，任何扩展钩子都不会触发。

> ⚠️ **但不要把"扩展"读成"社区世界包目前是纯数据"**（`09` 取证）。世界包**今天已经**能在 agent 进程里执行任意 Node 代码：
> - `launch.ts:70-76` 的 `--no-extensions` 只挡**自动发现**（注释 `:55-56` 逐字点名 `<cwd>/.airpworld/extensions/*.ts`）；
> - 而 `presets.ts:142-165`（旧标 `:129-149`，**快照已漂移**） 的 `extensionArgs(repoRoot, worldRoot)` 把 `<worldRoot>/extensions/` 下每个 `.ts`/`.js` **显式** `--extension` 传进去，`launch.ts:147`（writer）与 `:204`（character）都调它；
> - `launch.ts:63-65` 逐字：「Explicit `--extension` / `--skill` still load under `--no-*`」。
>
> → 社区世界包带一个 `extensions/evil.ts` 就在两个 agent 进程里全权限执行，而 `--approve` 已预授信任。`skillArgs`（`presets.ts:115-119`）把 `<worldRoot>/skills/` 塞进 agent 指令面，路径更短。**世界命令的任何注入面都比这条短。** `09` 已登记（其 §11.3）。这是**既有**风险，本批次不修，但不得被"C1 引入了安全面"这种说法掩盖。

### 2.3 它是"编排"，不是"编程"——这条必须对用户诚实

世界命令**不执行任意代码**。它是**声明式的效果编排**：条件 + 效果序列 + 参数 + 链式触发。

选这条路线的证据（全部是本仓既有的、被刻意写下的设计决定）：

1. `packages/shared/src/rules/dice.ts:193-195` 逐字：「Deliberately NOT Turing-complete: no parentheses, no variables, no arithmetic — only "did this check pass"」。
2. `packages/shared/src/rules/interactive.ts:70-72` 逐字：「Grammar is deliberately tiny: `<flatKey> ("==" | "!=") <scalar>`. Anything else … is malformed → fail-closed」。
3. `apps/server/src/engine/declared-actions.ts:72-153`（旧标 `:70-145`，**快照已漂移**） 的 `parseRecipe` 是逐字段白名单 + 上限 + 正则，没有任何求值器。

**组合空间从哪来**：效果原语 × 条件 × 参数 × 链式触发，**不是**语法的图灵完备性。MC 命令方块同理——它不是编程语言，它是固定命令集 + 选择器 + 条件 + 红石链；命令方块能把原版 MC 玩成 RPG，靠的是组合，不是语法。

**这条的代价必须写进决策记录**：确实存在一类玩法（需要循环、需要累加器、需要跨实体聚合计算）无法用声明式表达。本批次**不假装能做**；`docs/command/09` 负责给出这条边界在哪里、以及未来若要突破需要付什么代价。

**这条路线不是本仓独创，有成规模的工业先例**（`agent://SandboxExec` 调研）：Kubernetes 的 ValidatingAdmissionPolicy 与 CRD validation、Google Cloud IAM Conditions、Unleash 的 feature flag targeting，全部是**声明式规则 + 白名单上下文，不跑用户 JS**。它们共同的表达式层是 **CEL**（Common Expression Language），`cel-spec` README:16-24 逐字：「CEL evaluates in linear time, is mutation free, and not Turing-complete … allows … faster than equivalently sandboxed JavaScript」。

形态类比同样成立：**GitHub Actions = YAML 结构 + `if:` 表达式**，与本模块的 **YAML `do` + `when`**（§3.2）同构。

> CEL 是 `03`（求值）统一 `parseExpect` 与 `evalWhen` 时 MUST 正式评估的**第三个候选**（另两个：扩展其一、合并两者），也是 `09` 评估静态上限分析时的输入。**本文不预选 CEL**——它的表达力可能远超需要，依赖负担与错误文案的 LLM 友好度都要算进去。

## 3. 文件与目录契约（冻结）

### 3.1 目录

```text

├── world.json
├── world/            # 层树（唯一成层的地方）
```

### 3.2 文件形态：独立 YAML，**不是** `.md`

> **2026-09-14 修订（明月质疑，已采纳）。** 本节原先规定 `.md` + frontmatter，理由是"与世界同构 / 正文给人读 / 复用既有写入通道"。三条全部被推翻，修订记录见 §10.6。

世界命令是 `command/<id>.yaml`，**不是** `.md`、不是 `.json`、不是 `.js`。

**核心分界**——这是本节存在的理由：

| | 载体 | 回答什么 | 谁是真相源 |
|---|---|---|---|
| **实体** | `world/**/*.md` 等的 frontmatter | 我这里有什么、**发生什么时调谁**（`on:`） | 世界内容 |
| **世界命令** | `command/<id>.yaml` | **被调到时做什么**（`do:`） | 世界规则 |

**「世界里的实体」与「世界的规则」是两个概念，不能共用一种载体。** `world.json`、`characters/<id>/preset.json`、`.airpworld/settings.json` 都不是 `.md`——「文件即真相」（`AGENTS.md` §2）说的是**叙事状态**以文件为真相源，不是"万物皆 Markdown"。规则不是世界的内容物。

选 YAML 的四条理由：

1. **strict schema 能拒绝未知字段——这是 passthrough 陷阱的机制性对策（覆盖面仅限命令文件，见理由 1 的警告）。** 实体走 `EntityFrontmatter`，它对未知 key 是 **passthrough 保留**（`packages/shared/src/schemas/frontmatter.ts:137-146` 两个 `.passthrough()` 的 intersection；`:150-166` 注释逐字「NO schema filtering」）。`dice_outcomes` 正是靠这个 passthrough，在大量实体文件里（定稿 `9af9c9b` 声明规模 36；**HEAD 已 48**，MUST 现测，见 §R.25）"写了、没人执行、也从不报错"地活到今天。命令文件走**独立的专用校验器**，unknown key 与未命中注册表的 `action` 名一律 **reject**，不 passthrough。**`.md` 路线会把这个陷阱一起继承过来。**
   > ⚠️ **这条保护不覆盖 `on`**（`02` 取证，主 agent 确认）。`on` 住在实体的 `.md` 上，走的是**同一个** `parseFrontmatter`，因此写歪的 `on`（未知 hook、`run` 拼错、`when` 语法坏）在 passthrough 下**照样静默保留**——与今天的 `dice_outcomes` 无异。**迁移到 `on` 不会自动获得 strict 保护。** 缺口只能靠 `07` 在 `extensions/world-context.ts:50-56` 写入时校验 + `02` 触发时校验两处补。已登记为 §10.8。
2. **没有正文，就没有第二个真相源。** `.md` 的正文不受 schema 约束：作者可以在正文写"扣 2 份灯油"而 `do` 里写 1 份。说明文字用受 schema 约束的 `name` / `desc` 字段承载，和 GitHub Actions 的 `name:` 完全一致。
   > 这正是本文 §8 反模式 1 批评 `origin/niko` "把幂等标记藏进正文"的同一类错误——原设计自己犯了它。
3. **LLM 写 YAML workflow 的可靠性是全网最高的一档。** GitHub Actions / GitLab CI / Ansible 的训练语料密度极大，而"Agent 当场创建命令"（§6）是本模块的核心产品主张，写对率直接决定它成不成立。
4. **顶层即 schema，无 `---` 分隔符歧义**，也不必借用为实体设计的解析路径。

### 3.3 命名空间（冻结分配）

#### 3.3.1 命令文件 `command/<id>.yaml` 的顶层 key

由 `01` 定义完整 schema。**strict：未在 schema 中声明的顶层 key = 写入时报错**，不保留、不忽略。

| key | 含义 | 归属模块 |
|---|---|---|
| `name` | 人类可读名（对应 GitHub Actions 的 `name:`） | `01` |
| `desc` | 一句话说明，取代原设计的 Markdown 正文 | `01` |
| `params` | 参数声明 | `01` |
| `do` | 效果序列 | `01` |

> **不再有 `type: command`**——文件位置（`command/`）与扩展名（`.yaml`）已经确定了它的身份，再加一个 `type` 字段是冗余的第二真相源。

#### 3.3.2 被触发实体的 frontmatter 顶层 key

实体仍是 `.md`，仍走 `EntityFrontmatter`。本模块在实体上**只**占用以下三个 key，任何设计文档 MUST NOT 自行发明第四个：

| key | 出现在 | 归属模块 |
|---|---|---|
| `on` | 被触发的实体（chalk / note / README …） | `02` |

## 4. 执行位置契约（冻结）

### 4.1 世界命令在**动作层**执行，不在 server engine

- 玩家点击 `POST /api/dice` → 触发发奖；
- 作家 Agent 调 `roll_dice` 工具（`extensions/toolkit/roll-dice.ts:47-53`，只传 `path`）→ **不触发发奖**。

## 5. 身份、事件与 turn（冻结）

### 5.1 actor = **触发者**，不是 `engine`

世界命令产生的事件，`actor` MUST 是**触发这次动作的那个 actor**（玩家掷骰 → `player`；作家调工具 → `writer`）。

**不使用 `engine`**，尽管它存在且注释写着"reserved for trusted internal callers"（`packages/shared/src/actions/actor.ts:8,102-105`（旧标 `:9,80-83`，**快照已漂移**））。理由：从世界的角度，是**玩家的行动**导致灯油减少，不是"引擎自己拿走了"。历史面板与作家注入都应把因果归给玩家。`doc-21 §3.2` 之所以把 `god` 从 `player` 里单列，正是因为"世界自己变了"与"你让它变了"在叙事上是两件事。

**`functional` 不在命令的 actor 集合里（2026-09-15 裁定，基线 `50dd228`）。** `ActorType` 已从 5 值变 **6 值**，新增 `'functional'`（`packages/shared/src/actions/actor.ts:8` 逐字 `'player' | 'god' | 'writer' | 'character' | 'engine' | 'functional'`），并新增两个导出 `FUNCTIONAL_ARRANGER_ROLE` / `FUNCTIONAL_ARRANGER_SCOPE`（`:18-19`）。**世界命令 MUST NOT 产生 `functional` actor。** 依据三条：
>
> 1. **语义不同**：`actor.ts:5-7` 的注释逐字说它是「a deliberately narrow actor for player-authorized maintenance agents」——一个**被玩家授权、作用域受限的一次性维护会话**；而命令事件的 actor 是**触发者**（本节的冻结语义）。二者的身份来源不同：命令 actor 来自 `ctx.actor`（`packages/shared/src/actions/service.ts` 的 `createActionService(store, actor)`），`functional` actor 来自 `resolveFunctionalArrangerActor(role, scope)` 这条**独立的 fail-closed 入口**（`actor.ts:58-69`），注释逐字「It intentionally does not call the compatibility resolver above」。
> 2. **能力面不重叠**：`functional` 唯一被授权的动作是 `arrangeCanvas`，且它带硬门——`packages/shared/src/actions/canvas.ts:433` 逐字 `if (ctx.actor.type !== 'functional' || ctx.actor.id !== 'canvas-arranger' || ctx.agentScope !== FUNCTIONAL_ARRANGER_SCOPE) fail('unsupported', ...)`。**任何非 arranger 会话调它都被 `unsupported` 拒**，所以命令效果即使引用 `arrangeCanvas` 也跑不成功（见 §4.2 的能力集约束）。
> 3. **落事件面不重叠**：`canvas.ts` 的 `linkCards` / `arrangeCards` / `arrangeCanvas` **零个 `appendEvent`**（本节 §4.2 下方与 §10 的实测），而命令效果 MUST 落到会落账的动作上。所以 arranger 的产物本来就不进事件流，也就没有「命令该不该用 `functional` 落账」这个问题。
>
> **对读者的实操含义**：`actor` 字段的任何共享枚举（渲染模板、历史面板、`on` 的 `actor` 比较）**不需要**为命令扩充 `functional`；但**共享的 `ActorType` 类型本身已经含它**，因此任何 `switch`/穷举 MUST 覆盖它（TS 的穷尽性检查会强制）。`docs/command/02` 的 `actor` 变量行已同步。

**归属信息只用一个可选键**：`detail.command = '<id>'`。

> **2026-09-14 修订（`10` 取证，主 agent 采纳）**：原设计写 `detail.by = 'command'` + `detail.command`，**`by` 已删**。原因：`detail.by` 已被 `layer_initialized` 占用且是**闭枚举** `z.enum(['writer','player','engine'])`（`packages/shared/src/schemas/events.ts:99`），而 dev 模式 `appendEvent` 对 detail 跑 `safeParse`（`local-store.ts:760-771`（旧标 `:668-679`，**快照已漂移**））→ 写 `'command'` **会炸**。今天不炸只因 `recordLayerInitialized` 不在 `04` 的**七个**效果里（旧标"九个"，已随效果集 8→7 修正）——是个埋着没炸的雷。

世界命令的每个效果都经动作层执行，因而落的是那个动作**本来就会落的事件**（创建笔记 → `entity_created`；移动物品 → `entity_moved`）。

### 5.3 turn：复用触发者的 turn，不新造

`ActionContext.turn` 的语义是「一个 agent turn，或一个 HTTP request」（`packages/shared/src/actions/types.ts:18-22`）。世界命令在触发动作的同一次调用内执行，因此**天然共享同一个 turn**。

后果（**2026-09-14 修订：原表述被 `10` 实测证伪**）：玩家掷骰产生的 `roll_resolved` 与命令产生的 `entity_created` **带同一个 turn**——这是成立的。但**"作家下一轮会把它们合成一组连贯事实"不成立**，见 §10.10。

各文档 MUST NOT 依赖"同 turn 自动合并"来保证因果可读性；事件的**主语渲染**才是承载手段（`10` 负责）。

## 6. Agent 创作契约（冻结）

「Agent 能在需要玩法时当场创建世界命令」是本模块的核心产品主张。以下是它成立的前提条件，全部是硬门。

### 6.1 写入即校验

Agent 写入一个 `command/<id>.yaml` 时，MUST 在**写入时**完成 schema 校验，错误以**模型可见的文本**返回，让 Agent 当场自修。

**禁止**"写入时静默接受，玩家触发时才炸"。理由：`dice_outcomes` 正是这样活了 36 个实体文件却从未被执行——passthrough 让错误无声（§3.2 理由 1）。命令文件走 strict schema，**这一侧的陷阱已被机制性关闭**；实体侧的 `on` 字段仍在 passthrough 下，见 §3.3.2 末尾的警告。

### 6.2 必须放开写入门禁

**现状（已核实）**：`extensions/world-context.ts:50-56` 拦截 `write`/`edit`，条件是 `(world/ | player/ | characters/ 前缀) && .md 结尾`，其余一律 `block: true`。因此 **Agent 目前既写不了 `command/` 前缀，也写不了 `.yaml` 扩展名**——两个维度都挡着。

冻结要求：门禁改为**按前缀分派扩展名**——`world/` | `player/` | `characters/` 仍只放行 `.md`；新增 `command/` 只放行 `.yaml`。**MUST NOT** 改成"放行 `command/` 下的任意扩展名"，也 MUST NOT 放宽三个内容根对 `.md` 的限制。`07` 负责给出精确 diff 与随之而来的落账口径（命令文件的创建该不该落 `entity_created`？它不是 entity，也不在层里——`resolveLayer` 返回 `null`，`kind` 无从填起。这是 `[未拍板 C-2]`）。

> **同时登记一条安全事实**：Agent 还有 `bash` 工具（`vendor/pi-rp/.../tools/bash.ts:90-106`，无路径/扩展名白名单），`world-context.ts` 只拦 `write`/`edit` **不拦 bash**。因此"Agent 写不了 command/"在**工具层面**成立，在**物理层面**不成立。这是既有事实，不是本模块引入的；`09` 负责在云端多租户场景下评估它。区分**工具级强制**与**提示词级约束**（`extensions/instructions.ts:262-263` 是后者）。

### 6.3 命令随世界走，但它不是世界的内容物

世界命令属于**世界包**，跟着世界分发、备份、回滚。它**不进** `extensions/`，**不进**仓库根，**不需要**重启 agent 进程生效。

但它**不是**世界的内容物（§3.2）：它不成层、不是实体、不出现在画布上、不被 `look_at` 当卡片列出、不进背包。它是这个世界的**规则**。

## 7. 不可协商的硬门（hard gates）

任何模块设计违反以下任一条，评审 MUST 驳回，不接受"下一批再补"。

1. **文件即真相**。每个效果 MUST 落成文件变化 + 事件，不得只改内存或只发 WS 帧。一条审计事件本身也不够——玩家要能在画布上复访到它（`_shared/shared-vocabulary.md:21`）。
2. **不重复结算**。同一意图 × 同一目标 × 同一已结算结果，重复触发 MUST 复用既有结果，MUST NOT 二次发奖、二次扣除、二次掷骰（`_shared/failure-and-revisit.md:22`）。
3. **不篡改已结算事实**。世界命令 MUST NOT 改写 `roll_dice.result` / `passed`，MUST NOT 删除 `result` 制造免费重掷（`Chalk玩法形态与判定约定.md:28`）。
4. **不静默失败**。命令写错、目标缺失、上限超出 → MUST 进入**模型可见的输出**与**玩家可见的状态**。`console.warn` 不算（本仓既有教训，`design-first-feature-workflow` §「四类立刻可用的检查项」第 6 条）。
5. **不越权**。能力集 ⊆ 动作层（§4.2）。世界命令 MUST NOT 获得 Agent 本身没有的权限。
6. **不消耗不存在的东西**。扣除前 MUST 检查存在性；缺失 = 拒绝 + 说明缺什么，MUST NOT 把缺失静默当成功（`Chalk玩法形态与判定约定.md:41`：「灯油是拟新增的可损耗资源，未拥有时不能凭空扣除」）。
7. **关掉仍可玩**。世界命令被禁用或执行失败时，世界 MUST 仍能通过作家叙述继续；MUST NOT 变成死局（`_shared/failure-and-revisit.md:15`：失败要给出真实的下一步）。
8. **先公开，后执行**。命令造成的代价与回报 MUST 在玩家决定之前可见（`Chalk玩法形态与判定约定.md:20-28`）。命令不得引入玩家事先不知道的扣除。

## 9. 决策记录（governance）

### 9.1 玩家结果与假设

- **玩家结果**：玩家的高风险决定会**立刻**在世界里留下真实、可复访、代价对称的痕迹，且这个痕迹不因为"作家这一轮忘了"而消失。
- **可证伪假设**：如果把确定性后果交给代码执行，玩家在**重复触发、失败、中断、复访**四种情况下看到的结果将保持一致；若实测仍出现重复发奖或漏扣，则本方案的核心假设被证伪。

### 9.2 候选对比（含"什么都不做"）

### 10.7 已存在的 bug：一次 HTTP 请求可能产生**两个** turn（主 agent 实测，2026-09-14）
