## 1. 一句话问题

**「玩家一进门 / 一选项，作家立刻起一轮」是 niko 侧的一个实现选择（commit `f914d0a`，`routes/world.ts` 的 `dispatch`），它绕过了 I1 初始化内核、也违反 doc-21 §5.5；而 main 侧的 I1 前端触发线（`airp_init`）在合并中被丢掉，只剩服务端 handler。** 玩法上「开门即生成」的 Demo 节奏又是需要的，于是不能一刀切删掉——**做成一个每世界可配的三态开关，默认回到契约（`off`）。**

一句话修法：**`<worldRoot>/.airpworld/settings.json` 存 `{ autoWrite }`；服务端 `/api/world-settings` 读写；`/choice` 按档决定是否 `dispatch`；`/enter-layer` 永不 `dispatch`（门回归 I1，前端按 `first` + 开关发 `airp_init`）。**

## 2. 冻结契约

### 2.1 三态语义（唯一真相源）

| `autoWrite` | 进未写场景（门） | 玩家选项（choice） |
|---|---|---|
| `off`（**默认**） | 只落 `layer_entered`，作家在玩家下一轮注入里看见 | 只落 `choice_selected`，同上 |
| `scenes` | 前端发 `airp_init` → I1 内核建场景 | 只落 `choice_selected` |
| `scenes-and-choices` | 同 `scenes` | 服务端 `dispatch` → 作家起一轮 |

**为什么门与选项分开**：两者是**不同性质的工作**。门 = **场景物化**，是 I1 的活（`scene-init` preset + 结构化 brief + 产物校验 + W2 兜底 + 并发在飞锁）；选项 = **叙事推进**，本来就是作家的活，I1 没有也不该有 choice 处理器。合成一个布尔会逼出「要么两个都自动、要么两个都不自动」的假二分。

### 2.2 纯函数（`packages/shared/src/schemas/world-settings.ts`）

```
AutoWriteSchema     = enum(['off', 'scenes', 'scenes-and-choices'])
WorldSettingsSchema = strict({ autoWrite })
DEFAULT_WORLD_SETTINGS = { autoWrite: 'off' }
startsSceneInit(autoWrite)   ⟺ autoWrite ∈ {scenes, scenes-and-choices}
startsChoiceTurn(autoWrite)  ⟺ autoWrite === 'scenes-and-choices'
```

**MUST NOT** 在别处再写一份档位判断——服务端与前端同 import 这两个谓词。

### 2.3 存储（每世界一份）

- 路径：`<worldRoot>/.airpworld/settings.json`，内容 `{ "autoWrite": "off" }`（原子写：`.tmp` + `rename`）。
- **为什么每世界**：它决定那个存档的节奏，跟 `model-preferences.json` 同族、同为**存档属性**；放 `localStorage` 会让服务端看不见（服务端才是决定是否起一轮的一方），两边必漂。
- **MUST 当作不可信输入**：本文件用户可手改，用 `.strict()` + `.partial()` 解析，**任何非法值/坏 JSON 一律 fail-soft 回默认**（`off`）——绝不因一个手改文件把路由搞崩。
- 读：`apps/server/src/engine/world-settings.ts::readWorldSettings`；写：`writeWorldSettings`。

### 2.4 端点（唯一读写口）

| 方法 | 路径 | 体 | 返回 |
|---|---|---|---|
| GET | `/api/world-settings` | — | `{ world, autoWrite }`（无存档 → 409；缺失文件 → 默认） |
| POST | `/api/world-settings` | `{ autoWrite }` | `{ world, autoWrite }`（非法 → 400） |

### 2.5 门控点（谁读这个开关）

| 点 | 位置 | 行为 |
|---|---|---|
| 门（建场景） | **前端** `apps/web/src/state/useWorld.ts::enterLayer` | 服务端 `/api/enter-layer` 返回 `first:true` 且 `startsSceneInit(settings.autoWrite)` → `sendSocket({type:'airp_init', kind:'scene', target, by:'player'})` |
| 选项（叙事） | **服务端** `apps/server/src/routes/world.ts` `/choice` | `startsChoiceTurn(readWorldSettings(store.worldRoot).autoWrite)` → `dispatch` |

**`/api/enter-layer` 的 handler MUST NOT 调用 `dispatch`**（回归契约：只 `enterLayer({layer})` 落一条 `layer_entered`）。门走 I1 内核，不走作家——这是 `docs/init/00 §2.4` 的 R2 路径。

### 2.6 前端读取时机

- `useWorld` 挂载时 `reloadSettings()`；`App.loadWorld` 在**新存档激活后、进首个层之前**再 `reloadSettings()` 一次（开关是每世界的，文件在新存档的 `.airpworld/` 下）。
- `settings` 同时镜像进 `settingsRef`：`enterLayer` 是同步读（点击那一刻的 fetch 未必已落地）。

### 2.7 UI

`AgentSettings` 面板（niko 已建）新增一个 `<select>`，三档。**保存即 `POST /api/world-settings`**，失败静默保留旧值（`saveSettings` 抛错则 npm 层面不更新本地态——由调用方决定是否提示）。

## 3. 反模式（本批出现的真实错误）

- ❌ **把开关读在 `localStorage`**：服务端看不到 → 选项档门控在服务端无从判断。
- ❌ **在 `/enter-layer` 里保留 `dispatch`**：会绕过 I1 的 brief / 判空 / W2 兜底 / 并发锁，并让 `layer_initialized` 落两处（`docs/init/02` 已修过一次的双事件）。
- ❌ **门用作家 prompt 写场景**：作家人格 ≠ scene-init preset；产物无校验、无兜底。
- ❌ **档位判断散落各处**：必须走 `startsSceneInit` / `startsChoiceTurn`。
- ❌ **坏 settings.json 让路由 500**：必须 fail-soft 回 `off`。

| 位置 | 之前 | 之后 |
|---|---|---|
