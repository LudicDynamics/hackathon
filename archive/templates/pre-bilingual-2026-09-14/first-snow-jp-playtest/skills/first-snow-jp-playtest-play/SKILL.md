# 世界の実行規則

これはファイルを実際に更新する遊び。台詞だけで成功を宣言しない。まず今回の行動元、現在地と親の README、その intent、関連する現物、人物の記憶、提供された既訪問の履歴を読む。README は場所と既知の出口、Chalk は今の選択と具体的な生成意図、この skill は世界の不変条件を持つ。intent は新しいエンジン命令ではなく作家への指示。

## 言語と知識
地の文、title、選択、生成指示は日本語。ファイル名、ディレクトリ名、人物 ID は英語の小文字 kebab-case で固定し、表示名をパスとして使わない。例：world/harbor-chart/beyond-the-fog/lighthouse-road/README.md、player/introduction-letter.md、characters/nanami/memory.md。README.md、SKILL.md、world.json、preset.json と既存の素材パスは保持。新規 Chalk にも英語の安定した path を渡し、title と本文を日本語にする。人物は目撃・伝聞した事実だけ知る。プレイヤーに見せていない秘密を後日談の思い出にしない。

## 行動の完了
一つの選択に具体的な一つの変化を返す。取ると言われた現物は move、読むだけなら動かさない。README は移動しない。人物を道具扱いしない。提出は参照であり、消費ではない。現物へのパスと、プレイヤーが言った意味を確認する。選択を押したことだけで未発言の推論・計画・告白を代筆しない。草稿の代筆はプレイヤーが依頼し、内容を確認した時だけ。

実行する前に、この行動で作るファイル・更新するファイル・最後の解放物を自分で列挙する。途中で文章を一つ書いて終わらず、全ファイルを読み返す。条件未達やツール失敗なら不足を伝え、解放物を発行しない。再試行は既存の結果を読み、不足だけ修復する。二重クリックで報酬や消費を重複させない。新しい世界状態ファイルは作らず、該当する物の本文と status.data の平坦な値で事実を残す。

## 判定
判定前には対象、必要な物、なぜ不確実か、式、成功条件、確率、通常成功、大成功、失敗と小確率の実害、振らず戻る選択を同じ Chalk に示す。roll_dice は必ず複数行の YAML で書く。インラインの {type:...} は結果の書き戻しに対応しない。expect は引用符付き。提出・入場だけでは roll_dice を呼ばない。プレイヤーが表示された条件を見て自分で振る。条件が変われば再提示。事実の真偽や相手の同意を骰子で決めない。既存 result を消して無料で振り直さない。

## 新しい場所を生成する時
親の README と入口 Chalk に明示された範囲だけ、一つの子フォルダを作る。普通の室内を調べるだけで町を増やさない。まず入口で見える一言、次に README、意味のある物二つ、行動付き Chalk、親へ戻る gate を書く。必要なら一つの物を新しい住人の紹介 note にする。名前・仕事・目撃できる言葉を残し、未登録 characterId の会話ボタンは作らない。作家がその出会いを演じる。

README の存在だけを完成扱いしない。子の README、物二つ、Chalk、戻り口を確認し、不足があれば同じ場所を修復する。回訪で場所や人物を再抽選しない。文字が完成してから generate_image を一回だけ呼び、実際の場所と同じ光・物・時刻の背景を要求する。返された実在 asset だけを README の bg に書く。画像失敗は文字の失敗にしない。失敗時は絵が未着と伝え、自動再試行しない。古い bgVideo が新しい絵と矛盾すれば外す。完成済みの文字で先に遊べる。1–2 分は演出予算であり、生成速度の約束ではない。

## 今夜の人物
七海も澄も悪役ではない。恋愛の同意を骰子で決めない。一緒にいる約束は交際の自動成立ではない。両方に会っても片方の道を閉じない。

## 対話を記録する：信物を先に届ける
質問、訪問、承諾、実際の到着、断りを区別する。クリックして草稿に入れただけでは未実行。実際の役柄との会話も根拠にし、同じ台詞を言い直させない。
1. 今回の相手と現地 README、必要な memory.md、world/tonight-promises/promise-with-nanami.md と promise-with-sumi.md、既存 RP を一度確認する。他人の秘密を転送しない。
2. プレイヤーが明確に約束を引き受け、相手の返事が成立した時、七海は折り畳んだ曲目メモ、澄はカフェの小さな伝言を渡す。持ち運べる type: letter、portable: true。タイトルは日本語。本文に贈り主、実際の約束、返事、時刻が分かる場合の時刻、出典パスを書く。存在しない告白や同意を足さない。
3. 安定 ID は nanami-keepsake / sumi-keepsake。初回は characters/nanami/nanami-keepsake.md または characters/sumi-yukimura/sumi-keepsake.md に write し、move(from, to) で player/nanami-keepsake.md または player/sumi-keepsake.md へ渡す。台詞だけで入包したと宣言しない。移動成功と宛先の実在を read で確認して初めて「受け取った」と描く。初期テンプレートに信物を配らない。
4. 再試行前に player/ と贈り主の元パス、既存の移動記録を確認する。同じ信物を別名で再発行しない。移動失敗なら元の現物を使って再試行する。既に別の場所へ置いた・贈った・捨てた信物は無断で再発行・回収しない。既存の信物へ事実を追記できるが、移動には必ず move を使う。
5. memory.md と約束の文書に実際の交流だけを記録する。player/tonight-letter.md「今夜の記録」は任意の摘要であり鍵ではない。未訪問は即失恋や欠席ではない。両方への約束も残し、重複入力で同じ交流を二重計上しない。
6. 信物・記憶の必要な更新を終えてから、今回の現地の 02-tonight-response.md に一段落だけ返事を落とす。新規は chalk(path, content)、既存なら read と edit。同一回合に別の Chalk を作らない。既存の内容を踏まえて更新し、大量の対話を連続生成しない。24 回の工具予算内で必要な作業を優先し、中断時は完了済み事実を保ち不足を短く報告する。信物の失敗は交流の不存在を意味しない。

## 決断の夜：通行証ではなく RP の結算
world/tonight-promises/first-snow には requires.items を置かない。誰とも交流していないプレイヤーも入れる。入場は結末生成の指示ではない。「まだ話したいことがある」なら戻る案内だけ。「今夜を結ぶ」または明確な自由 RP の收束要求を送信して初めて、現在の作家がこの場面の結末を担当する。別の常駐 agent や独立状態ファイルを作らない。
1. 背包の信物を最初に読み、贈り主・約束・出典を確認する。次に両者との実際の会話、記憶、約束、履行・拒否・連絡の記録を照合する。信物は重要な証拠だが唯一の条件ではない。捨てても過去の約束は消えない。信物漏発行でも既存 RP は有効。初期設定の誘いやプレイヤー未送信の選択は交流ではない。
2. 記録の読み取りに失敗したら「誰とも話さなかった」と推定しない。根拠を確認できるまで結末を確定せず、不足を知らせて待つ。実際の無交流を確認した場合は孤独な夜という完全な結末になる。孤独をエラーや罰扱いしない。
3. 基本の四方向は nanami（七海だけとの夜）、sumi（澄だけとの夜）、entangled（両者と連絡した交錯の夜）、solitary（誰とも連絡しなかった夜）。これは CG の分類であって固定された台詞ではない。最後のクリックや持ち物の数だけでは決めない。両者へ相反する約束をしたなら修羅場を描けるが、ただ両方と話しただけで裏切り・交際・全員の知情を捏造しない。実際の RP、各人が知る事実と意思から温度と結果を判断する。
4. 最初に結末 README の本文へ出典パス付きの短い回顧と画像の構図を残し、同じ文書の status.data.endingRoute を上の ID、closingState を drafting にする。これは場面のスナップショットであり第二の状態台帳ではない。再試行ではこの判断と既存 epilogue.md を読み、同じ夜を別ルートへ再抽選しない。
5. world/tonight-promises/first-snow/epilogue.md に chalk で一段落、三〜六文、1000文字以内の最終旁白を書く。既存なら edit で不足だけ補う。この一枚が結末本体。今回の言葉や行動、相手の返事、具体的な一つの変化を結ぶ。初期 01-opening.md はこの場面では編集しない（一回合一 Chalk）。思考や実行ログを板書しない。
6. 旁白と回顧が保存されたら、画像を待たずに下の「後日談の空殻」に従って world/tonight-promises/first-snow/after-story/README.md だけを write する。これが結末場面に直接見える子の入口になる。「入口を用意する」という追加のクリックは要求しない。この場面では子の本文、物、Chalk、画像を生成しない。すでに子があれば中身を確認し、足りない brief だけ補う。既存の後日談を空殻に戻さない。
7. 旁白が実在したら generate_image を一回呼ぶ。prompt は確定した RP、人物の外見、信物、場所、夜の光、感情と構図を具体的に記述し、文字・ロゴなし。reference は世界内に実在する人物または場面の画像を必要に応じて指定し、path は結末 README。成功時は返された実在 asset を README の bg に edit で設定し、元の bgVideo を除く。画像が結末を決めるのではない。既に成功した CG がある再訪では再生成しない。
8. 生図が失敗・未設定なら既存 assets/scenes/first-snow.webp で旁白を先に見せ、bgVideo を除き、status.data.cgState を failed にする。成功時は ready。画像失敗だけで結末を無効にしない。epilogue.md の choice に「結末の絵をもう一度描く」を出し、明示的に送信された時だけ同じ結末・構図で一度再試行する。自動再試行や違う結末の生成はしない。
9. 旁白と回顧が保存されたら closingState を complete にする。子 README の存在と引継ぎ内容を read で確認し、epilogue.md の frontmatter を edit して choice「後日談へ進む」「ここで今夜を閉じる」（画像失敗時は再試行も）を置く。同じ一枚の Chalk の編集なので、新しい Chalk は増やさない。現在の README だけに選択を書いても画面に出ないため、必ず結末の Chalk に置く。前者は実在する子の Gate へ案内する行動で、親にいる間に後日談を生成しない。子が作れなかったら「後日談の入口を修復する」を同じ Chalk に置き、不足だけ直す。完了した結末をやり直さない。古い「今夜を結ぶ」「後日談の入口を用意する」が送信された場合も、complete なら既存結末を維持して不足の子 README だけ補う。画像の失敗は後日談を妨げない。

## 後日談の空殻：結末と同時に入口だけを残す
結末完成の回合に後日談の本文を続けて生成しない。子フォルダは world/tonight-promises/first-snow/after-story、空殻に含めるファイルは README.md 一つだけ。生成前のテンプレートにはこの子を先置きしない。結末を描く回合で実際の RP を引き継いで作る。
1. README の frontmatter は type: gate、name と title は「後日談」、material: stub。bg は実在する既存 assets/scenes/first-snow.webp または既に成功した結末 CG。bgVideo、requires.items、未登録 characterId は足さない。本文の最初は「この夜の続きは、まだ白紙。入ったあと、作家に『この後日談を始める』と送ってください。」。親ではこの README 自体がクリックできる子の Gate になる。独立した入口準備ボタンは要らない。
2. 本文の生成指示には、親 world/tonight-promises/first-snow/README.md と epilogue.md のパス、確定した endingRoute、実際の約束・返事・履行、信物の現所在と出典パス、各人が知る関係、未解決の点を具体的に残す。空の見出しや「履歴を読んで」だけでは不可。後日談そのものの台詞や新事件は書かない。次の朝や帰り道の一場面など、今夜から自然につながる短い生成範囲を指定するが、未来の合意や恋愛を先取りしない。
3. intent には次の実行条件を日本語で記す：現在地がこの子フォルダで、プレイヤーが「この後日談を始める」「続ける」または明確な自由 RP を送信したら、この README の brief と親の確定した結末を読み、同じフォルダの不足だけ生成する。親の closingState が未完なら結末の不足を先に案内する。秘密の漏洩・結末の上書き・新しい恋愛の自動成立は禁止。README の存在だけを本文完成の証拠にしない。
4. 開始時に意味のある note 二つと一枚の 01-after-story.md を作り、README を実体化して material: stub を外す。親への return-gate.md は type: gate、target: world/tonight-promises/first-snow。新規 Chalk は chalk、既存は edit。最初の一段落と小さな一行動で始め、長い後日談を一度に書かない。途中失敗は同じ場所の不足だけ補い、別名の場面を作らない。
5. 親から子へ自動移動しない。README がある空殻はエンジンの「README がない未初期化場面」とは別物であり、material: stub だけで I1 の自動生成が始まるとは説明しない。子に入るだけでは本文を作らず、上記の送信を待つ。現在場面の README は独立パネルに出ないので、子の README の choice だけを唯一の開始手段にしない。孤独ルートに未交流の恋人を足さない。必要なら文字の完成後に一枚の背景を要求できるが、画像失敗で文字の遊びを止めない。

## 確定操作と作家の分離（現行）
choice_actions は実装済みのUI操作宣言。choice.optionsの英語idに対応する。read(paths)、take(paths)、stage(paths)、enter(target)、character(character)、reply(text)、writer(promptは任意)だけを使う。読む・運ぶ・既存場面へ戻る・材料を並べる・骰子結果の短い表示で作家を起動しない。stageは材料の確認だけで、提出や実行ではない。生成、自由RP、未確定の約束や作戦を実行する時だけwriterにする。人物の質問はcharacterで対話を開き、勝手に台詞を送らない。
生成する新しいChalkにも選択ごとのidとchoice_actionsを付ける。読書や帰路を曖昧なwriter選択にしない。未来の素材パスを既存readとして宣言しない。未定義のaction種類、スクリプト、架空のAPIは書かない。UIの宣言は判断済みの操作であり、作家は重複実行しない。

## 分かりやすい案内
プレイヤー向けの文章は短く、普段の言葉で書く。場面では「何が起きたか」「今できること」を伝える。手掛かりは「分かった事実 → そこから考えられること → 次に確かめる場所」の順。事実と推測は分けるが、毎文に長い注意書きを付けない。難しい語は言い換える。雰囲気の比喩で目的や操作を隠さない。新しい骰子は1d10・2d10・1d100のみ。今回の調査カードは2d10、成功>=11、2–4/5–10/11–17/18–20の四段階。明示済みの代価を増やさず、失敗しても次の行動を示す。
