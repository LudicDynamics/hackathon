# 世界の実行規則

これはファイルを実際に更新する遊び。台詞だけで成功を宣言しない。まず今回の行動元、現在地と親の README、その intent、関連する現物、人物の記憶、提供された既訪問の履歴を読む。README は場所と既知の出口、Chalk は今の選択と具体的な生成意図、この skill は世界の不変条件を持つ。intent は新しいエンジン命令ではなく作家への指示。

## 言語と知識
地の文、title、選択、生成指示は日本語。ファイル名、ディレクトリ名、人物 ID は英語の小文字 kebab-case で固定し、表示名をパスとして使わない。例：world/harbor-chart/beyond-the-fog/lighthouse-road/README.md、player/introduction-letter.md、characters/nanami/memory.md。README.md、SKILL.md、world.json、preset.json と既存の素材パスは保持。新規 Chalk にも英語の安定した path を渡し、title と本文を日本語にする。人物は目撃・伝聞した事実だけ知る。プレイヤーに見せていない秘密を後日談の思い出にしない。

## 行動の完了
一つの選択に具体的な一つの変化を返す。取ると言われた現物は move、読むだけなら動かさない。README は移動しない。人物を道具扱いしない。提出は参照であり、消費ではない。現物へのパスと、プレイヤーが言った意味を確認する。選択を押したことだけで未発言の推論・計画・告白を代筆しない。草稿の代筆はプレイヤーが依頼し、内容を確認した時だけ。

実行する前に、この行動で作るファイル・更新するファイル・最後の解放物を自分で列挙する。途中で文章を一つ書いて終わらず、全ファイルを読み返す。条件未達やツール失敗なら不足を伝え、解放物を発行しない。再試行は既存の結果を読み、不足だけ修復する。二重クリックで報酬や消費を重複させない。新しい世界状態ファイルは作らず、該当する物の本文と status.data の平坦な値で事実を残す。

## 判定
判定前には対象、必要な物、なぜ不確実か、式、成功条件、確率、通常成功、大成功、失敗と小確率の実害、振らず戻る選択を同じ Chalk に示す。roll_dice は必ず複数行の YAML で書く。インラインの {type:...} は結果の書き戻しに対応しない。expect は引用符付き。提出・入場だけでは roll_dice を呼ばない。プレイヤーが表示された条件を見て自分で振る。条件が変われば再提示。事実の真偽や相手の同意を骰子で決めない。既存 result を消して無料で振り直さない。

## 新しい場所を生成する時
親の README と入口 Chalk に明示された範囲だけ、一つの子フォルダを作る。普通の室内を調べるだけで町を増やさない。まず入口で見える一言、次に README、意味のある物二つ、行動付き Chalk、親へ戻る gate を書く。必要なら一つの物を新しい住人の紹介 note にする。名前・仕事・目撃できる言葉を残し、未登録 characterId の会話ボタンは作らない。作家がその出会いを演じる。

README の存在だけを完成扱いしない。子の README、物二つ、Chalk、戻り口を確認し、不足があれば同じ場所を修復する。回訪で場所や人物を再抽選しない。文字が完成してから generate_image を一回だけ呼び、実際の場所と同じ光・物・時刻の背景を要求する。返された実在 asset だけを README の bg に書く。画像失敗は文字の失敗にしない。失敗時は絵が未着と伝え、自動再試行しない。古い bgVideo が新しい絵と矛盾すれば外す。完成済みの文字で先に遊べる。1–2 分は演出予算であり、生成速度の約束ではない。

## 霧埠の真実と短い到達点
無人船は囮。領主家の帳簿、古い税関トンネル、消灯した十二分がつながる。老モーは追跡船の存在を知らない。ヴェラの舵の留め具と銀鳶の空箱を、安易に犯人の自白に変えない。

## 二隻目の Hybrid 判定
world/harbor-chart/02-two-wakes.md で提出された独立した観察二つ以上と方法を内容で確認する。同じ記録の複製は二つに数えない。現物の場所は移動履歴で追う。採用した根拠のパスと短い理由を残す。妥当なら world/harbor-chart/03-lighting-terms.md を作り、準備の確認と選択を示す。灯油をまだ持たなければ灯台へ案内する。誰でも押せる骰子を先に置かない。

この Demo の候補条件：2d10、expect は ">=11"。霧と揺れる足場が不確実な理由。2–4 は 6/100（6%）で失敗し、所持する灯油一回分を失う。5–10 は 39/100（39%）で失敗だが消費なし、別の観察で方法を修正できる。11–17 は 49/100（49%）で通常成功、二隻目の輪郭と安全な岸道を発見。18–20 は 6/100（6%）で大成功、さらに次の町で協力を得られる紹介状を入手。合計成功率 55%。判定は既存の真相でなく、その場の発見の成否。大成功とエンジンの crit（全て最大目）は同一ではない。

最初の予告には choice「この条件で判定を用意する」「振らずに調査へ戻る」を置く。承諾されてから、同じ条件の roll_dice を複数行 YAML で同じ Chalk に追加する。type は "2d10"、desc は「霧の向こうを投光で確かめる」、expect は ">=11"。承諾だけでは roll_dice ツールを呼ばず、プレイヤーの骰子操作を待つ。油はファイル名だけでなく一回分が残っているか本文で確認する。

## 骰子の後も止まらない Chalk
1. 骰子を用意する時点で、同じ Chalk の choice を「出目を受けて行動する」「調査へ戻る」に更新する。本文には「振ったら、この札から続きを選べます。失敗なら足元の手掛かりへ、成功なら光の先へ」と書き、上の四段階の結果も残す。intent にこの節への参照と判定元 world/harbor-chart/03-lighting-terms.md を必ず書く。これが既存の choice から作家へ戻る入口。出目だけ表示されても待ち続けなくてよい。まだ result がない時に続行を押されたら、判定前だと短く伝えるだけで、代わりに振らず、消費も生成もしない。
2. 作家が result を読める次の行動で、公開済みの四段階を適用する。出目、expect、採用した証拠を変えない。まず実害の有無と次にできることを一、二文で同じ Chalk に返す。長い結果文、画像、場面転換を必須にしない。損害は画像待ちにせず先に現物へ反映する。判定元の status.data に rollOutcome（failure / success / great-success）、oilLossApplied（true / false）、revealState（pending / revealed、成功時のみ）を平坦な値で残す。これは作家の記録でありエンジン命令ではない。現物と記録を読み返し、途中停止からの再開では不足だけ直す。空瓶なら二度目の油を引かない。
3. 2–4 なら player/lamp-oil.md の本文を一回分の油を失った空瓶に更新し、portable な空瓶を残す。「光が途切れ、瓶には油が残っていない。船はまだ見えないが、足元の潮の跡は読める」と短く示す。5–10 なら油を減らさず「霧が光を押し返した。油は残っている。別の角度から確かめよう」。どちらも choice は「潮の跡と日誌を照合する」「ヴェラに方法を相談する」。単に失敗した、調査を続けよう、だけで終わらない。判定前専用の「振らずに調査へ戻る」を判定後の唯一の選択として残さない。
4. 「潮の跡と日誌を照合する」は灯油も再判定も不要。既に読んだ水位の痕跡と灯台日誌を実際に照合し、足りない記録は具体的な既知の場所へ案内する。揃えば world/harbor-chart/tide-route-note.md に旧税関側で次に確かめる一点を書き、徒歩でそこを調べる Chalk を出す。安全な岸道を発見済みとは書かず、二隻目、紹介状、新町はまだ発行しない。プレイヤーがその徒歩探索を選んだ時だけ world/harbor-chart/tidal-approach/ に小さな調査場面を生成できる。足場と潮の痕跡を調べる場所であり、成功専用の近道とは異なる。README、物二つ、次の観察を選べる Chalk、港への戻り口を備え、新しい現場の観察から調査を続けられる。失敗を無料の成功へ置換せず、失った油も戻さない。ヴェラへの相談は実際の方法修正を扱い、同じ result を消す口実にしない。
5. 11–17 と 18–20 はまず revealState: pending とし、「光が何かの輪郭を捉えた。近づいて確かめられる」のような一言と choice「光の先を確かめる」「調査へ戻る」を置く。18–20 は接応につながる手掛かりも待っていると短く予告してよい。この段階では完全な発見、子フォルダ、背景生成、紹介状の発行をしない。大成功でも自動でカメラや場面を切り替えない。
6. 成功した判定元の「光の先を確かめる」、または成功後に押された準備済みの「出目を受けて行動する」だけが完全な発見を開く。「調査へ戻る」なら未処理の損害だけ精算し、成功は pending のまま保持して後で選べるようにする。クリック時に同じ result と公開条件を読み直し、二隻目が霧から現れる短い Punch Line と world/harbor-chart/beyond-the-fog/README.md、物二つ、「岸道をたどる」Chalk、港への戻り口を作る。18–20 の時だけ player/introduction-letter.md を一通作り、今回の証拠に根拠のある接応を記す。11–17 にこの追加報酬を渡さない。存在確認後に revealState: revealed を記録する。再クリックは同じ入口を案内し、途中失敗は不足だけ修復する。生成の手順は上の「新しい場所を生成する時」に従い、文字を先に完成させる。1–2 分の生成はここから。完成しても自動入場せず、入口をプレイヤーに選ばせる。

## 霧の先へ
世界は終わらない。「岸道をたどる」を選んだ時だけ、world/harbor-chart/beyond-the-fog/ の下に英語の安定したディレクトリ ID と日本語 title を持つ新しい道と町の入口を一つ生成する。README、物二つ（うち一つは土地の住人でもよい）、Chalk、戻り口、背景一枚。紹介状が実際にあれば具体的な協力に反映する。次の町を一度に全て作らない。失敗直後や成功後の未クリック状態に、この成功用入口を先回りして作らない。

## 確定操作と作家の分離（現行）
choice_actions は実装済みのUI操作宣言。choice.optionsの英語idに対応する。read(paths)、take(paths)、stage(paths)、enter(target)、character(character)、reply(text)、writer(promptは任意)だけを使う。読む・運ぶ・既存場面へ戻る・材料を並べる・骰子結果の短い表示で作家を起動しない。stageは材料の確認だけで、提出や実行ではない。生成、自由RP、未確定の約束や作戦を実行する時だけwriterにする。人物の質問はcharacterで対話を開き、勝手に台詞を送らない。
生成する新しいChalkにも選択ごとのidとchoice_actionsを付ける。読書や帰路を曖昧なwriter選択にしない。未来の素材パスを既存readとして宣言しない。未定義のaction種類、スクリプト、架空のAPIは書かない。UIの宣言は判断済みの操作であり、作家は重複実行しない。

## 骰子による解読代行（現行、手動解謎との並列）
各調査地点と地図の04-investigation-dice.mdは、プレイヤーの代わりにキャラクターが観察をつなぐルート。現実のプレイヤーが正解を説明する必要はない。地図の判定を直接選んでもよく、各地点の判定は必須順序ではない。真相は固定、出目は発見の方法・代価・余裕を変える。dice_outcomesは四段階の短い結果と次のchoice_actionsを既存の動作層で同じファイルへ反映する。作家は二重に反映・再判定・追加徴収しない。
このルートでは「独立した証拠二点」「推論と計画の二文書」は必須条件ではない。旧規則のそれらの要求は手動提出ルートだけ。低い出目でも足掛かりと次の行動を得る。地図の結果から新場面や結末を明示依頼された時だけ作家が生成する。未発見の人物を既に話したことにせず、読めた推理と会話の記録を区別する。生成待ちを骰子失敗扱いにしない。

## 分かりやすい案内
プレイヤー向けの文章は短く、普段の言葉で書く。場面では「何が起きたか」「今できること」を伝える。手掛かりは「分かった事実 → そこから考えられること → 次に確かめる場所」の順。事実と推測は分けるが、毎文に長い注意書きを付けない。難しい語は言い換える。雰囲気の比喩で目的や操作を隠さない。新しい骰子は1d10・2d10・1d100のみ。今回の調査カードは2d10、成功>=11、2–4/5–10/11–17/18–20の四段階。明示済みの代価を増やさず、失敗しても次の行動を示す。
